## 一、作者字段及编译闭包

在 `COUNTER.detail` 新增可选 `targetTiming`，数值仍使用现有 `NumericValue` 结构：

```ts
type CounterTargetTiming =
  | { kind: 'PHASED_TICK'; processKey: string;
      intervalValue: NumericValue; phasePolicy: 'PRESERVE_ON_EXTEND' }
  | { kind: 'EXPIRY_PAYLOAD'; processKey: string };
```

两分支只接受列出的键；省略表示原普通计数器，显式 `null`、未知键或未知枚举拒绝。声明仅准本技能 `TARGET COUNTER`、静态初值0/容量1、无初值绑定、静态正安全整数期限。周期分支的间隔同样须在各合法等级完整静态求值为正安全整数；每锚唯一声明、每来源1～3锚；预约分支本轮每来源最多一个，不能与周期共用字段。不从英雄名、状态名、描述或固定状态图推断授权。

声明指向同技能真实 `PASSIVE` 过程：无冷却、费用、运行时绑定，恰好一个 `IMMEDIATE` 空细节步骤、明确不占动作。周期过程无状态操作、无过程时点规则，恰好一个执行时点效果绑定；效果无生命周期，结果为即时伤害。**展开后每锚恰好一条无条件、完整的 `TARGET damage`**，不暴击、复制或导出额外操作结果。禁止第二笔伤害、状态写、恢复、链接、供值器操作、事件、调用及隐藏子过程。金额仅本技能静态参数与当次目标最大生命；分类、防御和吸血完整，不能借旧周期允许的自身状态写扩大本分支。

## 二、通用字段、真实归属及新鲜初始化

周期能力保持 `kind='tick'`，`tickSpec` 必须显式为：

```ts
{ intervalMs: number; startDelayMs: 0;
  anchorScope: 'state_scope/provider_target'; anchorStateKey: string;
  phasePolicy: 'preserve_on_extend'; onTick: OperationDefinition[] }
```

`startDelayMs=0` 沿现锚语义，首跳仍在应用加间隔。新续期降低为：

```json
{
  "operation": "state_duration_change", "target": "self",
  "ref": "实际编译状态键", "valuePolicy": "ensure_remaining_preserve_phase",
  "amount": { "op": "const", "value": 4000 },
  "types": ["state_scope/provider_target"]
}
```

预约由同父 `kind='stateful'` 能力独立声明：

```ts
targetExpirySpec: {
  anchorScope: 'state_scope/provider_target'; anchorStateKey: string;
  onExpire: OperationDefinition[];
}
```

三个结构严格检查完整键、类型及互斥关系；预约能力不能再有普通操作、周期、监听、费用、冷却、施放条件或过程控制，也不能由驱动计划或能力引用直接调用。只能由匹配的真实目标到期事件进入。它绑定实际父挂载、状态索引、能力索引及操作表，保留本技能参数、完整能力分类、施放归属和作者起源；禁止用空能力执行伤害。

新时序来源只接受实际初始挂载的永久 `character/build`、真实稳定标识及拥有者。来源闭包只接纳上述周期、预约及其完整命中/逐伤被动监听；额外自然根必须完整支持或明确拒绝，不能静默过滤。按实际状态键查唯一周期能力，不能取第一项周期代替全部锚。无 `phasePolicy` 的旧来源不获得多锚权限；旧自身盾 `onExpire` 不进入新预约分支。

**新时序来源只支持新鲜运行。** 在计时恢复前检查该实际来源的初始状态：所有声明值只能是默认值，期限只能省略或0，目标绑定只能省略或空；拒绝非默认值、任何正期限、非空目标绑定和外带相位/预约事实。编译挂载初值与运行快照均检查，纯通用入口没有技能计划也不能绕过。无恢复协议、新运行输入、猜测相位或自动补预约；重复运行每次独立建立事实。旧无新时序来源的恢复规则不变。

## 三、相位、期限与队列

每锚按实际拥有者、供值器实例、目标及编译状态槽保存激活世代、相位原点、当前期限及已排相位序号；用整数槽或小数组，不新增字符串组合键热路径哈希。

- `SET1` 建立新世代，原点为实际应用时点；在 `origin+n×interval`、`n≥1` 且不晚于当前期限处排有限跳。对已有正值再 `SET1` 仍为重启，新动作才保相位。
- 新动作仅在值活动、目标一致且 `now<expiry` 时取 `max(oldExpiry,now+amount)`；缺失、0或到期不复活。延长不改世代/原点，保留旧有效跳，仅追加原相位落在 `(oldExpiry,newExpiry]` 的事件，不在刷新点补跳。
- 新模式跳按真实身份、世代、相位和 `eventTime≤liveExpiry` 验证；不能因旧载荷截止时间不同而丢跳。末跳按 `eventTime==liveExpiry` 判断；延长后的旧终点只是普通跳，新期限不落相位时不制造额外跳。旧清理核对期限及世代，不能清新窗口。
- 真正末跳与该锚清理同帧。精确到期保护须逐锚，不能用现有单键保护覆盖另两锚；仅真实已排、仍有效的终点事件享有保护。清零、新激活、卸载及目标切换使旧事实失效。

保留现有 `TimeMs→Category→Priority→Seq` 队列及过程稳定排序：真实 `ProcessTimer` 先于普通 `AnchoredTick`，后者先于 `ExpireCleanup`；初始 `SkillAction/AbilityAttempt` 仍依原类别在清理之后。已有“真实末跳先于同刻过程计时”选择器继续生效，仅准确纳入新模式的当前末跳，不提升所有跳。预约负载放 `ExpireCleanup`，不伪装一次终点跳或过程计时。

因此同组既定跳先于同刻爆炸/清理；非末跳炸点若有真实过程命中，则先完成该命中与P监听，再结既定跳，最后爆炸。命中可刷新灼烧，不能推迟已预约爆炸。若是真末跳，则末跳及清理先于同刻过程命中，新命中建立新世代；旧期限已经延长时不能误用该例外。普通限制标记按 `now>=expiry` 到期，无末跳保护。不得改全局类别或丢失暂存事件原序号。

## 五、逐伤状态前值及击杀关联证据

`DAMAGE_BEFORE_VALUE` 降低为 `event.provider_target_state_before.<实际状态键>`。编译展开全部条件依赖，只绑定该监听所属拥有者/供值器自己的声明目标标量；真实伤害来源须为该拥有者，目标为本笔实际目标。缺目标状态或按当时期限已过期读0；缺已声明的冻结事实报错，不回读当前状态补0。金额、其它事件、伪发送或外来状态读均拒绝。

仅含该新读取的会话采集：在每笔真实非复制伤害操作扣血前，从**该帧当时已暂存**的状态冻结所需标量；不取整帧入口或监听时值，不复制全部状态。沿现有伤害结算生成编号的入口，在本笔成功获得真实 `damageId` 后绑定已冻结值；编号、状态事实和伤害共同暂存提交。结构失败、未结算分支及复制伤害不得补造编号或事实。新会话的真实 `damage_instance` 内部快照及对应 `emitted_event.data` 同步运输该 `damageId`，连接已有伤害明细和 `killed`。

详细证据新增普通 `EvidenceItem`，`kind='damage_state_before'`，时点是本笔伤害时点，数据严格为：

```ts
{ damageId: number; owner: string; providerRef: string; definitionRef: string;
  stateKey: string; target: string; beforeValue: number }
```

`damageId` 为本次运行实际正整数编号；其余身份取真实挂载和编译字段，`beforeValue` 是合法非负安全整数。每笔/拥有者/实例/状态/目标只一条。读取此事实的真实 `DAMAGE_DEALT` 监听所产 `resource_restore.data` 增加 `triggerDamageId`、`triggerDamageSource`、`triggerDamageTarget`，分别来自同一冻结伤害事件；恢复原有 source/target/owner/provider/ability/operation/use 字段含义不变。无真实使用时保留原空使用，不靠时刻或路径推断伤害关联。无新读取的旧会话省略这些新因果字段/事实，不增加逐伤采集分配。

Brand返蓝以同一冻结总计数构成互斥或条件：A为实际来源任意真实伤害 `killed=1 && beforeCount>0`；B为实际已驱动Q/W/E/R的非反射技能伤害 `killed=1 && beforeCount==0`；C为P实际声明周期/预约生产的伤害 `killed=1 && beforeCount==0`。A与B/C互斥，B与C按真实技能身份互斥；每监听每事件最多一次，不用 `oncePerUse` 去重周期，也不新造全局去重。C必须由完整生产闭包证明，不能把任意P伤害当灼烧。它覆盖末跳计数已过期及爆炸先清层的情形；第一发技能致死不必后挂P。
