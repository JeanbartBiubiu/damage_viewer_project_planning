# 普攻主体替换与三牌正式接入

2026-10-19。本契约补齐已通过隔离原型到正式计算的边界，进入独立复核后实施。用户已授权继续开发缺失通用机制、真实资料录入和后续英雄适配；不再以资料拆分或局部原型作为本模块终点。三张牌是普通独立技能，不增加选牌参数、互斥提示、自动关闭、等级联动或专用共同冷却。

## 一、前端与作者数据

### 伤害角色

伤害结果的 `detail` 增加可选 `attackDamageRole`（普攻伤害角色），只接受 `PRIMARY`（普通攻击主体）、`REPLACE_PRIMARY`（待击替换主体）；省略表示普通伤害，显式空值、非字符串和未知值拒绝。非伤害结果不接此字段。无角色的既有响应继续省略，不为全部既有伤害补出空字段。后端负责严格类型、引用及事务最终态检查，原 JSON 存储不新增表；现行数组存储无此明细键限制，不需迁移。

`PRIMARY` 仅适用于所选真实普攻首次过程关联的唯一、无条件、即时目标伤害；`REPLACE_PRIMARY` 仅适用于自身首次主动启动的单步骤强化待击，其负载只有一个无条件、即时目标伤害。拒绝参与条件、事件值条件、重复和周期；替换负载不能附带第二个结果，普通主体效果的无角色结果保持。显式零金额仍合法。角色不依赖技能名、物理类型或候选顺序。单例角色编译为整数，并绑定真实输入中的能力及候选位置。

本轮声明 `PRIMARY` 的真实父命中全部候选必须省略法术盾粒度或为 `null`；替换负载仍可显式声明可阻挡。原父命中的盾单位会提前冻结，若同时允许父候选与替换消费同一盾，就需要额外的跨帧消费协议，本轮不引入该机制。真实共享普攻的伤害与命中联动均符合空粒度；无角色的既有路径不受这一新增边界影响。

普通作者可先保存尚未挂接过程的角色效果资料；这不代表完整可计算。后台严格检查局部形状与已存在的真实消费点，聚合提交后核完整最终态，不让修改过程或启动规则绕过已存在的角色限制。所选普攻和运行驱动才能判断的条件由宿主/Wasm严格核对。`PRIMARY` 自身只有一个无条件伤害结果，但真实父命中允许其前后还有其它普通候选。

三牌各自用真实普通过程、冷却和同一待击能力，主伤公式直接引用各自已保存的完整原式，不扣去总攻击力，不加入抵消伤害。原式已含暴击效能时，关闭该段通用期望暴击；实际暴击效能采用项目明确数值模型后再冻结作者候选。三牌的吸血、法术盾资格、期限及各色附带效果逐项留证，不把未知标志当默认。

角色共享普攻的真实主体由同一作者字段显式标记。仅有资料或有字段但没有实际消费不算计算通过。关闭、零级、未驱动的目标方来源仍走既有闭包规则；来源数量、启停、等级、预算及错误沿共同框架，不加 W 专用检查。

### 正式输出与宿主校验

沿用现有 `ProcessEmpoweredAttack.useRef / hitRef / target`（本次真实普攻关联）及过程自己的 `UseKey`（原激活使用），增加可选 `replacedPrimary`。其完整静态身份为：`owner / providerRef / definitionRef / startAbilityRef / initialControlAbilityRef / hitAbilityRef / candidateKey / effectOccurrenceKey / effectKey / resultKey`。这些字段都能从真实输入唯一重建，不把内部扁平化操作编号当成宿主可解释的身份。

详细伤害、过程及使用记录里的替换归属一致。新增可选 `basicAttack.primaryReplacements` 累计行，不受明细预算或输出模式影响，仅实际成功提交替换后出现。每行固定为 `{primary, replacement, target, count, blockedCount, postDefenseDamage, shieldAbsorbed, actualHpLoss}`；`primary` 为上述十字段主体身份，`replacement` 固定为 `{owner, providerRef, definitionRef, skillKey, processKey, hitAbilityRef}`。`target` 是实际普攻目标。同一静态绑定及目标的行合并，身份用稳定编译槽或小切片，不新增字符串结构体映射。累计伤害与同实际负载的 `damageBreakdown` 相符；零值和阻挡仍计替换次数，阻挡单独累计。

宿主按完整实际拥有方、供值引用和定义、首次控制、命中能力及作者结果重建身份，核对累计、明细前缀和两个使用归属。每刀主体只能原伤害或合法替换之一；不能继续要求替换后的旧物理主体伤害存在，也不能放宽成允许原主体和完整替换同时结算。汇总、零明细和截断仍校验可靠累计，不靠隐藏明细通过。没有实际替换的旧请求省略新增输出，保留字节对照。

管理表单只新增通用伤害角色字段及正常读回，不修改混合战斗页的三牌交互。身份升级为下一宿主版本，最终正式 Wasm 与前端源码、分发及生产构建须匹配。新产物下重新核对已开放对象，不能直接改旧证明摘要冒充验收。

范围资源仍保留五个原始资料槽；逻辑槽可选的 `currentSkillKeys` 明确列出当前全部实际技能。机械复制账本 `splitAuthoring.currentSkillKeys`，实际挂载逐项核对，不再要求归档技能继续挂载；遗漏、重复和跨槽重复均拒绝。排除来源按同一映射展开，实际技能闭包仍逐项进入覆盖与摘要。此映射只反映资料拆分，不代表可计算，也不生成互斥组。完整验证按不同普通开关场景覆盖每份技能，不能把来源存在误报为全部在同一刀成功执行。

## 二、Wasm

### 选择、顺序和提交

沿真实 `engine_compile / engine_run`，编译期验证角色所在的能力、过程和候选；运行前绑定所选实际普攻的唯一主体。冻结候选和待击来源后，在原主体位置重新核对实际来源、定义、使用、期限和目标，执行合法替换；其它父候选及普通命中监听保持顺序，旧附加强化仍后置一次。没有有效替换时走原主体；同刻多个有效主体替换按通用一致性错误拒绝，不静默取第一项，不按牌名加选择规则，也不提前因角色挂载三份定义而拒绝。

替换负载、待击消费、盾消费、过程完成、可靠累计在同一个暂存帧提交；组内预算或任一步错误全部不提交。原主体前已提交的其它候选保持，后续失败不跨帧回滚。合法替换为零或被合法盾阻挡时，仍抑制原主体、消费一次窗口，不回退原伤害。未匹配、过期、移除、刷新版本失效的待击不得被当作成功替换。

替换保留原主体的根伤害资格：成功提交后的正伤害按原根候选口径只派发一次 `event/damage_dealt`，沿真实父普攻的基本攻击事件分类，携带替换负载自己的能力、技能和激活使用，以及实际攻击关联；零、阻挡、组内失败不派发。监听、旧附加强化和周期不能借此升级成根伤害，也不能降低真实调用深度。普通攻击开始/命中仍各一次，E 类计数只走一次。死亡按现行同步尾部及停止规则处理。

已有强化待击不支持中途恢复，本次仍明确拒绝相应过程快照，不新增伪恢复。其它未涉及的恢复路径保持。普通攻击没有宿主 MISS 输入时不为验收伪造事实。

### 验证与完成

正式实现必须覆盖异名主体、无替换及旧附加、前后父候选、零值/盾、精确期限、来源移除/刷新、同刻冲突、预算及盾后错误回滚、根伤害监听、E 类共存、致死、记录为零/截断/汇总、同会话和释放重编。旧冻结请求逐字节对照；改动事件路径附真实 Wasm 分配调用对照。原生通过后完成完整 Go 测试、基准、正式构建、两类冒烟及 Web 全测/构建。

三份真实牌的数据采用统一接口保护保存并独立回读；由正式浏览器工作线程验证每色等级、正法强/攻击力、不同抗性、效能三档、真实吸血、E 第四击、记录模式及同会话。随后处理崔斯特剩余范围并验证全部必要来源，更新范围与证明后真实页面可选、可配置、可计算、可释放，才是整英雄完成。继续下一名时沿现有范围账本，不等待逐名用户确认。
