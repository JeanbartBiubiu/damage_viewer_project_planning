# 作者与宿主实施契约

本文件是本轮作者字段、校验和 Web 映射的实施真源；原生协议、事件及事务边界以同目录《通用弹药执行契约》Wasm 章为准。只读调查是源码依据，不再另设实现版本。基线 `a5ae1d3d7`，尚未补录 R 或开放整库奇。

## 前端与作者数据

### 状态初值的真实声明

保留已有 `NumericValue` 数值引用结构。在 `COUNTER` 和 `AMMO` 的 `detail` 增加可选 `initialValueBinding`；`AMMO` 另增加可选 `initialRemainingValue` 和 `initialRemainingMsBinding`。新增字段缺省时不改变旧对象的响应形状，不为它们自动补值。

两个绑定复用现有 `{bindingKey, parameterKey, sourceType, detail}` 形状，`sourceType` 只能是 `SCENE_INITIAL_PARAMETER`，`detail` 只有显式 `minValue / maxValue`。对应的 `initialValue` 或 `initialRemainingValue` 必须是直接引用同一参数的 `{kind: 'PARAMETER', parameterKey}`，参数属于本技能、`INTEGER / RUNTIME_INPUT` 且没有默认值。声明必须被对应字段实际消费，不接受孤立绑定、假效果或借给容量/时长的输入。

状态绑定本轮只作用于 `SKILL` 范围的 `COUNTER / AMMO`。边界必须为有序、非负安全整数；实际初值还需不超过编译时容量。`initialRemainingValue` 单位为毫秒，只适用于 `ONE_BY_ONE / AFTER_CONSUME`，可以是显式静态数值，或由对应绑定供值。欠弹时必须有真实余时，且不大于本场完整回充间隔；满弹时宿主只接受显式余时 0 或未声明余时，校验后不向原生发送 `initialRemainingMs`。不能把满弹时的非零输入丢掉。

场景输入发现器沿本次真正执行的来源与闭包收集声明，使用双方、完整来源身份、技能、状态键、字段、配置摘要及等级生成声明身份。关闭、零级、未驱动的 B 主动来源不索取库存或启动回充；配置或等级改变后旧输入失效。复用现有初值表单展示，禁止隐藏填零。绑定与对应静态数值互相核对，不新增条件输入协议。

### 普攻命中减少下一枚回充

新增通用触发动作 `MODIFY_INTERNAL_STATE`，明细固定为 `{stateSkillKey, stateKey, operation, value}`；操作本轮只有 `REDUCE_RECOVERY`，`value` 为现行数值引用，表示减少的毫秒数。它只能由本技能 `BASIC_ATTACK_HIT` 规则作用于 `EVENT_SOURCE`，指向本技能 `SKILL` 范围的 `AMMO`。禁止跨技能或跨供值器写入，不启动辅助过程，不改变库存或单发冷却。

该动作的动态输入绑定和结果修正数组本轮均必须为空；`value` 沿现有固定/等级参数及属性公式计算。原有 `SOURCE_INITIALIZED / EXECUTE_EFFECT` 的场景初值入口保持原校验，不因本次退款另行扩大准入。状态字段上的真实初值声明不受此限制。

后端同步动作反序列化、状态/参数/公式引用和删除保护、数值依赖、事件归属及一次聚合保存校验。状态和动作均已存在 JSONB 存储，本轮不增加数据库表、列或迁移。Web 管理编辑器须认识新字段与动作，不能读取后再次保存时静默删除。接口录入仍使用冻结计划、摘要保护及完整独立回读。

### 每发循环的冻结与推进

不新增原生循环算子。使用已有 `COUNTER`：下一发序号从场景输入明确为 1..3，另用一个本次发射序号作为内部暂存。真实首次 `START_PROCESS` 动作可以携带现有 `INTERNAL_STATE / VALUE` 输入绑定，但只允许读取同技能、`SKILL` 范围的整数 `COUNTER`，绑定到本技能无默认的整数运行参数。这个运行参数由帧状态提供，不显示为用户输入。

仅对 `PROCESS_START` 的 `COUNTER / SET` 有界开放上述动态参数及公式；其它状态操作和初值、容量、时长继续沿原静态或显式初值规则。依作者顺序先把当前序号写到暂存状态，再以既有 `if / eq / add` 公式将下一发序号加一或从 3 回到 1。两条写入与扣弹处于同一付款帧，失败整体不提交；MISS 已经发射，仍消耗库存并推进循环。

实施核对发现，原具名公式的参数供值尚不能引用帧内供值状态。本轮只在上述已核验的 `PROCESS_START / COUNTER / SET` 路径，把作者公式按现有语法降低为原生已有的数值表达式，复用校验、阶段引用和循环检测；只允许声明绑定的同技能整数状态参数及固定/等级参数。不得把状态读值伪装成能力参数，不新增原生供值种类，不开放属性、上下文或未绑定运行参数；原作者公式与覆盖记录保留，其他公式使用点维持原限制。

命中候选通过现有作者模型的同技能内部状态比较条件读取本次发射序号，区分普通和超级伤害；Web `hitAdapter` 当前尚未接入此条件，本轮需增加同技能冻结整数计数器的有界映射，不能当成已有运行能力。不能读取已推进的下一发序号。主动过程、自然普攻退款监听和弹药状态合并到同一个真实来源供值器，不能生成两份库存或套英雄标识分支。

### 库奇 R 的录入范围

保留原 13 个参数与 3 条公式；按已核实来源修正文案的最大 4 枚。保留学习时 2 枚的数据，不能用它代替战斗初值。新增战斗库存、初充余时和下一发序号的无默认参数；保留未知 `mStat8` 的原无默认参数和原秒公式作为资料，不给编号赋义、不填 0，也不让执行程序读取该未知参数。

复用原小导弹与 2 倍超级导弹公式。普通攻击命中退款新增独立公式，读取真实 `current_frame / SOURCE / TOTAL` 暴击率属性，使用 `2000 + 4000 × clamp(暴击率, 0, 1)` 毫秒；属性键以当前游戏计算配置的 `criticalChanceAttributeKey` 核对。按用户既定范围不模拟 R 前摇、飞行或多目标，使用即时单目标过程；原施法时间资料仍保留。法力成本保留作者定义，按已声明的本场忽略法力规则处理。正常命中、MISS、暴击资格、生命偷取/全能吸血等沿现有明确类型和作者结果处理。

新增依据是 [Riot 官方 26.14 补丁](https://www.leagueoflegends.com/en-us/news/game-updates/league-of-legends-patch-26-14-notes/)：普攻缩短 R 剩余回充的范围按暴击率由 2–4 秒改为 2–6 秒。官方给出端点和相关属性；区间线性插值、钳制以及取命中当前帧总值是结合原仿射公式结构采用的明确数值模型推断，符合当前项目数值抽象范围，不能写成官方逐值实现或 `mStat8` 枚举确认。26.15 的库奇条目仅为娱乐模式承伤，26.16 为魔抗，26.17 没有库奇条目。旧只读调查保留当时的未知结论，不回改历史。整英雄是否可用仍需按完整范围和最终真实工作线程证据独立判断。

## Wasm 与跨端验证

宿主把已验证整数初值冻结到真实供值状态，逐枚模式映射 `one_by_one / after_consume`，欠弹余时映射 `ammoRecovery.initialRemainingMs`。退款动作映射同供值器的 `state_duration_change / subtract`。循环映射既有整数 `state_change / set`，不新增原生操作种类。

至少覆盖：静态状态保持原编译、状态初值声明缺失/未消费/错归属/旧摘要/越界；B 不行动不索取输入；初始库存 0/1/4，余时 0/正数/过大，满弹非零拒绝；下一发位置 1/2/3，MISS 消耗推进，按冻结序号小/小/大；退款 0/刚好/超额、只有真实本方普攻命中触发、无回充时无效果；主动和普攻共存且同一库存实例；预算失败、旧事件、正反序、同会话/同工作线程反复运行以及结果模式和释放。

按各模块完成必要回归和独立复核后，统一构建正式 Wasm、同步 Web 身份并验证生产字节；最终使用真实管理数据与浏览器工作线程。旧 2 英雄、19 装备及既有机制在新产物上重新核对，不能沿用旧 Wasm 摘要的开放证明。
