## 一、场景属性快照

作者在真实本技能 `SKILL_USED / ACTIVE / INITIAL` 的 `START_PROCESS` 动作上绑定 `RUNTIME_INPUT` 参数。新增来源 `SCENE_ATTRIBUTE_SNAPSHOT`，即本次场景只读属性快照：

```json
{
  "bindingKey": "authored_snapshot",
  "parameterKey": "authored_input",
  "sourceType": "SCENE_ATTRIBUTE_SNAPSHOT",
  "detail": {
    "subject": "SOURCE",
    "attributeKey": "authored_attribute",
    "sources": ["CHARACTER_LEVEL", "EQUIPMENT_DIRECT"]
  }
}
```

- `subject` 只允许 `SOURCE / TARGET`，明确表示场景攻击方／目标方槽位，不随技能自施或实际命中目标改变。只开放攻击方真实首次主动过程消费，不开放事件来源、被动动作或外技能参数。
- `sources` 为非空、无重复的显式集合，只含 `CHARACTER_LEVEL`（所选等级的角色属性）和 `EQUIPMENT_DIRECT`（所选装备的直接属性）。允许任一子集；采集按固定来源顺序进行，不靠名称推断。
- 属性必须在真实启用目录中。仅选等级来源时，该等级必须有真实数值；仅选装备来源时不要求角色等级属性存在。装备稀疏属性中没有该键表示无贡献0，缺少完整装备属性响应不视作0。
- 不读取临时增益、装备被动、构筑、敌方光环或当前结算属性。参数没有默认值；同技能既有参数须为 `RUNTIME_INPUT`，数字类型明确。数值有限，整数参数须在实际取值及原生读取处满足安全整数要求，合法0不得当成缺失。
- 后端验证真实角色技能入口、主动过程、参数实际消费、属性引用和事务最终态；保存于现有动作数据，不新增表或列。管理时不猜实际场景值，数值型属性可供给整数参数，宿主及原生最终检查实际值。
- 宿主在准备时从本次已验证完整快照采集；装备或等级变化重新准备。绑定、来源值、作者路径和公式依赖进入覆盖记录及冻结请求，不把参数写回管理定义。

## 二、共同公式读取能力参数

原生 `FormulaRuntimeSource` 只新增 `kind=ability_parameter`，含义为该技能实际能力上已明确提供的参数。参数键沿原 `parameterKey`，不另加外部字段；禁止 `resourceKey`，包括空字符串和null。`RUNTIME_INPUT` 仍禁止 `value`。未知来源及未供值不补默认。

宿主将已验证快照值放进实际首次能力的 `params`；同一输入在 `compileSteps` 前建立读取映射。具名公式参数保留原 `RUNTIME_INPUT` 声明，使用新增来源。既有无来源运行输入继续拒绝，不能因为能力参数中碰巧有同名项就读取。

原生须保留新来源的运行参数身份，可增加内部专用读取种类，不能只降低为普通能力参数而绕过条件和跨技能门禁。共同公式只在相同实际技能上下文读取；原来禁止运行参数的条件、静态位置、外技能供值等位置继续禁止。过程时间和次数可显式消费新来源。整数声明在读取时校验，不等最终圈数检查。

过程保存本次真实首次能力；后续步骤继续沿该能力求值。进入引导时，圈数和时间沿既有机制求值并冻结；过程中临时属性变化不改变本次进度。恢复沿相同编译首次能力及已有冻结进度，不从恢复输入补造来源参数。

## 三、自动施放有限引导

自动入口在既有即时、延时、强化普攻之外，接入单步骤 `CHANNEL`（有限引导）；不顺便开放其它多步骤、重施或蓄力控制。作者必须明确总时长、次数、首段口径和行动占用；次数仍为1～64整数，超限拒绝而非截断。

每次真实步骤执行各自产生真实命中、伤害及后续事件，不提前完成过程，不只保留末圈。末圈早于完整期限时，过程仍保持到作者总时长。背景普攻继续由真实行动占用判断；引导中不可因自动轮询重新施放同技能。冷却按作者 `PROCESS_COMPLETE` 等真实时点启动；后项资格只在成功完整完成后授予一次，死亡、预算失败和中断沿原规则。

宿主请求、完整结果核对、明细／截断／汇总及页面描述须同时支持，不只放开枚举。相同身份和过程约束保持，不能用记录不完整跳过完整累计及真实冻结次数核对。
