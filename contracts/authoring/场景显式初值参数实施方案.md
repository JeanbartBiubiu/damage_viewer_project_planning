# 场景显式初值参数实施方案

2026-10-18。盖伦E、主动W、Q与R的运行矩阵已通过，但完整对象复核发现W战前永久双抗没有供值。现行W契约仍只承认主动组成，故盖伦继续禁选。这里补的是明确的本场初值，不新增击杀事件、自动增长、控制时长消费或英雄专属算法；当前W契约在本增量通过前继续有效。

## 共享约束

作者保留无默认的 `RUNTIME_INPUT` 参数。新增通用动作绑定 `SCENE_INITIAL_PARAMETER`（场景显式初值），只允许本技能的 `SOURCE_INITIALIZED` 规则通过 `EXECUTE_EFFECT`、`EVENT_SOURCE` 消费。明细只含明确的有限数值 `minValue / maxValue`，两者必填且前者不大于后者；整数参数还要求安全整数。输入必须被该动作引用的效果实际使用，不能用未消费的绑定打开其它位置读取。

本场输入按游戏、双方位置、完整来源身份、技能和参数关联；不只按名称或数组下标关联。缺失、重复、未声明、错归属、非有限数、违反整数或边界均拒绝，明确的0合法。来源停用或0级时不要求其初值，数据或来源身份改变后旧草稿不得自动匹配新声明。目标的主动不施放，不得因此裁掉同技能的自然初始化。

本轮宿主只接入角色与构筑的自然初始化；装备及所选普攻主体走各自既有装配链，遇到该声明在收集阶段明确拒绝，不先展示一个无法消费的输入。管理声明仍与所属技能关联，不从任意绑定关系猜测运行能力。

宿主将核定输入冻结到共同公式参数的 `runtimeSource: {kind: "scene_parameter", value: <本场明确值>}`，保留作者参数的 `RUNTIME_INPUT` 类型且不添加默认值。该来源禁止其它明细，包括 `resourceKey`；其它来源不能携带 `value`。原生在编译时核对有限值及作者数值类型，按既有静态求值处理；运行也读取同一冻结值。它不借用没有首次能力上下文的 `ability_parameter`，不修改作者取值方式，不伪装成角色属性。

场景输入参与准备结果、冻结档案与规则摘要。修改值必须重新准备及编译，不能沿用旧会话或旧结果；编译会话保持不可变。低层请求仍走现有编译／运行／释放，不新增战斗状态或运行事件。

## 前端

1. 先独立核验并收集已启用来源的初值声明，再做数值编译。缺值时返回带结构化声明的错误，保留真实快照供界面填值；不使用0或边界值代跑预检。
2. 混合页面在“机制初值”展示来源中文名、参数名、双方位置及真实上下界。首次留空；输入后对同一快照重新检查，必要属性及初始生命沿现有流程补全。与普攻弹药分开存储，不能把普通参数冒充弹药。
3. 常驻初始化数值状态仅接收本动作的已验证绑定。共同公式明确保留冻结来源；生命周期、条件、主动过程、外技能及未声明参数继续拒绝借用。
4. 复用现有自然初始化、属性加算与主动兄弟闭包。额外输入沿准备／规则摘要传递；切换双方、关闭来源、切游戏或换数据时复核身份与迟到响应，不跨快照恢复旧值。

## Wasm

1. 给共同公式现有运行输入来源增加窄小的 `scene_parameter`，严格限定明细形状和有限值；整数声明在原生独立校验，不能仅信任宿主。
2. 静态折叠及真正公式读取均使用同一冻结值，不增加通用读路径、状态槽或循环分支。保留所有现有来源的错误与上下文限制。
3. 初始化仍降低为现有 `SOURCE_INITIALIZED` 和常驻修正；不新建永久叠层系统，不在主动W开始时重复挂载，也不在击杀后增长。

## 管理接口与真实录入

后端只扩展现有动作JSON明细和统一保存校验，不新增表或迁移。保存及引用变更后按事务最终态检查：规则入口、效果归属、参数取值方式、实际消费和边界；参数／效果／规则更新或删除不得使旧声明悬空。枚举和接口录入说明在规划真源更新，模块生成文件沿现有入口生成。

盖伦W采用一个显式整数参数0～150，引用原 `resist_per_kill` 同时计算护甲和魔抗加算，等级固有值不改。原固定16.17客户端只证明每次0.2、上限30及对应计数公式；不按旧记忆增加满层额外比例。层数为0也必须由本场明确给出。永久效果与主动盾／减伤／韧性分离，双方均在初始化生效；不会随主动施放叠加。

- 宿主与页面：两套异名技能、双方及完整来源归属、重复与多余输入、未消费绑定、关闭与0级、输入修改后摘要／结果失效、自然和主动兄弟保留、缺值时不建立可运行请求。
