# 离线资料准备与只读对账

使用 Node.js 20 内置库，把当前工作集的待核对技能整理为可追溯的来源卡，并比较阶段账本、正式范围和正式证明的声明。工具不访问网络、数据库或管理接口，不修改账本、Wiki 原文、业务配置及证明文件，不新增依赖。

新检出使用此工具前，按[外置归档索引](../../数据参考/外置归档索引.md)恢复本机阶段账本、全英雄 Wiki 资料和审核卡。

```powershell
node tools/data-readiness/cli.mjs --repo-root . --output output/maintenance-20261028
node tools/data-readiness/cli.mjs --repo-root . --output output/maintenance-20261028 --check
node --test tools/data-readiness/readiness.test.mjs
```

`--repo-root` 指定仓库根目录，默认取工具所在仓库；`--output` 指定根目录 `output/` 下的独立子目录，也可传该子目录的绝对路径。输出不得指向资料、仓库根、仓库外或符号链接、目录联接点。生成只新建文件，相同字节可再次核对，已有不同产物会失败，需改用新输出子目录保留历史。`--check` 重新计算并核对输入、来源卡和五份已有报告，完全不写盘；报告不存在也会失败。

默认正式证明为 `server/data_manage/src/main/resources/simulation-verification/lol/combat-analysis.json`，可用 `--proof-manifest <相对仓库根的文件>` 明确选择另一份符合现行格式的本地证明。正式范围仍读 `server/data_manage/src/main/resources/simulation-scope/lol/combat-analysis.json`。工具只比较文件声明，不校验实时业务摘要、部署身份或证据引用文件，也不重跑 Wasm，不能据此认定现场可选状态。

## 口径

英雄范围只取 `阶段进度.json` 的 `heroes.priorityScope.batches[].heroes.sourceChampionId`，先筛选 `inventoryConclusions.skills`，再计算五个来源槽、整槽排除、管理完成和开放数量。旧 `selectionSnapshot`、全局覆盖统计与角色主体完成数均不作为当前技能分母。每名当前英雄须恰有五个稳定槽，重复英雄、重复技能、缺槽、无效分类及负数计数会失败。

资料核对队列包含两类未完成技能：结论为“资料待核”，以及“系统暂缓”中 `pendingCounts.source` 显式大于零的条目。已录入与明确排除条目不入队。队列保留批次顺序及同批英雄顺序，再按 P/Q/W/E/R 排列；缺少分支计数保留为空，不猜为零或自动补数。

Wiki 英雄对应只忽略稳定英文标识中的空格及标点，例如 `Chogath` 对应 `Cho'Gath`；不做模糊匹配，重名或未找到会失败。每次读取清单中全部英雄元信息、页面、技能正文和依赖，逐原文检查字节数与 SHA-256（原始字节摘要），检查技能槽引用与全量数量。错路径、丢失文件、摘要不符、版本不符分别输出明确错误代码和相对路径。

来源卡保留全部技能原文和修订号、修订时间、来源链接、固定修订链接、原文路径及摘要。一个槽对应多份正文时全部保留。等级模板、公式、触发条件、施法和命中时序、伤害注记原样保留；工具不做数字提取、模板求值、默认值推断或机制转换。Wiki 页面日期与账本固定游戏版本分别记录，不能据日期认定数值适用于账本版本。

## 产物与核对

| 文件 | 内容 |
| --- | --- |
| `queue.json` | 当前分母、分类数量、确定性资料队列与来源元信息 |
| `source-cards.json` | 队列全部来源卡、完整技能原文与清单保留的依赖元信息 |
| `source-index.json` | 输入文件摘要、全量原文字节与摘要核对清单、固定审核卡检查结果 |
| `reconciliation.json` | 逐英雄账本分类、正式范围差异、证明覆盖及需复核提示 |
| `摘要.md` | 本次快照的计数与证据边界 |

首批人工核对卡位于 `数据参考/全量录入-2026-09/资料准备-2026-10-28/review-cards.json`，只涵盖阿卡丽 P/Q/E/R。卡片固定 Wiki 清单摘要、账本固定游戏版本和每页原文；工具每次把卡片与当前重新核对的来源逐项比较。来源、修订、账本结论或范围变化会失败，需人工复核旧卡与新资料，不能直接更换摘要沿用旧结论。审核卡中的“待核对字段”是后续调查问题，不是获准写入配置。

对账提示分别保留管理配置与正式运行证明。已有 `PASSED`（通过）证明的英雄若在账本保留开放项，或者管理已完整但没有通过证明，都只提示复核日期、范围和口径；工具不判定两者冲突、不自动修改完成状态、不新增准入。声明范围中的人数、槽位与排除标记也按逐项数据比较，差异留在报告中。

测试使用临时目录中的固定合成资料，覆盖分母、完整原文、多正文槽、只读与重复核对、畸形输入、缺文件、字节和摘要漂移、固定修订变化、正式证明变化及输出路径保护；不连接真实服务。当前快照的原始报告放在被忽略的 `output/maintenance-20261028/`，不形成第二份累计账本。
