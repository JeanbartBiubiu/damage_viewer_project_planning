# 受保护管理数据批次

追加新参数、效果、过程和触发规则使用 `append-reviewed-skill-components-v3.mjs`，普通说明纠错使用 `update-reviewed-descriptions-v2.mjs`。已经执行过的旧版工具保留原字节，供原批次追溯；后续扩充另立版本，不修改已批准工具来重放旧批次。页面流程尚未稳定时，仍先按项目录入标准流程做真实页面录入，这些工具不替代该前提。

批次放在本工作树的 `数据参考` 下。`prepare` 只读固定来源和实时现值，生成完整请求、来源摘要、保护基线，并确认新对象不存在。独立评审必须绑定工具及01至04文件的原字节摘要；`write` 还要求 `DAMAGE_APPROVED_BATCH_SHA` 与获批冻结文件一致。它在请求前重核来源和现值，以独占方式建立06记录，然后逐项写入、即时回读。没有独立批准或现值漂移时停止，不在写入窗口临时改请求或跳过对象。

追加或吸血纠错写后，由独立执行者运行一次对应工具的 `readback`；普通说明纠错 v2 使用 `node tools/authoring/read-reviewed-description-updates.mjs <批次目录>`。后者仅发送GET并输出报告，先核对批准、来源、冻结文件和成功写入记录，再检查全部受保护响应；调用方保留完整输出和退出码，不覆盖既有07文件。它不支持旧版说明批次，旧证据按原工具追溯。

独立回读核对完整目标、预期集合变化和原响应（含时间戳）。参数列表包含完整参数值，不能照效果摘要删掉字段来比较；同一列表多个目标行按各自标识核对，列表与详情的说明及更新时间必须一致。原始工具输出须完整保留；若报告另加封装，汇总程序先取封装中的原始输出再解析，不改动原报告或重新发请求来适配报告格式。

中断、超时或06记录已经存在时，先用纯读取确认实际落地范围，不能从头重放。即时回读、独立接口回读、实库核对、页面验收及战斗运行分别记录；工具通过不代表未执行的页面或运行验证通过。

状态目录首次页面录入使用 `reviewed-status-ui.mjs` 的 `prepare`、`preflight` 和 `readback`。它只发送GET，保护原目录、详情及时间戳，业务保存仍在页面完成。保存结果未知时先读取目标详情核对完整冻结正文，在06中如实记录恢复查询及未捕获的响应，再由独立执行者回读；不能重复点击保存，也不能把查询响应写成新增请求的响应。

为原无条件的自身技能命中规则补齐本轮敌方英雄范围时，使用 `reviewed-hit-scope-ui.mjs` 的同名三个只读步骤，再在页面更新原规则。它仅允许增加英雄类别与明确敌方的同组条件，保留原事件、动作和其他字段，核对规则列表及全部原技能组成；不提供接口写入模式。依赖该范围的伤害效率等后续纠错，必须等此次独立回读通过后再以新现值准备。

新版本在解析响应前记录请求方法、路径与响应状态，因此响应正文损坏时仍保留写入尝试和响应证据。说明纠错即时回读只允许更新时间变化，创建时间和其他字段仍须一致；独立回读继续检查完整现值和允许的列表变化。

`update-reviewed-damage-vamp.mjs` 只用于已核定普通魔法技能伤害的空吸血规则纠错：目标必须只有一个直接伤害结果，补入明确的全能吸血资格并更新父说明。伤害数值、公式、暴击、法术护盾粒度和其余组成均保持原值；其他结构不在此工具范围内。它也执行完整冻结、逐笔现值保护和独立回读。写入尝试及响应审计先于响应解析保存；解析失败仍须先查已落地状态，不重放。
