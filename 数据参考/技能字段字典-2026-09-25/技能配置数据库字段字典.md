## 怎样阅读

1. **先看物理字段索引**：完整列出当前28张管理逻辑表的219个列。技能核心组成、挂载、引用表排在前面；属性等依赖目录随后；外层角色、装备、符文和图片放在后面，仅作为关联上下文。实际游戏分区子表不重复计数，用户库及任务治理库不属于技能数据。
2. **再看结构化字段**：公式、效果、过程、状态和触发规则的JSON内部字段逐项展开。仅知道某列是JSON对象或数组，不等于已经知道技能怎么配置。
3. **区分三层约束**：数据库直接执行的主键、外键、CHECK；管理服务和提交前执行的业务校验；运行时应当实现但本次未验证的行为。后两层不能从DDL单独推导。
4. **枚举与目录键不同**：`resultType`、`stepType`等是固定枚举；`attributeKey`、`damageTypeKey`、`skillCategoryKey`等引用同游戏目录，不是写死的中文名字枚举。
5. **物理列与接口字段不同**：SQL通常使用下划线，JSON内部通常使用驼峰。比如`effect_bindings`对应`effectBindings`；触发规则的`limits`是存储对象，但接口把三项限制放在规则顶层。各章说明具体位置。

本字典用`[]`表示数组中的任一元素，用`{等级}`、`{属性键}`表示对象的动态键。共用数值对象单独定义，各使用位置再说明毫秒、次数或比例等单位。

## 共用数值取值对象

效果的`valueRule.value`、期限、层数、过程时长、状态初始值、条件比较值等使用同一取值协议。它自身不是一张表，而是嵌入JSON中的小对象。

| 字段 | 类型、枚举与约束 | 作用和预期表达 |
| --- | --- | --- |
| `kind` | 必填字符串；`FIXED`、`PARAMETER`、`FORMULA`。 | 决定从哪个来源取数值。 |
| `value` | 仅`FIXED`必填JSON数字；不能同时出现另外两个引用字段。 | 直接使用该固定数值。`0`和负数是否可用由具体位置决定。 |
| `parameterKey` | 仅`PARAMETER`必填，格式为`^[a-z][a-z0-9_]{0,63}$`；引用当前技能参数。 | 读取固定、等级或由动作提供的计算时参数。 |
| `formulaKey` | 仅`FORMULA`必填，同样格式；引用当前技能公式。 | 执行该公式得到数值。 |

每种对象必须恰好含`kind`及其对应的一个字段；不能用另两个字段为`null`来充数，也不能混入额外字段。整个取值对象能否为空由它所在字段决定。底层使用十进制数值类型，不提供“未知即为0”的默认值。来源：[数值协议及严格解析](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/model/value/SkillNumericValue.java:11)。

合法例子：

```json
{"kind":"FIXED","value":4000}
{"kind":"PARAMETER","parameterKey":"shield_duration_ms"}
{"kind":"FORMULA","formulaKey":"total_shield"}
```

**单位不由`INTEGER/DECIMAL`决定。** 当前参数表和属性表都没有单独的单位列。时长位置按毫秒，次数/层数位置按整数，明确的比例字段通常以`1=100%`表达；但一般DECIMAL参数也可能表示伤害量等，不能一律按百分比显示。是否要求非负、正数、整数、静态可知或上限1，必须读取具体使用位置的校验。

## `skill_formulas.expression`：公式树

公式根节点及每个子节点只能是下面三种对象。公式引用本技能参数和同游戏属性；当前树中没有公式引用节点、数值字面量节点或条件分支节点。可调整数值经参数输入；效果数值取值的`FORMULA`是在调用完整公式，与公式树内部节点种类不同。

| 节点及路径 | 类型、枚举和组合限制 | 预期表达 |
| --- | --- | --- |
| 任意节点`.nodeType` | 必填种类：`OPERATION`运算、`PARAMETER`参数、`ATTRIBUTE`属性。 | 决定节点其余字段形状。 |
| 运算节点`.operation` | `ADD`相加、`SUBTRACT`前项减后项、`MULTIPLY`相乘、`DIVIDE`前项除后项、`MIN`取较小值、`MAX`取较大值。 | 四则运算及上下限组合；不是任意脚本语言。 |
| 运算节点`.operands` | 必填数组，必须恰好两个有序子节点；递归使用本表节点类型。 | 表达左右操作数，尤其减法/除法不得交换顺序。 |
| 参数节点`.parameterKey` | 必填当前技能参数键。 | 引用固定值、等级值或计算时输入。 |
| 属性节点`.attributeOwner` | 必填`SOURCE`来源对象或`TARGET`目标对象。 | 指定读取哪一方的属性；具体目标上下文由执行入口确定，不能从属性名推断。 |
| 属性节点`.attributeKey` | 必填同游戏属性键。 | 指定读取生命、攻击力、法强等目录属性。 |
| 属性节点`.attributeValueKind` | 必填，下表七种取值。 | 指定读取基础、加成、总值或当前资源等口径。 |

| `attributeValueKind` | 期待的取值口径 |
| --- | --- |
| `BASE` | 基础属性值。 |
| `BONUS` | 额外/加成属性值。 |
| `TOTAL` | 合成后的总属性值。 |

## 引用索引和约束由谁执行

`skill_object_references`是系统派生索引，不是作者手工填写的“联动配置”。它从公式、效果、状态、过程、触发规则的已知字段提取引用，始终带技能键和父对象键定位子项。

- `source_type`五种：`FORMULA`、`EFFECT`、`STATE`、`PROCESS`、`TRIGGER`。
- `target_type`十六种：`ATTRIBUTE`、`PARAMETER`、`FORMULA`、`SKILL`、`CATEGORY`、`DAMAGE_TYPE`、`MODIFIER_ZONE`、`STATUS`、`EFFECT`、`RESULT`、`LIFECYCLE`、`STATE`、`OPTION`、`PROCESS`、`STEP`、`ACTION`。各值中文含义见物理字段表。
- `target_skill_key`和`target_sub_key`在不适用时使用空字符串，不使用NULL；同名子项必须结合父键判断，不能只按resultKey等局部键识别。
- 通过管理接口写入时，服务要求真实可写事务和“读取已提交”隔离级别，先锁定当前游戏行；提交前读取最终聚合，检查引用和相关数值/组合，再整体重建该游戏的引用索引。失败与原对象写入共同回滚。
- 数据库仅有根对象外键、普通列CHECK和JSON形状CHECK。JSON中的每个子引用并没有各自SQL外键；直接改数据库不会自动执行Java服务的完整校验。
- 缺失最终引用使用`409.SKILL_OBJECT_REFERENCE_INVALID`；数值语义使用其既有400类错误；其他直接形状/业务错误按所属服务分类，不能把所有拒绝都简化成同一种错误。

### 数值与运行证据边界

本章记录现行管理配置的字段字典及其**期望表达的行为**。后端负责保存、校验和回读，不执行事件、条件或动作；表单及宿主中的局部能力不能据此推定完整战斗运行已通过。字段路径中的 `i`、`j`、`k` 是数组下标；对象键和枚举值保留接口原名。来源：[后端说明](/C:/project/damage_backend_dev/server/data_manage/README.md:3)、[请求与详情模型](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/model/skilltrigger/SkillTriggerRuleDetailResponse.java:5)。

### 存储形状与读写边界

数据库 `skill_trigger_rules` 中，`event_source` 是必填对象，`condition_groups`、`actions` 是必填数组，`limits` 是必填对象；独立 `event_type` 列与 `event_source.eventType` 同次写入，用于列表与索引。管理接口采用小驼峰字段：`eventSource`、`conditionGroups`、`actions`，并把 `limits.perTargetCooldown`、`limits.maxTriggersPerProcess`、`limits.oncePerUse` 平铺成详情及写入请求的三个顶层可空字段。保存时条件组按 `sortOrder, groupKey`，组内条件按 `sortOrder, conditionKey`，动作按 `sortOrder, actionKey` 排列；绑定按 `bindingKey`、结果修正按 `resultKey` 排列。`conditionGroups=[]` 允许，表示无附加条件；一旦建立条件组，组内至少一个条件。页面的配置语义为组间“任一”、组内“全部”。来源：[建表](/C:/project/damage_backend_dev/db/game_manage/schema.sql:537)、[JSON 类型约束](/C:/project/damage_backend_dev/db/game_manage/schema.sql:678)、[持久化映射](/C:/project/damage_backend_dev/server/data_manage/src/main/resources/mapper/skilltrigger/SkillTriggerRuleMapper.xml:640)、[组装排序](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/service/skilltrigger/SkillTriggerRuleAssembler.java:11)、[空条件与去重](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/service/skilltrigger/SkillTriggerRuleService.java:874)、[页面条件说明](/C:/project/damage_web_dev/web/src/pages/admin/skills/triggers/triggerRuleForm.ts:97)。

嵌套数值取值统一为严格互斥对象：`{kind:"FIXED",value:十进制数}`、`{kind:"PARAMETER",parameterKey:参数键}` 或 `{kind:"FORMULA",formulaKey:公式键}`。键格式均为小写字母开头，后接小写字母、数字或下划线，总长 1～64；参数、公式只引用当前技能。触发事件阈值、条件比较值与限制数值禁止依赖计算时传入参数。通用数值检查会对固定值、固定参数及可枚举的等级参数逐值复核字段边界；普通公式在此处只检查引用与计算时输入依赖，不求公式结果，也就不能凭保存成功断定其结果满足正数或整数要求。下文数值范围是配置应满足的语义；未求值的公式不补默认值。来源：[数值对象](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/model/value/SkillNumericValue.java:11)、[触发数值约束](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/support/authoring/SkillNumericSemantics.java:242)、[通用边界检查](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/support/authoring/SkillNumericSemantics.java:273)、[已知数值来源](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/support/authoring/SkillNumericSemantics.java:316)。
