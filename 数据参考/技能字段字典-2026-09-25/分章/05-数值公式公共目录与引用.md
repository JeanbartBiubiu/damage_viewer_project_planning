## 共用数值取值对象

效果的`valueRule.value`、期限、层数、过程时长、状态初始值、条件比较值等使用同一取值协议。它自身不是一张表，而是嵌入JSON中的小对象。

| 字段 | 类型、枚举与约束 | 作用和预期表达 |
| --- | --- | --- |
| `kind` | 必填字符串；`FIXED`、`PARAMETER`、`FORMULA`。 | 决定从哪个来源取数值。 |
| `value` | 仅`FIXED`必填JSON数字；不能同时出现另外两个引用字段。 | 直接使用该固定数值。`0`和负数是否可用由具体位置决定。 |
| `parameterKey` | 仅`PARAMETER`必填，格式为`^[a-z][a-z0-9_]{0,63}$`；引用当前技能参数。 | 读取固定、等级或由动作提供的计算时参数。 |
| `formulaKey` | 仅`FORMULA`必填，同样格式；引用当前技能公式。 | 执行该公式得到数值。 |

每种对象必须恰好含`kind`及其对应的一个字段；不能用另两个字段为`null`来充数，也不能混入额外字段。整个取值对象能否为空由它所在字段决定。底层使用十进制数值类型，不提供“未知即为0”的默认值。来源：[数值协议及严格解析](/C:/project/damage_backend_dev/server/data_manage/src/main/java/xyz/game/datamanage/model/value/SkillNumericValue.java:11)。

合法例子：

```json
{"kind":"FIXED","value":4000}
{"kind":"PARAMETER","parameterKey":"shield_duration_ms"}
{"kind":"FORMULA","formulaKey":"total_shield"}
```

**单位不由`INTEGER/DECIMAL`决定。** 当前参数表和属性表都没有单独的单位列。时长位置按毫秒，次数/层数位置按整数，明确的比例字段通常以`1=100%`表达；但一般DECIMAL参数也可能表示伤害量等，不能一律按百分比显示。是否要求非负、正数、整数、静态可知或上限1，必须读取具体使用位置的校验。

## 技能参数的四种模式

| `value_mode` | `fixed_value` | `level_values` | 预期用途与后端约束 |
| --- | --- | --- | --- |
| `FIXED` 固定值 | 必填 | 必须NULL | 所有等级使用一个值。INTEGER类型必须数学上是整数。 |
| `SKILL_LEVEL` 按技能等级 | 必须NULL | 必填对象 | 必须完整覆盖当前技能`1..max_level`，不能缺级、越界或带空值。 |
| `CHARACTER_LEVEL` 按角色等级 | 必须NULL | 必填对象 | 必须完整覆盖游戏等级配置的`min_level..max_level`。 |
| `RUNTIME_INPUT` 计算时输入 | 必须NULL | 必须NULL | 仅声明输入身份及INTEGER/DECIMAL类型；实际值通过执行动作的供值绑定取得，不能在此填默认值或模拟成等级曲线。 |

`level_values`的键是十进制正整数字符串，正则`[1-9][0-9]*`，例如`"1"`、`"18"`；不是`"01"`、小数或任意标签。值是数值；INTEGER检查使用去尾零后的小数位判定，因此`1.0`按数值等于整数1处理。参数基础定义没有统一“必须非负”要求；被冷却、次数、比例等位置引用时，会受到对应用途的更严格校验。

## `skill_formulas.expression`：公式树

公式根节点及每个子节点只能是下面三种对象。公式引用本技能参数和同游戏属性；当前树中没有公式引用节点、数值字面量节点或条件分支节点。可调整数值经参数输入；效果数值取值的`FORMULA`是在调用完整公式，与公式树内部节点种类不同。

| 节点及路径 | 类型、枚举和组合限制 | 预期表达 |
| --- | --- | --- |
| 任意节点`.nodeType` | 必填种类：`OPERATION`运算、`PARAMETER`参数、`ATTRIBUTE`属性。 | 决定节点其余字段形状。 |
| 运算节点`.operation` | `ADD`相加、`SUBTRACT`前项减后项、`MULTIPLY`相乘、`DIVIDE`前项除后项、`MIN`取较小值、`MAX`取较大值。 | 四则运算及上下限组合；不是任意脚本语言。 |
| 运算节点`.operands` | 必填数组，必须恰好两个有序子节点；递归使用本表节点类型。 | 表达左右操作数，尤其减法/除法不得交换顺序。 |
| 参数节点`.parameterKey` | 必填当前技能参数键。 | 引用固定值、等级值或计算时输入。 |
| 属性节点`.attributeOwner` | 必填`SOURCE`来源对象或`TARGET`目标对象。 | 指定读取哪一方的属性；具体目标上下文由执行入口确定，不能从属性名推断。 |
| 属性节点`.attributeKey` | 必填同游戏属性键。 | 指定读取生命、攻击力、法强等目录属性。 |
| 属性节点`.attributeValueKind` | 必填，下表七种取值。 | 指定读取基础、加成、总值或当前资源等口径。 |

| `attributeValueKind` | 期待的取值口径 |
| --- | --- |
| `BASE` | 基础属性值。 |
| `BONUS` | 额外/加成属性值。 |
| `TOTAL` | 合成后的总属性值。 |
| `CURRENT` | 属性的当前值；用于生命、法力等当前资源。 |
| `MISSING` | 已损失值；需要运行侧有明确的当前值与总量/上限口径。 |
| `CURRENT_RATIO` | 当前值占总量/上限的比例，生命门槛等使用这一口径。 |
| `MISSING_RATIO` | 已损失值占总量/上限的比例。 |

### 战斗状态与内部状态的区别

`statuses`是同游戏战斗状态目录。`status_kind`固定为`STUN`眩晕、`MOVEMENT_SLOW`普通移动减速、`ROOT`禁锢、`SILENCE`沉默、`CHARM`魅惑、`AIRBORNE`击飞；种类创建后不可改。效果结果的`STATUS_OPERATION`选择施加或移除该状态。持续时间、层数和数值强度由效果承载，而非目录承载。

## 引用索引和约束由谁执行

`skill_object_references`是系统派生索引，不是作者手工填写的“联动配置”。它从公式、效果、状态、过程、触发规则的已知字段提取引用，始终带技能键和父对象键定位子项。

- `source_type`五种：`FORMULA`、`EFFECT`、`STATE`、`PROCESS`、`TRIGGER`。
- `target_type`十六种：`ATTRIBUTE`、`PARAMETER`、`FORMULA`、`SKILL`、`CATEGORY`、`DAMAGE_TYPE`、`MODIFIER_ZONE`、`STATUS`、`EFFECT`、`RESULT`、`LIFECYCLE`、`STATE`、`OPTION`、`PROCESS`、`STEP`、`ACTION`。各值中文含义见物理字段表。
- `target_skill_key`和`target_sub_key`在不适用时使用空字符串，不使用NULL；同名子项必须结合父键判断，不能只按resultKey等局部键识别。
- 通过管理接口写入时，服务要求真实可写事务和“读取已提交”隔离级别，先锁定当前游戏行；提交前读取最终聚合，检查引用和相关数值/组合，再整体重建该游戏的引用索引。失败与原对象写入共同回滚。
- 数据库仅有根对象外键、普通列CHECK和JSON形状CHECK。JSON中的每个子引用并没有各自SQL外键；直接改数据库不会自动执行Java服务的完整校验。
