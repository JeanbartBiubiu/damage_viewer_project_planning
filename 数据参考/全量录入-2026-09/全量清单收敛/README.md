# 全量清单收敛

本目录保存把历史来源清单与当前实库、批次证据对齐时使用的只读检查器和回读证据。逐项结论唯一写入 `../阶段进度.json` 的 `inventoryConclusions`，本目录不建立第二份状态账。

当前先收敛角色主体层：171 个范围内角色必须逐项匹配当前角色、完整 1～18 级属性、5 项角色技能关系和启用代表图；厄斐琉斯、塞拉斯沿既定边界明确排除。技能机制结论另在技能层收敛，不能用角色主体完成替代。

执行顺序：

1. 临时生成非空 `DAMAGE_ENTRY_TOKEN`，运行 `node 核对角色清单.mjs readback`，只发 GET 并生成 `角色清单当前回读证据.json`。
2. 主负责人检查来源散列、685 次请求、零差异和排除边界。
3. 运行 `node 核对角色清单.mjs integrate`，只机械更新 `阶段进度.json` 中的角色逐项结论和覆盖计数。
4. 运行 `node 核对角色清单.mjs check-stage`，重新核对173个来源键、结论枚举、实库映射、覆盖计数和证据散列。

脚本不保存或输出令牌。技能、装备和符文覆盖保持“未收敛”直到各自完成真实映射，不能因为角色层已完成而把总账标为完成。

技能分阶段收敛使用 `核对技能清单第一阶段.mjs`。第一阶段只处理阶段进度中能用已批准候选原始字节散列唯一定位的31批、550个范围内技能，并加入两个排除角色的10个技能槽；其余305个范围内技能明确保持未收敛。候选还有来源缺口时归“资料待核”，只有配置或系统缺口时归“系统暂缓”，全部组成为空且候选只含完整范围排除时归“明确排除”。这只是当前唯一结论的第一阶段，不把未覆盖项默认归类。

```powershell
$env:DAMAGE_WEB_ROOT='C:\project\damage_web_dev'
$env:DAMAGE_ENTRY_TOKEN=[guid]::NewGuid().ToString('N')
node 核对技能清单第一阶段.mjs readback
Remove-Item Env:DAMAGE_ENTRY_TOKEN
node 核对技能清单第一阶段.mjs integrate
node 核对技能清单第一阶段.mjs check-stage
```

技能第二阶段使用 `核对技能清单第二阶段.mjs`，扩大到文件名包含“候选”且顶层确有技能对象的证据。它排除第一阶段已有批次，再以批准散列唯一命中9批、140个技能；执行顺序仍是 `readback`、`integrate`、`check-stage`，同样要求临时 `DAMAGE_WEB_ROOT` 与 `DAMAGE_ENTRY_TOKEN`。
