## 录入过程发现的问题

1. **可保存与语义正确容易混淆。** 属性字典和兼容修正区均存在时，页面仍无法证明多来源组合规则。韧性、减速抗性和百分比移速必须先核组合口径；本批仅保存候选参数，留空效果与规则。
2. **百分数存在两层含义。** `bonus_attack_speed_percent` 已经是比例属性，对它使用固定加算 0.10 才是加 10 个百分点；再选百分比修正会改变语义。录入流程应先确认目标属性单位，再选修正区。
3. **相同“已启用”不能说明完成度。** 只有参数的技能也可启用、挂载，容易被误认作机制完整。本批在候选范围与说明中单独标记参数阶段，计数不并入 3 个完整配置。
4. **资料名称、图标文件名不能替代数值。** 5011 的图标路径含 Scaling，但原文是固定 65；5007 图标也含 Scaling，原文仍是固定 8。5001 与 5008 的 tooltip 含占位，不能凭文件名、端点范围或常识补公式。
5. **挂载查询有来源前置条件。** 无来源过滤查询会返回 400；给定尚不存在符文的键返回 404。只读工具已使用明确 runeKey；录入者应先确认身份存在再挂载，超时后按稳定键回读，避免误以为失败而重复创建。

根验收脚本首次回读将关系列表误按单对象比较、又将效果数组误按分页对象比较，均为只读核对脚本错误；修正解析后19项全部通过，没有因此重写业务数据。接口返回结构应以实际契约为准，不能把核对程序异常直接记成系统录错。

本批证据覆盖冻结资料、单位与独立算例、管理接口保存及回读、代表页面；原候选文件的“未写入”等标记描述准备时点。当前配置不实现玩家选择装配，也未执行战斗运行。
