## 资料到表单映射（准备所见，非保存后体验）

只读核对了标准流程、候选 JSON、官方原始 `name`/`title`，以及独立页上的角色管理表单。未完成一次真实保存，下列判断不能当成回读结论。

角色主体三个字段直观：角色标识、角色名称、说明。稳定标识应为 `champion_malphite`、`champion_missfortune`。官方原始 `name` 是称号（熔岩巨兽、赏金猎人），`title` 才是中文姓名（墨菲特、厄运小姐）；角色名称应填后者。说明必须写来源版本、只含基础自然成长、技能和图片待录，不能写成已完整录入。建议文案已写入清单 JSON。

属性映射按任务约定，候选 10 项均有对应系统标识，无缺失项可编造：

| 来源字段 | 系统标识 | 生成方式 |

资料侧成长不是等差数列，页面「每级递增」不能用来展开生命值、护甲、攻速等。常量移速和攻击距离用「固定」即可。攻速必须贴候选里的次/秒序列，不能改贴成长百分比或收益系数。

资料文件把 `systemAttributeKey` 留空，要靠任务给定映射才能对上表单搜索框里的属性标识。这一步对未读过任务说明的维护者不够直白。

## 计划操作步骤与重复劳动

若登录可用，每名英雄的页面步骤是：

1. 用标识和中文名、称号分别查询，确认无重复后再新增。
2. 填写标识、名称、说明并保存主体。
3. 打开「等级属性」父弹窗。
4. 对非常量属性：搜索标识 → 设置/编辑 → 选「逐级录入」→ 粘贴 18 个数 → 应用。
5. 对移速、攻击距离：选「固定」→ 填 1 级值 → 应用。
6. 保存父弹窗，关闭后重开，按属性逐格核对 18 个数。

重复劳动明显：10 个属性要分别打开子弹窗；非线形成长不能一次按成长值生成；保存父对象后必须整表重开才能当回读。两名英雄大约 20 次属性弹窗加两次父级保存。此批未实际做到这些点击。

## 工具限制与产品问题

工具限制（不是产品缺陷）：

- 本会话没有可驱动「已授权浏览器」的页面工具。
- 本机 Chrome 未开远程调试，不能在不复制令牌的前提下接管已登录会话。
- 独立 Playwright 页是新上下文，没有本地已保存 Token。
- 授权禁止读取 localStorage/Cookie、禁止把 Token 填进新页面、禁止直接调业务 API 或 SQL 写入。

产品观察（与本次停写无关，不据此声称保存失败）：

- 无 Token 时刷新和查询被禁用，但「新增角色」仍可点；按代码，保存时才会提示配置 Token。本次没有去点。
- 无 Token 时列表显示「暂无角色」，容易被误认成库空。这是未授权会话的展示，不是删除证据。
- 候选 JSON 不带系统属性标识，要另表映射才能在「搜索属性」里找到 `hp_regen`、`magic_resistance` 等。
