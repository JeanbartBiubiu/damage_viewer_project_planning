# 赫卡里姆 W 双抗触发录入体验报告

本批从候选中只保留一项真正可写分支，没有为满足批次数量加入资格不明对象。固定来源与实库均确认，赫卡里姆主动使用恐惧之灵后获得持续 4000 毫秒的护甲和魔法抗性；持续伤害、治疗、周期、法力和冷却仍明确暂缓。

## 操作与耗时来源

- 写前准备：1223 次 GET，包含一次 1062 技能规则目录、旧 130 条规则详情及目标全部组成；进程约 6 秒。
- 受保护写入：32 次定点 GET、1 次 POST 和即时回读；进程约 3 秒。没有重放，也没有进入恢复分支。
- 独立回读：新的 Luna Max 使用 1222 次 GET，重新读取 1062 项技能、131 条规则详情和目标组成；旧 130 条规则零差异。
- 真实页面：Playwright Chromium 使用 174 次 GET，核对一张 64×64 列表图、两项属性结果和一条两动作规则；4 张截图，页面错误、控制台错误、失败请求、错误响应和业务写入均为零。

写入器没有重复全量基线，只做目标定点保护；完整最终集合由独立回读重新取得。全量图片同步占页面请求的大部分，但它只更新浏览器本地缓存，没有服务端业务写入。

## 字段歧义与错误恢复

- 规则动作的目标上下文显示“当前目标”，但两个效果结果的目标均固定为“来源对象”，因此实际增加赫卡里姆自身双抗。冻结、回读和页面都同时核对这两层，不能只看动作目标。
- 来源正文把双抗、持续伤害和伤害治疗写在同一技能中；现有双抗效果并不证明周期伤害、附近目标或实际伤害快照已经成立。本批只接入主动即得的独立双抗。
- 首次后端启动失败于 Java 本机选择器的 Unix 域套接字回连。复现确认不是业务代码或数据库后，仅为本次进程设置不存在的 `jdk.net.unixdomain.tmpdir`，让 JDK 回退到 TCP 回环；没有修改系统配置或仓库文件。随后 8080 服务和真实接口正常。
- 业务写入没有超时、断线或部分成功；若发生异常，执行器只回读 `hecarim_w/on_used` 稳定键，不自动重放 POST。

## 手工查找与后续方式

固定候选位于 `交叉试录/主负责人/英雄机制第二十七批/完整候选.json`，对应客户端 16.17 和官方中英文 16.17.1 原文位于该批输入包。页面手工入口为技能管理中查询 `hecarim_w`，依次打开“效果与结果”和“条件与触发”。

这种已有自身效果的低风险主动接线已经适合 API 批量方式：使用一次共享全量基线、定点写入保护、一次独立完整回读和代表页面验收。候选语义筛选仍需人工或 Luna Max 逐项完成，不能把“效果已存在”机械转换为规则。

## 证据边界

本批证明管理数据已保存、真实接口可回读、页面可展示。规则尚未组装进 Wasm 输入，宿主主动使用事件与真实战斗结算未执行；不能据此宣称恐惧之灵完整机制完成。
