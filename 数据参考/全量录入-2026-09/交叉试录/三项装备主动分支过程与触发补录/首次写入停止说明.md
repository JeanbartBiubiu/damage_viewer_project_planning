# 首次写入停止说明

唯一写入窗口的首个请求是创建救赎 `actual_hit` 规则。接口返回 HTTP 400，即时回读仍为 404，脚本在另外六个请求之前停止。随后六个定点 GET 确认救赎规则、水银弯刀过程与规则、中娅沙漏过程与规则均为空，因此本次尝试没有业务数据落地，也没有重放请求。

根因是救赎现有公式引用 `actual_target_max_health` 计算时传入参数。触发规则保存校验要求所有可达计算时传入参数都有合法绑定，但技能命中事件当前只提供命中序号和法术护盾结果，无法绑定目标最大生命。后端拒绝是正确保护行为。

当前公式模型已经用 `TARGET`、`hp`、`TOTAL` 表示目标总生命属性，例如内瑟斯 R 的目标最大生命伤害。因此修订方案不扩充事件协议，也不增加新表：把救赎公式改为直接读取目标总生命，随后删除失去引用的运行时参数，再重新冻结完整请求。水银弯刀和中娅沙漏仍沿用原候选；原请求不再使用。
