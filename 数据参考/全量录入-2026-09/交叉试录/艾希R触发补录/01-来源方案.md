# 艾希 R 触发补录来源方案

## 目标

为已经录入的 `ashe_r` 接入一次实际命中规则：

- 规则键：`actual_hit`。
- 事件：`SKILL_HIT`，事件来源技能键 `ashe_r`。
- 条件：`TARGET_CATEGORY_CHECK`，类别只有 `CHAMPION`。
- 动作：在 `CURRENT_TARGET` 上执行已有 `hit_damage`。
- 触发限制：`perTargetCooldown` 与 `maxTriggersPerProcess` 均为 `null`。

这是严格 1V1 范围下可证明的最小接线。事件只消费运行时已经确认的实际命中，不用施放过程代替命中，也不把箭的飞行、伤害范围或控制效果自行推导出来。

## 固定来源

版本固定为客户端 16.17、官方静态资料 16.17.1。主要来源由只读脚本再次计算散列并写入 `03-来源快照.json`：

1. 艾希技能候选和已有参数、公式、效果：规划工作树 `艾希技能实录第一批/录入候选.json`。
2. 客户端 R 主对象：规划工作树 `艾希拉克丝客户端补证/ashe.bin.json`，路径为 `Characters/Ashe/Spells/EnchantedCrystalArrowAbility/EnchantedCrystalArrow`。
3. 官方中文技能说明：规划工作树 `英雄/原始资料/zh_CN/champion/Ashe.json` 的 `EnchantedCrystalArrow`（艾希 R）。
4. 已有管理数据的历史回读：`艾希技能实录第一批/实录回读.json` 和 `独立核对.json`，只用来追溯已保存组成，不覆盖当前接口现值。

客户端资料同时包含 `MinStunDuration`、`MaxStunDuration`、`SlowRadius`、弹道与附近目标相关字段，但现有作者数据只有眩晕上下界参数，没有距离输入、控制结果或附近目标效果。因而本批只接已有一次魔法伤害 `hit_damage`；`mana_cost` 属于施法资源，不能由命中规则重复执行。

## 当前组成核对

脚本必须从实时 GET 核对：

- `ashe_r` 主体、艾希主体、角色技能关系和双方代表图片均为 200；
- 现有参数、公式、效果、过程、内部状态和触发规则列表及所有详情均可读；
- 效果键只有 `hit_damage`、`mana_cost`，其中 `hit_damage` 只有一个 `DAMAGE` 结果，目标为 `TARGET`，伤害类型为 `magic`，公式为 `hit_damage`；
- `hit_damage` 公式实际读取 `base_damage`、`ap_ratio` 和来源总法强；
- 候选详情 `/skills/ashe_r/trigger-rules/actual_hit` 返回 404，目标规则列表当前为空；
- 全局 1062 个技能、96 条触发规则及全部旧规则详情保持一致，第二轮键集合与第一轮一致，`SOURCE_INITIALIZED` 仍为 24。

## 严格 1V1 边界与停止条件

本批不录入：眩晕和距离驱动的持续时间、附近单位伤害和减速、弹道与视野、法力消耗、冷却以及无法由现有字段完整表达的护盾交互。若实时效果缺失、出现未知结果、规则列表已有同键不同内容、候选详情不是 404、全局旧规则详情或两轮键集合不稳定，状态为 `REVISE`，不产生任何 POST。

静态来源、接口 GET 和本准备脚本只能证明作者数据及接线请求具备保存条件，不能证明 TinyGo 或战斗运行时真的发出命中事件。
