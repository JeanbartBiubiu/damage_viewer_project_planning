# 崔丝塔娜 W 本人击杀英雄重置补录

本目录记录 `tristana_w` 冷却重置的来源判定、作者契约修正、一次真实写入、两路接口回读和代表页面验收。固定资料说明完整机制包含参与英雄击杀和在英雄身上引爆满层爆炸火花；本次只保存当前系统能够准确表达的“本人完成英雄击杀”子集。

## 实际结果

- 写前读取技能组成及待新增规则详情共 10 次，确认 `reset_jump` 效果和 `actual_hit` 规则已经存在，`own_kill_reset` 尚不存在。
- 作者契约允许 `KILL` 事件使用目标类别条件后，只新增一次 `own_kill_reset`，接口返回 201；条件限定当前被击杀对象为英雄，动作复用 `reset_jump`。
- 写入者即时回读 11 次；Luna Max 随后独立回读 11 次。新规则唯一且字段一致，既有 `actual_hit`、`reset_jump` 和施放过程未被改写。
- 真实浏览器在 `#/skills` 筛选 `tristana_w` 后，列表左侧代表图片可见；规则列表和重新打开的详情均显示“来源对象完成击杀”“事件目标类别 / 英雄”和冷却重置动作。
- Cursor 本地代理对第 2 版作者契约修正方案做了只读评审，结论为可以实施且没有阻塞项。

## 录入边界

本次没有把本人击杀扩大为参与击杀，也没有把爆炸火花满层引爆挂到任意击杀。助攻参与和满层爆炸的因果联动仍需各自具备准确事件后再补录。接口保存、独立回读和页面显示不证明战斗运行时已经生产或执行击杀事件。

## 体验记录

- 目标类别条件原先只允许技能命中和普攻命中，导致既有“击杀事件当前目标为被击杀对象”契约无法在管理页使用。本批已修正作者契约、界面名称和说明，没有改数据库结构或运行时协议。
- 页面自动化首次读取旧构建目录，重新构建后同一用例通过。实际页面验收前应确认预览产物与当前源码一致。
- Luna Max 发现无内部状态时接口返回 JSON `null`。本批写入和页面没有受影响；该返回形状是否属于稳定契约正在单独核查，不把它混入本次数据写入。
