# 英雄装备四项触发补录

本目录为四条触发规则的合并受保护录入材料：艾希 R、内瑟斯 E、火箭腰带主动和锐雯 E。纯读取准备已经完成：2508 次接口读取得到 2500 次成功响应和 8 次预期候选不存在响应，确认当前为 1062 个技能、100 条规则、24 条 `SOURCE_INITIALIZED`，两轮旧规则列表与详情稳定，四个候选均未存在，业务写入数为 0。

本批写前基线为 1062 个技能、100 条规则、24 条 `SOURCE_INITIALIZED`。四次新增已经完成，终态为 1062 个技能、104 条规则、24 条 `SOURCE_INITIALIZED`。

| 项目 | 事件来源 | 条件 | 动作 |
| --- | --- | --- | --- |
| `ashe_r/actual_hit` | `SKILL_HIT`，`sourceSkillKey=ashe_r` | `TARGET_CATEGORY_CHECK` 为 `CHAMPION` | `CURRENT_TARGET` 执行 `hit_damage` |
| `nasus_e/actual_initial_hit` | `SKILL_HIT`，`sourceSkillKey=nasus_e` | `TARGET_CATEGORY_CHECK` 为 `CHAMPION` | `CURRENT_TARGET` 执行 `initial_damage` |
| `item_3152_active/actual_hit` | `SKILL_HIT`，`sourceSkillKey=item_3152_active` | `TARGET_CATEGORY_CHECK` 为 `CHAMPION` | `CURRENT_TARGET` 执行 `firebolt_hit` |
| `riven_e/on_used` | `SKILL_USED`，`sourceSkillKey=riven_e`、`useKind=ACTIVE` | 无条件 | `CURRENT_TARGET` 执行 `shield`；结果目标已有 `SOURCE` |

四条规则都不设置逐目标冷却和过程触发次数。艾希 R 只接已有的单次命中伤害；内瑟斯 E 只接已有的初始命中伤害，不把区域周期伤害或护甲降低混入本次命中；火箭腰带只接已确认的一次火箭命中；锐雯 E 只接主动使用后的自身护盾。冲刺、弹道、命中判定、距离换算、区域停留、护盾吸收、冷却和施放资格等未冻结行为不在本批补造。

文件职责如下：

- `01-合并方案.md`：唯一的当前范围、字段契约、顺序和验收边界。
- `02-合并冻结请求.json`：四个完整 POST 请求体；每条都有对象键递归排序后的规范化 `bodySha256`。
- `03-来源散列快照.json`：四个上游候选目录的文件散列、来源事实和本批冻结请求体散列。
- `04-共享写前现值.json`：已取得的完整写前快照，含 100 条规则详情、1062 个规则列表、四个目标的非规则组成和两轮稳定性结果。
- `Cursor终审只读检查.mjs`：只读检查冻结请求、每条 `bodySha256`、脚本门禁和写前基线状态；不会访问接口。
- `准备合并只读.mjs`：纯读取准备脚本。它重新读取四个目标、全部组成和两轮全局规则快照，只在本目录更新 02～04 文件。
- `05-Cursor独立评审.json`：Cursor 独立只读终审的已接受证据，记录固定模型、运行标识、输入散列和零文件变化审计。
- `受保护写入.mjs`：四次受保护 POST 写入器，要求批准散列、Cursor 已接受证据、显式写入开关和两轮 GET 预检；本批只运行一次。
- `06-写入与即时回读.json`：四次写入及逐条即时回读，另含写前两轮和写后全局核对。
- `独立GET回读.mjs`：写后独立只读回读，逐条核对旧 100 条、四条新增、目标非规则组成及 104 条终态。
- `07-独立GET回读-首轮断言失败.json` 与 `07-独立GET回读断言修订.json`：保留后端默认空值造成首轮严格结构断言失败的事实与有界修订依据；两份证据均无业务写入。
- `07-独立GET回读.json`：修订后独立回读成功证据。
- `只读页面验收.mjs`：写后管理页面只读验收，检查四项图片、公式、效果、结果和规则展示，并断言业务写入数为 0。
- `08-页面验收.json` 与 `页面截图/`：Playwright Chromium 真实页面只读验收及 16 张截图。
- `05-Cursor评审占位.json`：终审前占位历史，已被正式评审证据取代，不能单独作为写入授权。

实际执行顺序固定为：纯读取准备 → 独立评审冻结文件和来源 → 用 Cursor 终审脚本生成已接受证据并固定批准散列 → 运行 `受保护写入.mjs` → 运行 `独立GET回读.mjs` → 运行 `只读页面验收.mjs`。任一步的目标候选详情不是 404、旧规则详情变化、两轮规则键或详情不稳定、组成缺失，均停止，不发送 POST。

不同录入者的体验问题已记录在方案中：英雄目标使用 `characters` 与 `character-skill-relations` 路径，装备目标使用 `equipment` 与 `equipment-skill-relations` 路径；同一份合并脚本必须同时处理两种返回形态。`SKILL_HIT` 的 `useKind` 需要省略而不是填入 `null`，锐雯 E 的 `SKILL_USED` 则必须同时保留 `sourceSkillKey` 和 `useKind=ACTIVE`。动作目标 `CURRENT_TARGET` 与锐雯护盾结果的 `SOURCE` 不是同一个概念，页面和回读均要分别核对。

首次纯读取准备还发现两项证据生成问题，并已在零网络请求时修正：上游目录分别采用“紧凑对象”或“文件字节”计算来源散列，合并器原先只接受后一种；冻结请求中的计划 POST 又被通用扫描器误算成已执行写入。合并器现在显式识别两种既有散列约定，并只在来源、现值和准备报告中检查实际调用证据；冻结请求本身的唯一计划 POST 由单独路径、方法和数量门禁核对。

Cursor 终审使用 `grok-4.6`、高推理、非快速模式，运行 `run-986e86e6-fa35-4550-8faa-7636a1f30876` 返回修订 2 `READY`。唯一一次终端调用完成且未截断，文件变化、范围外变化与业务写入均为 0。随后受保护写入器只执行一次：3778 次 GET、4 次 POST，四次响应均为 201 且即时回读为 200；旧 100 条规则和目标非规则组成未变，最终为 104 条规则。

首轮独立回读在 95 次 GET 后发现，后端会把三条 `SKILL_HIT` 请求中省略的 `useKind` 读取为 `null`，锐雯的主动使用明细不变。请求语义和数据没有冲突，因此只在新规则回读比较前删除这一项明确默认空值，再做全结构严格相等；没有重放写入。修订后独立回读共 1262 次 GET，旧 100 条、新 4 条、1062 个规则列表和四项目标非规则组成全部通过。

真实页面验收共 263 次 GET、0 次业务写入，四项列表图片实际尺寸均为 64×64，公式、效果、结果与规则详情全部可见，16 张截图已保存；控制台错误、页面错误、请求失败和错误响应均为 0。人工目视复核了艾希 R、锐雯 E 规则和火箭腰带列表图片，页面显示与冻结语义一致。

静态材料、接口 GET、管理页面和后续回读都不能证明 TinyGo、战斗运行时真的产生事件；运行时验证仍需另行完成。
