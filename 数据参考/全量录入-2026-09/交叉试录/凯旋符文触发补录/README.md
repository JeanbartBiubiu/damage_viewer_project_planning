# 凯旋符文触发补录

本目录保存凯旋 `rune_9111_passive` 触发补录的只读准备材料。目标候选是 `KILL` → `TARGET_CATEGORY_CHECK(CHAMPION)` → 执行 `triumph_heal`；20 金币属于与一对一伤害无关的分支，已排除。

本轮只访问真实后端的 `GET` 接口，没有业务写入、没有删除、没有 Git 操作。用户语义中的来源对象按当前动作目标枚举记录为 `EVENT_SOURCE`；当前能力表没有给 `KILL` 提供事件来源，所以准备结果为 `REVISE`，不能安全生成一次 POST。

当前有两个独立阻塞：一是 `KILL` 没有可供 `EVENT_SOURCE` 使用的事件来源；二是来源文字的“参与击杀”不能由仅表示本人击杀的 `KILL` 完整表达，助攻范围和触发时点仍未确定。后续最小修订是先让 `KILL` 明确携带来源对象，再单独明确参与击杀事件是否包含助攻，继续使用 `EVENT_SOURCE`，不增加 `CURRENT_SOURCE`。

文件说明：

- `01-来源与方案.md`：来源、现有组成、候选语义、契约核对和结论。
- `02-冻结请求.json`：冻结后的语义请求、保护门槛、冲突和写入边界；它不是可直接提交的接口请求体。
- `03-来源快照.json`：规划真源、官方与客户端原始资料、契约文件散列和来源条目快照。
- `04-写入前现值.json`：凯旋目标对象、全局 1062 个技能的触发规则目录与详情、两轮稳定性核对和保护现值。
- `05-只读准备报告.md`：本次运行的 GET、状态统计、READY/REVISE 判断和后续边界。
- `准备只读.mjs`：需要令牌环境变量的只读脚本，只在本目录写出上述三个 JSON 文件。

运行前确认后端已启动，并在当前 PowerShell 会话中临时提供令牌：

```powershell
$env:DAMAGE_ENTRY_TOKEN = '<本机令牌>'
node '.\数据参考\全量录入-2026-09\交叉试录\凯旋符文触发补录\准备只读.mjs'
Remove-Item Env:DAMAGE_ENTRY_TOKEN
```

脚本不会把令牌写入文件或输出。脚本运行后应检查 `02-冻结请求.json` 的 `status`、`04-写入前现值.json` 的 `getCount` 与两轮散列，再阅读报告；本次已记录 2333 次 GET，所有目标与全量规则详情返回 200，两轮规则对象一致。
