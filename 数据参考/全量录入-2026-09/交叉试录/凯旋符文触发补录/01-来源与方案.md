# 凯旋符文触发补录：来源与方案

## 目的与范围

本批只准备 `rune_9111_passive` 的一个自动触发候选：英雄击杀事件、被击杀对象为英雄、执行已有 `triumph_heal` 治疗效果。凯旋已有的主体、参数、公式和独立自身治疗属于本批核对范围；额外的 20 金币与一对一伤害计算无关，明确排除，不建立金币参数、金币效果或金币结果。

本文件及同目录 JSON 只记录来源和真实后端读取结果。没有发送业务写入请求，也没有在本轮指定规则键、展示名称或顺序，避免从缺失事实中补字段。

## 来源依据

规划真源中的凯旋条目指向以下冻结资料：

- 官方资料：`官方原始资料/runesReforged-16.17.1-zh_CN.json`，指针 `/2/slots/1/runes/1`。
- 客户端资料：`客户端提取资料/perks-16.17-zh_CN.json`，指针 `/42`。
- 规划候选：`API实录/符文机制盘点/下一批最多12项.json` 中的 `rune_9111` 条目。

两份原始资料都写明参与击杀后的自身治疗和额外 20 金币。规划候选已经把金币列为范围外，并保留以下已确认数值：

- 已损生命值的 5%。
- 最大生命值的 2.5%。

同目录的 `03-来源快照.json` 保存了规划条目、来源指针、文件字节数与散列，以及本轮采用的接口契约文件散列。它是本批来源的固定快照，不代替后端现值。

## 当前实库组成

本轮真实后端读取确认 `rune_9111_passive` 已存在并启用，且只包含以下组成：

| 组成 | 当前键 | 本轮核对结果 |
| --- | --- | --- |

| 公式 | `triumph_heal` | 1 条，按来源对象的已损生命与最大生命相加 |
| 效果 | `triumph_heal` | 1 条，结果类型 `DIRECT_HEAL`，结果目标为 `SOURCE` |
| 过程 | 无 | 空 |
| 内部状态 | 无 | 空 |
| 触发规则 | 无 | 空，正是本批候选的新增位置 |

同时确认凯旋主体、符文技能关系和代表图片均可读取，关系只返回 `rune_9111` 与 `rune_9111_passive` 的一条精确关系，图片键为 `rune_9111`。完整对象保存在 `04-写入前现值.json`。

## 冻结的触发语义

冻结候选只表达下面三段语义：

1. `KILL`：收到击杀事件。
2. `TARGET_CATEGORY_CHECK`：当前目标类别包含 `CHAMPION`，用于确认被击杀对象是英雄。
3. `EXECUTE_EFFECT`：执行 `triumph_heal`，治疗结果继续使用已有 `target: SOURCE` 和 `formulaKey: triumph_heal`。

用户语义中的“来源对象”按现行动作目标枚举标准化为 `EVENT_SOURCE`，不把不存在的 `CURRENT_SOURCE` 写进接口请求体。这个标准化结果已在 `02-冻结请求.json` 和 `03-来源快照.json` 中标记为 `normalizedFrom: CURRENT_SOURCE`。

## 契约核对与结论

当前后端和前端动作目标枚举只有 `CURRENT_TARGET`、`EVENT_SOURCE`。后端能力表当前把 `KILL` 的当前目标定义为“本次被击杀对象”，同时没有把 `KILL` 列入可提供事件来源的事件集合。现有 `tristana_w/own_kill_reset` 只能证明 `KILL` 与 `TARGET_CATEGORY_CHECK(CHAMPION)` 的组合已有实库实例，不能证明凯旋的持有者可以从本事件取得 `EVENT_SOURCE`。

因此本轮结论为 `REVISE`：

- 主体、关系、图片、参数、公式、效果和全局规则基线均通过读取核对。
- 两轮全量规则读取稳定，规则总数均为 96，已有 `KILL` 规则 1 条。
- `KILL` 当前没有可供 `EVENT_SOURCE` 使用的来源对象，动作目标无法安全冻结为可提交请求。
- 来源文字的“参与击杀”是否包含助攻以及治疗准确时点仍是规划中保留的待补事实；`KILL` 不能直接宣称覆盖完整参与击杀。
- 本轮不指定规则键、名称、顺序，不生成临时请求体，不发送 POST。

待独立评审补齐 `KILL` 的事件来源语义、参与击杀范围和稳定规则键后，才可以重新冻结一次。若届时所有门槛通过，单一写入边界只能是向 `/api/admin/games/lol/skills/rune_9111_passive/trigger-rules` 发送一次新增规则请求，并立即回读该规则及全局规则基线；本轮该边界为空。

后续最小系统修订建议分两步完成：第一步只扩充 `KILL` 的事件契约，让它明确携带击杀事件来源对象，动作继续使用现有的 `EVENT_SOURCE`，不增加 `CURRENT_SOURCE` 枚举；第二步单独定义“参与击杀”是否包含助攻及其触发时点，若包含助攻，必须提供可核对的参与击杀事件或等价来源字段。两步都完成并通过独立验证后，才重新准备凯旋规则。
