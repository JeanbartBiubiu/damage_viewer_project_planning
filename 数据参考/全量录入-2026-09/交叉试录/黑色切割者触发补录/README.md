# 黑色切割者触发补录

本目录保存黑色切割者 item_3071_passive 的一条触发规则补录准备证据。规则含义是：对英雄造成物理伤害时，在当前目标上执行已有的 armor_shred。

当前实库的物理伤害目录键是 physics。因此冻结请求中的 eventSource.detail.damageTypeKey 使用 physics；这只是现有目录键映射，不是新增伤害类型。deliveryKind 和 originKind 都保持 ANY，对象类别条件保持 CHAMPION。

本批不把已有参数 damage_internal_cooldown_ms=10 当作逐目标冷却。该参数只保留客户端 InternalCD=0.01 秒的来源记录；冻结规则的 perTargetCooldown 必须为 null。热烈移动速度待接线内容也不在本批处理。

文件用途如下：

- 01-来源方案.md：固定来源、边界和验收条件。
- 准备只读.mjs：读取固定来源并执行实时 GET；只在本目录生成下列证据，不发送业务写入请求。
- 02-冻结请求.json：由脚本生成的单一写入请求，主负责人独立评审后只执行其中唯一的 POST。
- 03-来源快照.json：固定来源文件散列和黑色切割者候选、官方资料及客户端关键值摘要。
- 04-写入前现值.json：目标技能完整组件、引用目录、全技能触发规则列表与详情的写入前保护快照，并包含第二次稳定扫描。
- 05-只读准备报告.json：本次 GET 数量、状态统计、目标冲突检查、规则基线和待执行 POST 摘要。

最低检查（在仓库根目录执行）：

    node --check "数据参考/全量录入-2026-09/交叉试录/黑色切割者触发补录/准备只读.mjs"
    node "数据参考/全量录入-2026-09/交叉试录/黑色切割者触发补录/准备只读.mjs"

脚本需要本机管理接口可读；若设置 DAMAGE_ENTRY_TOKEN 会使用该环境变量发送认证头，但不会把认证值写入证据。未设置时按当前本机认证关闭配置发送无认证 GET。脚本不执行 Git 操作，不读取或写入业务数据库之外的写入接口，也不向目标目录外落盘。

脚本成功后，主负责人应以 02-冻结请求.json 为唯一依据执行一次 POST，返回 201 后立即 GET 新规则详情，并核对事件类型、physics、ANY、CHAMPION、CURRENT_TARGET、armor_shred 和两个空值字段。本文档及脚本只证明来源和写入前读状态，不证明写入后的状态或战斗运行时接线。
