## 已确认的表达能力与缺口

当前结构能保存强化下一次普攻、分结果暴击策略、按当前等级读取属性，以及用标记和条件过程选择 Q 半冷却；不能继续将这些整体列为“系统不支持”。Q 额外部分沿用基础普攻的同一次暴击判定、无条件被动初始化事件、控制类别与数值强度的关联才是本轮需处理的公共结构缺口。缺少来源的时点单独补证，不能用新增字段代替查证。

Q 原计算还包含基础普攻攻击力，额外公式已扣除这部分，避免重复计算；暴击时累计伤害点数不随基础额外伤害一起放大，因此本批未生成一个错误的统一暴击伤害效果。Q 小兵/野怪增长支路及 R 体型/范围等空间支路按既定范围跳过，不当作本轮阻塞。

## 页面与错误恢复

真实浏览器筛选 `nasus_r`，进入“效果与结果”，查看 `fury_attributes`：三项属性变化均作用于施法者，持续生效、施加时留存，分别引用 `armor`、`hp`、`magic_resistance`；生命周期按来源对象单层保存，引用持续时间参数，重复刷新全部时间。参数的15000毫秒值另由接口回读证明；没有用页面显示参数名称冒充数值读回。

首次写入 R 三属性效果后，接口按同一排序值下的结果稳定键返回，导致按数组位置比较时报顺序差异。独立 GET 证明属性和值未丢失，候选改为相同的稳定键顺序后续录剩余2项，未重建或覆盖已保存效果。首轮37项回读保存在 `实录回读-首轮.json`；最终 `实录回读.json` 和 `独立核对.json` 均覆盖40项。此为录入脚本比较问题，不是后端保存错误。

`录入.mjs` 默认只读核对，显式 `--apply` 先全批读取、仅补缺项，冲突停止。`算术核对.mjs` 只读已保存公式并计算边界样例。使用捆绑 Node.js 24；后续公共能力完善后从候选各技能的 `gaps` 返回补录，不把本批检查点记为整轮完成。
