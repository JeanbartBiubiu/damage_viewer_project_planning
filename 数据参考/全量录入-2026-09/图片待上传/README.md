## 页面上传用法

在相应管理页打开目标对象，选择上传图片，然后从 [文件选择器路径.tsv](文件选择器路径.tsv) 复制该行“本机绝对路径”到原生文件选择器。核对中文名称和技能槽位后保存，再回读代表图片和表格左侧缩略图。图片输入根目录为：

`C:\project\damage_viewer_project_planning\数据参考\全量录入-2026-09\图片待上传`

常用相对路径：

- 盖伦角色：`01_角色\Garen.png`
- 盖伦被动：`02_技能\Garen\P_Garen_Passive.png`
- 盖伦 Q/W/E/R：`02_技能\Garen\Q_GarenQ.png`，其余槽位同目录按文件名选择。
- 伊泽瑞尔被动：`02_技能\Ezreal\P_Ezreal_RisingSpellForce.png`
- 伊泽瑞尔 Q/W/E/R：`02_技能\Ezreal\Q_EzrealQ.png`，其余槽位同目录按文件名选择。

技能图片名逐项来自冻结英雄详情的 `passive.image.full` 或 `spells[i].image.full`，没有依据技能名称拼图标名。角色中文本名取中文资料的 `title` 字段，避免与称号反置。装备图标同时核对纯属性清单的图片地址与原始 `item.json` 的图片对象。

## 来源和检查记录

[上传用途与来源清单.json](上传用途与来源清单.json) 逐张记录用途、对象名、槽位、本机路径、官方图片地址、源资料文件及字段位置、获取时间、响应类型、字节数、SHA-256 摘要、尺寸和解码结果。清单同时记录 17 份已冻结来源文件的摘要和 47 件装备的范围选择摘要。

核对包括：

1. 16 份英雄详情与 1 份装备原始响应的字节数/摘要仍与已有来源清单一致，资料版本均为 16.17.1。
2. 图标地址只使用官方 `ddragon.leagueoflegends.com` 固定版本目录，完整文件名由已冻结图片字段提供。
3. 每次响应必须成功、类型为 `image/png`，并通过 PNG 标记和尺寸检查；不把错误页保存成图片。
4. Windows `System.Drawing` 校验图片数据，将完整图像绘制成位图并在内存重新编码；磁盘保留官方原始字节。
5. 73 个用途、73 个文件、73 个源地址一一对应；扫描图片摘要无重复组。

本目录没有改写应用、调用业务接口、写数据库或执行上传。清单中的建议业务键供定位参考，仍应以页面实际对象核对。

## 复现

在本目录执行 `node 下载图片.mjs`。脚本从相邻冻结资料构建用途清单，复用摘要一致的已下载原字节，并再次调用 `核对图片解码.ps1` 完整解码。已存在但缺少对应有效摘要的文件不会被覆盖。失败项会明确保留在清单中，不下载替代图片。
