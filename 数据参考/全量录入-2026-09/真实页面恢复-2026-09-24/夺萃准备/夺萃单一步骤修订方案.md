# 夺萃之镰待击窗口：单一步骤修订方案

本文件是供主负责人写入共享计划并送独立评审的窄方案。此前《夺萃待击窗口页面候选.json》保持原字节，仅作为被拦下的历史候选；其中“普通攻击命中再录两条执行效果动作”的页面操作不得执行。以下均为源码静态推断和已冻结现值核对，尚未保存新的页面配置，也未用正式夺萃对象运行。

## 正式录入语义

原技能继续复用已保存的五个参数、两个公式、两个效果；按前一候选录入两个技能范围内部状态和一个单步骤“强化下一次普通攻击”过程。该步骤的期限引用`spellblade_window_ms=10000`，消费时点为`ATTACK_HIT`（攻击命中）；其`STEP_EXECUTION`（步骤执行）效果绑定依次引用既有额外伤害和回蓝效果，随后在同一步骤清除待命并启动`spellblade_cooldown_ms=1500`的内部冷却，超时只清除待命。

**只录一条首次主动施法启动规则。** 它只有一个指向上述过程的启动动作，来源为已绑定的真实主动非普攻技能之首次施放。待命关闭、待命开启两组条件均要求内部冷却剩余时间等于零；两组除待命真假外完全对称。待命开启时再次启动的正式含义是刷新现有待击期限，不能创建第二份待击或累加强化次数。页面不得新增普通攻击命中执行效果规则、过程时点执行效果规则，或其他引用该过程的触发规则。

逻辑待击实例按**实际拥有者＋该装备挂载＋待击过程**唯一确定。当前有界宿主以该挂载的技能范围待命状态和期限承载这个逻辑实例；这不是原生过程实例快照。命中时使用本次真实普通攻击事件的目标作为额外伤害目标，回蓝仍回到拥有者。两个效果、清待命、启动冷却属于同一次消费执行。此后冷却未结束的施法由既有条件挡住；未命中而超时不启动冷却。

## 宿主最小改动

1. 在`web/src/engine/triggerAdapter.ts`的强化过程识别中，要求恰好一个强化普攻步骤、一个启动规则、两个技能范围状态；过程普通冷却为空。启动规则只含一个指向本过程的动作。过程效果绑定都指向该步骤的执行时点，状态操作只允许开始时开启待命、执行时关闭待命并启动内部冷却、超时时关闭待命；缺失、重复或多余操作、额外过程事件引用及其他规则均按字段路径拒绝。消费时点与步骤所写时点一致，效果绑定和状态操作在消费时点的排序值应唯一，避免同序隐含先后。本次只接受既有即时伤害与来源资源回复的结果形状；额外结果类型明确拒绝。
2. 保留启动规则的真假对称核对及首次真实施法能力绑定。启动监听器写待命值`1`：原为`0`时开启，原为`1`时在同一挂载、同一过程上刷新期限。沿用状态的“每次写入刷新”策略覆盖当前到期时刻；状态到期按**当前**期限惰性判断，旧期限不再生效，无须增加删除计时事件的接口。正式步骤的超时清待命操作由到期恢复默认值实现；该有界降解不额外发出原生步骤超时事件。窗口有效区间为起点包含、终点不包含；到期同刻先视为已过期。
3. 宿主从强化步骤的消费时点、效果绑定和状态操作**内部派生一个**普通攻击命中监听器，不要求作者再保存消费规则。监听器匹配实际来源拥有者，读取该次真实命中事件的目标；条件为待命开启且内部冷却就绪。按过程绑定排序编译两个既有效果，再清待命并启动冷却。一次性消费键由该待击过程稳定标识派生，范围为当前挂载；真实普攻使用标识必须存在，缺失时明确报错。同次命中事件重复到达，即使消费后已重开窗口，也由已提交的使用账本拒绝第二次消费；新普攻使用可消费新窗口。该派生监听器是步骤的内部执行表示，不能成为第二份作者配置。
4. 修改适配结果的监听器排序、一次性消费信息和错误路径，使它们以启动规则及过程步骤为来源；计数窗口分支保持原行为。只更新原合成夹具为“一个作者启动规则＋过程绑定”，不保留两份作者规则的兼容路径。正式伤害的`vampQualification=UNRESOLVED`（吸血资格未核定）继续使运行编译失败，不能为跑通本项改成已核定或绕过校验。

不能直接调用现有通用过程适配器来省略第3步：`processAdapter.ts:263-307`只接即时、延时、蓄力及重施步骤，`processAdapter.ts:705-706`拒绝内部状态操作；原生过程的第二次首次启动在活动实例存在时返回`process_already_active`（`generic_process.go:72-79`）。本方案只改宿主有界降解，不扩建原生过程协议，也不开始整技能装配。

## 最小验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 配置识别 | 一条作者启动规则、一个强化步骤、两份过程效果绑定生成一条内部命中监听；多余命中规则、过程时点规则、目标范围状态、错误步骤时点和额外操作逐项拒绝。 |
| 启动与刷新 | 0毫秒施法、9000毫秒再次施法，逻辑待击仍只有一份且期限为19000毫秒；10000毫秒旧期限不清掉新窗口；19000毫秒未命中则过期而内部冷却为零。 |
| 实际命中 | 9000毫秒刷新后，11000毫秒对实际普攻命中对象只执行一次额外伤害和一次来源回蓝，待命值及期限清零，冷却到12500毫秒；对其他对象不误施加。 |
| 重复和重开 | 同一普攻使用的重复命中事件不二次消费；消费后冷却期间施法不能重开，冷却结束后新施法与新普攻使用可以完成下一次消费；重开后到达的旧普攻重复事件仍被使用账本挡住。 |
| 恢复与边界 | 刷新后待命快照、消费后冷却快照分别恢复；恢复后旧期限不复活，重复使用不复活，同刻到期不消费。无真实普攻使用标识、未绑定首次主动能力、非首次施放均明确拒绝。 |

优先改造并检查`triggerAdapter.test.ts`的强化步骤夹具及刷新、绑定、回蓝用例；状态期限和消费后恢复沿用`generic_provider_state_test.go:1114-1153`、`generic_p6_test.go:291-331`的原生测试入口。实际普通攻击事件在`generic_execution.go:2440-2488`携带命中来源和目标，`generic_execution.go:2712-2725`建立监听器执行对象；一次性使用账本在`generic_use_trigger.go:245-299`按拥有者、挂载、稳定组键和真实使用标识去重并可恢复。最终仍需真实工作线程核对单次伤害、回蓝、期限和快照；正式夺萃伤害运行须等待吸血资格另行核定。

## 证据边界

前一冻结档案`../夺萃下一批只读准备.json`记录18次只读请求、五参数两公式两效果及空过程／空状态／空规则；其主体和倍率参数旧说明仍将回蓝写成“咒刃附伤×0.5”，更正文案仍在前一候选文件，未保存。规划真源《管理页面与共性机制迭代计划》第6项的七条用户核定继续有效；本修订仅纠正该项原方案把过程绑定与命中动作重复表达的缺陷。源码证据与历史合成运行不能替代新页面保存、独立回读或正式对象运行证明。
