## 1. 只增加一处受限条件

在 `DAMAGE_MODIFIER.detail` 增加可空的 `condition`（生效条件），示意如下。原有乘区、方向、修正方式及伤害过滤字段不变。

```json
{
  "condition": {
    "receiver": "ENEMY_CHAMPION",
    "attributeKey": "hp",
    "attributeValueKind": "CURRENT_RATIO",
    "comparator": "LT",
    "comparisonValue": {
      "kind": "PARAMETER",
      "parameterKey": "target_health_threshold_ratio"
    }
  }
}
```

| 字段 | 首版含义与约束 |
| --- | --- |
| `condition` | `null` 或未配置表示没有新增资格限制，保持既有无条件修正。非空必须是对象，不接受数组或额外字段。读回可统一为空值，不按旧版本建立第二条处理路径，也不批量重写旧效果。 |
| `receiver` | 必填且首版仅为 `ENEMY_CHAMPION`，即本笔实际伤害承受者是相对实际伤害来源的敌方英雄；不借用命中事件字段。不是自由对象选择器。 |
| `attributeKey` | 本游戏数值属性引用，由作者明确选择生命属性；这两符文选择既有 `hp`。后端不根据键名猜属性类别。 |
| `attributeValueKind` | 必填且首版仅为 `CURRENT_RATIO`，按该实际承受者的当前值/最大值读取。 |
| `comparator` | 复用严格比较枚举，但本形状仅接受 `LT`、`GT`；等值均不成立。致命一击用 `LT`，砍倒用 `GT`。 |
| `comparisonValue` | 必填，复用既有 `NumericValue`：固定值、当前技能参数、当前技能公式。禁止直接或经公式引用 `RUNTIME_INPUT`。可静态取得的固定值和参数全部等级须为有限的 `[0,1]` 比例；不能静态求值的公式在执行时同样检查，不补零、不夹取。 |

所有条件项为固定的合取关系：敌方英雄资格且生命比例比较成立。没有条件组、任意逻辑、嵌套条件、执行动作或一般条件语言，也不让其他结果种类携带该字段。关闭条件后保存空值；其余业务字段完整保留。

建议首版非空条件仅允许 `target=SOURCE`、`direction=DEALT`、父生命周期存在且结果持续生效、乘区为 `DAMAGE + DAMAGE_PRE_DEFENSE`。这使修正承受对象、实际伤害来源与拥有者关系明确；不扩到“替另一来源的受伤对象加修正”。已有 `condition=null` 的方向、目标、阶段及修正方式保持原约束。`operation`、数值规则和所有原伤害过滤仍按现有规则处理，不强制变成某种伤害或特定符文。

## 2. 时点与参与者

条件固定在每一笔已经匹配原伤害过滤的伤害进入防御前乘区时判断，此时预期暴击已经形成，本笔普通护盾吸收和生命扣除尚未发生。条件不采用效果施加时的生命快照，不采用造成伤害事件后的生命值，也不修改当前伤害已完成的部分。多段伤害逐笔重新读取；本笔打过门槛不能追溯增加自己，下一笔按更新后的生命判定。

不新增可选的“采样时点”枚举。页面直接说明“本笔伤害进入防御前乘区、扣血前判定”。条件始终逐笔读取，与已有 `valueReadMode` 对修正数值采用施加快照还是当前读取的含义分开；不能因金额采用施加快照而把资格也冻结在施加时。

本条件左侧对象固定为 `cmd.Target`；若右侧公式读取 `SOURCE/TARGET`，分别指这笔命令的 `cmd.Source/cmd.Target`。效果初始施加者、供值器拥有者、事件原始参与者和执行帧默认目标均不能暗中替代它们。自身伤害不符合敌方资格。反向拥有者施放时按实际命令双方求值，不交换属性含义，也不复用正向敌我常量。

已知实现边界必须先处理：[generic_execution.go](C:/project/damage_wasm_dev/wasm/tinygo_engine_v2/internal/runtime/generic_execution.go:343) 当前条件基础上下文读执行帧双方，而伤害操作可以把实际目标改为自身；[applyDamageCommand](C:/project/damage_wasm_dev/wasm/tinygo_engine_v2/internal/runtime/generic_execution.go:1204) 收到实际命令后，修正求值尚未传入实际目标。因此不能仅把管理比较翻译成 `target.attr.hp.current` 就宣布接通。

建议仅为伤害条件及其比较右值构造实际命令双方的读取上下文；保持非伤害上下文、事件快照和供值器拥有者状态的身份各自独立。既有无条件修正与金额求值不顺手改义。若本轮要统一条件与修正金额的实际命令上下文，必须先由主负责人选择本节第 7 节的上下文方案，并验证已有路径，不藏在字段接线补丁里。

运行时生命当前值、最大值与右值必须明确、有限，最大值必须大于零；未知身份和缺属性均给出具体路径错误。不能假定原生所有帧都开启严格读取：[evalContext](C:/project/damage_wasm_dev/wasm/tinygo_engine_v2/internal/runtime/generic_execution.go:352) 当前按帧条件设置严格读取。

## 3. 敌方英雄与伤害范围

复用现有宿主明确身份事实，例如 [CombatantIdentityFact](C:/project/damage_web_dev/web/src/engine/hitAdapter.ts:35) 的类别、敌我关系及 `combatant/champion` 类型标签。类别或关系未知时拒绝，明确不是敌方英雄时本条件不匹配。标签只能承载经核验的事实；`damage.cast_origin.champion` 说明能力施放来源，`damage.ability_type.*` 说明能力类型，都不能证明承受者是敌方英雄。

推荐首版沿现有固定两对象的一对一边界处理：按实际拥有者分别核对其对手类别及双方敌我事实，将“对手是敌方英雄”编成受绑定保护的资格常量；同时在本笔实际命令中排除来源与目标为同一对象。后一个检查当前没有可直接读取的公式字段，需要窄小的命令参与者相同性谓词或等价显式检查，不能仅凭两对象键不同就推定敌方。具体选择见第 7 节。身份事实与拥有者绑定进入配置摘要；不同身份组合不能沿用旧编译会话和旧恢复快照。

此限制是固定一对一身份边界，不是物理普攻限制。管理保存必须完整保留 `damageTypeKey`、`deliveryKind`、`originKind`、`criticalFilter`，宿主将它们与新条件共同匹配；不支持的运行组合须按字段明确拒绝，不能删过滤、改成 `ANY` 或靠样例补默认。

新条件不决定真实伤害是否能被某符文增幅。原无条件修正的空伤害类型仍按现有含义处理；两符文尚未核定的真实伤害资格保持未知，不把空值当成已批准全部伤害，也不暗加“真实伤害永远排除”的全局默认。普通物理普攻、普通魔法技能、不同来源性质及暴击筛选可以作为能力测试输入，测试通过不自动核定两符文全部游戏资格。

## 7. 仅留给主负责人的两项技术决策

1. **实际命令上下文修正范围。** 推荐首轮只让新生效条件及其比较右值读取实际 `cmd.Source/cmd.Target`，保持既有无条件金额求值路径；新宿主先对确实覆盖的金额形状负责，其余明确拒绝。若决定把所有伤害修正金额也统一到命令双方，须明确承认对旧重定向金额读取的行为影响，并补对应回归，不能声称纯接线且旧义自动不变。两种选择都必须让本条件的 SOURCE/TARGET 一致，不能一边仍读旧帧目标。
2. **一对一身份向原生条件传递。** 推荐复用明确身份事实按拥有者绑定折叠“对手为敌方英雄”，再补一个只用于本笔伤害的“来源与承受者是否同一对象”瞬态检查；由该检查排除自伤，并由实际命令双方提供生命属性。它不把不同键自动认定为敌方，不在快照里存资格真假。若需要运行中改变类别/阵营，则必须另选显式身份读取方案，本轮不默认扩通用实体关系系统。
