# 英雄资料冻结与录入清单

本目录冻结官方 Data Dragon（游戏静态资料包）`16.17.1` 的召唤师峡谷基础英雄名单和中英文详情。它是本轮资料清单，不是业务数据库导入文件，也不代表页面已经录入或机制已经完整。

共 **173 名英雄、865 个被动/Q/W/E/R 槽位**。按用户约定排除赛拉斯、厄斐琉斯后，本轮为 **171 名英雄、855 个技能槽位**。其他英雄涉及独立召唤物、完整变形技能集时按机制后置，保留英雄和技能说明，不自动排除整个英雄。海克斯不在本目录范围。

## 文件用途

| 文件 | 用途 |
| --- | --- |
| `来源清单.json` | 固定版本、抓取时间、官方地址、349 份原始文件的 SHA-256 摘要和范围统计 |
| `原始资料/` | 版本列表、中英文英雄索引、中英文各 173 份详情，保留下载原字节 |
| `英雄资料清单.json` | 全部英雄原始属性、中文本名与称号、5 个技能槽、原始技能数值、未解析变量和已有 Wiki 对照 |
| `首批五名英雄.json` | 盖伦、艾希、拉克丝、墨菲特、厄运小姐的相同字段，便于先做页面录入 |
| `录入进度.jsonl` | 逐行记录 173 名角色和 865 个技能的录入状态，共 1,038 行；本次初始化全部为待录入或约定排除 |
| `攻击力成长交叉核对.json`、`成长补充原始资料/` | 三名英雄的客户端提取字段、历史官方对应值、版本和 11 份补充原始来源摘要 |
| `全英雄成长核对.json`、`角色根记录/` | 全 173 名英雄的完整角色根对象、原响应地址/版本/时间/摘要、英雄身份与基础攻击力对照 |
| `等级曲线依据.json`、`等级属性候选索引.json`、`等级属性候选/` | 1–18 级基础属性候选及缺失项，保留攻速基值和收益系数的区别 |
| `采集英雄资料.mjs` | 本次采集过程，可审查来源与生成规则；检测到已冻结清单时拒绝覆盖 |
| `核对攻击力成长来源.mjs` | 三名英雄成长来源的有界交叉核对，不解析技能、不写入业务数据库 |
| `补齐全英雄成长来源.mjs`、`生成等级属性候选.mjs` | 全英雄根记录提取及等级候选生成过程，不改动录入进度 |
| `核对资料.mjs` | 离线核对来源摘要、版本、技能槽和进度清单覆盖范围 |

只有 `录入进度.jsonl` 表示之后的页面工作进度；资料清单中的初始状态是采集时快照。进度状态使用“待录入、部分录入、完整录入、阻塞、约定排除”，完成项必须补页面核对时间及系统对象标识。已有伊泽瑞尔数据也尚未与本清单对账，因此未擅自标为本轮完成。

## 已确认的资料缺口

1. **173 名英雄的原始攻击力成长全部为 0。** 原字节保留，不能直接当成可靠成长数值录入。现已逐名提取客户端根记录，172 名获得明确成长补证；唯一例外赛娜的客户端成长字段省略，仍保留缺失、不补 0。
2. **692 个主动技能的 `vars`（系数列表）与 `datavalues`（补充数值）都为空。** 全部主动技能仍有未解析变量；去除两类通用显示变量后，还有 **682 个主动技能**存在具体机制或数值变量缺口。冷却、消耗等已有字段也要结合技能含义核对，不能假定其涵盖充能时间、生命消耗等全部参数。
3. **173 个被动都没有完整结构化数值。** 说明里即使有某个数字，也不代表完整触发条件、成长曲线或系数已经齐全。未知字段保留缺失，不能用 0 补足。
4. 本地既有 Wiki 只覆盖 **33 名英雄、165 个技能页面**，已按英雄与槽位建立对照。它来自多个修订，不是 `16.17.1` 的同版本机制资料；任何数值混用都需要记录来源差异。
5. 中文原始字段的 `name` 是称号、`title` 是本名，例如“德玛西亚之力 / 盖伦”。资料清单另列 `chineseChampionName`（中文本名）和 `chineseChampionTitle`（中文称号），避免把角色名字录反。

官方说明：英雄索引只含摘要，单英雄文件含更多字段；技能文本可引用 `effect` 或 `vars`，生命消耗要结合 `resource` 判断。资料由人工更新，可能滞后于补丁，不能等同所有地区客户端版本。参见 [Riot 官方字段说明](https://developer.riotgames.com/docs/lol#data-dragon_champions)。上述缺口数量来自本目录实际文件扫描。

## 三名英雄攻击力成长补证

补充来源为 CommunityDragon（社区维护的客户端数据提取项目）的固定 `16.17` 目录，元数据版本为 `16.17.8104348+branch.releases-16-17.content.release`。这是与 Data Dragon `16.17.1` 相同补丁号的不同资料版本标识，未证明构建内容完全相同；它不是 Riot 官方接口。项目说明游戏文件位于 `game/`，角色详细数值来自游戏数据文件，且没有统一的易读格式。参见 [提取项目自己的来源说明](https://github.com/CommunityDragon/Docs/blob/master/assets.md)。

| 英雄 | 16.17 基础攻击力 | 16.17 成长补证 | 16.1 官方及客户端历史成长 |
| --- | ---: | ---: | ---: |
| 盖伦 | 69 | 4.5 | 4.5 |
| 艾希 | 59 | 3.5 | 3 |
| 伊泽瑞尔 | 60 | 3.75 | 3.25 |

不是只按字段名称猜测：分别核对相同英雄的 `Characters/{英雄}/CharacterRecords/Root` 根记录及角色标识；历史 `16.1` 客户端的 `baseDamage`、`damagePerLevel` 与当期官方基础攻击力、攻击力成长完全一致。当前 `16.17` 的字段改为 `baseDamageModifiable.baseValue`、`damagePerLevelModifiable.baseValue`，当前基础攻击力也与官方相符，据此建立成长字段的交叉证据。艾希和伊泽瑞尔的当前成长与历史成长不同，表中没有把旧值直接沿用到当前版本。

三名英雄首次补证保留在原文件中，后续全英雄核对沿用这里确认的字段含义，但逐名读取本人的实际字段，不套用这三名的成长值。上一阶段伊泽瑞尔攻击力成长为 0 的数据需要主任务重新核对；本目录没有执行数据库修正。官方全零是否因为字段包装变更导致提取遗漏，仍只是推断，未认定根因。

## 全英雄根记录及等级候选

173 个英雄身份全部对齐，173 个客户端基础攻击力全部与官方值一致。172 名攻击力成长为明确有限值，赛娜缺少该字段。没有用不存在字段的默认值替代真实证据。每名完整角色根对象保存在 `角色根记录/`，全响应地址、版本、抓取时间、字节数和 SHA-256 在同文件及总清单中可追溯。首次三名的完整原始响应保留；另外 170 份大响应存放在 `.临时原始响应/`，由本目录 `.gitignore` 明确排除提交，复现采集脚本保留。

生成了 173 名英雄、共 1,661 个基础属性的 **1–18 级候选映射**。它只包含基础值和自然成长，不包含被动、技能、装备、符文、叠层或形态修正。系统属性标识保留为空，由主任务与实际游戏属性目录对应，不能拿来源字段直接当业务标识导入。

这轮全量核对明确了几类需要记录的问题：

- **60 名英雄的攻击速度基值与收益系数不同。** 攻速候选使用“基值 + 收益系数 × 成长百分比 × 等级成长因子”，不能统一使用“基值 × (1 + 成长百分比)”；例如拉克丝基值为 0.669，收益系数为 0.625。
- 贝尔维斯、烬缺少普通攻速成长字段，锤石缺少护甲成长，赛娜缺少攻击力成长，贝蕾亚缺少生命回复成长；另有 8 名英雄生命回复基础字段省略。对应候选保留缺失，不补零。
- 145 名明确使用普通法力的英雄可生成官方法力字段的候选。另 28 名特殊、无资源或未明确资源的英雄不统一当成法力处理，保留原值和待核对项。
- **37 名英雄至少有一项缺失或特殊资源待核对。** 这不表示角色整体不可录，也不表示其他英雄机制已全部覆盖。
- 官方 `26.1` 补丁规定上路任务完成后等级上限可到 20。本次沿用上一阶段 1–18 级范围；19–20 级未生成，也没有修改系统等级配置。[官方上路任务说明](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/)

等级曲线为 `基础值 + 成长 × (等级−1) × [0.7025 + 0.0175 × (等级−1)]`。本次核对了社区机制说明、已有冻结 Wiki 原文的相同因子，并用逐次升级累加检查全部候选等级值；未取得可读的官方旧补丁全文或游戏引擎源码。因此这里称“候选”，不能替代实际游戏或系统录入验收。[成长公式说明](https://leagueoflegends.fandom.com/wiki/Champion_statistic)

## 核对入口

在规划工作树根目录执行：

```powershell
node '数据参考/全量录入-2026-09/英雄/核对资料.mjs'
```

此核对证明原始来源与清单覆盖一致，不验证业务数据库、页面保存、机制表达或战斗执行。
