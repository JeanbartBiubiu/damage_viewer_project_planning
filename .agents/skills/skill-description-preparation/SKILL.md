# 技能描述整理

把本次选定的技能资料整理成数值与语义明确的中文文本，供[角色技能录入](../character-skill-authoring/SKILL.md)直接转换。已有上游模型确认的完整文本时直接交接，不把资料查询重新加回录入或验证流程。

## 读取与确认

1. 限定本次角色、技能及形态，复用任务中已有资料。需要查 Wiki 时，先按[外置归档索引](../../../数据参考/外置归档索引.md)准备本机资料，再从 `数据参考/lol-wiki-champions-full/README.md` 定位完整正文及必要模板；同槽有多份正文时保留相关分段。确认本地缺少所需内容后，再按本次范围补查对应资料。
2. 展开真正影响数值的模板或依赖，明确常量、完整等级曲线、公式、百分比单位，以及基础／额外／总属性的区别。需要算术展开或单位换算时用工具执行，不凭显示端点猜曲线、不用大模型心算结果代替工具。
3. 区分施放时间、行动占用、寻敌起点、弹道耗时和段间间隔；逐项保留触发条件、作用对象、次数及同目标规则。说明持续、刷新、消费、到期和读取时点，控制效果写清影响谁的哪类行动。
4. 正文、表格、模板或元数据冲突时，定点检查相关上下文。能消解的说明采用规则及简短原因；仍会改变转换结果的矛盾或缺项，集中交回调用方澄清，其他独立内容可继续整理。不要把推测写成已确认规则。
5. 将资料事实与用户已确认的项目取舍分别写明。不要因当前接口缺能力删改资料内容，也不在这里决定伤害关联、生成接口或开发机制。

只保留足以继续定位的必要资料位置；不要求版本对比、网址、修订号、文件摘要或长审计报告作为交接前提。

## 输出与交接

输出一段说明或少量条目，只填写该技能实际涉及的内容：

- 身份、形态、作用对象和范围。
- 数值、等级曲线、公式、单位、上下限及取值时点。
- 触发条件、命中／未命中、段数、同目标衰减或去重。
- 施放、延迟、持续、刷新、到期、冷却起点与恢复资格。
- 控制、标记、层数、消费与跨技能联动；资料明确的护盾、暴击或吸血等特殊资格。
- 用户已确认的抽象取舍，以及尚待澄清的具体信息。

文本应让下游无需重读原文即可知道要转换的规则。整理完成后交给[角色技能录入](../character-skill-authoring/SKILL.md)，计算验证由[技能伤害验证](../skill-damage-verification/SKILL.md)承担。本技能不写业务数据、不运行 Wasm，不附加英雄选批、账本或准入步骤。
