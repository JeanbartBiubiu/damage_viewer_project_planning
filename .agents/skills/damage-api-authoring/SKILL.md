# 数据接口录入

把有来源依据的候选写入当前管理模型，并证明只改变了本次核定字段。默认通过管理接口录入；需要检验表单行为或用户明确要求时再使用浏览器。技能不扩大用户授权的数据范围，也不把数据保存成功解释为计算可用。

## 先核对当前契约

1. 按根规则进入实际模块工作树，确认分支、脏改和正在运行的接口目标。规划工作树内的模块副本不作为当前接口实现依据。
2. 读取[现行入口与变更核对](references/current-api.md)，再定点读取本次对象的后端控制器、请求类型、校验服务和前端客户端。确认方法、路径、请求字段、空值、数组顺序、摘要或其他保护条件；结构变化时先更新本技能及受影响脚本，再写数据。
3. 从原范围账本选择对象，核对固定资料版本、已有排除依据与当前引擎能力。只补现有能力能准确表达的数据；缺数值、行动占用、周期节拍或机制时保留缺口，不猜值、不删除必要组成来绕过校验。

## 冻结、保存与回读

1. 用独立读取请求保存完整基线和摘要。冻结来源路径及文件摘要、候选、允许的字段变化和预期完整结果；已有未保存浏览器草稿先明确归属及保存状态，避免两条路径重复写入。
2. 复用现行聚合接口提交相关变化。同一技能优先一次保护保存，不用逐字段请求制造半完成状态。只提交本次字段，更新对象的请求值按写入类型构造，不能原样回传响应中的只读字段。
3. 写入前重新读取。当前完整业务内容等于候选时记录“已落地”，不重放；仍等于原基线且摘要匹配才保存。内容漂移时停止该对象，重新核对事实，不只换摘要后重试。
4. 保存后发独立读取请求，逐字段比较完整对象与预期，确认未改字段、关系、数值及顺序保持。响应丢失、超时或服务错误时先读回；未证实结果前不再次写入。不通过删除条件、填写假值或停用必需来源处理校验错误。
5. 记录对象、摘要前后值、请求与独立回读、实际差异及失败原因。令牌只通过进程环境提供，不进入参数、计划、证据或输出。管理保存、结构检查、正式编译运行和整对象可用分别报告。

## 当前技能聚合更新脚本

`scripts/apply-skill-plan.mjs`支持已有技能的参数、公式、效果、过程、内部状态与触发规则的新增和修改；不执行删除、技能新建或主体修改。新增值必须含与变更键一致的对象标识，修改值不带标识；两者都使用完整现行写入类型，不带游戏、所属技能和服务时间。脚本逐项投影并核对完整预期，计划格式与完整命令以`--help`为准。其他写入对象继续按其现行请求类型构造，不让脚本猜协议。先生成有来源的完整计划并只读检查，已有本次执行授权后可直接采用，不增加逐项确认。

```powershell
node .agents/skills/damage-api-authoring/scripts/apply-skill-plan.mjs --help
# 在当前进程提供 DAMAGE_AUTHORING_TOKEN，不将令牌放进命令参数。
node .agents/skills/damage-api-authoring/scripts/apply-skill-plan.mjs --api-base http://127.0.0.1:8080 --plan <冻结计划绝对路径> --output-dir <本次证据绝对目录>
node .agents/skills/damage-api-authoring/scripts/apply-skill-plan.mjs --api-base http://127.0.0.1:8080 --plan <冻结计划绝对路径> --output-dir <本次证据绝对目录> --timeout-ms 120000 --apply
```

默认只读检查不写业务数据；采用时每对象至多一次写入尝试。证据分次保存，不覆盖此前尝试。批次失败后先检查已落地结果，确认计划仍有效或修订计划，再显式执行；不能盲目重跑旧写请求。

请求默认等待 60000 毫秒，可用 `--timeout-ms` 在 1000～300000 毫秒内调整，等待范围包括完整响应体。超时不等于保存失败；先独立回读确认，结果已落地时显式重新执行只会跳过，不会重发该写请求。

## 完成标准

本次字段均有准确来源、保护保存及独立回读证据；未完成对象保留具体缺口。只在状态确实变化时维护原账本。按当前代码做受影响验证；涉及计算行为时使用正式Wasm核对，不用接口成功代替运行证明。只有完整范围及当前版本均通过真实验证的英雄、装备才开放计算选项。
