# 编写与验证技能

技能只保存一项需要判断、可重复使用的项目方法。一次性操作不建技能；通用协作底线放在 `AGENTS.md`；可可靠检查的规则交给脚本。用户明确指令优先于技能指南，技能不得扩大授权。

## 内容组织

- `description` 简洁写明何时使用、何时不使用，并把主要触发词放在前面。语言不作固定要求，本项目优先中文。
- `SKILL.md` 只保留选择条件、必要步骤、输入输出和完成标准。大量背景放入 `references/`，确定性操作或外部工具接线放入 `scripts/`，并只在任务需要时读取或运行。
- 命令、路径和输出契约只定义一次。不要在技能正文、参考文件和 `AGENTS.md` 中复制同一工作流。
- 使用祈使句和明确输入输出；避免口号、说服性措辞、重复的禁止清单和无实际分支的长流程。

## 按变更选择验证

| 变更 | 修改前 | 修改后 |
| --- | --- | --- |
| 行为变化：新增判断、授权边界或执行步骤 | 选择 1～3 个有界场景，记录当前规则下的结果；可复用既有失败 | 用相同场景核对新规则，确认纠正问题且未损坏保留边界 |
| 引用修复：路径、命令或失效链接，未改变流程含义 | 核对当前引用与实际文件、命令入口 | 检查目标存在、命令准确以及本次差异，无需代理压力测试 |
| 真源发布：共享技能从 planning/master 发布 | 确认真源分支和目标改动 | 在真源验证、提交并按授权推送；其他工作树由对应分支自行获取并合入，不直接写副本 |

修改命令时若改变权限、数据写入或执行顺序，按行为变化验证，不能按“改了一行”归为引用修复。

## 行为变化的轻量检查

1. 读当前技能、最近的 `AGENTS.md` 和实际入口，限定写入范围。
2. 记录场景输入、期望、当前结果和复查方法。没有既有记录时做一次小范围文本或实际基线，明确证据类型，不把推演写成真实代理结果。
3. 只修改已确认的问题，优先删除冲突、重复和易漂移信息。
4. 用相同场景复查。只有新事实暴露实质问题时才继续修订。

普通规则调整可直接做文本场景核对。只有需要确认代理能否发现并遵循技能，或需要独立检验授权、安全边界时，才读取 `testing-skills-with-subagents.md` 并考虑有界只读代理；不为机械修正组织多代理测试。

若技能导致暂停、请求确认、留下未完成工作或偏离用户目标，应在回复中指出具体 `SKILL.md` 和相关规则，并区分明确要求与模型解释。

## 真源发布

共享项目技能以 planning/`master` 的 `.agents/skills` 为真源。在该分支修改、验证，并按任务授权提交和推送。其他工作树由各自分支执行 `fetch` 后按 Git 策略合入；不要跨工作树直接复制文件或应用补丁来制造内容一致。交付说明真源提交及仍待各分支更新的漂移。

## 文件结构

```text
---
name: skill-name
description: <简洁说明使用与不使用条件>
---
# 中文标题
## 判断与步骤
## 验证方法
```

`description` 可使用项目主要语言；上例仅表示它要描述触发边界。只修改本次负责的路径。

## 完成标准

- 描述短且能准确触发技能，正文聚焦一项工作并与当前仓库权限一致。
- 已按变更类型完成相应检查；行为变化记录修改前后同场景结果，并标明是文本核对还是实际运行。
- 变更涉及的路径、命令和配套文件一致；差异检查通过。
- 没有重复上层规则、引入不可用工具依赖、额外审批或无关修改。
