# 角色技能录入

接收上游整理好的技能文本，判断伤害关联，拆解为当前系统的技能结构并生成接口请求。

## 输入边界

输入是 GPT 或其他大模型已经确认 Wiki 或其他技能资料后整理出的文本。默认资料为最新、数值正确，直接采用文本中的规则；不重复查询、核对来源或版本，也不要求网址、修订号、来源摘要或账本。

按任务取得技能标识、新建或编辑信息；编辑时取得现有配置以保留未改内容。只按需查现行接口类型、枚举和引用标识，入口为 `web/src/types/skillConfiguration.ts` 及其引用类型。公式结构查 `contracts/formula/README.md`。

只有文本内部矛盾，或缺少会影响结构和计算的必要信息时，指出具体缺项并向调用方补问；不自行重新调查资料。

## 转换步骤

1. 按“是否改变伤害金额、实际扣血、触发资格、可用次数或双方行动时序”判断相关性。保留直接伤害，以及属性、攻速、增减伤、减抗、标记、强化普攻、冷却和资源等间接影响。控制能打断或打乱对方攻击／施放时序时也保留。治疗、护盾等只保留与这条数值链有关的部分。
2. 排除无关部分；整技能无伤害关联时返回“跳过”及简短理由，不创建空技能。编辑时跳过不等于删除原配置。
3. 将保留内容逐项映射到以下结构，保证效果有实际触发和消费位置，不只创建孤立参数或公式。

| 系统组成 | 转换内容 |
| --- | --- |
| 主体 | 标识、分类、技能等级与启停 |
| 参数与公式 | 常量、等级曲线、运行输入、比例单位、上下限、基础／额外／总属性及读取时点 |
| 效果 | 有序数值结果、伤害类型、作用对象、生命周期及接口必需的结果声明 |
| 过程 | 施放延迟、行动占用、多段／周期、引导、重施与冷却 |
| 内部状态 | 层数、标记、模式、弹药、计数及消费、刷新、到期 |
| 条件与触发 | 真实事件、条件、动作、供值、次数限制及必要引用 |

4. 沿用贴脸取舍：位移和弹道不增加耗时，明确施放延迟与行动占用分别保留。控制作用于受影响一方的行动资格或排程，不能给施控者加延迟冒充打断。其他已有产品取舍按需查[系统模型](../../../文档记录/概要设计/项目/系统模型与计算协作设计.md#计算范围与简化取舍)。
5. 复用或组合现有能力。无法表达的内容列为具体结构缺口，不以删除必要效果、改数值或猜默认值绕过，也不在本技能内启动引擎开发。

## 输出与交接

输出接口请求、简短的“文本内容 → 系统组成”映射、排除项和无法表达的缺口。技能主体与必要关系按当前接口分别表达。

要求实际录入时，复用[接口录入技能](../damage-api-authoring/SKILL.md)的请求构造、摘要保护及独立回读步骤；上游已完成的资料确认不重做。只要求结构或接口请求时，到生成结果为止。

实际录入完成后，在同一任务将输入文本、转换结果和场景条件交给[技能伤害验证](../skill-damage-verification/SKILL.md)。本技能完成判断只覆盖本次文本的结构转换，不附加英雄选批、账本维护、整角色准入或发布流程。
