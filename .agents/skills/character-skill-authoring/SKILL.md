# 角色技能录入

先判断哪些效果影响伤害，再把有依据的部分映射到当前管理模型。完成目标是“来源可追溯、必要组成无遗漏、真实保存后能够验证”，不是把技能说明压缩成一条伤害公式。

## 资料与范围

1. 核对本次角色、技能槽、形态、新建或编辑、固定游戏版本及已有配置。范围和原有排除从[计算范围与录入边界](../../../文档记录/项目说明/计算范围与录入边界.md)定位，不因本次跳过而删除既有技能或关系。
2. 先读[全英雄 Wiki 入口](../../../数据参考/lol-wiki-champions-full/README.md)，核对清单、修订、完整正文和依赖模板；遍历英雄资料的全部技能正文，覆盖同槽多形态、分段及关联被动。记录采用的来源与版本差异；本地确实缺失后才补查对应页面。
3. 同时读取[系统模型与计算取舍](../../../文档记录/概要设计/项目/系统模型与计算协作设计.md)、[领域口径](../../../文档记录/领域知识库/README.md)和当前技能配置类型 `web/src/types/skillConfiguration.ts`。资料、已确认抽象和实际支持分别记录。

## 先判断伤害关联

按“是否改变伤害金额、实际扣血、触发资格、可用次数或双方行动时序”逐项判断，不以有无直接伤害作为唯一条件。

| 效果 | 处理 |
| --- | --- |
| 直接伤害、附加伤害、持续伤害、强化普攻 | 保留金额、类型、对象、触发与时间关系 |
| 属性、攻速、增减伤、减抗、穿透、标记、层数、重置、冷却、弹药与装填 | 保留对后续伤害的真实作用；通过实际后续攻击或技能验证 |
| 控制、打断、禁用行动 | 保留对受影响一方攻击、施放、引导和恢复时点的作用；纯控制也可能相关，不能因自身无伤害直接跳过 |
| 治疗、护盾、生命或机制资源变化 | 若影响生命阈值、存活、后续伤害、受击反应或触发资格，保留这条数值联系 |
| 装饰、视野等确无所选数值和时序影响的部分 | 写明排除理由；整技能均无关联时跳过本次录入，不创建空技能 |

无法判断时留下具体条件或资料缺口，不能把“尚未支持”当成“不相关”。编辑时重新检查被改部分及受影响的联动，不丢弃未修改组成。

## 拆解并核对能力

为每个保留项建立一行映射：**来源条目 → 数值或时间规则 → 所属组成与真实消费点 → 已支持或缺口 → 验证场景**。只在本次工作记录保留这张表，不建立另一份累计账本。

| 管理组成 | 必须核清的内容 |
| --- | --- |
| 技能主体与角色关系 | 身份、分类、等级、启停、所属形态及角色挂载；保存技能不等于已挂载 |
| 参数与公式 | 固定值、角色／技能等级曲线、运行输入、比例单位、上下限、对象、基础／额外／总属性及读取时点 |
| 效果 | 有序结果、伤害类型与对象、修正阶段、持续／到期／刷新，以及护盾、治疗等必要数值影响 |
| 过程 | 施放延迟、行动占用、多段／周期时点、引导、重施、冷却；延迟和行动占用分别确认 |
| 内部状态 | 层数、模式、标记、弹药、计数及它们的创建、消费、重置和到期 |
| 条件与触发 | 真实事件、触发者与承受者、成立／不成立条件、供值、动作、次数限制及跨技能引用 |

按以下取舍落地：

- 沿用默认贴脸：位移和弹道直接到达，不额外添加路径或飞行时间；明确施放延迟和行动占用仍保留。距离若参与伤害公式，仍需有依据的场景输入，贴脸不能代替未说明的数值。
- 控制应作用于受影响一方的真实行动资格、取消或排程；不能仅给施控者添加一个延迟冒充打断。若当前目标没有相应行动驱动，保留“对方时序尚不能验证”的缺口，不能判该控制完整可用。
- 按现行产品取舍处理施法费用、指定二次释放和蓄力，不机械还原全部游戏操作。简化不得补造命中、层数、受击或战斗时间。
- 先检查现有能力能否直接表达或组合。缺少必要机制时记录最小触发输入、预期数值／时序、当前错误及所属边界；已获开发授权则转入 `wasm-batch-mechanism-development`，否则把缺口交回当前任务。可继续处理独立且可准确表达的部分，但不能将半成品声明为完整技能。

## 保存与验证交接

1. 将核定映射变成完整候选，用[接口录入技能](../damage-api-authoring/SKILL.md)完成冻结、保护保存和独立回读；认证、接口字段及重试规则只在该技能维护。
2. 区分新建和编辑：现有 `apply-skill-plan.mjs` 仅更新已有技能；新建沿当前聚合新建接口或工作区执行，并独立核对角色挂载。不得给更新脚本更换请求方法来冒充新建支持。
3. 回读成功后，在同一任务立即使用[技能伤害验证](../skill-damage-verification/SKILL.md)。交接实际完整配置及摘要、来源版本、保留与排除项、抽象取舍、场景输入和未解决缺口；验证对象必须是这份回读配置。
4. 验证发现问题时，按资料／配置、生产适配、引擎能力定位根因，在原授权内修正并重验受影响场景。不能靠移除必要效果、补零或改期望消除差异。

## 完成标准

所有保留项均有来源、归属、触发与消费点；排除项有理由；保存有独立回读；数值与时序有验证结论。分别报告“跳过”“待补资料／能力”“已保存待验证”“验证通过／不通过”，这些是本次结论用语，不新增任务状态。单技能通过不代表整角色准入。
