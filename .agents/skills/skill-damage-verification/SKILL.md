# 技能伤害验证

验证“指定来源、配置摘要、场景范围和 Wasm 身份下，该技能的必要数值行为符合预期”。没有直接伤害的技能，通过它对后续伤害、生命或双方行动时序的作用验证。

## 冻结输入与场景

1. 接收[角色技能录入](../character-skill-authoring/SKILL.md)的来源、拆解与独立回读；单独复核时补齐这些事实。确认角色挂载、依赖、运行技能等级及完整配置摘要，不从编辑草稿或旧快照验收新保存内容。
2. 从[领域知识库](../../../文档记录/领域知识库/README.md)选择金额、生命、比例和读取时点口径。区分技能基础金额、`rawAmount`、防御后金额、护盾吸收、实际扣血及过量伤害；不能把这些字段互相比对。
3. 根据真实依赖选择有区分力的少量场景，通常先做三组：正常触发基线、改变关键等级／属性、条件不成立或边界。数量服从覆盖；不为凑组数重复等价输入，也不因只有三组而遗漏独立分支。记录输入、预期事件及对照字段。

| 存在的行为 | 需要覆盖的变化 |
| --- | --- |
| 等级曲线、属性倍率、生命比例、层数、阈值 | 各独立依赖至少变化一次；阈值两侧，必要时包含恰好等于阈值；确认基础／额外／总属性和百分比单位 |
| 条件、附伤、增益、减抗、标记、强化普攻 | 成立与不成立；用实际后续事件观察开启前后差异，不能只看配置存在 |
| 多段、持续、延迟、引导、弹药、冷却、刷新 | 逐笔金额、次数、顺序、时刻、到期和后续资格；动态读值须包含中途属性或生命变化 |
| 控制与打断 | 对受影响一方安排实际攻击／施放，对照中断前后、控制期间及恢复时点；检查已结算结果不回滚。无该行动上下文时报告能力缺口 |
| 护盾、回复、致死、免疫或阻挡 | 分别核对吸收、实际扣血／回复、过量、最终状态和停止／拒绝原因；0伤害不能代替触发结论 |

贴脸口径下不增加位移或弹道耗时；保留明确施放延迟、行动占用及控制中断。隔离无关装备、构筑、普攻和被动；必要联动不能关闭，应明确列出并加入对应对照。

## 先用工具计算独立期望

1. 从已确认资料和取舍写出分步算式、变量、事件时刻、条件及数值演进；大模型负责选式和解释，算术结果由工具执行。不得调用被测公式求值器、生产结算函数或 Wasm 来生成期望。
2. 默认使用[离线计算与对照工具](references/calculation-tool.md)。先执行计算并保存期望，再运行被测链路；保留计划、算式、输入、工具输出和摘要。复杂状态也可用独立 Node.js／Python 脚本计算，必须显式实现资料规则，不复制被测结算逻辑。无合适工具时保留“未验证”，不退回大模型心算。
3. 先核对期望规则与拆解映射是否一致。期望有误时回到来源修正，说明原因并重新冻结；不能看见 Wasm 输出后把它反填成期望。

## 运行真实已保存配置并对照

按[当前真实运行入口](references/wasm-route.md)读取新快照、核对配置身份，通过生产适配、正式 Wasm 编译和运行，检查完成状态并释放会话。工具故障、编译／解码失败、预算耗尽、报告截断、关键字段缺失或未完成执行，都不能当作通过。

- 保存完整原始结果，再通过工具读取字段对照，不手填“实际值”。每个场景都必须真正执行，触发基线必须存在预期事件；预期不触发时明确检查事件数和原因，不能用空列表的逐项检查冒充通过。
- 对照逐笔来源、技能／效果／结果、伤害类型、金额、次数、顺序、时刻、必要中间状态和最终生命／资源。总伤害相同仍需逐笔一致；依赖范围外的背景事件须显式解释。
- 金额使用现行机制比较口径：`abs(实际值 - 期望值) <= 1e-9 × max(1, abs(期望值))`。身份、次数、整数时刻和条件精确比较，不为通过任意放宽误差；读取完整性标记后才能用汇总或明细判定。
- 验证前后核对实际配置摘要及产物身份；期间漂移则结论失效，重取输入并复查受影响场景。合成机制通过不替代真实已保存技能通过。

## 差异与结论

差异记录到具体场景、字段、期望、实际值和首次分歧时点。先排查资料／抽象及期望，再检查录入映射、适配和引擎；已授权的修复继续完成，涉及新业务取舍时集中确认。必要缺口未解决时不得声明完整通过，也不以更换期望迁就实现。

完成时交付：来源与配置身份、Wasm 产物身份、场景及覆盖范围、工具计算证据、逐项对照结果、未覆盖或受阻部分。原始计划、快照、结果和报告放本次忽略输出目录；已有规则要求长期保留的通用机制用例和正式证明仍按[开发流程](../../../文档记录/项目说明/开发与独立评审流程说明.md)维护，不为每个英雄添加锁定配置细节的源码断言。

只有必要分支、相关数值及时间行为全部符合，且配置与产物身份有效，才判本技能在该范围通过。单技能通过不自动开放角色、扩大范围或改正式准入证明；首次完整对象准入仍走现行流程。

## 随工具能力演进

用户已授权：出现可实际使用的更合适工具时，可自动更新**本技能的工具选择、接线说明及必要辅助脚本**。先用同一组固定场景验证独立计算、正常一致、故意差异能失败，再切换；保留算式来源、独立性、证据身份和通过标准。运行工具不等于授权安装服务、修改全局配置或改变业务取舍。

工具升级按 `writing-skills` 做受影响场景检查；已确认无依赖的旧工具说明随切换清理。仅有新工具名称、未经验证的能力或同源引擎的输出，不构成切换依据。
