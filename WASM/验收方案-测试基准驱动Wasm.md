# 验收方案：测试基准驱动的 Wasm 实现

## 1. 验收目标

本方案用于验收 [详细设计-测试基准驱动Wasm实施方案.md](c:\project\damage_viewer_project_planning\wasm\详细设计-测试基准驱动Wasm实施方案.md) 的实现结果。

验收只看两件事：

1. 是否符合 [测试基准.md](c:\project\damage_viewer_project_planning\wasm\测试基准.md)
2. 是否符合详细设计里定义的中间结果、默认口径和模块边界

任何“能跑但不符合基准”的实现都不通过。

---

## 2. 验收顺序

## 2.1 静态检查

先检查这些点：

- 新增文件是否符合模块边界
- 子 agent 是否越权修改了不属于自己范围的文件
- 是否保留了现有 Wasm ABI 的基本兼容
- 是否把关键默认规则写死，而不是散落在魔法常量里

## 2.2 构建检查

至少通过：

```powershell
cd wasm/katarina_mvp_engine
cargo test
```

如果 Wasm 目标构建也已接好，再补：

```powershell
cargo build --target wasm32-unknown-unknown --release
```

## 2.3 基准测试检查

按下面顺序验：

1. 初始化编译
2. 首次普攻
3. 首次秘术射击
4. 首次奥术跃迁
5. 护盾生成与刷新
6. 黑切叠层与过期
7. 眩晕阻断
8. 资源门禁补充验收
9. 最终击杀

顺序不能反，因为前面的失败会污染后面的判断。

---

## 3. 必过断言

## 3.1 初始化编译

必须能确认：

- 属性 key 转换正确
- 攻速总值按 `base + bonus * ratio`
- 我方/敌方初始 HP 正确
- 装备属性累加正确

## 3.2 首次普攻

必须能确认：

- 生成一个聚合攻击事件
- 事件内至少有：
  - 普攻本体组件
  - 吸血刀组件
  - 魔法刀组件
- 生命偷取值可单独追溯

## 3.3 首次秘术射击

必须能确认：

- 技能本体与附带攻击特效分项分开
- 成功释放时法力扣减 `25`
- 冷却减少 `1000ms` 生效
- 若附带物理伤害分量，黑切层数更新正确

## 3.4 首次奥术跃迁

必须能确认：

- 主体魔法伤害正确结算
- 成功释放时法力扣减 `40`
- 面具 DoT 被成功入队
- DoT 共 3 次，不多不少

## 3.5 护盾

必须能确认：

- `t=0` 护盾生成
- 护盾先吸收、HP 后扣减
- 再次生成护盾时按“取大值”刷新

## 3.6 黑切

必须能确认：

- 同一攻击事件内多个物理伤害分量可叠多层
- 层数上限 6
- 5 秒不续层后正确清空
- 清空后护甲恢复原始值

## 3.7 眩晕

必须能确认：

- 眩晕生效时间和结束时间可记录
- 眩晕期间我方不会普攻和放技能
- 若存在可打断动作，能正确打断

## 3.8 资源门禁补充验收

必须能确认：

- 蓝量不足时主动技能不会成功施法
- 被阻止的施法不会扣蓝，不会进入冷却
- 被阻止的施法不会产出伤害、护盾、DoT、攻击特效、减 CD 等后续结果
- 自动决策会尝试下一个可释放动作；若无动作可放，则等待后续事件

## 3.9 最终结果

必须能确认：

- `stopReason = enemyDead`
- `samples`、`events`、`result` 都非空或符合设计预期
- 输出字段足够支撑回归

---

## 4. 拒收条件

出现任一情况直接拒收：

- 只输出总伤害，不输出组件级细节
- 护盾吸收顺序错误
- 生命偷取混入技能本体伤害
- 黑切只按事件叠 1 层，忽略分量叠层
- 眩晕只记录状态，不真正阻断动作
- 蓝量不足仍然成功施法，或被阻止施法后仍扣蓝 / 进入冷却
- 为了通过测试，绕过中间状态更新
- 把基准规则硬编码到单个测试里，而不是落到运行逻辑里

---

## 5. 主控集成检查点

集成时主控只检查：

- `model/catalog` 的接口是否能供 `engine/sim` 使用
- `runtime/effects` 是否按设计输出标准包与状态
- `engine/tests` 是否正确消费这些接口

如果子 agent 之间接口不一致，以详细设计文档为准，不以“谁先写完”为准。

---

## 6. 后续扩展门禁

只有当本阶段全部必过断言稳定通过，才允许进入下一步：

- 更通用的 formula profile/binding
- 多状态统一容器
- 更复杂的 action DSL
- 前端正式 bundle 接入
- 多个 test profile 扩展
