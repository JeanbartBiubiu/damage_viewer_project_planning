## 5. 导出 JSON 复核

多曲线导出包含：

1. `selection`：全局选择和每条 curve 的 `curveId`、`label`、`heroLevel`、`skillLevels`、`equipmentSet`、`enabledPassiveEffects`、`scenarioStates`、`critPolicy`。
2. `resolvedSnapshot`：目标快照和每条 curve 的 attacker/equipment/passive/scenario/rune 投影。
3. `simulationRules`：`durationMs=10000`、`attackSpeedCap=3`、`critPolicy=expected` 等规则。
4. `targetSnapshot`：`target_dummy_fighter`。
5. `wasmOutput`：完整 `curveResults`，包含 `damageTimeline`、`targetHpTimeline`、`damageByType`、`damageBySource`、`skillPassiveTriggers`、`itemPassiveTriggers`、`effectBreakdown`。

页面展示值与导出值来自同一个 `wasmOutput` / `preparedInput` 状态，运行后编辑 selection 会清空旧导出，避免展示与导出不一致。

## 6. Blocked 规则复核

本轮没有前端私造 hidden skill/effect/action：

1. 英雄、标靶、装备、技能被动和场景状态均从 published bundle 派生。
2. curve 请求的装备如果不在 ADC 成装 type 池或 bundle item 中，`selection.equipmentSet` 与 `resolvedSnapshot.equipmentSet` 会不一致，wasm 返回 blocked。
3. curve 启用的技能/装备被动如果没有对应 `resolvedSnapshot.passiveEffects`，wasm 返回 blocked。
4. 本轮默认 4 条 curve 在现有 `lol` current bundle 中数据齐全，因此均为 `ok`。

## 6.1 修复后复查

2026-05-18 23:58 复查上一轮 review 问题：

1. 移除前端 Batch B hard-code 技能等级表，不再由前端补出 published bundle 中不存在的技能等级数值。
2. 默认 curve 的 `skillLevels` 固定为 `P/Q/W/E/R = 1/1/1/1/1`，与当前 published bundle 中的 scalar 技能被动参数口径一致。
3. 如果用户把 Q/W/E/R 技能等级调到 2+，但 published bundle 仍只有 scalar 参数、没有等级表，前端投影不会私造等级值；该技能被动不会进入 `resolvedSnapshot.passiveEffects`，wasm 会按缺失被动返回 blocked。
4. 删除非 active curve 不再强制跳到第一条 curve；只有 active curve 被删后才由通用 selection 同步逻辑选择下一条可用 curve。
5. 汇总表新增 `Blocked Reasons` 列。
