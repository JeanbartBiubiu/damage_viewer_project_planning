## 3. DROP 前安全回滚（简述）

最终 DROP 在成功前曾两次安全回滚：

1. 分区上的 `fk_skills_owner_type` / `fk_skills_log_owner_type`（如 `skills_lol`）未纳入已知 FK 清单，被判为对 `owner_categories` 的未知依赖而中止。
2. 删除父表 FK 后 PostgreSQL 同步移除分区克隆约束，循环再 DROP 同名分区约束时报不存在而中止。

修复后改为对白名单 FK 使用 `DROP CONSTRAINT IF EXISTS`（仍无 CASCADE、仍拦截未知依赖），重跑成功。
