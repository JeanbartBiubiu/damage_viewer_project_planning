# 验证里程碑 V2：单攻击方 DPS 展示路线

本文定义 Damage Viewer 在 M1-M4 机制验证稳定后的下一条产品化验证路线：单攻击方平A DPS 展示。旧版 `文档记录/概要设计/验证里程碑.md` 继续作为 M1-M4 机制验证和 M5 小型 1v1 回归的 gate 文档保留；本文不覆盖旧验收结论，只补充“单攻击方 DPS + 技能被动效果 + 装备联动”的新验证主线。

V2 的目标不是恢复完整 1v1，也不是一次性录入全英雄、全装备或全主动技能。它优先服务一个用户能直接理解的输出场景：固定一个攻击方、固定标靶 actor、固定时间窗，展示平A、技能被动效果和装备联动对累计伤害、DPS、击杀时间和伤害构成的影响。

## 1. 当前决策

1. V2 只允许一个 actor 主动执行普攻动作；目标不主动行动、不反击、不释放技能。
2. “技能被动效果”包含英雄 P 被动，也包含 Q/W/E/R 技能描述里的被动、常驻、攻击触发、每 N 次攻击触发、on-hit、计数器和简单 DoT 等非主动释放效果。
3. 本期不录入 Q/W/E/R 的主动释放动作，不做技能轮转，也不做需要按键释放后才生效的主动 buff、toggle 或模式切换；这些后续可作为模式 preset 扩展。
4. 装备联动进入本期范围；只接入会影响平A DPS 的装备属性、装备被动和攻击特效，不接入装备主动技能。
5. 第一阶段以 ADC/平A流英雄为样本，但架构边界是“单攻击方 DPS”，不限定只能 ADC。
6. 前端优先做固定 preset 和图表输出，不先做自由战斗编辑器。
7. 验证通过条件不是“看起来曲线合理”，而是核心输出字段能回扣到版本、输入、攻击时间线、被动/装备触发和伤害拆分证据。

## 1.1 已冻结的方案边界

1. DPS 计算口径统一放入 `simulationRules`，至少包含攻速上限、首刀时间、时间窗事件计入策略、DoT tick 间隔、暴击模式和 seed。首版攻速上限按 3.0，暴击采用期望值，保留 seed 但不参与随机计算。
2. DPS 时间线核心由 wasm 负责，前端只负责从 published bundle 解析用户选择、组装数值快照、展示图表和导出证据 JSON。
3. Wasm V2 DPS API 一次接收多条 curve，一次返回多条 curveResults；所有曲线共用同一 case、版本、规则和目标快照。
4. V2 新增单攻击方 DPS driver，复用现有 runtime 的伤害、抗性、触发和效果结算能力，不另起一套伤害逻辑。
5. 技能被动、装备被动、触发型符文和场景预设状态都走统一 effect/trigger 口径；wasm 不写英雄或装备专属分支。
6. 时间线采用事件驱动，不做固定 tick 主循环。首刀在 0ms；DoT 首跳在 `appliedAtMs + dotTickIntervalMs`；事件计入规则为 `timeMs < timeWindowMs`。
7. 同时间点事件按固定优先级处理：过期事件、普攻命中、on-hit/技能被动/装备被动、DoT tick、HP/击杀汇总、下一次普攻排程。
8. 内部数值使用浮点，时间使用毫秒整数；攻击间隔由攻速换算后四舍五入到毫秒；展示层格式化，验收使用容差。
9. 目标不使用前端临时常量，而是作为 actor 进入发布链。首批新增 `target_dummy` type 以及脆皮、战士、坦克 3 个标靶 actor，并在目标选择栏优先展示。
10. 页面拆成两类：单英雄多曲线页面允许每条曲线独立配置等级、技能等级、装备、被动、场景预设和符文/属性调整；多英雄同装备页面共享目标、规则、装备和符文/属性调整，每行英雄独立配置等级、技能等级和被动。
11. 装备首期按“属性全覆盖、被动分机制闭环、未支持效果明确标记”推进。装备主动、击杀/参与击杀触发等可通过 curve 级 `scenarioStates` 显式假定触发，用于对比触发态价值，但不算自然触发证据。
12. 首批英雄样本为薇恩、提莫、韦鲁斯、卡莎、图奇、克格莫。克格莫 Q 被动攻速和 W 预开启进入首期；主动 Q/W/E/R 释放动作仍不进入首期。
13. 符文碎片和简单属性调整走 stat adjustments；致命节奏等触发或叠层型符文走 external passive effects。致命节奏进入 V2 首期扩展 case，但不阻塞普攻、英雄被动和装备主链。

## 3. V2-M0 DPS 口径冻结

V2-M0 的目标是冻结“单攻击方 DPS”这条路线的最小输入和输出口径，避免后续实现滑向完整 1v1。

最小输入：

1. `caseId`、`versionCode`、`wasmSha256`。
2. 攻击方英雄、等级、符文/天赋、装备方案和启用的技能被动效果。
3. 目标标靶 actor，包括 `targetActorId`、生命值、护甲、魔抗和必要的抗性选项。
4. 固定时间窗 `timeWindowMs`。
5. 固定 seed；无随机场景也保留 seed 字段，方便后续暴击或随机分支复现。

最小输出：

1. 攻击次数、攻击时间点和攻击间隔。
2. 每次伤害事件的来源、伤害类型、原始值、抗性处理后值和目标 HP 变化。
3. 汇总的累计伤害、时间窗 DPS、击杀 DPS、击杀时间、伤害类型拆分和来源拆分。
4. 技能被动效果和装备被动的触发明细。

非目标：

1. 不做敌方主动动作。
2. 不做 AI 出手策略。
3. 不做自由动作队列编辑。
4. 不把 V2-M0 变成完整战斗模拟器的输入协议。

## 4. V2-M1 普攻动作基准

V2-M1 只验证普攻本身。该阶段不启用技能被动效果和装备触发，只允许基础属性影响普攻动作。

Wasm 侧至少证明：

1. 攻击间隔来自攻击速度输入，并能稳定转换为攻击时间点。
2. 固定时间窗内攻击次数可复现。
3. 普攻物理伤害能经过护甲减免进入目标 HP 变化。
4. 无被动和无装备触发时，`damageBySource` 只包含普攻来源。

Web 侧至少展示：

1. 攻击方基础属性。
2. 标靶 actor。
3. 攻击时间线。
4. 累计伤害、时间窗 DPS 和击杀 DPS。

通过标准：攻击次数、攻击间隔、每次 HP 变化和汇总伤害没有未解释 diff。

## 5. V2-M2 固定时间窗 DPS 时间线

V2-M2 把普攻结果从单次事件扩展为固定时间窗统计。它仍不负责新机制，只负责把时间线和汇总指标固定下来。

核心输出字段：

1. `damageTimeline`：每个伤害事件的时间点和数值。
2. `targetHpTimeline`：目标 HP 随时间变化。
3. `totalDamage`：时间窗内累计伤害。
4. `timeWindowDps`：累计伤害除以固定时间窗。
5. `killDps`：目标被击杀时，累计伤害除以击杀时间；未击杀时为空或明确标记。
6. `killTimeMs`：目标被击杀时的时间点；未击杀时为空或明确标记。

通过标准：同一输入重复运行时，时间线和汇总指标完全可复现。

## 6. V2-M3 技能被动效果

V2-M3 录入并验证 P/Q/W/E/R 中和普攻或伤害直接相关的技能被动效果。这里的“技能被动效果”不是只指英雄被动 P，也包括技能描述中的被动段落。

本期纳入：

1. 常驻属性或常驻伤害修正。
2. 普攻触发的 on-hit 额外伤害。
3. 每 N 次攻击触发。
4. 普攻或伤害触发的计数器。
5. 简单 DoT，且 DoT tick 口径必须在 case 中固定。
6. 只依赖当前攻击方、当前目标和当前时间线的伤害增幅。

本期不纳入：

1. 需要主动按键释放的 Q/W/E/R 动作。
2. 技能轮转。
3. 需要敌方动作、位移、视野、召唤物或复杂目标选择的被动。
4. 多目标扩散或弹射。

通过标准：`skillPassiveTriggers` 能解释每次触发的时间点、来源技能、触发条件、效果值和进入伤害拆分后的结果。

## 7. V2-M4 装备属性与装备联动

V2-M4 将装备纳入本期验证范围。装备不只是属性包，也包括平A DPS 相关的被动和攻击特效。

本期纳入：

1. 攻击力、攻击速度、暴击率、暴击伤害、穿甲、护甲穿透等直接影响平A DPS 的属性。
2. on-hit 额外伤害。
3. 每 N 次攻击触发。
4. 暴击触发或暴击相关修正。
5. 简单伤害增幅。
6. 简单 DoT。

本期不纳入：

1. 装备主动技能。
2. 复杂唯一被动冲突裁决。
3. 自然击杀/参与击杀触发、位移、控制、召唤物或范围选择；其中击杀/参与击杀类效果可用 `scenarioStates` 显式假定触发后参与对比，但不算自然触发证据。
4. 依赖完整双方交互才能解释的装备效果。

通过标准：`equipmentStats` 能回扣 actor 快照，`itemPassiveTriggers` 和 `effectBreakdown` 能解释装备对 DPS、击杀时间和伤害构成的影响。

## 8. V2-M5 标靶 actor 与装备方案对比

V2-M5 用少量固定标靶 actor 和固定装备方案形成用户可理解的对比。标靶不是前端常量，而是进入发布链的 actor，并通过 `target_dummy` type 在目标选择栏优先展示。

首批标靶 actor：

1. 脆皮标靶：HP 2000 / 护甲 50 / 魔抗 50。
2. 战士标靶：HP 3000 / 护甲 100 / 魔抗 80。
3. 坦克标靶：HP 5000 / 护甲 200 / 魔抗 150。

装备方案建议先保持小样本：

1. 无装备或基础装备基准。
2. 偏攻击力方案。
3. 偏攻速/攻击特效方案。
4. 偏暴击方案。

通过标准：同英雄同标靶下，不同装备方案的 `totalDamage`、`timeWindowDps`、`killDps`、`killTimeMs`、`damageByType` 和 `damageBySource` 差异可解释。

## 9. V2-M6 前端 DPS 展示页

V2-M6 是展示闭环，不是自由编辑器。页面优先承载固定 preset、图表和证据导出。

页面至少展示：

1. 攻击方、标靶 actor、时间窗、装备方案和启用的技能被动效果。
2. 累计伤害曲线。
3. 目标 HP 曲线。
4. 时间窗 DPS、击杀 DPS 和击杀时间。
5. 物理、魔法、真实伤害占比。
6. 普攻、技能被动效果、装备被动的来源占比。
7. 触发明细表。

导出 JSON 至少包含：

1. `versionCode`、`wasmSha256`、`caseId`。
2. `attacker`、`targetActor`、`targetSnapshot`、`timeWindowMs`。
3. `equipmentSet`、`equipmentStats`。
4. `enabledPassiveEffects`。
5. `attackCount`、`attackIntervalMs`。
6. `damageTimeline`、`targetHpTimeline`。
7. `totalDamage`、`timeWindowDps`、`killDps`、`killTimeMs`。
8. `damageByType`、`damageBySource`。
9. `skillPassiveTriggers`、`itemPassiveTriggers`、`effectBreakdown`。

通过标准：页面展示值和导出 JSON 一致，且导出 JSON 足够支撑人工复核和后续回归。

## 10. Diff 排查顺序

V2 发现 diff 时按以下顺序排查：

1. 固定 preset 的输入是否变更。
2. 发布版本、bundle 快照或 wasm 文件是否不一致。
3. 攻击方基础属性、装备属性或标靶 actor 是否录入错误。
4. 攻击速度到攻击间隔的转换是否错误。
5. 技能被动效果或装备被动是否触发条件错误。
6. 伤害类型、抗性处理或来源拆分是否错误。
7. 时间窗、tick、击杀截断或汇总指标口径是否错误。
8. 前端图表是否只展示错误，还是导出 JSON 本身已经错误。

## 11. 明确非目标

以下内容不作为 V2 本期阻塞项：

1. Q/W/E/R 主动释放动作。
2. 主动技能轮转。
3. 敌方主动动作、反击、控制或打断。
4. AI 自动出手策略。
5. 完整 1v1 模拟器。
6. 自由战斗编辑器。
7. 全英雄、全装备、全被动覆盖。
8. 装备主动技能。
9. 召唤物、位移、视野、击杀刷新、多目标选择或复杂唯一被动冲突裁决。

这些能力仍是长期方向，但必须在单攻击方 DPS 展示路线稳定后逐步纳入。
