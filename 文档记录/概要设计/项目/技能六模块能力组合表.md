## 本期减法：已确认的计算口径

本节优先于下方完整能力库存及旧组合样例。**前三项、面具边界、事件驱动以及读条／中断／到期刷新／历史累计四项均已获负责人确认。** 本稿只修改设计范围，不删除已有代码、字段或正式数据，不把简化后的结果标成真实游戏完整战斗。

### 已明确的三项

| 项目 | 本期计算口径 | 同时移出的工作 | 仍需保留 |
| --- | --- | --- | --- |
| 1 取消施放费用 | 不计算法力、能量和生命等施法费用，不因这些资源不足拒绝本次施放。生命直接按场景输入起算，施法本身不再扣费。 | 施法费用登记、付款／退款、费用不足失败，以及配套的自然回复和等待资源恢复。 | 伤害、主动治疗和吸血造成的生命变化；公式引用的当前／最大生命、法力等属性；决定输出分支的怒气、热量、豪意等机制。 |
| 2 合并二次释放开关 | 拉克丝E、贾克斯E这类“先开、再结束”的单次使用，默认直接执行其结束／释放结果，不操作等待与二次按键。 | 开关窗口计时、手动与自然结束竞争、最早重按时点、单纯为关闭窗口而设置的交互。 | 同一次使用只结算一次；结果先后顺序；影响金额的明确输入。多个独立攻击或施放次数不因合并开关而增加。 |
| 3 省去时间窗口、取上限 | 有明确上限的蓄力取满；单次有限持续输出按完整段数；强化可用窗口不等待过期。 | 中间蓄力进度、窗口倒计时、迟到／提前操作等时机选择。 | 次数上限、叠层上限、一次消费及真实的增伤资格。永久叠层没有有限最大值，必须给场景层数。 |

“去掉资源费用”不等于删掉资源这个数值维度。怒气等按本次场景的初始状态与明确变化参与计算；例如强化需要消耗怒气时仍扣除相应怒气，后续技能不能再次使用已消费的同一份状态。生命施法费不再降低施法者生命，是本期主动选择的近似，因而不承诺复现完整的自损连招。

直接释放也不自动补出等待期间发生的受击、闪避或额外命中。如果这些事实决定最终倍率，须由下面的场景口径明确提供。

**负责人已确认的最大值边界：省去所选蓄力／重施等操作窗口的等待，条件和层数由场景给定。** 蓄力强度与单次有限持续输出的段数取满；受击次数、层数、生命比例和互斥状态不自动满足。场景选择满层时只采用有来源的有限上限；永久成长等没有有限上限的数值由场景输入，不能外推无限层数。这里不删除冷却、攻击节拍、弹药恢复、装填及影响金额的时间事件。

### 保留事件驱动：冷却、攻速、弹药与装填

负责人明确纠正：Wasm继续按事件时间推进，不能把本期结果改成完全不计时间的有限动作金额相加。冷却和攻击节拍仍决定何时可以执行下一次动作；弹药恢复和装填是特殊攻击机制，继续参与调度。

| 机制 | 已确认处理 | 与被精简部分的边界 |
| --- | --- | --- |
| 技能普通冷却、内部冷却、规则每目标冷却 | 保留开始、就绪与允许再次触发的时间；已有合法冷却修改继续影响后续事件。 | 去掉施法费用，不等于去掉冷却准入或把技能改成无限连放。 |
| 普通攻击节拍 | 以实际攻速配置间隔公式：间隔（秒）＝1÷攻速（次／秒）；转为引擎毫秒时为1000÷攻速。 | 公式产生下一次普通攻击的时间间隔，不额外生成一次攻击。取样与时间精度在实现时沿引擎契约明确。 |
| 普攻计时重置 | 本期暂不执行技能带来的提前重置，普通攻击继续遵守正常间隔。 | 不取消攻速收益；不将间隔公式本身当成一次“重置”效果。 |
| 弹药恢复 | 保留弹药消耗、恢复计时、补充及恢复后的可用资格。 | 自然回蓝等施法资源恢复退出，不影响武器／技能弹药机制。 |
| 特殊普攻装填 | 保留弹匣、当前发次、空弹限制、装填等待及装填完成事件。 | 起始弹药可由场景给定，但之后仍演进；不能直接给满跳过装填。特殊发次资格按其机制保留。 |
| 位移与弹道 | 动作允许执行时，直接到下一个目标点或目标，更新位置／到达事实并进入正常结算。 | 不模拟中途路线、逐帧移动、途中碰撞或飞行耗时；目标合法性、免疫、格挡等仍要判断。起终点或距离被公式使用时保留，不能因瞬时到达而把距离填零。 |

普通攻击的1÷攻速公式使用该攻击机制实际采用的攻速值；固定节拍或装填等特殊普攻继续遵守自身已核定规则，不为套用普通公式删除其限制。缺失攻速不能补成默认值，非正攻速不能执行除零并排出无限攻击。

输出可以按一次技能、连招或明确的战斗观察时长汇总。固定时长总伤害和平均每秒伤害必须来自该区间内实际调度、成功执行的事件；不能把完整技能总量直接冒充该区间输出。单次技能“完整段数”表示需要结算哪些段，不表示所有段挤在同一时刻；观察区间尚未到达的后续段不提前计入。

### 面具等按战斗时间成长的增伤必须单列

负责人另行强调面具的按秒增伤。这里的时间决定伤害倍率，属于战斗状态的数值来源，不能按“时间窗口省略”直接填成满层。已有[兰德里候选记录](/C:/project/damage_viewer_project_planning/数据参考/全量录入-2026-09/装备技能实录/Luna第三轮装备触发候选/候选汇总.json:99)也把持续伤害调度与受苦层数增伤分开列出；本文不重新猜测每秒数值和层数上限，原资料待核项保持。

| 时间的用途 | 本期处理 | 不可混同的地方 |
| --- | --- | --- |
| 等待二次按键／关闭窗口 | 合并成一次直接释放 | 不自动补窗口内受击或命中。 |
| 主动蓄力提高本次释放强度 | 按已定口径取满蓄力 | 不意味着所有“经过时间变强”的被动都取满。 |
| 强化攻击的可用期限 | 省去等待过期，仍只消费一次 | 不增加独立触发或攻击次数。 |
| 面具的随战斗时间增长增伤 | 保留进入本次计算时的战斗时长或层数；按核定的增长节拍、上限和触发资格取倍率 | 不默认开打即满层，不把伤害技能满段数等同于增伤满层。 |
| 灼烧等周期性伤害 | 保留本次有限段数；先按序逐段结算，再汇总总量 | 若跨段倍率、生命或护盾改变，不能先合并成一笔。 |
| 雷恩加尔W等时间窗历史累计 | 本次模拟内根据事件自动累计并移出过期记录；开始前历史由场景提供 | 历史累计量既不是窗口时长，也不是当前缺血量，更没有可随意取用的无限最大值。 |

具体到面具：单次伤害读取场景给定的当前战斗状态；如果计算覆盖若干秒和多笔伤害，则保留会影响倍率的相对发生时点，每笔读取该时点对应的增伤，再结算伤害。起始战斗时长与层数不能同时成为互相矛盾的独立输入，应选择一种作为事实来源，另一种按核定规则得到。起算事件、每秒增长和上限按来源核定，不在本稿假设首次命中已经获得一秒增伤。

因此本期省的是选定操作窗口与移动／飞行过程；**决定金额或资格的事件时间仍须保留。** 位移和弹道按已确认的直接到达近似处理，不额外等待真实旅行时间；面具读取简化后事件时间线上的真实战斗状态，不为补偿被省去的飞行时间提前加层。读条保留单一施放延迟，冷却、攻击间隔和装填不会随之被取消。

以下数字只解释模型行为，不是对应英雄的实际技能数值。

| 项目 | 已确认处理 | 例子与边界 |
| --- | --- | --- |

| 中断 | 保留明确中断事件及死亡对仍在执行的引导等过程的终止；先不做复杂操作取消、动画取消和逐帧优先级。 | 假设女枪R类引导有6波，第3波后被有效打断，后3波不再发生。控制能否打断按相应机制判断；已结算的伤害不回滚，其他已施加效果按自身生命周期处理。 |
| 自然到期／刷新 | 保留基本期限、自然到期、重施刷新及其对后续事件的影响；复杂暂停期限、逐层独立到期的新增专项先后置。 | 假设4秒攻速增益第0秒生效，正常第4秒失效；若配置为刷新期限，第3秒重施则第7秒结束。灼烧刷新不自动额外叠加整套伤害。已有相关能力可复用，不主动回退已验证实现。 |
| 历史累计 | 本次模拟内的受伤、层数增长等由真实事件累计；滚动窗口按事件时间过期。模拟开始前的历史和初始层数由场景提供，不回放此前整局。 | 假设统计最近4秒，第1秒受伤100、第3秒受伤200，第6秒读取只包含200。狗头初始层数可输入，本次新获得的层数仍自动更新；近期伤害不能用当前缺血量替代。 |

滚动窗口的战前历史若要继续参与之后多次读取，场景输入须能说明这些记录何时过期；只给一个无时间的累计总数不能被当作永远有效。本稿不冻结具体存储字段，实现时按实际场景确定最小输入形状。

本次确认覆盖以上四项；脱战、复活等其他机制继续沿既有范围，不从这次确认额外推导新的排除或开发任务。

本期结果沿Wasm事件驱动计算：**指定起始状态、操作方案或观察时长，按施放延迟、冷却、攻击间隔、弹药、装填、明确中断及效果到期／刷新等事件依次产生结果，并更新本次模拟的必要历史。** 自动选择最优操作与时机是否实现是另一个问题，不影响必须保留事件时间与准入。

减法集中在施法费用、特定操作窗口和移动／飞行过程，事件驱动内核保留。单次技能可使用已确定的满蓄力强度和有限完整段数；攻击、恢复弹药、装填完成及伤害等仍在各自时点发生，面具按每笔实际事件时点取增伤。额外场景条件只在确实影响结果时出现。

减法后的组合主线是“选定场景与操作→按事件时间检查冷却／攻击／弹药／装填资格→执行动作与到达目标点→结算本笔效果→更新生命、护盾和必要状态→安排后续就绪／恢复／装填／效果事件→继续到指定结束条件”。六模块与事件时间线共同保留。

### 暂缓的开发依赖

- 不再以“付费→退款→自然恢复”完整链作为库奇Q、索拉卡R等进入计算的前置。
- 拉克丝E／贾克斯E不再以重施窗口、到期竞争为前置；先表达唯一的释放结果。
- 满蓄力数值可直接使用已核定上限，不要求先开发中间蓄力过程。
- 不回放模拟开始前的整局历史；本次模拟内历史按事件维护。单一施放延迟、明确中断、基本到期／刷新、冷却、攻速、弹药恢复和装填均保留。
- 迦娜E若场景只给“盾和增益当前存在”，可以先计算该状态下的输出；一旦计算中真的发生破盾，就仍须同步失去依赖增益，不能把它当作时间窗口略去。

## 1. 先确认的模型

保留六个配置模块：主体与分类、参数与公式、效果与生命周期、施放过程、内部状态、条件与触发。它们是职责划分，不要求一模块一张表，也不要求把技能现有组成拆成全局共享实例。

每份参数、公式、效果、过程、状态和规则继续归属于具体技能。两个技能可以分别配置同一种“蓄力”或“伤害”能力，共用编辑、校验和运行机制。需要联动时，再明确由哪个技能拥有状态、哪个事件或动作能够访问它，不能仅凭对象名称相同认定共享。

以下概念也要分开：

| 概念 | 本稿的含义 | 例子 |
| --- | --- | --- |
| 子能力 | 能独立说明输入、行为、输出与限制的机制 | 蓄力、普通护盾、内部计数 |
| 动作 | 某次事件或时点实际要求执行的操作，须说明所属层次 | 规则可执行效果或启动过程；消费计数经过程时点操作，重置冷却经效果执行 |
| 关系 | 将配置和执行上下文连接起来的引用 | 步骤完成时执行某效果；动作给公式提供本次蓄力时长 |
| 配置实例 | 属于具体技能的一份数据 | 蔚Q自己的蓄力过程与伤害公式 |
| 运行实例 | 某次施放、某个目标上实际存在的状态 | 本次蓄力、本目标的三层标记、本次护盾 |

主体身份、分类和公式定义不必伪装成执行动作。公式负责算数；过程负责阶段；效果负责变化；状态负责记忆；规则负责把事件与动作接起来。

  F --> D

  D --> H[结果或生命周期事件]
  G --> H
  H --> B
  N[参数与公式] -. 提供数值 .-> C
  N -. 提供数值 .-> E
  N -. 提供数值 .-> D
  S[内部状态与运行事实] -. 供条件和动态输入读取 .-> C
~~~

图中的回流表示可能产生后续事件；实际配置仍须满足引用、顺序、次数和循环保护，不能理解为任意递归均可执行。首次施放成功、真实命中和伤害结算是不同事实，不能由其中一个自动替代另一个。
