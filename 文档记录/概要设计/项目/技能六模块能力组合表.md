# 技能计算取舍与六模块职责

本稿保留已确认的产品取舍；具体对象必须符合实际适配与引擎准入，不能因取舍已确认就宣称全部实现。旧49名英雄与逐槽组合库存已移除，范围及排除只查[原账本](../../../数据参考/全量录入-2026-09/阶段进度.json)。

## 已确认的计算取舍

| 项目 | 保留的口径 |
| --- | --- |
| 施法费用 | 本期产品计算不收取法力、能量或生命施法费用，不模拟费用不足及付款退款；怒气、热量等影响输出的机制资源按其明确规则消费。底层仍有通用资源能力，不能把普通资源键当成实际生命扣费 |
| 指定二次释放与蓄力 | 所选开关合并为一次直接释放；有明确上限的蓄力可取满。窗口内受击、命中及层数不自动满足，影响金额的条件由场景或真实运行事实提供 |
| 有限持续输出 | 单技能可按完整有限段数分析；固定观察区间只累计区间内实际结算，后续段不提前计入。跨段生命、护盾或倍率变化时逐笔计算 |
| 冷却与普通攻击 | 保留事件时间、普通／内部冷却、攻击节拍及已接入的冷却修改。普攻按其真实节拍或特殊机制执行，不把全部动作堆到同一时刻；计时重置按已接入机制判断，不再沿用旧稿一律暂缓的限制 |
| 弹药与装填 | 保留消耗、恢复、空弹限制、装填及后续可用资格，不能仅给初始满弹而跳过之后的演进 |
| 位移与弹道 | 在所选近似下直接到达目标，不模拟逐帧路径和飞行；公式需要的距离、起终点及命中资格仍须明确提供，不能填零代替缺失 |
| 读条与中断 | 采用明确施放延迟，先不细分动画帧；保留已定义的中断和死亡终止，已结算结果不回滚。具体场景是否接入对应控制仍独立判断 |
| 到期与刷新 | 保留效果期限、自然到期、重施刷新及对后续事件的影响，不因简化操作窗口删除已验证的生命周期 |
| 层数与历史 | 有限上限按来源核定；永久成长和战前状态由场景输入。本次模拟内的累计按真实事件变化，滚动历史需保留过期时点，不能用当前缺血量代替近期受伤 |

面具等按战斗时间增长的增伤不默认满层。每笔伤害读取其时点的真实增伤；起始时长与层数选定一个事实来源，另一个按核定规则取得。省去蓄力或飞行等待，不补造额外战斗时间、命中或层数。

## 六模块各自负责什么

| 模块 | 职责 |
| --- | --- |
| 技能主体 | 身份、分类、等级及启停 |
| 参数与公式 | 有来源的数值、等级曲线及明确输入到结果的计算 |
| 效果 | 一组有序结果及必要生命周期，不决定任意触发时机 |
| 内部状态 | 计数、弹药、模式、标记及内部冷却等技能自有数据 |
| 过程 | 施放步骤、明确时点、行动占用及关联冷却 |
| 条件与触发 | 真实事件、条件、动作、供值及同次使用等限制 |

统一编辑和组合保存已进入代码；不再保留另一次拟建页面或存储模型的施工计划。源码入口见[系统精简设计](实录驱动的系统精简设计.md)。上述简化用于有限数值分析，不承诺完整游戏还原；尚未接入的来源、空间、多单位或控制效果逐对象列出限制。
