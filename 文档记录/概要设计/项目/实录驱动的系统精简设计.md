# 实录驱动的系统精简设计

本文保留当前管理模型及责任关系。字段、枚举、校验和接口的完整定义由建表脚本、共享规范和实际源码维护；已完成的逐表与逐页面施工设计不再另存。

## 数据怎样流动

管理页面编辑配置，后端校验、保存并维护引用；场景接口在一致性只读事务内读取所选对象及必要依赖；前端适配为计算请求；Wasm独立校验并运行；页面消费真实结果。后端不执行战斗，Wasm不读取数据库或管理接口。

## 当前管理模型

| 数据 | 所有者与边界 |
| --- | --- |
| 游戏、属性、等级、角色与装备 | 维护稳定标识、来源及直接数值，角色与装备属性和技能行为分开 |
| 技能及六类组成 | 主体、参数／公式、效果、内部状态、过程、条件触发由同一技能组织；统一工作区提供完整读取和受摘要保护的组合保存 |
| 状态与修正区域 | 目录声明身份、合并及计算方式；作者选择真实目录，不按名称猜算法 |
| 构筑 | 系统、分组、可选项与技能授予；选择和投入合法后产生真实来源实例，取代旧符文专用三表 |
| 关系及图片 | 角色、装备、构筑挂载技能；图片独立存储并关联业务对象，列表与内容读取分开 |
| 引用索引 | 后端按最终配置提取并定向维护，供删除保护及反查；没有独立人工编辑接口 |

[建表脚本](../../../db/game_manage/schema.sql)当前定义30张public逻辑表，包含图片分区父表，不含图片子分区；这是静态结构，不是实库核验结论。五类技能根对象的结构化内容保存为JSONB，明细不再拆成旧节点表。构筑四表、吸血规则及计算规则均按现行脚本维护。

## 保存与读取责任

统一技能配置以整技能摘要防止旧页面覆盖，在同一游戏写锁及事务内检查最终组合。未提交对象保留，组合失败全部回滚；前端草稿、基线和离开保护由统一工作区负责。具体接口及源码入口见[后端说明](../../../server/data_manage/README.md)和[前端说明](../../../web/README.md)。

参数可以是固定值、角色等级值、技能等级值或运行输入；定义不混入本场状态。已有值可直接引用，不强迫经过中转公式；需要计算时使用[共同公式](../../../contracts/formula/README.md)。战斗状态、技能内部状态、效果生命周期及运行供值各自保留归属，不能用一个通用字段抹平。

共同公式与[固定枚举](../../../contracts/system-enums/README.md)分别拥有结构及固定选项。技能、属性、伤害类型、对象关系及数值仍由作者配置；数值内核不按英雄、装备或目录中文名分支。

资料依据、保护保存、独立回读及完整对象准入见[录入边界](../../项目说明/计算范围与录入边界.md)。数据库脚本、管理保存、编译成功及运行通过分别提供证据，不相互代替。
