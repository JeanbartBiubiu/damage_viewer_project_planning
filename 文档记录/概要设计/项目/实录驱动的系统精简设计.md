# 实录驱动的系统精简设计

本轮先将原91张业务逻辑表收敛为24张，再根据真实符文录入需要增加3张，当前为27张。按技能组成独立维护的管理接口、直接取值、命中条件与角色录入检查继续复用。发布功能取消，不保留旧存储或旧接口兼容层。减少表数服务于维护和理解，正确性由保存校验、引用保护和实际回读保证。

本文拥有当前系统边界与存储设计；字段约束见[系统精简实施说明](../../详细设计/项目/系统精简实施说明.md)，维护者操作见[角色技能数据录入标准流程](../../详细设计/项目/角色技能数据录入标准流程.md)，实施与真实验证证据见[本轮验收记录](../../测试记录/项目/实录与系统精简验收记录-2026-09-06.md)。

## 当前存储结构

`public`中现有27张业务逻辑表：原23张保留表、1张系统引用明细及3张符文表。原68张技能内部明细已收入五类聚合并移除。此数字包含图片分区父表，不包含图片子分区、分区索引或账户模式中的表。图片分区、账户与访问记录不为凑表数而删除。

2026-09-10 的只读实库核对确认：实际27表、当前后端建表脚本27表、本文表清单一致；图片当前有1个表分区，另2条索引挂接不是表分区。核对只执行4次目录查询并回滚事务，没有改业务数据或结构。证据见[结构复核](../../../数据参考/全量录入-2026-09/结构复核-2026-09-10/README.md)。持续状态施加及符文生成装备的本轮问题都能沿用现有根对象和关系处理，目前没有继续合并表的实际依据。

| 保留部分 | 表 |
| --- | --- |
| 游戏、角色与等级属性 | `games`、`attributes`、`game_level_configs`、`characters`、`character_attributes` |
| 装备、通用字典与状态 | `equipment`、`equipment_attributes`、`damage_types`、`modifier_zones`、`statuses` |
| 图片与明确挂载关系 | `images`、`character_skill_relations`、`equipment_skill_relations`、`image_relations` |
| 技能基本资料与分类 | `skill_categories`、`skills`、`skill_category_relations` |
| 可独立维护的技能组成 | `skill_parameters`、`skill_formulas`、`skill_effects`、`skill_internal_states`、`skill_processes`、`skill_trigger_rules` |
| 系统生成的引用明细 | `skill_object_references` |
| 符文身份、布局与技能挂载 | `runes`、`rune_paths`、`rune_skill_relations` |

每个技能组成以所属游戏、技能及自身稳定标识定位，整项读取和保存。名称、类型、排序等检索字段仍使用普通列；子项使用 PostgreSQL 的 `jsonb` 类型保存有明确形状的结构化数据。

| 聚合根 | 结构化内容 | 吸收的原内部表数 |
| --- | --- | ---: |
| 技能公式 | 表达式树，保留深度与节点数限制 | 1 |
| 技能效果 | 结果数组、数值规则、类型明细、可选生命周期及结果生命周期行为 | 23 |
| 内部状态 | 与类型对应的唯一明细，含模式选项 | 5 |
| 技能过程 | 步骤、冷却、效果挂接与状态操作；效果挂接属于过程，不藏进步骤 | 11 |
| 触发规则 | 事件来源、条件组、有序动作、动态输入、修正及次数限制 | 28 |

角色等级属性整图、装备属性图及参数等级数值维持各自保存边界；固定参数仍为数值列。结果、步骤、模式选项、条件和动作保留稳定标识。前端不操作内部表，也不把整个角色或技能变成一个无边界的大字段。

符文身份独立于技能，分组以一个有序槽位数组维护布局；同一属性碎片可以在不同槽位复用，不复制身份。技能挂载复用现有技能组成，图片沿用单张`image_relations`关联表，未增加符文专属效果或图片表。新增三表分别承担身份、布局和关系，继续压成一张表会混淆保存与引用边界，目前没有实录依据支持这样合并。共享字段和删除保护见[符文基础管理契约](../../详细设计/项目/符文基础管理详细设计.md)。

## 保存校验与引用保护

同游戏配置写入先锁定对应游戏行，再读取依赖、校验并保存对象。在同一事务提交前，从该游戏各根对象的明确字段重建引用并复核最终状态；失败回滚业务内容及引用。该顺序同时覆盖新增引用、修改被引用内容和删除对象，避免两个写入各自通过却留下失效引用。

引用明细记录来源游戏、技能、对象种类、稳定标识和字段路径，以及目标种类、技能、稳定标识和可选子项标识，并按目标组合键建立反查索引。它是系统派生的检查与反查数据，没有手工编辑入口，不反向生成业务对象。当前采用全游戏重建，不增加增量维护框架。

保存继续核对字段、等级范围、同游戏与同技能约束、目标及子项存在、类型不可变、动作先后、动态输入和循环。参数、公式或生命周期等依赖变化也检查已有使用者，不能只保护删除。数值按十进制保存，空值、固定零、数组顺序和子项标识保持各自含义。

这些保证适用于服务的受保护事务；直接 SQL 不享有同样保护。恢复依靠明确备份与快照，不长期保留旧表视图或两套字段。只为实际查询路径增加索引，不对每个结构化字段预建通用索引，也不加入多人编辑合并或假设容量不足的基础设施。

## 当前管理能力

| 录入需要 | 已实现方式 |
| --- | --- |
| 常量和单个参数无需中转公式 | 数值位置直接选择固定数值、当前技能参数或具名公式；只有组合表达式或明确复用才建公式 |
| 私有持续效果直接作为条件 | 生命周期检查支持存在、不存在和层数比较，沿用效果实例范围；W 已移除计数投影与同步规则 |
| 读取引爆技能原始消耗 | 明确来源技能的技能命中规则可按资源属性绑定来源施放消耗，目标为可达的十进制动态参数 |
| 按实际命中目标分支 | 技能命中或普攻命中可选择目标类别；同一条件内多选表示任一类别，条件组内要求全部条件成立 |
| 区分命中与法术护盾阻挡 | 技能命中提供独立的整数 0/1 护盾事件值；结果另行声明阻挡粒度，空值表示该结果不参与护盾处理；旧伤害阻挡值含义不变 |
| 目标状态持续存在并参与护盾阻挡 | 持续状态施加允许当前结果粒度，复用父效果生命周期；表单、响应解析和后端校验一致，维迦E已有真实页面保存及独立回读证据 |
| 修改已有动态输入依赖 | 复制为新效果，逐条同时切换规则动作和绑定，最后删除无引用旧效果；复制不自动迁移使用者 |
| 无条件初始被动 | 来源对象初始化完成事件复用触发聚合和自身动作；空明细、无事件数值、初始化一次，未新增表，既有库只扩充事件类型检查约束 |
| 独立来源的比例修正 | 复用乘区字典为不同合并组增加记录，组内按层加算、组间按配置顺序组合；黑切与放血者已保存各自减抗区，不增加装备专用表 |
| 装备常驻直接属性 | 轻灵之靴25%减速抗性只新增属性字典记录和现有装备属性值；与移动速度并列维护，不因文字称为被动而额外建立技能、触发或新表 |
| 从角色连续录入 | 关联技能或录入检查可直达选中技能，返回同角色并保留筛选；候选显示名称与稳定标识 |
| 图片随对象维护 | 业务对象直接上传并建立代表图片关系，也可选择当前游戏已有图片 |
| 符文身份与分组录入 | 独立管理页维护身份、有序槽位、技能挂载与代表图；本地分页，整体保存布局，碎片跨行复用 |

子结果、步骤、条件和动作弹窗只更新父草稿，最终由效果、过程或规则保存整个聚合。保存失败保留草稿；动作显示顺序与保存排序一致，条件组编辑使用稳定的页面标识，比较摘要显示实际取值。操作步骤不随存储合并变成跨对象批量保存。

## 角色录入检查与完成边界

角色录入检查只读取当前角色及直接挂载技能，检查基本字段、原始等级属性整图、挂载和直接引用，并提示未接入效果、未启动被动过程等需要人工判断的情况。检查结果不保存，不阻止其他配置保存，也不创建发布版本。

页面分别显示结构结论、机制结论和运行结论。结构无错误只说明本次自动检查未发现已定义的问题；未接入提示不代表对象无用。机制始终显示未检查，运行始终显示未执行，完整表达能力仍需按资料人工核对，计算结果需要另外的实际运行证据。

2026-09-06 的伊泽瑞尔样例管理实现与数据整理已完成，以下数量仅属于该样例，不是当前全量英雄完成情况。Q/E/R 实际命中接线已通过浏览器保存及完整接口回读，R 使用两个独立类别分支，四处伤害的结果护盾粒度已核对。10 个父对象的 21 处取值已改为直接参数，并按引用顺序删除 25 个无用公式、5 个无用参数，公式从 31 减至 6、参数从 57 减至 52；其他效果、过程、规则、角色整图、关系及图片保持预期。最终角色检查为 5 个技能、16 项属性，零结构错误、零待核对；14 个独立算术样例通过。完整数据对照及证据见本轮验收记录，这些结果不代表战斗执行已验证。

2026-09-09 全量实录继续进行，当前进度以[阶段进度](../../../数据参考/全量录入-2026-09/阶段进度.json)为准。符文三表已经实际落库，迁移提交前确认原24表数据摘要不变；身份、布局、直接图片上传及技能挂载已有真实页面和API证据。玩家符文页与战斗选择装配仍不在本次管理范围。来源初始化直接复用现有聚合；重伤跨来源只取最强、百分比穿透剩余比例组合、控制强度绑定及伤害/击杀事件限定英雄等已发现缺口，后续采用明确字段或校验的最小修正，不因出现一种新机制就增加专用表。当前27张表不能被表述成全部范围内机制已经录入。

2026-09-13 六项英雄主动触发补录再次验证，既有技能过程、技能效果和触发规则三个聚合根可以覆盖“启动完整施法过程”和“按顺序直接执行已有结果”两种常见入口，无需新增表或拆回内部明细表。赛恩W首次施放与再次施放、蔚P冷却资格的未决点属于宿主事件阶段和状态语义；在生产路径未证明前暂缓接线，也不能以增加表数量代替事件契约。当前实录没有提供继续合并或扩展27张表的依据。

同日后续七项英雄复核又用相同三个聚合根安全接入六条规则。安蓓萨W唯一阻塞是护盾公式所需角色等级没有合法动态输入来源，属于供值契约与宿主快照缺口，不是表结构缺口。同期两轮八件装备触发候选均因冷却、状态、同次施放去重、击杀参与窗口或时序证据不足暂缓，也没有形成新增或拆分表的依据。当前27张表继续保持不变，先按能解锁最多候选的事件与供值能力迭代。

本轮未接通或验证这些管理配置到位置、弹道、碰撞、选敌、命中事件、施放消耗快照、计时与战斗执行的运行路径，既有 Wasm 能力以其自身验收范围为准。W 额外消耗及消耗修正后的退款口径、印记数值留存时点，以及未确认目标类别继续作为游戏事实待核对；缺少上下文不能补零或默认命中。本轮不为这些未决问题继续扩展系统，也不把存储与管理验收写成完整英雄机制已运行。
