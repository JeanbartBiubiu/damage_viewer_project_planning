# 实录驱动的系统精简设计

当前决定：停止推进发布功能。通过浏览器录入本地伊泽瑞尔的技能，先修复录入阻碍与已确认的数据问题，再确定存储精简边界。减少表数服务于维护和理解，不作为独立的正确性标准。本文拥有本轮系统边界与表设计；操作步骤见[角色技能数据录入标准流程](../../详细设计/项目/角色技能数据录入标准流程.md)，实际证据见[本轮验收记录](../../测试记录/项目/实录与系统精简验收记录-2026-09-06.md)。

## 当前基线与短方案

2026-09-06 只读核对 `test0221`：`public` 有 91 张业务逻辑表，与后端 `schema.sql` 一致；加 `images_lol` 子分区和 `user` 下三张表共 95 个物理表对象。现有角色为伊泽瑞尔，正式挂载技能为 `ez_p/q/w/e/r`。数据已包含参数、公式、效果、过程和触发规则，不能以空表演示替代实录。

本轮执行顺序：

1. 保存现有聚合接口的只读快照；浏览器修改前核对对象、资料和引用。
2. 从角色按被动、Q、W、E、R 顺序进入技能；补齐明确数值，逐层检查公式、效果、过程与命中关联。
3. 修复角色侧无法直接进入技能录入的操作问题，复用现有页面及未保存保护。
4. W 先用已有私有生命周期修复命中挂标和刷新时限；来源消耗与目标类别等缺失契约单独明确，不用伪造属性、通用状态或必定命中近似掩盖。
5. 形成可逐表核对的精简方案和实际可重复的录入流程。物理删表迁移须在聚合契约与完整性边界收敛后执行，不能先删表再寻找数据含义。

普通界面和数据修复只检查受影响路径、保存回读和对应局部测试。涉及聚合迁移时，仍需一次完整数据对照与引用检查；这不是恢复发布功能。

## 完整性与发布取消后的检查

保存仍校验字段、等级范围、对象存在、同游戏和同技能、动作先后、动态输入与循环；删改检查指向根对象及结果、步骤、模式选项的引用。技能内部的稳定标识继续保留。

引用明细由服务从保存对象提取，与对象同事务替换，仅用于反查和检查，不提供手工编辑入口，也不反向生成业务对象。多态引用表不等于外键：合并后的结构由服务保存校验、事务内引用重建和删改互斥保证，不能声称任意直接 SQL 都安全。实施迁移时采用统一的同游戏配置写入事务锁，先校验再写入；不额外设计多人编辑合并系统。

取消发布后，以只读的“角色录入检查”发现缺失技能、失效关系、未接入的效果和明确未表达的机制。它不创建版本或快照表，不把完整录入做成基础资料每次保存的前提。保存通过、资料可表达与计算已运行是三个不同结论。

## 迁移必须保留的最小证据

物理迁移前后按稳定标识比较现有聚合接口，检查数值精度、数组顺序、空值和子项标识；引用重算一致、无悬空引用；每类聚合至少一次真实增改回读，以及被引用子项拒绝删除、循环与动态输入错误拒绝、一次新增引用与删除目标的冲突检查。最后回读本地角色并检查图片内容未变化。

2026-09-06 已将原开发库迁移为 24 表并完成上述存储证据，后端提交 `c23c9b3`。具体分步实施以[系统精简实施说明](../../详细设计/项目/系统精简实施说明.md)为准。Wasm、弹道、事件调度、真实伤害计算和线上部署不因本轮录入而被视为完成。

W 原先的双重表示来自条件只能读取内部状态。现已实现直接检查当前技能生命周期是否存在及层数，并通过真实页面替换四条引爆规则后，清理计数投影、两条同步规则和两个同步过程；真正的弹药、模式、独立计数仍保留内部状态。引用提取、校验和前端候选已同步完成。生命周期伤害仍是提前移除时的真实结果，无需为了这次录入引入“无结果效果”例外。

## 聚合契约的最小形状

每个技能组成仍以 `gameId + skillKey + 自身稳定标识` 定位和整项保存，后端负责子项校验与引用，前端不操作内部表。保留现有聚合接口边界即可；先把表结构实现从契约中移走。

| 聚合根 | 普通列 | 结构化字段 |
| --- | --- | --- |
| 技能参数 | 所属键、参数键、名称、数值类型、取值方式、排序、说明、时间 | 等级值整图；固定值仍为数值列 |
| 技能公式 | 所属键、公式键、名称、排序、说明、时间 | 表达式树，保留既有深度与节点数限制 |
| 技能效果 | 所属键、效果键、名称、排序、说明、时间 | 结果数组、可选生命周期；每个结果保留结果键、类型、目标、数值、明细和生命周期行为 |
| 内部状态 | 所属键、状态键、名称、类型、保存范围、排序、说明、时间 | 与类型对应的唯一明细；模式选项保留稳定键 |
| 技能过程 | 所属键、过程键、名称、启动方式、排序、说明、时间 | 步骤数组、普通冷却、效果挂接、内部状态操作；时点引用步骤键 |
| 触发规则 | 所属键、规则键、名称、排序、说明、时间 | 事件来源、条件组、有序动作、动态输入及限制；动作保存顺序与页面一致 |

上述数值直接取值统一为三种互斥形状：固定值 `{kind: FIXED, value}`、当前技能参数 `{kind: PARAMETER, parameterKey}`、具名公式 `{kind: FORMULA, formulaKey}`。数值类型、整数要求、毫秒单位、范围和计算时必填输入仍由使用位置校验。34 处数值位置已完成前后端切换及真实数据迁移，接口只保留新形状；后端提交 `f7600e6`，前端提交 `a782b5b`。

引用明细至少包含来源游戏、技能、对象类型、对象键、字段路径，以及目标类型、技能键、对象键和可选子项键。以目标组合键建反查索引。一个对象整项保存时重新提取其全部引用；结果、步骤和模式选项的删除检查依据保存前后的键集合。服务事务外不得通过直接 SQL 修改结构化内容。

同游戏配置写入采用一致的事务锁顺序，涵盖新增引用和被引用对象删除。该保护已随存储精简在本地服务落地。只对实际按字段查询的场景增加索引，不为每个结构化字段建立通用索引。

## 实施次序与停止扩表

1. 固定本轮实录数据、资料清单及接口快照，先修复现有录入错误。
2. 在上述聚合契约内补直接取值、生命周期条件、原始施放消耗和命中目标类别；将 W 的临时计数投影转换为直接生命周期条件。明确护盾是否阻挡的事件字段，保留未查明游戏事实。
3. 按公式、效果、内部状态、过程、触发规则的依赖顺序改存储；复用校验算法，替换依赖旧表的装配和反向引用查询。不为第二步再增加一批类型明细表。
4. 使用本轮角色做一次迁移前后聚合对照及关键引用检查，实录流程回走一遍，再移除旧内部表和旧 SQL。

现有真实数据应从修改前快照和明确的数据库备份恢复，而非长期保留兼容层。物理删表前核对目标仍为指定开发库，保护已有角色、图片及其他任务工作。存储容量和线上性能按实际问题处理，本轮不以假设的线上容量不足驱动额外基础设施。
