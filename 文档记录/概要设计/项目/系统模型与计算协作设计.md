# 系统模型与计算协作设计

本文统一说明计算取舍、管理模型和执行协作，按“计算什么 → 配置怎样表达 → 数据怎样流转 → 引擎怎样执行”阅读。已确认的产品取舍、当前实现与剩余方向分别说明；字段、枚举、校验和接口的完整定义继续由建表脚本、共享规范及实际源码维护。

## 计算范围与简化取舍

当前面向1对1的有限数值分析，不承诺完整游戏还原。具体对象必须符合实际适配与引擎准入，不能因取舍已确认就宣称全部实现；尚未接入的来源、空间、多单位或控制效果逐对象列出限制。对象范围及排除只查[原账本](../../../数据参考/全量录入-2026-09/阶段进度.json)，本文不维护英雄或逐槽组合库存。

| 项目 | 保留的口径 |
| --- | --- |
| 施法费用 | 本期产品计算不收取法力、能量或生命施法费用，不模拟费用不足及付款退款；怒气、热量等影响输出的机制资源按其明确规则消费。底层仍有通用资源能力，不能把普通资源键当成实际生命扣费 |
| 指定二次释放与蓄力 | 所选开关合并为一次直接释放；有明确上限的蓄力可取满。窗口内受击、命中及层数不自动满足，影响金额的条件由场景或真实运行事实提供 |
| 有限持续输出 | 单技能可按完整有限段数分析；固定观察区间只累计区间内实际结算，后续段不提前计入。跨段生命、护盾或倍率变化时逐笔计算 |
| 冷却与普通攻击 | 保留事件时间、普通／内部冷却、攻击节拍及已接入的冷却修改。普攻按其真实节拍或特殊机制执行，不把全部动作堆到同一时刻；计时重置按已接入机制判断，不再沿用旧稿一律暂缓的限制 |
| 弹药与装填 | 保留消耗、恢复、空弹限制、装填及后续可用资格，不能仅给初始满弹而跳过之后的演进 |
| 位移与弹道 | 在所选近似下直接到达目标，不模拟逐帧路径和飞行；公式需要的距离、起终点及命中资格仍须明确提供，不能填零代替缺失 |
| 读条与中断 | 采用明确施放延迟，先不细分动画帧；保留已定义的中断和死亡终止，已结算结果不回滚。具体场景是否接入对应控制仍独立判断 |
| 到期与刷新 | 保留效果期限、自然到期、重施刷新及对后续事件的影响，不因简化操作窗口删除已验证的生命周期 |
| 层数与历史 | 有限上限按来源核定；永久成长和战前状态由场景输入。本次模拟内的累计按真实事件变化，滚动历史需保留过期时点，不能用当前缺血量代替近期受伤 |

面具等按战斗时间增长的增伤不默认满层。每笔伤害读取其时点的真实增伤；起始时长与层数选定一个事实来源，另一个按核定规则取得。省去蓄力或飞行等待，不补造额外战斗时间、命中或层数。

## 管理模型与技能组成

### 数据归属

| 数据 | 所有者与边界 |
| --- | --- |
| 游戏、属性、等级、角色与装备 | 维护稳定标识、来源及直接数值，角色与装备属性和技能行为分开 |
| 技能及六类组成 | 主体、参数／公式、效果、内部状态、过程、条件触发由同一技能组织；统一工作区提供完整读取和受摘要保护的组合保存 |
| 状态与修正区域 | 目录声明身份、合并及计算方式；作者选择真实目录，概念与算例见[乘区词条](../../领域知识库/乘区与修正区域.md) |
| 构筑 | 系统、分组、可选项与技能授予；选择和投入合法后产生真实来源实例，取代旧符文专用三表 |
| 关系及图片 | 角色、装备、构筑挂载技能；图片独立存储并关联业务对象，列表与内容读取分开 |
| 引用索引 | 后端按最终配置提取并定向维护，供删除保护及反查；没有独立人工编辑接口 |

[建表脚本](../../../db/game_manage/schema.sql)当前定义公共模式（public）中的30张逻辑表，包含图片分区父表，不含图片子分区；这是静态结构，不是实库核验结论。五类技能根对象的结构化内容保存为数据库中的二进制JSON字段（JSONB），明细不再拆成旧节点表。构筑四表、吸血规则及计算规则均按现行脚本维护。

### 技能六类组成

| 模块 | 职责 |
| --- | --- |
| 技能主体 | 身份、分类、等级及启停 |
| 参数与公式 | 有来源的数值、等级曲线及明确输入到结果的计算 |
| 效果 | 一组有序结果及必要生命周期，不决定任意触发时机 |
| 内部状态 | 计数、弹药、模式、标记及内部冷却等技能自有数据 |
| 过程 | 施放步骤、明确时点、行动占用及关联冷却 |
| 条件与触发 | 真实事件、条件、动作、供值及同次使用等限制 |

技能六类组成与下文Wasm的六个功能执行包是不同划分：前者组织作者配置，后者执行战斗流程。统一编辑和组合保存已进入代码，已完成的逐表与逐页面施工设计从Git历史追溯。

### 保存与读取责任

统一技能配置以整技能摘要防止旧页面覆盖，在同一游戏写锁及事务内检查最终组合。未提交对象保留，组合失败全部回滚；前端草稿、基线和离开保护由统一工作区负责。具体接口及源码入口见[后端说明](../../../server/data_manage/README.md)和[前端说明](../../../web/README.md)。

参数可以是固定值、角色等级值、技能等级值或运行输入；定义不混入本场状态。已有值可直接引用，不强迫经过中转公式；需要计算时使用[共同公式](../../../contracts/formula/README.md)。战斗状态、技能内部状态、效果生命周期及运行供值各自保留归属，不能用一个通用字段抹平。

共同公式与[固定枚举](../../../contracts/system-enums/README.md)分别拥有结构及固定选项。技能、属性、伤害类型、对象关系及数值仍由作者配置；数值内核不按英雄、装备或目录中文名分支。

资料依据、保护保存、独立回读及完整对象准入见[录入边界](../../项目说明/计算范围与录入边界.md)。数据库脚本、管理保存、编译成功及运行通过分别提供证据，不相互代替。

## 系统数据流与执行协作

管理页面编辑配置，后端校验、保存并维护引用；场景接口在一致性只读事务内读取所选对象及必要依赖；前端选择场景、核对支持范围并适配为计算请求；浏览器工作线程负责协议与内存运输；Wasm独立校验、编译规则、管理会话并按确定次序运行；页面消费真实结果。后端不执行战斗，Wasm不读取数据库或管理接口。

正式调用为 `engine_compile → engine_run → engine_release_session`，依次表示编译、运行和释放会话。完整能力声明从[引擎说明](../../../wasm/tinygo_engine_v2/README.md)、[架构说明](../../../wasm/tinygo_engine_v2/ARCHITECTURE.md)及[执行功能入口](../../../wasm/tinygo_engine_v2/internal/runtime/execution/README.md)进入；执行层当前共享语义由[功能执行与组合设计](../../详细设计/项目/执行协调层功能执行与组合重构技术方案.md)维护，接口与协作约束只在[详细说明](../../详细设计/项目/Wasm子系统接口设计草案.md)定义。

### Wasm当前职责

完整职责、协作契约与阶段交接见[控制反转规划](Wasm子系统控制反转规划.md)，六步职责封装及最终产物验收已完成。下表代码路径相对 `wasm/tinygo_engine_v2/`，只提供源码分工导航；完整职责可以跨执行包、状态包和计算组件，不按表格行或包数量创建同级服务。

| 职责 | 当前落点 | 拥有的事实及对外结果 |
| --- | --- | --- |
| 宿主协议与会话 | `cmd/engine_wasm/`、`internal/runtime/`；入口授权由 `internal/authorization/` 提供 | 会话登记、编译身份及计划；按构建策略核验编译／运行票据，运行校验同账号，每场另建状态 |
| 规则编译 | `internal/compile/`、`internal/plan/` | 校验通用定义，形成只读执行计划、公式及索引，不执行战斗 |
| 执行协调 | `internal/runtime/execution/` | 组合行动、效果、数值、命中、监听和续接；根层提供真实帧、读取时点、跨功能次序、预检及统一发布 |
| 时间调度 | `internal/scheduler/` | 唯一战斗逻辑时钟、稳定事件队列、接纳计数与停止账 |
| 角色数值状态 | `internal/runtime/actor/` | 当前属性、机制资源及所属暂存变更；生命与资源的口径见[领域定义](../../领域知识库/属性、生命与机制资源.md) |
| 行动状态 | `internal/runtime/action/` | 真实使用、过程、占用、冷却、弹药及等待；提供局部转换、视图和快照 |
| 效果状态 | `internal/runtime/effect/` | 效果实例、状态袋、护盾集合、期限、世代与计时载荷；登记载荷不等于已排程 |
| 战斗公式 | `internal/formula/` | 分阶段构建、冻结及交付只读求值与元信息；消费已准备事实和纯表达式，返回数值或问题，不回调执行帧或发布状态 |
| 战斗操作与数值结算 | `internal/runtime/execution/operation/`、`internal/pipeline/`，借用 `actor/` 与 `evaluation/` | 完整有序结算、属性初值、单遍／两遍重算和缓存流程归数值职责；角色数值暂存与跨职责统一发布分别交接 |
| 结果观察 | `internal/runtime/report/` | 可靠累计、有界明细和采样；接收实际事实，不决定行动资格 |

共享请求与结果在 `internal/model/`，只读计划在 `internal/plan/`，跨所有者的有限身份和值在 `internal/runtime/contract/`。完整字段及数学定义继续归源码、共同公式与固定枚举，本文只保留职责摘要。

### 执行状态与所有权

当前已形成六个功能执行包、三个支撑包和四个基础战斗状态包，执行根层组合真实帧及跨功能次序。

六个功能执行包分别是：`actionflow`（行动与过程）、`lifecycle`（效果与周期）、`operation`（数值操作）、`hit`（命中与强化）、`listener`（监听冻结与派发）、`continuation`（复制与续接）。三个支撑包为 `admission`（准入）、`evaluation`（求值）和 `usage`（共同额度账）。名称均为源码包名，完整职责与合法依赖由执行层设计维护。

| 状态层次 | 谁拥有 | 根层怎样使用 |
| --- | --- | --- |
| 会话规则 | 会话及只读计划 | 每场借用计划；本场公式表允许追加，不能改写共享计划 |
| 基础战斗状态 | `actor/action/effect/report` 四包 | 借用有限视图，组合所属变更和末态 |
| 流程私有事实 | 六个功能执行包 | 通过有限同步能力交接原帧、阶段和事实；包括发动前捕获、逐伤输出、命中历史、监听节流及复制因果 |
| 支撑事实 | `evaluation` 的本场缓存、`usage.Ledger` 的每场唯一额度账 | 在原时点求值、预留、提交或失败释放；不另建同名账本 |
| 全场驱动 | `scheduler.Loop`（调度循环） | 由根运行入口创建唯一实例，执行根层借用；执行子包不取得调度器 |

根执行层保留装配、真实帧、原时点读取、预算、跨功能固定次序和统一发布。六个功能执行包不互相导入；通过根层提供的有限同步能力协作，也不意味着它们持有完整执行器或根帧。四个基础状态包并非所有可变事实的总容器，流程私有事实仍由实际执行者拥有。

稳定基础能力在 `internal/base/` 的六个独立包：`abi`（帧运输）、`attribute`（属性分页）、`expression`（纯表达式）、`inputbinding`（输入绑定）、`numeric`（数值边界及分组聚合）、`typeset`（类型匹配）。普通业务在外层组合；护盾底层值与资源槽计算归数值管道。基础层不保存战斗执行状态。

### 协作约束

| 约束 | 当前含义与依据 |
| --- | --- |
| 会话与授权 | 编译成功绑定账号，每次运行按构建策略重新验票；释放不验票，重复释放返回 `session_not_found`。实际检查及写出失败边界见[会话实现](../../../wasm/tinygo_engine_v2/internal/runtime/session.go) |
| 战斗时间准入 | 创建循环前检查非负起点、非负时长、终点加和不溢出及通用驱动不早于起点；允许零时长和通用非零起点，各场景的新鲜初态约束另行校验。见[运行校验](../../../wasm/tinygo_engine_v2/internal/runtime/validation.go) |
| 输出边界 | 开启采样时，点数和预算调整后的有效间隔还需可用32位有符号整数表达；关闭采样不施加这项输出限制。见[采样实现](../../../wasm/tinygo_engine_v2/internal/runtime/report/sampling.go) |
| 确定性 | 唯一时钟指战斗逻辑时间；授权有效期核验另读系统时间。同刻堆序、过程排序与执行侧选择共同决定战斗次序，只测堆排序不足以证明组合行为 |
| 借用与读取 | 纯计算、活借用、读取准备、历史冻结、暂存和发布分别解释。读取准备可能处理缓存或惰性到期，不能任意提前；具体期限以所属能力声明为准 |
| 发布与失败 | 数值管道计算，所属状态暂存，根层按真实帧边界预检并协调发布；局部发布后仍可能失败，已发生事实不隐含全链回滚 |
| 结果解释 | 安全预算、正常停止、执行完整性、明细截断和采样分别负责。`ok=true` 不能代替完整性判断，截断记录不能用来重建全场累计 |

游戏公式、伤害类型和属性引用从明确目录及定义读取，不按中文名称猜测。新增数值变化先按[功能设计与能力组合指南](../../项目说明/开发指南/功能设计与能力组合指南.md)判断复用、组合或修正契约，再定位编译与执行拥有者；现有目录不限制新责任的建立。

## 当前实现与剩余方向

当前引擎已完成[控制反转规划](Wasm子系统控制反转规划.md)的六步职责封装。行动与效果分别跨执行和状态组件完成所属规则，数值职责拥有完整结算及重算缓存流程，命中、监听和派生各自隐藏内部步骤；根层保留原事实捕获、真实帧、跨职责顺序和统一提交。调度层通过有限排程能力控制同一队列，前置业务决定由执行侧返回；同刻候选取还和帧内容量计算已分别集中维护。事件后内部失败与普攻死亡继续立即复核。

| 方向 | 当前证据 | 后续工作的最小边界 |
| --- | --- | --- |
| 有限排程已收敛 | 可写堆外借已删除，三类唤醒查询／改期、同刻取还及队列事实均由有限能力提供 | 维护容量预检、原序恢复与真实业务身份，不另建队列或容量账 |
| 循环前置决策已收敛 | 执行侧返回继续、推进终点、立即核定、按原因停止四种决定 | 保留原分支顺序与预算原因；`LoopState` 缩为事件后立即复核的事实 |
| 读取、快照及发布 | 计划、活视图及可写句柄仍有明确使用期限，部分读取含准备副作用 | 在实际声明处维护契约，针对真实越界修正调用方；全面深复制和全局回滚不作为默认方案 |
| 执行权限及因果 | 使用身份、额度、命中、监听和复制事实已分别归实际拥有者；驱动读取资格仍按各用途准入 | 根据新机制的真实变化点收敛共同规则，不再以“因果全部尚未拆分”描述现状 |
| 浏览器数据复用 | 计算仍会重取完整快照，公式预检会编译／释放临时会话 | 快照缓存、复用与失效更新暂缓到版本管理之后 |
| 性能与分页 | 当前属性每页8项，结构拆分本身不证明复制或耗时下降 | 只有实际测量支持时再优化；同时核对正式Wasm、完整结果和成本 |

上述方向是持续维护、暂缓或条件性优化，不是已完成六步之后另欠的一批子系统开发，也不阻止本版任务收口。有限交接的输入、输出、失败及验收只在详细说明维护，不为每项职责增加接口壳、服务注册器或面向未来的扩展层。

[子系统协作图](Wasm子系统协作图.html)提供“职责与协作”和“具体改动进度”两个阅读视角，展示本文执行协作与剩余方向的摘要。任务状态仍以[任务规则](../../../db/task_doc_governance/task_rules.json)为准，本文不另维护任务进度。

后续运行时改造按[开发与独立评审流程](../../项目说明/开发与独立评审流程说明.md)执行。数值、来源、时刻、停止原因及末态一起验证；网络准备、编译、计算、编码运输和展示分别计量，原生Go耗时或宿主往返不能代替正式Wasm纯计算收益。历史测量与施工过程从Git追溯。
