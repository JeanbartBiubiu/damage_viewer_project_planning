# Wasm子系统控制反转规划

## 1. 本次结论与设计边界

本版按完整职责重划边界：行动规则与行动状态共同构成“行动与过程”；效果规则、实例与状态共同构成“效果生命周期”；有序操作、数值算法、角色数值及派生缓存共同支撑“战斗操作与数值结算”。命中裁决、事件反应、派生伤害各自保留独立规则。战斗编排与提交负责真实帧、原读取时点、跨职责固定次序和发布，确定性调度独占机械循环与唯一队列。公式提供分阶段的编制、纯求值与只读元信息，报告只接收已提交事实。

原方案将29个生产包逐一列为同级子系统，混淆了业务职责、流程组件、状态存储、数据产物和基础工具。包导入无环只能证明源码组织约束，不能证明调用者不需要协调他人的内部步骤。本版先说明职责、协作及变化集中性，再在第8节映射包；覆盖所有包仅是清单检查。

本次共识别12项逻辑职责，数量来自各自对外承诺和独立变化原因，不是实施目标或验收门槛。跨包职责不要求合并目录、合并状态对象、统一大外观或增加动态接口；同一个包也可能承载不同职责的实现片段。共同额度账是明确的一致性组件；协议、计划和基础工具是数据或技术支撑，都不与业务职责混作同级服务。

**公式完整能力、行动与过程、效果生命周期的职责封装已实施；其他目标边界仍按第7节区分现状与待实施部分。** 本文件及[展示页面](Wasm子系统控制反转依赖图.html)同步说明边界。现行行为以[接口约束](../../详细设计/项目/Wasm子系统接口设计草案.md)、[执行协作设计](../../详细设计/项目/执行协调层功能执行与组合重构技术方案.md)及源码为准。本文是目标设计唯一来源，HTML只展示摘要；既有总体任务仍为进行中，不新增任务。

调查日期2026-11-11，源码基线 a655d4ab047b8237d1eb52d6496a3231c86a7d39。本轮在已完成公式与行动能力上落实效果生命周期，不据此宣称数值或总体迁移完成。保留应用二进制接口（ABI）、请求与结果结构（DTO）、数值、读取时点、同刻排序、同帧与子帧、唯一队列、唯一额度账及部分发布后的失败语义。任何必须改变这些语义的建议都须另列决策，不能混入行为保持重构。

## 3. 目标职责、状态与不变量

各节的“对外能力”是语义契约，不要求逐条新增Go接口。已有具体类型、函数及不可变值能表达时继续使用。未施放、失效计时、条件不满足等正常结果与执行失败分别保留；没有统一改造现有错误码或结果字段。

<a id="d-session"></a>
### 会话与运行入口

| 边界项 | 目标契约 |
| --- | --- |
| 职责 | 将合法外部编译、运行和释放请求转为受身份保护的会话与独立运行，完成字节交付。 |
| 输入与结果 | 现行请求帧、授权及身份 → 编译/运行/释放结果或结构化问题；业务导出不变。 |
| 拒绝与失败 | 授权、账号、摘要和输入按现行契约拒绝；编译写出失败撤销本次登记，运行失败保留会话，释放后写出失败不恢复登记。 |
| 所有权与不变量 | 固化授权策略、会话登记、账号绑定及出箱；不保存跨场可变战斗状态，不用战斗时间验票。 |
| 对外能力 | 编译、运行、释放及有限帧运输；内部调用者不取得账号策略修改或任意状态入口。 |
| 隐藏细节 | 验签、会话查找、输入/出箱内存期限和失败写出规则。 |
| 所需能力 | 规则编译、单场运行装配和最终结果；授权与帧运输为内部技术组件。 |
| 作用域 | 每个Wasm实例持会话表；计划每会话；每次运行另建状态；出箱视图只在既有借用期内有效。 |
| 变化集中性 | 修改一项入口拒绝或登记规则主要在入口内部；不牵动逐事件业务。 |
| 收益与代价 | 宿主只理解现行协议；代价是入口装配与战斗编排虽同属runtime路径，必须维持不同作用域。 |

<a id="d-compile"></a>
### 规则编译

| 边界项 | 目标契约 |
| --- | --- |
| 职责 | 将作者规则、来源与目录校验并编译成可确定执行的只读计划。 |
| 输入与结果 | CompileRequest → 计划、编号与元信息，或保持原顺序的全部编译问题。 |
| 拒绝与失败 | 非法引用、作用域、类型、规模及循环按原编译契约拒绝；失败编号不可供后续消费。 |
| 所有权与不变量 | 编译规则、引用分析和编译预算；不拥有角色、队列或运行缓存。 |
| 对外能力 | 编译规则；按原准备阶段编译本场驱动条件，不改宿主协议。 |
| 隐藏细节 | 目录解析、索引、编译遍历和无效结果清理。 |
| 所需能力 | 公式编制与依赖元信息、类型和属性目录；计划是产物，不是下属服务。 |
| 作用域 | 每个编译请求局部构建；成功产物随会话借用；本场补充仅属该场准备。 |
| 变化集中性 | 同类作者约束与编译规则在本职责及其所属叶编译器修改，运行层只消费计划。 |
| 收益与代价 | 隔离作者输入与运行形态；代价是公式语言由公式职责定义，使用点授权由编译职责维护，两者不能互相替代。 |

<a id="d-orchestration"></a>
### 战斗编排与提交

| 边界项 | 目标契约 |
| --- | --- |
| 职责 | 在既定逻辑时点调用完整业务职责，组合真实帧、跨职责次序、预检、分阶段发布和同步尾部。 |
| 输入与结果 | 已就绪计划、本场请求、唯一循环及所属能力 → 循环业务决定、已发生事实、最终交出或错误。 |
| 拒绝与失败 | 失效事件由所属职责判定；预算或阶段失败沿原边界停止，保留已发布前缀，不承诺全链回滚。 |
| 所有权与不变量 | 真实帧身份、当前暂存/帧入口/事件冻结的选择、跨帧因果、跨职责预算与发布进度；不复制业务状态账。 |
| 对外能力 | 循环业务驱动、真实阶段执行、统一预检/分阶段提交、末态交出；给各消费者分别提供小能力。 |
| 隐藏细节 | 帧开立及恢复、合并队列需求、发布阶段先后、事件与命中尾部；不向子系统传根帧或完整执行器。 |
| 所需能力 | 行动、效果、结算、命中、事件反应、派生伤害、报告；有限排程与同一额度账。 |
| 作用域 | 每场装配，真实帧与每次同步借用各自独立；嵌套不能覆盖全局当前帧。 |
| 变化集中性 | 新增一种普通冷却、效果刷新或数值修正不应要求根层重写所属规则；新增跨功能顺序才改变编排。 |
| 收益与代价 | 保留必要中心协调并减少业务知识集中；代价是不能一次搬走commit或把全部业务合成一个完成布尔值。 |

<a id="d-scheduling"></a>
### 确定性调度

| 边界项 | 目标契约 |
| --- | --- |
| 职责 | 按稳定顺序驱动唯一战斗时钟、队列、接纳计数与停止账。 |
| 输入与结果 | 已核验时间范围、停止策略、事件及LoopDriver → 原序处理、观察和停止结果。 |
| 拒绝与失败 | 队列容量及无效候选恢复明确失败；业务错误立即按原循环规则复核，不吞错继续推进。 |
| 所有权与不变量 | 唯一时钟、堆序、序号和循环计数；不拥有冷却资格、命中裁决或效果世代规则。 |
| 对外能力 | Run(driver)及有限入队、改期、查询、同刻取还；不借出可写堆。 |
| 隐藏细节 | 堆结构、稳定序号和机械循环；事件业务资格交给所属职责。 |
| 所需能力 | 由自身声明的有限业务驱动，战斗编排提供实现；运行时回调不构成包反向导入。 |
| 作用域 | 每场唯一实例；先建循环，后在Run传入已完成装配的驱动。 |
| 变化集中性 | 同类机械排程变化留调度内部；同刻特殊业务选择仍由编排按原规则决定。 |
| 收益与代价 | 已有控制反转可继续复用；代价是必须区分业务重选、队列动作和停止规则，不能靠移包重排同刻事件。 |

<a id="d-action"></a>
### 行动与过程

| 边界项 | 目标契约 |
| --- | --- |
| 职责 | 从行动意图到真实接纳、付款、步骤推进、等待及结束，统一维护普攻、技能和过程资格。 |
| 输入与结果 | 意图或完整身份计时、当前时点、实际来源/双方 → 已接纳、正常未施放及原因、等待、失效回调跳过、阶段完成或错误。 |
| 拒绝与失败 | 冷却/占用/条件未满足保持正常结果；付款或阶段失败保留原成功前缀；明确返回真实接纳结果，不靠报告计数差推断。 |
| 所有权与不变量 | 唯一使用身份、过程、占用、冷却、弹药、等待及发动捕获；过程全部费用先按同一付款前视图读取，普通费用扣付后才求冷却；阶段提交后复查活资格。 |
| 对外能力 | 尝试行动、推进真实过程、处理到期/中断、准备和发布所属阶段、输出行动事实与等待请求。 |
| 隐藏细节 | EnterStep/Finish、费用和冷却政策、内部账更新、失效版本与后继资格；调用方不逐项拼接这些步骤。 |
| 所需能力 | 结算执行已核定付款及操作；效果提供来源事实；编排提供原真实帧和提交，调度只通过编排交接。 |
| 作用域 | 每场行动账，执行对象可轻量借用；每次步骤使用原真实帧，真实子能力按原有独立能力帧边界执行。 |
| 变化集中性 | 新增同类行动或冷却规则主要在行动职责内部及其编译适配；无需外层解释过程内部状态。 |
| 收益与代价 | actionflow与action规则和状态共同封装；代价是分离业务决定与跨职责提交，不能让行动自行提交整条链。 |

行动结果（`ActionResult`）与原错误并列：`Accepted=false`是本次未接纳，附已有正常拒绝原因或原失败；`Accepted=true`是本次原帧已发布行动事实，仍可能附同步尾部错误。它不等于整链成功，未接纳也不承诺此前没有部分发布。普通帧、原生过程启动、重施、蓄力及取消/中断都沿同次局部回执交接；计时推进不凭空新增接纳，原生命中实际执行但不重复计施放。调用方不查全局计数、最后结果或事后过程数。见[结果定义](../../../wasm/tinygo_engine_v2/internal/runtime/execution/actionflow/action_result.go)及[真实帧结果用例](../../../wasm/tinygo_engine_v2/internal/runtime/execution/action_result_test.go)。

行动接收普通帧的有限金额读取、资源暂存与冷却暂存能力，内部决定付款与冷却顺序；周期和非分阶段锚定路径复用这项政策，不改成普通施放。过程命令只在行动内生成和消费；根仅开立原局部帧并提供提交、结束观察和命中尾部能力。重施接纳与负载仍使用两帧，开始监听后才创建负载暂存。过程冷却先走原数值操作，再保存同一冷却账的普通总时长来源，最后按需准备首次普攻等待。

<a id="d-effect"></a>
### 效果生命周期

| 边界项 | 目标契约 |
| --- | --- |
| 职责 | 应用、刷新、移除、到期及周期推进效果，为指定原时点准备有效效果事实。 |
| 输入与结果 | 效果意图、真实身份、时刻及所属帧 → 既定效果变更、已准备事实、有界计时请求、无变化或错误。 |
| 拒绝与失败 | 旧期限/世代正常跳过；非法状态、预演或阶段失败明确返回，已完成外部清理与发布不自动撤销。 |
| 所有权与不变量 | 实例、状态袋、修正挂载、护盾集合及每盾剩余值、期限、世代与周期载荷；旧到期不能删除新实例，预演不发布或分配真实身份。 |
| 对外能力 | 应用/刷新/移除、按时点准备读取、处理周期、预检并发布所属阶段、交出状态与计时事实。 |
| 隐藏细节 | 查找替换实例、字段元数据、惰性到期、挂卸修正、关联盾及实例列表；PrepareRead明确为受控准备。 |
| 所需能力 | 公式求时长/数值；结算暂存属性及盾血变化；行动清理冷却/弹药；事件反应绑定/解绑；编排保留这些交接的既有先后。 |
| 作用域 | 每角色每场实例；投影/变更属真实帧；写句柄不跨发布或冻结；准备不提前到事件开头。 |
| 变化集中性 | 同类效果刷新和期限规则集中在生命周期内部；不要求根调用方查ExpiredRef或补齐容器步骤。 |
| 收益与代价 | lifecycle与effect逻辑合责，状态仍独立存储；代价是部分操作借用角色变更及外部清理，必须维持精确阶段契约。 |

已落地的实例入口为[完整实例执行](../../../wasm/tinygo_engine_v2/internal/runtime/execution/lifecycle/live.go)：应用内部处理过期卸载、重读及复用；刷新保留期限先请求再发布；标准移除内部完成反向关联、真实资格、外部清理及所属删除。新实例先发布、挂修正、重算、安排期限和周期、记录，最后绑定监听；最后失败不撤回前缀。数值重算和排程原有的延后错误通道保留，效果不在每个回调后擅自提前停止。

到期载荷由[到期执行](../../../wasm/tinygo_engine_v2/internal/runtime/execution/lifecycle/expiry_execution.go)核对原期限和清理方式；效果命令的状态规则私有，根只开立原真实帧、消费预算并统一提交。普通清扫与关联盾逐个清扫保留各自语义，关联盾先清实例，再取得当前盾视图；精确到期的数值失活仍先于物理清理，锚定末拍与状态袋准备不提前。关联盾创建和期限续时也由效果完整控制原校验、读准备及暂存顺序。

所属头运输值（`LiveEffects`）只带效果实例、状态袋和同一行动冷却账的借用，不带角色数值，不复制第二份权威状态。写回仅替换这些已决定字段；跨数值或效果准备后重新取得真实角色。批次发布不向根交出种类开关；预检内部选择原底表并完整预演，根只汇总队列需求。盾期限预检查当前暂存、发布重新读实际状态，保留重复请求和每项原请求时刻。

构建器（`Builder`）只在编译和本场驱动准备时持有；冻结集合（`Library`）分别交出纯求值器（`Evaluator`）和只读元信息（`Metadata`）。运行求值器只有按编号求值、同步借用上下文求值及显式绑定数值求值三项能力。程序、索引及输入绑定不借出可写存储；登记复制输入，冻结后旧构建句柄的继续写入与重绑均不能改变已交付集合。诊断、准入与缓存使用单独元信息，不为查路径或依赖取得构建器。

运行上下文只持属性、资源、数值、状态、类别和输出的有限只读视图。伤前状态、关联盾存在及冻结吸收额由原准备点交付值与延后错误，公式不持任意读回调、根帧或状态写句柄。有效0与缺失分别保留；输入只在同步求值期借用，不跨帧保存。

## 4. 共同组件及根层应保留的内容

**共同额度账不升格为业务子系统，也不隐去。** 它私有持有完整身份的唯一预留/已提交记录与真实凭据。运行装配只建一份，命中、事件反应和派生伤害在原位置借用；合法使用身份由行动提供，具体成功边界由业务消费者决定，账本执行预留/提交/释放。嵌套不得重建身份、复制账或重置预算；失败只释放原未提交凭据。见[额度实现](../../../wasm/tinygo_engine_v2/internal/runtime/execution/usage/ledger.go)与[嵌套及已提交前缀测试](../../../wasm/tinygo_engine_v2/internal/runtime/execution/usage/ledger_test.go)。

准入是准备阶段的规则组件：现有admission包的检查由所属职责提供完整输入和结果，编排只维持原检查顺序；不为它创建总服务，也不把检查全部提前。模型、计划、内部交接值和基础工具见第8节。

根层保留的必要知识包括：真实帧开立与嵌套恢复；普通暂存、帧入口、事件入口/冻结和复制防御的时点选择；原跨职责固定顺序；唯一队列的容量汇总与发布；各职责原发布阶段、死亡冻结、事实提交和观察。根层不得独立解释步骤进入/结束、实例替换/刷新、普通费用与冷却政策、候选裁决或监听触发结果。

目标迁移不是把所有发布压缩为一次最终交换。当前commit先发布部分数值/实例，再执行部分生命周期与后继步骤，后续失败可能保留前缀。目标由各职责提供“预检既定变化、发布指定原阶段、交出原事实”的有限操作，编排保持相同调用位置。不能把发布函数移进业务职责后提前调用，也不能声称整帧变成跨系统事务。

## 6. 用真实调用链检验目标边界

### 6.1 行动触发数值结算

当前链为：行动PrepareCast/ExecuteAbilityFrame → 根executePreparedAbility → ExecuteAbilityOperations → Frame.executeOperations → operation.Execute → 伤害/治疗/资源暂存 → Frame.commit → 原事件和命中尾部。见[能力施放](../../../wasm/tinygo_engine_v2/internal/runtime/execution/actionflow/ability_cast.go)、[根能力执行](../../../wasm/tinygo_engine_v2/internal/runtime/execution/actions.go)、[有序操作](../../../wasm/tinygo_engine_v2/internal/runtime/execution/operation/routing.go)。

协作05/12/07/14已按行动边界交接：行动准备意图，StageAbilityTerms决定普通付款及付款后冷却，ExecuteAbilityFrame执行原身份与负载；编排在相同位置提供真实帧，结算暂存数值，根层原位提交并交出本次接纳回执、继续固定尾部。原费用辅助已删除；普通施放、周期与非分阶段锚定帧使用同一行动政策，保留各自编号、统计与开始事件规则。过程的完整时点由ExecuteMoment消费，原准备和ApplyMoment后才提交；已提交终结先观察结束，即使提交尾部报错，成功后才解析后继命中。

本次不把根executePreparedAbility整段搬给行动：其中commit → pending events → ability started → basic attack start → basic attack hit → death是跨职责顺序。目标是消除调用方对行动内部政策的重复理解，保留该顺序。付款前整组检查、逐阶段复查和部分提交分别由[费用用例](../../../wasm/tinygo_engine_v2/internal/runtime/execution/actionflow/process_costs_test.go)、[过程用例](../../../wasm/tinygo_engine_v2/internal/runtime/execution/actionflow/process_test.go)约束；[同帧前写后读用例](../../../wasm/tinygo_engine_v2/tests/runtime/generic_formula_phase3b_test.go)约束暂存可见性。

### 6.2 效果到期后的读取

当前链为：Loop交付原事件 → 根同刻选择/到期处理 → 供值适配器providerFormulaContextForTarget → providerStateBagForRead → effect.PrepareRead → 属性/公式计算。PrepareRead可能绑定元数据、补默认、处理到期和投影，所以这条完整路径不能宣称纯查询。

目标在**相同实际需求点**显式交接“效果准备 → 已准备事实 → 纯数学求值”，原同刻规则、分支惰性及前后操作可见性不变。禁止按ReadDependencies的条件两支全集统一预热，禁止把精确到期一律提前到事件开头。已有[锚定末拍用例](../../../wasm/tinygo_engine_v2/tests/runtime/generic_anchored_tick_boundary_test.go)、[同刻盾到期用例](../../../wasm/tinygo_engine_v2/tests/runtime/generic_timed_shield_test.go)及[惰性分支用例](../../../wasm/tinygo_engine_v2/tests/runtime/generic_formula_phase3b_test.go)分别约束这些时点。

本轮核对后确认：帧上下文、实际修正成员及缓存探测的效果准备原本就在对应数学调用之前，可以保留原点。未引入暂停/恢复求值、依赖统一预热或反复重算补值。原公式内部的伤前状态、关联盾存在和冻结吸收额改成编译后有限请求：在对应上下文准备完成后取得每项值或错误，只有实际读指令访问该项时才返回错误。准备伤前状态时仍逐次保留“首条匹配即返回”的顺序；护盾耗尽后的读取仍用原冻结回执，并核对实际父挂载，不能改查当前活盾。普通帧只准备所属定义获准的关联盾请求，监听专属事实仅在实际条件位置准备；命中参与切换到其他真实供值者时，请求随已绑定定义交接，返回后恢复原拥有者。

因此“全部公式纯化”只承诺数学求值器没有状态准备或发布能力，完整战斗结算仍有必要的受控准备。原修正遍历、缓存命中后的到期、普通帧与供值覆盖的目标状态准备范围均保持；公式阶段不能证明效果生命周期全部封装完成。

### 6.3 监听触发嵌套执行

当前链为：Frame.dispatchPendingEvents → Engine.dispatchListeners → listener.Dispatch → DispatchHost.ListenerAbility → 行动PrepareListenerCast → 根executePreparedCast/executePreparedAbility → 子帧执行/提交与局部接纳回执 → 子事件再次派发。见[监听接线](../../../wasm/tinygo_engine_v2/internal/runtime/execution/listeners.go)、[实际能力交接](../../../wasm/tinygo_engine_v2/internal/runtime/execution/hit.go)与[事件尾部](../../../wasm/tinygo_engine_v2/internal/runtime/execution/events.go)。

监听继续拥有冻结列表、全部条件、逐项复查和节流，已消费行动的真实接纳结果；编排按原边界建立独立能力帧、交接结果并执行尾部。监听准备保留“先冷却、后引用与用途限制”，普通PrepareCast仍先核用途、后查冷却；两入口不能互换错误优先级。监听先检查原错误，再处理成功节流；子帧已发布后报错仍停派发，不补成功节流或撤回前缀。现行编译拒绝每次使用额度与AbilityRef同用，本次不扩大准入。此处“子帧”不承诺整条嵌套原子提交，同帧附着操作仍借原帧。

[监听嵌套测试](../../../wasm/tinygo_engine_v2/internal/runtime/execution/listener/dispatch_test.go)约束外层冻结不被嵌套卸载/新增破坏；[帧预算测试](../../../wasm/tinygo_engine_v2/internal/runtime/execution/execution_budget_frame_test.go)约束嵌套深度不重置及已提交过程保留；[失败回复测试](../../../wasm/tinygo_engine_v2/internal/runtime/execution/damage_state_before_test.go)约束失败子回复不发布，但不能回滚父伤害。

### 6.4 数值结算、护盾与发布的交叉边界

伤害当前依次经历修正/防御 → 当前盾血计算 → 写角色与护盾暂存 → 耗尽关联处理 → 两遍属性重算 → 吸血 → 原伤害尾部。数值职责拥有计算与数值状态；效果职责仍唯一拥有护盾实例和每盾剩余值，结算只在原帧借用它的所属变更；护盾出现、期限、关联和卸载政策不进入纯管道。

根commit.go先按原序发布全部拥有者的角色/冷却/效果暂存，再准备一次原移除上下文，逐拥有者调用效果PublishMutations；效果内部解释种类并执行完整实例责任。随后效果Projection.Publish交出原投影期限/证据，编排继续生命解析同步、过程、死亡、统一队列与事实。两阶段预检仍在原位置：投影完整性先检查，后续效果预演内部选择原底表且不跳过已投影操作；逐盾需求和正式期限匹配由效果负责，根只汇总容量。预检失败不发布，后续失败保留原具体前缀；同一帧的部分发布不是跨职责事务。数值重算/缓存及角色状态发布的进一步收敛留第4步。

## 9. 初始化、作用域与循环处理

| 阶段 | 所属职责与交接 | 公开运行前必须成立 |
| --- | --- | --- |
| 实例启动 | 入口构建固化策略、会话表和出箱 | 没有本场Loop、状态或跨场可变业务对象 |
| 会话编译 | 编译使用公式编制与基础目录，成功登记计划 | 引用、授权、预算和可用元信息完整；失败产物不登记 |
| 运行准入与构造 | 入口核验本次身份/时间；先建唯一Loop，再建所属状态、缓存、共同额度与业务执行能力 | 必要依赖按单场作用域就绪；构造不回调未完成对象 |
| 原序准备 | 各职责在既有位置检查/恢复资源上限初态、记录/采样、驱动公式、命中、计时、额度、过程、来源等 | 不重排初态准入和后续生命同步；本场公式允许补充且不回写会话 |
| 完成装配 | 最后公式追加与绑定后冻结运行能力，按原位置登记首事件，传入有限阶段 | 会话计划只持冻结集合；初始化先借会话能力，在原驱动位置以本场构建器补充后冻结，不回写会话 |
| 运行与结束 | Loop驱动编排；各职责按原阶段推进；结果观察后交出 | 每场可变对象退出作用域；会话可复用；延迟载荷和同步借用不跨场 |

纯数学程序、目录和计划是已就绪数据；数值管道是函数，不为了画构造图制造实例。准备失败只清理本场未公开资源，现有会话不删除；这不等于撤销已发布战斗事实。轻量执行对象可在同步调用时借用，不要求全部变长期实例。

| 风险 | 本版处理 | 不可采用的替代 |
| --- | --- | --- |
| 调度与编排互相需要 | 先建Loop，再建编排，最后Run(driver)；运行回调不进入构造环 | 半初始化对象、可写堆或第二循环 |
| 效果准备与公式/派生求值交错 | 按第6.2节保持原实际准备点，随后只交付事实；现行两遍方向与缓存规则保持 | 全依赖预热、条件两支提前执行效果准备、改成无限迭代或把PrepareRead伪装成纯读 |
| 行动/效果/结算相互请求 | 各自声明所需阶段，编排在原真实帧路由；传有限值/能力，不互持完整对象 | 相互导入业务包、总服务上下文或异步事件总线 |
| 监听或复制同步再入 | 每次独立冻结和恢复凭据，共享原预算与额度；延迟恢复不带同步栈 | 全局当前帧、每层重置额度/深度、把合法往返当包循环拒绝 |
| 共同契约与状态交叉 | 共享有限值放实际合适下层；接口在真实消费者声明，权威状态唯一 | 把全部状态与接口塞入contract导致反向引用；合成一个总状态 |
| 分阶段发布彼此依赖 | 所属职责交出已决定变更，编排保留原预检与发布次序，按真实位置验证失败前缀 | 将变更一次性批量发布、全链回滚或通过重试重复提交 |

包图用源码检查；构造依赖按作用域检查；运行往返按身份、时点、重入、预算与发布检验，不能互相充当证明。HTML主视图是目标职责与协作契约，构造阶段和数据交接单独说明，包图仅供调查。

## 10. 设计模式与外部参考的具体落点

| 变化点 | 使用方式与已有落点 | 适用边界 |
| --- | --- | --- |
| 创建和共同生命周期 | 显式工厂与依赖注入，由运行组合装配各具体对象 | 无动态扫描、反射容器、服务定位或可选空依赖；不创建纯数据服务 |
| 调度与业务分离 | 调度控制循环，通过LoopDriver回调编排，已实现 | 保留机械循环与业务决定各自所有权 |
| 行动、命中、监听等稳定流程需要外部步骤 | 消费方声明有限同步阶段，编排实现；已有ProcessStartWork/CandidateHost/DispatchHost/Host | 先封装所属业务知识，再限定能力；不能仅增加接口转发壳 |
| 操作与数值算法 | 既有命令、策略和管道；编译后编号驱动 | 不为每条公式造对象，不把全部子系统改成统一命令解释器 |
| 规则与状态共同不变量 | 行动和效果各自维护业务状态迁移，所属变更和发布按阶段交接 | 无全场总状态，不强制合包或状态对象合并 |
| 事件反应和观察 | 同步观察者式派发；记录消费已提交事实 | 冻结、活资格复查和原提交点是契约，不改异步总线 |
| 公式阶段交接 | 构建能力、冻结集合、运行纯能力和只读元信息分开 | 登记封闭别名，后续构建写时复制；事实借用限于同步求值，完整结算仍包含原位置的受控准备 |

沿用已核对的[DeepSeek Harness官方入口](https://www.deepseek.com/en/harness/)及其[固定提交架构](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/architecture.md)、[Cordis依赖与生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/cordis-primer.md)，参考其消费者、提供者、装配与所属范围分离；[Spring依赖注入](https://docs.spring.io/spring-framework/reference/core/beans/introduction.html)和[循环依赖说明](https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-collaborators.html)用于构造与作用域判断。框架资料不替代本项目职责推导，也不将注册撤销理解成战斗回滚。本次不引入它们的运行框架。

## 11. 可独立验收的迁移步骤

| 步骤 | 实施边界与收益 | 独立完成标准 |
| --- | --- | --- |
| 1．公式完整能力（已实施） | 封闭程序/上下文可写入口；构建、冻结、运行、元信息分阶段交接；全部正式公式路径移除帧回调 | 运行方不能注册/改绑定；冻结后旧句柄和跨场追加隔离；三种特殊读取的合法0/缺失/未选分支错误及原顺序保持；元信息满足准入、缓存与诊断；原效果准备与部分失败边界不变 |
| 2．行动完整结果（已实施） | 普通费用/冷却政策、步骤状态准备及真实接纳归行动；根层保留原帧和尾部 | 调用者不读计数差、不决定EnterStep/Finish、不协调多个行动账；正常未施放、失效计时、付款视图、逐阶段复查和失败前缀等价 |
| 3．效果完整迁移（已实施） | 应用/替换/刷新/移除决定、所属容器与队列需求预演归效果 | 根层不解释ExpiredRef/providerOps种类或逐盾规则；跨行动/监听/重算次序保持，旧世代和精确到期及预演不发布有证据 |
| 4．数值职责收敛 | 操作、数值状态与重算/缓存形成完整能力，效果仍拥有护盾 | 新同类数值规则不要求根层拼抗性/盾血/吸血；前写后读、两遍方向、帧入口防御、复制冻结和原时点失败保持 |
| 5．反应/命中/派生协作 | 复用已接通的真实行动结果，收敛有限负载能力；保留独立算法与一份共同额度 | 原候选和监听冻结、同帧组与子帧、同步深度、立即/延迟复制及共同凭据分别等价；不是接口数量下降就算完成 |
| 6．最终集成 | 对照真实帧、调用方知识、状态所有权和物理依赖完成根层收尾 | 三条关键链完整通过，逐阶段失败前缀与输出完整性等价，根只掌握跨职责规则；再按模块规则完成正式Go、Wasm及宿主性能与分配验证 |

公式作为首项实施，能检验阶段交接、程序私有、输入封装、元信息、预算，以及公式外效果准备的时点保持。行动作为第二项已验证真实接纳、过程完整阶段、费用政策和同步尾部；效果作为第三项已封装实例意图、所属发布/预检、到期和读准备交接。它们仍不能代替数值职责或后续跨所属发布验证；后三步须各自验收，不能仅凭结果等价宣称其职责完成。

实施允许修改的包由对应步骤及第8节映射确定；本轮效果实现已获用户明确授权并完成独立方案与关键改动评审，后续步骤仍须各自明确范围与验收。遇到业务语义不明、原基线失败、并发改动重叠，或必须改变保持项，先补查证据并升级设计。方法与验证继续见[设计指南](../../项目说明/开发指南/功能设计与能力组合指南.md)、[测试指南](../../项目说明/开发指南/测试编写与运行指南.md)及[模块验证入口](../../../wasm/tinygo_engine_v2/README.md)。
