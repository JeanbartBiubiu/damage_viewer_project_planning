# Wasm编码指南

本页用于TinyGo引擎的编译、运行与数值能力修改。[模块规则](../../../wasm/tinygo_engine_v2/AGENTS.md)规定热路径、正式协议及验证门槛；[架构说明](../../../wasm/tinygo_engine_v2/ARCHITECTURE.md)和[执行功能入口](../../../wasm/tinygo_engine_v2/internal/runtime/execution/README.md)维护真实依赖。先定位拥有者，再选择具体实现，不以增加包或接口数量作为重构目标。

## 从变化找到所属位置

| 要改变什么 | 首先核对的拥有者 | 不能由此顺带接管的事实 |
| --- | --- | --- |
| 作者字段、引用和合法输入 | `internal/model/`、`internal/compile/`、`internal/plan/` | 单场可变状态和事件时钟 |
| 时间推进、排序、停止与循环预算 | `internal/scheduler/` | 数值结算、命中和效果私有状态 |
| 行动、占用、过程、冷却和费用 | `internal/runtime/execution/actionflow/`及行动状态包 | 效果实例、命中历史和第二份时钟 |
| 效果实例、期限、周期与护盾生命周期 | `internal/runtime/execution/lifecycle/`及效果状态包 | 报告累计和立即派发所有监听 |
| 数值操作与求值 | `operation/`、`evaluation/`、`internal/pipeline/` | 自行改变跨功能事件次序 |
| 命中、监听和续接 | `hit/`、`listener/`、`continuation/` | 彼此私有状态及完整执行器 |
| 同次使用的预留与额度记录 | `internal/runtime/execution/usage/` | 行动身份的创建及调用方成功边界 |
| 结果累计、有限明细与采样 | `internal/runtime/report/` | 从截断记录重建全场事实 |

表中执行子包均位于 `wasm/tinygo_engine_v2/`。合法依赖以包边界检查及近层规则为准；表只帮助定位，不授权扩大包依赖。

## 类型、能力目录与注释

沿用 `gofmt`（Go代码格式化工具）和目标包的导入风格。类型、能力声明和方法的排列按模块规则，保持变量初始化顺序和编译指令位置。

已有 `类型名API` 是公开实例方法目录，说明写在接口声明处，至少说明调用方依赖的输入约束、借用期限、失败结果及发布边界；实现处只补算法原因。新增纯函数不为形式统一制造空接口或转发服务。具体类型能直接表达高频协作时，不为测试方便改成动态分派。

可参考[共同额度账](../../../wasm/tinygo_engine_v2/internal/runtime/execution/usage/ledger.go)的 `LedgerAPI`：预留、提交、释放、快照各有不同语义。对外说明不能只写“处理额度”，否则调用方无法判断何时可以释放或保留结果。

## 只读计划、每场状态与借用

编译计划可在会话内复用；每场角色、行动、效果、命中及额度状态独立创建。不要将运行过程中的指针或可写切片写回计划，也不要复制已经开始使用、内部持有指针的状态所有者。

传参优先使用本次需要的有限值、已冻结事实、所属变更对象或明确能力。需要完整执行器才能实现一个局部功能时，先检查是否把其他拥有者的读取、排序或提交责任放错了位置。

借用必须回答三个问题：谁拥有底层内容、到哪个同步边界仍有效、调用方是否允许保留。需要跨异步或内存刷新边界保留的数据按现有协议复制，不把宿主的线性内存视图当作永久对象。帧协议和输出缓冲的真实定义从 `internal/base/abi/`及前端桥接源码核对。

## 预留、暂存和提交不能混为一次成功

以共同额度为例，[Ledger](../../../wasm/tinygo_engine_v2/internal/runtime/execution/usage/ledger.go)的预留凭据只属于原账本及原次预留；账本本身不决定战斗帧成功。

| 时点 | 调用方要确认什么 | 可观察结果 |
| --- | --- | --- |
| 预留前 | 当前挂载与真实使用身份合法，完整额度键正确 | 无合法身份不开始占额 |
| 成功预留后 | 是否得到跳过结果或明确错误 | 待提交计数增加，已提交快照仍不包含该条 |
| 原成功边界 | 所属操作确已达到应消费额度的时点 | 提交真实凭据后进入已提交快照 |
| 原失败边界 | 凭据仍是本账的未提交预留 | 仅释放本次预留，不影响已经提交的其他事实 |

不能把 `Reserve` 返回的 `skip` 当作新成功，也不能创建另一份同名账本补记消费。具体行为和身份字段以源码声明为准，组合回归见[额度账测试](../../../wasm/tinygo_engine_v2/internal/runtime/execution/usage/ledger_test.go)。

错误写法是“派生操作失败，清空整场额度账重新计算”。它可能删除已经发布的成功前缀。正确方法是在真实失败边界处理原凭据，并保留之前已提交事实；整条派生链是否可回滚必须由契约明确给出。

## 数值读取、身份与错误

缺失字段、有效0、暂存值、事件冻结值和当前值分别处理。不能因为当前只有一个来源，就用技能名或列表下标替代拥有者、真实挂载、使用和目标的完整身份。

例：同一装备定义挂在两名角色上，或同一角色有两个实际挂载，它们的额度或效果不一定共享。先核对当前规则定义的身份与范围，再选编译期编号、稳定槽位或完整键；优化哈希不能省掉相等性核对。

预期编译及运行拒绝通过已有结果与错误结构返回，保留可定位的作者路径或运行身份。不用 `panic/recover`（崩溃与恢复机制）代替正常控制流程，不吞掉错误继续用零值结算，也不把未提交操作报告为成功。

新增失败分支时，核对失败前哪些内容已暂存、哪些已发布，恢复了什么借用及预留，可靠累计是否只记录已提交事实。提交语义变化按根规则评审，MVP允许修正不合适的契约。

## 确定性和热路径

逻辑时间由同一调度循环拥有；同时刻先后按现有稳定排序和事件规则处理。不依赖映射遍历顺序、系统时间或未受控制的随机输入决定战斗结果，也不在执行热路径增加线程、锁或反射。

例：两个同刻到期事件需要稳定先后时，应使用调度层既有次序与身份；不能遍历一个映射并把遍历先后当作游戏规则。更换容器后，即使总伤害相同，也要核对逐笔时刻、来源和后继资格。

新增每事件查找、缓存和分配前，先说明键的完整身份、缓存有效期、失效条件和容量界限。仅为避免一次小复制而跨场借用状态，可能破坏隔离；仅为统一接口而引入动态调用，也可能改变热路径成本。

性能结论使用正式Wasm及同口径输入、输出模式、观测窗口和工具链。原生Go计时可定位问题，不能代替正式收益；宿主往返含初始化或回收时不能命名为纯计算耗时。剖析入口与参数由[引擎README](../../../wasm/tinygo_engine_v2/README.md)维护。

## 编写与完成核对

开始前明确改变的字段、拥有者、合法依赖、成功与失败时点，以及受影响的调用方。新增机制先从通用供值、能力和操作组合判断，不为单个英雄增加平行执行链。

完成时检查：

- 公开能力目录、中文约束、编译计划和运行输入一致，未给调用方隐含补默认值。
- 每场状态只有所属拥有者，借用没有越界，暂存、发布与预留处理可说明。
- 数值、事件次序、来源及记录限制分别验证，未以最终总额代替生命周期证据。
- 包边界、类型布局、受影响测试及正式产物证据按模块规则执行。
- 测试写法及层次见[测试指南](测试编写与运行指南.md)，构建和失败定位见[排错指南](构建运行与排错指南.md)。
