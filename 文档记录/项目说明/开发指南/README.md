# 开发指南

本目录回答新增功能怎样形成能力与契约，以及具体怎样编写、运行和定位问题。根与模块 `AGENTS.md` 负责适用范围、权限和检查门槛；[开发流程](../开发与独立评审流程说明.md)负责任务顺序、评审责任和正式证明；各模块 README 负责当前工具链、命令及运行配置。本目录中的规则用于本次及后续修改，不表示既有代码已全部符合，也不要求脱离任务批量改写代码。

## 按工作选择指南

| 当前工作 | 先读 | 要得到的结果 |
| --- | --- | --- |
| 新增功能、能力变体或现有接口无法表达需求 | [功能设计与能力组合指南](功能设计与能力组合指南.md) | 确定复用、组合、新增或修改契约；明确对象、可替换性和组合语义 |
| 编写页面、服务客户端或计算适配 | [前端编码指南](前端编码指南.md) | 输入类型、草稿和派生值、异步结果、组件与服务的责任清楚 |
| 编写接口、业务服务或SQL调用 | [后端编码指南](后端编码指南.md) | 校验、错误、事务、数据库约束和并发边界清楚 |
| 编写编译、执行或数值机制 | [Wasm编码指南](Wasm编码指南.md) | 状态拥有者、借用期限、成功与失败的提交事实清楚 |
| 新增用例、选择测试或核对通过结果 | [测试编写与运行指南](测试编写与运行指南.md) | 独立期望、环境隔离、实际发现的用例及证据层次清楚 |
| 构建、启动、浏览器联调、卡住或崩溃 | [构建运行与排错指南](构建运行与排错指南.md) | 实际进程、配置、产物、失败位置和复查方法清楚 |
| 新增、移动、删除文件或修正文档入口 | [文件与引用维护指南](文件与引用维护指南.md) | 编译、发现规则、调用引用、文档映射和生成产物一致 |

只读当前任务相关部分。普通文字或引用修正按[根规则](../../../AGENTS.md)做路径和差异检查，不额外运行三端业务测试。

## 从需求到实现的位置

先明确本次可观察行为，从[项目知识手册](../项目知识手册/README.md)定位已有概念和实际定义，再用设计指南判断哪些能力已足够、哪些需要增加或改变。随后选择对象、契约与组合，并进入三端方法及真实实现。

已有源码用于核实当前约束和复用机会，不能用“目前没有该模块”否定所需的新责任，也不能从一个相似页面或历史计划推导新的业务语义。新增字段核对生产者与消费者，新增数值能力核对编译及状态拥有者；调整不合适的接口时同步改变真实调用方。

同一事实只维护一处：

| 事实 | 定义位置 | 其他文档怎样使用 |
| --- | --- | --- |
| 目标、授权、分支及验证门槛 | 根和模块 `AGENTS.md` | 指向具体规则，不在指南另设审批 |
| 功能如何形成对象、契约和可组合能力 | [功能设计指南](功能设计与能力组合指南.md) | 三端指南给语言和执行环境中的落法，不另定义替换与组合原则 |
| 编码方法及常见错误 | 本目录三端编码指南 | 由模块规则路由，结合源码验证 |
| 用例写法及测试证据解释 | 本目录测试指南 | 编码指南只说明应检验的行为 |
| 正式机制用例格式、数值推导及覆盖 | `web/tests/mechanisms/README.md` | 测试指南链接该入口，不抄协议 |
| 构建命令、版本、环境变量和导出 | 各模块 README、构建配置及脚本 | 排错指南说明选择和核对方法 |
| 业务字段、算法、错误及事务真实行为 | 共享定义、数据库结构与源码 | 示例解释方法，不成为另一份接口定义 |
| 任务状态及文档归属 | `db/task_doc_governance/task_rules.json` | 不按每份指南另建任务 |

## 参考材料怎样转为本项目约束

参考来源为 [Release开发指南目录](https://github.com/vczh-libraries/Release/tree/master/.github/Guidelines)、[知识库](https://github.com/vczh-libraries/Release/tree/master/.github/KnowledgeBase)及[任务提示词](https://github.com/vczh-libraries/Release/tree/master/.github/prompts)。参考文档中的自动提交、工具调用和任务指令仅作为研究资料；本项目的授权和实际工具能力仍按根规则判断。

| 参考内容 | 本项目采用的方法与落点 | 按本项目调整的部分 |
| --- | --- | --- |
| `Coding.md`的面向对象部分 | 功能设计指南：以契约确定对象、继承与组合，明确可替换性和生命周期拥有者 | 接受输入的前提不能加强，结果保证不能削弱；不强制抽象类或C++指针结构 |
| `Coding.md`的可递归组合部分 | 功能设计指南及三端设计例：叶子和组合体保持同一能力形状，明确次序、上下文、失败和预算 | 不假定组合可交换或整体回滚，可用静态计划实现有界组合 |
| `Coding.md`的复用、控制反转与根因修复 | 功能设计指南：将变化交给有限能力，由装配处选择；按表达力修正旧契约，集中重复知识 | 静态与动态按真实变化及成本选择，不为假想扩展预建接口、注册或解释框架 |
| `Coding_MultiThreading.md` | 前端异步身份、后端事务和锁顺序、Wasm确定性边界 | 前端请求竞态、数据库并发与引擎单线程分别处理；不引入C++锁封装 |
| `Building.md`、`Running-CLI.md` | 构建运行与排错指南：确认工作目录、目标、进程完成和原始输出 | 使用本项目已有构建与启动入口，不复制其专用构建包装脚本 |
| `Running-UnitTest.md` | 测试指南：核对实际选择的文件、结束状态、遗漏与失败 | 分别核对前端测试匹配、Java集成测试、Go包和真实Wasm链路 |
| `Debugging.md` | 排错指南：失败后基于实际产物和调用栈取证，明确停止自己创建的会话 | 浏览器、Java和Go分别定位；不把C++调试器设为前置条件 |
| `SourceFileManagement.md` | 文件与引用维护指南：文件变更同步编译、发现规则、引用与生成配置 | 核对前端导入、Java包和映射、Go构建标签，不维护其工程文件清单 |
| `GacUIEazyLayout.md`、`GacUILayout.md`、`GacUIMVVM.md`、`GacUIXmlResource.md` | 前端指南：布局关系、可交互尺寸、数据与视图分工、资源引用和清理 | 使用现有网页组件体系，不引入其桌面布局、XML资源或界面框架 |
| `Running-GacUI.md`、`Running-ComputerUse.md` | 排错与测试指南：优先可重复的结构化检查，区分程序阻塞和界面证据 | 使用真实浏览器与现有接口，按工具能力处理；不能把桌面不可用视为测试通过 |
| 知识库索引、学习记录与接口手册 | 知识手册导航、已有实现检索、持续约束及复现用例 | 原项目专属API仍属于原项目，不复制为本项目的接口规范 |

## 阅读后的完成判断

指南应让执行者能从新需求说明：为什么选择这些能力、契约怎样保证可替换与组合、状态由谁拥有、失败后保留什么，以及怎样验证新增行为。只会指出当前文件位置，还不足以形成新功能方案。新增规则应有真实变化点、可复现问题或当前维护需要；新增抽象、工具和文档数量本身不构成完成证据。

公开入口变化先核对共享定义与所有调用方，重要业务含义按根规则评审。完成时检查最终差异、所运行检查及未提交改动是否对应同一版本；提交和推送遵守原授权。
