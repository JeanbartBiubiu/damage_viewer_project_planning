# 测试编写与运行指南

本页定义三端用例写法、发现与选择、结果读取及证据边界。各模块 `AGENTS.md` 继续定义最低验证门槛，README维护命令和工具版本；[开发流程](../开发与独立评审流程说明.md)维护正式机制回归与证明刷新。固定机制用例格式和数值推导只在 `web/tests/mechanisms/README.md` 定义。

## 先选择能证明问题的层次

| 要确认什么 | 合适的用例 | 单独不能证明什么 |
| --- | --- | --- |
| 输入校验、纯逻辑、错误及状态转换 | 直接构造输入的单元测试 | 浏览器交互、数据库执行及正式产物 |
| 请求路径、凭据、载荷及错误接线 | 前端请求替身、后端控制器测试 | 双方真实服务及网络部署 |
| SQL、唯一约束、事务、锁和并发 | 已授权隔离数据库中的集成测试及独立回读 | 浏览器接线和正式Wasm运行 |
| 跨子系统的编译和运行组合 | Go公开入口组合测试 | TinyGo编译后的行为和宿主内存协议 |
| 作者配置经适配后的数值机制 | 生产适配与真实Wasm的固定机制回归 | 任意真实英雄都已完整准入 |
| 表单、路由、键盘、草稿保留及页面时序 | 真实浏览器用例 | 被接口拦截替换的后端或数据库 |

缺少目标环境时，完成仍可做的检查，保留限制并明确未验证部分；不得将替身结果写成真实链路通过。低影响、可逆改动不新增只复述实现的测试。

## 用例先写行为，再写构造

每个用例先明确触发输入、当前现象、期望及成功标准。名称要能说明条件与结果，例如“旧请求较晚返回时不覆盖新筛选结果”，比“刷新正常”更容易定位失败。

断言覆盖本次改变的成功、失败及边界即可。依赖调用次数只有在“仅一次”“不重放写入”等次数本身属于契约时才作为主要验收；不以断言私有方法恰好被调用来代替业务结果。

期望来自已确认规则、独立推导或可信基准。禁止先跑实现，再把输出复制为期望；发现期望可能错误时先核对依据。既有固定基准不能为迁就新实现而改写，必须区分产品缺陷与原推导错误。

优先复用最近的构造，替身只覆盖本用例不需要真实执行的依赖。构造失败、编译失败或缺少预期对象应立即让用例失败，不能返回空列表让后续断言失去意义。

时钟、随机输入与异步完成条件使用固定输入或受控依赖，清理本用例创建的状态。需要安全随机性的行为按其真实契约验证，不为测试稳定改变生产规则。

## 用契约替换和嵌套场景检验设计

新增能力的测试从[设计指南](功能设计与能力组合指南.md)中确定的契约出发，覆盖本次实际变体与组合。不要只证明每个类单独可调用，而遗漏调用方统一使用时的行为。

| 设计承诺 | 验证方法 | 应发现的破坏 |
| --- | --- | --- |
| 多个实现可替换 | 将相同合法输入和结果要求用于各实现，在共同调用位置使用 | 某实现拒绝有效0、要求额外初始化或用“不支持”绕过能力 |
| 组合后仍是一项能力 | 分别使用叶子、两项组合和必要的嵌套组合 | 父层依赖具体子类型，嵌套丢失上下文、路径或身份 |
| 收集全部业务问题 | 同时构造多个普通拒绝，再单独构造执行失败 | 第一个业务问题错误地终止后继，或执行失败被当成完整报告 |
| 次序属于数值语义 | 独立手算非交换输入，例如10先加5再乘2为30，反向为25 | 组合或编译优化错误重排操作 |
| 成功后才发布 | 在中途注入契约规定的失败，独立检查发布结果和所属状态 | 局部结果泄漏，或把已有提交假定为可自动回滚 |
| 嵌套有界且状态隔离 | 检查预算边界、必要的环拒绝、重跑及独立实例 | 子组合重置预算、修改只读计划或跨次共享可变状态 |

只有契约明确的等价关系才能用于组合测试。空组、单项包装、展开嵌套或交换次序可能影响路径、预算和读取时点，不能凭数学直觉假定等价。保留直接计算的独立期望，不能只让两个同源错误实现相互比较。

上述方法按本次风险和实际设计承诺选择；没有变体、递归或状态发布的简单函数，不为测试表格制造接口和组合框架。假想的后续变体可用于设计推演，不能据此扩大实现范围。

## 前端单测：纯逻辑和请求边界

当前框架为 Vitest（前端单元测试框架），默认在Node环境运行；直接导入纯逻辑和客户端，不假定有浏览器文档对象。需要 `window`、`document`、存储或请求时显式提供受控替身，用例结束后恢复全局对象、计时器、模块状态和替身。

从[密码输入用例](../../../web/src/pages/auth/passwordPolicy.test.ts)可观察独立边界。以下为同目录用例写法示例，测试字符串为构造材料：

```ts
import { expect, it } from 'vitest';
import { passwordValidationError } from './passwordPolicy';

it('接收72字节并拒绝第73字节，不截断输入', () => {
  const maximum = 'aB9!'.repeat(18);
  expect(passwordValidationError(maximum)).toBeNull();
  expect(passwordValidationError(maximum + 'Z')).toContain('72字节');
});
```

这里的边界来自账号契约，不能从实现的当前返回值反推允许长度。多字节字符、全空白、空字符与孤立代理项的构造继续参考同一用例；产品规则的完整定义仍归账号方案。

客户端用例分别核对地址、方法、载荷、凭据模式、取消信号及错误，不把成功响应写成万能替身。401、业务校验拒绝、网络错误和主动取消按各自契约断言；只有原约束允许静默处理的操作才断言不提示。参考[访问统计客户端用例](../../../web/src/services/visitStatisticsClient.test.ts)与[账号客户端用例](../../../web/src/services/authClient.test.ts)。

异步断言要等待完成。控制请求完成顺序，先发A、再发B、先完成B、再完成A，验证最终状态仍对应B；不要靠任意休眠制造“看起来稳定”的测试。对计时器、重试或节流使用受控时间，并核对清理后不再触发行为。

## 后端单测：业务拒绝和可见状态

Java单测使用 JUnit（Java测试框架）和 Mockito（依赖模拟工具），放在 `server/data_manage/src/test/java/`。优先直接构造业务对象；验证装配、过滤器或事务代理时才使用对应框架上下文。

控制器用例检查状态码、响应及权限边界，服务用例检查结果、拒绝原因和业务副作用。模拟数据库只证明调用约定；“调用过一次更新”不能证明唯一约束、原子累计或事务回滚。

时间用固定时钟注入被测对象。例如[访问统计服务用例](../../../server/data_manage/src/test/java/xyz/game/datamanage/service/VisitStatisticsServiceTest.java)在以下时点核对日期：

| 固定UTC时点 | 北京日期期望 | 要发现的问题 |
| --- | --- | --- |
| `2026-11-04T15:59:59Z` | `2026-11-04` | 午夜前不能提前算入次日 |
| `2026-11-04T16:00:00Z` | `2026-11-05` | 午夜整应切换到次日 |

用 `Clock.fixed`（固定时钟）明确输入，不能读取测试机器当天日期作为期望。并发测试使用同步点控制“已经开始”“允许继续”和“已经完成”，为等待设置上限；普通单元测试不因此增加真实数据库依赖。

涉及数据库一致性时，另在已授权的隔离目标验证：准备最小数据，运行真实服务或SQL，独立读回成功与失败后的事实，再清理本用例数据。按数据库访问技能执行，不操作未知共享数据。修改事务回滚时应证明失败没有留下部分写入，修改并发累计时应证明最终值和重复规则，不用模拟调用次数代替。

## Go单测：边界、不变量与公开组合

包内不变量使用 Go `testing`（标准测试框架）和 `*_test.go`，同类输入优先用表驱动组织；辅助构造调用 `t.Helper()`，构造及编译错误立即失败。局部测试可以读取所属私有状态，跨子系统组合经公开编译、会话和运行入口验证，不增加生产旁路。

例如[额度账用例](../../../wasm/tinygo_engine_v2/internal/runtime/execution/usage/ledger_test.go)同时核对三个状态量，而不是只看最终伤害：

| 操作 | 总记录数 | 待提交数 | 已提交快照条数 |
| --- | ---: | ---: | ---: |
| 首次预留成功 | 1 | 1 | 0 |
| 预留后在原成功边界提交 | 1 | 0 | 1 |
| 再释放已提交凭据 | 1 | 0 | 1 |

还需区分旧凭据、后续重试和别场账本。额度凭据的重复处理与会话释放是不同协议，不能从前者推断后者可重复成功。跨场隔离、同刻事件顺序、预算耗尽和失败后的已发布前缀，分别选择对应组合用例断言。

涉及数值机制时，手算预期、逐笔时间与来源、生命周期和最终状态按[机制用例规则](../../../web/tests/mechanisms/README.md)核对。原生Go通过之后，仍按模块规则补真实Wasm与宿主证据。

## 浏览器和真实引擎的组合验证

浏览器用例使用 Playwright（浏览器测试工具），从页面输入到结果检查真实操作，优先按角色、标签和用户可见状态定位控件。不要只断言组件类名或内部DOM层级；截图辅助查看布局，不能代替交互结果断言。

区分接口拦截、真实服务和真实Wasm。账号与访问统计的现有配置主要核对接口替身下的页面行为；真实数据写入按任务授权另行验证。代表计算页面还要核对编译、运行、释放和错误后输入保留，不以页面出现一个数值代表完整链路成功。

当前一些浏览器配置启动构建后的预览服务。修改源码后应先生成当前构建，再启动对应配置，避免让新用例验证旧页面。配置及命令从[前端README](../../../web/README.md)进入。

## 核对实际被发现和执行的用例

| 测试入口 | 当前选择依据 | 开始与结束都要核对 |
| --- | --- | --- |
| 前端逻辑和机制 | `web/vitest.config.ts`的文件匹配、排除与运行过滤 | 新文件是否被发现、过滤是否包含目标、实际执行文件及失败摘要 |
| 前端脚本检查 | `web/package.json`中Node测试的显式列表 | 新脚本用例是否进入列表，或在本次显式执行 |
| 浏览器 | `web/playwright*.config.ts`的目录、文件匹配及项目 | 选中配置是否包含目标、页面是否来自当前构建、跳过项及项目结果 |
| Java | `server/data_manage/pom.xml`及实际测试选择 | 以 `IT` 结尾的集成类不能假定被默认单测发现；显式选择后确认报告有该类 |
| Go | 当前模块、包路径、文件后缀、构建标签和名称过滤 | 目标包与用例是否运行，是否只得到“无测试”或缓存结果，真实产物层是否另验 |

新增文件、改名或改过滤后必须核对发现范围。没有被执行的测试不贡献通过证据；不能为缩短时间删除仍相关的筛选项或静默跳过失败用例。

## 读取结果与处理偶发失败

记录实际命令、工作目录、源码版本、相关配置和必要环境差异。等待当前进程结束，核对退出码与最终摘要；进程仍运行、被取消、超时、没有最终摘要或测试未被发现，均不能写“全部通过”。

发现失败先保留最小输入及原始错误，区分构造、环境、实现和期望依据。偶发失败记录触发频率，用有界重复缩小原因；一次重跑通过不能证明问题消失。与任务相关的缺陷继续修复，无关既有问题单独报告，不改断言掩盖。

完成必要检查后只在新改动、失败、模块门槛或未解决风险要求时扩展或重跑。输出、日志、截图和失败投影放入被忽略目录，长期维护用例、正式证明及必要约束。交付结果必须区分静态、单测、实库、真实Wasm和浏览器。
