# 构建运行与排错指南

本页用于选择现有入口、确认实际运行对象及定位构建、启动和联调失败。具体命令、版本、环境变量与正式参数由模块README和脚本维护；本页不建立第二套构建链。[测试指南](测试编写与运行指南.md)定义用例选择和通过条件。

## 构建前确认输入与目标

| 范围 | 命令与配置入口 | 启动或产物要核对什么 |
| --- | --- | --- |
| 前端 | [前端README](../../../web/README.md)、`web/package.json`、Vite配置 | 依赖锁、构建环境、当前源码、开发服务或预览服务、实际访问来源 |
| 后端 | [后端README](../../../server/data_manage/README.md)、`server/data_manage/pom.xml` | Java与依赖、配置覆盖、启动端口、当前服务进程及所连目标 |
| Wasm | [引擎README](../../../wasm/tinygo_engine_v2/README.md)、构建脚本和目标配置 | 固定工具链、正式参数、固化授权策略、输出位置、身份及分发字节 |

在所属模块目录执行对应命令。先确认脚本用途、读写范围及输出位置，不从同名历史目录或生成副本启动。使用已有脚本检查参数和工具版本；失败后不能临时绕过检查生成一个看似可用的产物。

依赖或工具缺失时明确缺失项，按当前任务需要处理；不要擅自升级到另一套版本来消除错误。配置读取只输出必要结构，涉及本地私密配置时先按密钥安全文件处理技能过滤。

## 怎样确认构建完成

记录当前源码版本及相关未提交差异、工作目录、实际命令和目标。等待进程结束，核对退出码、完整错误和最终摘要，再检查期望产物及其身份。开始构建、日志出现“已写文件”或沿用已有同名产物，都不能单独证明本轮成功。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 命令找不到或脚本参数不接受 | 当前目录、README、固定工具链及脚本参数 | 修正调用或补齐明确依赖，保留原错误 |
| 读取到旧类型、模块缺失或测试未发现 | 源码引用、配置匹配、已完成产物及当前进程 | 定点检查对应配置，不先清空所有缓存 |
| 端口占用或文件被占用 | 实际持有进程、启动目录和任务归属 | 复用已确认符合目标的服务，或只停止本任务拥有的进程 |
| 构建成功但页面没有变化 | 开发/预览模式、当前分发目录、浏览器来源、工作线程或缓存 | 确认访问的是本轮构建，保留输入后按问题清理受影响状态 |
| Wasm重建与分发不一致 | 工具版本、目标、参数、授权策略、源码和输出路径 | 查明差异后按正式发布链更新，不直接改摘要或证明 |

## 启动与进程生命周期

启动服务前确认是否已有符合当前代码和配置的实例，记录自己启动的会话或进程身份、目录和用途。端口可访问只说明有进程监听，还需通过最小接口或页面确认目标版本与行为。

长运行服务保留可交互或可轮询的会话，不把持续监听误报为未完成构建。测试及一次性工具应有结束状态；明显卡住时检查最近日志、实际进程与待完成操作，再决定是否中断。停止范围限定为本任务拥有且已确认的会话或进程，不按名称批量结束其他任务。

工具失败、取消或超时后，先检查文件、业务副作用和产物，再决定重试。写操作不因没有收到最终响应就自动重放；先独立读回实际状态，按接口的重试语义处理。

## 前端与浏览器：沿一次操作排查

1. 固定页面来源、路由、输入和复现动作，确认开发或预览服务对应当前代码。
2. 查看浏览器控制台和网络面板：请求是否实际发出、地址与方法是否正确、凭据模式和响应状态是否符合当前操作。
3. 沿组件状态、业务客户端、统一请求入口、适配器或工作线程定位；只检查定位所需的非敏感字段。
4. 控制同一操作的开始与完成顺序，检查旧请求、卸载后的回调和订阅是否覆盖新输入。
5. 修复后重做原动作，核对成功、错误和保留草稿行为，再按模块规则扩大验证。

例：页面显示旧查询结果时，先看A、B两次请求和各自对应的输入身份。若B先完成而A后完成覆盖页面，应修正失效结果提交边界；仅增加延迟或重试会使竞态更难发现。

布局问题检查元素实际尺寸、滚动区域、缩放和键盘路径；结构化状态与交互优先，截图辅助确认视觉。无法使用桌面时继续完成可用的浏览器或接口检查，同时明确尚缺的界面证据，不将缺失能力当作通过。

## 后端：区分装配、契约和持久化

先区分启动装配失败、请求未到达、权限或校验拒绝、业务失败与数据库失败。沿控制器、服务、事务、映射及SQL的真实调用链读取，不为了让请求成功先扩大认证或跨域放行。

| 失败位置 | 需要的证据 | 避免的误判 |
| --- | --- | --- |
| 启动或依赖装配 | 实际异常链、依赖和配置覆盖的非敏感结构 | 用“编译成功”代替启动验证 |
| 请求与权限 | 实际来源、路径分类、状态码和错误类型 | 将所有401都当作会话失效，或重放原写操作 |
| 映射与SQL | 接口方法、XML语句编号、参数、结果别名和真实结构 | 只看模拟持久化测试成功 |
| 事务与并发 | 事务边界、锁顺序、真实冲突与独立回读 | 控制器预查一次就认为不会竞争 |
| 数据库或外部依赖 | 受控环境中的错误及实际连接目标 | 将临时连通失败转换为空数据成功 |

涉及真实数据库时使用数据库访问技能；仅核对静态SQL时无需访问实库。需要调试时固定目标请求和输入，选当前测试或服务进程设置断点、查看异常栈和局部状态，避免将完整请求、凭据和连接配置输出到日志。

## Wasm：先区分协议、机制与宿主

1. 确认正在加载的分发字节、身份、导出及当前授权策略；不要仅凭前端常量判断产物。
2. 区分加载/导出、请求帧、编译拒绝、会话生命周期、运行拒绝及数值差异。
3. 保存最小输入、明确来源和输出模式，检查具体错误路径、运行身份、停止原因及记录是否截断。
4. 根据失败所属层选择原生Go局部测试、公开入口组合、Node宿主、真实Wasm机制回归或浏览器；保持相同输入和预期。
5. 修复后按[开发流程](../开发与独立评审流程说明.md)核对最终源码、正式构建、分发字节和必要证明，不能用旧二进制验证新源码。

例：汇总正确但逐笔命中归属不对时，应核对候选、事件次序和完整使用身份；不能把问题简化成小数误差，也不能删除来源断言。性能问题按正式口径剖析，无法归因时明确符号限制，不用父调用累计耗时代替自身耗时。

正式工具链、内存目标、授权参数及剖析入口从引擎README读取。调试产物只作定位，不能替代正式分发身份；授权拒绝先检查受信任公钥、票据期限和账号身份，不加绕过验签的测试开关。

## 崩溃、卡住与一次修补后仍失败

保留原输入和错误，在实际运行对象上确认最后推进到哪里，查看调用栈、等待条件、资源和相关状态。需要交互调试时保留同一会话，分步执行并读取输出，结束后明确停止该会话。一次猜测性修改失败后继续补默认值或扩大捕获，通常只会丢失根因。

界面阻塞、服务等待、死循环和真实耗时长分别判断。有诊断进展时继续取证，没有新证据时缩小输入、局部启用必要诊断；不无界等待或反复运行同一失败命令。调试工具不可用时先收集可用证据并标明限制，不伪造调用栈或运行结果。

## 完成记录

交付说明问题的触发、实际根因、修复位置、执行命令、结果与尚缺层次。原始输出放入忽略目录，仓库维护可复现用例、必要约束和正式证明；历史过程从Git追溯。发布、部署及真实数据处理继续按原授权，不因本页给出排查步骤扩大任务范围。
