# 文件与引用维护指南

新增、改名、移动和删除文件时使用本页。工作范围与提交规则以[根规则](../../../AGENTS.md)为准；编写方法见[指南入口](README.md)，验证门槛仍由各模块规则维护。

## 修改前先区分文件性质

| 文件性质 | 怎样处理 |
| --- | --- |
| 当前源码或测试 | 从定义、导入和调用方确定拥有者，再核对编译与测试发现规则 |
| 构建配置、共享类型或SQL映射 | 同时查消费者、生成输入和工具脚本，不能只改文件名 |
| 当前文档或规则 | 确认入链入口、唯一来源及任务映射；近层规则不得静默覆盖授权 |
| 生成文件或分发产物 | 找真实输入和生成命令，按正式链路重建与比对 |
| 被忽略的日志、截图或参考材料 | 作为局部证据使用，不自动加入版本库或变为规范真源 |
| 其他任务的已修改或已暂存文件 | 记录基线并保留，只提交本任务范围 |

先用 `rg`、`rg --files` 搜索路径、定义和引用。被忽略目录中的文件可能已受Git跟踪；必要时用 `git ls-files -- <路径>` 核对，不能仅因默认搜索没有显示就判定文件不存在。

## 新增和移动代码时核对什么

| 模块 | 必须追踪的引用 | 容易遗漏的发现或生成配置 |
| --- | --- | --- |
| 前端 | 导入、导出、路由、导航、页面消费、样式及资源路径 | `web/tsconfig*.json`、`web/vitest.config.ts`、`web/playwright*.config.ts`、`web/package.json`中的显式脚本列表 |
| 后端 | Java包名、注入、控制器路径、服务调用、映射接口和XML | `server/data_manage/pom.xml`、资源扫描路径、映射命名空间及语句编号；使用框架扫描时确认所属包仍被扫描 |
| Wasm | Go包导入、公开能力目录、调用方和宿主协议 | 包边界检查、构建标签、编译指令、导出、目标配置和正式分发身份 |
| 共享定义 | 前端类型、后端返回、引擎协议、公式和固定枚举的生产与消费 | 共享契约检查、固定机制用例及正式证明所依赖的执行链 |

移动前先读取文件和近层规则，移动后重新检索原路径、原导出和新路径。生成目录里的同名文件不参与源码修改；需要保留的编译指令必须继续紧邻对应声明。

### 例：测试改名后没有被执行

将 `web/src/services/example.test.ts` 改成 `example.spec.ts`，文件仍可能被编辑器识别，但当前Vitest普通源码匹配不包含该后缀。正确处理是遵循当前匹配，或在任务确需调整测试发现时明确修改配置并验证实际执行文件；不能仅看文件存在。

运行选择与结果核对见[测试指南](测试编写与运行指南.md)。修改测试发现范围不能把原有相关用例无意排除。

### 例：映射接口改名后SQL没有同步

Java映射方法改名时，同时检查XML的语句编号、参数、结果列及调用它的服务。仅凭Java编译成功不能证明映射能运行；资源加载错误、空结果及事务行为需按后端规则验证。

对于被正式调用的结构化SQL，使用对应数据库结构确认列和别名。涉及实库时继续遵守数据库访问技能，不从配置文件直接打印连接凭据。

## 维护文档的当前入口

文档正文先回答该主题独占的问题。共享字段、接口、错误、必要顺序只有一个定义位置；拆出指南时将原正文迁移，并把原入口改为链接，不在两处维护同一条详细规则。

移动或删除当前文档时，至少检查：

1. 根README、模块README、近层 `AGENTS.md` 和知识手册是否仍链接原路径。
2. 当前有效设计、工具和测试是否把该文档当作规则来源。
3. Markdown链接目标及锚点是否存在，显示标题能否解释引用用途。
4. 任务映射是否更新，文档头与对应任务归属是否一致。

历史证据中的原始出处可以保留，但须能区分“当时来源”与“当前必读”。不能删除规则的唯一来源后，只留一条指向Git历史的现行实现要求。

### 例：本机绝对路径不能成为共享入口

将旧检出的本机绝对路径作为报告链接，会依赖该机器目录和未提交产物。当前规范应链接仓库内受维护的依据；仅存历史证据时指向可访问的归档入口，并如实说明证据状态。不要把缺失文件重命名为空文档来通过链接检查。

仓库正文中的路径相对根书写；Markdown相对链接按所在文档位置解析。不要把聊天中供点击的本机绝对路径原样复制进项目文档。

## 生成产物与正式证明

Wasm分发文件、身份记录和正式证明必须按[引擎说明](../../../wasm/tinygo_engine_v2/README.md)及[开发流程](../开发与独立评审流程说明.md)更新。改源码后只复制旧二进制，或只改摘要常量，都不能建立源码与产物的一致性。

依赖锁文件由对应包管理器与本次依赖选择维护；不要为修格式删除锁文件或清空本机依赖。固定机制期望和保留基准按其维护规则修改，不因当前运行失败批量重录。

## 完成核对

- 原路径、导出和调用点已经定点检索；未运行的层次有明确说明。
- 新文件处于正确拥有者内，并被当前编译、发现或生成入口使用。
- 当前文档链接、代码引用和任务映射一致；归属检查按[文档治理技能](../../../.agents/skills/task-doc-governance/SKILL.md)执行。
- 新增或移动受治理文档时只维护实际映射；SQLite仅在明确需要时重建。
- 最终差异只包含本任务文件，已有脏改和暂存状态未被顺带覆盖。
