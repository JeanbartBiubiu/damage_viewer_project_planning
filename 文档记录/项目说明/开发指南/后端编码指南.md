# 后端编码指南

本指南适用于后端新增和修改代码时的具体选择，不表示既有代码已经全部符合这些要求。授权与最低验证门槛见[后端规则](../../../server/data_manage/AGENTS.md)，产品概念从[知识手册](../项目知识手册/README.md)进入；实际接口、字段和数据库结构仍以各自定义为准。

工具版本、构建和运行命令只查[后端说明](../../../server/data_manage/README.md)。测试构造、替身、发现规则及证据分层由[测试编写与运行指南](测试编写与运行指南.md)维护；本文说明生产代码怎样组织和处理失败。

## 先确定修改属于哪一层

| 修改内容 | 主要责任位置 | 同时核对 |
| --- | --- | --- |
| 路径、参数绑定、请求格式、响应状态 | 控制器及请求类型 | 现有错误响应、权限过滤及调用页面 |
| 业务规则、组合保存、引用与权限复核 | 所属服务或已有守卫 | 调用链、事务入口、失败后状态 |
| 查询列、更新条件、数据库约束 | 映射接口、SQL映射或所属存储 | 实际建表语句、参数、返回类型和影响行数 |
| 配置读取、依赖装配、连接行为 | 现有配置与支撑组件 | 模块说明、覆盖来源及受影响启动路径 |
| 跨端字段或错误含义 | 当前共享定义 | 生产者、消费者及对应验证 |

控制器保持清晰的解析、调用和响应，不把事务拆成多次服务调用后再在路由层补救。服务复用现有校验和存储入口；新增抽象应解决本次真实复用或责任边界，不为未来功能建立通用框架。

修改前沿定义找到真实调用方。管理配置链同时核对 `server/data_manage/src/main/java/` 与 `server/data_manage/src/main/resources/mapper/`；不能只改路由、接口声明或一份SQL后就判断行为已改变。

## 类型表达稳定契约，动态结构保留动态边界

稳定请求和返回值优先用明确字段的类型。Java的 `record`（固定字段的数据载体）适合没有独立可变生命周期的结果；有真实状态和行为的对象沿现有类结构组织。

| 数据形状 | 选择 | 避免 |
| --- | --- | --- |
| 固定字段的请求或统计行 | 明确字段、类型及可空性 | 靠字符串键和调用方强制转换表达固定契约 |
| 作者配置中的开放键集合 | 已有JSON树或经过边界校验的映射 | 为形式一致硬编码所有可能键 |
| 数据库查询的临时行 | 核对列名和结果转换，边界处转为需要的类型 | 把未经检查的查询映射直接传遍业务层 |
| 错误详情中的可变字段 | 沿现有错误模型给出必要结构 | 借错误详情返回凭据、完整配置或内部堆栈 |

下面是同一统计结构的写法示意，局部变量省略；第一种把数字误写成字符串也可能通过编译，第二种在构造边界表达字段类型：

```java
// 反例：固定契约仍靠字符串键和值类型约定。
Map<String, Object> day = Map.of("date", date, "pv", "7", "uv", 1);

// 正例：与当前统计返回类型相同的结构。
record DayStatistics(LocalDate date, long pv, long uv) {}
DayStatistics day = new DayStatistics(date, 7L, 1L);
```

真实实现见[访问统计服务](../../../server/data_manage/src/main/java/xyz/game/datamanage/service/VisitStatisticsService.java)。该服务也使用以日期为键的映射完成查找；这类临时索引有明确用途，不需要为了禁止映射而改造。

`null`、未提供、空集合、有效0和对象不存在分别判断。局部更新先确认“字段未出现”与“明确清空”的现有含义，不把缺失数值补成0，不把不存在的对象补成空结果。

## 校验放在实际边界，失败保持可区分

控制器利用现有请求绑定和校验能力拒绝格式错误；服务校验对象关系、权限和组合语义。数据库约束承接最终一致性，不能因前端已有校验而省略后端边界。

| 失败种类 | 处理方向 | 不应发生的行为 |
| --- | --- | --- |
| 外部输入格式、必填或取值范围错误 | 沿现有字段校验及错误模型返回 | 强制转换后补默认值继续写入 |
| 对象不存在、引用冲突、基线过期 | 使用所属业务的已有错误码和状态 | 把不同失败统一当作“保存失败”或空结果 |
| 数据库、连接或装配异常 | 保留可诊断原因，沿现有基础设施失败路径返回 | 捕获所有异常后返回成功、空列表或伪造业务不存在 |
| 内部状态违反已成立的契约 | 明确暴露实现错误并定位根因 | 静默跳过操作以维持表面可用 |

公共错误模型见[ApiException](../../../server/data_manage/src/main/java/xyz/game/datamanage/support/error/ApiException.java)与[统一错误处理](../../../server/data_manage/src/main/java/xyz/game/datamanage/support/error/GlobalExceptionHandler.java)；账号链还有自己的错误处理，修改前先确认真实入口。

只有恢复动作及其结果有明确语义时才捕获异常。已确认的可选行为也应有清楚的失败边界；不能把现有局部容错推广成所有数据库操作的通用策略。

## SQL、参数和结果必须一起核对

使用 MyBatis（SQL映射工具）时，接口命名空间、语句标识、参数名和返回列同时维护。值通过现有参数绑定传入；动态排序或列名只从明确允许的集合选择，不拼接未经校验的请求文本。

下面的结果别名写法来自现有游戏查询；PostgreSQL会把未加引号的普通标识转成小写，因此这两种写法不能视为等价：

```sql
-- 反例：需要 gameId 的映射可能拿到 gameid。
SELECT game_id AS gameId FROM public.games;

-- 正例：保留契约要求的驼峰字段名。
SELECT game_id AS "gameId" FROM public.games;
```

对照[游戏SQL映射](../../../server/data_manage/src/main/resources/mapper/games/GamesMapper.xml)同时检查Java返回结构。更新和删除还要检查受影响行数：0行、1行和意外多行分别意味着什么，由所属业务定义，不能统一按成功处理。

## 事务拥有完整业务变更

一次原子保存明确读取、加锁、基线复核、落地、最终引用校验和提交顺序。声明事务的方法必须由实际事务入口调用；不要只看到注解就假定所有内部调用都获得了新的事务边界。

现有[技能组合保存](../../../server/data_manage/src/main/java/xyz/game/datamanage/service/skillconfiguration/SkillConfigurationService.java)在可写事务内先进入[游戏配置写守卫](../../../server/data_manage/src/main/java/xyz/game/datamanage/support/authoring/GameConfigurationWriteGuard.java)，再读当前基线并核对 `baseDigest`（读取时配置的摘要）。守卫还会在提交前检查最终组合，改动时要沿真实调用关系保留或明确修改这些责任。

- 反例：控制器先读摘要，随后分别保存参数和效果。两个请求都可能通过预查；第二步失败时，第一步也可能已经提交。
- 正例：在所属事务和锁边界内复核摘要，再提交完整变更；任一必需校验失败则拒绝该次原子保存。发生并发修改时返回冲突，由调用方重新读取。

事务外预查可以改善提示，但不能替代写入前的最终复核。失败验证要另读最终数据库事实，确认没有残留部分写入；同一连接里读到了值不等于它已经提交。

需要独立提交的事实必须有明确理由。现有账号存储区分共同事务与独立事务；不能把独立事务当作修复“回滚后数据丢了”的通用开关，也不能捕获异常后让原子变更部分提交。

## 并发由共享事实的拥有者约束

服务对象会处理并发请求，可变请求状态放在当前调用或明确拥有者中。跨请求的一致性依靠现有事务、数据库约束及锁，不用控制器内的先查后写或新增进程内锁替代。

访问累计已有一个可直接核对的例子：同一日期、同一访问者当前次数为1，两个并发上报都应计入，最终为3。

```sql
-- 正例：使用数据库唯一键冲突处理，在数据库内原子递增。
INSERT INTO analytics.daily_visits AS visits (visit_date, visitor_id, pv)
VALUES (?, ?, 1)
ON CONFLICT (visit_date, visitor_id) DO UPDATE SET pv = visits.pv + 1;
```

反例是两个请求各读到1，再各自写入2，造成一次访问丢失。上述语句沿用[访问统计服务](../../../server/data_manage/src/main/java/xyz/game/datamanage/service/VisitStatisticsService.java)与[统计表定义](../../../db/visit_statistics/schema.sql)的设计；存在语句不代表本次已经完成并发实库验证。

多个资源的加锁顺序按所属协议保持一致。[账号存储](../../../server/data_manage/src/main/java/xyz/game/datamanage/support/account/AccountStore.java)说明账号锁先于凭证、流程和会话；[密码额度预占](../../../server/data_manage/src/main/java/xyz/game/datamanage/support/account/AccountRateLimits.java)固定先账号维度、后来源维度。不要在新路径反向取锁，或为方便处理而引入全局串行。

重试先判断是否可能已经产生业务效果。只按明确的幂等语义或可证明未提交的失败进行重试；超时本身不证明写入失败。耗时操作、网络等待和外部回调是否可以移出锁区，要根据真实依赖决定。

## 配置、资源和说明跟随真实所有权

配置可能被环境变量和私有文件覆盖；排错先核对需要的非敏感结构与实际装配，不直接打印配置全文。涉及可能含凭据的文件时先用项目的密钥安全处理技能，私密材料及其摘要规则仍由对应账号或数据库定义维护。

日志仅保留定位需要的操作、对象标识和脱敏错误；密码、动态码、种子、恢复码、票据、会话值和连接凭据不进入日志、测试附件或编辑记录。需要原始响应取证时先确认响应不含这些材料。

直接持有的连接、语句及结果集沿现有资源边界释放；框架管理的事务连接按其管理方式使用。不要为解决泄漏手动关闭仍由当前事务共享的连接，也不要把请求相关资源留在服务字段中。

方法说明写调用方必须知道的必填、可空、错误、事务、锁顺序和副作用；实现注释解释算法或不可直观推断的原因。接口改名、SQL列调整或职责迁移时，同步更新当前入口和示例，不让旧说明继续定义已删除的路径。

## 修改与完成核对

- 开始前确认真实请求入口、所属服务、映射及DDL，找到相关调用方和已有边界用例；共享字段变化先核对跨端定义。
- 修改时确认必填与有效0没有混淆，错误没有变成成功，事务及锁仍覆盖所需事实，没有引入无条件重试、凭据日志或兼容分支。
- 完成时按[测试指南](测试编写与运行指南.md)选择对应证据，再按[后端规则](../../../server/data_manage/AGENTS.md)完成最低检查；涉及实库时遵循已授权目标和独立回读要求。
- 交付分别说明源码与静态检查、单元测试、实库及接口结果；未执行的层次明确标记。不要由一次保存成功推断所有对象可运行，也不要由应用启动推断数据库迁移已生效。
