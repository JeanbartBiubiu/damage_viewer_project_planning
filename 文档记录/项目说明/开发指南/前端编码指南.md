# 前端编码指南

本指南规定前端新增和修改代码时怎样处理类型、状态、请求与呈现。它提供检查方法，不表示现有代码已经逐项完成审计；修改时仍先读[前端规则](../../../web/AGENTS.md)及目标目录更近的规则。

测试编写、发现与结果判断由[测试编写与运行指南](测试编写与运行指南.md)维护；工具版本、构建命令与运行配置以[前端说明](../../../web/README.md)、`web/package.json`及实际配置为准。

## 先确定代码的拥有者

| 本次改变什么 | 首先进入 | 留在该边界的事实 |
| --- | --- | --- |
| 菜单、路由、模式与草稿离开保护 | `web/src/config/navigation.ts`、`web/src/App.tsx` | 用户当前入口和页面切换行为 |
| 表单字段、草稿及用户操作 | 对应 `web/src/pages/admin/` 页面 | 编辑基线、未保存内容、校验提示和提交状态 |
| 请求、响应和账号凭据 | `web/src/services/`及其近层规则 | 接口路径、载荷、错误模型和认证选择 |
| 场景输入到计算请求的映射 | `web/src/engine/`及其近层规则 | 来源身份、输入限制和当前场景可表达范围 |
| 曲线、表格和明细解释 | 对应结果转换与展示组件 | 正式输出的展示含义和截断说明 |

先查现有定义与调用方再增加抽象。组件负责交互和呈现，服务负责接口约定，适配器负责计算映射；不要为一个页面新建第二套请求基址、账号状态或Wasm加载器。

## 类型与输入边界

TypeScript是当前前端使用的类型语言。内部业务数据使用明确类型；从网络、浏览器存储及通用组件回调获得的未知值，以`unknown`表示并在实际边界校验。类型断言不会把未知载荷变成有效数据。

- 对象形状、数组元素、有限数值、可空字段分别检查，再向业务函数交付已确认的类型。已有解析器直接复用，不在每个消费组件重新解释相同字段。
- 区分未填写、明确空值、空集合、有效0和非法值。默认值只有在产品或字段契约允许时才能补入，展示占位不能流回计算输入。
- 不用`any`、非空断言或双重强制转换消除真实不确定性；必要断言应能指出已经建立该事实的校验位置。
- 引擎请求的数值与来源限制从现有适配入口继承，不能在页面层按英雄名称或显示文字猜测键和值。参考[数值适配器](../../../web/src/engine/numericAdapter.ts)。

以下是数值边界的写法示例，不是新增生产接口；接入时沿用所属模块的错误类型和作者路径。

```ts
function requiredFiniteNumber(value: unknown, field: string): number {
  if (typeof value !== 'number' || !Number.isFinite(value)) {
    throw new Error(`${field}必须是有限数值`);
  }
  return value;
}
```

| 输入与用途 | 错误写法及结果 | 应有结果 |
| --- | --- | --- |
| 当前生命为数值`0` | `value || maximum`把已死亡改成满血 | 上述校验返回`0`，后续按生命规则处理 |
| 必填数值为`undefined` | `Number(value) || 0`把缺失改成有效0 | 在输入边界报出字段错误 |
| 网络字段为字符串`"0"` | `value as number`保留错误的运行时类型 | 若接口规定数值则拒绝；表单文本按其专用解析契约转换 |

## 草稿、派生值与保存

先区分服务端读取基线、用户正在编辑的草稿、从草稿计算的派生值，以及正在等待的操作。它们的生命周期不同；名称和类型应能看出区别。

- 直接从已有状态计算脏标记、摘要、可用操作等派生值，不再保存一份并用副作用追赶同步。只有计算成本或引用稳定性有实际需要时才缓存派生结果。
- 草稿保留用户尚未完成的输入，例如空字符串与中间数值文本；构造提交载荷时集中校验，不在每次输入时强行补成可保存值。
- 只有属于当前上下文的读取或确认成功的保存结果才能更新基线。保存失败保留草稿和字段错误，不能先清空内容再等待服务器。
- 游戏、对象或账号上下文改变时，明确保留、拒绝继续编辑或按已有离开保护切换；不能把旧对象草稿提交到新对象路径。
- 修改嵌套草稿时产生新的所属对象，避免直接改写基线或共享读取结果。列表项使用稳定业务标识，重排后仍指向同一编辑对象。

可参考[技能配置工作台](../../../web/src/pages/admin/skills/SkillConfigurationWorkspace.tsx)的基线、草稿、请求代次和共同保存边界。复用其有效约束，不把整个页面复制成另一个功能的框架。

## 异步请求、会话与清理

每个请求都要能回答：为哪个上下文发起、谁接收结果、什么时候过期、失败怎样呈现。发送成功不等于允许响应覆盖当前页面。

| 发生顺序 | 必须保持的结果 |
| --- | --- |
| 先读取对象A，随后切到B；B先返回、A后返回 | 页面保持B；A不得覆盖数据、错误或加载状态 |
| 打开统计后关闭，随后响应到达 | 不重新打开弹窗，不更新已失效的内容 |
| 恢复旧账号会话期间，用户退出或切换账号 | 旧响应不能恢复已经失效的身份 |
| 保存请求的连接中断，服务端是否提交未知 | 保留操作身份并核对结果，不能盲目重放写入 |

请求支持取消时传递取消信号；取消不足以区分上下文时使用现有代次或身份检查。成功、失败和最终清理分支都受同一有效性条件约束。取消本地等待不保证服务端写入已撤销。

下面是组件副作用中的示意，使用现有统计客户端；完整加载状态处理见[统计组件](../../../web/src/components/VisitStatistics.tsx)。

```ts
useEffect(() => {
  const controller = new AbortController();
  void listVisitStatistics(apiBaseUrl, controller.signal).then(rows => {
    if (!controller.signal.aborted) setDays(rows);
  }).catch(error => {
    if (!controller.signal.aborted) setError(getErrorMessage(error));
  });
  return () => controller.abort();
}, [apiBaseUrl]);
```

不要用无条件`.catch(() => [])`把查询失败伪装成“成功但没有数据”。产品明确允许忽略的非关键上报按既有契约处理，并保持它与主操作、登录状态和错误提示相互独立。

订阅、计时器、事件监听和图表实例由创建它们的生命周期负责清理。副作用依赖列出实际读取的上下文；不要为压制重复执行而遗漏依赖。账号恢复与修订检查参考[账号客户端](../../../web/src/services/authClient.ts)和[账号状态](../../../web/src/services/authState.ts)。

## 请求与错误呈现

业务客户端沿用[公共请求客户端](../../../web/src/services/apiClient.ts)的基址、凭据、防伪值与错误模型。匿名读取和受保护写入按既有接口契约选择，不能根据页面是否显示登录按钮猜测权限。

- 预期字段错误放回对应输入或现有诊断位置；服务不可用、网络失败和权限失效保留不同含义，避免所有错误都显示成“参数错误”。
- 登录或权限失败保留当前页面和输入，沿现有登录提示处理。需要重新执行的写入由用户在状态恢复后重新操作，不在后台自动重放。
- 错误文本提供可操作信息，日志和界面不得包含密码、绑定材料、恢复码、会话值或完整敏感响应。
- 结果展示读取正式汇总与运行完整性。有限明细只解释已保留记录，不能从截断列表反算全场伤害或悄悄补造来源。

## 布局、键盘与组件生命周期

沿用现有组件库和局部布局模式。界面大小由内容、容器关系和可用视口共同决定；固定宽高要有当前内容依据，避免用多层容器逐层叠加相同内边距。

- 长名称、长错误、空列表和较窄窗口下，输入、关闭和提交操作仍须可达。表格可在自身区域滚动，弹窗不能因固定宽度把关闭按钮推到视口外。
- 表单输入有可访问名称，必要时使用`aria-label`（辅助技术读取的标签）；图标操作不能只靠图形或颜色解释含义。优先使用已有按钮、输入框和对话框的语义及键盘行为。
- 按自然阅读顺序检查键盘焦点；弹窗打开、关闭、取消和校验失败时，焦点留在可解释的位置。不要把纯展示元素改成只有鼠标才能操作的伪按钮。
- 列表重绘和局部刷新保持稳定标识，不因每次渲染新造标识而重建整棵编辑子树。尺寸变化只更新所需布局，不重新创建会话或请求完整数据。
- 调整布局时同时检查实际元素边界、滚动和键盘路径；截图可辅助判断，不能单独证明表单提交、权限和状态保持正确。

## 修改与完成核对

修改前确认字段的定义与实际消费方、草稿所属上下文、请求身份和受影响路由；检查是否已有同类解析器或结果转换可复用。

完成时至少能用具体场景说明：有效0没有变成默认值，非法输入没有被断言放行，旧响应不能覆盖当前对象，失败没有清掉草稿，关闭和切页释放了所属资源。

再按[前端规则](../../../web/AGENTS.md)选择必要验证，从[测试编写与运行指南](测试编写与运行指南.md)确认用例确实被收集。检查最终差异和必要文档，不把构建通过等同于页面或真实计算链已通过。
