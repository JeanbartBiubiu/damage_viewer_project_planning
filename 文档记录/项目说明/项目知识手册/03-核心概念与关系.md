# 第三章：核心概念与关系

本章串联配置和计算中反复出现的对象。阅读后应能说明一个数值来自哪里、属于谁、由什么规则改变。已收录术语的准确口径查[领域知识库](../../领域知识库/README.md)，完整字段和校验仍查[管理模型说明](../../概要设计/项目/实录驱动的系统精简设计.md)、[技能计算取舍](../../概要设计/项目/技能六模块能力组合表.md)与对应共享规范。

## 对象怎样关联

| 关系 | 含义 |
| --- | --- |
| 游戏组织目录与配置 | 属性、角色、装备、技能、状态及构筑在明确的游戏范围内被引用 |
| 角色和装备提供属性、挂载技能 | 直接数值和技能行为分别维护；一个装备可以同时贡献两者 |
| 构筑系统组织分组与可选项 | 合法选择和投入决定所获得的贡献与技能来源 |
| 技能组织六类内容 | 主体、参数与公式、效果、内部状态、过程、条件与触发共同描述行为 |
| 场景实例化实际来源 | 本场选择决定哪个角色、哪件装备或哪个构筑选项提供一份技能 |
| 一次使用产生执行事实 | 使用、命中、效果挂载和结算各有可追溯身份，结果据此关联 |

这些是不同性质的关系。“挂载了某技能”只说明来源关系；是否能在某个计算场景执行，还取决于配置、依赖和实际支持范围，见[当前能力与阅读导航](07-当前能力与阅读导航.md)。

## 角色、属性与资源

**角色**是承受和产生本场数值变化的对象。角色配置声明基础资料与属性来源；进入场景后，还要确定等级、当前生命以及所选装备和构筑。攻击方与目标方是本场分工，不是两套角色定义。

角色以属性参与公式计算，以当前生命承受扣血，机制资源另有自己的状态和消费规则。基础、解析、当前和上限的区别，以及生命为什么不能用同名资源代替，统一见[属性、生命与机制资源](../../领域知识库/属性、生命与机制资源.md)。

效果通过修正区域声明数值如何参与计算。修正区域也称乘区，但不一定做乘法；分组、基数、阶段及正反算例见[乘区与修正区域](../../领域知识库/乘区与修正区域.md)。

## 技能怎样组织行为

**技能**是组织一组角色行为与数值规则的配置单位，可以描述主动使用、被动响应或持续作用。它不要求只对应一条伤害公式，也不能仅凭名称判断发生什么。

| 技能组成 | 回答的问题 | 示意 |
| --- | --- | --- |
| 主体 | 这是什么技能，怎样分类，使用几级，是否启用 | 一个可选的主动技能 |
| 参数与公式 | 数值依据是什么，哪些值需要计算 | 基础伤害按技能等级取值，再结合攻击力计算 |
| 效果 | 要产生哪些有序结果，是否有持续期限 | 造成伤害，或施加一个有期限的修正 |
| 内部状态 | 技能自己需要记住什么 | 层数、弹药、选定模式、准备标记或内部冷却 |
| 过程 | 使用分成哪些步骤，分别何时执行 | 延迟后执行，或按间隔执行有限段数 |
| 条件与触发 | 响应什么真实事件，满足条件后做什么 | 命中后检查层数并执行指定效果 |

例如，“命中后造成伤害并累计层数”至少涉及命中事件、伤害效果和层数归属。若有“累计到指定层数才额外生效”的要求，还要表达条件。效果负责组织结果，实际触发时机由过程或触发规则说明。

参数与公式提供数值依据，场景和真实事件提供本场事实；对象、口径和读取时点共同决定结果。详细区别见[参数、公式与取值时点](../../领域知识库/参数、公式与取值时点.md)，机器结构仍由[共同公式](../../../contracts/formula/README.md)定义。

## 效果、战斗状态与内部状态

**效果**描述有序数值结果及必要的生命周期。一次立即伤害和一个持续修正都可以由效果组织；持续效果还需要明确何时施加、刷新、到期或移除。

**战斗状态**表达施加在对象上的状态事实，并按其配置提供存在、层数或剩余时间等读值。状态目录说明身份与合并规则；运行中的挂载才有本场来源、目标和期限。

**技能内部状态**由技能自己持有，服务于它的计数、弹药、模式或内部冷却。它与对象身上的战斗状态用途不同，也与页面尚未保存的草稿状态不同。

例如，一个效果可以给目标施加持续状态，而触发该效果的技能同时增加自己的计数。前者属于目标上的挂载，后者属于技能自己的运行数据；不能因为显示时都叫“层数”就合成同一份值。

**生命周期**描述一次效果挂载随时间发生的变化，包括施加、周期执行、层数变化、自然结束和提前移除等已接入行为。期限和刷新方式影响后续事件，不能只保存一个“当前存在”的标记。

## 配置、实例和身份

**配置**描述可复用规则；**实例**描述规则在本场的实际出现。数据库中的技能配置、某件装备授予的技能来源、一次技能使用和该次使用产生的效果挂载，不能互相代替。

| 身份 | 用来区分什么 |
| --- | --- |
| 目录与配置标识 | 引用的是哪一个已定义对象 |
| 来源实例 | 哪个角色、装备或构筑选择提供了行为 |
| 使用身份 | 本场哪一次真实开始的使用 |
| 命中身份 | 哪次使用中的哪次目标接触 |
| 挂载身份 | 哪一份持续效果或状态实例 |

同一个技能可以被重复使用；一次使用也可能有多个命中或持续结果。判断“同次使用只触发一次”、关联伤害来源或恢复效果期限，都需要保留对应身份。

## 装备与构筑怎样参与计算

**装备**通过直接属性和所挂载技能贡献数值。场景中的装备选择还要保留来源实例，使同名行为、叠加限制和结果归属能够被区分。

**构筑**用系统、分组和可选项组织选择与投入，并由合法选择产生实际贡献和技能来源。当前使用通用构筑模型承接相应规则，具体选项仍需其真实配置及生产适配支持。

图片、分类和来源资料帮助识别与维护对象；它们不会仅凭显示内容产生战斗行为。管理关联存在、保存成功和本场可运行分别判断。
