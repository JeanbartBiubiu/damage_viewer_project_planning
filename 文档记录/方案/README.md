# 方案约定

本目录存放方案角色 `planner`（Antigravity 中的 Gemini）编写、交 Codex 实施的临时方案。哪些任务需要完整方案或轻量短方案见根 [AGENTS.md](../../AGENTS.md) 第 2 节“工具分工”；本页是方案文件位置、格式、流转和删除的唯一来源。

## 文件与治理

- 临时方案以未跟踪文件存放在主检出的 `文档记录/方案/<task_key>.md`。同一任务分阶段时，使用第一层的 `<task_key>-<阶段>.md`。
- 文件开头写六字段文档头。`TASK_KEY` 写对应任务键（没有现成任务时拟一个），`DOC_TYPE` 固定为 `其他`，`WORKSTREAM` 与任务模块一致，`STATUS` 为 `draft`、`returned` 或 `active`，`EXECUTION_MODEL` 写实际模型（如 `Antigravity Gemini Neon`），`LAST_TRACKED_AT` 写真实日期。
- 本页 `README.md` 保持现有任务映射。临时方案不登记到 `db/task_doc_governance/task_rules.json`。`node tools/task-governance/cli.mjs check` 将它们列为 `temporary_plans` 并检查文档头。SQLite 重建及 `--fix-headers` 跳过未登记的临时方案。

## 正文

按任务档位选择完整方案或轻量短方案，没有内容的写“无”。

### 完整方案

1. **方案版本**。从 1 开始，每次实质修订加 1。
2. **目标与验收**。写明可观察的行为和成功标准。
3. **非目标**。
4. **已核实的现状锚点**。列出实际核对的关键文件、类型、接口、表、符号及约束。
5. **契约**。写明输入、结果、失败、副作用、拥有者，以及共享字段与规则的唯一定义来源。
6. **写入范围、实施顺序与长期沉淀**。按模块列出路径和依赖次序、验收后保留长期定义的位置，以及本次涉及的 A→B→C 后续清理对象。
7. **校验边界与不做的防御**。沿用现有校验时直接引用所属契约。本次新增或改变的校验与容错须在本节列明执行边界和依据。兜底默认值、静默重试、兼容旧格式的分支、内部重复校验和吞掉异常，凡本次新增或改变且未在本节明确允许的，均阻塞验收。按实际任务写明容易实现偏移的行为。
8. **验证层次**。写明本次需要的单测、实库、真实 Wasm、浏览器等证据。
9. **未决问题**。
10. **退回条件**。写明出现哪些事实时暂停受影响部分并退回修订。
11. **评审与偏差记录**。由 Codex 主负责人记录所审版本、结论和依据，以及评审阻塞或实施偏差。

### 轻量短方案

轻量档使用方案文件时，保留六字段文档头和以下 6 节。

1. **方案版本**。
2. **目标与验收**。
3. **变更边界与已核实的现状锚点**。
4. **写入范围、长期沉淀与验证层次**。
5. **校验边界与不做的防御**（遵守上述同一白名单口径）。
6. **评审与偏差记录**（由 Codex 主负责人填写）。

## 流转

Antigravity 与 Codex 始终在主检出的同一份方案上交接。从临时工作树接手时，Codex 用 `git worktree list --porcelain` 定位首条 `worktree` 路径，再读取该路径下的 `文档记录/方案/`。评审记录、确认、退回和清理都落在这份文件上。

只有 `STATUS` 为 `active` 的当前版本可以作为实施依据。退回期间，有独立现行依据的工作可以继续。

| STATUS | 含义 | 写入者 |
| --- | --- | --- |
| `draft` | 草案，编写、修订或评审中 | 方案角色编写，Codex 主负责人记录评审结论 |
| `returned` | 已退回，等待修订 | Codex 主负责人记录原因并退回，方案角色修订 |
| `active` | 当前版本已确认，可实施 | 方案角色按下列条件启用 |

1. **起草**。方案角色在主检出创建 `draft` 文件。
2. **独审**。完整方案在 `draft` 阶段由 Codex 安排只读独立评审。主负责人核对当前稿与所审版本及内容一致，将版本、结论和依据写入“评审与偏差记录”。有阻塞项时，主负责人记录事实和证据，将 `STATUS` 改为 `returned` 后交方案角色修订。
3. **确认**。方案角色在用户明确确认当前版本后将 `STATUS` 改为 `active`。完整方案此时必须已有同版本的独审通过记录。正式开工前有实质修订时，方案角色升版并回到 `draft`，新版按本流程再确认，完整方案先独审新版。启用多角色异步协作时，按[完成申报规则](../../agents/README.md#完成通知与待办)记录已确认的方案阶段。
4. **实施与退回**。Codex 核对主检出方案的状态和版本，从最新 `master` 开实施分支，并在交付中注明所依据的版本。与 Antigravity 并行推进另一项任务时，Codex 在临时工作树实施，主检出停在 `master` 供方案角色使用。关键契约、任务范围或业务含义需要变化时，主负责人暂停受影响部分，在主检出的方案文件写入事实与证据并改为 `returned`。方案角色修订升版后从 `draft` 重新流转。
5. **验收与清理**。Codex 按方案验收，将长期定义和必要证据落到对应位置，按根规则维护和检查实际变更的任务状态与长期文档映射。合入 `master` 并完成必要复验后，由 Codex 主负责人从主检出删除临时方案文件。
