# 伤害金额、护盾与实际扣血

讨论“伤害是多少”时必须说明计算阶段。技能公式得到的金额、正式伤害记录中的原始金额、防御后金额、护盾吸收和实际扣血各有用途，不能直接互换。

## 口径与当前普通伤害链

| 口径 | 表示什么 |
| --- | --- |
| 技能基础金额 | 作者数值规则得到、尚未进入后续伤害修正的金额；它不是所有输出中“原始伤害”的统一含义 |
| 正式输出的原始金额 `rawAmount` | 当前普通伤害链在预期暴击及来源方防御前修正之后、有上限固定减伤和作者防御倍率之前记录的金额 |
| 防御后伤害 `postDefenseDamage` | 当前链的防御及后续伤害修正完成、尚未由数值护盾和生命承受的金额 |
| 护盾吸收 `shieldAbsorbed` | 本笔由有效数值护盾实际承受的部分 |
| 实际扣血 `actualHpLoss` | 本笔真正减少的当前生命，受当时可扣生命约束 |
| 过量伤害 `overkillDamage` | 本笔超过护盾吸收和实际可扣生命的剩余金额 |

以上说明当前普通伤害链，不将独立斩杀、免疫或法术护盾阻挡强行解释为同一条金额流程。读取其他报告字段时仍核对其真实生产者和完整性标记。

当前普通链的主要顺序是：

```text
作者金额与预期暴击
  → 来源方防御前修正
  → 记录 rawAmount
  → 承受方有上限的固定减伤
  → 伤害类型的作者防御倍率
  → 仅暴击部分的后续修正
  → 承受方防御后修正
  → 有效数值护盾吸收
  → 实际扣血
```

不能把 `rawAmount` 解释成“一切修正之前的技能公式值”。例如基础金额100，无暴击变化，来源方防御前增幅20%，且没有其他影响该阶段的因素，则本例记录的原始金额为120。防御倍率为0.5且没有其他减伤或后置修正时，防御后金额为60。

具体实现见[伤害金额结算](../../wasm/tinygo_engine_v2/internal/runtime/execution/operation/damage_numbers.go)、[作者防御求值](../../wasm/tinygo_engine_v2/internal/runtime/execution/evaluation/defense.go)和[护盾与生命结算](../../wasm/tinygo_engine_v2/internal/pipeline/resolver.go)。乘区阶段见[乘区词条](乘区与修正区域.md)。

## 护盾与生命的手算例

以下是口径示意，不对应具体英雄或准入对象。设公式为 `60 + 0.5 × 攻击力`，攻击力80，其余修正和防御均不改变金额，因此每笔防御后伤害为100。

目标开始有80当前生命和40有效数值护盾，连续承受两笔伤害；没有其他回复、免疫或触发：

| 本笔 | 防御后伤害 | 护盾吸收 | 实际扣血 | 过量伤害 | 结算后生命 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第一笔 | 100 | 40 | 60 | 0 | 20 |
| 第二笔 | 100 | 0 | 20 | 80 | 0 |

两笔防御后伤害合计200，实际扣血合计80。不能将200解释为目标扣了200生命，也不能在第一笔同时扣掉100生命和40护盾。这个例子中的剩余关系为“防御后金额＝护盾吸收＋实际扣血＋过量伤害”；只在其已说明的普通结算条件下使用。

## 护盾、治疗与斩杀分别理解

数值护盾是有归属、剩余量和必要期限的实例。创建、刷新、到期和吸收都会改变后续结算；多个护盾按当前选择顺序处理。法术护盾阻挡是一种门禁结果，不能当作相同金额的数值吸收。

治疗增加当前生命，实际回复受上限与治疗修正约束。公式治疗金额、修正后请求金额、实际回复和过量回复也需要分开；吸血还依赖它所读取的伤害口径与来源规则。

独立斩杀可能直接改变当前生命而不形成普通伤害金额，也不必消耗数值护盾。不能把“生命变为0”自动补记成一笔伤害，或用护盾总量反算这类行为。是否在具体作者链可用仍看当前支持边界。

## 展示与分析时避免混用

- 对比输出先选择同一金额口径、时间范围和来源集合，不能把一个场景的原始金额与另一个场景的实际扣血直接比较。
- 击杀、吸血、近期受伤与前序结果读取分别使用它们约定的字段；最终生命不足以重建每笔伤害或治疗。
- 有限明细可能截断，可靠累计应使用正式汇总及完整性结果，不能把保留的明细相加冒充全场总额。
- 免疫、阻挡、未命中、预算中止和正常造成0伤害是不同事实，不只看数值0判断原因。
