# 乘区与修正区域

**乘区，也称修正区域，是游戏配置中用于声明一类数值修正如何参与计算的目录项。** 真实标识、作用域、计算方式和应用阶段共同表达其含义。效果再引用该目录，提供修正数值、增加或减少方向、作用对象及生命周期。

这里的“乘区”不保证执行乘法。显示名称也不决定算法；判断两个修正怎样组合，需要核对真实标识和当前计算上下文。

## 先分清三件事

| 层次 | 负责什么 | 不能据此推出什么 |
| --- | --- | --- |
| 参数与作者公式 | 算出修正所用的数值 | 表达式里出现乘法，不代表结果属于独立乘算组 |
| 乘区目录及效果配置 | 声明数值用于哪个领域、阶段和计算方式 | 两个目录名称相似，不代表真实分组相同 |
| 伤害类型的作者防御公式 | 根据允许输入得到防御倍率 | 伤害类型名称本身不硬编码抗性算法，也不替代其他修正阶段 |

例如20%同组增幅的作者比例是 `0.2`，适配后内部可用倍率 `1.2` 表示该成员；二者是不同口径。静态作者值还可能经过固定倍率及上下界处理，不能绕过其数值规则直接使用显示值。

## 计算方式与基数

下表解释已定位的典型语义；完整合法组合由[固定枚举](../../contracts/system-enums/README.md)、[后端组合校验](../../server/data_manage/src/main/java/xyz/game/datamanage/model/modifierzone/ModifierZoneCombinations.java)和适配实现维护。

| 计算方式 | 典型含义与单位 | 必须注意 |
| --- | --- | --- |
| 固定值加算 `FLAT_ADD` | 增减属性或金额的单位值 | 20是20个数值单位，不自动是20% |
| 比例加算 `RATIO_ADD` | 属性场景相对基础值增加；治疗等场景按所属组规则处理比例 | 同名方式在不同领域不保证使用相同基数 |
| 比例乘算 `RATIO_MULTIPLY` | 将所属阶段的金额或整体属性乘以因子 | 作者比例、增减方向与内部倍率要分开解释 |
| 同组增幅加算 `RATIO_GROUP_ADD` | 同组先加增幅率，再转成倍率；不同组倍率相乘 | 当前语义只接增幅，不把减少混入增幅组 |
| 比例减少取强 `RATIO_MAX` | 治疗的同一组内取最大减少比例 | 不等于所有组、所有领域都取最大值 |
| 剩余比例连乘 `RATIO_COMPLEMENT_MULTIPLY` | 对已有比例尚未覆盖的部分继续减少 | 不直接把多个百分比相加 |

目录作用域区分属性、伤害、治疗及护盾；应用阶段还区分属性固定/比例、防御前/后及治疗或护盾结果。不是表中任意方式都能与任意领域或阶段组合。

## 同组增幅的正反算例

假设某属性基础值100，固定增加20，基础比例增加10%；同一增幅组有20%和30%，另一增幅组有10%。

```text
普通修正后 = 100 + 20 + 100 × 0.1 = 130
第一组倍率 = 1 + 0.2 + 0.3 = 1.5
第二组倍率 = 1 + 0.1 = 1.1
最终属性   = 130 × 1.5 × 1.1 = 214.5
```

把三个增幅都当作独立倍率，会得到 `130 × 1.2 × 1.3 × 1.1 = 223.08`，这是另一种语义。把属性基础比例加算当作“固定加算后再增加10%”也不对：当前例子的普通修正是130，不是132。

上述两种分组结果由[属性分组测试](../../wasm/tinygo_engine_v2/internal/pipeline/attribute_multiplier_group_test.go)直接对照。整体属性乘算在普通修正之后作用，例如 `(100 + 50) × 0.7 × 0.5 = 52.5`，见[整体属性测试](../../wasm/tinygo_engine_v2/internal/pipeline/attribute_total_test.go)。

“同组”仍受实际对象和计算位置限制。不同属性不能因内部组编号相同而相加；伤害分组还受当前伤害、阶段及优先级带约束。真实分组使用乘区标识及执行上下文，不按中文名称合并全场贡献。

## 剩余比例与取强不是同一规则

基础比例40%，再加入两份10%的剩余比例修正：

```text
最终比例 = 1 − (1 − 0.4) × (1 − 0.1) × (1 − 0.1)
         = 0.514，即51.4%
```

结果不是60%。这里操作的是剩余部分，依据见[剩余比例测试](../../wasm/tinygo_engine_v2/internal/pipeline/attribute_complement_test.go)。

若原治疗100，同一取强组内有两份40%减疗，最终是60，不是36或20。该组取最大减少比例；较强的60%到期后，仍有效的40%可以继续生效，见[治疗取强测试](../../wasm/tinygo_engine_v2/tests/runtime/generic_heal_ratio_max_test.go)。不能将这种规则推广到同组增幅。

## 顺序与支持范围

属性的基础比例加算读取基础值；整体倍率和同组增幅随后作用，剩余比例处理有自己的后置阶段。伤害按防御前、作者防御倍率、防御后等真实阶段处理；治疗也区分造成与收到方向。没有一条可适用于所有领域的“乘区统一顺序”。

目录的显示排序不能直接当作所有修正的执行顺序。伤害金额的具体口径见[伤害词条](伤害金额、护盾与实际扣血.md)，属性口径见[属性词条](属性、生命与机制资源.md)，公式与时点见[公式词条](参数、公式与取值时点.md)。

合法目录不等于任意作者配置都已接入。某些输入组合会被生产适配拒绝；具体场景必须核对它的适配、机制用例与准入。不要由枚举存在推断全部路径支持，也不要将某条路径的限制说成整个数学机制不存在。
