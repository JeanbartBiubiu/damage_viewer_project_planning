## 1. 文档目的

本文维护一份跨 Web、Backend、Wasm 和文档体系共用的中英文术语对照，解决三个问题：

1. 中文用户看到英文缩写、内部字段或工程词时，能知道它实际对应游戏里的什么事物、机制或数据状态。
2. 后续文档和 UI 文案使用同一套解释口径，减少同一个词在不同 Batch 里被翻成多个含义。
3. 代码、接口、seed key 等内部契约继续保留英文标识，但文档能用中文说明它们的业务含义。

本文是需求澄清层文档，只定义读者理解和命名口径，不规定具体代码改造步骤。

## 2. 使用口径

1. 面向玩家、攻略作者、普通编辑用户的文案，优先使用中文；行业缩写第一次出现时可写成“中文（英文）”，例如“每秒伤害（DPS）”。
2. 已有 UI 中文化方案明确要求纯中文展示的页面，继续按对应方案执行，不因为本文重新保留英文缩写。
3. 代码标识符、接口字段、数据库字段、seed key、bundle key、测试 fixture 名不翻译；文档中用反引号保留原文，并在旁边解释中文含义。
4. 英雄、装备、技能、符文等游戏专有名词优先跟随官方中文或静态文本快照；英文名只在检索、对照或内部 key 需要时保留。
5. 单个 Batch 的临时术语可以写在局部设计文档内；跨两个以上模块或反复出现的术语，应补充到本文。

## 3. 游戏机制术语

| 英文/内部词 | 推荐中文 | 对应游戏事物或机制 | 展示与维护口径 |
| --- | --- | --- | --- |
| DPS | 每秒伤害 | 单位时间内的平均输出能力，常用于比较持续输出、装备组合或版本差异 | 用户说明可写“每秒伤害（DPS）”；UI 具体页面按中文化方案执行 |
| DoT | 持续伤害 | 点燃、流血、灼烧等按时间周期造成伤害的效果 | 面向用户写“持续伤害” |
| HoT | 持续治疗 | 按时间周期回复生命值的效果 | 面向用户写“持续治疗” |
| HP / Health | 生命值 | 单位当前或最大生命值 | 表头可写“生命值”；内部字段如 `currentHp` 保留 |
| AD / Attack Damage | 攻击力 | 物理输出相关基础属性，可能区分基础攻击力和额外攻击力 | 文档需说明是“基础攻击力”“额外攻击力”还是“总攻击力” |
| AP / Ability Power | 法术强度 | 法术系数相关基础属性 | 面向用户写“法术强度” |
| Attack Speed | 攻击速度 | 普攻频率属性，可能受上限或模式规则影响 | 文档中遇到 cap 时写“攻击速度上限” |
| Crit / Critical Strike | 暴击 | 普攻或特定效果产生暴击判定后放大伤害 | 需区分“暴击率”“暴击伤害”“是否暴击” |
| Crit Chance | 暴击率 | 暴击发生概率 | 期望值计算时不要写成实际随机结果 |
| Crit Damage | 暴击伤害 | 暴击后的伤害倍率或额外加成 | 与 `critMultiplier`、`critDamage` 等字段对应时保留字段名 |
| Basic Attack / Attack | 普通攻击 / 普攻 | 英雄基础攻击动作，是很多装备和被动的触发入口 | LoL 语境下用户文案优先用“普攻” |
| On-hit | 命中附加 / 攻击特效 | 普攻命中时附带的额外伤害、状态或触发效果 | 局部文档可按语境写“命中附加伤害”或“攻击特效” |
| Passive | 被动 | 装备、英雄、技能或符文自带的非主动释放机制 | 需说明来源：装备被动、英雄被动、技能被动 |
| Active | 主动 | 玩家主动释放的技能、装备或动作 | 与技能主动段对应时写“主动效果” |
| Proc | 触发 / 触发一次 | 某个被动或条件效果成功生效一次 | 不建议直译为 proc；代码字段可保留 |
| Cooldown | 冷却时间 | 效果再次可用前需要等待的时间 | `cooldownMs` 等内部字段保留 |
| Internal Cooldown | 内置冷却 | 某个被动自身的隐藏或局部冷却 | 可写“被动内置冷却” |
| Stack | 层数 / 叠层 | 可累积的增益、计数或机制层 | 需说明最大层数、刷新或衰减规则 |
| Status | 状态 | 眩晕、减速、护盾、充能、标记等持续存在的运行时对象 | 工程语境下是运行时状态，不等同于 UI 状态 |
| Buff | 增益 | 对己方或自身有利的状态 | 如果只是中性状态，不要统称 buff |
| Debuff | 减益 | 对目标不利的状态 | 控制、减速、易伤等都可能是 debuff |
| Shield | 护盾 | 在生命值前吸收伤害的临时数值层 | 需说明刷新、叠加、取大值或消耗顺序 |
| Heal | 治疗 / 回复 | 恢复生命值 | 和护盾、吸血、持续治疗分开写 |
| Resource | 资源 | 法力、能量、怒气、特殊条等施放或触发所需资源 | 如果是 LoL 蓝条，面向用户可写“法力值” |
| Execute | 斩杀 | 目标低于阈值时触发的额外伤害或直接击杀机制 | 需写清阈值基于当前生命值、最大生命值还是已损生命值 |
| Takedown | 参与击杀 | 击杀或助攻后触发的游戏事件 | 官方中文通常为“参与击杀” |
| Tick | 周期 / 一跳 | 持续效果按固定间隔结算的一次 | 文档中可写“每个周期”或“每跳” |
| Gate | 门槛 / 条件门槛 | 阻止动作或效果进入下一步的条件检查 | UI 已有“门槛”口径；代码可保留 gate |
| Snapshot | 快照 | 在某个时间点冻结一组属性、数据包或发布内容 | 需区分“战斗属性快照”和“发布数据快照” |

## 4. 引擎与验证术语

| 英文/内部词 | 推荐中文 | 对应游戏事物或工程含义 | 展示与维护口径 |
| --- | --- | --- | --- |
| Wasm | Wasm | 浏览器本地运行的计算引擎载体 | 作为产品/技术名保留 |
| TinyGo | TinyGo | Go 编译到 Wasm 的工具链 | 作为技术名保留 |
| EngineBundle / Bundle | 引擎数据包 / 数据包 | 前端或后端发布给 Wasm 适配层使用的只读机制数据集合 | 用户文案可写“数据包”；契约名保留 |
| RunInput | 运行输入 | 一次模拟运行的输入参数 | 概念名；源码类型可能带 `V2` 后缀 |
| DPSInput | 每秒伤害输入 | DPS 竖切模拟所需的攻击方、目标、装备和策略输入 | 面向用户不直接展示此词 |
| Adapter | 适配层 | Web 把后端 bundle 翻译成 Wasm 输入结构的代码层 | 文档中可写“Web 适配层” |
| Evidence | 证据 / 计算证据 | 证明某个结果由哪些字段、公式、被动和中间值计算得到的结构化信息 | 用户可见时写“证据”；内部字段保留 |
| Breakdown | 拆解 / 明细 | 对总伤害、乘区、属性来源等结果的分项说明 | 图表或表格可写“明细” |
| Formula | 公式 | 属性、伤害、治疗或条件的计算表达式 | 内部 `formulaId`、`formulaProfiles` 保留 |
| AST | 抽象语法树 | 公式的一种结构化表达方式 | UI 方案已定为“抽象语法树” |
| Modifier | 修正 / 修饰器 | 对属性、伤害、冷却等数值进行加成或削减的规则 | 需说明修正对象和阶段 |
| coefficientBucket | 乘区桶 | 伤害或属性修正按阶段和聚合方式分组后的乘区证据 | 文档解释为“乘区桶”，字段名保留 |
| single_attacker_dps | 单攻击方 DPS 通道 | 一个攻击方打一个目标假人的 DPS 验证竖切 | 内部 lane 名保留；用户文案写“单攻击方每秒伤害” |
| target_dummy | 目标假人 | 用于稳定复现伤害的固定目标 | 面向用户写“假人”或“目标假人” |
| deterministic | 确定性 | 同一输入必然得到同一结果；常用于固定暴击或固定随机 | 文档中可写“确定性策略” |
| expected | 期望值 | 用概率期望近似平均结果，例如按暴击率折算平均伤害 | 需明确它不是实际随机序列 |
| seeded_random | 固定种子随机 | 使用固定随机种子复现随机序列 | 用于需要真实随机分支但仍可复现的验证 |
| critPolicy | 暴击策略 | DPS 运行时如何处理暴击：期望值、确定性或固定种子随机 | 字段名保留，旁边解释 |
| attackSpeedCap | 攻击速度上限 | 当前模拟规则允许的最高攻击速度 | 文档需注明具体数值和来源 |
| eventWindowPolicy | 事件窗口规则 | 运行时如何决定哪些事件属于本次统计窗口 | 内部策略名保留 |

## 5. 数据、发布与筛选术语

| 英文/内部词 | 推荐中文 | 对应游戏事物或工程含义 | 展示与维护口径 |
| --- | --- | --- | --- |
| current | 当前版本 / 当前快照 | 对外读取的当前发布版本或数据快照 | 需说明是 game current 还是 bundle current |
| published | 已发布到快照 | 数据已进入 `published_bundle_snapshots.bundle_json`，可被 current bundle API 读取 | 不等于已经通过 Wasm 页面验证 |
| ready | 已验证可默认选择 | 数据已通过当前验证链，允许在默认模拟候选中出现 | BatchW 中由 readiness type 表达 |
| unverified | 已发布但未验证 | 数据在 current published bundle 中，但未挂 ready 标记 | 只能在测试开关或人工验证场景出现 |
| base selectable | 基础可选项 | 满足业务分类的候选，例如 ADC 成装或目标侧防御装备 | 还没叠加 readiness filter |
| filtered selectable | 筛选后可选项 | 基础候选经过 ready / unverified 筛选后的最终选项 | 页面导出证据应保留筛选模式 |
| reserved_type | 保留类型 / 稳定语义类型 | 跨版本、跨 game-local type 复用的稳定语义注册项 | 字段名保留，文档解释为“稳定语义” |
| type_relations | 类型关系 | 把英雄、装备、技能等实体挂到分类、机制或 ready 标记上的关系 | 数据结构名保留 |
| skillRefs | 技能引用 | 装备、英雄或其他实体引用的技能/被动列表 | 字段名保留，UI 可写“技能引用” |
| ownerRole | 所属角色 | 表示某个效果属于攻击方、目标方或其他运行时角色 | 字段名保留，需说明 attacker / target |
| Preflight | 发布前检查 / 预检 | 发布或运行前对数据契约、引用和可计算性的自动检查 | 文档可写“Preflight 预检” |
| Seed | 种子数据 | 用于初始化或补录的数据文件、SQL 或 JSON | 不等同于随机 seed |
| Version | 版本 | 游戏版本、数据版本或发布版本 | 必须写清是哪一层版本 |
| ID | ID | 稳定标识符 | UI 方案保留 ID，不强行译成“标识” |
| Key | Key | 数据契约中的自然键、分类键或配置键 | UI 方案保留 Key，例如“乘区 Key” |
| URI | 资源标识 | 图片或静态资源的定位标识 | UI 方案写“资源标识” |

## 6. 维护规则

1. 新术语如果只在一个 Batch 内使用，先放在该 Batch 的“术语”章节；当它跨文档复用时，再补到本文。
2. 如果一个英文词在游戏语境和工程语境中含义不同，必须拆成两行或在说明中明确上下文。例如 `Snapshot` 可能指属性快照，也可能指发布快照。
3. 如果官方中文不确定，先使用临时中文并在备注中标记“待确认”；后续以静态文本快照、官方中文或用户确认结果更新。
4. 修改 UI 用户文案时，先查本文和对应 UI 中文化方案；修改内部字段或接口契约时，不能只因为中文术语存在就重命名字段。
5. 每次新增跨模块机制、发布状态或验证状态术语时，同步检查本文是否需要补充。
