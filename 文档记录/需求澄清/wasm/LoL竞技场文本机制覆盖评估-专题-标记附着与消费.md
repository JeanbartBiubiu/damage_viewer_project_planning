# LoL竞技场文本机制覆盖评估-专题-标记附着与消费

日期：2026-04-10
状态：已确认
数据快照：`文档记录/详细设计/最小验证/数据/lol_竞技场静态文本快照`
Data Dragon 版本：`16.7.1`
范围约束：

- 只讨论 `1v1` 数值计算
- 跳过召唤物
- 地形、位移、多目标、建筑物、史诗级野怪只在必要时标记为“需转换”
- 本专题只收“先附着、后消费、再刷新/引爆”的标记链路，不把纯计数器专题混进来

## 专题定位

第 3 组已经确认：真正的阻塞点不在伤害公式，而在标记状态本体是否可消费、可过期、可刷新、可引爆。  
本专题只收这一条链路，把共性收成统一实现口径：

- `mark_state`：先挂在目标上的可消费状态
- `armed_mark`：带武装时间或等待窗口的标记
- `stored_damage_on_mark`：标记窗口里额外存储伤害、到期后再引爆的标记

## 本专题样本

1. 阿卡丽 `我流奥义！隼舞`，`champion:Akali:spell:AkaliE`
2. 伊芙琳 `引诱 / 魅魔`，`champion:Evelynn:spell:EvelynnW`
3. 伊泽瑞尔 `精华跃动`，`champion:Ezreal:spell:EzrealW`
4. 艾瑞莉娅 `先锋之刃 / 重心不稳` 消费链，核心用 `champion:Irelia:spell:IreliaR`
5. 劫 `禁奥义！瞬狱影杀阵`，`champion:Zed:spell:ZedR`

说明：

- 布隆、布兰德、羊刀式第 N 次触发等条目不放进本专题，它们属于下一轮的“计数器与阈值触发”专题。
- 本专题的中心不是“有没有一个 mark”，而是“这个 mark 是不是可绑定、可武装、可消费、可过期、可引爆、可刷新”。

## 样本 1：阿卡丽 `我流奥义！隼舞`

文本摘要：

- 阿卡丽后空翻并掷出手里剑，命中第一个敌人或烟雾弹后为其附加标记；再次施放会突进到被标记的目标处并造成额外伤害。

抽象机制：

- 一段命中后生成标记
- 标记绑定到特定目标
- 二段施放只在存在标记时才开放
- 二段施放同时消费标记并触发位移与额外伤害

映射到 V2：

- 一段技能：`AkaliE1`
- 标记施加：`mark_attach`
- 二段技能：`AkaliE2`
- 二段门槛：`has_mark(target_ref)`
- 消费结果：`deal_damage` + `dash_to_marked_target`

结论：

- **这是纯 `mark_state`**
- **不属于 stored damage on mark**
- **核心不是输出，而是“二段技能被标记状态解锁”**

说明：

- 当前更合理的实现口径是把 `E1 / E2` 拆成两个技能。
- `E2` 的存在条件不是冷却，而是目标上是否仍有可消费标记。

## 样本 2：伊芙琳 `引诱 / 魅魔`

文本摘要：

- 伊芙琳标记一名英雄或野怪 5 秒；如果随后用一次攻击或技能命中该目标，就会抹除印记并返还法力消耗。
- 如果标记持续至少 2.5 秒，抹除时还会触发额外效果。

抽象机制：

- 标记先附着，再等待武装
- 武装完成后，后续命中可以消费标记
- 消费同时产生资源返还与减速
- 存在时间阈值，成熟后消费结果增强

映射到 V2：

- 标记施加：`mark_attach(duration=5s)`
- 武装延迟：`mark_arm_after(2.5s)`
- 命中消费：`mark_consume(on_attack_or_skill_hit)`
- 结果返还：`modify_attribute("mana", +x)`
- 强化分支：`if mark_age >= 2.5s then enhanced_effect`

结论：

- **这是 `armed_mark`**
- **不属于 stored damage on mark**
- **核心是“武装完成后订阅被标记对象再次被命中”**

说明：

- 按当前确认口径，`W` 的低收益分支先剪掉，专题里只保留主收益线。
- 这个样本证明标记不是静态开关，而是带时间门槛的消费状态。

## 样本 3：伊泽瑞尔 `精华跃动`

文本摘要：

- 法球会附着在命中的第一个敌方英雄、建筑物或史诗级野怪上；当伊泽瑞尔用技能或攻击命中这个法球时，法球会引爆造成伤害。

抽象机制：

- 命中后附着一个对象
- 之后再次命中同一对象会引爆
- 标记本身承担“附着物”和“触发器”两层职责

映射到 V2：

- 附着状态：`mark_attach`
- 引爆触发：`on_hit_attached_object`
- 引爆结果：`mark_consume` -> `deal_damage`

结论：

- **这是纯 `mark_state`**
- **不属于 stored damage on mark**
- **被附着目标必须是独立可消费实体，不是普通布尔标记**

说明：

- 建筑物和史诗级野怪不在当前 `1v1` 主链路，属于后续扩范围时再转换的对象。
- 这个样本更像“可附着的命中触发器”，不是伤害储存器。

## 样本 4：艾瑞莉娅 `先锋之刃 / 重心不稳` 消费链

文本摘要：

- 艾瑞莉娅发射刀锋弹幕，对命中的敌方英雄和大型野怪施加持续 `重心不稳`。
- 当目标已被标记或死于利刃冲击时，`Q` 的冷却会刷新。

抽象机制：

- `R` 负责施加标记状态
- `Q` 负责消费或利用标记状态
- 消费结果不是引爆伤害，而是冷却刷新/技能解锁
- 标记状态要能驱动另一个技能的可释放性或重置逻辑

映射到 V2：

- 标记施加：`mark_attach(duration)`
- 消费方式：`mark_consume`
- 消费结果：`refund_cooldown` / `reset_skill_cd`
- 技能解锁：`skill_gate_on_mark`

结论：

- **这是纯 `mark_state`**
- **不属于 stored damage on mark**
- **这里的 mark 消费结果是“刷新/解锁”，不是额外伤害**

说明：

- 这里的核心不是 `Q` 自身，而是 `Q` 的释放条件与重置条件都能被 `R` 留下的标记状态驱动。
- 这类条目说明标记状态的消费者不一定是伤害结算，也可以是冷却/技能门槛。

## 样本 5：劫 `禁奥义！瞬狱影杀阵`

文本摘要：

- 劫突进至目标并施加死亡印记；3 秒后，印记爆炸，且劫在印记激活期间造成的伤害越多，额外伤害越高。

抽象机制：

- 先附着死亡印记
- 标记存在一个固定存活窗口
- 窗口内对目标造成的伤害会被累计或存储
- 到期后按存储值引爆

映射到 V2：

- 标记施加：`mark_attach(duration=3s)`
- 伤害存储：`stored_damage_on_mark`
- 窗口结算：`mark_detonate`
- 结果输出：`deal_damage(extra_from_stored_damage)`

结论：

- **这是 `stored_damage_on_mark`**
- **不再只是普通 `mark_state`**
- **它要求标记状态额外持有“存储的伤害值”和“引爆规则”**

说明：

- 这是本专题里最关键的分界样本。
- 不是所有标记都只是“挂上去再消费”，有些标记本身就是一个伤害储蓄桶。

## 本专题汇总结论

### 已确认可支撑的能力

1. 标记状态本体已经足够覆盖“附着 -> 武装 -> 消费 -> 过期 -> 解锁/刷新 -> 定时引爆”这一整条链路。
2. `mark_state` 至少需要支持 `source_ref`、`target_ref`、`duration`、`armed_at`、`consume_trigger`、`consume_result`。
3. 当机制进入伤害储存型分支时，还需要 `stored_damage_on_mark`，至少携带 `stored_damage_amount` 和 `detonation_rule`。
4. `1v1` 主链路里，标记消费不一定表现为伤害，也可以表现为冷却刷新、技能解锁、资源返还。

### 本专题暴露出的真实重点

1. **标记不是布尔值，而是目标级可消费状态。**
2. 标记状态至少要分三类语义：
   - `attach`：先挂上去
   - `arm`：经过等待窗口后进入可消费状态
   - `consume / detonate`：命中后消费或到期后引爆
3. `阿卡丽 / 伊芙琳 / 伊泽瑞尔 / 艾瑞莉娅` 主要都是 `mark_state`。
4. `劫` 才真正进入 `stored_damage_on_mark`，因为它把窗口内产生的伤害再结算进标记爆炸。
5. 布隆、布兰德、羊刀式 N 次触发不在本专题，它们是下一轮“计数器与阈值触发”的专题。

### 本专题建议收口的通用模板

1. `mark_attach`
   - 输入：来源、目标、持续时间
   - 输出：可消费标记状态
2. `mark_arm`
   - 输入：标记状态、武装时间
   - 输出：进入可消费状态
3. `mark_consume`
   - 输入：被标记目标、消费事件
   - 输出：伤害、减速、返还、冷却刷新或技能解锁
4. `mark_refresh_or_unlock`
   - 输入：标记状态、关联技能
   - 输出：刷新冷却或解锁二段技能
5. `stored_damage_on_mark`
   - 输入：窗口内累计伤害
   - 输出：到期引爆的额外伤害
6. `mark_detonate`
   - 输入：到期条件或消费条件
   - 输出：一次性爆炸伤害

### 本专题已确认的实现导向

1. 标记状态不应按“是否存在”建模，而应按“来源 / 目标 / 持续时间 / 武装状态 / 消费方式 / 消费结果”建模。
2. `E1 / E2`、`W 后续消费`、`R 留标记给 Q 刷新` 这类关系，都应通过 `mark_state` 的门槛来表达，不要在技能 JSON 里硬写成特判。
3. `stored_damage_on_mark` 只在像劫这种明确要求“标记窗口内累计伤害”的条目里启用，不要默认加到所有标记上。
4. 标记消费的结果必须允许是非伤害型结果，例如冷却刷新、技能解锁、资源返还。
5. 召唤物、地图对象、建筑物、史诗级野怪仍然留在当前专题的边界外，只在文本里作为 `需转换` 说明。

## 当前判断

本专题结论是：**可行，而且已经把“标记附着与消费”从一级组里收成了一个可实现的二级状态模型。**

更具体地说：

- `阿卡丽 / 伊芙琳 / 伊泽瑞尔 / 艾瑞莉娅` 说明了标记状态本体的通用字段
- `劫` 说明了标记还可能演化成 `stored_damage_on_mark`
- 这两类语义共用一套“附着 -> 武装 -> 消费/引爆”的链路，但不是同一种状态结构

因此，下一步实现收口应优先把 `mark_state` 和 `stored_damage_on_mark` 分层，而不是把所有标记都压成一个统一的布尔位。
