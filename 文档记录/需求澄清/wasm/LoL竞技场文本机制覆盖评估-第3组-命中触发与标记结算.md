## 样本 1：阿卡丽 `我流奥义！隼舞`

文本摘要：

- 阿卡丽掷出手里剑，命中第一个敌人或烟雾弹后为其附加标记；再次施放会突进到被标记的目标处并造成额外伤害。

抽象机制：

- 伤害命中后生成一个可消费的目标标记
- 标记对象是“第一个命中的敌人”或特定召唤物/场景对象
- 二段施放消费标记，触发位移与额外伤害

映射到 V2：

- 一段技能：`AkaliE1`
- 标记施加：`apply_mark`
- 二段技能：`AkaliE2`
- 二段释放门槛：`has_mark(target_ref)`，语义上更接近“状态约束”而不是普通伤害分支
- 额外伤害：`deal_damage`
- 位移：`dash_to_marked_target`，在本组里只作为 `需转换` 的执行效果，不影响机制结论

结论：

- **命中后附加标记：已覆盖**
- **二段消费标记并读取目标：已覆盖**
- **主要缺口：标记需要是可复用的目标状态，而不是一次性布尔开关**

说明：

- 这个样本真正要求的是“标记状态带绑定对象与可消费生命周期”。
- 当前更推荐把 `E1 / E2` 拆成两个技能，`E2` 只有在存在可消费标记时才允许释放，类似蓝量/充能这类可见约束。
- 位移不是本组阻塞点，真正要收口的是标记状态如何被后续施放读取。

## 样本 2：伊芙琳 `诱惑 / 魅魔`

文本摘要：

- 伊芙琳标记一名英雄或野怪数秒；如果她随后用一次攻击或技能命中该目标，就会抹除印记并返还法力消耗。
- 如果标记持续足够久，抹除时还会触发更强效果。

抽象机制：

- 目标附着一个带持续时间的标记
- 标记存在一个“生效前等待窗口”
- 后续攻击或技能命中可消费标记
- 消费时会触发资源返还与减速
- 标记存在“存活时间阈值”，满足阈值后消费结果增强

映射到 V2：

- 标记施加：`apply_mark(duration)`
- 武装延迟：`arm_after(N)`
- 命中消费：`on_attack_or_skill_hit_consume_mark`
- 资源返还：`modify_attribute("mana", +x)`
- 时间阈值：`mark_age >= threshold`
- 强化分支：`if mark_elapsed >= threshold then enhanced_effect`

结论：

- **延迟消费标记：已覆盖**
- **阈值型强化结算：已覆盖**
- **主要缺口：标记状态需要携带创建时间、消费条件和消费结果**

说明：

- 当前范围内可直接采用“理想对局”近似：`W` 释放后的 `N` 秒内默认不去提前攻击目标，只保留成熟后再消费标记的主收益分支。
- 更实现化地说，这里应存在一个带武装时间的状态，它会在武装完成后去订阅“被标记对象再次被攻击/命中”的事件。
- 如果没有统一的标记载荷，消费逻辑会被迫写成大量特判。

## 样本 3：伊泽瑞尔 `精华跃动`

文本摘要：

- 法球会附着在命中的第一个敌方英雄、建筑物或史诗级野怪上；当伊泽瑞尔用技能或攻击命中这个法球时，法球会引爆造成伤害。

抽象机制：

- 命中后附着一个可被后续命中引爆的对象
- 引爆条件是“再次命中法球”
- 这是典型的“附着物 / 标记物 / 触发器”二段式结构

映射到 V2：

- 附着状态：`apply_mark` 或 `attach_proc`
- 引爆触发：`on_hit_attached_object`
- 引爆结果：`deal_damage`
- 目标范围：英雄、建筑、史诗级野怪在原文里都存在；本组只取 `1v1` 英雄前提，其他对象先记为 `需转换`

结论：

- **附着后再命中引爆：已覆盖**
- **对象绑定与触发解耦：已覆盖**
- **主要缺口：需要把“被附着目标”建成独立可消费实体，而不是只记一个单纯标志位**

说明：

- 对建筑物和史诗级野怪的适配不影响本组主结论，但属于后续扩展时要转换的对象范围。

## 样本 4：布隆 `震荡猛击`

文本摘要：

- 布隆的普攻会给目标叠加震荡猛击；后续友军也可继续叠层，叠到 4 层后目标会被击晕并受到伤害，之后一段时间内无法再次叠层。

抽象机制：

- 目标维度的层数累计
- 普攻命中驱动叠层
- 达到阈值后触发控制与伤害
- 触发后进入短时锁定窗口

映射到 V2：

- 层数累计：`increment_stack`
- 阈值触发：`on_stack_threshold_reached`
- 控制效果：`apply_stun`
- 锁定窗口：`per_target_lockout`

结论：

- **按目标叠层计数：已覆盖**
- **层数阈值结算：已覆盖**
- **主要缺口：需要目标级别的 stack 状态和触发后 lockout**

说明：

- 这个样本不要求新的数值表达式，而是要求状态模型能记住“每个目标各自叠了几层”。
- 它和“每第三下额外触发一次攻击特效”是同一类问题，后续可以和羊刀这类计数触发一起收口到通用计数器机制。
- 友军叠层在 `1v1` 下不是主样本，但不影响核心机制判断。

## 样本 5：布兰德 `炽热之焰`

文本摘要：

- 布兰德的技能会对目标施加持续伤害效果，可叠加至 3 次；当击杀带有该效果的敌人时会回复法力值；满层后还会在短延迟后爆炸并造成更大范围伤害。

抽象机制：

- 技能命中生成可叠加的持续状态
- 叠层上限和持续时间并存
- 击杀结果会反向驱动资源返还
- 满层后发生延迟爆炸

映射到 V2：

- 持续状态：`apply_dot_mark`
- 叠层上限：`stack_cap`
- 击杀返还：`on_kill_refund_resource`
- 延迟爆炸：`schedule_delayed_detonation`
- 范围伤害：`deal_damage`，其中范围部分对本组仍按 `需转换` 处理

结论：

- **持续叠层状态：已覆盖**
- **击杀驱动资源返还：已覆盖**
- **延迟爆炸与叠层联动：已覆盖**
- **主要缺口：需要把“叠层持续状态”与“触发后爆炸”统一成同一种可复用模板**

说明：

- 这个样本和伊芙琳一起说明，标记机制的重点不是“有没有一个状态”，而是“状态结束、消费、强化、返还是否能串起来”。
- 从运行时抽象看，它也属于“计数器达到阈值后触发事件”的模式，可以和布隆、羊刀类效果共用同一层 counter 机制。

## 本组汇总结论

### 已确认可支撑的能力

1. `apply_mark`、`consume_mark`、`increment_stack`、`on_stack_threshold_reached`、`schedule_delayed_detonation` 这类基础能力，足以覆盖本组里的命中标记、层数结算、延迟触发和二段消费。
2. 本组没有暴露出必须新增 AST 节点的新公式需求。
3. `命中后附着状态 -> 后续命中消费 -> 阈值结算 -> 结果值回流` 这条链路可以继续走 V2 主路线。

### 本组暴露出的真实重点

1. **真正的阻塞点不是伤害公式，而是标记状态的生命周期。**
2. 这类机制通常同时依赖：
   - `on_hit_apply_mark`
   - `on_attack_or_skill_hit_consume_mark`
   - `on_stack_threshold_reached`
   - `on_mark_age_threshold_reached`
   - `on_mark_expire`
3. 如果这些触发源和结果载荷没有统一模型，后续实现会重新回到大量针对单个英雄的特判。

### 本组建议收口的通用模板

1. `mark_apply`
   - 输入：命中目标、持续时间、来源
   - 输出：可消费标记状态
2. `mark_consume`
   - 输入：被标记目标、消费事件、是否满足时间阈值
   - 输出：基础效果与增强效果
3. `stack_threshold_proc`
   - 输入：目标当前层数、阈值、锁定窗口
   - 输出：控制 / 伤害 / 冷却锁定
4. `delayed_mark_detonation`
   - 输入：标记状态、延迟时间、触发条件
   - 输出：延迟爆炸或额外伤害

### 本组稳定结论

1. `命中触发与标记结算` 本体不会逼着 V2 推翻重来。
2. V2 下一步最需要收口的是 **目标级标记状态、层数状态、消费条件和结果载荷**，不是再扩公式节点。
3. `附着式标记`、`叠层阈值`、`延迟爆炸`、`命中后消费` 都应抽成通用模板，而不是针对阿卡丽、伊芙琳、伊泽瑞尔、布隆、布兰德分别写一套语义。

## 本组已确认的实现导向

1. 标记不应被理解成一次性的布尔开关，而应被建成带 `来源 / 对象 / 持续时间 / 可消费条件 / 消费结果` 的目标级状态。
2. 叠层不应散落在各个技能里单独实现，而应统一落到目标级 stack 状态和阈值触发模板。
3. 命中消费型技能，应优先复用 `mark_consume` 或 `attach_proc` 这一类模式，避免在 bundle 编译层手工拼接。
4. 延迟爆炸和资源返还应作为标记状态的后续结果，而不是孤立的特判逻辑。
5. 阿卡丽 `E` 当前更适合拆成 `E1 / E2` 两个技能，`E2` 通过“存在标记”这一状态门槛解锁，语义上接近资源/状态约束。
6. 伊芙琳 `W` 当前优先保留“等待成熟后再命中消费”的主收益分支，提前打破印记的低收益分支先剪掉，不进入当前主建模。
7. 布隆 `震荡猛击` 与布兰德 `炽热之焰` 都应归到通用计数器机制，可与“每第三次攻击额外触发特效”类效果一起讨论，不单独发明新子系统。

## 当前判断

本组结论是：**可行，而且不会推翻前面的方向。**

第 1 组确认了比例与阈值类公式可覆盖，第 2 组确认了护盾 / 治疗 / 吸血的结果值串联可收口；本组进一步说明，`命中触发与标记结算` 的核心也能落到同一套状态与事件模型里。

真正需要提前加固的不是“有没有标记”，而是：

- 标记能否绑定目标
- 标记能否被后续命中消费
- 标记能否按时间阈值、层数阈值、击杀结果做分支
- 这些结果能否继续回流到伤害、控制、资源返还等后续效果
