范围约束：

- 只讨论 `1v1` 数值计算
- 跳过召唤物
- 地形、位移、范围、多目标只在必要时标记为“需转换”，不作为本组主结论
- 本组目标是验证“待人工归类”这一兜底桶里，哪些内容能直接收口到 V2，哪些内容本质上需要分类重拆或运行时特殊通道

## 本组 5 个样本

1. 英雄被动：费德提克 `巫骇草人`
2. 英雄被动：菲兹 `伶俐斗士`
3. 英雄被动：卡尔萨斯 `死亡契约`
4. 英雄被动：玛尔扎哈 `虚空穿越`
5. 英雄被动：纳亚菲利 `狂烈种群`

说明：

- 本组 5 个样本均取自 champion 入口，因为 `待人工归类` 桶里的 champion 入口已经足够覆盖这次分析。
- 这一组的重点不是“还原英雄百科”，而是判断这类条目到底是机制分组问题、运行时语义问题，还是 V2 数值能力问题。

## 样本 1：费德提克 `巫骇草人`

文本摘要：

- “费德提克的饰品会被替换为【草间人】。”

抽象机制：

- 这是一个 loadout / 物品槽位替换语义
- 其核心不是伤害、治疗、护盾或比例公式
- 更接近“单位初始化后，默认可用物品被替换”

映射到 V2：

- 不是典型 `deal_damage / modify_attribute / apply_shield` 问题
- 如果要覆盖，只能走“物品槽位或起始配置替换”的引擎层通道
- 对当前 `1v1` 数值引擎而言，它不是主算式的一部分

结论：

- **数值层：不构成阻塞**
- **运行时语义：需要过滤或单独建通道**
- **分类层：说明 `待人工归类` 里确实混入了非数值机制**

## 样本 2：菲兹 `伶俐斗士`

文本摘要：

- “菲兹在移动时可以穿过单位，并且从所有来源处受到的伤害都会减少一个固定的数额。”

抽象机制：

- 单位碰撞忽略
- 固定数值减伤
- 一个被动同时横跨空间语义和伤害修正语义

映射到 V2：

- 固定减伤可以抽象成 incoming damage modifier 或 flat reduction
- 单位穿过单位体积属于空间/碰撞语义，不是纯数值公式
- 在 `1v1` 口径下，后者应视为需转换或过滤

结论：

- **减伤部分：已接近可覆盖**
- **碰撞穿行部分：不属于当前数值主链路**
- **整体上更像“部分可收口 + 部分需转换”的混合条目**

## 样本 3：卡尔萨斯 `死亡契约`

文本摘要：

- “在死亡时，卡尔萨斯会化为一个灵体，能够继续施放技能。”

抽象机制：

- 死亡后仍存在可操作状态
- 死亡不是立即结束，而是切换到另一种 actor mode
- 这属于生命周期语义，不是数值结算语义

映射到 V2：

- 不是现有比例、阈值、护盾、治疗、吸血类能力
- 也不是普通的 buff / debuff 数值调整
- 如果要支持，必须引入 post-death actor state 或同类运行时模式

结论：

- **当前 1v1 数值引擎不应把它当作已覆盖能力**
- **这是本组最典型的“应过滤或单独建生命周期通道”的样本**
- **如果不拆出来，后续实现会把死亡后机制硬塞进数值链路**

## 样本 4：玛尔扎哈 `虚空穿越`

文本摘要：

- “玛尔扎哈如果近期没有受到伤害或控制效果，就会获得巨幅伤害减免和免疫控制的效果，并且这个效果在受到伤害后还会残留一小段时间。”

抽象机制：

- 基于“最近一段时间是否受伤 / 是否受控”的状态判定
- 命中前有一段防御窗口
- 命中后还有残留窗口
- 兼具触发源、持续时间和状态免疫

映射到 V2：

- 伤害减免本体可以收口到防御修正
- 免疫控制需要明确 status flag 或 effect gate
- “近期未受伤/未受控”需要事件驱动的时间窗，而不是简单数值公式

结论：

- **防御数值本体：部分可覆盖**
- **触发条件与残留窗口：需要显式时间窗模型**
- **它说明 `待人工归类` 里也包含一部分“能数值化，但不能只写公式”的条目**

## 样本 5：纳亚菲利 `狂烈种群`

文本摘要：

- “纳亚菲利生成狗群伙伴，它们会在她攻击或施放技能时攻击目标。”

抽象机制：

- 召唤 / 伙伴生成
- 伙伴随主人攻击或施放技能而联动
- 这属于伴随实体的攻击联动，而不是单一英雄的纯数值结算

映射到 V2：

- 召唤物 / 伙伴联动本身不属于当前 `1v1` 主算式主链路
- 即使未来支持，也应在独立的 summon / companion 模型里处理
- 不应把它硬折叠成普通英雄技能伤害公式

结论：

- **当前阶段应过滤**
- **它验证了 `待人工归类` 里确实混有召唤/伙伴类语义**
- **这类内容的正确处理方式不是补公式，而是拆分类边界**

## 本组汇总结论

### 已确认可支撑的能力

1. 固定数值减伤、持续时间窗口、状态免疫这类内容，V2 的数值和状态层可以承接一部分。
2. `待人工归类` 里并不是“缺一个统一数值节点”，而是混进了多种不同层级的语义。
3. 对于单纯的减伤和时间窗防御，现有 `damage modifier + timer + status` 的思路已经足够接近可实现。

### 本组暴露出的真实重点

1. **`待人工归类` 不是一个可直接实现的机制簇，而是分类兜底桶。**
2. 这里面至少混有四类不同语义：
   - `loadout / 饰品替换`
   - `空间碰撞 / 穿行`
   - `死亡后继续存在`
   - `召唤 / 伙伴联动`
3. 其中只有一部分能收进 V2 数值链路，剩下的必须走过滤、转换，或者独立的生命周期 / 召唤 / 配置通道。

### 本组建议收口的通用模板

1. `damage_reduction_window`
   - 输入：近期状态和时间窗
   - 输出：防御减免
2. `status_immunity_window`
   - 输入：状态 flag 和持续时间
   - 输出：控制免疫或同类防御
3. `post_death_actor_mode`
   - 输入：死亡事件
   - 输出：切换到死亡后可操作状态
4. `loadout_override`
   - 输入：英雄或单位初始化配置
   - 输出：替换默认饰品或默认道具
5. `companion_spawn`
   - 输入：攻击 / 技能联动
   - 输出：伙伴或召唤物行为

### 本组稳定结论

1. `待人工归类` 不是“下一步直接实现”的分组，而是“下一步继续拆分类边界”的分组。
2. 这一组里真正能和 V2 数值链路直接接上的，只是减伤、时间窗和部分状态修正。
3. 真正阻塞的是运行时语义边界，不是公式 AST。
4. 后续如果继续做 LoL 文本覆盖评估，`待人工归类` 应先再拆成更具体的子桶，再进入实现讨论。

## 本组已确认的实现导向

1. 对于 `费德提克 / 纳亚菲利` 这类非数值语义，优先按过滤或独立通道处理，不要硬塞进普通 combat formula。
2. 对于 `菲兹 / 玛尔扎哈` 这类带减伤和时间窗的条目，可以继续沿用“数值修正 + timer + 状态”模板。
3. 对于 `卡尔萨斯` 这类死亡后可继续行动的条目，应单独标记生命周期语义，避免被误并入当前 1v1 结算链。

## 当前判断

本组结论是：**可行，但它证明问题主要在分类层，不在 V2 数值层。**

换句话说，`待人工归类` 不应该被当作一个已收敛的机制组；它更像一批语义未分流的条目。V2 已经能接住其中的减伤和时间窗部分，但 loadout、召唤、死亡后态、碰撞穿行这些内容，必须先分流，再决定是否进入实现范围。
