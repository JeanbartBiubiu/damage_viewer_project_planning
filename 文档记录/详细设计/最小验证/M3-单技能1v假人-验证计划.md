# M3 单技能 1v 假人验证计划

关联文档：
1. `文档记录/概要设计/验证里程碑.md`
2. `文档记录/详细设计/验证计划编写说明.md`
3. `文档记录/详细设计/最小验证/M2-Action面板值对齐-验证计划.md`

## 1. 目标与绑定里程碑

目标里程碑：`M3 单技能 1v 假人`。

本计划只验证一个固定攻击方对固定假人释放一个主动技能后的最小结算闭环。M3 的主证据是 Wasm `done.actionResults[]`，用于解释施法是否被接受、公式输入与原始输出、最终伤害、资源变化、冷却变化和同输入可复现性。

M2 人工验收未完成时，M3 可以推进实现和验收准备，但不得把 M2 面板字段当作已通过前置，也不得宣布 M3 gate 已通过。

## 2. case 定义

caseId：`M3-single-skill-dummy-canonical-001`。

绑定对象：
1. 游戏：LoL 或当前发布 bundle 对应游戏。
2. 版本：执行时记录 `versionCode`、`dataHash`、wasm artifact sha256 或等价快照标识；没有真实快照时不得填写通过结论。
3. 攻击方：一个固定英雄，默认优先复用 M2 当前样本中的 Ahri。
4. 技能：一个固定主动技能，默认优先复用 `Q` 直伤技能。
5. 目标：固定假人或固定 enemy hero 模板；目标不主动行动。
6. 模式：训练模式或等价手工复核环境。
7. seed：固定为页面导出的 `runInput.seed`。
8. 装备：默认空数组；如为了补足 AP、资源或冷却证据加入装备，必须在 `case_meta` 中列出。
9. 等级：攻击方等级、目标等级、技能等级均由页面导出的 `case_meta` 固定。

## 3. 输入构造

输入来源：
1. Bundle 来自 `loadPublishedBundleSnapshot(apiBaseUrl, gameId)` 读取的已发布快照。
2. 页面入口：`#/wasm-validation-m3`。
3. 页面复用 `compileTinyGoV2ValidationInput(bundle, selection)` 构造 `engineBundle` 和基础 `runInput`。
4. M3 通过 `buildTinyGoV2SingleActionRunInput(...)` 把 `initialActions` 固定为一个动作：

```json
[
  {
    "triggerAtMs": 0,
    "sourceActorId": "self",
    "targetActorId": "enemy",
    "actionId": "<selected self actionId>"
  }
]
```

运行参数：
1. `stopCondition.maxEvents` 默认最小值为 `8`。
2. `trace.enableLogs` 为 `true`。
3. `trace.valueTrace` 为 `true`，但当前主证据仍以 `done.actionResults[]` 为准。

当前数据不足时允许最小补录技能字段，但补录范围只限 M3 canonical 需要的字段：`on_spell_cast -> deal_damage`、公式、技能等级、资源消耗、冷却、`damageType`、`sourceRole/targetRole`。

## 4. 游戏侧基线与证据来源

人工基线必须来自真实游戏侧证据，不得由开发侧伪造。

最少证据：
1. 训练模式或等价环境的版本截图。
2. 攻击方英雄、等级、装备、技能等级截图。
3. 目标假人或固定目标的施法前生命值截图。
4. 施法后目标生命值截图。
5. 施法前后攻击方资源值截图。
6. 施法后技能冷却或可再次施放时间截图。

OCR 只能作为辅助抽取，最终字段仍需人工复核。若某字段无法从截图或人工记录中确认，验收状态必须写 `missing_evidence`。

## 5. Wasm 输出字段与对照关系

本计划实际消费的 Wasm 输出：
1. `done.stopReason`：运行停止原因。
2. `done.processedEvents`：处理事件数。
3. `done.actionResults[0].accepted`：施法是否被接受。
4. `done.actionResults[0].blockedReason`：未被接受时的阻塞原因。
5. `done.actionResults[0].effects[].formulaId`：本次 effect 实际使用的公式。
6. `done.actionResults[0].effects[].formulaBreakdown`：公式分解证据。
7. `done.actionResults[0].effects[].rawAmount`：公式原始输出。
8. `done.actionResults[0].effects[].damageType`：伤害类型。
9. `done.actionResults[0].effects[].finalDamage`：最终扣血量。
10. `done.actionResults[0].effects[].targetHpBefore/targetHpAfter`：目标施法前后生命值。
11. `done.actionResults[0].resourceDeltas[].before/after/delta`：资源前后值与变化。
12. `done.actionResults[0].cooldownBefore/cooldownAfter`：施法前后冷却状态。
13. `done.actors[]`：最终 actor snapshot，用于复核目标 HP 和资源状态。

M1 `snapshot` 和 M2 `action_snapshot` 可作为辅助回扣证据，但不能替代 M3 的 `done.actionResults[]`。

## 6. 验收表结构

验收表最少列固定为：

| 列 | 含义 |
| --- | --- |
| `field` | 字段路径，例如 `effect.0.finalDamage`。 |
| `wasmValue` | Wasm 实际输出值。 |
| `baselineValue` | 游戏侧人工基线值。 |
| `tolerance` | 允许误差。 |
| `status` | `match`、`diff`、`low_confidence`、`missing_evidence`。 |
| `evidenceRef` | 截图、页面导出、JSON path 或人工记录索引。 |
| `note` | 归因、显示口径或待复查说明。 |

M3 第一张表必须至少覆盖：
1. `action.accepted`
2. `effect.0.formulaId`
3. `effect.0.rawAmount`
4. `effect.0.finalDamage`
5. `effect.0.targetHpBefore`
6. `effect.0.targetHpAfter`
7. `resource.<resourceId>.delta`
8. `cooldown.after.readyAtMs`
9. `run.stopReason`

## 7. 通过标准

通过不是零 diff。通过标准是主证据字段没有未解释的阻塞级 `diff`。

规则：
1. 主证据字段不得存在未解释 `diff`。
2. 已归因、已登记、当前不阻塞的差异可以保留，但必须写进 `note`。
3. `low_confidence` 和 `missing_evidence` 不能伪装为通过。
4. 如果没有真实游戏截图或人工基线，只能判定“实现推进完成 / 验收准备就绪”，不能判定 M3 gate 通过。
5. M2 面板字段仍未人工确认时，M3 计划必须保留依赖说明，不得把 M2 当作已通过。

## 8. 升级规则

出现以下情况时升级人工复核或回到开发排查：
1. 同一 `case_meta` 下 Wasm 输出不可复现。
2. `action.accepted=false` 且无法解释阻塞原因。
3. 公式 raw 输出与 M2 面板预期不一致，且无法判断是 M2 数据问题还是 M3 runtime 问题。
4. 游戏侧显示值无法区分 raw damage、最终扣血、护盾吸收或显示取整。
5. 资源或冷却字段缺少游戏侧证据。
6. Web adapter 把英雄、等级、装备、技能等级、版本或 actionId 映射错。

## 9. 验收 sub agent 输入包

验收 sub agent 必须拿到：
1. `case_meta`：英雄、等级、技能等级、装备、模式、seed、`versionCode`、`dataHash`、wasm sha256。
2. `wasm_output`：页面导出的 `done` JSON，至少包含 `actionResults`。
3. `baseline_input`：人工基线表、OCR 结果或截图抄录值。
4. `evidence_index`：截图路径、时间点、对应字段说明。

可自动生成：
1. `case_meta` 中的 gameId、versionCode、dataHash、actionId、skillId、skillLevel、seed。
2. `wasm_output` 和字段级证据表。

必须人工补：
1. 游戏客户端版本和训练环境。
2. 游戏侧截图/OCR/人工记录。
3. 对 `diff`、`low_confidence`、`missing_evidence` 的最终复核。

## 10. 交付物

1. M3 验证计划。
2. `#/wasm-validation-m3` 页面。
3. 页面导出的 `case_meta + runInput + wasm_output + evidenceRows`。
4. Wasm `done.actionResults[]` DTO。
5. Go runtime 测试。
6. Web build 验证。
7. 单独测试记录，放在 `文档记录/测试记录/wasm/`。

## 11. 非目标

1. 不验证完整 1v1。
2. 不验证敌方 AI 或自动循环释放。
3. 不验证多技能连招。
4. 不验证 DoT、HoT、多段伤害、护盾、治疗、标记、条件命中、触发链、历史窗口、计数器、模式强化。
5. 不验证暴击、随机命中、控制、打断或复杂 action gate 组合。
6. 不验证全量英雄、装备、符文、技能覆盖。
7. 不把 M2 未完成人工验收的字段伪装成 M3 已通过前置。
