# M4 闭环验证页开发计划

## 目标

在 `C:\project\damage_web_dev\web` 新增独立页面 `#/wasm-validation-m4-closure`，用于闭环验证 M4 剩余页面能力缺口：

- `initialHp`：页面能设置受损初始血量，不改英雄基础数值。
- `multi-action`：页面能按固定 preset 执行多段 action 时序。
- `seed`：页面能固定随机种子并展示 `done.rng`。
- `modeAugments`：页面能传入 `runInput.modeAugments` 并对比 normal / augment 输出。
- `shield absorb`、`heal/hot applied`、`mark consume true`、`history window`、`counter read`：页面能从 `done.actionResults`、`done.tickResults` 和 `done.actors` 提取闭环字段。

## 复用约束

- 通过 `loadPublishedBundleSnapshot(apiBaseUrl, gameId)` 读取 published bundle。
- 通过 `compileTinyGoV2ValidationInput(bundle, selection)` 生成 `engineBundle` / `runInput` 基线。
- 通过 `TinyGoV2Bridge.init()`、`beginRun()`、`step()` 执行 Wasm。
- 通过 `JsonBlock` 展示 `runInput`、`done payload` 和可复制验收包。
- 不做通用战斗编排器，只实现固定 preset。
- 页面不注入隐藏 debug action，不私造 current bundle 中不存在的技能。

## 输入构造策略

1. 每个 preset 固定 `selfHeroId`、`enemyHeroId`、等级、技能等级、属性覆盖和资源覆盖。
2. 先调用 `compileTinyGoV2ValidationInput` 取得完整动作、公式和状态。
3. 对返回值做页面内最小 patch：
   - `engineBundle.actors[].initialHp` 用于受损初始血量。
   - `runInput.seed` 用于 seed 分支。
   - `runInput.modeAugments` 用于 KSante All Out 对比。
   - `runInput.initialActions` 用固定 action 列表表达 multi-action。
   - `runInput.stopCondition.maxEvents` 按 preset 放大，保证 tick/history/action 全部处理。
   - `runInput.trace.enableLogs=true`、`valueTrace=true` 便于证据输出。
4. action 必须来自 compiled `engineBundle.actions`。找不到任一必需 action 时，该 preset 标记为 `blocked`，并显示缺失技能/发布前置。

## 页面输出

页面需要按 preset 展示：

- run 状态：`ready` / `passed` / `failed` / `blocked` / `error`。
- `accepted`：每个 action 的 accepted/blockedReason。
- 关键 effect：`kind`、`finalDamage`、`shieldAbsorbed`、`healApplied`、`counterBefore/After`、`modeActive`、`historyWindowMs`、`critRoll/critResult`。
- HP/resource/cooldown：actor HP、shield、resource deltas、cooldown before/after。
- rng/mode：`done.rng`、`runInput.seed`、`runInput.modeAugments`。
- copy package：`case_meta`、`runInput`、`wasm_output`、`assertions`。

## 实现补充

- `modeAugments` 需要贯穿 `TinyGoV2RunInput` 到 `runInput.modeAugments`，页面只负责传入 preset 固定值。
- `counter` 读取需要把 published bundle 原始参数中的 counter 变量编译为 `{ op: "counter", counter: counterKey }`，再由公式编译器识别。
- `shieldKind` 兼容应放在 TinyGo runtime 侧兜底；published bundle 可能提供 `magic_shield` / `physical_shield`，运行时匹配伤害类型时应归一为 `magic` / `physical`，避免页面或 adapter 为单一来源做特例。

## blocked 规则

页面只消费 current published bundle。任一 preset 的必需 hero 或 skill 不存在时：

- 不在页面创建本地 action、formula 或隐藏 debug skill。
- 不调用 Wasm 运行该 preset。
- 输出 `blocked`，列出缺失项和需要先补 DB/发布的说明。
- 特别是 `skill_vayne_w_counter_read` 不存在时，`M4.18 counter read` 必须保持 blocked。
