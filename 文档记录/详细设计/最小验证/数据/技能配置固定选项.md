# 技能配置固定选项

## 1. 目的
这份文件只解决一件事：把当前 `mvp_skill_v2` 结构里哪些字段应该做成“选择”，哪些字段必须“手填”先分清。  
后面做前端配置页时，优先以这里的输入方式为准，避免把本来应该下拉或引用选择的字段做成自由文本。

当前建议把输入方式分成 6 类：

- `single_select_fixed`：固定单选，下拉选 code。
- `multi_select_fixed`：固定多选，多选 code。
- `single_select_dictionary`：不是手填，从外部字典或实体列表选。
- `single_select_local_ref / multi_select_local_ref`：不是手填，从当前 skill 内部已定义的 key 引用。
- `boolean_switch`：布尔开关。
- `manual_*`：手填，按文本 / 数字 / 公式 / 备注分别处理。

## 2. 直接做固定下拉

### 2.1 基础信息
| 字段 | 输入方式 | 当前 code | 说明 |
| --- | --- | --- | --- |
| `ownerType` | `single_select_dictionary` | `hero`（英雄）, `item`（装备） | 当前 MVP 只用到这两个，后续应从 `owner_categories` 字典加载。 |
| `skillKey` | `single_select_fixed` | 英雄：`A`（普攻）, `P`（被动）, `Q`（Q 技能）, `W`（W 技能）, `E`（E 技能）, `R`（R 技能） | 英雄技能建议固定下拉。 |
| `skillKey` | `single_select_fixed` | 装备：`passive_1`（被动 1）, `passive_2`（被动 2）, `active_1`（主动 1） | 装备技能先按这一组做。后续若有更多被动位可扩展。 |

### 2.2 数值定义
| 字段 | 输入方式 | 当前 code | 说明 |
| --- | --- | --- | --- |
| `resourceCosts[].kind` | `single_select_fixed` | `const`（固定值）, `table`（等级表）, `formula`（公式） | 当前资源消耗只建议开放这 3 种。 |
| `cooldowns[].kind` | `single_select_fixed` | `const`（固定值）, `table`（等级表）, `formula`（公式） | cd 录入和资源消耗同一套。 |
| `params.vars[].kind` | `single_select_fixed` | `const`（固定值）, `table`（等级表）, `scaled_attr`（属性缩放）, `formula`（公式变量）, `mapping_scaled_attr`（映射属性缩放） | 这几个 code 已经在当前 JSON 里实际用了。 |
| `params.vars[].by` | `single_select_fixed` | `skillLevel`（技能等级）, `championLevel`（英雄等级） | 只在 `table` 这类按等级取值时出现。 |

### 2.3 时序
| 字段 | 输入方式 | 当前 code | 说明 |
| --- | --- | --- | --- |
| `timingProfile.phases[].kind` | `single_select_fixed` | `cast`（施法/前摇）, `channel`（引导）, `recovery`（后摇）, `persistent_effect`（持续效果） | phase 类型固定下拉。 |

### 2.4 mechanicsConfig
| 字段 | 输入方式 | 当前 code | 说明 |
| --- | --- | --- | --- |
| `mechanicsConfig.triggers[].event.type` | `single_select_fixed` | `on_spell_cast`（施放技能）, `on_basic_attack_hit`（普攻命中）, `on_damage_dealt`（造成伤害后）, `on_damage_taken`（受到伤害后）, `on_tick`（tick 触发）, `on_stack_change`（层数变化） | 这是当前 MVP 建议先开放的稳定事件。 |
| `mechanicsConfig.triggers[].actions[].type` | `single_select_fixed` | `deal_damage`（造成伤害）, `apply_modifier`（施加属性修正）, `add_stack`（增加层数）, `remove_stack`（移除层数）, `schedule_tick`（安排 tick）, `if`（条件分支） | 这是当前 MVP 建议先开放的动作。 |
| `damage.source` | `single_select_fixed` | `self`（自身）, `owner`（归属者） | 当前 damage source 先固定这两个。 |
| `damage.target` | `single_select_fixed` | `enemy`（敌方） | 当前 `deal_damage` 先只开放敌方目标。 |
| `damage.damageType` | `single_select_fixed` | `physical`（物理）, `magic`（魔法）, `true`（真实） | 伤害类型固定下拉。 |
| `modifier.target` | `single_select_fixed` | `self`（自身）, `enemy`（敌方） | modifier 目标当前先做这两个。 |
| `modifier.stats[].op` | `single_select_fixed` | `add`（加法叠加）, `mul`（乘法修正） | 属性修正操作固定下拉。 |
| `modifier.stacking.mode` | `single_select_fixed` | `refresh`（刷新）, `stack`（叠加） | 当前堆叠模式先做这两个。 |

## 3. 固定多选
| 字段 | 输入方式 | 当前 code | 说明 |
| --- | --- | --- | --- |
| `stacks[].resetOn` | `multi_select_fixed` | `combat_end`（战斗结束）, `timeout`（超时） | 可以做多选。若都不选，表示默认不自动清空。 |

## 4. 从字典或上下文里选，不要手填

### 4.1 外部字典选择
| 字段 | 输入方式 | 来源 | 说明 |
| --- | --- | --- | --- |
| `ownerId` | `single_select_dictionary` | 根据 `ownerType` 从英雄/装备列表选 | 不建议手敲字符串。 |
| `params.vars[].attr` | `single_select_dictionary` | 属性字典 | 例如 `self.ability_power`（自身法强）、`target.hp_current`（目标当前生命）。 |
| `params.vars[].selector` | `single_select_dictionary` | 运行时 selector 字典 | 当前示例里用到了 `self.profession`（自身职业/近战远程标签）。 |
| `modifier.stats[].key` | `single_select_dictionary` | 属性字典 | 例如 `attack_speed_ratio`（攻速比例）、`move_speed_bonus_from_base`（基于基础移速的加成）。 |

### 4.2 当前 skill 内部引用
| 字段 | 输入方式 | 来源 | 说明 |
| --- | --- | --- | --- |
| `params.vars[].formulaVars` | `multi_select_local_ref` | 当前 `params.vars` keys | 只允许引用当前 skill 已定义变量。 |
| `mechanicsConfig.triggers[].event.stackId` | `single_select_local_ref` | `mechanicsConfig.stacks[].id` | `on_stack_change` 必须引用已有 stack。 |
| `mechanicsConfig.triggers[].event.tickKey` | `single_select_local_ref` | 当前 skill 已声明/约定的 `tickKey` | 最好不要手敲重复字符串。 |
| `actions[].stackId` | `single_select_local_ref` | `mechanicsConfig.stacks[].id` | `add_stack/remove_stack` 必须引用已有 stack。 |
| `mvpExtensions.attackInteraction.resetStacksAfterTrigger[]` | `multi_select_local_ref` | `mechanicsConfig.stacks[].id` | 这类重置栈 id 应该直接多选。 |

## 8. 当前标准里“先别做正式下拉”的预留 code
下面这些 code 在 wasm 设计里出现过，但当前最小验证先不要默认开放到页面主流程里，最多放 `experimental`：

### 8.1 预留 TriggerEvent
- `on_heal_done`（造成治疗后）
- `on_heal_taken`（受到治疗后）
- `on_shield_gain`（获得护盾）
- `on_shield_break`（护盾被击破）
- `on_shield_expire`（护盾过期）
- `on_cast_blocked`（施法被阻止）
- `on_disrupt`（发生扰乱）
- `on_interrupt`（被打断）
- `on_channel_start`（引导开始）
- `on_channel_end`（引导结束）
- `on_status_gain`（获得状态）
- `on_status_expire`（状态过期）
- `on_status_cleanse`（状态被净化）

### 8.2 预留 ActionNode
- `deal_heal`（造成治疗）
- `apply_shield`（施加护盾）
- `remove_shield`（移除护盾）
- `apply_status`（施加状态）
- `remove_status`（移除状态）
- `cleanse_status`（净化状态）
- `apply_control_directive`（施加强制行为/位移指令）
- `disrupt_execution`（扰乱当前执行）
- `start_channel`（开始引导）
- `cancel_execution`（取消执行）

## 9. 页面实现时的最小建议
- 固定 code 一律不要做自由文本输入。
- 能从外部字典拿的字段不要手填，例如 `ownerId`、`attr`、`stat.key`。
- 能从当前 skill 内部引用的字段也不要手填，例如 `formulaVars`、`stackId`、`tickKey`。
- 当前还没有强约束 ExprNode 的地方，先保留 `formulaText`，但一定要配本地引用选择器，别让用户盲写变量名。
