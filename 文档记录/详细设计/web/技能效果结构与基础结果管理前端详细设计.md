1. 当前“技能管理”页面已经提供技能查询和基本资料操作，并通过“参数与公式”弹窗维护同一技能的参数与公式。

## 3. 类型与客户端

### 3.1 强类型

`web/src/types/skillEffect.ts` 定义：

1. `SkillEffectSummary`、`SkillEffect`
2. `SkillEffectResultType`、`SkillEffectTarget`
3. `SkillEffectValueRule`
4. 七种结果各自的 `detail` 类型
5. 以 `resultType` 为判别字段的 `SkillEffectResult` 联合类型
6. `CreateSkillEffectRequest`、`UpdateSkillEffectRequest`
7. 对应创建和更新的结果联合类型

联合类型必须保证：

1. 伤害、属性变化、资源变化、冷却变化和状态操作只能访问自己的明细字段。
2. 直接治疗和普通护盾的 `detail` 是空对象。
3. 状态操作和冷却重置不携带数值规则；其余数值结果必须携带数值规则。
4. `UpdateSkillEffectRequest` 不包含 `effectKey`。

不得使用 `Record<string, unknown>`、任意配置对象或与旧 combat-data effect detail 共用类型。

### 3.2 客户端

`skillEffectClient.ts` 提供：

1. `listSkillEffects`
2. `getSkillEffect`
3. `createSkillEffect`
4. `updateSkillEffect`
5. `deleteSkillEffect`

所有游戏、技能和效果路径片段使用 `encodePathSegment`，所有请求使用现有 `requestJson` 和 Admin Token。客户端不展开、执行或归一化公式；只传递共享契约中的强类型聚合。

## 4. 文件与组件

`web/src/pages/admin/skills/effects/**` 包含：

1. `SkillEffectManagementModal.tsx`：当前技能的效果列表、加载、删除和效果编辑入口。
2. `SkillEffectEditorModal.tsx`：新建、查看和编辑一个完整效果聚合。
3. `SkillEffectResultEditorModal.tsx`：只编辑效果草稿中的一个结果，不直接请求后端。
4. `effectForm.ts`：草稿、规范化、强类型请求构建、目录引用保留和服务端字段错误映射。
5. `effectForm.test.ts`：纯函数单元测试。

三个弹窗延续当前参数/公式弹窗的同级受控状态模式，不建立通用 CRUD 框架。结果编辑弹窗保存时只更新父效果的本地草稿；只有效果编辑弹窗的“保存”才调用效果聚合接口。

## 5. 技能页入口

1. `SkillManagementPage` 在每个技能操作区增加“效果与结果”。
2. 点击后保存当前 `Skill` 作为 `effectTarget`，打开 `SkillEffectManagementModal`。
3. 切换游戏、技能被删除或收到 `404.SKILL_NOT_FOUND` 时关闭效果相关全部弹窗，清空草稿、错误和旧请求序号，再刷新技能列表。
4. 不修改“参数与公式”现有名称、弹窗和行为，不把两个入口强行合并成新的产品名称。
5. 不增加导航项、路由分支或页面教学文案。

## 6. 效果管理弹窗

标题固定为“效果与结果 - {技能名称}”。列表列为：

1. 效果名称
2. 稳定标识
3. 结果数量
4. 排序
5. 更新时间
6. 操作

行为如下：

1. 打开时加载效果摘要；空列表显示“暂无效果”。
2. 操作提供“查看”“编辑”“删除”，顶部提供“新增效果”和“刷新”。
3. 删除使用组件库默认确认弹窗；成功后关闭确认并刷新，失败保留确认和错误。
4. 列表请求使用递增序号，旧请求不能覆盖切换技能或刷新后的新结果。
5. 列表失败不关闭弹窗，显示可重试错误；不会用旧列表伪装成功。

## 7. 效果编辑弹窗

### 7.1 效果资料

新建字段：效果标识、效果名称、说明、排序。编辑时效果标识只读；查看模式全部只读。

效果编辑弹窗同时展示结果草稿表格，列为：

1. 结果名称
2. 稳定标识
3. 结果种类
4. 作用对象
5. 关键引用摘要
6. 排序
7. 操作

结果按 `sortOrder/resultKey` 排序显示。新建和编辑模式提供“新增结果”“查看”“编辑”“删除”；查看模式只提供“查看”。

### 7.2 聚合草稿

1. 新建效果从空结果草稿开始，但至少增加一个有效结果后才能提交。
2. 编辑先读取效果详情，再将完整结果转换为本地草稿；详情未成功加载前不能保存。
3. 新增、编辑和删除结果都只更新本地数组；结果稳定标识在草稿内实时去重。
4. 保存时按当前显示顺序构建完整 `results` 数组，但后端顺序仍以显式 `sortOrder/resultKey` 为准。
5. 保存成功关闭效果编辑弹窗并刷新效果摘要；保存失败保留效果资料、全部结果草稿和当前字段错误。
6. 点击遮罩或按 Esc 关闭时直接丢弃整个效果草稿，不额外增加二次确认；同时清除页面未保存状态。
7. 编辑期间通过现有 `onDirtyChange` 方向向页面报告未保存状态，不引入新的全局状态容器。

## 8. 结果编辑弹窗

### 8.1 公共字段

结果编辑器展示：

1. 结果标识
2. 结果名称
3. 结果种类
4. 作用对象
5. 排序
6. 说明

创建时结果种类可选；编辑已有结果时结果标识和结果种类只读。结果种类显示中文：伤害、直接治疗、普通护盾、属性变化、资源变化、冷却变化、状态操作。

作用对象显示“施法者 / 当前目标”，不出现事件来源目标。

### 8.2 数值规则

需要数值的结果显示：

1. 数值公式
2. 固定倍率
3. 固定最小值
4. 固定最大值

公式使用同一技能公式下拉选择；倍率默认 1。前端校验非负倍率和最小值不大于最大值。页面不嵌入公式表达式编辑器，也不显示计算结果。

冷却重置隐藏并清空数值规则。状态操作按状态目录的种类决定是否显示强度，具体规则统一见[普通减速共享契约](../项目/系统精简实施说明.md#第四单元状态身份与普通减速强度)；目录未就绪时不能提交依赖它的结果。减少或增加冷却时在字段标签附近明确写“变化量按毫秒解释”，不新增单位选择。

### 8.3 类型专属字段

1. 伤害：伤害类型。
2. 直接治疗、普通护盾：无额外字段。
3. 属性变化：属性和“增加 / 减少 / 覆盖”。
4. 资源变化：资源属性和“恢复 / 扣除 / 返还”。
5. 冷却变化：受影响技能和“减少 / 增加 / 重置为可用”。
6. 状态操作：状态和“施加 / 移除”。

切换新建结果种类时，必须清空上一种类专属字段和不再适用的数值规则，不能把隐藏草稿带入请求。页面不显示斩杀、反伤、过程、生命周期、条件、事件、暴击、吸血或前序结果选项。

## 9. 目录加载与停用引用

1. 效果编辑器缓存当前技能的公式目录；结果编辑器按所选种类按需加载伤害类型、属性、技能或状态目录，避免无关目录失败阻塞只读查看。
2. 每类目录加载使用独立请求序号；切换结果种类或关闭弹窗后，旧请求不得覆盖新种类目录。
3. 新建结果只显示启用伤害类型、属性、技能和状态；冷却变化的受影响技能选择器始终额外保留当前父级技能，即使父级技能已停用，并标记“当前技能（已停用）”。其他停用技能不提供为新选项。公式没有启停状态，显示同技能全部公式。
4. 编辑已有结果时，如果当前引用已经停用，选择器保留该项并显示“已停用”；用户可原样保留或换成启用项。
5. 目录中找不到已有引用时仍用稳定标识兜底显示，但编辑保存被禁用，并显示目录不完整错误，防止误覆盖未知引用。
6. 某类目录加载失败只阻止新增或编辑依赖该目录的结果；不影响效果列表、效果只读详情和其他不依赖该目录的结果种类。
7. 任何目录都通过现有客户端读取，不在页面硬编码物理、魔法、真实伤害、生命值、法力值或状态记录。

## 10. 表单校验与错误映射

`effectForm.ts` 负责：

1. 去除稳定标识、名称和说明首尾空白，空说明转 null。
2. 校验效果和结果稳定标识、名称、说明、非负整数排序和结果键去重。
3. 校验至少一个结果、结果种类与明细互斥、数值规则必填或必须为空。
4. 校验固定倍率、固定最小值和固定最大值。
5. 构建七种强类型请求，不把隐藏字段或目录展示对象提交给后端。
6. 把 `details.fieldIssues` 映射到效果字段或 `results[index]` 对应的结果草稿；无法定位的问题显示在效果弹窗顶部。

服务端返回数组下标时，映射以本次实际提交数组为准。结果弹窗已经关闭时，错误仍在父级结果行显示摘要；用户重新打开该结果即可看到字段错误。前端不得解析数据库原文或中文消息判断错误种类。

## 11. 弹窗与页面行为

1. 效果列表、效果编辑、结果编辑和删除确认都使用 Arco 默认 Modal。
2. 不覆盖弹窗边框、阴影、定位或建立新的全局宽度样式。
3. 打开子弹窗时父级草稿保持不变；关闭子弹窗不触发后端保存。
4. 保存进行中禁用重复提交和关闭动作；请求结束后按成功或失败规则恢复。
5. 页面不显示用途说明、阶段说明、设计边界教学或后续功能占位。
6. 缺少游戏或 Admin Token 时沿用现有功能性警告，不新增产品术语。
