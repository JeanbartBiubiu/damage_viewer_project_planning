## 1. 当前前端事实

前端现有页面由 `web/src/pages/admin/combat-data/resourceRegistry.ts` 驱动，直接暴露属性 Key、值种类、比率目标、资源初始值和资源上限等底层字段。该页面是通用表编辑器，不是围绕录入者业务组织的属性管理页面。

现有属性/资源请求走 `/api/admin/games/{gameId}/combat-data/**`。本任务不得修改 `combatDataClient.ts` 来维持新页面，也不得回退调用旧属性/资源接口。

## 2. 路由与导航

新增主路由：

```text
#/attributes
```

主导航使用中文「属性管理」。为避免新旧作者入口同时写不同表，本轮采用以下唯一策略：

1. `navigationGroups` 不再展开 `combatDataNavGroups`，整个旧 `combat-data` 通用工作台从侧栏退出。
2. `entity-growth` 从静态路由集合和数据管理导航移除。
3. `App.tsx` 不再渲染 `CombatDataPage` 或 `EntityGrowthPage`，产品路由入口也不再调用 `readCombatDataLocation`、默认资源重定向或非法 filter 规范化逻辑。
4. `#/combat-data/**`、`#/admin/**`、`#/entity-growth` 保留浏览器原 hash，但页面内容按现有未知路由行为回到总览；不得通过 `replaceState` 或赋值 hash 改写地址。
5. 不新增未找到页面，也不把旧 URL 重定向到 `#/attributes`。
6. `COMBAT_DATA_RESOURCE_LIST`、`resourceRegistry.ts`、`resourceRelations.ts`、`combatDataNav.ts` 和 `combatDataClient.ts` 保持冻结，避免本轮触碰旧计算读取和 lookup 合同。
7. `ImagesPage.tsx` 移除属性图片绑定说明；属性图片关系已经后置，不链接新属性页。
8. `EntitySetupPage.tsx` 移除实体成长、通用实体表和旧属性定义链接，不用新属性页伪装尚未建设的角色属性关系。

其他冻结页面若仍含 `#/combat-data/**` 链接，点击后按上述规则回到总览；其文案清理由对应业务阶段处理，本轮不得据此扩大写入范围。

因此「旧页面退出」验收的是主导航不可见、App 不再进入旧工作台和旧地址回到总览，不是 registry 行被删除，也不是独立 404 页面。

## 4. 页面布局

页面由三个区域组成：

1. 页面标题和说明：明确「这里只定义属性，不录入角色、装备或能力数值」。
2. 查询区：关键词、状态、查询、重置。
3. 表格区：新增、刷新、属性列表和操作列。

表格列：

1. 属性名称
2. 稳定标识
3. 数值类型
4. 有效范围
5. 状态
6. 排序
7. 更新时间
8. 查看/编辑

当前不分页。空数据时显示「暂无属性，可以新增第一条属性」，不显示资源创建引导。

类型、表格和编辑弹窗均不得包含显示单位字段。页面不提供默认值、比率目标、图片关联、资源初始值、资源上限或计算公式字段。

## 5. 编辑弹窗与交互

弹窗支持新增、查看、编辑三种模式：

1. 新增时稳定标识可编辑。
2. 编辑时稳定标识锁定。
3. 查看时全部只读。
4. 保存成功后关闭弹窗、重新请求列表，并重新选中保存记录。
5. 保存失败时弹窗保持打开，用户草稿不丢失；保存中禁用重复提交，请求完成后恢复。
6. 共享契约中的 `fieldIssues` 映射到对应表单字段；非字段错误显示在弹窗顶部。
7. 关闭、取消、切换路由或刷新页面时，若表单已修改且未保存，必须二次确认。未保存提醒覆盖 `beforeunload` 和 hash 路由切换；确认离开后才允许更新 hash。
8. 页面从 `App.tsx` 接收现有 `apiBaseUrl`、`selectedGameId` 和 `adminToken`；不得自行建立第二套全局状态。

页面组件本身不新增 Vitest 渲染测试。表单规范化、脏状态判断和字段问题映射提取为 `attributeForm.ts` 纯函数并由 `attributeForm.test.ts` 覆盖；真实弹窗、保存和路由行为由 `non-wasm-pages.spec.ts` 覆盖。
