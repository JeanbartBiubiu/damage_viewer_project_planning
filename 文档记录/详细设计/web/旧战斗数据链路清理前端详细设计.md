## 1. 当前仓库事实

1. 当前主导航同时展示阶段 0～7.4 的管理页面和 Provider、Ability、Effect Sequence、Effect Step、直伤技能等旧入口。
2. 除可见旧入口外，仓库还保留旧实体、实体成长、实体挂载、通用战斗数据工作台、旧发布和旧 Wasm 验证页面。
3. 旧页面依赖 `combatDataClient`、`combatDataLoader`、`combatDataCache`、旧类型、旧图片引用组件和 `combatDataAssembler`，与当前阶段 0～7.4 管理客户端是两套链路。
4. 当前管理页面没有使用 `GET /api/games` 返回的旧 `progressionSchema`；等级范围由游戏配置页面及当前等级配置接口维护。
5. 图片管理页面和浏览器图片缓存仍是当前功能，需要保留；其中指向旧实体或旧战斗数据页面的文案和链接需要删除。
6. `WasmValidationGenericPage` 和 `wasm-generic.spec.ts` 依赖旧战斗数据装配。本次删除页面和验证宿主，但不修改底层 Wasm 资源、桥接和工作线程。

## 2. 前端职责

1. 删除全部旧页面、旧导航项和旧 Hash 路由。
2. 删除仅为旧后端接口服务的客户端、类型、缓存、加载器、图片引用和数据装配代码。
3. 删除旧版本发布和旧 Wasm 验证入口，不设计替代页面。
4. 保留当前阶段 0～7.4 管理页、图片管理页和底层 Wasm 文件。
5. 把游戏摘要类型与后端精简响应同步，并更新受影响测试和说明。
6. 用静态检查、完整前端验证和桌面浏览器冒烟证明没有旧入口和旧网络请求。

## 13. 前端停止条件

1. 任一当前阶段 0～7.4 页面仍需要旧 `combatData` 类型、客户端或数据装配器才能工作。
2. `OverviewPage` 实际已承载当前业务功能，不能按候选清单直接删除。
3. 底层 Wasm 桥接或工作线程直接依赖待删除装配器，删除会改变 Wasm 接口或运行时。
4. 当前页面仍实际消费后端游戏摘要中的 `progressionSchema`。
5. 图片管理必须依赖旧实体或旧战斗数据接口才能完成当前功能。
6. 发现与本任务交叉的未提交改动，且无法在不覆盖用户工作的前提下完成。
7. 删除旧路由导致当前管理页行为变化，且无法用定点调整解决。

遇到停止条件时保留现场并报告，不增加兼容层、不重写 Wasm，也不扩大到当前业务页面重构。
