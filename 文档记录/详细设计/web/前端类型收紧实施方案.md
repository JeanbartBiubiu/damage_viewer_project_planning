# 前端类型收紧实施方案

## 1. 目标与范围

恢复关键数据流的编译检查：过程规则进入装配后保留规则、事件和动作的具体类型，页面选项进入草稿或计算计划时保留业务枚举及数组元素类型。收益是更早发现字段拼写、错误枚举和不合适的赋值；不以运行性能提升作为验收目标。

本轮聚焦第3节列出的3个引擎适配文件和5个页面。复用现有业务类型，不新增兼容层，不拆分模块，不改后端接口、Wasm运行协议、数值语义或正式产物。全仓推导出的 `any` 不要求清零，未使用的表格占位参数、校验边界内的临时变量和测试样例复制暂不专项处理。

推导退化主要有两种来源：组件库的回调参数本身声明为 `any`；原生数组检查 `Array.isArray` 将只读数组 `readonly T[]` 收窄为 `any[]`，使后续泛型推导丢失元素类型。606处不是606个独立缺陷，也不作为固定整改数量。

优先使用局部显式泛型、具体类型的局部变量，或不污染原类型的形状检查。仅在本轮确有重复时提取最小辅助函数，不建立通用校验框架。对于尚未校验的外部值，先按 `unknown` 或 `unknown[]` 校验，再产生业务类型。

保留现有数组形状、规则数量、标识、数值、引用、循环和枚举检查及错误路径；不得因静态类型存在而删除运行时检查。稳定排序继续复制数组，保留只读约束和同序号规则的既有顺序。

回调参数、选项数组和目标字段复用同一业务类型。键集合保持字符串数组；单选枚举保持现有联合类型；允许清空的字段沿用现有空字符串、空数组或空值约定。保留未保存草稿、确认与取消、切换清理和只读规则。

给回调补具体类型时同步核对选项值，不能只把回调值断言成目标类型。确实需要解析未知值时复用既有校验和合法值范围；若必须改变现有拒绝、默认值或清空行为，先报告业务影响，不把行为变化混入类型优化。

表格中未使用的占位参数保留；行类型已通过数据或泛型正确推导时不重复整改。本轮只处理实际进入业务状态、计算计划或展示模式的选定回调，不以消除全部页面计数为目标。
