# 技能参数与公式管理前端详细设计

方案版本：`skill-parameter-formula-management-v4-frozen`

方案状态：已按冻结版本完成实现，并于 2026-08-27 通过自动检查和真实前后端浏览器验收。

本文实施[技能参数与公式管理共享契约](../项目/技能参数与公式管理详细设计.md)。公共字段、接口、错误、属性取值方式、等级调整和跨端验收只以共享契约为准，本文只负责页面入口、交互状态、客户端转换和前端验证。

## 1. 页面职责

1. 在现有“技能管理”页面进入一个技能的参数与公式管理。
2. 展示和维护固定参数、技能等级参数、角色等级参数和计算时传入参数。
3. 用结构化编辑器维护技能公式，不让用户手写 JSON 或公式字符串。
4. 在属性节点中直接选择施法者/目标、属性以及基础值、加成值、最终值、当前值、已损失值或比例。
5. 把固定填充和等差递增草稿转换成后端要求的完整等级 Map。
6. 提示技能最大等级和游戏等级范围缩小时会删除的数值。

页面不管理游戏级计算变量，不执行公式，不管理技能效果、条件、伤害类型、发布或 Wasm。

## 3. 页面入口

### 3.1 技能管理

现有 `#/skills` 列表的每行操作增加“参数与公式”：

1. 启用和停用技能都允许进入。
2. 点击后打开标题为“参数与公式 - {技能名称}”的管理弹窗。
3. 操作位置放在“编辑”之后、“启用/停用”和“删除”之前。
4. 技能被删除或切换游戏时关闭弹窗并清空内部状态。

管理弹窗使用组件库默认 `Modal`，只设置容纳等级表格所需的宽度；不写遮罩、边框、阴影、定位或全局覆盖样式。允许点击遮罩或按 Esc 关闭。

### 3.2 游戏配置

现有 `#/game-settings` 页面不增加新管理区块。只在修改游戏等级范围时补充角色等级参数的影响提示。

## 4. 客户端类型与接口

### 4.1 技能参数

新增：

1. `SkillParameterValueType = 'INTEGER' | 'DECIMAL'`
2. `SkillParameterValueMode = 'FIXED' | 'SKILL_LEVEL' | 'CHARACTER_LEVEL' | 'RUNTIME_INPUT'`
3. `SkillParameter`
4. `CreateSkillParameterRequest`
5. `UpdateSkillParameterRequest`

`levelValues` 使用 `Record<string, number> | null`，只在提交函数中从按等级排列的草稿转换生成，不在组件之间传递稀疏数组。

`skillParameterClient` 提供：

1. `listSkillParameters`
2. `getSkillParameter`
3. `createSkillParameter`
4. `updateSkillParameter`
5. `deleteSkillParameter`

### 4.2 技能公式

新增：

1. `FormulaAttributeOwner = 'SOURCE' | 'TARGET'`
2. `FormulaAttributeValueKind = 'BASE' | 'BONUS' | 'TOTAL' | 'CURRENT' | 'MISSING' | 'CURRENT_RATIO' | 'MISSING_RATIO'`
3. `FormulaOperationNode`
4. `FormulaParameterNode`
5. `FormulaAttributeNode`
6. `FormulaExpressionNode`
7. `SkillFormulaSummary`
8. `SkillFormula`
9. `CreateSkillFormulaRequest`
10. `UpdateSkillFormulaRequest`

不使用 `Record<string, unknown>` 或 `any` 表示公式节点。公式联合类型只包含运算、参数和属性三类节点，不包含变量节点。

`skillFormulaClient` 提供：

1. `listSkillFormulas`
2. `getSkillFormula`
3. `createSkillFormula`
4. `updateSkillFormula`
5. `deleteSkillFormula`

两个客户端继续使用现有 `requestJson`、Admin Token 和 `encodePathSegment`。请求体只发送共享契约字段，不发送页面草稿、中文预览、节点编号、父节点编号或计算时传入参数的实际值。

### 4.3 表单公共校验

两个表单直接实现共享契约字段规则：

1. 新增时稳定标识使用 `^[a-z][a-z0-9_]{0,63}$`；编辑时不允许修改。
2. 名称去除首尾空白后校验 1～100 个字符。
3. 说明将纯空白转为 `null`，非空时最多 2000 个字符。
4. 排序必须填写为不小于 0 的整数。
5. 前端用于即时提示，后端仍执行相同最终校验。

## 5. 参数与公式管理弹窗

### 5.1 总体状态

新增 `SkillParameterFormulaModal`，维护：

1. 当前游戏、技能标识和技能名称。
2. 当前页签：技能参数或技能公式。
3. 参数列表和公式摘要列表各自的加载、错误和最新请求序号。
4. 当前查看/编辑的参数或公式。
5. 删除确认和保存中的状态。

弹窗打开时并行读取参数列表和公式摘要列表。两类请求独立显示错误；一类失败不能清空另一类已成功数据，重试只重发失败部分。

管理弹窗不提供统一“保存全部”。每次新增、编辑或删除都是独立后端事务；外层底部只有“关闭”。保存成功后关闭当前条目的编辑弹窗、刷新对应列表，外层弹窗保持打开。

### 5.2 关闭行为

1. 外层和条目弹窗都允许点击遮罩、按 Esc 或点关闭按钮退出。
2. 未保存草稿直接丢弃，不增加二次挽留弹窗。
3. 保存请求进行中时禁用当前保存按钮，防止重复提交。
4. 关闭弹窗不取消已经发出的请求，但响应必须通过请求序号和当前技能键检查，不能写回另一个技能的页面状态。
5. 保存成功必须自动关闭当前新增、查看或编辑弹窗。

## 6. 技能参数页签

### 6.1 展示结构

页签顶部只保留关键词输入和“新增参数”。参数按取值方式分成四个区块：

1. 固定值
2. 按技能等级
3. 按角色等级
4. 计算时传入

固定值区块列为参数名称、稳定标识、数值类型、当前值、更新时间和操作。

两个等级区块沿用已确认的阅读方向：

```text
参数名称 / 标识    Lv1   Lv2   Lv3   ...   操作
基础伤害           20    45    70    ...   查看 编辑 删除
```

计算时传入区块列为参数名称、稳定标识、数值类型、更新时间和操作，不显示数值列。

共同规则：

1. 行是参数，列是等级，不使用“等级 → 展开 → 参数列表”。
2. 技能等级列来自当前技能 `1..maxLevel`。
3. 角色等级列来自游戏等级配置 `minLevel..maxLevel`。
4. 等级列过多时只让表格横向滚动，参数名称/标识和操作列固定。
5. 关键词匹配参数名称或稳定标识，四个区块使用同一过滤结果。
6. 空区块显示组件库默认空状态，不增加教学说明。

### 6.2 参数编辑弹窗

新增和编辑共用 `SkillParameterEditorModal`。字段顺序：

1. 稳定标识：仅新增可输入；编辑只读。
2. 参数名称。
3. 数值类型。
4. 取值方式。
5. 数值区域。
6. 说明。
7. 排序。

查看模式使用相同布局但全部只读，底部只显示“关闭”。

取值方式行为：

1. 固定值只显示一个 `InputNumber`，不显示 `%` 单位，也不做 `15` 与 `0.15` 自动换算。
2. 两种等级模式显示完整等级输入和生成工具。
3. 计算时传入不显示数值区域，只保存名称、标识、数值类型、说明和排序。

### 6.3 等级数值录入

按技能等级或角色等级时提供：

1. 固定填充：输入一个值，应用到全部等级。
2. 等差递增：输入起始值和每级增加值，按等级顺序生成。
3. 逐级手填：直接修改任意等级。

生成后的每一级仍可单独修改。生成按钮只改变当前弹窗草稿，不请求后端。

提交前 `buildLevelValues` 必须按当前范围生成完整字符串键，检查每级为有限数字、`INTEGER` 每级为整数且不存在范围外键。

### 6.4 模式切换

模式切换不猜测旧值含义：

1. 切到 `FIXED` 时将固定值初始化为 `0`，清空等级草稿。
2. 切到任一等级模式时按目标范围初始化为全 `0`，清空固定值。
3. 切到 `RUNTIME_INPUT` 时同时清空固定值和等级草稿。
4. 从 `RUNTIME_INPUT` 切到其他模式时按目标模式重新初始化。
5. 编辑已有参数时只有用户实际改变取值方式才执行重置。

### 6.5 游戏等级配置缺失

如果游戏尚未配置等级范围：

1. 参数列表仍可查看固定值、技能等级和计算时传入参数。
2. “按角色等级”选项禁用，并在选项旁提示“请先设置游戏等级范围”。
3. 已存在但无法取得范围的角色等级参数视为接口或数据异常，不从 Map 自行推断范围。

### 6.6 参数操作

1. 新增和编辑成功后关闭编辑弹窗并刷新参数列表。
2. 删除使用组件库默认确认组件；成功后刷新参数列表。
3. `409.SKILL_PARAMETER_IN_USE` 显示“该参数正在被技能公式使用，不能删除”。
4. 删除、保存失败时保留当前上下文，允许直接重试。

## 7. 技能公式页签

### 7.1 公式列表

公式摘要表格列为公式名称、稳定标识、排序、更新时间和查看/编辑/删除操作。列表保持后端 `sortOrder/name/formulaKey` 排序，不显示中文预览。

点击查看或编辑后，再并行读取：

1. 公式详情。
2. 当前技能全部参数。
3. 当前游戏属性目录。

任一必要目录失败都不打开可保存的编辑状态。查看模式若公式详情成功，可以显示稳定标识，但需明确标记目录加载失败。

### 7.2 公式编辑弹窗

新增 `SkillFormulaEditorModal`，字段顺序：稳定标识、公式名称、说明、排序、公式结构、中文预览。稳定标识只在新增时可输入。

公式结构由 `FormulaExpressionEditor` 递归渲染。每个节点先选择：

1. 运算
2. 技能参数
3. 属性

节点切换类型时清除原类型字段，防止提交互斥字段。

### 7.3 节点编辑

运算节点：

1. 选择“加、减、乘、除、取较小值、取较大值”。
2. 固定显示左值和右值两个子节点。
3. 新建时两个子节点处于待选择状态；保存前必须补全。

技能参数节点：

1. 只列当前技能参数。
2. 选项显示“参数名称（parameterKey）”。
3. `RUNTIME_INPUT` 追加“计算时传入”标记，但和其他参数使用相同公式节点。

属性节点按顺序选择：

1. “施法者”或“目标”。
2. 属性，显示“属性名称（attributeKey）”。
3. 属性取值：“基础值、加成值、最终值、当前值、已损失值、当前值比例、已损失比例”。

新增公式只显示启用属性。编辑公式时，当前已经引用的停用属性继续显示并标记“已停用”；其他停用属性不出现。

编辑器不出现计算变量、条件、幂、衰减、数值常量或引用其他公式的入口。根节点深度记为 1，子节点深度为父节点加 1；将要超过深度 32 或包含根节点的总数 256 时禁止继续增加并定位问题。

### 7.4 中文预览

预览由当前草稿纯函数生成，不调用后端求值。例如：

```text
目标.生命值.已损失值 × 已损失生命值系数
```

规则：

1. 属性显示“对象.属性名称.取值方式”。
2. 计算时传入参数按参数名称显示，不额外制造变量语法。
3. 减法、除法和嵌套运算按树结构加括号，不能改变左右顺序。
4. `MIN` 显示“取较小值(左值, 右值)”，`MAX` 显示“取较大值(左值, 右值)”。
5. 目录中找不到的旧引用显示稳定标识并标红，不自行删除节点。
6. 预览只用于阅读，不进入请求体，也不作为公式真源。

### 7.5 保存与删除

1. 保存前运行与共享契约一致的结构检查，定位空节点、属性取值缺失、超深和超量。
2. 保存成功后关闭公式编辑弹窗并刷新摘要列表。
3. 删除使用组件库默认确认组件；成功后刷新摘要列表。
4. `400.INVALID_FORMULA_REFERENCE` 按 `details.fieldIssues[].field` 映射到具体树节点。
5. `409.FORMULA_ATTRIBUTE_DISABLED` 保留草稿，并定位新增的停用属性节点。

## 8. 等级配置联动提示

### 8.1 技能最大等级

现有技能资料编辑弹窗记录打开时的 `maxLevel`：

1. 新值小于旧值时，保存前用默认确认弹窗提示“高于 Lv{新值} 的技能等级参数值将被删除”。
2. 新值大于旧值时直接保存；成功消息追加“新增等级参数已补 0”。
3. 新值不变时沿用现有保存行为。

前端不自行修改参数 Map。技能保存成功后，如果该技能的参数管理弹窗仍打开，必须刷新参数列表。计算时传入参数不受等级变化影响。

### 8.2 游戏等级范围

游戏等级配置保存前新增组件库默认确认弹窗，文案同时覆盖角色属性和角色等级参数：

1. 缩小范围提示超出范围的角色属性和角色等级参数会删除。
2. 扩大范围提示新增等级会补 0。
3. 保存成功后刷新等级配置；下次打开参数弹窗时按新范围展示。

前端不并行提交角色属性或技能参数补丁。计算时传入参数不受游戏等级范围影响。

## 9. 错误、并发与状态隔离

1. 两个客户端继续交给现有统一请求层解析稳定错误。
2. 所有列表请求使用递增请求序号，旧响应不能覆盖新游戏、新技能或手动刷新后的结果。
3. 外层弹窗关闭后到达的响应不得重新打开弹窗或写入已销毁表单。
4. 表单错误先按共享契约字段路径定位；没有对应控件的错误显示在弹窗顶部。
5. 409 引用冲突不自动刷新并丢失草稿。
6. 404 技能不存在时关闭参数与公式弹窗并刷新技能列表。
7. 公式编辑期间参数被其他请求删除时，以后端保存结果为准，返回引用错误后保留公式草稿。

## 10. 样式与可用性

1. 使用现有 Arco `Modal`、`Table`、`Tabs`、`Form`、`InputNumber`、`Select`、`Space`、`Alert` 和确认组件。
2. 不新增全局 CSS，不覆盖 `.arco-modal`，不自制遮罩、边框或阴影。
3. 公式树优先用组件的间距、缩进和卡片属性组合，不新增复杂样式文件。
4. 所有操作按钮保留文字，不能只用图标表达查看、编辑、删除或添加节点。
5. 表单标签和错误信息与控件关联，键盘可以遍历节点类型、运算和引用选择。
6. 页面只显示完成操作所需的名称、字段、错误和确认，不添加“这里维护什么”等学习文案。

## 11. 前端验证

### 11.1 客户端测试

两个客户端测试至少覆盖：

1. 游戏、技能、参数和公式路径片段编码。
2. POST、PUT、DELETE 方法、状态和请求体。
3. PUT 不发送稳定标识。
4. 固定参数发送 `fixedValue` 且 `levelValues=null`。
5. 等级参数发送完整 `levelValues` 且 `fixedValue=null`。
6. 计算时传入参数两个值字段均为 `null`。
7. 公式摘要列表和详情响应使用不同类型。

### 11.2 纯函数测试

新增参数表单和公式表达式测试：

1. 固定填充、正负等差递增、非 1 起始角色等级和手工覆盖。
2. 范围变化后完整 Map 生成、缺值、额外键、整数小数和非有限数字。
3. 四种参数模式切换，特别验证进入 `RUNTIME_INPUT` 清空两个值字段。
4. 三类节点、六种运算和七种属性取值的请求转换。
5. 中文预览中的对象、属性、取值方式、括号和左右顺序。
6. 根深度为 1 时深度 32、节点总数含根为 256 的边界以及超限拒绝。
7. 字段路径能定位嵌套节点，节点类型切换会清除旧字段。

3. 建立参数 + 施法者最终属性公式、目标已损失生命值公式和当前层数公式。
4. 查看中文预览，编辑嵌套运算并确认保存后编辑弹窗自动关闭。
5. 点击遮罩和按 Esc 均能关闭查看/编辑弹窗。
6. 删除被引用参数时收到清晰冲突，数据不变。
7. 技能最大等级和游戏等级范围扩大/缩小后，页面与数据库联动结果一致，计算时传入参数不变化。
8. 切换游戏和快速连续刷新不会串数据。
9. 游戏配置页没有新增计算变量区块；公式编辑器没有变量节点。
10. 页面没有新增学习说明、状态筛选、启停按钮、自制弹窗边界或全局样式。
11. 浏览器流程不发起 Wasm 编译、会话或执行请求。

## 12. 前端停止条件

出现以下任一情况停止编码并回到共享方案：

1. 页面需要恢复游戏级计算变量或公式变量节点。
2. 结构化编辑器无法用参数和属性取值完成代表性公式。
3. 需要让用户手写 JSON、公式语言或条件表达式才能继续。
4. 需要在前端或效果阶段另存一份等级 Map。
5. 后端接口、字段、错误或等级联动未冻结。
6. 需要修改全局弹窗样式、旧能力页面、发布链或 Wasm 才能完成页面。

只有自动检查和真实浏览器跨端验收都通过后，前端任务才能标记完成。
