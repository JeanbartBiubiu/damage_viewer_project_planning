# 阶段 9 关联管理前端实施

公共字段、接口、启停规则和跨端验收只以[关联管理共享契约](../项目/关联管理详细设计.md)为准。实施工作树为 `C:\project\damage_web_dev`，沿用既有页面和弹窗，不新增导航。

## 页面与文件

| 入口 | 实现职责 |
| --- | --- |
| 角色、装备行「关联技能」和技能行「挂载对象」 | `SkillRelationsModal.tsx` 完成双向新增、顺序调整、移除和刷新；技能侧分角色、装备两组 |
| 六类对象行「代表图片」 | `ObjectRelationActions.tsx` 接入既有列表；技能效果带所属技能键定位 |
| 游戏配置「代表图片」 | `GameRepresentativeImagePanel.tsx` 与等级表单独立；保存后刷新当前关系及游戏摘要 |
| 对象代表图片弹窗 | `RepresentativeImageModal.tsx` 默认在当前对象内上传并自动设置，次要入口可选择已有图片，支持移除 |
| 图片行「用途关系」 | `ImageUsagesModal.tsx` 反查七组来源，支持新增用途、替换确认和移除；效果先选择所属技能 |
| 缓存预览 | `CachedImagePreview.tsx` 只读当前游戏缓存；缺失显示占位，权威响应停用时遮蔽缓存图片 |

上述组件位于 `web/src/pages/admin/relations/`。类型在 `web/src/types/`，请求分别由 `skillRelationClient.ts` 和 `imageRelationClient.ts` 负责；客户端校验响应结构、同游戏和固定枚举，复用统一错误结构。游戏摘要使用 `representativeImageKey`，不读取旧地址字段。

## 交互约束

排序直接校验非负整数范围，不自动钳制用户输入。已有停用技能关系可以调整顺序、移除，新增候选仅含启用技能；图片停用保留用途，禁止新用途或改选停用图片。

读取失败提供重试；保存失败保留当前草稿并显示后端错误。保存成功刷新权威关系，只清理对应已保存草稿。关闭弹窗、切换页面或离开浏览器时接入未保存确认；弹窗的遮罩与焦点限制阻止操作背景中的游戏和 API 控件。组件按游戏、接口和对象隔离状态，并使已卸载或旧上下文的迟到请求失效。技能及图片用途候选均支持按中文名称或稳定标识搜索。

图片管理仍以本地缓存作为列表来源；需要时执行原有全量同步。代表图片候选请求不下载内容，预览不尝试根据旧前缀或地址推导图片。

代表图片上传由 `web/src/services/representativeImageUpload.ts` 编排，复用 `ResourceImageUploadField`、`prepareResourceImage`、`createImage` 与 `upsertManagedImage`。用户只需选择本地文件并点击“上传并使用”，图片名称与随机标识由前端生成。上传成功后自动调用关系接口并更新缓存，重新打开弹窗或进入图片管理即可看到结果。共享图片的替换和失败恢复遵守共享契约第 8 节；文件处理、上传、保存期间锁定会丢失当前操作的控件。

角色、属性、装备、技能、技能效果和状态表格最左侧固定展示「图片」列，宽 84 像素，缩略图为 48×48。共用 `useRepresentativeImageColumn.tsx`：逐行读取现行代表图片接口，图片内容复用当前游戏缓存；上传、更换、移除成功后仅重读当前行，刷新列表时重读当前列表。切换游戏、接口或对象会隔离旧请求与图片状态。没有关联、没有缓存、停用和读取失败分别展示占位；游戏配置保留既有图片面板，图片管理保留原缩略图列。
