## 1. 页面和路由

新增两个直接入口，不建设合并页、页签页、技能分类分组页或通用类型页：

| 路由 | 导航名称 | 页面标题 |
| --- | --- | --- |
| `#/skill-categories` | 技能分类管理 | 技能分类管理 |
| `#/damage-types` | 伤害类型管理 | 伤害类型管理 |

两个入口放在“装备管理”之后、后续技能管理之前。页面继续从 `App.tsx` 接收现有 API 地址、当前游戏、Admin Token 和脏状态回调，不建立第二套全局状态。

## 2. 列表交互

技能分类页面直接展示单层分类列表，不增加分类分组、分组筛选或组内选择规则。后续技能管理页面读取启用的技能分类并提供多选，本阶段不提前实现技能与分类的关联。

两个页面分别维护自己的查询和请求状态，均提供：

1. 关键词输入。
2. “全部 / 启用 / 停用”受控单选按钮。
3. 查询、重置、刷新和新增按钮。
4. 列表列：名称、稳定标识、状态、排序、更新时间、操作。
5. 行操作：查看、编辑、启用或停用、删除。

查询使用“输入草稿”和“已应用查询”两套状态；只有点击查询或回车才应用，重置同时清空两者。切换游戏时清空查询、列表选中、弹窗、提示和未完成请求结果，避免旧游戏响应覆盖新游戏页面。

空列表只显示“暂无技能分类”或“暂无伤害类型”，不附加教学说明。

## 3. 资料弹窗

每个资源分别建立新增、查看、编辑弹窗和纯函数表单校验：

1. 新增字段：稳定标识、名称、说明、排序；提交时固定发送 `status=ENABLED`。
2. 编辑字段：名称、说明、排序；稳定标识只读；状态不在编辑弹窗修改。
3. 查看弹窗只读展示完整字段和创建/更新时间。
4. 启用、停用只通过列表行操作完成，两种操作使用相同的默认确认弹窗和 PUT 流程。
5. 删除使用默认危险确认弹窗；引用冲突保留弹窗并显示后端错误。
6. 资料弹窗显式允许点击遮罩和按 Esc 关闭；关闭直接清空草稿并通知脏状态为 false，不增加二次确认。
7. 保存成功自动关闭并重新读取列表；失败保留草稿并映射 `fieldIssues`。

不得覆盖组件库弹窗的边框、阴影、定位和宽度样式，也不新增页面用途说明或字段教学文案。
