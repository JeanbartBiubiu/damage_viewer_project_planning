## 4. 类型与客户端契约

### 4.1 `skillEffect.ts`

结果联合仍为八种，不新增结果类型。增加以下固定类型：

1. 伤害产生方式 `SKILL / BASIC_ATTACK`。
2. 伤害来源性质 `DIRECT / REFLECTED`。
3. 暴击模式 `DISALLOWED / SOURCE_CRIT_CHANCE / FORCED`。
4. 吸血种类 `LIFE_STEAL / OMNIVAMP / PHYSICAL_VAMP / SPELL_VAMP`。
5. 吸血基准 `POST_DEFENSE_DAMAGE / ACTUAL_HP_LOSS`。
6. 护盾衰减 `NONE / LINEAR_TO_ZERO`。

`SkillEffectDamageDetail` 增加：

1. 非空 `deliveryKind`。
2. 非空 `originKind`。
3. 非空 `critical` 对象。
4. 非空 `vampRules` 数组。

`SkillEffectNormalShieldDetail` 从空对象改为可空 `absorbedDamageTypeKey` 与非空 `decayMode`。请求、响应和草稿必须使用判别联合，不建立一个所有字段可选的宽结果类型。

本阶段类型中不得出现 `spellShieldBlockScope`、后续八种结果或后续四种事件。

### 4.2 `skillTriggerRule.ts`

事件联合仍为十七种：

1. 只把 `DAMAGE_DEALT / DAMAGE_TAKEN` 的 detail 改为 `damageTypeKey/deliveryKind/originKind`。
2. 其他十五种事件形状不变。
3. 事件值联合和 `PRIOR_ACTION_RESULT.outputKind` 保持阶段 7.5 集合，不提前添加伤害结算值。

### 4.3 客户端响应检查

开发环境最小协议检查增加：

1. 伤害四组新字段完整、枚举合法、吸血数组元素形状正确。
2. 普通护盾两字段完整。
3. 两种伤害事件明细完整。
4. 结果仍只有八种、事件仍只有十七种，响应若出现本阶段未知后续类型按协议错误处理。

后端缺少迁移后的必填字段时必须抛明确协议错误；不得在客户端为旧响应偷偷补 `SKILL/DIRECT/DISALLOWED/NONE` 默认，也不得静默删除未知字段。

## 5. 效果草稿、默认值与映射

`effectForm.ts` 增加本阶段草稿结构和唯一映射表：

1. 新建伤害结果默认 `SKILL + DIRECT + DISALLOWED + null 倍率 + 空吸血数组`。
2. 新建普通护盾默认“全部伤害 + 不衰减”。
3. `fromDetail` 无损保留枚举、null、稳定结果键和吸血规则；吸血按 `LIFE_STEAL / OMNIVAMP / PHYSICAL_VAMP / SPELL_VAMP` 固定顺序重建，不能依赖后端行顺序。
4. `toCreateRequest/toUpdateRequest` 提交精确 detail，不提交目录展示对象、空吸血行或隐藏字段。
5. 伤害切换为 `DISALLOWED` 时清空倍率公式；删除吸血行后不保留空对象。
6. 新建结果切换种类时清空上一种类的伤害、吸血或护盾字段；已有结果类型仍只读。
7. 保存成功后用后端完整详情重建草稿，不在本地推测数据库默认或回填结果。

## 6. 伤害结果编辑

在现有结果子弹窗的伤害专属区按以下顺序展示：

### 6.1 伤害来源

1. “伤害产生方式”：技能、普通攻击。
2. “伤害来源性质”：直接伤害、反伤。

反伤旁固定说明：“这里只标记伤害性质；受到伤害后的触发关系仍在条件与触发中维护。”页面不自动创建规则或冷却。

### 6.2 暴击

1. “不允许暴击”。
2. “按来源对象暴击率判定”。
3. “强制暴击”。

后两种显示可空“暴击倍率公式”选择器，只列当前技能公式；第一种隐藏并清空倍率公式。页面不显示实际暴击率、倍率计算值或随机按钮。

### 6.3 吸血

以结构化行编辑：

1. 吸血种类。
2. 计算基准：“防御后伤害”或“实际扣血”。
3. 必填效率公式。
4. 删除操作。

“新增吸血规则”只展示尚未使用的种类，最多四行；种类重复、公式缺失或目录失败时禁止保存并定位该行。页面不显示实际治疗量，也不把吸血基准加入前序结果选择器。

## 7. 普通护盾结果编辑

普通护盾专属区显示：

1. “吸收伤害类型”：全部伤害或一个启用伤害类型。
2. “护盾衰减”：不衰减、随生命周期持续时间线性衰减至 0。

选择线性衰减后：

1. 父效果必须有生命周期，且 `durationFormulaKey` 非空。
2. 到期方式必须为整体到期。
3. 当前结果时点必须为持续生效，数值必须整个实例共享。
4. 页面隐藏或禁用逐层到期、每层独立到期、每层分别贡献值；已有草稿冲突时列明会被清理字段并要求确认，不能静默改写。

选择不衰减时不自动改变合法生命周期字段。页面只说明保存语义，不显示护盾条、衰减曲线或实际破裂事件。

## 8. 结果列表与目录

结果列表的“特殊交互”摘要只显示：

1. 伤害：技能/普通攻击、直接/反伤、暴击方式、吸血规则数量。
2. 普通护盾：全部/指定伤害类型、不衰减/线性衰减。
3. 其他六种结果显示“—”。

打开效果编辑器沿用当前公式和伤害类型目录缓存：

1. 新建/改选只列启用引用；已有停用引用保留“已停用”并允许原样保存。
2. 目录中找不到已有引用时显示稳定标识兜底并禁止保存，不能当作 null。
3. 公式或伤害类型目录失败只阻止依赖区保存，保留完整草稿并允许重试。
4. 不为吸血基准、暴击模式或衰减模式请求目录。

## 9. 既有伤害事件编辑

阶段 7.5 的造成伤害和受到伤害事件增加同一个筛选区：

1. “伤害类型”：任意或一个启用伤害类型。
2. “伤害产生方式”：任意、技能、普通攻击。
3. “伤害来源性质”：任意、直接伤害、反伤。

规则：

1. 新建两种伤害事件默认任意/任意/任意。
2. 后端迁移后的已有规则必须完整回读；客户端不兼容空对象响应。
3. 切换到其他十五种事件时清空伤害筛选，不提交隐藏字段。
4. 事件值选择器保持阶段 7.5 原样，不出现原始伤害、防御后伤害、护盾吸收或实际扣血。
5. 不显示伤前伤害、命中联动、攻击联动或法术护盾阻挡事件。

## 10. 反伤表单保护

触发规则表单按目标效果完整详情判断是否包含反伤结果：

1. 反伤效果只能在“受到伤害”事件中选择执行，动作目标固定为“事件来源对象”。
2. 事件来源性质为“直接伤害”时可保存。
3. 来源性质为“任意”或“反伤”时，必须配置合法每目标冷却；页面显示明确保护提示并阻止明显非法提交。
4. 页面不实现全技能有向环算法；后端返回无保护循环错误时保留全部草稿，在触发保护区显示参与规则/动作和中文原因。
5. 修改目标效果后发现其变成反伤效果时，立即重新校验当前草稿；不自动改事件、动作目标或冷却。

## 11. 动态输入可达公式增量

阶段 7.5 最终 `triggerRuleForm.ts` 在既有公式收集上增加：

1. 执行效果动作收集伤害数值规则、非空暴击倍率和全部吸血效率公式。
2. 启动过程动作通过直接效果挂接到达伤害时使用同一收集规则。
3. 读取上述公式详情并去重后，只展示实际引用的 `RUNTIME_INPUT` 参数。
4. 参数绑定缺失、重复或多余时继续沿用阶段 7.5 字段提示；公式目录失败保留草稿、禁止保存并允许重试。
5. 前序结果选择器仍只显示 `CONFIGURED_VALUE`，不得因为吸血基准字面量而显示后续输出。

错误边界：

1. 当前触发规则 POST/PUT 自身缺失、多余或类型不兼容绑定时，继续处理 `400.INVALID_RUNTIME_INPUT_BINDING` 并定位动作/绑定字段。
2. 效果 PUT 改变暴击/吸血公式后会改变既有规则可达参数集合时，处理 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_RUNTIME_INPUT_IN_USE`，定位本次效果公式字段，并在当前弹窗列出受影响规则、动作和参数。
3. 409 提示固定说明：“请先在条件与触发中移除或改写这些依赖规则，再修改效果，最后按新参数恢复规则。”页面不得自动删除规则、预先提交多余绑定或发起跨聚合批量请求。
4. 保存失败保留效果完整草稿；用户关闭当前弹窗后可自行进入“条件与触发”处理依赖。

## 12. 前端同步校验与错误定位

提交前至少校验：

1. 伤害来源、暴击形状、吸血种类唯一、基准与公式完整。
2. 普通护盾吸收类型和线性衰减生命周期组合。
3. 两种伤害事件筛选完整，其他事件没有隐藏筛选。
4. 反伤事件、动作目标、来源过滤与每目标冷却组合。
5. 暴击/吸血新增可达公式参数绑定集合。
6. 新增或改选引用不是未知/停用项。

前端不判断公式最终范围、数据库外键或完整规则图。

后端字段路径映射增加：

1. `results[i].detail.deliveryKind/originKind` → 伤害来源区。
2. `results[i].detail.critical.*` → 暴击区。
3. `results[i].detail.vampRules[j].*` → 对应吸血行。
4. `results[i].detail.absorbedDamageTypeKey/decayMode` → 普通护盾区。
5. `eventSource.detail.damageTypeKey/deliveryKind/originKind` → 事件筛选区。

未知字段问题显示在当前弹窗顶部并保留服务端详情；不能把英文原因码作为主要用户文案。

6. 动作目标效果变化后可达参数和反伤校验刷新。
7. 保存失败保留草稿、保存期间防重复提交和 404/409 行为。

### 14.3 非 Wasm 浏览器测试

在 `non-wasm-pages.spec.ts` 增加 Desktop Chrome 代表流程：

1. 新建带暴击和三类吸血的伊泽瑞尔 Q 伤害，保存、关闭并重新打开。
2. 新建线性衰减普通护盾并验证非法生命周期组合不能提交。
3. 新建受到普通攻击直接伤害触发的反伤规则；去掉来源保护和冷却后，模拟后端循环错误并确认草稿保留。
4. 验证页面没有法术护盾范围、新结果、新事件、丰富前序输出、实际计算或 Wasm 入口。

浏览器测试复用现有非 Wasm 基础设施，不增加移动设备项目。

## 17. 前端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.5 最终类型、事件表单、动作目标、动态输入或循环错误结构与本设计前提不一致。
2. 需要增加后续结果、事件、法术护盾范围或丰富输出才能完成本阶段表单。
3. 需要建立第二套效果/触发规则编辑器、主导航或独立路由。
4. 页面必须手写 JSON、自由表达式或数据库复合键才能保存。
5. 需要在前端复制完整规则图或执行公式、暴击、吸血、护盾、反伤、结算、预览或 Wasm。
6. 后端真实接口或浏览器验收不可用且无法定点确认原因。

在 Cursor 只读评审、项目负责人确认和阶段 7.5 完整验收之前，本设计不授权任何 Web 代码、配置、服务或浏览器操作。
