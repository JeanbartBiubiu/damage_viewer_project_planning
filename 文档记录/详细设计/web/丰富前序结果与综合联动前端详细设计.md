## 5. 最终事件值选择

事件能力表由 `triggerRuleForm.ts` 单一固定表拥有：

1. 即将受到伤害：原始伤害、防御后伤害、受伤前生命、预计受伤后生命。
2. 造成伤害/受到伤害：原始伤害、防御后伤害、护盾吸收、实际扣血、已阻挡、已免疫、已击杀。
3. 应用命中联动/触发攻击联动：本次序号、总次数。
4. 法术护盾成功阻挡：无事件值。
5. 其他事件保持阶段 7.5 能力。

同一能力表同时驱动事件值比较条件和事件值动态输入来源；两个组件不复制各自白名单。

显示规则：

1. 小数值使用普通数值标签。
2. 已阻挡、已免疫、已击杀显示“否 = 0，是 = 1”。
3. 本次序号和总次数显示“从 1 开始”。
4. 事件变化令现有条件/绑定失效时，列出完整稳定标识并要求确认清理；取消则保留原事件和草稿。

## 6. 前序结果三级选择

动态输入来源选择 `PRIOR_ACTION_RESULT` 后依次显示：

1. “来源动作”：只列当前规则排序更早的执行效果动作。
2. “来源结果”：加载动作目标效果完整详情，只列无生命周期效果结果或生命周期应用时点结果。
3. “结果输出”：按来源结果当前完整形状显示合法中文输出。

规则：

1. 来源动作按 `sortOrder + actionKey` 稳定顺序计算，当前动作、同动作和后续动作不显示。
2. 来源效果详情按 `effectKey` 在当前规则弹窗会话缓存；关闭弹窗释放。
3. 详情加载失败保留稳定标识和草稿、禁止保存并允许重试，不退化为摘要判断或自由输入。
4. `sourceEffectKey` 仅从已选动作推导用于页面显示，不进入请求。
5. 来源动作改变时清空结果和输出；来源结果改变时清空输出，均对已有值执行确认流程。
6. “来源结果”按 `resultKey` 去重；一个多目标冷却变化只出现一次，目标技能只用于结果详情展示，不生成新的选择层级或重复候选。
7. 不增加“来源乘区”或“乘区输出”层级；`modifierZoneKey` 只用于结果详情与管理摘要，不能代替 `sourceResultKey`。

## 7. 输出选项矩阵

`triggerRuleForm.ts` 的固定解析器按最终效果类型提供：

1. 任意具有数值规则的即时结果：基础配置值。
2. 伤害：原始伤害、防御后伤害、护盾吸收、实际扣血、已免疫、已击杀；有吸血规则时增加实际治疗。
3. 任意非空合法阻挡范围的即时离散结果：已阻挡。
4. 直接治疗：实际治疗。
5. 状态施加：是否成功施加。
6. 斩杀：是否击杀。

“基础配置值”只表示结果自身的 `valueRule`，不表示同乘区加算值、乘区因子、属性修正后值或最终伤害/治疗修正值。页面不为乘区新增输出项。

显示中文标签：

| `outputKind` | 页面标签 |
| --- | --- |
| `CONFIGURED_VALUE` | 基础配置值 |
| `RAW_DAMAGE` | 原始伤害 |
| `POST_DEFENSE_DAMAGE` | 防御后伤害 |
| `SHIELD_ABSORBED` | 护盾吸收 |
| `ACTUAL_HP_LOSS` | 实际扣血 |
| `ACTUAL_HEALING` | 实际治疗 |
| `BLOCKED` | 是否被法术护盾阻挡（0/1） |
| `IMMUNE` | 是否被伤害免疫（0/1） |
| `STATUS_APPLIED` | 是否成功施加状态（0/1） |
| `KILLED` | 是否形成击杀（0/1） |

直接治疗和普通护盾不会显示“是否被法术护盾阻挡”。没有吸血规则的伤害不会显示“实际治疗”。状态移除不会显示“是否成功施加状态”。

## 8. 即时性与动作变化处理

1. 来源结果列表排除持续生效、满层、周期、自然结束和提前移除时点；使用 `MOMENT_EVALUATION` 的修正结果仍为持续生效结果，不能因存在数值规则而出现在候选中。
2. 动作重排后重新计算全部 `PRIOR_ACTION_RESULT`；变成同动作或后向引用的绑定标记为失效。
3. 动作目标效果变化、结果删除、生命周期时点变化、吸血清空、阻挡范围清空或状态操作变化时重新计算输出可用性。
4. 当前规则内可确定的失效项列出 `actionKey / bindingKey / sourceResultKey / outputKind` 并要求确认清理；取消则回滚触发变化的草稿操作。
5. 其他会话对效果的并发变化由后端保存校验；前端不得依赖缓存绕过 400/409。
6. 乘区选择变化本身不创建或清理前序结果绑定；若同一修改同时改变结果公式或生命周期即时性，继续按现有输出失效确认处理，并无损保留效果草稿中的乘区字段。

## 9. 值类型与绑定完整性

1. 目标参数为小数时可选择小数或整数输出。
2. 目标参数为整数时只显示整数输出；小数输出不显示并在旧草稿中标记错误。
3. 输出选择器与内部状态、战斗状态、事件值三种来源共同参加“每个可达参数恰好一个绑定”检查。
4. 缺失、多余、重复或类型错误在动作区域按参数稳定顺序显示。
5. 页面不执行整数转小数、不计算结果，也不允许预先绑定未来可能出现的参数。

## 16. 开发获批后的真实浏览器综合验收

只在后端本阶段真实迁移、接口、重启回读和事务回滚验收通过后执行：

1. 使用真实技能、公式、属性、伤害类型、效果、生命周期、过程和规则逐项录入七个代表案例。
2. 每个案例保存后关闭全部弹窗、刷新页面并重新打开；后端重启后再次核对。
3. 验证十种输出、最终事件值、动作顺序、目录引用和错误定位完整。
4. 尝试共享契约全部关键反例，确认原聚合不变、草稿保留且没有半成品数据。
5. 确认页面没有实际结算、运行、预览、发布或 Wasm 请求。
6. 验证乘区目录和修正结果字段仍可完整回显，但前序结果选择器没有乘区层级、乘区因子或最终修正值选项。

## 17. 前端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.6.4 最终类型、乘区目录与动态读取、动态输入表单、效果详情、错误结构或分析器与本文前提不一致。
2. 需要新结果、事件、接口、运行缓存、自由输出或跨规则引用才能完成。
3. 输出可用性必须执行公式或结果才能判断，无法从完整效果详情确定。
4. 需要建立第二套规则/效果编辑器、主导航或独立路由。
5. 页面必须手写 JSON、自由表达式、输出名或数据库复合键才能保存。
6. 需要在前端复制完整规则图或执行伤害、护盾、吸血、阻挡、斩杀、联动、事件、预览或 Wasm。
7. 七个案例的后端真实接口或浏览器验收不可用且无法定点确认原因。

在主会话内部闭环评审、项目负责人确认及全部前段完整验收之前，本设计不授权任何前端代码、配置、服务或浏览器操作。
