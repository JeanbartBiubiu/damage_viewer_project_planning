# 技能基本管理前端详细设计

方案版本：`skill-basic-management-v2-frozen`

方案状态：已于 2026-08-26 完成前端实现、自动检查和真实浏览器验收。

本文实施[技能基本管理共享契约](../项目/技能基本管理详细设计.md)，不重复定义公共字段和错误含义。

## 1. 页面职责

新增独立“技能管理”页面，用于：

1. 查询技能基本资料。
2. 新建、查看和编辑技能。
3. 多选已有技能分类。
4. 直接启用、停用和删除技能。

页面不录入技能参数、公式、效果、伤害类型、角色归属、装备归属或计算配置。

## 2. 写入范围

开发获批后，允许写入：

1. `web/src/types/skill.ts`
2. `web/src/services/skillClient.ts` 及对应测试
3. `web/src/pages/admin/skills/**`
4. `web/src/App.tsx`
5. `web/src/config/navigation.ts` 及对应测试
6. 与新增静态页面直接相关的非 Wasm Playwright 清单和测试
7. 与新页面入口直接相关的 `web/README.md`

不得修改 Wasm 适配器、旧能力页面、旧 Provider 页面、现有战斗数据客户端或全局弹窗样式。

## 3. 路由与导航

1. 静态路由增加 `skills`，地址为 `#/skills`。
2. 导航名称固定为“技能管理”，放在“伤害类型管理”之后、“游戏配置”之前。
3. 页面组件使用 `SkillManagementPage`；产品文案不使用“能力”“实体”“数据作者区”等内部名称。
4. 不恢复旧 `AbilitySetupPage` 或其他旧技能入口；本阶段只新增独立页面。

## 4. 客户端类型与接口

新增前端类型：

1. `SkillStatus = 'ENABLED' | 'DISABLED'`
2. `Skill`
3. `SkillListQuery`、`SkillListResponse`
4. `CreateSkillRequest`、`UpdateSkillRequest`

`Skill` 与请求中的分类只使用 `skillCategoryKeys: string[]`。页面继续调用现有 `listSkillCategories` 获取分类名称、状态和排序，不在技能客户端复制分类资料。分类目录请求不传 `status` 过滤，确保已经关联的停用分类仍能映射名称；多选框只允许新增启用分类，并额外保留当前技能已经选择的停用分类。

`skillClient` 提供：

1. `listSkills`
2. `getSkill`
3. `createSkill`
4. `updateSkill`
5. `deleteSkill`

所有路径片段继续使用 `encodePathSegment`，所有请求继续使用 `requestJson` 和现有 Admin Token。

## 5. 页面状态与查询

页面分别维护：

1. 关键词草稿和状态草稿。
2. 已应用查询条件。
3. 技能列表、技能分类目录和两者各自的加载错误。
4. 资料弹窗、状态确认和删除确认状态。
5. 最新请求序号，防止旧请求覆盖新结果。

状态筛选使用 Arco `Radio.Group` 的“全部 / 启用 / 停用”，查询后不重置草稿值。切换游戏时清空查询、弹窗、提示和未保存状态，并重新读取技能与分类目录。

## 6. 列表

列表列：

1. 技能名称
2. 技能标识
3. 最高等级
4. 技能分类
5. 状态
6. 排序
7. 更新时间
8. 操作

分类键通过技能分类目录映射为名称标签；停用分类增加“已停用”标记。目录临时加载失败时以分类键兜底，不把现有关系显示为空。

操作提供“查看”“编辑”“停用/启用”“删除”。启用和停用都从列表直接操作，并用组件库默认确认弹窗。

## 7. 技能资料弹窗

新增、查看和编辑共用 `SkillEditorModal`：

1. 新增字段：技能标识、技能名称、最高等级、技能分类、说明、状态、排序。
2. 编辑字段：技能名称、最高等级、技能分类、说明、状态、排序；技能标识只读。
3. 查看模式全部只读。
4. 技能分类使用多选 Select；空选择提交空数组。
5. 启用分类可新增；停用选项只包含当前技能已经选择的停用分类，并以 disabled 形式展示。用户可以移除，不能重新新增；目录中的其他停用分类不进入多选框。
6. 创建默认 `maxLevel=1`、`status=ENABLED`、`sortOrder=0`、`skillCategoryKeys=[]`。
7. 前端在提交前校验标识、名称、整数、范围、说明长度和分类重复；后端仍执行完整校验。
8. PUT 每次提交完整 `skillCategoryKeys`，不能因目录加载失败或字段未展开而漏传。
9. 创建和更新请求只提交共享契约规定的可写字段；PUT 不提交 `skillKey`、`gameId`、`createdAt` 或 `updatedAt`。
10. 后端返回 `/skillCategoryKeys/{index}` 时，表单错误映射到对应多选值；不能只识别顶层 `skillCategoryKeys`。

## 8. 弹窗行为

1. 资料、状态和删除确认均使用 Arco 默认 Modal。
2. 不覆盖弹窗边框、阴影、位置或宽度样式。
3. 资料弹窗允许点击遮罩或按 Esc 关闭；直接丢弃未保存内容。
4. 保存成功先关闭弹窗，再刷新当前查询列表。
5. 保存失败保留弹窗、输入内容和后端错误。
6. 状态或删除成功关闭确认弹窗并刷新；失败保留确认弹窗。
7. 页面不显示教学说明或用途介绍。

## 9. 分类目录异常

1. 技能列表和分类目录分别请求，不因分类目录失败而清空已读取的技能。
2. 分类目录失败时允许查询、查看、状态切换和删除；分类用键兜底显示。
3. 分类目录失败时禁用新增和编辑，并显示可重试错误，避免把未知的现有分类关系覆盖为空。
4. 分类目录恢复后，无需离开页面即可新增或编辑。

## 10. 前端验证

### 10.1 自动检查

1. `skillClient` 测试覆盖列表查询、路径编码、POST、PUT 完整分类数组和 DELETE。
2. 表单测试覆盖默认值、去空格、空说明转 null、正整数、分类数组和后端字段错误映射。
3. 导航测试覆盖 `#/skills` 的解析、显示和移动端导航。
4. 页面测试或 Playwright 覆盖筛选值稳定、保存自动关闭、遮罩关闭、直接启停、分类多选、停用分类保留和目录失败保护。
5. 在 `web` 目录依次执行：
   - `npm run lint`
   - `npm run typecheck`
   - `npm run test`
   - `npm run build`
   - `npm run test:e2e:non-wasm`

### 10.2 真实浏览器

项目负责人确认并进入开发后，启动真实前后端并验证：

1. 空列表。
2. 新建无分类技能。
3. 编辑为多个启用分类并刷新回读。
4. 停用一个已关联分类后，技能仍正确显示并可保存其他基本资料。
5. 状态筛选、直接停用和直接启用。
6. 遮罩关闭、保存成功关闭、保存失败保留。
7. 删除技能后列表刷新，分类本身仍存在。

本方案评审阶段不启动开发服务或执行浏览器写入验收。

## 11. 前端停止条件

1. 后端最终接口与共享契约不一致。
2. 分类多选必须依赖旧通用类型或旧能力接口。
3. 无法在完整提交时安全保留已关联的停用分类。
4. 实现必须修改全局弹窗样式或恢复旧页面。
5. 完整前端验证不可用，且定点复查不能确认安全性。

出现任一项时停止开发并回到共享契约确认。
