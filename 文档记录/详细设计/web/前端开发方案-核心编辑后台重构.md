# 前端开发方案-核心编辑后台重构

更新时间：2026-03-24

## 1. 这轮调整结论

前端资源页不再使用“资源工作台 + 右侧发布侧轨”的布局，而是统一回到传统 Web 后台的 CRUD 页面模式。

当前状态：旧 `Katarina MVP` 页面已删除；当前导航分为“数据管理”和“Wasm 验证”两组，Wasm 入口使用 TinyGo V2 M1/M2/M3 验证页。

本轮明确采用以下原则：

1. 4 个资源页和“图片缓存”是左侧菜单同级页面
2. 每个资源页只管理自己的查询、列表、查看、编辑、新增
3. 页面展示全量数据，不做分页
4. 表格操作列固定在最右侧
5. 表格右上角提供“新增”按钮
6. 查看 / 编辑 / 新增统一使用弹窗
7. 写接口统一使用 `PUT`
8. 发布版本必须放在单独页面，不放在资源编辑页里

## 2. 左侧菜单结构

左侧菜单保留以下一级入口：

1. `系统总览`
2. `版本发布`
3. `图片缓存`
4. `英雄`
5. `技能`
6. `装备`
7. `属性定义`
8. `状态管理`
9. `类型定义`
10. `类型挂载`
11. `公式档案`
12. `公式绑定`
13. `乘区桶`
14. `状态动作规则`

对应路由：

- `#/workspace`
- `#/images`
- `#/formula-profiles`
- `#/formula-bindings`
- `#/coefficient-buckets`
- `#/status-action-control-rules`

兼容旧路由：

- `#/admin/{resource}` 继续映射到对应资源页
- `#/versions` / `#/version-publish` 继续映射到 `#/workspace`

## 3. 资源页标准布局

每个资源页都遵循同一页面结构：

1. 查询卡片
2. 表格卡片

查询卡片内容：

- 搜索表单
- 查询按钮
- 重置按钮

表格卡片内容：

- 工具栏
- 全量表格

工具栏规则：

- 左侧是列表说明
- 右侧是操作按钮
- “新增”按钮固定在右上角
- “刷新”按钮与“新增”并列

表格规则：

- 不分页
- 直接显示全部数据
- 操作列固定在表格最右侧
- 操作列至少包含“查看”“编辑”

弹窗规则：

- 点击“新增”打开创建弹窗
- 点击“查看”打开只读弹窗
- 点击“编辑”打开编辑弹窗
- 已有记录的主键字段在编辑态下不可修改

## 4. 发布页独立

发布是高风险操作，必须独立到单独页面处理。

资源页不提供以下能力：

- 创建版本
- 发布版本
- 在编辑页顺手发布

发布页单独负责：

- 输入 Admin Token
- 创建版本
- 发布版本
- 刷新 current version / bundle
- 触发 MVP 页面复验

## 5. 接口策略

资源页接口策略统一如下：

1. 列表读取走 `list` 接口
2. 页面用列表结果直接驱动查看 / 编辑
3. 不新增 `get by id`
4. 写入统一走 `PUT`
5. 不再设计前端 `PATCH` 流程

这样做的原因：

- 编辑用户可以直接通过 list 感知最新态
- 前端请求链路更短
- 页面实现更贴近传统后台模式

## 6. 文件组织

每个资源页都有自己的文件夹，目录统一如下：

```text
web/src/pages/admin/resources/{resource-name}/
  constants.ts
  types.ts
  search.tsx
  columns.tsx
  table.tsx
  modal.tsx
  index.tsx
```

职责约定：

- `constants.ts`：选项、默认查询条件、默认表单
- `types.ts`：当前资源页自己的类型
- `search.tsx`：查询区域
- `columns.tsx`：表格列定义
- `table.tsx`：表格与工具栏
- `modal.tsx`：查看 / 新增 / 编辑弹窗
- `index.tsx`：把当前页面组装起来

共享层保留在：

```text
web/src/pages/admin/resources/shared/
```

只放真正通用的能力，例如：

- `useCrudResourcePage.ts`
- `json.ts`

## 7. 当前实现落点

当前 4 个资源页已经按上述结构拆分：

- `web/src/pages/admin/resources/formula-profiles/`
- `web/src/pages/admin/resources/formula-bindings/`
- `web/src/pages/admin/resources/coefficient-buckets/`
- `web/src/pages/admin/resources/status-action-control-rules/`

全局壳层负责：

- 路由切换
- `apiBaseUrl`
- `gameId`
- `adminToken`

资源页本身只负责自己的 CRUD。

## 8. 验收标准

方案通过的标准如下：

1. 4 个资源页在左侧菜单中与“图片缓存”同级
2. 每个资源页都只有查询卡片和表格卡片
3. 表格右上角存在“新增”按钮
4. 操作列固定在最右侧
5. 查看 / 编辑 / 新增均通过弹窗完成
6. 页面不分页，直接展示全量数据
7. 资源页中不出现版本发布能力
8. 前端写操作统一走 `PUT`
