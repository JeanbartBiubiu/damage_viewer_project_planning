## 6. 结果编辑器公共区域

结果编辑顺序固定为：

1. 基本资料。
2. 结果种类专属字段。
3. 数值规则（当前种类需要时）。
4. 法术护盾阻挡范围（当前组合允许时）。
5. 生命周期行为（效果开启生命周期时）。

`spellShieldBlockScope` 使用中文下拉：

1. 不参与法术护盾阻挡。
2. 阻挡整个技能。
3. 阻挡所属效果。
4. 只阻挡当前伤害实例。
5. 只阻挡当前结果。

当结果 target 为施法者、结果为持续生效或固定禁止种类时，直接隐藏法术护盾阻挡范围并提交 null，不显示无效选项或只读说明。`DIRECT_HEAL / NORMAL_SHIELD` 属于固定禁止种类，即使作用于当前目标且不是持续生效也不得显示下拉框。

多目标冷却变化满足阻挡资格时只显示一个结果级阻挡范围；该选择作用于全部受影响技能。需要不同阻挡行为时由录入者拆成不同结果，页面不提供每个技能单独配置。

## 7. 伤害编辑

### 7.1 来源

使用两个中文单选/下拉：

1. “伤害产生方式”：技能、普通攻击。
2. “伤害来源性质”：直接伤害、反伤。

反伤旁显示简短说明：“这里只标记结果性质；受到伤害后的触发关系仍在条件与触发中维护。”不自动创建规则。

### 7.2 暴击

“暴击方式”固定选项：不允许暴击、按来源对象暴击率、强制暴击。后两种显示可空“本结果暴击倍率公式”；为空时显示“使用来源对象默认暴击倍率”。

公式目录只显示当前技能公式，停用/未知旧引用按现有目录规则保留。页面不计算概率、不抽取随机数、不显示期望伤害。

### 7.3 吸血

吸血规则使用小表维护：

1. 吸血方式。
2. 取值依据：防御后伤害、实际扣血。
3. 适用效率公式。
4. 删除。

新增时只显示尚未使用的吸血方式。表上方说明：“每次已解析伤害实例应用一次；多段次数由技能过程维护。”不得增加“吸血次数”自由数字。

## 8. 普通护盾编辑

`NORMAL_SHIELD` 专属字段：

1. “吸收伤害类型”：全部伤害或一个现有伤害类型。
2. “护盾衰减”：不衰减、随生命周期持续时间线性衰减至 0。

选择线性衰减时，前端要求效果已开启生命周期、`durationFormulaKey` 非空、`expiryMode = ALL_AT_ONCE`、结果位于持续生效且 `stackValueMode = SHARED`；`PER_STACK`、逐层到期或每层独立到期都同步显示组合错误并禁止保存。页面不显示护盾条、剩余值或衰减动画。

## 9. 八种新结果编辑

### 9.1 伤害修正

字段：作用方向、提高/降低、可空伤害类型、产生方式、来源性质、暴击过滤和数值规则。中文摘要示例：“受到的暴击伤害降低”。

### 9.2 治疗修正

字段：造成/受到、提高/降低、全部/直接治疗/吸血和数值规则。中文摘要示例：“受到的全部治疗降低”。

### 9.3 伤害免疫

字段：可空伤害类型、产生方式、来源性质；不显示数值规则。

### 9.4 生命下限

字段：生命属性和下限公式；公式继续通过数值规则选择。页面不根据属性中文名猜测生命值。

### 9.5 法术护盾

没有专属业务字段和数值规则。选择后要求效果已开启生命周期且结果时点为持续生效。

### 9.6 斩杀

字段：生命属性和阈值公式；禁止持续生效。

### 9.7 命中联动应用、攻击联动应用

只显示“应用次数公式”和既有固定倍率/最小/最大数值规则，并按非负整数校验；不提供联动目标技能列表或运行按钮。

## 10. 生命周期同步校验

在阶段 7.4 校验基础上增加：

1. 伤害修正、治疗修正、伤害免疫、生命下限、法术护盾必须为 `PERSISTENT`。
2. 斩杀、命中联动、攻击联动禁止 `PERSISTENT`。
3. 扩展 `isPersistentMomentAllowed`：在原普通护盾、属性变化和状态施加之外，只增加上述五种持续特殊结果；不得把斩杀或两种联动加入白名单。
4. 扩展 `isPersistentNumericResult`：只增加伤害修正、治疗修正和生命下限。伤害修正/治疗修正允许 `SHARED / PER_STACK`；生命下限只允许 `SHARED` 且重复值只显示保留/覆盖。
5. 伤害免疫和法术护盾隐藏并清空 `valueReadMode/stackValueMode/reapplicationValueMode`；三种持续数值结果固定显示 `APPLICATION_SNAPSHOT` 并按共享矩阵维护层数和值合并字段。
6. 斩杀、命中联动和攻击联动使用离散时点时，沿用阶段 7.4 数值读取和周期执行字段；`stackValueMode/reapplicationValueMode` 必须为空。
7. 法术护盾阻挡范围禁止持续生效结果。
8. 普通护盾线性衰减要求 `durationFormulaKey` 非空、`expiryMode = ALL_AT_ONCE` 且 `stackValueMode = SHARED`。
9. 用户把合法生命周期改为不合法形状时，页面列出受影响结果并确认后清理；取消则保持原草稿。
10. 前端不静态求值公式来判断比例、正整数或持续毫秒。

## 11. 条件与触发事件扩展

### 11.1 事件选项

在阶段 7.5 事件编辑器增加：

1. 即将受到伤害。
2. 应用命中联动。
3. 触发攻击联动。
4. 法术护盾成功阻挡。

同时把“造成伤害”“受到伤害”的空明细改为显式筛选区域。

### 11.2 伤害筛选

`DAMAGE_PENDING / DAMAGE_DEALT / DAMAGE_TAKEN` 显示：

1. 伤害类型：全部或明确类型。
2. 产生方式：全部、技能、普通攻击。
3. 来源性质：全部、直接伤害、反伤。

任一规则选择的执行效果含 `originKind = REFLECTED` 伤害结果时，前端要求事件为 `DAMAGE_PENDING / DAMAGE_TAKEN`、动作目标为 `EVENT_SOURCE`，并要求该规则 `eventSource.detail.originKind = DIRECT` 或存在合法每目标冷却；其他事件、其他目标或 `ANY / REFLECTED` 无保护组合都提示反伤闭环风险并禁止提交。后端仍是最终安全边界。

### 11.3 联动事件

命中/攻击联动事件显示可空“来源技能”。空值中文显示“任意技能”。已停用或未知旧技能沿用阶段 7.5 的只读保留规则。

### 11.4 法术护盾事件

只列出当前技能中满足“有生命周期且含法术护盾持续结果”的效果。目录尚未加载或失败时保留草稿、禁止保存并提供重试；不能退化为自由填写 `effectKey`。

## 12. 新事件值与条件

事件值选择器严格按共享契约能力表显示：

1. 即将受到伤害：原始伤害、防御后伤害、受伤前生命、预计受伤后生命。
2. 造成/受到伤害：原始伤害、防御后伤害、护盾吸收、实际扣血、已阻挡、已免疫、已击杀。
3. 命中/攻击联动：本次序号、总次数。
4. 法术护盾成功阻挡：没有事件值。

布尔值显示“否 = 0，是 = 1”。页面不增加新的条件类型，也不允许法术护盾事件选择不存在的数值。

## 13. 丰富前序结果选择

在阶段 7.5 动态输入绑定编辑器中：

1. 先选择排序更早的执行效果动作。
2. 再选择该效果中即时可用的结果。
3. 最后根据结果类型、暴击/吸血/阻挡配置显示合法中文输出。

过滤矩阵必须来自 `triggerRuleForm.ts` 固定表：

1. 任意数值结果：基础配置值。
2. 伤害：原始伤害、防御后伤害、护盾吸收、实际扣血、免疫、击杀；有吸血规则时增加实际治疗。
3. 带法术护盾阻挡范围的离散结果：已阻挡。
4. 直接治疗：实际治疗。
5. 状态施加：是否成功施加。
6. 斩杀：是否击杀。

多目标冷却变化在第二级只按 `resultKey` 出现一次，不按 `affectedSkillKeys` 生成重复结果项；仅当结果具有 `valueRule` 时显示一个 `CONFIGURED_VALUE`，`RESET` 不显示该输出。

`CONFIGURED_VALUE` 只显示结果自身保存的数值规则，不显示乘区内加算值、乘区因子或最终修正值。使用 `MOMENT_EVALUATION` 的持续修正被即时性过滤排除，不新增“乘区”选择层级或前序输出。

布尔输出标记“0/1”。选择 output kind 后显示目标参数整数/小数兼容提示。来源动作被重排、结果被改种类、吸血被清空或阻挡范围被移除时，列出将失效的绑定并确认后清理。

`triggerRuleForm.ts` 收集执行效果和启动过程动作的可达公式时，必须在阶段 7.5 既有集合上追加伤害暴击倍率、全部吸血效率，以及伤害修正、治疗修正、生命下限、斩杀、命中联动应用和攻击联动应用六类数值结果公式；这些公式中的运行输入参数继续要求恰好一个绑定。

## 14. 目录加载

打开效果编辑器沿用当前目录加载，阶段 7.6 新增的伤害类型、公式和属性都复用已有缓存，不重复请求同一目录。

打开触发规则编辑器时：

1. 效果详情按动作和事件选择懒加载。
2. 判断法术护盾资格、伤害输出和吸血输出必须使用完整效果详情，不能只看摘要。
3. 在当前规则弹窗会话按 `effectKey` 缓存；关闭弹窗释放，不写全局或本地持久化。
4. 某个必需目录失败时保留草稿、禁止保存并允许重试；未使用目录失败不阻塞基本资料编辑。
5. 效果编辑器沿用乘区补充阶段的目录加载与停用旧引用显示；阶段 7.6.3～7.6.5 不自行推导乘区结构，也不把乘区目录并入触发规则前序输出目录。

## 15. 前端同步校验

在阶段 7.4/7.5 规则上至少增加：

1. 暴击模式、倍率公式和旧字段清理。
2. 吸血种类唯一、依据与效率公式完整。
3. 伤害/普通护盾/八种新结果 detail 完整且无其他种类字段。

## 16. 后端字段错误映射

扩展字段路径：

1. `results[i].detail.critical.*` → 伤害暴击区。
2. `results[i].detail.vampRules[j].*` → 对应吸血行。
3. `results[i].spellShieldBlockScope` → 法术护盾阻挡范围。
4. `results[i].detail.absorbedDamageTypeKey/decayMode` → 普通护盾区。
5. 新特殊结果 detail → 当前结果专属区。
6. `eventSource.detail.*` → 事件筛选区。
7. `actions[i].runtimeInputBindings[j].detail.outputKind` → 前序结果输出选择。

无法识别的新字段显示在当前弹窗顶部，保留服务端 `code/message/details` 和完整草稿；不能把英文原因码直接作为主要用户文案。

## 17. 弹窗与并发行为

4. 400/409 保持弹窗、滚动到首个可定位字段；循环错误仍显示在触发保护区。
5. 保存成功重新拉取详情和列表，不做乐观拼接。
6. 本阶段不改变当前宽弹窗尺寸，不增加移动端布局。

## 21. 前端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.5 最终类型、事件能力、规则表单、可达参数或错误路径与本设计前提不一致。
2. 后端不能通过现有效果/规则聚合完整回读，前端必须调用子项接口拼装半成品。
3. 页面必须让用户手写 JSON、复合键、自由事件、自由结果或公式文本。
4. 基本录入必须执行公式、随机暴击、伤害、护盾、吸血、事件、结算或 Wasm。
5. 需要新增主导航、独立特殊交互页面、全局状态或移动端专属行为。
6. 前端必须复制全技能循环或数据库约束算法才能完成普通校验。
7. 代表案例无法用现有过程、效果、生命周期、规则和固定扩展表达。
8. 实现方试图按本总设计一次扩展全部结果、事件、前序输出或页面测试。

上述开发期门禁已经随五个子阶段逐项完成而关闭。后续如果修改阶段 7.6 已冻结前端结构，仍须按本节停止条件重新确认，并由新的明确任务授权。
