# 模拟来源与通用编译拆分技术方案

本方案供独立前端开发会话实施，范围是 `web/src/engine/` 中的来源准备与通用触发编译。目标是让装备、角色与构筑等来源拥有各自的解释入口，让通用技能校验和触发程序编译拥有独立落点；完成标准包含实际算法和集合状态归属，不能只搬目录。

来源与通用编译拆分已实施并补齐独立复核，按用户授权快进合入本地主干。独立开发证据见第 9 节，三端组合与合入验证见第 10 节；任务状态以[任务规则](../../../db/task_doc_governance/task_rules.json)为准。后端工作见[触发规则校验与引用保护拆分方案](../server/触发规则校验与引用保护拆分技术方案.md)，两端不改变接口契约。

## 2. 范围与保持项

本轮实施来源准备与通用编译的分离，允许调整内部类型、函数位置及全部直接调用方。现有来源特有的常驻贡献装配可以随所属来源迁移，算法保持原样。

以下内容保持不变：

- 管理接口请求与响应、场景快照、编译请求和运行结果的字段及业务含义。
- 已支持和明确拒绝的配置范围、来源启停、未学技能、费用处理、目标限制及现有报错。
- 公式命名空间、类型键、拥有方与挂载身份、覆盖路径、稳定排序和重复检测。
- 相同业务输入产生的装配结果、请求摘要与真实运行结果。
- 实际编译、运行和释放协议；现有 Wasm 加载器、后台工作线程及分发字节。

本轮不重构编辑器、模拟页面任务状态、后端服务、引擎算法或整个适配目录；不实施浏览器快照缓存和编译复用，不增加兼容转发文件、通用注册框架或新的机制支持。

## 3. 目标责任与依赖

以下布局表达责任，内部辅助文件名由实施者按实际调用收敛，不要求逐函数照搬固定文件名。

```text
web/src/engine/
  simulationAdapter.ts             场景装配与对外准备入口
  simulation/
    model.ts                       来源编译共享类型
    sources/
      equipment.ts                 装备来源准备及所属组合
      natural.ts                   角色、构筑等自然来源准备及所属组合
      description.ts               来源身份、资格与根规则说明
      closure.ts                   实际引用闭包
    compile/
      configuration.ts             完整技能配置校验
      damageFormula.ts             共同防御公式编译
      validation.ts                两层共用的无状态字段检查与稳定排序
      triggered.ts                 通用触发程序的实际编译
```

依赖方向为“装配入口 → 来源准备 → 通用编译 → 现有过程、命中、持续效果和数值适配”。主动技能直接使用通用配置校验与公式编译。共享类型不依赖装配入口；通用编译不导入装备或自然来源的组合入口。

来源准备仍可在原位置同步调用通用编译并合并结果，以保留原校验、捕获和报错顺序。不得为了统一阶段而先收集所有来源、再集中校验或一次性编译，除非能证明完整行为不变。两层共同需要的纯规则可放在明确命名的叶子文件，不把来源准备整体倒置为编译器的依赖。

| 所有者 | 拥有的事实与状态 |
| --- | --- |
| 装备来源准备 | 装备选择、完整关系、所选技能闭包、来源描述、排除覆盖记录，以及预期与实编来源身份核对 |
| 自然来源准备 | 来源排序、双方独立等级、启停和计划资格、来源追踪、来源特有常驻贡献及依赖合并 |
| 通用配置与公式校验 | 接收明确配置及上下文，返回原结果或抛出原错误；不读取接口、不保存跨调用状态 |
| 通用触发编译 | 单次调用中的程序、挂载、公式、类型、操作来源、覆盖记录、属性需求及各类贡献集合 |
| 场景装配入口 | 按原顺序组合各来源与主动过程、角色初值、规则和摘要，不接回通用编译内部算法 |

`TriggeredSkillSourceDescription`、`TriggeredEquipmentAssembly` 以及相关内部类型可以改为表达通用职责的名称。其字段、可选字段和排列含义应保持；下层使用的 `SimulationCoverage`、`OperationOrigin` 等类型下沉到共享类型文件，调用方直接引用真实所有者。

每次编译继续建立自己的集合。来源之间只按原有合并规则交接结果，不新增全局集合、重复的公式冲突账或第二份来源身份记录；保留当前必要的复制边界，不能通过借用可变输入使前一次装配污染下一次。

## 4. 关键契约

### 4.1 来源与执行范围

完整作者配置和本场可执行闭包分别保留。未接入或不可达的作者定义继续按原覆盖记录说明，不能为缩短输入而删除完整参数、公式或作者身份；启用来源与实编来源继续一一核对。

双方、装备、角色和构筑的真实身份必须延续到挂载、公式及结果来源。来源排序变化可能改变生成键和后续数组顺序，因此不能改用无序归并或按显示名称重建身份。

### 4.2 错误与重复装配

保留 `NumericAdaptationError` 的原字段路径、错误文本及原有短路顺序。调用方输入缺失、有效零值、空集合及可选字段不互相替代；不通过默认值让原本失败的输入通过。

独立核对同快照重复装配、来源开关变化、双方互换及兄弟技能共存。迁移不能让覆盖、公式、属性需求或常驻贡献跨调用残留。

### 4.3 稳定入口与正式证明

`simulationAdapter.ts` 继续保留真实的场景装配职责和对外准备函数。`SIMULATION_ADAPTER_VERSION`、`SIMULATION_SCHEMA_HASH` 的现行声明位置和值保持；[证明刷新脚本](../../../web/scripts/refresh-verification-identity.mjs)按固定路径读取版本赋值，不能仅改成再次导出。

迁移内部模块时同步更新生产导入、单测、浏览器动态导入和脚本引用；旧内部文件清除后不保留仅转发的新旧双入口。真实行为相同不等于正式源码身份自动更新，证明刷新按第 7 节独立完成。

## 6. 实施顺序

1. 核对当前调用方，运行受影响测试建立基线；记录代表输入的完整装配结果与请求摘要，原始证据放 `web/output/`。
2. 下沉共享类型；抽离完整配置校验与共同防御公式编译，让主动技能和来源准备直接使用新所有者。
3. 将 `assembleTriggeredSkillSources` 的实际编译流程和单次集合一起迁入通用编译目录；不只抽出函数签名或再套转发。
4. 迁移装备及自然来源的准备、所属组合和辅助规则，保留原调用次序；删除失去生产调用的旧内部入口。
5. 对照完整装配、摘要、错误及真实结果，完成独立复核、本地验证和正式证明身份刷新，报告实际结果与限制。

每一步应能单独审阅。发现真实缺陷时单独界定行为修复，不把新增支持或金额变化混入结构迁移。
