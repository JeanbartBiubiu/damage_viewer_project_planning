## 1. 当前事实与前端职责

当前实现事实：

1. `SkillEffectCooldownChangeDetail` 只有一个 `affectedSkillKey`。
2. `SkillEffectResultDraft` 使用一个 `affectedSkillKey` 和一个 `originalAffectedSkillKey`。
3. “受影响技能”是单选 `Select`。
4. `listAffectedSkillOptions` 允许启用技能、停用父级自引用和一个原样保留的停用技能。
5. 表单转换、字段错误映射、客户端测试和非 Wasm E2E 都按单技能字段断言。

本补项前端负责：

1. 把冷却变化结果类型和草稿改为技能标识列表。
2. 把“受影响技能”改为默认组件多选。
3. 对多个停用、未知、重复和字段下标错误提供稳定回显。
4. 一个结果仍只显示一行，不在草稿中复制多个结果。
5. 保持效果、过程、生命周期和阶段 7.5 结果引用入口可用。

## 3. 类型契约

`web/src/types/skillEffect.ts` 中冷却变化明细改为：

```ts
export type SkillEffectCooldownAdjustDetail = {
  affectedSkillKeys: string[];
  operation: 'REDUCE' | 'INCREASE';
};

export type SkillEffectCooldownResetDetail = {
  affectedSkillKeys: string[];
  operation: 'RESET';
};
```

要求：

1. 不保留 `affectedSkillKey` 别名。
2. `SkillEffectCooldownChangeResult` 仍是减少/增加与重置两类的联合。
3. 减少和增加仍要求 `valueRule`，重置仍要求 null。
4. 其他结果类型、生命周期行为和效果请求结构不变。

## 4. 表单草稿与规范化

`SkillEffectResultDraft` 调整为：

1. `affectedSkillKeys: string[]`：当前多选值。
2. `originalAffectedSkillKeys: string[]`：编辑打开时从后端取得的原始目标集合，用于停用引用比较。

草稿规则：

1. 新建冷却结果默认空数组。
2. 从详情转草稿时复制并规范化列表，不能保留响应对象引用。
3. 切换离开冷却变化结果时清空两个列表。
4. 修改 `REDUCE / INCREASE / RESET` 只影响数值规则，不清空已选技能。
5. 构造请求前按技能目录 `sortOrder, skillKey` 生成稳定列表；目录不可用时按 `skillKey` 排序。
6. 重复检查发生在去重之前，不能通过静默去重掩盖用户输入或异常响应。
7. 脏状态比较使用规范化后的集合，不因多选标签顺序变化误报未保存。
8. clone、查看、编辑和重新打开都进行深复制，避免嵌套弹窗修改外层草稿。

## 5. 目录选项与停用引用

`listAffectedSkillOptions` 调整为接收当前列表和原始列表：

```ts
listAffectedSkillOptions(
  catalog,
  affectedSkillKeys,
  originalAffectedSkillKeys
)
```

选项规则：

1. 所有启用技能可选。
2. 当前父级技能始终可选；已停用时显示“当前技能（已停用）”。
3. 原始列表中的每个停用技能都保留并标记“已停用”。
4. 不在原始列表中的其他停用技能不提供为新选项。
5. 当前列表中目录查不到的每个技能使用稳定标识兜底显示，并把结果保存置为不可用。
6. 同一技能只生成一个选项；父级、自身已保留和启用目录重复时按现有优先级合并。
7. 目录加载失败只阻止依赖技能目录的冷却结果编辑，不影响其他结果种类和只读查看。

## 6. 结果编辑弹窗

“受影响技能”字段改为：

1. 使用 Arco `Select` 的多选模式和现有默认弹窗样式。
2. 支持搜索、逐项移除和清空。
3. 字段必填，空列表显示“至少选择一个受影响技能”。
4. 已有停用项继续显示标签并可删除。
5. 目录不存在项显示稳定标识和错误状态，不能保存。
6. 多项标签由组件库默认布局和折叠能力处理，不增加自定义 CSS。
7. 不增加“全选角色技能”“排除装备技能”开关；当前通过明确勾选 Q、W、E、R 实现排除装备技能。

冷却操作和数值规则保持：

1. 减少、增加显示数值公式、固定倍率、固定最小值和固定最大值，并提示“变化量按毫秒解释”。
2. 重置隐藏并清空数值规则。
3. 作用对象继续使用“施法者 / 当前目标”。

## 7. 结果列表与回显

1. 一个冷却变化结果无论选择几个技能，都只占结果列表一行。
2. 查看或编辑结果时按目录顺序回显全部技能名称。
3. 摘要文字可显示“秘术射击、精华跃动、奥术跃迁、精准弹幕”；超出可视宽度时使用组件库默认省略或折叠。
4. 不把多选目标写入效果名称、结果名称或说明字段。
5. 外层效果 `resultCount` 不因目标数量增加。
6. 所有已选技能共享同一作用对象、操作、数值规则和生命周期行为；页面不提供每项技能独立数值或独立时点编辑。

## 8. 校验和错误映射

`effectForm.ts` 必须覆盖：

1. 空列表。
2. 空字符串、格式不合法项。
3. 规范化后重复项。
4. 新增停用技能。
5. 原样保留或移除多个已有停用技能。
6. 目录缺失的未知技能。
7. 一个结果从单项更新为多项或从多项更新为单项。

后端字段路径映射：

1. `results[i].detail.affectedSkillKeys` 映射到整个多选字段。
2. `results[i].detail.affectedSkillKeys[j]` 也映射到该多选字段，并优先展示具体项目错误。
3. 旧 `results[i].detail.affectedSkillKey` 若由后端返回，只作为未映射协议错误展示，不重新提交旧字段。
4. 多个项目错误可以合并为一条字段提示并保留后端 `code`；不得因只显示第一项而丢失完整草稿。

保存失败时结果编辑弹窗和外层效果草稿都保持打开，已选标签不丢失。

## 9. 客户端与嵌套入口

1. `createSkillEffect`、`updateSkillEffect` 和 `getSkillEffect` 路径、方法和请求外壳不变。
2. TypeScript 类型必须让旧 `affectedSkillKey` 在编译期报错。
3. 阶段 7.3 过程中的“效果与结果”入口继续复用同一个效果管理弹窗。
4. 阶段 7.5 动作编辑器只选择效果，不感知冷却目标列表；一个 `EXECUTE_EFFECT` 动作仍执行一个效果。
5. 阶段 7.5 前序结果候选仍按结果稳定标识列出一次，不按受影响技能展开。

## 10. 前端自动验证

### 10.1 类型、客户端与表单单元测试

至少覆盖：

1. 详情中的四个目标转换为一个草稿列表，构造请求后仍是一个结果和四项 `affectedSkillKeys`。
2. 新建空列表失败，选择一项或四项通过。
3. 重复技能和格式不合法技能失败，且错误落在多选字段。
4. 目录顺序变化不造成脏状态误判；请求输出稳定排序。
5. 父级停用自引用允许新增。
6. 多个原有停用目标可以保留或移除，不能新增其他停用目标。
7. 任一未知目标保留标签并阻止保存。
8. 减少、增加和重置的数值规则显示与清理不变。
9. 后端列表项字段错误映射到对应结果的多选字段。
10. 客户端请求体只包含 `affectedSkillKeys`，不存在旧字段。
11. 阶段 7.4 生命周期、阶段 7.5 动作和前序结果仍只识别一个结果，不按目标技能生成重复候选。

### 10.2 桌面端非 Wasm E2E

在现有技能管理 E2E 中覆盖：

1. 创建 Q、W、E、R 和一个装备技能目录记录。
2. 在 Q 的效果中新增一个“冷却变化”结果，选择 Q、W、E、R，操作为减少。
3. 保存请求只有一个结果，目标列表有四项且没有装备技能。
4. 重开结果弹窗完整显示四个标签。
5. 编辑移除 Q 后保存，回读只显示 W、E、R。
6. 空列表不能保存；目录失败保留草稿。
7. 已有停用目标可见可保留，新停用目标不可选。
8. 阶段 7.5“条件与触发”入口仍可选择该效果，动作和前序结果不重复展开。

## 12. 前端停止条件

出现以下任一情况必须停止：

1. 后端仍返回或要求旧 `affectedSkillKey`。
2. 后端把一个多选拆成多个结果，导致结果标识或前序结果身份变化。
3. 页面必须手写 JSON、自定义 CSS 或新增独立页面才能保存。
4. 需要根据角色/装备挂载自动展开技能集合。
5. 阶段 7.5 动作或前序结果把同一多目标结果展开为多个候选。
6. 实现需要修改移动端、Wasm、发布、计算输入或阶段 7.6 业务字段。
