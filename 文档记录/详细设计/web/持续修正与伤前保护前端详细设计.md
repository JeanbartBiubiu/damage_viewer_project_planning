## 4. 类型与客户端契约

### 4.1 效果类型

`skillEffect.ts` 在阶段 7.6.1 八种结果上增加：

1. `DAMAGE_MODIFIER` 及强类型 detail。
2. `HEALING_MODIFIER` 及强类型 detail。
3. `DAMAGE_IMMUNITY` 及强类型 detail。
4. `HEALTH_FLOOR` 及强类型 detail。

请求和响应继续使用封闭判别联合，不能改为全部字段可选的宽接口。结果公共字段仍不含 `spellShieldBlockScope`；本阶段类型、草稿和请求都不得提前预留该字段。

### 4.2 触发规则类型

在阶段 7.5/7.6.1 最终类型上：

1. 事件联合增加 `DAMAGE_PENDING`，detail 复用三项伤害筛选类型。
2. 事件总数精确为十八种。
3. 事件值联合在既有集合上追加 `RAW_DAMAGE / POST_DEFENSE_DAMAGE / HEALTH_BEFORE / PROJECTED_HEALTH_AFTER`。
4. `PRIOR_ACTION_RESULT.outputKind` 仍只允许 `CONFIGURED_VALUE`。
5. 不增加法术护盾、联动事件或后段事件值的隐藏联合成员。

### 4.3 客户端响应检查

开发环境最小协议检查增加：

1. 四种结果 detail、数值规则有无和生命周期行为基本形状。
2. `DAMAGE_PENDING` detail 与四种事件值字符串。
3. 后端返回未知后段结果、事件、事件值或公共字段时抛明确协议错误。

客户端不得静默删除字段、补业务默认或把未知类型当空对象显示。

## 5. 效果草稿、默认值与映射

`effectForm.ts` 增加四种结果的完整草稿：

1. `fromDetail` 无损保留固定枚举、null、稳定结果键和未知/停用旧目录引用。
2. `toCreateRequest / toUpdateRequest` 只输出当前结果种类合法 detail、数值规则和生命周期行为，不提交隐藏字段。
3. 切换结果种类时重建 detail 和数值规则；旧种类的伤害、护盾或其他特殊字段必须清除。
4. 四种结果都要求父效果已有生命周期且当前结果为持续生效。父效果不满足时显示阻塞说明；只有用户确认后才复用阶段 7.4 既有生命周期默认初始化，不能另造一套默认值或静默改父聚合。
5. 用户取消生命周期调整时保持原草稿和原结果种类，不留下半转换结果。
6. 保存成功后始终使用后端完整详情重建草稿，不用本地推测摘要、目录名称或默认值。

## 6. 四种结果编辑

### 6.1 伤害修正

按共享契约显示：

1. 作用方向：造成的伤害、受到的伤害。
2. 修正方式：提高、降低。
3. 伤害类型：全部或明确伤害类型。
4. 产生方式：全部、技能、普通攻击。
5. 来源性质：全部、直接伤害、反伤。
6. 暴击过滤：全部、仅暴击、仅非暴击。
7. 既有数值规则编辑区，字段标签明确为“修正比例公式”。

页面不把比例换算为百分比结果，不预览最终伤害。

### 6.2 治疗修正

显示造成/受到、提高/降低、全部/直接治疗/吸血和数值规则。字段标签明确为“修正比例公式”，不计算最终治疗。

### 6.3 伤害免疫

显示伤害类型、产生方式和来源性质，不显示数值规则。固定提示：“伤害免疫只处理匹配伤害，不等于法术护盾，也不会自动阻止其他结果。”

### 6.4 生命下限

显示数值属性目录和既有数值规则，字段标签为“生命下限公式”。页面不按 `hp`、中文名或排序猜测生命属性；由数据维护者明确选择。

## 7. 生命周期同步校验

在阶段 7.4 规则上增加：

1. 四种结果只允许 `PERSISTENT`。
2. 伤害修正、治疗修正固定 `APPLICATION_SNAPSHOT`，允许共享值或每层值。
3. 共享值显示保留、覆盖、相加；每层值隐藏并清空重复施加值方式。
4. 伤害免疫隐藏并清空数值读取、层数值和重复施加值字段。
5. 生命下限固定 `APPLICATION_SNAPSHOT + SHARED`，重复施加只显示保留、覆盖。
6. 把父生命周期或结果时点改成不合法形状时，列出受影响结果并要求确认；确认后按阶段 7.4 清理规则执行，取消则保留原草稿。
7. 页面不静态求值公式来判断比例、下限或持续时间。

## 8. 结果列表与目录

1. 结果种类选择器按固定顺序追加四个中文选项。
2. 结果表继续使用一个紧凑摘要列，不为每个过滤项增加窄列。
3. 伤害修正摘要组合方向、提高/降低和关键过滤；治疗修正组合方向、提高/降低和治疗种类；免疫显示关键伤害过滤；生命下限显示属性名称。
4. 公式、属性和伤害类型目录复用现有请求与会话缓存；不重复加载同一目录。
5. 停用/未知旧引用只读保留；新增或改选时不可选择。目录失败保留草稿、禁止保存并允许重试。

## 9. 即将受到伤害事件编辑

1. 在事件选择器增加中文“即将受到伤害”。
2. 复用阶段 7.6.1 伤害筛选组件，显示伤害类型、产生方式和来源性质。
3. 切换到其他事件时清除 `DAMAGE_PENDING` detail，不保留隐藏筛选。
4. 当前目标说明固定为“技能拥有者自身”，事件来源对象说明为“本次候选伤害来源对象”。
5. 选择执行反伤效果时，允许事件从仅“受到伤害”扩展为“即将受到伤害/受到伤害”；动作目标、直接来源过滤或每目标冷却要求保持不变。
6. 前端只做同步提示和明显非法组合拦截，完整候选图仍由后端校验。

## 10. 事件值、条件与动态输入

事件值选择器使用固定能力表：

1. `DAMAGE_PENDING` 只显示“原始伤害、防御后伤害、受伤前生命、预计受伤后生命”。
2. 四项可用于既有事件值比较条件和事件值动态输入来源。
3. 其他十七种事件保持原能力，不显示本阶段四项。
4. 不显示护盾吸收、实际扣血、阻挡、免疫、击杀、本次联动序号或总次数。
5. 事件或时点变化导致现有条件/绑定失效时，列出将清理项并要求确认；取消则保持原草稿。
6. 页面显示参数整数/小数兼容错误，但不执行事件值或公式。

## 11. 动作可达公式与占用错误

`triggerRuleForm.ts` 在阶段 7.5/7.6.1 收集表上追加三种新数值结果的 `valueRule.formulaKey`：

1. 执行效果和启动过程通过直接效果挂接到达时都收集。
2. 公式中的运行输入参数继续要求恰好一个绑定。
3. 规则自身保存的缺失、多余或类型错误显示为 400 绑定错误，并定位规则动作/绑定。
4. 效果公式变更被既有规则占用时显示 409，定位结果公式字段，列出后端返回的有序规则/动作/参数，并提示先处理依赖规则。
5. 不允许预先多绑参数，也不在页面增加跨聚合批量保存。

## 12. 前端同步校验与错误定位

提交前至少校验：

1. 四种 detail 完整且没有其他种类字段。
2. 数值规则有无与生命周期矩阵合法。
3. 伤害类型、属性和公式目录已成功加载，新增引用不是未知/停用项。
4. `DAMAGE_PENDING` 筛选完整、事件值属于能力表。
5. 反伤事件、动作目标、来源过滤和每目标冷却组合。
6. 三种新结果公式的可达参数绑定集合。

后端字段路径映射增加：

1. `results[i].detail.*` → 当前新结果专属区。
2. `results[i].valueRule.*` → 当前数值规则区。
3. `results[i].lifecycleBehavior.*` → 生命周期行为区。
4. `eventSource.detail.*` → 伤害筛选区。
5. 条件或绑定中的 `eventValueKey` → 对应事件值选择器。

未知字段问题显示在当前弹窗顶部并保留服务端详情；不能把英文原因码作为主要用户文案。
