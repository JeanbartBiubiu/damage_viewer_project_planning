## 1. 页面职责

新增独立“状态管理”页面，用于：

1. 查询状态基本资料。
2. 新建、查看和编辑状态。
3. 从列表直接启用、停用和删除状态。

页面不维护状态分类、持续时间、层数、刷新、周期、技能效果、角色或装备挂载和计算配置。

## 2. 写入范围

开发获批后，允许写入：

1. `web/src/types/status.ts`
2. `web/src/services/statusClient.ts` 及对应测试
3. `web/src/pages/admin/statuses/**`
4. `web/src/App.tsx`
5. `web/src/config/navigation.ts` 及对应测试
6. `web/tests/e2e/non-wasm-pages.spec.ts`
7. 与新页面入口直接相关的 `web/README.md`

不得修改全局弹窗样式、旧能力页面、旧 Provider 页面、combat-data 客户端、计算页面或 Wasm 适配器。

## 3. 路由与导航

1. `StaticRouteId` 增加 `statuses`，地址为 `#/statuses`。
2. 导航名称固定为“状态管理”，放在“技能管理”之后、“游戏配置”之前。
3. `App.tsx` 的 `STATIC_ROUTE_IDS` 明确加入 `statuses`，同时增加 `StatusManagementPage` 的静态页面分支，并继续传入 `apiBaseUrl`、`selectedGameId`、`adminToken` 和现有未保存状态回调。
4. 不增加“状态中心”“规则中心”“基础配置”等新产品名称。

## 4. 客户端类型与接口

`web/src/types/status.ts` 定义：

1. `StatusRecordStatus = 'ENABLED' | 'DISABLED'`
2. `GameStatus`
3. `StatusListQuery`、`StatusListResponse`
4. `CreateStatusRequest`、`UpdateStatusRequest`

类型字段严格遵循共享契约。`UpdateStatusRequest` 不包含 `statusKey`。

`statusClient.ts` 提供：

1. `listStatuses`
2. `getStatus`
3. `createStatus`
4. `updateStatus`
5. `deleteStatus`

所有路径片段使用 `encodePathSegment`，所有请求使用现有 `requestJson` 和 Admin Token。列表只在草稿实际应用后发送规范化的 `keyword` 和 `status`。

## 5. 文件与组件

`web/src/pages/admin/statuses/**` 包含：

1. `StatusManagementPage.tsx`
2. `StatusEditorModal.tsx`
3. `statusForm.ts`
4. `statusForm.test.ts`

页面复用现有管理页的 `Panel`、Arco `Table`、`Radio.Group`、默认 `Modal` 和现有错误解析，不新增页面专用弹窗样式或通用 CRUD 框架。

## 6. 页面状态与查询

页面分别维护：

1. 关键词草稿和状态草稿。
2. 已应用查询条件。
3. 列表、总数、加载错误和成功提示。
4. 资料弹窗、启停确认、删除确认及各自提交状态。
5. 最新请求序号，避免旧请求覆盖切换游戏或新查询后的结果。

状态筛选固定使用“全部 / 启用 / 停用”按钮式单选。查询只应用当前草稿；重置同时清空草稿和已应用条件并重新加载。切换游戏时清空弹窗、查询、提示和未保存状态。

## 7. 列表与操作

列表列固定为：

1. 状态名称
2. 状态标识
3. 说明
4. 启停状态
5. 排序
6. 更新时间
7. 操作

操作提供“查看”“编辑”“停用/启用”“删除”。启停和删除使用组件库默认确认弹窗。操作成功后关闭确认弹窗并刷新当前已应用查询；失败时保留弹窗并显示错误。

## 8. 资料弹窗

新增、查看和编辑共用 `StatusEditorModal`：

1. 新增字段：状态标识、状态名称、说明、排序；提交时状态固定为 `ENABLED`。
2. 编辑字段：状态名称、说明、排序；状态标识只读，提交时完整保留当前启停状态。
3. 查看模式全部只读，并显示启停状态、创建时间和更新时间。
4. 前端校验标识格式、名称、说明长度和非负整数排序；后端继续执行最终校验。
5. 创建默认排序为 0；空说明提交 null。
6. 服务端 `details.fieldIssues` 映射到 `statusKey`、`name`、`description` 和 `sortOrder`；无法定位的错误显示在弹窗顶部。

## 9. 弹窗与页面行为

1. 资料、启停和删除确认全部使用 Arco 默认 Modal。
2. 不覆盖弹窗边框、阴影、位置或宽度样式。
3. 资料弹窗允许点击遮罩或按 Esc 关闭，直接丢弃未保存内容。
4. 保存成功先关闭资料弹窗，再刷新列表；保存失败保留输入和字段错误。
5. 页面不显示用途说明、学习提示或引导段落。
6. 空列表只显示“暂无状态”。
7. 没有选择游戏或缺少 Admin Token 时沿用现有功能性警告，不增加教学文案。

## 11. 前端停止条件

1. 后端最终接口与共享契约不一致。
2. 实现必须依赖旧状态、Provider、Ability 或 combat-data 接口。
3. 页面必须提前录入状态分类、生命周期、技能效果或计算字段。
4. 实现必须修改全局弹窗样式、建立通用 CRUD 框架或恢复旧页面。
5. 完整前端验证不可用，且定点复查不能确认原因。

出现任一项时停止开发并回到共享契约确认。
