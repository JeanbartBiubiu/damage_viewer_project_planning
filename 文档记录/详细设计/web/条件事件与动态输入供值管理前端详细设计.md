## 3. 类型与客户端

### 3.1 强类型

在 `skillTriggerRule.ts` 建立：

1. `SkillTriggerRuleSummary`、`SkillTriggerRuleDetail`、创建请求和更新请求。
2. `SkillTriggerEventSource` 与 17 种事件的强类型联合。
3. 条件组、四种条件和各自专属明细联合。
4. 三种动作、四种动态输入来源和固定结果修正联合。
5. 每目标冷却、单次过程最大触发次数、目标上下文和固定比较符。
6. 前端固定事件能力表：逐行照搬共享契约第 5.2 节的中文名称、当前目标绑定、是否有事件来源对象、允许事件值、需要的引用目录和合法明细字段；不得在前端自行补充事件能力。

联合类型使用 `eventType`、`conditionType`、`actionType` 和 `sourceType` 判别，不能用一个全部字段可选的宽接口。技术标识只出现在代码与高级说明，页面字段使用共享契约中文名称。

### 3.2 客户端

`skillTriggerRuleClient` 只提供：

1. `listSkillTriggerRules`
2. `getSkillTriggerRule`
3. `createSkillTriggerRule`
4. `updateSkillTriggerRule`
5. `deleteSkillTriggerRule`

所有路径片段使用 `encodeURIComponent`，沿用 Admin Token、统一成功响应和错误外壳。客户端在开发环境对响应做判别联合最小形状检查，发现后端返回事件或子项种类与明细不匹配时抛出明确协议错误。

不增加事件、条件、动作、绑定、修正或排序的独立客户端方法。

## 4. 草稿模型与映射

`triggerRuleForm.ts` 独占接口对象和表单草稿之间的转换：

1. 为新建条件组、条件、动作和绑定生成仅用于当前草稿的临时稳定标识初值；保存前仍按共享格式校验。
2. `fromDetail` 必须无损保留所有稳定标识、null、固定数值和排序。
3. `toCreateRequest` 提交 `ruleKey`；`toUpdateRequest` 明确移除 `ruleKey`。
4. 切换事件、条件、动作或来源种类时重建对应明细，只保留共享字段，不把旧种类隐藏字段带入请求。
5. 条件组、条件和动作按稳定排序显示；拖动或上移下移只调整 `sortOrder`，并在并列时保留稳定键顺序。
6. `FAIL_PROCESS` 自动保持最后；用户移动到非最后位置时立即阻止并显示中文原因。
7. 删除或重排被后续绑定引用的动作时，先列出受影响绑定并要求确认；确认后删除失效绑定，取消则保持草稿不变。
8. 保存成功后以服务端完整详情重新初始化草稿，避免本地推测更新时间或排序。

## 5. 规则管理弹窗

### 5.1 页面入口

`SkillManagementPage` 在技能行操作中增加“条件与触发”。点击后打开：

```text
条件与触发 - {技能名称}
```

不新增路由、主导航或技能详情页。

### 5.2 列表

列表显示：

1. 名称和稳定标识。
2. 中文事件类型。
3. 条件组数和动作数。
4. 是否配置每目标冷却、单次过程最大触发次数。
5. 排序和更新时间。
6. 编辑、删除操作。

空态使用“当前技能还没有条件与触发规则”。删除前显示规则名称；规则没有外部入站引用，删除只处理成功、父级或规则 404 和普通请求失败，不虚构规则自身 409 场景。

列表只读取摘要，不为每行加载详情或目录。

## 6. 规则编辑弹窗

使用一个桌面宽弹窗，按以下顺序分区：

1. 基本信息。
2. 事件来源。
3. 条件组。
4. 有序动作。
5. 触发保护。

弹窗底部固定“取消 / 保存”。存在未保存修改时关闭需要确认。请求进行中禁用重复提交、删除子项和关闭。

### 6.1 基本信息

新建时填写稳定标识、名称、说明和排序；编辑时稳定标识只读。不要增加启用状态、规则分类或自由标签。

### 6.2 事件来源

1. 先选择中文固定事件，再按类型显示专属字段。
2. 技能、过程、步骤、效果、结果、状态、属性、公式和内部状态都使用目录选择。
3. 过程时点复用阶段 7.3 中文时点，选择步骤型时点后才显示步骤。
4. 生命周期时点只显示施加、满层、周期、自然结束和提前移除，不显示“持续生效”。
5. 结果事件只展示无生命周期效果中的结果；生命周期效果统一展示五个离散生命周期时点，前端目录过滤不是安全边界，后端仍负责最终校验。
6. 切换事件导致条件事件值、动作事件来源对象或保护失效时，页面列出影响并要求确认后再清理。

## 7. 条件组编辑

### 7.1 条件组展示

条件区顶部固定说明：

```text
不添加条件时直接触发；多个条件组满足任意一组即可，同一组内必须全部满足。
```

每个组使用卡片显示名称、条件中文摘要、排序、编辑和删除。组内条件列表明确使用“并且”，组之间显示“或者”，不使用需要用户理解的条件树术语。

### 7.2 条件编辑器

四种条件分别显示：

1. 属性比较：对象、属性、属性取值、比较符、比较公式。
2. 战斗状态检查：对象、状态、存在方式；检查层数或剩余时间时再选择当前技能的生命周期效果和状态施加结果、比较符及公式。
3. 技能内部状态检查：内部状态；按种类显示数值比较、模式选项、准备标记布尔值或剩余时间。
4. 事件值比较：只显示当前事件允许的事件值、比较符和公式。

选择 `EVENT_SOURCE` 前先检查当前事件能力；不可用时不展示该选项。修改引用对象导致下游字段不再合法时同步清空并显示原因。

## 8. 有序动作编辑

### 8.1 动作列表

动作卡片显示顺序、中文动作类型、目标对象、目标效果或过程、绑定数和修正数。支持新增、编辑、删除、上移和下移，不提供画布连线或自由流程图。

### 8.2 执行效果

编辑字段：

1. 动作名称、稳定标识和排序。
2. 目标对象为当前目标或事件来源对象。
3. 当前技能效果。
4. 动态输入来源绑定。
5. 固定结果修正。

固定结果修正只展示目标效果具有数值规则的结果，每个结果最多一项。字段名称为“额外固定倍率”“额外固定最小值”“额外固定最大值”，并显示应用在效果基础修正之后。

### 8.3 启动过程

编辑目标对象、当前技能过程和动态输入来源绑定。不显示结果修正。过程启动方式仅作只读说明，不用前端推断事件。

### 8.4 令过程失败

编辑当前技能过程和五种中文失败原因。不显示目标对象、绑定或修正，并固定为规则最后动作；请求中的 `targetContext` 为 null。

## 9. 动态输入绑定编辑

### 9.1 可达参数加载

选择动作目标后，前端按需加载：

1. 目标效果或过程详情。
2. 过程直接挂接的效果详情。
3. 过程操作引用且会提供初始值或内部冷却时长的内部状态详情。
4. 这些对象按共享契约第 8.1 节封闭表引用的公式详情。
5. 公式节点实际引用的当前技能参数详情。

去重后只展示 `RUNTIME_INPUT` 参数。读取结果按 `gameId/skillKey/formulaKey` 缓存在当前弹窗会话；关闭弹窗即释放，不写全局状态或本地持久化。

加载失败时保留已编辑草稿、禁止保存并提供“重新加载引用”。不得因某个目录失败提交不完整绑定。

### 9.2 完整性提示

参数区按每个可达参数显示：

1. 参数中文名称、稳定标识和整数/小数类型。
2. 当前来源类型与中文摘要。
3. 缺少绑定、重复绑定、未使用绑定和值类型不兼容提示。

新建动作时可以暂时缺少绑定，但规则保存前必须恰好完整。动作目标改变后重新计算可达参数，并列出将被移除的无效绑定。

### 9.3 四种来源

1. 技能内部状态：按状态种类展示数值、模式是否选中、准备标记是否启用或剩余毫秒。
2. 战斗状态：展示对象、状态和存在/层数/剩余时间；后两者要求选择明确生命周期效果和状态施加结果。
3. 当前事件值：只展示当前事件白名单。
4. 更早动作基础结果：只展示排序更早的执行效果动作及其即时数值结果，结果来源固定显示“基础结果值”。

来源摘要不得显示阶段 7.6 尚未开放的防御后伤害、护盾吸收、实际扣血、实际治疗、阻挡、免疫或击杀。

## 10. 触发保护与循环错误

### 10.1 每目标冷却

开关开启后选择同技能时长公式和目标对象。事件没有事件来源对象时只显示当前目标。

### 10.2 单次过程最大触发次数

只有事件来源为 `PROCESS_MOMENT` 时显示该开关；开启后过程固定为事件来源过程，只选择次数公式。页面说明本阶段只保存规则，不执行计数。其他事件切换到来时清空该保护并要求确认。

### 10.3 循环错误

前端不复制后端保守图算法。保存返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED` 时：

1. 保留全部草稿。
2. 在触发保护区显示“当前关系形成没有保护的循环”。
3. 若 `details` 返回参与规则和动作，按当前技能可识别名称列出；陌生键原样安全显示。
4. 提示可增加每目标冷却、单次过程最大触发次数或调整关系，不自动替用户添加保护。

## 11. 目录加载与失效处理

打开管理弹窗只加载规则摘要。打开新建或编辑时并行加载当前技能必需目录：

1. 技能、属性和状态摘要。
2. 当前技能参数、公式、效果、过程和内部状态摘要。
3. 编辑已有规则时加载完整规则详情。

效果、过程、内部状态和公式详情按字段选择懒加载并在弹窗会话缓存。各目录独立显示错误；缺少当前表单必需目录时禁止保存，其他暂未使用目录失败不阻塞基本信息编辑。

停用引用规则：

1. 已有停用状态、属性或来源技能继续显示并标记“已停用”。
2. 新增选择器默认不提供停用记录。
3. 用户改变已有引用后不能重新选回停用记录，最终以后端引用校验为准。

## 12. 前端同步校验

提交前至少检查：

1. 基本字段、稳定标识、重复组/条件/动作/绑定标识。
2. 至少一个动作，每个条件组至少一个条件，失败动作唯一且最后。
3. 事件、条件、动作和来源专属字段完整且无旧种类残留字段。
4. 当前事件是否提供事件来源对象和所选事件值。
5. 状态层数/剩余时间引用是否选择完整效果与结果。
6. 动态输入绑定是否与当前动作可达参数集合完全一致，值类型是否兼容。
7. 前序动作是否仍排在当前动作之前，来源是否为即时数值结果。
8. 固定结果修正至少一项非空、倍率非负、最小值不大于最大值。
9. 两类触发保护字段是否成组完整。
10. 事件、条件和两类保护直接引用的公式详情中不得出现 `RUNTIME_INPUT` 参数。

前端不尝试判断全技能循环、数据库引用完整性或公式最终正数；这些由后端负责。

## 13. 后端字段错误映射

`triggerRuleForm.ts` 提供字段路径映射：

1. `eventSource.detail.*` 定位事件区。
2. `conditionGroups[i].conditions[j].detail.*` 定位具体条件卡片和编辑器。
3. `actions[i].detail.*` 定位动作目标。
4. `actions[i].runtimeInputBindings[j].*` 定位具体参数绑定。
5. `actions[i].resultModifiers[j].*` 定位具体结果修正。
6. `perTargetCooldown.*`、`maxTriggersPerProcess.*` 定位触发保护。

无法识别的新字段路径显示在弹窗顶部通用错误区，不丢弃服务端 `code/message/details`，也不把英文原因码直接当主要用户文案。

## 14. 弹窗与并发行为

1. 管理弹窗关闭时同时关闭其规则编辑子弹窗和引用选择子弹窗。
2. 打开效果或过程详情只用于核对引用时保持规则草稿，不允许从规则弹窗同时修改被引用聚合。
3. 保存、删除期间禁用相关操作；其他规则不做乐观本地改写，成功后重新拉列表。
4. 后端返回 404 表示规则或父级已被其他会话删除时，提示并刷新列表；草稿可保留供用户查看，但不能继续覆盖不存在记录。
5. 后端返回 409 或 400 时保持弹窗和草稿，聚焦第一个可定位字段。
6. 参数删除返回 `409.SKILL_PARAMETER_IN_USE` 时，既有文案改为“该参数正在被技能公式或条件与触发规则使用，不能删除”；公式删除沿用服务端具体消息，不能只解释为效果引用。
7. 内部状态删除返回 `409.SKILL_INTERNAL_STATE_IN_USE` 时，既有文案改为“该内部状态正在被技能过程或条件与触发规则使用，不能删除”。

## 15. 自动验证

### 15.1 客户端和表单单元测试

至少覆盖：

1. 五个客户端路径、编码、请求体和响应解析。
2. 17 种事件能力表、确定当前目标、三种事件来源对象能力、精确事件值白名单与专属明细转换。
3. 四类条件、三类动作、四类来源的联合转换和旧字段清理。
4. 创建请求含 `ruleKey`，更新请求不含 `ruleKey`。
5. 条件组“组间或、组内且”的草稿排序与摘要。
6. 失败动作保持最后，删除或重排来源动作的绑定清理确认。
7. 可达公式详情去重缓存、参数集合、缺失/多余绑定和值类型兼容。

## 18. 前端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.4 最终效果详情、生命周期时点或生命周期操作与本方案前提不一致。
2. 后端五个规则接口不能完整回读联合类型，前端必须调用子项接口拼装半成品。
3. 页面必须手写 JSON、自由表达式或数据库复合键才能保存规则。
4. 动态输入绑定必须执行公式、读取某次运行值或建立全局计算变量才能确定。
5. 需要在前端复制全技能循环算法才能完成基本录入。
6. 需要修改阶段 7.2～7.4 页面和公共类型契约，而不只是读取目录或增加入口。
7. 实现需要增加阶段 7.6 丰富结果、战斗结算、计算预览、发布、Wasm 或移动端专属行为。
