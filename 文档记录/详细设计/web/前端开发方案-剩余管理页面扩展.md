# 前端开发方案-剩余管理页面扩展

更新时间：2026-03-25

## 1. 目标

在现有 4 个资源页的基础上，把剩余可编辑资源也补齐成同样的传统 CRUD 页面。

本轮新增页面范围：

1. `heroes`
2. `skills`
3. `items`
4. `attribute-definitions`
5. `types`
6. `type-relations`

不在本轮范围内：

- 图片缓存页重构
- 版本发布页重构
- 删除能力
- 分页能力
- PATCH 交互
- get by id 交互

## 2. 页面原则

所有新增页面必须严格复用已经落地的 4 个资源页布局：

1. 查询卡片
2. 表格卡片
3. 表格右上角 `新增`
4. 表格最右侧固定操作列
5. 查看 / 编辑 / 新增统一使用弹窗
6. 列表展示全量数据，不分页
7. 保存统一走 `PUT`

不允许重新引入：

- 右侧编辑栏
- 页面内发布侧轨
- 多资源共用一个工作台页

## 3. 左侧菜单与路由

### 3.1 左侧菜单新增项

新增 6 个一级菜单项，与现有 4 个资源页和“图片缓存”保持同级：

1. `英雄`
2. `技能`
3. `装备`
4. `属性定义`
5. `类型定义`
6. `类型挂载`

### 3.2 路由建议

新增路由：

- `#/heroes`
- `#/skills`
- `#/items`
- `#/attribute-definitions`
- `#/types`
- `#/type-relations`

需要同步修改：

- `web/src/config/navigation.ts`
- `web/src/App.tsx`

## 4. 文件结构

每个资源页都建独立文件夹，沿用现有目录规范：

```text
web/src/pages/admin/resources/{resource-name}/
  constants.ts
  types.ts
  search.tsx
  columns.tsx
  table.tsx
  modal.tsx
  index.tsx
```

共享层继续沿用：

```text
web/src/pages/admin/resources/shared/
```

本轮优先复用：

- `useCrudResourcePage.ts`
- `json.ts`

如新增共享逻辑，只允许放在 `shared/`，不要把 6 个资源重新写成一个超级组件。

## 5. 前端基础补齐项

在落页面前，需要先补齐前端基础层：

补充以下响应类型：

- `HeroesResponse`
- `SkillsResponse`
- `ItemsResponse`
- `AttributeDefinitionsResponse`
- `TypesResponse`
- `TypeRelationsResponse`

### 5.2 `services/apiClient.ts`

补充以下接口函数：

- `getHeroes`
- `putHero`
- `getSkills`
- `putSkill`
- `getItems`
- `putItem`
- `getAttributeDefinitions`
- `putAttributeDefinition`
- `getTypes`

## 7. 共享实现约束

### 7.1 统一交互

6 个新增页面全部复用 `useCrudResourcePage` 语义：

- `createSearchData`
- `createFormData`
- `listRecords`
- `saveRecord`
- `filterRecords`
- `toFormData`

不要为某一页单独引入不同交互范式。

### 7.2 JSON 处理

沿用现有 JSON 解析能力，必要时补充：

- `parseJsonObjectText`
- `parseJsonNumberArrayText`
- `parseJsonStringArrayText`

其中：

- `skillRefs`
- `recipeIds`
- 可能需要新的字符串数组解析函数

### 7.3 文案约束

新增页面的标题、按钮、字段说明全部使用中文后台文案，保持与已完成 4 页一致。

## 8. 实施顺序

建议按以下顺序开发：

### Phase 1：前端基础层

1. 扩展 `types/api.ts`
2. 扩展 `services/apiClient.ts`
3. 扩展 `navigation.ts`
4. 扩展 `App.tsx`

### Phase 2：简单资源页

优先实现结构简单的 3 页：

1. `attribute-definitions`
2. `types`
3. `type-relations`

### Phase 3：中等复杂资源页

再实现：

1. `heroes`
2. `items`

### Phase 4：复杂资源页

最后实现：

1. `skills`

原因：

- `skills` 字段最多，JSON 域最多
- 可能还涉及 `ownerType` 选项来源

## 9. 验收标准

完成后必须满足：

1. 左侧菜单出现 6 个新资源页入口
2. 每个页面结构与现有 4 个资源页一致
3. 每个页面都有查询卡片和表格卡片
4. 每个页面表格右上角都有 `新增`
5. 每个页面操作列固定在最右侧
6. 每个页面新增 / 查看 / 编辑都走弹窗
7. 每个页面列表不分页
8. 每个页面写入统一使用 `PUT`
9. `npx tsc -b` 通过
10. `npm run build` 通过
