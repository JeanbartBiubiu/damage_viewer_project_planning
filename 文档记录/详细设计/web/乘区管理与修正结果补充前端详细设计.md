## 1. 当前页面事实与前置依赖

1. 当前应用由 `web/src/config/navigation.ts` 和 `web/src/App.tsx` 维护静态导航与 Hash 路由，尚无乘区入口。
2. 伤害类型管理已经提供独立列表、默认弹窗、客户端、表单和测试，可作为乘区基本管理的页面结构参考。

5. 页面不执行公式、属性、伤害、治疗或乘区聚合；本轮只保存、回读和校验。
6. 本项目只验收桌面页面，不增加移动端布局或移动设备测试。

## 2. 前端职责与非目标

前端负责：

1. 执行或预览同区加算、跨区相乘、属性、伤害、治疗或舍入。

## 4. 类型与客户端

### 4.1 乘区类型

`modifierZone.ts` 按共享契约定义封闭类型：

1. `ModifierZoneDomain`
2. `ModifierZoneCalculationMode`
3. `ModifierZoneApplicationStage`
4. `ModifierZoneStatus`
5. `ModifierZone`
6. `ModifierZoneListQuery / ModifierZoneListResponse`
7. `CreateModifierZoneRequest / UpdateModifierZoneRequest`

不得把固定枚举降级为任意字符串，也不得增加旧 `bucketConfig` 或页面专用隐藏字段。

### 4.2 客户端

`modifierZoneClient.ts` 实现共享契约五个接口：

1. 所有路径段使用现有 `encodePathSegment`。
2. 关键词 trim 后为空不发送；作用范围和状态有值时发送。
3. POST/PUT 只提交共享请求字段。
4. DELETE 复用统一空响应处理。
5. 开发环境响应检查拒绝未知作用范围、计算方式、阶段、状态和非法固定组合。

客户端不缓存为全局永不过期目录。独立页面每次显式刷新；结果弹窗按当前打开会话缓存，新增乘区成功后强制刷新。

### 4.3 效果类型

1. `SkillEffectDamageModifierDetail` 增加必填 `modifierZoneKey`。
2. `SkillEffectHealingModifierDetail` 增加必填 `modifierZoneKey`。
3. `SkillEffectAttributeChangeDetail` 增加可空 `modifierZoneKey`。
4. 其他结果联合不得出现该字段。
5. 请求、响应和草稿继续使用判别联合，不改成全部字段可选的宽对象。

## 5. 导航与独立页面

### 5.1 路由

1. `StaticRouteId`、静态路由集合和页面分支增加 `modifier-zones`。
2. Hash 固定为 `#/modifier-zones`。
3. 导航标签为“乘区管理”，位置在“伤害类型管理”和“技能管理”之间。
4. 导航摘要保持空字符串；页面不增加入门教学或阶段说明。

### 5.2 列表

页面结构复用当前伤害类型管理：

1. 关键词输入。
2. 作用范围筛选：全部、属性、伤害、治疗。
3. 状态筛选：全部、启用、停用。
4. 查询、重置、刷新和新增乘区。
5. 表格列：乘区名称、稳定标识、作用范围、计算方式、结算阶段、状态、更新时间、操作。
6. 操作：查看、编辑、启用/停用、删除。

页面不显示技能数量、反向引用列表或聚合计算结果。删除被占用时使用后端 409 文案，不提前加载所有技能做客户端判断。

### 5.3 新建、查看和编辑弹窗

使用组件库默认 Modal 与表单，不新增自定义边界样式。

字段顺序：

1. 稳定标识
2. 乘区名称
3. 作用范围
4. 计算方式
5. 结算阶段
6. 说明
7. 状态
8. 排序

交互：

1. 稳定标识创建后只读。
2. 作用范围或计算方式变化时，只显示兼容结算阶段并清除不兼容旧值。
3. 查看模式全部只读。
4. 已引用乘区若后端拒绝结构修改，弹窗保留草稿并定位字段；前端不伪造引用计数。
5. 保存成功关闭弹窗并刷新列表；失败保留草稿。
6. 关闭、遮罩点击和 Esc 直接关闭并丢弃当前乘区草稿，保持现有管理页约定。

## 6. 结果草稿与映射

`effectForm.ts` 增加一个可空 `modifierZoneKey` 草稿字段，并按结果种类严格映射：

1. 伤害修正和治疗修正从详情完整回填，提交时必填。
2. 属性变化从详情回填；只有 `PERSISTENT + INCREASE/DECREASE` 提交该字段。
3. 离散属性变化、属性覆盖和其他结果提交前清空该字段。
4. 新建伤害/治疗修正时不自动选择第一个乘区；用户必须明确选择或新建。
5. 从其他结果切换到修正结果时清空旧乘区；从修正结果切换出去时清空乘区。
6. 保存成功后使用后端完整详情重建草稿，不以当前目录名称拼接响应。

目录项保留 `modifierZoneKey / name / domain / calculationMode / applicationStage / status`，用于筛选、标签和旧引用显示。

## 7. 乘区选择器

### 7.1 兼容过滤

1. 属性持续增加/减少只显示 `ATTRIBUTE`。
2. 伤害修正只显示 `DAMAGE + RATIO_ADD`。
3. 治疗修正只显示 `HEALING + RATIO_ADD`。
4. 属性覆盖和离散属性变化不显示乘区选择器。
5. 停用乘区不出现在新增选项；当前详情引用停用或未知乘区时，额外插入只读旧选项并标识状态。

选项文本至少包含“名称 / 计算方式 / 结算阶段”，不能只显示稳定标识。下拉选项不展示来源技能或长说明。

### 7.2 明确新增入口

乘区选择器右侧放置“新增乘区”按钮：

1. 点击后打开 `ModifierZoneEditorModal`，父结果和父效果弹窗保持打开。
2. 从属性结果打开时锁定 `domain = ATTRIBUTE`；从伤害/治疗结果打开时分别锁定对应作用范围和比例加算。
3. 用户仍需明确填写稳定标识、名称、计算方式允许项、阶段、状态和排序。
4. 保存成功后关闭乘区弹窗、重新请求目录、自动选择新 `modifierZoneKey`，但不自动保存结果或效果。
5. 保存失败保留乘区草稿和父效果草稿。
6. 取消新增只关闭乘区弹窗，不清空父结果现有选择。
7. 禁止在 Select 中输入不存在的文本后自动创建。

## 8. 三种修正结果编辑

### 8.1 属性变化

1. 先选择操作和属性。
2. 只有父效果有生命周期、结果为持续生效且操作是增加/减少时显示必填乘区。
3. 选择 `FLAT_ADD` 后，数值规则标题为“固定属性修正公式”。
4. 选择 `RATIO_ADD` 后，标题为“比例属性修正公式”，辅助值示例只说明 `0.15` 表示 15%，不显示教学段落。
5. 操作为覆盖或结果改成离散时，清空乘区并恢复原数值规则标题。

### 8.2 伤害修正

1. 保留作用方向、提高/降低、伤害类型、产生方式、来源性质和暴击过滤。
2. 增加必填“所属乘区”。
3. 回归基本功仍通过“产生方式 = 技能”配置，不在乘区上增加技能/普攻字段。
4. 公式标题保持“修正比例公式”。

### 8.3 治疗修正

1. 保留造成/受到、提高/降低和治疗种类。
2. 增加必填“所属乘区”。
3. 公式标题保持“修正比例公式”。

### 8.4 摘要

结果列表摘要增加乘区名称：

1. 属性持续修正：属性名称 / 增加或减少 / 乘区名称。
2. 伤害修正：方向 / 提高或降低 / 乘区名称 / 关键过滤。
3. 治疗修正：方向 / 提高或降低 / 乘区名称 / 治疗种类。

目录加载失败时摘要保留稳定标识，不显示空字符串或把结果判为损坏。

## 9. 生命周期同步校验

前端矩阵必须与共享契约一致：

1. 快照读取继续显示现有共享值、每层值和重复施加值组合。
2. 伤害修正、治疗修正、持续属性增加/减少允许选择“每次结算重新读取”。
3. 选择每次结算重新读取时允许“整个实例共享”和“每个有效层分别贡献”，清空并隐藏 `reapplicationValueMode`；提交前再次校验。
4. 共享动态值每个生命周期实例贡献一次；逐层动态值按当前有效层分别贡献，页面使用这两个中文选项，不增加另一套层数概念。
5. 属性覆盖、普通护盾、生命下限和其他不兼容结果不显示动态读取选项。
6. 从动态读取切回快照时不自动猜测共享值或重复施加值方式，要求用户明确选择合法组合。
7. 父生命周期或操作变化导致乘区、读取方式或层值失效时，列出清理内容并要求确认；取消保持原草稿。
8. 动态读取公式若被后端判定含运行输入参数，错误定位到读取方式和公式区域并保留草稿；前端不复制公式参数分析器。

前端不求值巨人杀手公式，也不根据公式节点自动选择动态读取。

## 10. 目录加载与并发行为

1. 打开结果编辑器时按当前游戏加载启用乘区；已有停用引用按详情键补回。
2. 游戏切换、API 基址变化或父技能关闭时丢弃对应会话缓存。
3. 同一父效果会话多次打开结果编辑器复用目录；显式刷新或内联新增成功后强制更新。
4. 加载失败显示错误和重试，禁止保存依赖乘区的修正结果；不把失败当空目录。
5. 保存期间禁用父效果重复提交和乘区新增。
6. 乘区被其他会话删除、停用或改结构导致效果保存 400/409 时，保留全部草稿并刷新目录，不自动改选其他乘区。

## 11. 字段错误定位

新增映射：

1. 乘区管理 `domain / calculationMode / applicationStage` → 对应表单字段。
2. `results[i].detail.modifierZoneKey` → 当前结果乘区选择器。
3. `results[i].lifecycleBehavior.valueReadMode / stackValueMode / reapplicationValueMode` → 生命周期行为区域。
4. `404.MODIFIER_ZONE_NOT_FOUND` → 乘区管理弹窗顶部或结果目录错误。
5. `409.MODIFIER_ZONE_IN_USE` → 删除确认或结构字段区域。

无法定位的字段问题显示在当前弹窗顶部并保留后端详情；原因码不是主要用户文案。

## 15. 前端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 后端最终字段、固定组合、错误或停用引用规则与共享契约不同。
2. 必须让技能主记录而不是具体结果保存乘区，导致一个技能不能进入多个乘区。
3. 必须手写 JSON、自由输入乘区键或自动创建隐式乘区才能完成页面。
4. 内联新增无法保持父结果和父效果草稿，必须关闭父弹窗。
5. 需要在前端执行公式、属性、伤害、治疗、聚合或 Wasm 才能校验表单。
6. 需要增加移动端布局、旧管理页面或阶段 7.6.3～7.6.5 字段才能完成本轮。
