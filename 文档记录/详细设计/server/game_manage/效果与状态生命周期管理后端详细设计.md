## 4. 数据库表

新增三张关系表。所有表使用完整 `game_id/skill_key/effect_key/result_key` 复合键，禁止跨游戏或跨技能引用，不使用数组或 JSONB。

### 4.1 `skill_effect_lifecycles`

一行表示一个效果的一份生命周期：

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`effect_key` | 三列主键，同时外键引用 `skill_effects`，内部删除级联。 |
| `duration_formula_key` | 可空；非空时复合外键引用同一技能公式。 |
| `max_stacks_formula_key` | 非空；复合外键引用同一技能公式。 |
| `application_stacks_formula_key` | 非空；复合外键引用同一技能公式。 |
| `instance_scope` | 检查 `SKILL/SOURCE/TARGET/SOURCE_TARGET`。 |
| `reapplication_stack_mode` | 检查 `KEEP/INCREASE/REPLACE`。 |
| `reapplication_duration_mode` | 可空；非空检查 `REFRESH_ALL/KEEP_REMAINING/INDEPENDENT`。 |
| `expiry_mode` | 检查 `ALL_AT_ONCE/ONE_BY_ONE/INDEPENDENT/EXPLICIT_ONLY`。 |
| `periodic_interval_formula_key` | 可空；非空时复合外键引用同一技能公式。 |
| `first_periodic_execution` | 可空；非空检查 `IMMEDIATE/AFTER_INTERVAL`。 |

表级检查先保证：

1. 没有持续时间时只能显式移除，重复持续规则为空。
2. 有持续时间时不能只显式移除，重复持续规则非空。
3. 独立重复计时和独立到期必须成对。
4. 周期间隔和首次周期必须同时为空或同时非空。

是否存在周期结果、自然结束结果以及每个结果行为是否合法，需要跨表延迟约束触发器完成。

公式反向索引分别以 `game_id, skill_key, *_formula_key` 为前导列。四个公式外键约束名固定为：

1. `fk_skill_effect_lifecycles_duration_formula`
2. `fk_skill_effect_lifecycles_max_stacks_formula`
3. `fk_skill_effect_lifecycles_application_stacks_formula`
4. `fk_skill_effect_lifecycles_periodic_interval_formula`

### 4.2 `skill_effect_result_lifecycle_behaviors`

一行表示一个结果在所属效果生命周期中的行为：

| 列 | 约束 |
| --- | --- |
| 四个结果主键列 | 主键，同时外键引用 `skill_effect_results` 并级联删除。 |
| `moment` | 检查 `APPLICATION/PERSISTENT/FULL_STACKS/PERIODIC/NATURAL_END/EARLY_REMOVE`。 |
| `value_read_mode` | 可空；非空检查 `APPLICATION_SNAPSHOT/MOMENT_EVALUATION`。 |
| `stack_value_mode` | 可空；非空检查 `SHARED/PER_STACK`。 |
| `reapplication_value_mode` | 可空；非空检查 `KEEP/REPLACE/ADD`。 |
| `periodic_execution_mode` | 可空；非空检查 `ONCE_PER_INSTANCE/ONCE_PER_ACTIVE_STACK`。 |

该表只保存固定列，不复制结果种类明细。结果种类、状态操作、属性操作和是否存在数值规则由延迟触发器联表判断。

### 4.3 `skill_effect_lifecycle_operation_details`

一行表示一个 `LIFECYCLE_OPERATION` 结果：

| 列 | 约束 |
| --- | --- |
| 四个结果主键列 | 主键，同时外键引用 `skill_effect_results` 并级联删除。 |
| `target_effect_key` | 非空；与 `game_id/skill_key` 组成复合外键，直接引用 `skill_effect_lifecycles`。 |
| `operation` | 检查 `INCREASE/DECREASE/SET/REFRESH/CONSUME/REMOVE`。 |

外键 `fk_skill_effect_lifecycle_operations_target` 使用默认的即时、不可延迟检查且不级联删除，保证目标效果移除生命周期或删除效果时先处理引用。建立 `(game_id, skill_key, target_effect_key, effect_key, result_key)` 反向索引。

数据库检查 `target_effect_key <> effect_key`，Service 仍须在写入前返回字段级错误。

## 5. 既有表与触发器扩展

### 5.1 结果种类

`skill_effect_results.result_type` 检查约束增加 `LIFECYCLE_OPERATION`。不新增自由结果目录，不改变已有七种值。

### 5.2 结果完整形状

扩展现有事务结束延迟检查：

1. 原七种结果继续满足阶段 7.2 数值规则和类型明细互斥关系。
2. `LIFECYCLE_OPERATION` 恰好一行生命周期操作明细，不得有伤害、属性、资源、冷却或状态明细。
3. `INCREASE/DECREASE/SET/CONSUME` 恰好一行 `skill_effect_result_values`。
4. `REFRESH/REMOVE` 不得有 `skill_effect_result_values`。
5. 原七种结果的生命周期操作明细计数必须为 0，不能只检查原五类明细。
6. 现有形状函数的子表触发器循环增加 `skill_effect_lifecycle_operation_details`，覆盖 INSERT、UPDATE、DELETE。
7. 所有效果删除级联已经删除父结果时，触发器直接结束，不能把合法删除误判为形状损坏。

### 5.3 生命周期聚合形状

新增事务结束延迟检查，覆盖效果、生命周期、结果和行为三张关系：

1. 无生命周期的效果不得有任何结果生命周期行为。
2. 有生命周期的效果，每个结果必须恰好有一行行为。
3. `PERSISTENT` 只允许普通护盾、属性变化和状态施加。
4. 状态移除、伤害、治疗、资源、冷却和生命周期操作不得为 `PERSISTENT`。
5. 有数值规则的生命周期结果必须有 `value_read_mode`；无数值规则必须为空。
6. `APPLICATION/PERSISTENT` 数值只允许施加快照。
7. 持续普通护盾和属性变化必须满足 `stack_value_mode` 与 `reapplication_value_mode` 组合；持续状态施加两者必须为空。
8. 属性覆盖 `SET` 不得使用每层贡献或重复相加。
9. `PERIODIC` 行为必须有 `periodic_execution_mode`，其他时点必须为空。
10. 存在周期行为时生命周期必须有周期间隔和首次周期；不存在周期行为时两字段必须为空。
11. 无自然到期时不得存在 `NATURAL_END` 行为。

挂载范围固定为：

1. `skill_effects`：AFTER INSERT OR UPDATE。
2. `skill_effect_results`：AFTER INSERT OR UPDATE OR DELETE。
3. `skill_effect_lifecycles`：AFTER INSERT OR UPDATE OR DELETE。
4. `skill_effect_result_lifecycle_behaviors`：AFTER INSERT OR UPDATE OR DELETE。
5. `skill_effect_lifecycle_operation_details` 继续由第 5.2 节结果形状触发器覆盖；它对目标生命周期的存在由即时复合外键保证。

聚合检查从 NEW 或 OLD 解析 `game_id/skill_key/effect_key`；父效果已经删除时立即结束。这样在生命周期行未变化、只新增或删除结果的 PUT 中，事务结束前仍会检查“有生命周期则每个结果恰好一行行为”。

Service 是表单校验责任方，延迟触发器只作为数据库最后防线。

### 5.4 刷新目标持续时间约束

新增跨效果延迟约束 `ck_skill_effect_lifecycle_refresh_target_duration`，从关系两侧保证：

1. `skill_effect_lifecycle_operation_details` INSERT 或 UPDATE 为 `REFRESH` 时，目标 `skill_effect_lifecycles.duration_formula_key` 必须非空。
2. `skill_effect_lifecycles` UPDATE 把 `duration_formula_key` 清空时，不得存在指向该生命周期且 `operation = REFRESH` 的操作明细。
3. 约束触发器分别挂在 `skill_effect_lifecycle_operation_details` 的 AFTER INSERT OR UPDATE，以及 `skill_effect_lifecycles` 的 AFTER UPDATE OR DELETE，并使用 DEFERRABLE INITIALLY DEFERRED；目标或操作已在同一事务合法删除时按最终状态判断。
4. 即时复合外键仍负责目标生命周期是否存在；本约束只负责刷新目标必须有自然到期。
5. Service 必须先返回共享契约的稳定错误；触发器异常只处理并发竞争或绕过 Service 的非法写入，异常约束名固定为 `ck_skill_effect_lifecycle_refresh_target_duration`。

## 9. Service 校验与事务

### 9.1 统一校验顺序

1. 验证路径游戏、技能和效果。
2. 归一化效果与结果基本字段，并检查结果标识、种类不可修改和重复标识。
3. 校验生命周期自身字段和组合。
4. 校验每个结果的基础结果形状。
5. 校验结果生命周期行为与结果种类、数值规则的组合。
6. 一次收集并查询同技能公式、状态、属性、伤害类型、技能和目标生命周期效果引用。
7. `REFRESH` 操作目标存在但没有 `durationFormulaKey` 时返回 `400.INVALID_SKILL_EFFECT_REFERENCE`，字段 `results[index].detail.targetEffectKey`、原因 `TARGET_EFFECT_HAS_NO_DURATION`。
8. 返回全部可确定字段问题；存在任一问题时不进入写事务。

### 9.2 创建

事务写入顺序：

1. 锁定父技能和相关目录行。
2. 插入效果。
3. 非空时插入效果生命周期。
4. 插入全部结果、数值规则和原七种或新生命周期操作明细。
5. 非空时插入全部结果生命周期行为。
6. 写入管理编辑日志。
7. 事务提交后按详情查询路径重建响应。

目标生命周期效果必须在创建当前效果前已经存在；当前效果不能在同一次 POST 中引用自身。

### 9.3 全量更新

1. 锁定当前效果并读取旧生命周期、旧结果种类和旧目标引用。
2. 如果请求移除生命周期，先检查其他效果是否引用；有引用时返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`。
3. 如果旧生命周期和请求生命周期都存在但 `instanceScope` 不同，返回 `400.VALIDATION_FAILED`，字段 `lifecycle.instanceScope`、原因 `IMMUTABLE`。
4. 如果旧 `durationFormulaKey` 非空而请求清空，先查询入站 `REFRESH` 操作；存在时返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`，字段 `lifecycle.durationFormulaKey`、原因 `REFRESH_OPERATION_IN_USE`，不得修改操作方。
5. 结果仍按 `resultKey` 区分保留、新增和删除；已有结果种类不可修改。
6. 已存在且仍保留的生命周期必须原位 UPDATE，禁止 DELETE 后 INSERT；否则即时目标外键会让合法更新失败。
7. 删除结果时先删除其行为和类型明细，再由现有聚合逻辑清理数值规则与主记录。
8. 生命周期操作目标、当前效果生命周期、结果行为和类型明细在同一事务内更新。
9. 任一引用、数据库约束或编辑日志失败时，效果资料与全部子表回滚。

### 9.4 删除效果与删除技能

1. 单独删除效果或移除生命周期前查询 `skill_effect_lifecycle_operation_details`；存在外部引用时返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`。
2. 阶段 7.3 过程挂接引用仍优先返回既有 `409.SKILL_EFFECT_IN_USE`；不得把两种冲突混成一个数据库错误。
3. 删除技能自身数据时，在同一事务中先删除该技能所有生命周期操作明细，再按阶段 7.3 冻结顺序删除过程、效果、内部状态、公式、参数和技能。
4. 其他技能不能引用当前技能生命周期，因此自身清理不需要跨技能扫描。

### 9.5 公式删除

`SkillFormulaService.delete` 在阶段 7.2 既有清单和阶段 7.3 合入后的完整清单上追加第 4.1 节四个外键名，继续统一映射 `409.SKILL_FORMULA_IN_USE`。不得用只含 7.4 的集合覆盖既有清单，也不得把全部 SQLSTATE `23503` 或名称前缀泛化为公式占用。

## 10. 错误映射

1. 请求绑定失败和外来字段继续使用 `400.INVALID_BODY`。
2. 生命周期组合和结果行为组合使用 `400.VALIDATION_FAILED`，字段路径与共享契约一致。
3. 公式和目标生命周期效果引用问题使用 `400.INVALID_SKILL_EFFECT_REFERENCE`。
4. 修改已有生命周期 `instanceScope` 使用 `400.VALIDATION_FAILED`，字段 `lifecycle.instanceScope`、原因 `IMMUTABLE`。
5. `REFRESH` 指向无持续时间目标使用 `400.INVALID_SKILL_EFFECT_REFERENCE`，字段 `results[index].detail.targetEffectKey`、原因 `TARGET_EFFECT_HAS_NO_DURATION`。
6. 目标清空仍被刷新操作使用的持续时间，使用 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`，字段 `lifecycle.durationFormulaKey`、原因 `REFRESH_OPERATION_IN_USE`。
7. 单独删除效果时先检查阶段 7.3 过程挂接，再检查生命周期目标引用；同时存在时优先返回 `409.SKILL_EFFECT_IN_USE`，只有第二类冲突时返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`。
8. `fk_skill_effect_lifecycle_operations_target` 和 `ck_skill_effect_lifecycle_refresh_target_duration` 加入显式异常约束清单，作为 Service 预检查的并发防线；根据当前写入方向映射到上述 400 或 409，其他未知约束、触发器异常或 SQLSTATE 不得伪装成表单错误。
9. 创建、更新和删除继续记录 `AdminEditLogService`；生命周期不单独写第二条编辑日志。

### 11.2 Service 与 Controller

聚焦覆盖：

1. 无生命周期效果继续完整创建和回读。

3. 周期字段与周期结果双向完整性。
4. 持续普通护盾、属性变化和状态施加合法形状。
5. 非法 `PERSISTENT`、值读取、层数值合并和独立计时组合。

12. 删除同时被过程挂接和生命周期操作引用的效果时优先返回 `409.SKILL_EFFECT_IN_USE`；生命周期冲突案例不挂过程夹具。
13. 操作方保存 `REFRESH` 时目标没有自然到期，返回 `TARGET_EFFECT_HAS_NO_DURATION` 且事务不落部分数据。
14. 先建立合法 `REFRESH` 再清空目标持续时间，返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE` / `REFRESH_OPERATION_IN_USE`，操作方与目标方都保持原值。

## 13. 后端停止条件

1. 阶段 7.3 实际实现与冻结契约不一致，并改变效果引用、删除顺序或共享接口。
