# 技能基本管理后端详细设计

方案版本：`skill-basic-management-v2-frozen`

方案状态：已于 2026-08-26 完成后端、SQL、真实数据库迁移和接口验收。

本文实施[技能基本管理共享契约](../../项目/技能基本管理详细设计.md)，不重复定义前后端公共字段和错误含义。

## 1. 后端职责

1. 用独立技能表保存技能基本资料。
2. 用专用关联表保存技能和技能分类的多选关系。
3. 在同一事务内完成技能资料和全部分类关系的创建或更新。
4. 校验游戏、技能分类、分类状态、字段格式和重复分类。
5. 为前端提供完整增删改查，不调用 Wasm、不发布数据。

## 3. 数据库设计

### 3.1 `public.skills`

```sql
CREATE TABLE public.skills (
    game_id varchar(64) NOT NULL,
    skill_key varchar(64) NOT NULL,
    name varchar(100) NOT NULL,
    description varchar(2000),
    max_level integer NOT NULL,
    status varchar(16) NOT NULL,
    sort_order integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT pk_skills PRIMARY KEY (game_id, skill_key),
    CONSTRAINT fk_skills_game
        FOREIGN KEY (game_id) REFERENCES public.games (game_id),
    CONSTRAINT ck_skills_key
        CHECK (skill_key ~ '^[a-z][a-z0-9_]{0,63}$'),
    CONSTRAINT ck_skills_name CHECK (btrim(name) <> ''),
    CONSTRAINT ck_skills_max_level CHECK (max_level >= 1),
    CONSTRAINT ck_skills_status CHECK (status IN ('ENABLED', 'DISABLED')),
    CONSTRAINT ck_skills_sort_order CHECK (sort_order >= 0)
);
```

不建立名称唯一索引。列表索引明确为：

```sql
CREATE INDEX ix_skills_list
    ON public.skills (game_id, status, sort_order, name, skill_key);
```

### 3.2 `public.skill_category_relations`

```sql
CREATE TABLE public.skill_category_relations (
    game_id varchar(64) NOT NULL,
    skill_key varchar(64) NOT NULL,
    skill_category_key varchar(64) NOT NULL,
    CONSTRAINT pk_skill_category_relations
        PRIMARY KEY (game_id, skill_key, skill_category_key),
    CONSTRAINT fk_skill_category_relations_skill
        FOREIGN KEY (game_id, skill_key)
        REFERENCES public.skills (game_id, skill_key)
        ON DELETE CASCADE,
    CONSTRAINT fk_skill_category_relations_category
        FOREIGN KEY (game_id, skill_category_key)
        REFERENCES public.skill_categories (game_id, skill_category_key)
        ON DELETE RESTRICT
);

CREATE INDEX ix_skill_category_relations_category
    ON public.skill_category_relations
       (game_id, skill_category_key, skill_key);
```

迁移不创建默认技能，不搬运旧技能数据。执行建表前先查询 `information_schema` 和 `pg_constraint`：同名表不存在时创建；已经存在且结构完整时保持幂等；已经存在但列、类型、主键、外键或检查约束不一致时停止并触发共享契约中的停止门禁。不能仅凭 `CREATE TABLE IF NOT EXISTS` 判断结构一致。

## 4. 包与模型

独立建立 `skill` 包：

1. `SkillAdminController`
2. `SkillService`
3. `SkillMapper` 与 MyBatis XML
4. `SkillCreateRequest`、`SkillUpdateRequest`、`SkillListQuery`
5. `SkillResponse`、`SkillListResponse`、`SkillStatus`
6. 仅供 mapper/service 使用的分类关系行模型

不得让新模型继承或包装旧 `Ability`、Provider 或通用类型模型。

`SkillUpdateRequest.skillKey` 沿用现有更新模型的 `@Null` 约束：允许省略或显式 null，拒绝非 null。`gameId`、`createdAt`、`updatedAt` 不属于创建或更新请求。

## 5. 查询实现

1. 基本资料列表只查询 `skills`，按共享契约筛选和排序。
2. 分类关系使用第二条批量查询读取本页全部技能的分类键，禁止按技能逐条查询形成 N+1。
3. 关系查询连接 `skill_categories`，按分类自身的排序、名称和标识返回。
4. service 按 `skillKey` 分组后组装 `skillCategoryKeys`；没有关系时返回空数组，不返回 null。
5. 单条查询先确认技能存在，再读取其分类关系。

## 6. 创建与更新事务

### 6.1 归一化

1. `skillKey`、`name` 去除首尾空格。
2. `description` 去除首尾空格；空串转 null。
3. `skillCategoryKeys` 保持调用方完整数组用于重复检测，不能先静默去重。

### 6.2 创建

在一个事务中依次完成：

1. 校验游戏和全部基本字段。
2. 校验技能标识不存在。
3. 校验分类数组格式与重复项。
4. 非空分类数组先按 `skill_category_key` 排序，再批量锁定并读取请求涉及的技能分类；空数组跳过分类锁定和关系插入，不能生成空 `IN ()`；未知或停用分类拒绝。
5. 插入技能基本资料。
6. 批量插入分类关系。
7. 回读并返回完整技能。

任一步失败都回滚。

### 6.3 更新

在一个事务中依次完成：

1. 锁定技能；不存在返回 `404.SKILL_NOT_FOUND`。
2. 读取当前分类键集合。
3. 校验基本字段、分类数组格式与重复项。
4. 非空分类数组先按 `skill_category_key` 排序，再批量锁定并读取请求分类；空数组跳过分类锁定和新增关系写入，只删除已有关系。所有键必须存在；仅“请求中新增且当前未关联”的分类要求处于启用状态。
5. 更新技能基本资料。
6. 删除请求中不再存在的关系，并批量插入新增关系；未变化关系不重复写入。
7. 回读并返回完整技能。

锁定技能用于串行化同一技能的资料和关系更新；分类读取需使用能阻止并发删除的行锁，确保校验和关系插入之间分类不会消失。

## 7. 删除与分类状态

1. 删除技能时依赖技能外键的 `ON DELETE CASCADE` 清理关系。
2. 删除技能分类时，现有 `SkillCategoryService` 继续把关系外键的 PostgreSQL `23503` 映射为 `409.SKILL_CATEGORY_IN_USE`。
3. 停用技能分类不更新技能或关系。
4. 停用技能不删除关系。

## 8. 控制器与编辑日志

1. 控制器路径严格使用共享契约中的 `/skills`。
2. POST、PUT、DELETE 沿用 `AdminEditLogHelper` 记录现有编辑日志。
3. 状态切换复用 PUT，不新增只为状态服务的接口。
4. 统一错误由现有全局错误处理器输出，controller 不解析数据库错误文本。

## 9. 错误映射

1. `pk_skills` 冲突映射 `409.SKILL_KEY_EXISTS`。
2. 未知分类映射 `400.UNKNOWN_SKILL_CATEGORY`，并定位原数组下标。
3. 新增停用分类映射 `409.SKILL_CATEGORY_DISABLED`，并定位原数组下标。
4. `pk_skill_category_relations` 不作为正常用户冲突暴露；重复输入应在写数据库前返回 `400.VALIDATION_FAILED`。
5. 非预期数据库约束错误不得伪装成业务错误，保留原异常供统一处理和日志定位。
6. 同一请求同时包含未知分类和新增停用分类时，先返回 `400.UNKNOWN_SKILL_CATEGORY`；所有错误仍按请求原数组下标定位，不能因锁定前排序改变字段路径。

## 11. 后端停止条件

1. 目标库已存在结构不同的同名表。
2. 新接口必须依赖旧能力、Provider 或通用类型模型才能实现。
3. 分类引用无法通过复合外键和事务保证。
4. 完整 Maven 测试出现无法归因于本次改动的失败，且定点复查不能确认安全性。
5. 真实数据库迁移或接口验证不能完成。

出现任一项时保留证据并停止，不转为兼容层或绕过外键。
