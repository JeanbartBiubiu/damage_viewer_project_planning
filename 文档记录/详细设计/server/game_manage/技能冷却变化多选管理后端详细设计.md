## 1. 当前事实与后端职责

当前实现事实：

1. `skill_effect_cooldown_change_details` 以结果主键保存一行，行内同时保存 `affected_skill_key` 和 `operation`。
2. `SkillEffectCooldownChangeDetail` 只接收一个 `affectedSkillKey`。
3. `SkillEffectService` 以结果标识索引一行冷却明细，并把一个目标技能加入批量目录锁定。
4. PUT 通过结果稳定标识区分保留、新增和删除结果，已有停用目录引用可原样保留。
5. `SkillService.delete` 通过冷却明细中的目标技能反向查询外部引用。
6. `triggers.sql` 在事务提交时要求每个冷却变化结果恰好一行冷却明细，并按操作检查数值规则。

本补项后端负责：

1. 把冷却操作和受影响技能集合拆成明细表与关系表。
2. 把请求、响应和内部模型改为技能标识列表。
3. 保留现有效果聚合接口与事务边界。
4. 无损迁移现有单目标记录。
5. 扩展停用引用比较、批量锁定和技能删除保护。
6. 更新数据库形状约束、静态契约测试和真实数据库验收。

## 3. 数据库结构

### 3.1 冷却变化明细表

保留 `public.skill_effect_cooldown_change_details`，职责收窄为保存一个结果唯一的冷却操作：

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`effect_key`、`result_key` | 联合主键，同时外键引用 `skill_effect_results` 并级联删除。 |
| `operation` | 非空；只允许 `REDUCE / INCREASE / RESET`。 |

删除旧 `affected_skill_key` 列、旧目标技能外键和旧目标技能反向索引。明细表不保存数组或重复操作。
同一结果所有目标共用这一行 `operation`、同一行数值规则和同一结果生命周期行为；关系表不得重复保存这些字段。

### 3.2 受影响技能关系表

新增 `public.skill_effect_cooldown_change_targets`：

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`effect_key`、`result_key` | 关联所属冷却变化明细。 |
| `affected_skill_key` | 非空，表示一项明确受影响技能。 |

约束固定为：

1. 主键：`(game_id, skill_key, effect_key, result_key, affected_skill_key)`，数据库层同时禁止重复目标。
2. 父级外键：前四列引用 `skill_effect_cooldown_change_details`，`ON DELETE CASCADE`。
3. 目录外键：`(game_id, affected_skill_key)` 引用 `skills(game_id, skill_key)`，限制删除。
4. 反向索引：`(game_id, affected_skill_key, skill_key, effect_key, result_key)`，供技能删除保护使用。
5. 不增加 `sort_order`；集合没有执行顺序，读取时关联 `skills` 按技能目录排序。

新库父表数量从 71 增加到 72。`LegacyCombatDataCleanupDbContractSqlTest` 必须把新表加入当前保留表清单，并将精确数量改为 72；旧清理脚本仍只负责旧表，不得删除新表。

## 4. 数据库形状约束

现有技能效果结果延迟形状函数和约束触发器需要扩展：

1. `COOLDOWN_CHANGE` 结果恰好一行 `skill_effect_cooldown_change_details`。
2. 同一结果至少一行 `skill_effect_cooldown_change_targets`。
3. `REDUCE / INCREASE` 恰好一行数值规则；`RESET` 不得有数值规则。
4. 冷却结果不得拥有其他结果种类明细；其他结果种类不得拥有冷却明细或冷却目标。
5. 新目标关系表也挂接延迟形状约束触发器，插入、更新和删除都在事务提交时检查最终形状。
6. 父结果或父冷却明细已由合法级联删除时，触发器直接结束，不误报缺少目标。
7. 绕过 Service 直接写入空目标、孤立目标、重复目标或错误结果种类时，数据库必须拒绝。

Service 必须在写库前返回共享契约的稳定字段错误；数据库异常只作为最后防线。

## 5. 兼容迁移

新增 `skill_cooldown_multi_select_migration.sql`，只处理阶段 7.5 已完成开发库中的单目标冷却数据。

迁移前置状态分为：

1. 旧结构：明细表存在 `affected_skill_key`，新关系表不存在。
2. 完整新结构：明细表已无旧列，新关系表及主键、两个外键、索引和形状触发器完整。
3. 部分结构或漂移结构：上述条件均不满足。

迁移步骤必须在单事务中执行：

1. 核对 `skill_effect_results`、`skill_effect_cooldown_change_details` 和 `skills` 的主键及关键约束。
2. 创建新关系表、主键、父级级联外键、技能限制删除外键和反向索引。
3. 按每条旧冷却明细把 `affected_skill_key` 回填为一条目标关系。
4. 校验旧明细数量等于新目标数量，且每条旧明细恰好迁移一项。
5. 删除旧目标技能外键和旧反向索引。
6. 从明细表删除 `affected_skill_key`。
7. 替换结果形状函数和相关约束触发器。
8. 再次核对新结构和数据数量后提交。

完整新结构重复执行时只校验并成功结束。部分结构、数量不一致或约束漂移时主动失败并回滚；不得使用默认技能、删除业务数据、`DROP ... CASCADE` 或双写旧列。
不修改历史阶段 7.2、7.4、7.5 兼容迁移；测试需要分别验证历史迁移仍保持原始职责、本补项迁移能够把其产物升级到当前结构。

迁移执行前必须按现有数据库访问流程确认目标库并备份。迁移后重新加载 `triggers.sql`，再进行真实接口和重启回读验收。

## 6. 强类型模型

### 6.1 外部请求与响应

`SkillEffectCooldownChangeDetail` 改为：

```java
record SkillEffectCooldownChangeDetail(
    List<String> affectedSkillKeys,
    SkillEffectCooldownChangeOperation operation
) implements SkillEffectResultDetail
```

要求：

1. 列表字段使用明确的 `List<String>`，不得用 `JsonNode`、`Map` 或逗号文本。
2. 局部反序列化继续捕获其他结果种类字段和未知字段。
3. 旧 `affectedSkillKey` 作为不再允许的字段返回 `400.INVALID_BODY`，不得自动包装为单项列表。
4. 响应列表不可变，并按共享契约稳定排序。

### 6.2 内部行模型

1. `SkillEffectCooldownChangeDetailRow` 只保存结果主键和 `operation`。
2. 新增 `SkillEffectCooldownChangeTargetRow`，保存结果主键和 `affectedSkillKey`。
3. 聚合重建以结果标识分组目标行；没有目标、重复目标、孤立目标或非冷却结果拥有目标时记录键并返回 `500.INTERNAL_ERROR`。

## 7. Mapper 与聚合读取

`SkillEffectMapper` 和 XML 至少调整：

1. 冷却明细查询不再读取 `affected_skill_key`。
2. 新增按效果读取全部冷却目标的方法，关联技能目录并按 `skills.sort_order, skills.skill_key` 排序。
3. 新增批量插入一条目标关系的方法。
4. 新增按结果删除全部目标关系的方法。
5. 冷却明细插入和更新只写 `operation`。
6. 外部冷却目标引用计数改查新关系表，并继续排除所属技能等于待删技能的自引用。
7. 不为每个结果或每个技能单独发查询；效果详情一次读取全部冷却明细和目标，再在内存组装。

读取一个冷却结果时：

1. 找到唯一冷却明细。
2. 取得该结果全部目标行。
3. 校验至少一项且无重复。
4. 组装一个 `SkillEffectCooldownChangeDetail` 和一个结果响应。

## 8. Service 写入和停用引用

### 8.1 请求校验与引用收集

`SkillEffectService` 必须：

1. 在规范化后校验列表非空。
2. 在保留请求数组下标的同时校验每项目标格式和重复项。
3. 把所有结果的目标技能去重后批量锁定目录；错误仍定位到每个原始列表项。
4. 对未知技能一次累积返回所有 `UNKNOWN_SKILL`。
5. 对新增停用技能一次累积返回所有 `SKILL_DISABLED`。

### 8.2 已有停用目标比较

现有 `RetainedCatalog` 或等价结构中，冷却目标从一个可空字符串改为按 `resultKey` 保存不可变技能集合。

PUT 比较规则：

1. 旧、新集合交集属于原样保留。
2. 旧集合减新集合允许移除，不要求技能仍启用。
3. 新集合减旧集合属于新增引用，必须启用。
4. 新增目标等于路径父级技能时沿用停用自引用例外。
5. 只改结果名称、说明、排序、作用对象、操作或数值规则，不把未变化的停用目标误判为新增。

### 8.3 创建和全量更新

创建冷却结果：

1. 插入结果主记录和必要数值规则。
2. 插入一行冷却明细。
3. 按稳定顺序插入全部目标关系。

更新保留的冷却结果：

1. 更新结果公共字段、数值规则和冷却操作。
2. 删除该结果旧目标关系。
3. 插入请求中的最终目标关系。
4. 依赖延迟约束在事务提交时校验最终非空集合。

目标关系没有独立身份，MVP 全量更新可采用删除后重建，不需要建立逐项更新接口。任一写入失败时整个效果聚合回滚。

## 9. 删除保护

1. `SkillService.delete` 的业务语义不变，只把反向查询切换到 `skill_effect_cooldown_change_targets`。
2. 其他技能拥有的任一冷却结果选择待删技能时，返回 `409.SKILL_IN_USE`，不得开始删除。
3. 待删技能自己的效果选择自身时不阻止删除；删除顺序继续先清理自身效果和结果，再删除技能。
4. 数据库目标技能外键限制删除，防止绕过 Service。
5. 删除效果或删除结果通过内部级联删除冷却明细和目标关系，不删除受影响技能。

## 12. 后端停止条件

出现以下任一情况必须停止：

1. 需要把目标列表保存到数组、JSONB、文本或通用多态表。
2. 需要恢复旧字段兼容、双写或版本化接口。
3. 现有真实数据库不是阶段 7.5 完成结构，无法安全区分旧、新和部分迁移状态。
