# 角色基本管理后端详细设计

本文实施[角色基本管理共享契约](../../项目/角色基本管理详细设计.md)。HTTP、JSON 和错误含义只以共享契约为准。

实施 worktree：`C:\project\damage_backend_dev`。

## 1. 数据库

在 fresh schema 中新增三张不分区表：

1. `game_level_configs`：`game_id` 主键和游戏外键，`min_level`、`max_level`、创建更新时间；等级范围 1～100。
2. `characters`：复合主键 `(game_id,character_key)`，角色名称、说明、创建更新时间；标识 CHECK、名称非空和同游戏规范化唯一索引。
3. `character_attributes`：每个角色一行 `level_values jsonb`，复合主键同时外键到角色并 `ON DELETE CASCADE`；CHECK `jsonb_typeof(level_values)='object'`。

已有库迁移：`db/game_manage/migrations/compatibility/character_management_compatibility_migration.sql`。脚本幂等建表、约束和索引；若 `games` 已有 `lol` 且缺配置，插入 1～18；不得 DROP、迁移旧实体数据或修改战斗表。

稀疏 Map 兼容迁移：`db/game_manage/migrations/compatibility/character_attributes_sparse_compatibility_migration.sql` 只清理由旧版本自动生成、整张 Map 不含任何非 0 数值的默认数据；包含实际非 0 数值的角色不改。

## 2. 后端模块

新建独立 `character` 控制器、服务、DTO、Mapper 和 XML。等级配置代码也放在该包，不复用 combat-data progression。

写操作使用 `AdminEditLogHelper`。角色创建事务依次校验游戏和等级配置、插入角色、生成外层等级完整且内层为空的 Map 并插入。角色删除依赖数据库级联。

角色属性 GET 只回传全部等级均存在的当前属性；PUT 校验外层等级、拒绝未知属性，并要求同一属性覆盖全部等级或完全缺失，再验证已配置数值后整块更新。基本资料 PUT 不加载或更新 Map。

等级配置 PUT 使用 upsert；保存新范围后，在同一事务内把全部已有角色 Map 整理为新等级范围，新增等级补 0，移除范围外等级。

不得修改全局异常处理器；所有字段校验在角色服务内抛现有 `ApiException`，并构造共享契约要求的 `fieldIssues`。
