## 4. 数据库结构

本阶段只增加两张表。

### 4.1 斩杀明细

`skill_effect_execute_details`：

1. 主键为 `game_id + skill_key + effect_key + result_key`。
2. 完整外键到 `skill_effect_results` 并随结果级联删除。
3. `attribute_key varchar(64) NOT NULL`，以 `game_id + attribute_key` 完整外键到同游戏属性并使用 `RESTRICT`。
4. 以被引用属性复合键开头建立反向索引。
5. 只允许父结果为 `EXECUTE`，且父结果必须有数值规则。

### 4.2 联动事件明细

`skill_trigger_rule_link_events`：

1. 主键为 `game_id + skill_key + rule_key`。
2. 完整外键到触发规则并随规则级联删除。
3. `source_skill_key varchar(64)` 可空。
4. 非空时以 `game_id + source_skill_key` 完整外键到同游戏技能并使用 `RESTRICT`。
5. 只允许父事件为 `HIT_LINK_APPLIED / ATTACK_LINK_APPLIED`。
6. 以被引用技能复合键开头建立反向索引。

`HIT_LINK_APPLICATION / ATTACK_LINK_APPLICATION` 的 detail 固定为空对象，不创建没有业务列的空结果表。

## 5. Schema、兼容迁移与延迟检查

### 5.1 `schema.sql`

新库直接形成：

1. 两张本阶段表、完整外键、检查和反向索引。
2. 结果固定集合为最终十六种，事件固定集合为最终二十一种。
3. `skill_effect_results.result_type` 使用 `varchar(32)`；结果形状函数内承接该值的局部变量同步使用可容纳 32 字符的类型。
4. 两种联动结果继续使用既有数值规则表，空 detail 不落空表。
5. 两处事件值检查和前序输出检查保持阶段 7.6.3 集合不变。

### 5.2 独立兼容迁移

`execute_hit_attack_linkage_migration.sql` 使用一个显式事务：

1. 先核对冷却变化多选补项和阶段 7.6.3 的十三种结果、十九种事件、累计八张效果子表、冷却目标关系、两张事件明细表、形状函数和触发器完整。
2. 两张表全部缺失时创建；全部存在时逐列、键、外键、检查和索引核对；部分存在或未知漂移时主动失败。
3. 结果类型列为精确前置宽度时扩到 32；已经是 32 时核对其约束；其他类型、长度、默认或未知漂移整体停止。
4. 替换结果、事件检查和形状函数前只接受精确前置集合或目标集合；同步替换局部变量声明，不留下列已扩宽但函数仍截断的状态。
5. 不改动两处事件值和前序输出检查，不回填业务数据。
6. 同一事务内完成表、列宽、检查、函数和触发器；任一步失败全部回滚。
7. 重复执行时精确目标状态安全结束；表存在但其他目标缺失不得直接结束。
8. 不使用 `CASCADE`，不读取旧战斗数据，不创建兼容视图或双写。

### 5.3 结果形状函数

结果形状函数扩展到十六个显式分支：

1. 所有十六个分支都统计阶段 7.6 累计九张效果子表，包括本阶段斩杀明细。
2. `EXECUTE` 必须恰好一行斩杀明细和一行数值规则，禁止 `PERSISTENT`，其他类型明细为 0。
3. 两种联动结果必须恰好一行数值规则、detail 为空、斩杀明细和其他类型明细为 0，禁止 `PERSISTENT`。
4. 三种结果使用其他离散时点时继续检查阶段 7.4 数值读取和周期字段；层数值与重复施加值必须为空。
5. 三种结果在 `target = TARGET` 且离散时允许 0～1 条阻挡策略，只允许 `SKILL / EFFECT / RESULT`。
6. 前十三种结果继续满足前段完整形状，并明确斩杀明细行数为 0；`COOLDOWN_CHANGE` 仍必须恰好一条冷却明细并至少一条目标关系。

### 5.4 事件形状函数

1. 事件形状函数扩展到二十一个显式分支，并统计伤害事件、法术护盾阻挡事件和本阶段联动事件三张表。
2. 两种联动事件必须恰好一行联动明细，另两张事件明细为 0。
3. 三种伤害事件和法术护盾事件保持各自恰好一行专属明细；其他十五种三表都为 0。
4. 联动事件本阶段没有事件值；固定集合检查仍不包含 `LINK_INDEX / LINK_COUNT`。

### 5.5 触发器挂载

1. 斩杀明细表的 INSERT/UPDATE/DELETE 重新检查父效果结果。
2. 联动事件表的 INSERT/UPDATE/DELETE 重新检查父规则事件。
3. 既有结果主表、数值规则、冷却目标关系、生命周期行为、阻挡策略和事件主表挂载继续覆盖新类型。
4. 优先扩展累计形状函数和已有触发器，不创建重复检查同一聚合的平行触发器。

## 6. 效果模型、Mapper 与聚合

### 6.1 强类型模型

1. `SkillEffectResultType` 增加三种固定值，detail 密封联合同步扩展到十六个分支。
2. 增加斩杀 detail 请求、响应和 Row 类型；两种联动使用明确空 detail 类型，不能用 Map。
3. 反序列化器按十六种结果完整 switch；缺 detail、错误数值规则或其他种类字段返回 `400.INVALID_BODY`。
4. 三种结果继续包含阶段 7.6.3 公共阻挡范围字段。

### 6.2 Mapper 读取与写入

1. 在效果聚合锁内读取斩杀明细，按完整结果键组装一对一 Map。
2. 两种联动通过结果类型和数值规则组装空 detail，不查询空业务表。
3. 重复、孤儿或类型不匹配行视为数据库契约损坏。
4. 写入顺序把斩杀明细与其他类型明细统一同步，不增加联动专用结果 DAO。

### 6.3 Service 校验

写库前一次收集全部字段问题：

1. 十六种结果 detail 和数值规则互斥形状。
2. 斩杀属性存在、启用且同游戏；三种公式存在且属于当前技能。
3. 三种结果禁止持续生效，并符合离散时点、数值读取、周期字段和阻挡范围要求。
4. 候选效果是否改变既有规则可达参数集合、来源事件匹配或候选图。
5. 公式不求值；不因无法证明非负整数而保存运行结果或增加自由字段。

### 6.4 聚合写入顺序

创建：效果 → 生命周期 → 结果主行 → 数值规则 → 原有/累计类型明细（含斩杀）→ 阻挡策略 → 生命周期行为。

更新：

1. 锁当前聚合和入站规则，形成旧/新快照。
2. 完成引用、可达参数和候选图检查。
3. 删除待移除结果的斩杀明细、阻挡策略及其他子表。
4. 删除结果；更新保留结果；新增结果。
5. 全量同步数值规则、类型明细、阻挡策略和生命周期行为。
6. 提交时由延迟触发器检查完整形状。

任一步失败全部回滚；不得先清空旧聚合后依赖重新插入成功。

## 7. 触发规则增量

### 7.1 事件模型与 Mapper

1. 事件类型增加 `HIT_LINK_APPLIED / ATTACK_LINK_APPLIED` 和共用强类型 detail。
2. Mapper 对两种事件统一读写 `skill_trigger_rule_link_events`。
3. `sourceSkillKey` null 原样回读；非空引用同一游戏技能。
4. 事件能力表固定当前目标为联动目标、`EVENT_SOURCE` 不可用、事件值为空。

### 7.2 可达公式

1. 可达公式收集器加入三种结果的 `valueRule.formulaKey`。
2. 直接执行效果和通过过程挂接到达时都收集。
3. 规则自身绑定错误返回 400；效果 PUT 令已有规则可达集合变化时返回 409 和 `TRIGGER_RULE_RUNTIME_INPUT_IN_USE`。
4. 必须复用同一分析器，不在效果服务复制结果遍历。

### 7.3 候选生产图

1. `EXECUTE` 增加 `KILL / ENTITY_DIED` 候选边。
2. 两种联动结果分别增加对应联动事件边，并按非空 `sourceSkillKey` 缩小匹配。
3. 三种结果带阻挡范围时叠加 `SPELL_SHIELD_BLOCKED` 候选边。
4. 保护边和残余有向环检查继续复用阶段 7.5。
5. 跨技能挂载未知时不建无法证明的本地边。

## 8. 引用与删除保护

1. `SkillService` 删除技能时保留既有冷却目标关系入站检查，并增加其他技能规则中本阶段联动事件的 `source_skill_key` 检查；两类查询都排除待删技能自身聚合，任一外部引用返回既有 `409.SKILL_IN_USE`，自引用不阻止整技能删除。
2. 公式删除若已统一检查 `skill_effect_result_values`，三种结果自动受保护；若现有实现按结果类型枚举，只补三种值并保持 `409.SKILL_FORMULA_IN_USE`。
3. 当前属性没有独立删除能力时不新增接口；新增/改选斩杀属性仍检查存在、启用和同游戏。
4. 三种公式变化改变既有规则可达参数集合时返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_RUNTIME_INPUT_IN_USE`。
5. 结果/事件变化形成无保护环时返回 400 循环错误并保持原聚合。
6. 数据库外键和延迟检查只作并发防线，未知约束保留服务端错误。

3. 通过真实效果/过程/规则接口完成艾希 Q、鬼索和收集者骨架案例。
4. 关闭客户端并重启后端，再次 GET 验证完整回读来自 PostgreSQL。
5. 验证非法生命周期、来源技能删除保护、事务回滚、循环检查和迁移重复执行。
6. 确认接口没有丰富前序输出、联动事件值或实际斩杀/联动后，前端才能进入真实浏览器验收。

## 12. 后端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.6.3 最终结果、事件、阻挡范围、来源技能引用或候选图与本文前提不一致。
2. 需要增加阶段 7.6.5 输出、事件值或通用结果表才能完成本阶段。
3. 联动结果必须保存目标技能、运行次数、攻击模板或自由关系。
4. 效果或规则无法在一次聚合事务中维护，必须暴露半成品子接口。
5. 必须保存 JSONB、数组、自由字符串或通用多态关系。
6. 需要执行公式、斩杀、联动、攻击、事件、结算或 Wasm 才能完成结构校验。
7. 真实数据库、接口或重启回读验收不可用且无法定点确认原因。

在 Cursor 只读评审、项目负责人确认及前段完整验收之前，本设计不授权任何后端、SQL、数据库或服务操作。
