# 装备基本管理后端详细设计

本文实施[装备基本管理共享契约](../../项目/装备基本管理详细设计.md)，不重复定义接口字段和错误含义。

## 1. 写入范围

1. `db/game_manage/schema.sql` 与一份幂等兼容迁移。
2. `server/data_manage` 下独立的装备 controller、service、mapper、模型和测试。
3. 装备实现不得读取或写入旧 item、Provider、发布和 Wasm 表。

## 2. 数据库存储

1. `equipment` 保存装备基本资料，主键为 `(game_id, equipment_key)`，名称在游戏内按规范化值唯一。
2. `equipment_attributes` 保存一条 JSONB 直接属性 Map，主外键同为 `(game_id, equipment_key)`，删除装备时级联删除。
3. 创建装备时在同一事务插入空属性对象。

## 3. 后端实现

1. 目录按 `equipment` 独立建立，不复用角色业务类型。
2. service 负责字段归一化、重复校验、游戏和装备存在性、属性定义读取、整块属性校验与事务边界。
3. mapper 只访问 `equipment`、`equipment_attributes`、`attributes` 和 `games`。
4. Admin controller 记录现有编辑日志。

## 4. 验证

1. 数据库契约测试覆盖表、约束、索引、外键和迁移幂等文本。
2. service 测试覆盖增删改查、名称和标识重复、未知属性、整数与范围校验、整块失败不写入。
3. 执行 `mvn test`。
4. 对真实数据库执行兼容迁移后，用真实接口验证创建、回读、属性整块保存、删除和 404。
