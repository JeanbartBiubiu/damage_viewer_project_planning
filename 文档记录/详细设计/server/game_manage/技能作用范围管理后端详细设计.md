## 4. 数据库最终结构

### 4.1 公共范围主表

新增 `public.skill_effect_result_skill_scopes`：

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`effect_key`、`result_key` | 主键；完整引用 `skill_effect_results`，删除结果时级联。 |
| `mode` | 非空，只允许共享契约三种值。 |

该表不保存结果操作、公式、生命周期或目录标识。

### 4.2 明确技能关系

新增 `public.skill_effect_result_skill_targets`：

1. 父级复合外键引用公共范围主表，删除范围时级联。
2. `affected_skill_key` 完整引用同一游戏技能，删除目录时限制。
3. 主键为范围父键加 `affected_skill_key`。
4. 建立以 `(game_id, affected_skill_key)` 开头的反向索引。

### 4.3 技能分类关系

新增 `public.skill_effect_result_skill_category_targets`：

1. 父级复合外键引用公共范围主表，删除范围时级联。
2. `skill_category_key` 完整引用同一游戏技能分类，删除目录时限制。
3. 主键为范围父键加 `skill_category_key`。
4. 建立以 `(game_id, skill_category_key)` 开头的反向索引。

### 4.4 技能急速结果明细

新增 `public.skill_effect_haste_modifier_details`：

1. 主键完整引用所属 `skill_effect_results`，删除结果时级联。
2. `operation` 非空，只允许增加或减少。
3. 不保存范围字段、公式、生命周期或乘区。

### 4.5 移除旧结构与表数

迁移成功后删除 `public.skill_effect_cooldown_change_targets`。冷却操作明细表继续保留。

本补项新增四张表、移除一张表，相对 85 张前置净增三张，新库目标为 88 张。阶段 7.6 既有十三张累计表仍是历史事实，本补项单独计数。

公共范围表只引用一种真实父表 `skill_effect_results`，不是对象类型加自由标识的多态关系。

## 5. 数据库完整形状

`trg_skill_effect_result_complete_shape()` 需要增加公共范围和技能急速明细计数：

1. `COOLDOWN_CHANGE`：恰好一条冷却明细、恰好一条公共范围、零条技能急速明细。
2. `SKILL_HASTE_MODIFIER`：恰好一条数值规则、一条公共范围和一条技能急速明细，其他类型明细全部为零。
3. 其余十五种结果不得有公共范围或技能急速明细：`DAMAGE / DIRECT_HEAL / NORMAL_SHIELD / ATTRIBUTE_CHANGE / RESOURCE_CHANGE / STATUS_OPERATION / LIFECYCLE_OPERATION / DAMAGE_MODIFIER / HEALING_MODIFIER / DAMAGE_IMMUNITY / HEALTH_FLOOR / SPELL_SHIELD / EXECUTE / HIT_LINK_APPLICATION / ATTACK_LINK_APPLICATION`。
4. `ALL`：两种目标关系均为零。
5. `SKILLS`：明确技能关系至少一条、分类关系为零。
6. `CATEGORIES`：明确技能关系为零、分类关系至少一条。
7. 技能急速结果必须有生命周期、时点为持续生效、读取方式为施加时快照。
8. 技能急速结果的法术护盾策略和乘区引用均为零。

冷却变化现有数据库 `v_cooldown_target_count < 1` 断言必须替换为公共范围模式检查：`ALL` 允许两类关系均为零，只有 `SKILLS / CATEGORIES` 分别要求对应关系至少一条。

四张新表加入结果子表延迟形状触发器清单。旧冷却目标表从清单删除。数据库在事务提交时再次检查，Service 仍需提前返回业务 400。

## 6. 兼容迁移

新增 `skill_scope_management_migration.sql`，采用单一事务：

1. 精确核对阶段 7.6.5 的 85 张父表、十六种结果、旧冷却目标表、生命周期矩阵和阶段 7.6.5 检查。
2. 四张新表必须全部缺失或全部结构正确；部分存在立即失败。
3. 前置态要求旧冷却目标表存在；目标态要求旧表不存在。
4. 沿用现有兼容迁移做法，对本次读取、复制、替换的结果与冷却关系表取得 `ACCESS EXCLUSIVE` 锁，再创建四张新表及全部主键、复合外键、检查和反向索引。
5. 为每个既有冷却变化结果插入一条公共范围，模式固定为 `SKILLS`。
6. 将旧表每条 `affected_skill_key` 复制到公共明确技能关系。
7. 按结果数、关系总数和逐结果目标数三层核对；任何不一致主动失败。
8. 更新结果种类检查、结果形状函数、生命周期检查和相关延迟触发器。
9. 核对新关系完成后删除旧目标表。
10. 不回填技能急速业务记录，不创建示例分类、公式或效果。
11. 目标态重复执行时完整核对结构与函数后成功退出，不重复数据。
12. 未知列、约束、索引、函数、前置枚举或部分目标结构全部失败并回滚。

不提供双写触发器、旧字段响应或第二阶段清理脚本。

## 9. Service 校验和事务

### 9.1 引用收集

扩展现有 `CollectedRefs` 和 `ExistingCatalog`：

1. 公共范围 `SKILLS` 收集技能标识。
2. 公共范围 `CATEGORIES` 收集技能分类标识。
3. 技能急速数值规则继续进入公式集合。
4. 原始范围复合元组用于判断停用引用是否原样保留。
5. 形状错误、空值和重复项先形成字段问题，不进入锁定集合。

### 9.2 锁定顺序

创建和修改统一采用：公式 → 伤害类型 → 属性 → 技能 → 技能分类 → 状态 → 乘区 → 目标效果 → 目标生命周期。各目录键先按稳定标识排序再批量锁定；技能分类插在技能与状态之间，不允许两条写路径采用不同顺序。

### 9.3 结果校验

1. 仅冷却变化和技能急速结果允许公共范围。
2. 三种模式严格执行数组形状。
3. 新引用必须存在、同游戏且启用。
4. PUT 只允许完整复合引用原样保留停用项。
5. 冷却变化继续校验操作和值规则组合。
6. 技能急速结果校验数值规则、生命周期、快照读取、禁止乘区和禁止法术护盾范围。
7. 技能急速结果允许 `SOURCE / TARGET`，不增加角色/装备来源检查。

停用引用沿用现有统一处理：未知或跨游戏进入 `400.INVALID_SKILL_EFFECT_REFERENCE`；停用且不是 PUT 原样保留进入 `409.SKILL_EFFECT_REFERENCE_DISABLED`。不得只对技能分类另设 400，也不得改动其他目录引用的既有语义。

### 9.4 写入

1. 新结果先写结果主记录和值规则，再写类型明细、公共范围和目标关系，最后写生命周期行为。
2. 更新保留结果时原地更新公共范围，清空两种旧关系后只写当前模式关系。
3. 冷却结果不再调用旧目标 Mapper。
4. 删除结果由结果主记录级联清理公共范围、目标关系和技能急速明细。
5. 任一步失败时整个效果聚合回滚。

## 10. 删除保护

1. `SkillService.delete` 在自身清理前检查其他技能拥有的公共明确技能关系。
2. 外部引用复用 `409.SKILL_IN_USE`，文案覆盖冷却变化和其他技能范围，不再只写冷却变化。
3. 待删技能自己的效果引用自身不阻止删除。
4. 技能分类删除由真实外键复用 `409.SKILL_CATEGORY_IN_USE`，不得级联删除范围。
5. 技能急速公式继续由数值规则外键保护并复用 `409.SKILL_FORMULA_IN_USE`。

## 11. 阶段 7.6.5 累计兼容

1. 技能急速数值公式由现有通用结果值收集进入可达公式分析。
2. 技能急速为持续结果，不进入立即可用前序输出。
3. 冷却结果既有 `RESET` 无配置值、其余操作有配置值的规则不变。
4. 十种前序输出、二十一种事件和二十三种事件值不变。
5. 候选事件图不因公共范围新增边；技能急速结果不产生副作用事件边。
6. 所有 `switch`、结果资格白名单和数据库固定集合显式覆盖第十七种结果，不能由默认分支吞掉。
7. 效果 PUT 改变技能急速公式时继续执行触发规则运行输入绑定保护。
8. `validatePersistentBehavior`、`validatePersistentSpecialResultLifecycle`、数据库持续时点允许集合和必须持续生效集合显式加入 `SKILL_HASTE_MODIFIER`。
9. 技能急速只允许施加时快照；不能加入按当前时点读取白名单。持续数值行为固定生成并校验 `stackValueMode = SHARED`、`reapplicationValueMode = KEEP`。
