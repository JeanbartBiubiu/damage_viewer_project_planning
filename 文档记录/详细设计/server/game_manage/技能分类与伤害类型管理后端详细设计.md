## 2. 数据库存储

### 2.1 `public.skill_categories`

```sql
CREATE TABLE public.skill_categories (
    game_id varchar(64) NOT NULL,
    skill_category_key varchar(64) NOT NULL,
    name varchar(100) NOT NULL,
    description text,
    status varchar(16) NOT NULL DEFAULT 'ENABLED',
    sort_order integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT pk_skill_categories PRIMARY KEY (game_id, skill_category_key),
    CONSTRAINT fk_skill_categories_game
        FOREIGN KEY (game_id) REFERENCES public.games (game_id),
    CONSTRAINT ck_skill_categories_key
        CHECK (skill_category_key ~ '^[a-z][a-z0-9_]{0,63}$'),
    CONSTRAINT ck_skill_categories_name CHECK (btrim(name) <> ''),
    CONSTRAINT ck_skill_categories_status CHECK (status IN ('ENABLED', 'DISABLED')),
    CONSTRAINT ck_skill_categories_sort_order CHECK (sort_order >= 0)
);

CREATE UNIQUE INDEX uq_skill_categories_name
    ON public.skill_categories (game_id, lower(btrim(name)));
```

### 2.2 `public.damage_types`

```sql
CREATE TABLE public.damage_types (
    game_id varchar(64) NOT NULL,
    damage_type_key varchar(64) NOT NULL,
    name varchar(100) NOT NULL,
    description text,
    status varchar(16) NOT NULL DEFAULT 'ENABLED',
    sort_order integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT pk_damage_types PRIMARY KEY (game_id, damage_type_key),
    CONSTRAINT fk_damage_types_game
        FOREIGN KEY (game_id) REFERENCES public.games (game_id),
    CONSTRAINT ck_damage_types_key
        CHECK (damage_type_key ~ '^[a-z][a-z0-9_]{0,63}$'),
    CONSTRAINT ck_damage_types_name CHECK (btrim(name) <> ''),
    CONSTRAINT ck_damage_types_status CHECK (status IN ('ENABLED', 'DISABLED')),
    CONSTRAINT ck_damage_types_sort_order CHECK (sort_order >= 0)
);

CREATE UNIQUE INDEX uq_damage_types_name
    ON public.damage_types (game_id, lower(btrim(name)));
```

两张表只保存共享契约字段，不增加 JSONB、数值公式、抗性属性、颜色、图标、发布 revision、日志表或多态关系。`skill_categories` 保持单层结构，不增加分类分组、组内选择规则或唯一类型字段。后续技能与技能分类使用关联表表达多选；后续伤害效果通过真实外键选择伤害类型。引用表均不在本阶段提前创建。

## 4. 后端模块

分别建立两个包，不新增技能分类分组、通用类型服务或通用字典框架：

```text
controller/adminapi/skillcategory/**

resources/mapper/skillcategory/**

controller/adminapi/damagetype/**
service/damagetype/**

```

每组包含强类型的创建、更新、列表查询、列表响应、单条响应和状态枚举。更新请求显式声明对应稳定标识字段并使用 `@Null` 约束，防止请求体中的新标识被静默忽略；列表查询的 `status` 先按字符串接收，再由资源服务映射为状态枚举。控制器沿用现有 Admin 过滤器；POST、PUT、DELETE 使用 `AdminEditLogHelper` 记录编辑日志。

## 5. 服务与事务

两组服务独立实现以下事务，不以一个资源的 DTO 或 Service 承载另一个资源：

1. 列表：先验证游戏存在，再规范化查询并按共享顺序返回。
2. 详情：游戏不存在和记录不存在分别映射共享 404。
3. 创建：trim 字段、校验重复标识和规范化名称、单事务插入并回读。
4. 更新：先按复合主键 `FOR UPDATE` 锁定；稳定标识不可修改；全量更新可编辑字段并写 `updated_at=now()`。
5. 删除：先锁定目标；不存在返回 404；执行物理删除。仅将 SQLSTATE `23503` 外键冲突映射为共享 `IN_USE`，其他完整性错误不得伪装为引用冲突。
6. 数据库唯一约束是并发最终真源，按 `pk_*` 和 `uq_*_name` 约束名映射共享重复错误，不返回数据库原文。
