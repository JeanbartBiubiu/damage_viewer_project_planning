## 4. 数据库结构

本阶段只增加四张表，并给一张既有表增加两列。

### 4.1 伤害明细扩列

`skill_effect_damage_details` 增加：

1. `delivery_kind varchar(32) NOT NULL`，检查 `SKILL / BASIC_ATTACK`。
2. `origin_kind varchar(32) NOT NULL`，检查 `DIRECT / REFLECTED`。

既有行迁移为 `SKILL + DIRECT`。完成后不保留数据库默认值。

### 4.2 暴击策略

`skill_effect_result_critical_policies`：

1. 主键为 `game_id + skill_key + effect_key + result_key`。
2. 完整外键引用 `skill_effect_results` 并随结果级联删除。
3. `critical_mode varchar(32) NOT NULL`，检查 `DISALLOWED / SOURCE_CRIT_CHANCE / FORCED`。
4. `multiplier_formula_key varchar(64)` 可空；非空时以 `(game_id, skill_key, multiplier_formula_key)` 复合外键引用当前技能公式并 `RESTRICT`。
5. 反向公式引用索引以 `game_id + skill_key + multiplier_formula_key` 开头。
6. 每个伤害结果恰好一行，其他结果不得有行；倍率公式与模式组合由 Service 和延迟形状函数共同检查。

### 4.3 吸血规则

`skill_effect_result_vamp_rules`：

1. 主键为结果完整键加 `vamp_type`。
2. 完整外键引用父结果并级联删除。
3. `vamp_type varchar(32) NOT NULL`，检查四种固定值。
4. `basis_output_kind varchar(32) NOT NULL`，只检查 `POST_DEFENSE_DAMAGE / ACTUAL_HP_LOSS`。
5. `efficiency_formula_key varchar(64) NOT NULL`，复合外键引用当前技能公式并 `RESTRICT`。
6. 反向公式引用索引以 `game_id + skill_key + efficiency_formula_key` 开头。
7. 只允许父结果为伤害；主键天然保证同一吸血种类不重复，形状函数限制每个伤害最多四行。

### 4.4 普通护盾交互

`skill_effect_result_normal_shield_interactions`：

1. 主键为结果完整键，完整外键引用父结果并级联删除。
2. `absorbed_damage_type_key varchar(64)` 可空；非空时复合外键引用同游戏伤害类型并 `RESTRICT`。
3. `decay_mode varchar(32) NOT NULL`，检查 `NONE / LINEAR_TO_ZERO`。
4. 反向伤害类型索引以 `game_id + absorbed_damage_type_key` 开头。
5. 每个普通护盾恰好一行，其他结果不得有行。
6. 线性衰减必须联表检查 `duration_formula_key` 非空、整体到期、`PERSISTENT` 和共享值；禁止逐层到期、每层独立到期和每层值。

### 4.5 伤害事件筛选

按阶段 7.5 最终规则主键建立 `skill_trigger_rule_damage_events`：

1. 主键为 `game_id + skill_key + rule_key`，完整外键引用规则并级联删除。
2. `damage_type_key varchar(64)` 可空；非空时复合外键引用同游戏伤害类型并 `RESTRICT`。
3. `delivery_kind varchar(32) NOT NULL`，检查 `ANY / SKILL / BASIC_ATTACK`。
4. `origin_kind varchar(32) NOT NULL`，检查 `ANY / DIRECT / REFLECTED`。
5. 反向伤害类型索引以 `game_id + damage_type_key` 开头。
6. 只允许 `DAMAGE_DEALT / DAMAGE_TAKEN`，二者必须恰好一行；其他十五种事件不得有行。

`DAMAGE_PENDING` 不在本阶段事件检查值中，也不得向本表写入该事件。

1. 动作目标效果包含 `REFLECTED` 伤害时，事件必须为 `DAMAGE_TAKEN`，动作目标必须为 `EVENT_SOURCE`。
2. `eventSource.detail.originKind = DIRECT` 或规则存在合法每目标冷却；否则返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED / REFLECT_LOOP_UNGUARDED`。
3. 规则创建、更新、删除和被引用效果形状变化均重新检查当前技能候选图。
4. 生产表仍使用阶段 7.5 既有事件：`target=TARGET` 伤害可能产生 `DAMAGE_DEALT`，`target=SOURCE` 伤害可能产生 `DAMAGE_TAKEN`；本阶段只增加按三项筛选匹配，不增加 `DAMAGE_PENDING`。

### 7.3 动作可达公式

1. 执行效果动作收集伤害原数值规则、非空暴击倍率与全部吸血效率公式。
2. 启动过程动作经直接效果挂接到达伤害时使用同一收集规则。
3. 可达参数集合与实际绑定集合必须完全相等；字段错误定位实际动作和绑定下标。
4. 前序结果输出集合保持阶段 7.5 原样，本阶段不改变 `output_kind` 检查或来源矩阵。

触发规则自身 POST/PUT 的缺失、多余或类型不兼容绑定继续返回 `400.INVALID_RUNTIME_INPUT_BINDING` 并定位规则字段；不得与上节效果 PUT 的 409 混用。

## 8. 引用与删除保护

1. `SkillFormulaService` 删除前检查暴击倍率和吸血效率，继续返回 `409.SKILL_FORMULA_IN_USE`。
2. `DamageTypeService` 删除前检查普通伤害、普通护盾交互和伤害事件筛选，返回 `409.DAMAGE_TYPE_IN_USE`。
3. 修改或删除效果结果前仍检查阶段 7.3～7.5 入站引用；暴击/吸血公式变更导致既有规则可达参数集合变化时返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_RUNTIME_INPUT_IN_USE`，其他本阶段新增形状令规则失效时沿用既有 409，新形成无保护环则返回 400 循环错误。
4. 删除技能自身时先删自身触发规则，再按既有过程、效果、内部状态、公式、参数和技能顺序清理；不单独建立阶段 7.6.1 删除入口。
5. 复合外键或延迟检查只作并发防线，Service 预检查应给出稳定业务错误；未知约束保留服务端错误并由测试暴露。
