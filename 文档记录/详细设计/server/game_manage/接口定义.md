# game_manage 接口定义（当前后端索引）

当前业务接口以 [后端 README](../../../../server/data_manage/README.md) 与对应功能契约为准；本文下方旧战斗数据、版本发布等章节仅作历史参考，不作为当前开发入口。

符文基础管理新增 `/api/admin/games/{gameId}/runes`、`/rune-paths` 的列表、详情、增改删及 `/rune-skill-relations` 的双向查询、挂载、调序与解绑；符文和分组分别提供 `representative-image` 子资源。字段、错误、完整布局及图片用途响应仅由 [符文基础管理详细设计](../../../../../damage_viewer_project_planning/文档记录/详细设计/项目/符文基础管理详细设计.md) 定义。后端入口为 `controller/adminapi/rune/**` 与 `RuneSkillRelationAdminController`，追加迁移见后端 README；当前没有符文发布或战斗执行接口。

下文历史 DDL、revision、资源路径与 PUT 规则对应 [通用 1v1 战斗数据模型 DDL 与接口详细设计](./通用1v1战斗数据模型DDL与接口详细设计.md)，历史系统边界见 [通用 1v1 战斗数据模型替换方案](../../../概要设计/server/通用1v1战斗数据模型替换方案.md)。

## 1. 统一约定

### 1.1 成功响应

- 保留接口（games / current version / images / publish）：直接返回 JSON 对象或数组。
- Public `/combat-data/**`：统一 envelope：

```json
{
  "gameId": "lol",
  "currentRevision": 0,
  "data": []
}
```

单条 GET 的 `data` 为 object，列表 GET 为 array。

- Admin `/combat-data/**` PUT：返回写入对象，并附带 `currentRevision`。

### 1.2 失败响应

```json
{
  "error": {
    "code": "400.INVALID_BODY",
    "message": "human readable message",
    "details": {}
  }
}
```

常见错误码：`400.INVALID_BODY`、`401.UNAUTHORIZED`、`403.FORBIDDEN`、`404.NOT_FOUND`、`409.CONFLICT`、`500.INTERNAL_ERROR`。

### 1.3 写约束

1. 不提供 DELETE；不提供通用 batch。
2. 每个 Admin PUT 独立事务，只增加一次 `current_revision`。
3. 请求体不得提交 `changeRevision` / `currentRevision` / `versionId` / `versionCode`。
4. 后端只保证 JSON 可解析、必填字段、基础类型与数据库约束；语义校验由 Web 负责。
5. **具名聚合写例外（仅此两处）**：`PUT .../entities/{entityId}:batch`（见 §4.2）与 `PUT .../providers/{providerId}/abilities/{abilityId}:direct-damage-setup`（见 §4.3）。均为窄范围、原子、乐观并发；通用 batch/delete 仍禁止。

## 4. Admin `/combat-data/**`

基路径：`/api/admin/games/{gameId}/combat-data`

### 4.1 类型与基础

```text
PUT /progression-schema
PUT /attribute-definitions/{attrKey}
PUT /resource-definitions/{resourceKey}
PUT /types/{typeId}
PUT /type-relations/{typeId}/{targetCategory}/{targetId}
```

`PUT /attribute-definitions/{attrKey}` 与对应 Public `GET` 暴露可选 `imageUri`（同游戏 `images.uri` 引用）。请求省略则保留既有关联（新行起步为 null）；JSON `null` 或空白字符串清除；非空字符串须精确存在于同游戏 `images(game_id, uri)`，否则 `400.INVALID_BODY`（`details.path=/imageUri`），且发生在 `nextRevision` 之前；出现非文本类型同样 `400.INVALID_BODY`（`/imageUri`）。不做 Web URI 正则校验。URI 随 `change_revision` 版本化；`images` 表字节本身不版本化。

### 4.2 Entity

```text
PUT /entities/{entityId}
PUT /entities/{entityId}/attributes/{attrKey}
PUT /entities/{entityId}/attributes/{attrKey}/stages/{stage}
PUT /entities/{entityId}/resources/{resourceKey}
PUT /entities/{entityId}/resources/{resourceKey}/stages/{stage}
PUT /entities/{entityId}/provider-mounts/{providerId}
PUT /entities/{entityId}:batch
```

细粒度 PUT 行为不变。`PUT /entities/{entityId}` 与对应 Public `GET` 同样暴露可选 `imageUri`，语义与 §4.1 属性定义一致（省略保留 / null·空白清除 / 同游戏精确存在 / 非文本与缺失引用在 revision 分配前 `400.INVALID_BODY` `/imageUri`）。

`:batch` 是受控聚合写例外之一（另一处见 §4.3 `:direct-damage-setup`）：

- 路径 `entityId` 为准；一次事务写入实体元数据，以及请求中提交的 attributes / resources / providerMounts。
- 顶层允许字段：`expectedCurrentRevision`、`entityId`、`displayName`、`description`、`imageUri`、`attributes`、`resources`、`providerMounts`。
- 提交的每个 attribute / resource 必须带唯一 key，且 `stages` 恰好覆盖 level `1..18`（LoL 实体编辑器合同，不上升为通用 DDL）。
- `providerMounts` 仅加性 upsert；省略的 attributes / resources / mounts 保持不动（无替换、无删除）。
- 必填 `expectedCurrentRevision`：先完整校验文档（含 `imageUri` 解析），再锁定并在匹配时恰好递增一次 revision；不匹配返回 `409.REVISION_CONFLICT`（含 expected / actual），不写库。
- 成功响应返回服务端权威聚合对象，并含 `gameId`、`entityId`、`currentRevision`；写一条 Admin edit audit。

通用 batch / DELETE 仍不提供。

### 4.3 Provider / Ability / Effect

```text
PUT /providers/{providerId}
PUT /providers/{providerId}/lifecycle
PUT /providers/{providerId}/formulas/{formulaKey}
PUT /providers/{providerId}/state-fields/{stateKey}
PUT /provider-modifiers/{modifierId}
PUT /provider-listeners/{listenerId}
PUT /listeners/{listenerId}/match-types/{matchModeTypeId}/{typeId}
PUT /providers/{providerId}/tick-sequences/{sequenceId}

PUT /abilities/{abilityId}
PUT /providers/{providerId}/abilities/{abilityId}:direct-damage-setup
PUT /abilities/{abilityId}/parameters/{paramKey}
PUT /abilities/{abilityId}/state-fields/{stateKey}
PUT /ability-phases/{phaseId}
PUT /ability-costs/{costId}
PUT /ability-cooldowns/{cooldownId}

PUT /effect-sequences/{sequenceId}
PUT /effect-steps/{stepId}
PUT /ability-phases/{phaseId}/effect-sequences/{triggerTypeId}/{sequenceId}
PUT /listeners/{listenerId}/effect-sequences/{sequenceId}
```

`PUT /effect-steps/{stepId}` body 含公共字段与恰好一种 detail，同事务写入。

`PUT .../providers/{providerId}/abilities/{abilityId}:direct-damage-setup` 是第二处具名聚合写例外（非通用 batch）：

- 一次事务创建/更新恰好一条 Ability → AbilityPhase → provider 归属 EffectSequence → 一条仅含 `damageDetail` 的 EffectStep → 一条 phase-effect-sequence binding。
- 请求体仅允许顶层键：`expectedCurrentRevision`、`ability`、`phase`、`effectSequence`、`effectStep`、`phaseEffectSequenceBinding`；拒绝未知字段；`*TypeId` 保持整数合同。
- 完整校验（含 path/嵌套身份交叉校验与仅允许 `damageDetail`）先于 revision 分配；匹配后恰好递增一次 revision；`409.REVISION_CONFLICT` 时不写库。
- 成功响应返回权威聚合：`gameId` / `providerId` / `abilityId` / `currentRevision` 与上述五个嵌套节点；写一条 Admin edit audit。
- 不调用细粒度 `putAbility` / `putPhase` / `putSequence` / `putStep` / `putPhaseEffectSequence`（那些各自分配 revision）；细粒度路径行为不变。
