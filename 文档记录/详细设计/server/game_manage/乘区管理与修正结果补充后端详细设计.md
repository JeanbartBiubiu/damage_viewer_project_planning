## 4. 数据库结构

### 4.1 `modifier_zones`

新表列：

| 列 | 规则 |
| --- | --- |
| `game_id` | 非空，完整外键到游戏。 |
| `zone_key` | 非空，与 `game_id` 组成主键。 |
| `name` | 非空。 |
| `domain` | `ATTRIBUTE / DAMAGE / HEALING`。 |
| `calculation_mode` | `FLAT_ADD / RATIO_ADD`。 |
| `application_stage` | 共享契约固定五值。 |
| `description` | 可空。 |
| `status` | `ENABLED / DISABLED`。 |
| `sort_order` | 非负整数。 |
| `created_at / updated_at` | 非空时间戳。 |

约束和索引：

1. `zone_key` 使用当前稳定标识检查。
2. 一个组合检查精确限制共享契约五种 `domain + calculation_mode + application_stage`，不能分别放宽后形成无意义组合。
3. 以 `game_id + lower(btrim(name))` 建唯一索引；停用记录继续占用名称。
4. 列表索引为 `game_id + sort_order + name + zone_key`。
5. 不增加 `bucket_config`、JSONB、聚合方式、优先级、钳制、来源类型或目标属性列。

### 4.2 三处结果外键

1. `skill_effect_damage_modifier_details` 增加非空 `modifier_zone_key`。
2. `skill_effect_healing_modifier_details` 增加非空 `modifier_zone_key`。
3. `skill_effect_attribute_change_details` 增加可空 `modifier_zone_key`。
4. 三处都使用 `game_id + modifier_zone_key` 完整外键到 `modifier_zones`，删除行为为 `RESTRICT`。
5. 三处都建立以 `game_id + modifier_zone_key` 开头的反向索引。
6. 属性明细只有 `PERSISTENT + INCREASE/DECREASE` 必须非空；离散属性变化和 `SET` 必须为空。该跨表形状由结果延迟检查负责，不通过宽空字段规避。

### 4.3 跨表兼容检查

结果形状函数增加：

1. 持续属性增加/减少引用的乘区必须为 `ATTRIBUTE`。
2. 伤害修正引用的乘区必须为 `DAMAGE + RATIO_ADD`。
3. 治疗修正引用的乘区必须为 `HEALING + RATIO_ADD`。
4. 乘区状态不进入数据库形状检查；停用只影响新增或改选，由 Service 按旧引用规则处理。
5. `ATTRIBUTE_CHANGE + SET`、离散属性变化和其他九种结果必须没有乘区引用。

`modifier_zones` 的 `domain / calculation_mode / application_stage` 更新也要挂延迟检查：事务结束时若任一现有引用与新结构不兼容，整体失败。外键继续负责删除并发防线。

### 5.1 新库

### 5.2 独立兼容迁移

`modifier_zone_management_migration.sql` 使用一个显式事务：

1. 精确核对阶段 7.6.2 当前表、列、主外键、检查、形状函数和触发器。
2. 在任何 DDL 前统计现有伤害修正、治疗修正以及 `PERSISTENT + INCREASE/DECREASE` 属性结果。
3. 只要上述任一类存在无法明确归区的记录，抛出包含三类数量的错误并整体停止；不得自动插入“通用乘区”，不得用方向或名称猜测。
4. 目标记录为零时创建乘区表，给三张明细表增加列、外键和索引，替换形状函数并挂载触发器。
5. 迁移不写业务乘区种子。迁移后由管理页面或真实接口创建所需乘区。
6. 全部目标结构已精确存在时重复执行安全结束；部分存在、约束缺失或函数漂移时主动失败。
7. 不使用 `DROP CASCADE`、旧表复制、兼容视图、双读或双写。

如果真实库存在上述记录，开发实施必须停在迁移前，由项目负责人选择通过现有接口删除测试记录，或单独提供“旧结果 → 乘区”明确映射；不在通用迁移中写样本特例。

### 5.3 `triggers.sql`

1. 刷新现有结果形状函数，使三种结果检查乘区存在和兼容关系。
2. 三张结果明细表的既有 INSERT/UPDATE/DELETE 延迟触发器继续覆盖新增列。
3. `modifier_zones` 结构字段更新增加延迟兼容触发器；名称、说明、状态、排序更新时间不触发业务形状扫描。
4. 不增加运行结算触发器，也不把关系检查放到应用启动代码。

## 6. 乘区模型与管理接口

### 6.1 模型

`model/modifierzone` 增加：

1. `ModifierZoneDomain`
2. `ModifierZoneCalculationMode`
3. `ModifierZoneApplicationStage`
4. `ModifierZoneStatus`
5. `ModifierZoneCreateRequest / ModifierZoneUpdateRequest`
6. `ModifierZoneListQuery / ModifierZoneListResponse`
7. `ModifierZoneResponse / ModifierZoneRow`

固定枚举使用严格 Jackson 绑定；未知值返回 `400.INVALID_BODY`。请求字段和组合的业务错误一次收集后返回共享字段问题。

### 6.2 Mapper

`ModifierZoneMapper` 和 XML 负责：

1. 游戏内关键词、作用范围、状态过滤列表及总数。
2. 详情查询和 `FOR UPDATE` 锁定。
3. 规范化名称冲突查询。
4. 新建、全量更新和删除。
5. 统计属性、伤害、治疗三处引用，并按稳定来源顺序返回占用摘要。

列表不得 join 技能效果形成重复行；引用统计只在删除或结构更新校验时执行。

### 6.3 Service

`ModifierZoneService` 复用当前游戏存在校验、状态模式和唯一错误映射：

1. 创建前校验稳定标识、名称、固定组合和名称唯一。
2. 更新先锁乘区；`modifierZoneKey` 只取路径。已被引用时禁止修改作用范围、计算方式和结算阶段。
3. 停用允许被引用；恢复启用不改引用。
4. 删除先锁乘区并检查三类引用，存在引用返回 `409.MODIFIER_ZONE_IN_USE`；数据库外键处理并发兜底。
5. 创建、修改、删除都由 Controller 写管理编辑日志。

### 6.4 Controller

`ModifierZoneAdminController` 路径和五个方法严格实现共享接口。GET 仍经过当前 Admin 鉴权边界；请求路径编码、统一错误外壳和日志方式复用伤害类型管理，不建立第二套基础设施。

## 7. 技能效果聚合调整

### 7.1 强类型明细

1. `SkillEffectDamageModifierDetail`、Row 和响应增加 `modifierZoneKey`。
2. `SkillEffectHealingModifierDetail`、Row 和响应增加 `modifierZoneKey`。
3. `SkillEffectAttributeChangeDetail`、Row 和响应增加可空 `modifierZoneKey`。
4. 反序列化器继续拒绝其他结果携带该字段；不把字段放到结果公共基类。

### 7.2 Mapper

1. 三张明细读写新增列，聚合响应只返回稳定键，不展开乘区名称或整个乘区对象。
2. 效果聚合锁定后，按 `modifierZoneKey` 稳定顺序锁定本次新增或改选乘区，避免结构更新与效果保存竞态。
3. 重复、孤儿、空的必填乘区或不兼容数据库行继续视为数据契约损坏，不自动降级为空。

### 7.3 Service 校验

写库前一次收集：

1. 字段是否按结果种类和生命周期必填或禁止。
2. 乘区是否存在于同一游戏。
3. 新增或改选引用是否启用；原样保留的停用引用允许继续保存。
4. 作用范围、计算方式和阶段是否满足共享固定组合。
5. 生命周期动态读取矩阵是否完整。
6. `MOMENT_EVALUATION` 公式不得包含 `RUNTIME_INPUT` 参数；复用现有公式参数分析结果，不在效果 Service 复制公式树遍历。

错误定位到实际 `results[i].detail.modifierZoneKey` 或 `results[i].lifecycleBehavior.*`。乘区变化不改变公式引用集合时，不得误报触发规则运行输入占用。

## 8. 生命周期矩阵调整

1. 原有无生命周期结果和离散属性变化规则不变。
2. `PERSISTENT + ATTRIBUTE_CHANGE + INCREASE/DECREASE`、`DAMAGE_MODIFIER`、`HEALING_MODIFIER` 允许 `APPLICATION_SNAPSHOT` 或 `MOMENT_EVALUATION`。
3. `APPLICATION_SNAPSHOT` 沿用当前 `SHARED / PER_STACK` 和重复施加值矩阵。
4. `MOMENT_EVALUATION` 允许 `SHARED / PER_STACK`，`reapplicationValueMode` 必须 null；共享值每个实例贡献一次，每层值按有效层分别贡献。
5. 其他 `PERSISTENT` 结果继续使用原矩阵；不得把动态读取开放给属性覆盖、普通护盾、生命下限或没有数值规则的结果。
6. `SkillEffectService` 的通用“PERSISTENT 只能快照”检查必须收窄为结果种类和操作分支，数据库形状函数同步保持同一矩阵。

## 9. 引用、删除和并发

1. 乘区删除保护覆盖三张明细，不依赖前端统计。
2. 修改乘区结构时先锁乘区，再检查引用；效果保存按稳定键锁乘区后再写结果。
3. 并发新建引用与删除由外键保证最多一方成功。
4. 并发结构更新与效果改选由乘区行锁和提交时形状检查保证不会留下不兼容关系。
5. 删除技能或效果仍级联删除自己的结果明细，但不删除乘区；最后一个引用消失后乘区仍保留，只有显式 DELETE 才删除。
6. 当前属性没有删除接口；未来属性删除仍只检查属性引用，不反向删除乘区。
