## 4. 数据库表

所有表都使用 `game_id` 参与复合主键和复合外键，禁止跨游戏或跨技能引用。除技能内部已有等级 Map 外，本阶段新表不使用数组或 JSONB。

### 4.1 `skill_effects`

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`effect_key` | 三列主键；`effect_key` 使用稳定标识格式。 |
| `name` | 非空，去空白后长度 1～100。 |
| `description` | 可空，最长 2000。 |
| `sort_order` | 非负整数。 |
| `created_at`、`updated_at` | `timestamptz`，默认当前时间。 |

`(game_id, skill_key)` 复合外键引用 `skills`，不使用级联删除；技能删除由 `SkillService` 按明确顺序处理。

列表索引：`(game_id, skill_key, sort_order, effect_key)`。

### 4.2 `skill_effect_results`

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`effect_key`、`result_key` | 四列主键。 |
| `name` | 非空，去空白后长度 1～100。 |
| `result_type` | 共享契约七种固定值。 |
| `target` | `SOURCE` 或 `TARGET`。 |
| `description` | 可空，最长 2000。 |
| `sort_order` | 非负整数。 |

父级复合外键引用 `skill_effects` 并 `ON DELETE CASCADE`。该级联只清理效果内部结果，不跨业务对象删除目录记录。

列表索引：`(game_id, skill_key, effect_key, sort_order, result_key)`。

### 4.3 `skill_effect_result_values`

一行表示一个数值结果的数值规则，与结果一对一：

| 列 | 约束 |
| --- | --- |
| 四个结果主键列 | 主键，同时外键引用 `skill_effect_results` 并级联删除。 |
| `formula_key` | 非空；复合外键引用同一技能的 `skill_formulas`，删除受限。 |
| `fixed_multiplier` | 非空 `numeric`，大于等于 0，默认 1。 |
| `fixed_min_value`、`fixed_max_value` | 可空 `numeric`；同时存在时最小值不得大于最大值。 |

建立 `(game_id, skill_key, formula_key, effect_key, result_key)` 反向索引，供公式删除保护和引用定位。

### 4.4 五张类型明细表

1. `skill_effect_damage_details`：结果主键 + `damage_type_key`，真实复合外键引用 `damage_types`。
2. `skill_effect_attribute_change_details`：结果主键 + `attribute_key` + `operation`；属性外键引用 `attributes`，操作检查 `INCREASE/DECREASE/SET`。
3. `skill_effect_resource_change_details`：结果主键 + `attribute_key` + `operation`；属性外键引用 `attributes`，操作检查 `RESTORE/CONSUME/REFUND`。
4. `skill_effect_cooldown_change_details`：结果主键 + `affected_skill_key` + `operation`；技能外键引用 `skills`，操作检查 `REDUCE/INCREASE/RESET`。
5. `skill_effect_status_operation_details`：结果主键 + `status_key` + `operation`；状态外键引用阶段 7.1 的 `statuses`，操作检查 `APPLY/REMOVE`。

五张表的结果主键同时外键引用 `skill_effect_results` 并级联删除。每个目录引用都建立以被引用键为前导列的反向索引。直接治疗和普通护盾没有额外明细表，只拥有结果主记录和数值规则行。

### 4.5 数据库形状约束

在 `triggers.sql` 增加延迟到事务结束检查的约束触发器，覆盖结果表、数值规则表和五张明细表：

1. 伤害：恰好一行数值规则和一行伤害明细，不得有其他明细。
2. 直接治疗、普通护盾：恰好一行数值规则，不得有五类明细。
3. 属性变化：恰好一行数值规则和一行属性变化明细。
4. 资源变化：恰好一行数值规则和一行资源变化明细。
5. 冷却变化：恰好一行冷却变化明细；减少或增加时恰好一行数值规则，重置时不得有数值规则。
6. 状态操作：保持唯一状态明细；锁定状态目录后按[普通减速共享契约](../../项目/系统精简实施说明.md#第四单元状态身份与普通减速强度)决定是否必须有数值规则，不能只按结果种类一律拒绝数值。
7. 内部 `ON DELETE CASCADE` 已删除父结果时，延迟触发器必须识别父记录不存在并直接结束，避免合法删除在事务提交时被误判为结果形状损坏。

约束触发器是数据库最后防线；Service 必须先返回共享契约规定的字段错误，不能依赖触发器异常作为正常表单校验。

## 7. 查询与聚合重建

### 7.1 查询

1. 列表先验证游戏和技能，再查询效果摘要及每个效果的结果数量；禁止每个效果单独发一次计数查询。
2. 详情一次读取效果、全部结果、数值规则和五类明细，在内存按结果稳定标识组装强类型响应。
3. 排序严格使用共享契约的 `sortOrder + 稳定标识`，不按名称改变语义顺序。
4. 如果数据库存在缺少必填数值规则、重复明细或种类不匹配等形状损坏，记录游戏、技能、效果和结果键，返回 `500.INTERNAL_ERROR`；不得猜测或静默丢字段。

### 7.2 创建

1. 规范化效果和结果的名称、说明与稳定标识，并完成全部结构校验。
2. 锁定并确认父级游戏和技能；父级技能即使已停用，仍允许维护自身效果。
3. 收集全部公式、伤害类型、属性、受影响技能和状态引用，批量查询并锁定目录记录，累积返回所有未知引用。
4. 新引用只允许启用伤害类型、属性、技能和状态；公式只校验同技能存在。冷却变化的 `affectedSkillKey` 等于当前路径 `skillKey` 时允许父级技能已停用，其他停用技能仍拒绝。
5. 插入效果主记录，再按请求数组插入结果主记录、数值规则和唯一允许的类型明细。
6. 延迟约束触发器在事务提交前再次验证完整形状；成功后回读完整详情。

### 7.3 全量更新

1. 锁定父级技能、效果和现有结果集合；效果不存在返回稳定 404。
2. 以 `resultKey` 比较请求和现有集合。已有键必须保持原 `resultType`；新增键执行完整创建校验；缺少键进入删除集合。
3. 从现有结果保存伤害类型、属性、受影响技能和状态引用元组，只允许原样保留停用引用，禁止新选或改选为停用记录。唯一例外与创建一致：`COOLDOWN_CHANGE.affectedSkillKey` 等于当前路径 `skillKey` 时，即使父级技能已停用，PUT 新增或改选该自引用仍允许；其他停用技能继续拒绝。
4. 在同一事务内依次删除移除结果、更新保留结果及其数值/明细、插入新增结果，最后更新效果资料和 `updated_at`。
5. 更新类型明细时只写当前结果种类对应表；不得保留上一版多余明细。同一 `COOLDOWN_CHANGE` 结果在 `REDUCE/INCREASE` 与 `RESET` 之间切换时，必须相应插入或删除 `skill_effect_result_values` 行，不能把非空 `formula_key` 更新为 null，也不能留下旧数值行。
6. 任一引用、结果形状、写入或约束失败时全部回滚，原效果及全部结果保持不变。

### 7.4 删除效果

1. 锁定父级技能和效果。
2. 删除效果主记录，由内部级联清理结果、数值规则和类型明细。
3. 不删除公式、伤害类型、属性、受影响技能或状态。

## 8. 引用锁定与删除保护

1. 引用校验按“公式 → 伤害类型 → 属性 → 技能 → 状态”的固定顺序批量锁定，避免不同请求使用不一致锁顺序。
2. 公式删除捕获约束 `fk_skill_effect_result_values_formula`，精确映射 `409.SKILL_FORMULA_IN_USE`；其他完整性异常原样上抛。
3. 伤害类型和状态删除继续通过真实外键的 SQLSTATE `23503` 映射既有 `409.DAMAGE_TYPE_IN_USE` 和 `409.STATUS_IN_USE`。
4. `SkillService.delete` 通过新的 `skilleffect` Mapper 查询是否存在“拥有技能不是待删技能、但 `affected_skill_key` 是待删技能”的冷却变化结果；存在时返回 `409.SKILL_IN_USE`，不做任何删除。本阶段不为该查询修改 `SkillMapper`。
5. 技能允许删除时，顺序调整为“自身效果及结果 → 公式及节点 → 参数 → 技能分类关系/技能”。自身冷却结果在第一步清理，不阻止删除自身。
6. 数据库所有目录外键使用限制删除，不允许 CASCADE 删除业务目录记录。

## 9. 控制器与编辑日志

1. 控制器路径严格使用共享契约的 `/skills/{skillKey}/effects`。
2. GET 列表返回摘要数组，GET 详情返回完整聚合；POST 201、PUT 200、DELETE 204。
3. POST、PUT、DELETE 各写一条 `AdminEditLogHelper` 日志，记录效果聚合请求和最终状态码；不为结果数组内每一项重复写日志。
4. controller 不读取旧 combat-data，不解析数据库错误文本，不执行公式。
5. JSON 字段类型、未知结果种类或未知操作值继续由统一绑定错误返回 `400.INVALID_BODY`；业务形状问题由 Service 返回稳定字段路径。

## 12. 后端停止条件

1. 阶段 7.1 尚未实现或目标数据库前置表结构与冻结契约不一致。
2. 八张分表和真实外键无法表达共享契约，必须退回数组、JSONB、自由脚本或旧通用多态关系。
3. 实现需要提前增加过程、生命周期、条件、事件、暴击、吸血、前序结果、斩杀或反伤结构。
4. 公式必须跨技能引用，或结果必须复制公式表达式、等级 Map 或运行值。
5. 技能删除顺序或外部冷却引用保护无法在一个事务内安全完成。
6. 延迟形状约束无法在新库和已有开发库保持一致。
7. 完整 Maven 测试、真实迁移或真实接口验收不可用，且无法定点确认原因。

出现任一项时保留证据并停止，不新增兼容表、占位字段或绕过外键。
