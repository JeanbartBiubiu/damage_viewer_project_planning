## 4. 数据库总体约束

1. 所有表都使用 `game_id` 和 `skill_key` 参与复合主键或复合外键，禁止跨游戏或跨技能引用。
2. 本阶段不使用数组、JSONB、自由脚本、通用键值明细或类型编号关系。
3. 技能拥有的过程和内部状态不通过数据库级联跨业务对象删除；技能删除由 `SkillService` 按共享契约的明确顺序执行。
4. 过程内部子表允许对所属过程或步骤使用 `ON DELETE CASCADE`；公式、效果、内部状态和模式选项等被引用记录全部限制删除。
5. 形状约束由 Service 先返回稳定字段错误，数据库延迟约束触发器只作为最终完整性防线。
6. `state_key`、`process_key`、`step_key`、`binding_key`、`operation_key` 和 `option_key` 都使用 `^[a-z][a-z0-9_]{0,63}$` 检查约束；Service 在写入前返回对应字段错误。

## 5. 内部状态表

### 5.1 `skill_internal_states`

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`state_key` | 三列主键；复合外键引用同游戏技能。 |
| `name` | 非空，去空白后长度 1～100。 |
| `state_type` | `COUNTER/AMMO/MODE/FLAG/INTERNAL_COOLDOWN`。 |
| `scope` | `SKILL/TARGET`；除计数外必须为 `SKILL`。 |
| `description` | 可空，最长 2000。 |
| `sort_order` | 非负整数。 |
| `created_at`、`updated_at` | `timestamptz`，默认当前时间。 |

列表索引：`(game_id, skill_key, sort_order, state_key)`。

### 5.2 计数与弹药明细

1. `skill_internal_state_counter_details`：内部状态主键 + `initial_value_formula_key` + `max_value_formula_key`。
2. `skill_internal_state_ammo_details`：内部状态主键 + `initial_value_formula_key` + `max_value_formula_key` + `recovery_interval_formula_key` + `recovery_mode`。

三个公式列都使用 `(game_id, skill_key, formula_key)` 复合外键引用同技能 `skill_formulas`，删除受限。`recovery_mode` 检查逐个恢复或一次全部恢复。每个公式引用列分别建立以 `game_id, skill_key, 对应公式键` 为前导的反向索引，供公式删除保护和引用定位。

### 5.3 准备标记和内部冷却明细

1. `skill_internal_state_flag_details`：内部状态主键 + `initial_enabled boolean NOT NULL`。
2. `skill_internal_state_cooldown_details`：内部状态主键 + `duration_formula_key`，同技能公式外键，删除受限并建立反向索引。

### 5.4 `skill_internal_state_mode_options`

| 列 | 约束 |
| --- | --- |
| 内部状态主键列 + `option_key` | 四列主键。 |
| `name` | 非空，去空白后长度 1～100。 |
| `sort_order` | 非负整数。 |
| `initial` | 非空布尔值。 |

父级复合外键引用 `skill_internal_states` 并在删除内部状态时级联清理选项。数据库延迟约束保证模式状态至少两项且恰好一个初始选项，非模式状态不得拥有模式选项。

### 5.5 内部状态形状约束

在 `triggers.sql` 增加事务结束前检查：

1. 计数恰好一行计数明细，不得有其他明细或模式选项；范围可以为技能自身或按目标。
2. 弹药恰好一行弹药明细，范围只能为技能自身。
3. 模式不得有四类单行明细，必须至少两个选项且恰好一个初始选项，范围只能为技能自身。
4. 准备标记恰好一行标记明细，范围只能为技能自身。
5. 内部冷却恰好一行冷却明细，范围只能为技能自身。
6. 父内部状态已经通过合法级联删除时，触发器识别父记录不存在并直接结束。

## 6. 技能过程主表与步骤

### 6.1 `skill_processes`

| 列 | 约束 |
| --- | --- |
| `game_id`、`skill_key`、`process_key` | 三列主键；复合外键引用同游戏技能。 |
| `name` | 非空，去空白后长度 1～100。 |
| `activation_type` | `ACTIVE/PASSIVE/CONSUMABLE`。 |
| `description` | 可空，最长 2000。 |
| `sort_order` | 非负整数。 |
| `created_at`、`updated_at` | `timestamptz`，默认当前时间。 |

列表索引：`(game_id, skill_key, sort_order, process_key)`。

### 6.2 `skill_process_steps`

| 列 | 约束 |
| --- | --- |
| 过程主键列 + `step_key` | 四列主键。 |
| `name` | 非空，去空白后长度 1～100。 |
| `step_type` | 共享契约八种固定值。 |
| `description` | 可空，最长 2000。 |
| `sort_order` | 非负整数。 |

父级外键引用 `skill_processes` 并 `ON DELETE CASCADE`。列表索引为 `(game_id, skill_key, process_key, sort_order, step_key)`。

### 6.3 七张步骤明细表

立即步骤没有明细表，其余步骤各使用一张强类型明细表：

1. `skill_process_delay_step_details`：步骤主键 + `delay_formula_key`。
2. `skill_process_multi_hit_step_details`：步骤主键 + `repeat_count_formula_key` + 可空 `interval_formula_key`；可空公式复合外键显式使用 `MATCH SIMPLE`。
3. `skill_process_periodic_step_details`：步骤主键 + `repeat_count_formula_key` + `interval_formula_key` + `first_execution`。
4. `skill_process_channel_step_details`：步骤主键 + `duration_formula_key` + `execution_count_formula_key` + `first_execution`。
5. `skill_process_charge_step_details`：步骤主键 + `minimum_charge_formula_key` + `maximum_charge_formula_key` + `release_at_maximum`。
6. `skill_process_recast_step_details`：步骤主键 + `window_formula_key` + `maximum_recast_count_formula_key`。
7. `skill_process_empowered_attack_step_details`：步骤主键 + `window_formula_key` + `consume_moment`。

每个公式列使用同技能复合外键引用 `skill_formulas` 并限制删除；每个公式引用列分别建立反向索引。步骤主键同时外键引用 `skill_process_steps` 并级联删除。固定选项使用检查约束，不引用自由类型表。

### 6.4 步骤形状约束

延迟约束触发器覆盖步骤表和七张明细表：

1. 立即步骤不得有任何明细。
2. 其余七种步骤必须且只能有自身一行明细。
3. 多段的间隔公式可以为空；其他冻结为必填的公式不得为空。
4. 父步骤已经通过合法级联删除时不误报形状损坏。

Service 必须先完成同样校验，不能依赖触发器异常处理正常表单错误。

## 7. 普通冷却、效果挂接和内部状态操作表

### 7.1 `skill_process_cooldowns`

一行表示过程可选的普通冷却：

| 列 | 约束 |
| --- | --- |
| 过程主键列 | 主键，同时外键引用过程并级联删除。 |
| `duration_formula_key` | 同技能公式复合外键，删除受限。 |
| `moment_type`、`step_key` | 共享契约的过程时点；步骤型时点引用当前过程步骤。 |

建立公式反向索引和步骤反向索引。可空 `step_key` 的复合外键显式使用 `MATCH SIMPLE`；检查约束保证过程级时点的 `step_key` 为空、步骤级时点的 `step_key` 非空，复合外键保证非空步骤属于当前过程。

### 7.2 `skill_process_effect_bindings`

| 列 | 约束 |
| --- | --- |
| 过程主键列 + `binding_key` | 四列主键。 |
| `effect_key` | 复合外键引用同技能 `skill_effects`，删除受限。 |
| `moment_type`、`step_key` | 固定过程时点；步骤型时点引用当前过程步骤。 |
| `sort_order` | 非负整数。 |

建立以效果键、步骤键和过程时点为前导的反向索引。可空 `step_key` 的复合外键显式使用 `MATCH SIMPLE`，并由时点检查保证空值组合合法。该表只保存关系和顺序，不复制效果名称、结果、公式或资源字段。

### 7.3 `skill_process_state_operations`

| 列 | 约束 |
| --- | --- |
| 过程主键列 + `operation_key` | 四列主键。 |
| `name` | 非空，去空白后长度 1～100。 |
| `state_key` | 复合外键引用同技能 `skill_internal_states`，删除受限。 |
| `operation` | 共享契约固定操作值。 |
| `value_formula_key` | 可空，同技能公式外键，删除受限；复合外键显式使用 `MATCH SIMPLE`。 |
| `option_key` | 可空，与 `state_key` 组成复合外键引用同一模式选项。 |
| `moment_type`、`step_key` | 固定过程时点；步骤型时点引用当前过程步骤。 |
| `sort_order` | 非负整数。 |

建立状态、模式选项、公式、步骤和过程时点反向索引。可空 `option_key` 和 `step_key` 所在复合外键显式使用 `MATCH SIMPLE`；Service 与延迟约束仍须保证非模式选择操作没有选项键、步骤型时点必须拥有步骤键。

### 7.4 跨表完整性约束

延迟约束触发器进一步保证：

1. 每个过程至少一个步骤，并且至少包含有效普通冷却、效果挂接或内部状态操作之一。
2. `STEP_TIMEOUT` 只引用蓄力、重施或强化下一次普通攻击步骤。
3. 状态操作与实际内部状态种类匹配；数值公式和模式选项的有无符合共享契约。
4. 模式选择的选项确实属于同一个被操作模式状态。
5. 删除步骤前必须先移除本次聚合中仍引用该步骤的冷却、效果挂接和状态操作。

同一 PUT 中的最终步骤数组不包含某个 `moment.step_key` 时，Service 统一返回 `400.INVALID_SKILL_PROCESS_REFERENCE` 和 `UNKNOWN_STEP`，不得改用 `400.VALIDATION_FAILED` 形成第二种错误分支。

`cooldown` 为空且 `effectBindings` 和 `stateOperations` 都为空时，服务在数据库写入前返回 `400.VALIDATION_FAILED`，同时定位两个数组并使用 `PROCESS_BEHAVIOR_REQUIRED`。仅含普通冷却的过程仍完整验证数值及引用；不能用步骤或伪造零消耗替代有效行为。当前聚合存储入口以系统精简实施说明为准。

## 10. 查询与聚合重建

### 10.1 内部状态

1. 列表先验证游戏和技能，再一次查询摘要；不按记录单独查询明细。
2. 详情读取主记录、四类单行明细和模式选项，在内存组装唯一强类型响应。
3. 模式选项按 `sort_order, option_key` 排序。
4. 数据库形状缺失、重复或与种类不符时记录游戏、技能和状态键，返回 `500.INTERNAL_ERROR`，不得猜测默认明细。

### 10.2 技能过程

1. 列表一次返回摘要和三个计数，禁止每个过程分别发计数查询。
2. 详情读取过程、普通冷却、步骤和七类明细、效果挂接、状态操作，在内存按稳定标识组装。
3. 步骤、挂接和操作严格按共享契约排序。
4. 数据库存在无效时点、缺少明细、错误模式选项或空行为过程时返回 `500.INTERNAL_ERROR`，不静默丢弃。

## 11. 内部状态写入

### 11.1 创建

1. 规范化公共字段和模式选项，校验稳定标识、种类、范围和强类型明细。
2. 锁定并确认父级游戏、技能和所引用公式；父级技能停用不阻止维护。
3. 一次收集全部公式引用并返回所有未知引用字段问题。
4. 插入主记录，再插入唯一允许的类型明细或完整模式选项。
5. 延迟触发器在提交前再次验证形状；成功后回读完整详情。

### 11.2 全量更新

1. 锁定内部状态主记录、现有明细和模式选项；不存在返回稳定 404。
2. `stateType` 和 `scope` 必须与原记录一致。
3. 模式状态按 `optionKey` 做完整差异更新；准备移除被过程状态操作引用的选项时返回 `409.SKILL_INTERNAL_STATE_OPTION_IN_USE`。
4. 其他种类更新自己的唯一明细，不留下旧种类行。
5. 资料、明细或选项任一校验和写入失败时全部回滚。

### 11.3 删除

1. 锁定父级技能和内部状态。
2. 存在过程状态操作引用时返回 `409.SKILL_INTERNAL_STATE_IN_USE`。
3. 允许删除时删除内部状态主记录，由内部级联清理自身明细或模式选项。

## 12. 技能过程写入

### 12.1 创建

1. 规范化过程、步骤、挂接和状态操作，完成所有稳定标识、种类、时点和强类型形状校验。
2. 锁定并确认父级游戏和技能；父级技能停用不阻止维护。
3. 按稳定顺序批量锁定同技能公式、效果、内部状态和模式选项，一次累积所有未知引用。
4. 插入过程主记录和步骤，再插入步骤明细、普通冷却、效果挂接和状态操作。
5. 延迟触发器验证完整聚合；成功后回读详情。

### 12.2 全量更新

1. 锁定过程和现有完整聚合；过程不存在返回稳定 404。
2. 以稳定标识比较步骤、挂接和状态操作。已有步骤保持 `stepType`，已有状态操作保持 `operation`；新增标识执行完整创建校验。
3. 在写数据库前用提交后的完整步骤集合校验所有时点，任何被删除步骤仍被新聚合引用时定位到实际数组字段并拒绝。
4. 固定写入顺序为：移除将删除步骤的冷却/挂接/操作引用 → 删除移除子记录 → 更新保留步骤及明细 → 插入新增步骤及明细 → 写入最终冷却、挂接和状态操作 → 更新过程时间戳。
5. 同一事务中任一引用、形状、写入或约束失败时全部回滚，旧过程保持不变。

### 12.3 删除

锁定过程后删除主记录，由内部级联清理普通冷却、步骤明细、效果挂接和状态操作；不得删除任何公式、效果或内部状态。

## 13. 引用锁定与删除保护

1. 引用校验在同一事务内按“公式 → 效果 → 内部状态 → 模式选项”的固定顺序和稳定键排序锁定，避免不同请求使用不一致顺序。
2. `SkillFormulaService.delete` 必须精确识别阶段 7.2 和 7.3 新增的公式外键，统一映射 `409.SKILL_FORMULA_IN_USE`；其他完整性异常不得误吞。允许映射的约束只能来自下列显式清单，不得按名称前缀或全部 SQLSTATE `23503` 泛化匹配。
3. 阶段 7.2 `SkillEffectService.delete` 在删除前检查 `skill_process_effect_bindings`，或精确捕获该外键，映射 `409.SKILL_EFFECT_IN_USE`。
4. `SkillInternalStateService.delete` 在删除前检查状态操作引用，映射 `409.SKILL_INTERNAL_STATE_IN_USE`。
5. 模式选项全量更新在删除选项前检查引用，映射 `409.SKILL_INTERNAL_STATE_OPTION_IN_USE`。
6. `SkillService.delete` 的自身清理顺序调整为“过程 → 效果与结果 → 内部状态 → 公式与节点 → 参数 → 技能分类关系/技能”。
7. 阶段 7.2 的外部冷却目标技能引用继续先于自身清理检查；其他技能引用待删技能时仍返回 `409.SKILL_IN_USE`。

## 14. 控制器与编辑日志

1. 两个控制器严格使用共享契约路径，不建立子资源单独写接口。
2. GET 列表返回摘要数组，GET 详情返回完整聚合；POST 201、PUT 200、DELETE 204。
3. 每个 POST、PUT、DELETE 只写一条 `AdminEditLogHelper` 日志，记录聚合请求和最终状态码；不为数组子项重复记录。
4. controller 不读取旧 combat-data、不执行公式或过程、不解析数据库错误原文。
5. 非法枚举和互斥明细字段使用 `400.INVALID_BODY`；业务形状与引用问题由 Service 返回稳定数组路径。
