## 4. 数据库结构

本阶段只增加四张结果明细表，不增加事件明细表。

### 4.1 伤害修正明细

`skill_effect_damage_modifier_details`：

1. 主键为 `game_id + skill_key + effect_key + result_key`。
2. 完整外键到 `skill_effect_results` 并随结果级联删除。
3. 列为 `direction / operation / damage_type_key / delivery_kind / origin_kind / critical_filter`。
4. `damage_type_key` 可空，非空时以完整游戏键外键到伤害类型并使用 `RESTRICT`。
5. 其余列使用共享契约固定检查，不使用目录表或自由字符串。

### 4.2 治疗修正明细

`skill_effect_healing_modifier_details`：

1. 主键和父结果外键同上。
2. 列为 `direction / operation / healing_kind`，全部非空并使用固定检查。
3. 不增加治疗类型目录或另一个过滤子表。

### 4.3 伤害免疫明细

`skill_effect_damage_immunity_details`：

1. 主键和父结果外键同上。
2. 列为 `damage_type_key / delivery_kind / origin_kind`。
3. 伤害类型外键和固定检查与伤害修正复用同一约束语义。
4. 父结果禁止存在 `skill_effect_result_values` 行。

### 4.4 生命下限明细

`skill_effect_health_floor_details`：

1. 主键和父结果外键同上。
2. `attribute_key` 非空，以 `game_id + attribute_key` 完整外键到同游戏属性并使用 `RESTRICT`。
3. 父结果必须恰好一行数值规则。
4. 以被引用属性复合键开头建立反向索引；不按属性名称猜测生命属性。

## 5. Schema、兼容迁移与延迟检查

### 5.1 `schema.sql`

新库直接形成：

1. 四张本阶段明细表、完整外键、检查和反向索引。
2. `skill_effect_results.result_type` 固定集合为前八种加本阶段四种，不提前加入后三阶段结果。
3. 事件固定集合为阶段 7.5 十七种加 `DAMAGE_PENDING`。
4. 阶段 7.6.1 伤害事件表允许 `DAMAGE_PENDING / DAMAGE_DEALT / DAMAGE_TAKEN`。
5. 两处事件值检查保留阶段 7.5 十二项并追加本阶段四项。

本阶段不因未来 `ATTACK_LINK_APPLICATION` 提前扩大结果类型列或触发器局部变量；需要的列宽变化由阶段 7.6.4 独立负责。

### 5.2 独立兼容迁移

`persistent_modifier_pre_damage_protection_migration.sql` 使用一个显式事务：

1. 先核对阶段 7.5、冷却变化多选补项和 7.6.1 前置表、列、复合键、外键、伤害事件回填、检查函数和触发器均处于已验收状态。
2. 四张表全部缺失时创建；全部存在时逐列、主键、外键、检查和索引核对；部分存在或未知漂移时主动失败。
3. 替换结果、事件和两处事件值检查前读取现有定义；只接受精确前置集合或精确目标集合，未知值或缺失既有值时整体停止。
4. 把 `skill_trigger_rule_damage_events` 的父事件检查从精确 `{DAMAGE_DEALT, DAMAGE_TAKEN}` 扩成 `{DAMAGE_PENDING, DAMAGE_DEALT, DAMAGE_TAKEN}`。该检查与事件固定集合、事件形状函数属于同一迁移完成条件；只接受精确前置集合或精确目标集合，出现未知值、表检查与形状函数不一致时整体停止。
5. 本阶段没有既有新结果或新事件行需要回填，不插入业务样本，不修改阶段 7.6.1 既有结果/规则数据。
6. 同一事务内完成表、全部固定检查、伤害事件父事件检查、形状函数和触发器挂载；任一步失败全部回滚。
7. 重复执行时精确目标状态可安全结束；表存在但检查、函数或触发器缺失不得直接结束。
8. 不使用 `CASCADE`，不读取旧战斗数据，不创建兼容视图或双写。

### 5.3 结果形状函数

结果形状函数扩展到十二个显式分支：

1. 所有十二个分支都统计阶段 7.6.1 三张效果子表和本阶段四张明细表。
2. 四种新结果各自恰好一行所属明细，其他六张本阶段累计效果子表行数符合类型要求。
3. `DAMAGE_MODIFIER / HEALING_MODIFIER / HEALTH_FLOOR` 必须恰好一行数值规则；`DAMAGE_IMMUNITY` 禁止数值规则。
4. 四种结果必须有生命周期且行为为 `PERSISTENT`，并按共享矩阵检查值读取、层数值和重复施加值。
5. 原八种结果仍按阶段 7.6.1 形状检查，并明确要求本阶段四张明细表行数为 0；其中 `COOLDOWN_CHANGE` 继续要求恰好一条冷却明细和至少一条目标关系，其他结果不得拥有冷却目标。

### 5.4 事件形状和事件值检查

1. 事件形状函数扩展到十八个显式分支。
2. 三种伤害事件必须恰好一行 `skill_trigger_rule_damage_events`；其他十五种事件必须为 0。
3. `DAMAGE_PENDING` 的 `damage_type_key / delivery_kind / origin_kind` 使用既有伤害明细强类型 Row，不建立第二个表或宽空字段。
4. `skill_trigger_rule_event_value_conditions` 和 `skill_trigger_rule_event_value_bindings` 两处检查都追加四项，不能只改其中一处。
5. 事件与值的合法组合由 Service 返回 400；数据库固定集合检查只兜底未知标识。

### 5.5 触发器挂载

四张新结果明细表的 INSERT/UPDATE/DELETE 都必须在提交时重新检查父结果聚合。既有结果主表、数值规则、生命周期和行为表的挂载继续覆盖新类型；`skill_trigger_rule_damage_events` 的既有挂载继续覆盖 `DAMAGE_PENDING`，不得重复创建第二组触发器。

1. 十二种结果的 detail 和数值规则互斥形状。
2. 四种结果的 `PERSISTENT`、值读取、层数值和重复施加值矩阵。

5. 停用旧引用允许原样回读；新增或改选停用引用失败。

先锁父技能和当前效果，再按稳定键顺序锁公式、伤害类型和属性，沿用既有锁顺序，不引入反向加锁。

1. 锁当前聚合并形成旧/新结果快照。
2. 完成引用、可达参数和候选图校验。
3. 删除待移除结果的本阶段明细、其他结果子表和生命周期行为。

5. 全量同步数值规则、四张明细和生命周期行为。

### 7.2 可达公式

1. 可达公式收集器的结果封闭表加入三种数值结果的 `valueRule.formulaKey`。
2. `EXECUTE_EFFECT` 和 `START_PROCESS` 通过直接效果挂接到达时都收集。

3. `DAMAGE_PENDING` 动作可引用普通护盾、伤害免疫或生命下限效果，但不产生隐藏动作或运行顺序。

## 8. 引用与删除保护

1. `SkillFormulaService` 删除前检查伤害修正、治疗修正和生命下限数值规则，返回 `409.SKILL_FORMULA_IN_USE`。
2. `DamageTypeService` 删除前增加伤害修正、伤害免疫和 `DAMAGE_PENDING` 筛选检查，返回 `409.DAMAGE_TYPE_IN_USE`。

9. 累计形状函数和触发器仍覆盖 `skill_effect_cooldown_change_targets`，新库父表总数按 72 张前置基线加本阶段及阶段 7.6.1 新表计算。

### 9.2 效果服务与控制器

1. 四种结果完整创建、更新、回读和删除。

3. 伤害类型、属性、公式跨游戏/跨技能/停用引用和事务回滚。
4. PUT 保留、新增、删除结果时四张明细与生命周期行为原子同步。
5. 效果公式可达集合不变时成功，变化且存在直接/过程间接引用规则时稳定返回 409。

5. 三种新增公式带来的缺失、多余、重复和类型不兼容绑定。

## 12. 后端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.6.1 最终表、结果联合、伤害事件、事件值或分析器与本文前提不一致。
2. 需要增加阶段 7.6.3～7.6.5 表、枚举、字段或输出才能完成本阶段。
3. 四种结果无法用四张明确明细表和既有生命周期关系表达。
4. 效果或规则无法在一次聚合事务中维护，必须暴露半成品子接口。
5. 必须保存 JSONB、数组、自由字符串或通用多态关系。
6. 需要执行公式、修正、免疫、生命下限、事件、结算或 Wasm 才能完成结构校验。
7. 真实数据库、接口或重启回读验收不可用且无法定点确认原因。

本阶段开发前门禁已完成；后续数据库与接口变更继续按独立阶段审批，不在本文件扩写 7.6.3～7.6.5。
