## 4. 数据库结构

本阶段只增加两张表，新库父表从 81 张增加到 83 张。`modifier_zones` 是已验收前置表，不属于本阶段新增表。

### 4.1 结果阻挡策略

`skill_effect_result_spell_shield_policies`：

1. 主键为 `game_id + skill_key + effect_key + result_key`。
2. 完整外键到 `skill_effect_results` 并随结果级联删除。
3. `block_scope varchar(32) NOT NULL`，使用共享契约四值检查。
4. 没有行表示 API 的 null；每个结果最多一行。
5. 以父结果完整键建立必要索引；不增加适用结果类型数组或自由范围列。

### 4.2 法术护盾阻挡事件

`skill_trigger_rule_spell_shield_blocked_events`：

1. 主键为 `game_id + skill_key + rule_key`。
2. 完整外键到触发规则并随规则级联删除。
3. `shield_effect_key varchar(64) NOT NULL`。
4. 复合外键 `(game_id, skill_key, shield_effect_key)` 指向当前技能效果并使用 `RESTRICT`。
5. 只允许父事件为 `SPELL_SHIELD_BLOCKED`。
6. 以被引用效果复合键开头建立反向索引，支持入站保护和资格复查。

### 5.2 独立兼容迁移

1. 先核对冷却变化多选补项和阶段 7.6.2 的十二种结果、十八种事件、累计七张效果子表、冷却目标关系、伤害事件表、`modifier_zones`、三处结果引用、乘区结构兼容触发器、`MOMENT_EVALUATION` 生命周期矩阵、形状函数和触发器均完整。
2. 两张表全部缺失时创建；全部存在时逐列、键、外键、检查和索引核对；部分存在或未知漂移时主动失败。
3. 替换结果和事件固定检查前只接受精确前置集合或精确目标集合；不得改动事件值和前序输出检查。
4. 既有所有结果的阻挡范围自然表示为无策略行/null，不插入默认策略；不存在既有法术护盾结果或阻挡事件需要回填。
5. 同一事务内完成表、检查、形状函数、入站资格函数和触发器挂载；任一步失败全部回滚。
6. 重复执行时精确目标状态安全结束；表存在但函数、检查或触发器缺失不得直接结束。
7. 不使用 `CASCADE`，不读取旧战斗数据，不创建兼容视图或双写。

### 5.3 结果形状函数

结果形状函数扩展到十三个显式分支：

1. 所有十三个分支都统计前段累计七张效果子表和本阶段阻挡策略表。
2. `SPELL_SHIELD` 禁止数值规则、detail 为空、必须有生命周期且为 `PERSISTENT`，三个值合并字段均为空，阻挡策略行数为 0。
3. `DAMAGE` 在资格满足时允许 0～1 条策略，并额外允许 `DAMAGE_INSTANCE`。
4. 属性、资源、冷却、状态和生命周期操作结果在资格满足时允许 0～1 条策略，但禁止 `DAMAGE_INSTANCE`；一个多目标冷却结果的一条策略作用于全部目标关系，不为每个受影响技能复制策略。
5. 直接治疗、普通护盾、阶段 7.6.2 四种结果、任意 `target = SOURCE` 或 `moment = PERSISTENT` 的策略行数必须为 0。
6. 原十二种结果继续满足前段完整形状，不能因增加公共策略表弱化已有约束；`COOLDOWN_CHANGE` 仍必须恰好一条明细并至少一条目标关系。
7. 原十二种结果中的持续属性增加/减少、伤害修正和治疗修正继续执行 `modifier_zone_key` 必填/禁填、乘区类型兼容及动态读取矩阵；`SPELL_SHIELD` 不引用乘区，不能因新增公共策略表放宽这些检查。

### 5.4 事件形状与护盾资格

1. 事件形状函数扩展到十九个显式分支，并同时统计伤害事件表和本阶段阻挡事件表。
2. `SPELL_SHIELD_BLOCKED` 必须恰好一行本阶段明细且伤害事件明细为 0；三种伤害事件保持恰好一行伤害明细且阻挡事件明细为 0；其他十五种两表都为 0。
3. 提交时资格函数检查 `shield_effect_key` 对应效果存在生命周期，且至少有一个满足完整形状的 `SPELL_SHIELD + PERSISTENT` 结果。
4. 资格不只在事件行写入时检查：被引用效果的结果、生命周期、生命周期行为发生 INSERT/UPDATE/DELETE 时，也必须触发对入站阻挡事件的延迟复查，避免直接数据库事务留下失资格引用。
5. Service 在写库前返回稳定 400/409；延迟触发器只作并发和数据库直写防线。

### 5.5 触发器挂载

1. 阻挡策略表的 INSERT/UPDATE/DELETE 重新检查父效果结果。
2. 阻挡事件表的 INSERT/UPDATE/DELETE 重新检查父规则事件和目标护盾效果资格。
3. 结果主表、生命周期、生命周期行为和效果删除路径必须挂入站资格复查。
4. 既有父表触发器若已能统一调用累计形状函数，应扩展原挂载而不是重复创建平行触发器。
5. `modifier_zones` 的结构兼容触发器及三处引用表的入站检查保持原挂载；本阶段不得删除、替换为弱检查或遗漏在累计触发器复核之外。

## 6. 效果模型、Mapper 与聚合

### 6.1 强类型模型

1. `SkillEffectResultType` 增加 `SPELL_SHIELD`，detail 密封联合增加明确空 detail 类型。
2. 结果公共请求/响应增加可空 `spellShieldBlockScope` 强类型联合；反序列化器要求字段存在并只接受 null 或四种固定值。
3. `SPELL_SHIELD` 分支禁止数值规则和其他种类字段。
4. 结果联合保持十三个完整分支，不能使用 Map 或宽可选接口。

### 6.2 Mapper 读取与写入

1. 在效果聚合锁内读取阻挡策略表，按完整结果键组装 0～1 行。
2. 无行响应显式返回 null；重复、孤儿或不合格策略视为数据库契约损坏。
3. `SPELL_SHIELD` 响应返回空 detail 和完整生命周期行为，不伪造数值规则。
4. 写入顺序沿用现有聚合，并把策略放在结果类型明细完成后、生命周期行为提交检查前同步。

### 6.3 Service 校验

写库前一次收集全部字段问题：

1. 十三种结果 detail 和数值规则互斥形状。
2. 法术护盾完整生命周期矩阵。
3. 阻挡范围与结果类型、target、时点的资格矩阵；直接治疗和普通护盾始终拒绝非空值。
4. 候选效果是否令现有 `SPELL_SHIELD_BLOCKED` 规则失去合格目标。
5. 新增/扩大阻挡生产边是否形成无保护环。

候选检查使用一次旧/新效果快照；不得先写结果再发现规则失效。

### 6.4 聚合写入顺序

创建：效果 → 生命周期 → 结果主行 → 数值规则/类型明细 → 阻挡策略 → 生命周期行为。

更新：

1. 锁当前效果聚合和引用它的当前技能规则，形成旧/新快照。
2. 完成阻挡资格、护盾事件入站引用和候选图检查。
3. 删除待移除结果的阻挡策略及其他子表。
4. 删除结果；更新保留结果；新增结果。
5. 全量同步类型明细、阻挡策略和生命周期行为。
6. 提交时由延迟触发器检查结果形状与入站护盾资格。

任一步失败全部回滚，不依赖外键异常转成业务 500。

## 7. 触发规则增量

### 7.1 模型与 Mapper

1. 事件类型增加 `SPELL_SHIELD_BLOCKED` 和强类型 detail。
2. Mapper 读写本阶段事件表，详情保留稳定效果标识；触发规则列表响应保持现状，不解析或增加护盾效果名称。
3. 事件能力表固定当前目标、`EVENT_SOURCE` 可用且事件值为空。
4. 客户端或请求提交事件值条件/绑定时，Service 返回事件能力错误，不静默删除。

### 7.2 目标效果资格

1. 规则创建/更新先按当前技能锁定 `shieldEffectKey` 目标效果并读取完整聚合。
2. 不存在、跨技能、无生命周期、没有合格法术护盾结果或数据库形状损坏均不能保存。
3. 用户请求引用失资格效果返回 `400.INVALID_SKILL_TRIGGER_RULE_REFERENCE / SHIELD_EFFECT_NOT_ELIGIBLE`。
4. 效果 PUT 令既有规则目标失资格返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_SHAPE_IN_USE`，受影响规则按稳定键排序。

### 7.3 候选规则图

1. 结果阻挡策略的新增/修改加入可能生产 `SPELL_SHIELD_BLOCKED` 的候选边。
2. 只在当前技能内目标护盾规则关系明确时建本地边；跨技能/跨对象未知挂载不作无环承诺。
3. 阻挡事件后的执行效果、启动过程和生命周期操作继续复用阶段 7.5 生产表。
4. 保护边和残余有向环算法继续复用，不新增护盾专用遍历。

## 8. 引用与删除保护

1. 删除被 `shieldEffectKey` 引用的整个效果返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_EFFECT_IN_USE`。
2. 删除最后一个合格法术护盾结果、移除生命周期或破坏其行为形状返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_SHAPE_IN_USE`。
3. 同一效果仍有另一合格法术护盾结果时，不因不相关结果变化误报。
4. 同一次请求还存在阶段 7.3 过程或阶段 7.4 生命周期操作引用时，沿用既有冲突优先级；规则/过程占用优先于生命周期专属冲突。
5. 新阻挡策略形成无保护循环时返回 400 循环错误并保持旧聚合。
6. 数据库 `RESTRICT` 和延迟资格检查只作并发防线，未知约束保留服务端错误。

9. 不出现斩杀、联动、丰富输出、业务种子、自由 JSON 或总迁移。
10. `skill_effect_cooldown_change_targets` 的形状触发器继续挂载，多目标冷却结果只允许 0～1 条结果级阻挡策略。
11. 新库父表精确为 83；`modifier_zones`、三处结果外键、乘区结构兼容触发器和 `MOMENT_EVALUATION` 矩阵在新库及兼容迁移后均保持完整，且不计入累计八张效果子表行数。

### 9.2 效果服务与控制器

至少覆盖：

1. 法术护盾结果完整创建、更新、回读和非法生命周期组合。
2. 所有合格结果/target/时点的阻挡范围与全部固定禁止组合。
3. `DAMAGE_INSTANCE` 仅伤害可用。
4. PUT 清空/设置策略、移除/恢复法术护盾时两张相关聚合原子同步。
5. 破坏既有护盾事件引用稳定返回 409；仍有另一合格护盾结果时允许更新。
6. 新阻挡边形成无保护环时 400 并回滚。
7. 前十二种结果回归且响应显式返回 null/合法范围。
8. 携带合法乘区引用和 `MOMENT_EVALUATION` 的既有修正结果与新增法术护盾共同保存、更新和回读时，乘区字段及生命周期字段均不丢失；`SPELL_SHIELD` 提交乘区字段时拒绝。
9. 效果列表响应字段保持现状，不增加法术护盾或阻挡范围摘要。

### 9.3 触发规则服务与控制器

至少覆盖：

1. `SPELL_SHIELD_BLOCKED` 创建、更新、回读和事件能力。
2. 目标效果不存在、跨技能、无生命周期、无合格护盾结果的稳定 400。
3. 该事件携带任何事件值条件/绑定时拒绝。
4. 护盾移除、治疗、增益和启动延迟过程仍按有序动作保存。
5. 阻挡生产边与既有动作生产边形成合法保护/无保护循环的差异。
6. 前序输出仍只有 `CONFIGURED_VALUE`。
7. 触发规则列表响应字段保持现状，不增加护盾效果名称。

## 12. 后端停止条件

出现以下任一情况停止编码并回到共享契约：

1. 阶段 7.6.2 最终结果、乘区引用与结构兼容检查、生命周期动态读取、事件、入站保护或候选图与本文前提不一致。
2. 需要增加阶段 7.6.4～7.6.5 表、枚举、事件值或输出才能完成本阶段。
3. 法术护盾必须隐藏执行消耗、治疗、增益或延迟过程才能保存。
4. 直接治疗或普通护盾无法在数据库形状中固定禁止阻挡策略。
5. 效果或规则无法在一次聚合事务中维护，必须暴露半成品子接口。
6. 必须保存 JSONB、数组、自由字符串或通用多态关系。
7. 需要执行阻挡、事件、公式、结算或 Wasm 才能完成结构校验。
8. 真实数据库、接口或重启回读验收不可用且无法定点确认原因。

在主会话内部闭环评审、项目负责人确认及前段完整验收之前，本设计不授权任何后端、数据库或服务操作。
