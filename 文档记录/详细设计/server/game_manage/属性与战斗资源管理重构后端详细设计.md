### 2.1 `public.attributes`

```sql
CREATE TABLE public.attributes (
    game_id varchar(64) NOT NULL,
    attribute_key varchar(64) NOT NULL,
    name varchar(100) NOT NULL,
    value_type varchar(16) NOT NULL,
    min_value numeric,
    max_value numeric,
    description text,
    status varchar(16) NOT NULL DEFAULT 'ENABLED',
    sort_order integer NOT NULL DEFAULT 0,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT pk_attributes
        PRIMARY KEY (game_id, attribute_key),
    CONSTRAINT fk_attributes_game
        FOREIGN KEY (game_id) REFERENCES public.games (game_id),
    CONSTRAINT ck_attributes_key
        CHECK (attribute_key ~ '^[a-z][a-z0-9_]{0,63}$'),
    CONSTRAINT ck_attributes_name
        CHECK (btrim(name) <> ''),
    CONSTRAINT ck_attributes_value_type
        CHECK (value_type IN ('DECIMAL', 'INTEGER')),
    CONSTRAINT ck_attributes_status
        CHECK (status IN ('ENABLED', 'DISABLED')),
    CONSTRAINT ck_attributes_bounds
        CHECK (min_value IS NULL OR max_value IS NULL OR min_value <= max_value),
    CONSTRAINT ck_attributes_sort_order
        CHECK (sort_order >= 0)
);

CREATE UNIQUE INDEX uq_attributes_name
    ON public.attributes (game_id, lower(btrim(name)));
```

列约束与索引必须原样保留：主键 `(game_id, attribute_key)`、游戏外键、`attribute_key` 正则、`name` 非空白、`value_type`/`status` 枚举、上下界、`sort_order >= 0`，以及 `uq_attributes_name`。

存储规则：

1. `attribute_key` 创建后不可修改。
2. `name` 在同一游戏内忽略大小写和首尾空格后唯一。
3. `updated_at` 由更新 SQL 显式设置为 `now()`，不新增触发器。
4. `INTEGER` 属性的上下界仍使用 PostgreSQL `numeric`，本阶段不额外强制上下界必须是整数。

明确不保留的列：`default_value`、`value_kind`、`rate_target_attr_key`、`image_uri`、`change_revision`、`_log`、`display_unit`。

## 5. 强校验、控制器、服务与事务

字段合法值、空查询标准化、全量 PUT 的 null/省略语义见共享契约。后端必须用强类型 DTO、`@Valid` 和 `@Validated` 落实这些规则，不得继续接收 `ObjectNode`。

列表查询使用独立强类型 `AttributeListQuery`；`status` 先按字符串接收并由本资源校验器映射。

### 5.1 新建事务

1. trim/标准化请求。
2. 检查 `public.games` 中 `gameId` 存在；不存在返回 `404.GAME_NOT_FOUND`。
3. 检查同游戏 `attributeKey` 和规范化名称唯一。
4. 单事务插入并回读完整记录。

### 5.2 修改事务

1. 以 `(game_id, attribute_key)` 查询并锁定目标；不存在返回 `404.ATTRIBUTE_NOT_FOUND`。
2. 不允许修改稳定标识。
3. 检查名称与其他属性冲突。
4. 按完整 PUT 合同替换全部可编辑字段；可空字段按请求中的 null/省略写入 NULL。
5. 更新 `updated_at`，随后回读。

数据库唯一约束仍是并发下的最终真源；服务按约束名映射稳定错误：`pk_attributes` → `409.ATTRIBUTE_KEY_EXISTS`，`uq_attributes_name` → `409.ATTRIBUTE_NAME_EXISTS`。不得复用会泄露数据库原文的旧 `CombatDataSupport.mapConstraint`。

控制器沿用现有 Admin 接线：所有 GET/POST/PUT 都经过 `AdminAuthFilter`；写操作使用现有 `AuthContext` 和 `AdminEditLogHelper` 记录编辑身份与摘要。`AdminEditLogHelper.log(...)` 仍接收 `JsonNode`，控制器通过 `ObjectMapper.valueToTree(dto)` 转换强类型请求，不修改 helper。游戏存在性复用现有 `GamesMapper.countGames`，不为本任务修改 `GamesMapper`。

`GlobalExceptionHandler` 将 `MethodArgumentNotValidException`、`ConstraintViolationException`、`HandlerMethodValidationException` 和 `BindException` 统一转换为共享契约中的 `details.fieldIssues`。非法查询参数必须返回 `400.VALIDATION_FAILED`，不得落入现有 `400.INVALID_BODY`。
