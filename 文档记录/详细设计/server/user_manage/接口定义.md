# user_manage 接口定义（强约束）
本文件是“用户管理与安全记录”的唯一契约来源：后端实现与前端调用必须严格遵循本文档。若需要变更接口，必须先更新本文档，再进入实现阶段。

## 0. 范围与目标
- 覆盖范围：编辑行为留痕（7 天）、PV/UV 表落库（如需）。
- 不做复杂审计与回滚：编辑日志仅用于出现滥用时快速定位责任人。
- 编辑日志保留 7 天：过期自动清理（见 6）。

## 1. 全局约束
### 1.1 统一响应包装
#### 成功
- `2xx`：直接返回 JSON 对象或数组（不做额外 wrapper）。

#### 失败
```json
{
  "error": {
    "code": "401.UNAUTHORIZED",
    "message": "invalid credentials",
    "details": {
      "reason": "password mismatch"
    }
  }
}
```

### 1.2 错误码集合
- `400.INVALID_BODY`：JSON 结构缺字段/类型错误/不符合最小约束
- `401.UNAUTHORIZED`：未登录或 token 无效
- `403.FORBIDDEN`：无权限
- `404.NOT_FOUND`：资源不存在
- `500.INTERNAL_ERROR`：未预期错误

## 2. 用户信息与权限（无接口）
说明：登录/鉴权/权限授予由外部系统负责；本系统不提供注册、登录、权限管理与用户信息查询接口。

约束：
- 外部系统签发的 JWT 必须使用 `ES256`，并包含 `email`、`canEdit`、`paid`（前端据此决定是否展示编辑模式入口与付费能力）。
- `canEdit=false` 的用户访问 `/api/admin/**` 必须返回 `403.FORBIDDEN`。

## 3. 编辑日志（无查询接口）
说明：本项目不提供编辑日志查询接口；需要时直接查询数据库表 `"user".edit_log`。

### 3.1 写接口自动留痕（强约束）
所有 `/api/admin/games/**` 的写接口（PUT/PATCH/POST 发布等）必须在成功后写入一条 edit_log：
- `email`：从 JWT 中取
- `editBody`：后端自定义，但必须可用于快速定位责任与动作范围；建议至少包含：method、path、request body（可脱敏）、response code
- `createTime`：写入时刻

## 4. PV/UV（无接口）
说明：本项目不提供 PV/UV 查询接口；需要时直接查询数据库表 `"user".pv_uv`。

## 5. edit_log 保留 7 天（运维约束）
编辑日志只保留 7 天，建议通过 pg_cron 每天 03:00 清理：
```sql
CREATE EXTENSION IF NOT EXISTS pg_cron;

SELECT cron.schedule(
  'edit_log_cleanup',
  '0 3 * * *',
  $$DELETE FROM "user".edit_log
    WHERE create_time < now() - interval '7 days';$$
);
```

约束：
- `shared_preload_libraries = 'pg_cron'` 属于实例级配置，必须在部署时配置完成。

## 6. 数据契约（DTO）
本文件不定义对外 API，因此不额外定义 DTO；对外强约束体现在：
- JWT 必须包含 `email/canEdit/paid`，且签名算法为 `ES256`
- `"user".edit_log` 的写入约束与 7 天保留策略
