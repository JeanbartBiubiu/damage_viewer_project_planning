# Redis移除与公开资源缓存边界详细设计

## 目标与范围

用户已确认移除Redis并授权实施。基线为`master`提交`fe8223848`。后端只依赖PostgreSQL保存和读取业务数据，游戏列表每次读取数据库；移除Redis客户端、Spring方法缓存、启动探测和配置要求，不引入替代缓存框架或缓存表，不修改数据库结构。

本次不修改图片同步、鉴权、管理写入、场景快照或Wasm协议，不恢复已退役的版本发布链。未来版本与图片分发仅在本文明确职责边界，不随本次开发提前实现。

## 当前依据与最终行为

- 唯一业务缓存是`GameDataService.listGames()`的游戏列表。游戏代表图关系设置、解除会清理该缓存；控制器外层事务提交前发生的清理存在并发回填旧值的窗口。
- `StartupDependencyVerifier`目前检查PostgreSQL和Redis。最终只检查PostgreSQL，保留现有立即检查开关及失败行为。
- `GET /api/games`保留三个原字段、排序、悬空引用错误和ETag条件请求；ETag是内容校验标识，返回304仍先查询数据库并计算摘要。
- 游戏代表图关系写入或解除事务提交后，新请求立即读取新值。日志写入失败时关系与日志整体回滚，不增加缓存失效补偿。
- 图片继续通过公开全量或`updatedAfter`增量接口读取，浏览器本地数据库继续保存图片及停用记录。当前同步由管理页面按钮触发，不承诺自动同步。

## 实施范围与责任

| 范围 | 负责人 | 改动 |
| --- | --- | --- |
| 后端Java、依赖与单测 | 内置执行代理 | 删除两个缓存及Redis依赖、五个专用配置类、缓存注解和Redis启动探测；调整受影响测试 |
| 默认配置、当前文档、任务映射 | 主负责人 | 删除Redis及方法缓存配置要求，更新运行和部署说明，维护本任务映射 |
| 最终服务与独立复核 | 主负责人及未参与实现的只读代理 | 核对最终差异，运行隔离验收，按证据记录结论 |

五个专用配置类为`CacheConfig`、`CacheResilienceConfig`、`AppCacheProperties`、`RedisLettuceConfig`和`AppRedisProperties`。同时删除`@EnableCaching`、游戏列表缓存和游戏代表图失效注解，避免Spring自动退回默认内存缓存。保留Tomcat仍需使用的JDK本机通信临时目录参数。

默认配置`server/data_manage/src/main/resources/application.yml`与测试配置`server/data_manage/src/test/resources/application-it.yml`均删除`spring.data.redis`、`spring.cache`、`app.cache`、`app.redis`及Redis环境变量要求。真实凭据不进入文档、日志或提交；只保留当前需要的数据库和鉴权配置。

事务、游戏写保护、引用校验和编辑日志保持原逻辑。删除缓存专用测试；列表测试证明连续读取取得当前结果，事务测试继续证明关系与日志同事务及失败回滚。启动测试覆盖PostgreSQL有效、无效连接及连接失败，不依赖Redis。

## 公开资源的缓存边界

| 数据 | 本次与后续职责 |
| --- | --- |
| 游戏列表、管理配置、实时场景快照 | 本次直接读取PostgreSQL，管理和未发布预览不进入共享缓存 |
| 现有图片全量、增量接口 | 本次保持直读和浏览器本地缓存，不开启Nginx共享缓存；增量结果不能仅按游戏确定缓存键 |
| 未来已发布版本 | 发布时生成不可变JSON，以游戏、发布编号和内容摘要确定地址；文件写完并校验后才切换当前指针，由Nginx静态分发、浏览器复用 |
| 未来当前版本指针与图片目录 | 每次条件校验；内容或启停状态变化必须改变校验标识 |
| 未来独立图片内容 | 内容摘要地址可长期缓存，替换生成新地址；停用通过目录同步使浏览器停止引用，不能撤回已下载字节 |

仓库部署模板的`proxy_cache off`继续保留，它不等于已经核验线上配置。后续确需公共接口缓存时仅开放白名单路径，完整区分查询参数，带身份的请求不进入共享缓存。上述未来分发不要求本次新增接口、表或兼容层。

## 验收与部署顺序

1. 运行受影响单测，再运行`mvn clean test`和`mvn -DskipTests package`；确认最终依赖与程序类不包含Redis或Lettuce，不再启用方法缓存。
2. 使用独立端口和隔离验证数据启动最终后端，无Redis连接配置或服务参与，PostgreSQL立即检查保持开启；不停止已有服务。
3. 对最终服务验证游戏列表、未变化304和代表图关系设置／解除后的新ETag与立即可见性；验证非法写入及日志失败整体回滚。
4. 验证图片全量、增量、停用记录以及管理鉴权；分别记录真实数据库、HTTP、单测证据，不以单测代替实库回滚。
5. 记录固定请求下游戏列表、图片全量和增量的响应字节、耗时与数据库查询路径；当前没有访问量或性能承诺，局部测量不宣称生产容量已通过。
6. 部署时先安装并验证新后端，清理该应用私有配置中的Redis变量，确认Redis实例无其他消费者后再退用。保留原部署配置用于恢复；回退旧Redis版本时，在维护状态下恢复其连接并按旧配置定向清除本应用游戏列表缓存，禁止清空共用实例。本次开发不执行线上停机、卸载或数据清理。

当前方案与[验收记录](../../测试记录/server/Redis移除验收-2026-10-26.md)分开维护。任务状态以`db/task_doc_governance/task_rules.json`为准。
