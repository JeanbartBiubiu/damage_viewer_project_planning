# Cursor 可选协作说明

项目通用开发流程以根 `AGENTS.md` §2 为准。Cursor 是可选执行工具；普通任务可由主负责人或允许编码的执行代理直接完成。本文件只在任务选择 Cursor 时适用。历史评审与运行记录仍描述当时实际使用的流程，不作为新任务的强制前置条件。

## 1. 何时使用

- 用户选择 Cursor，或本次任务有明确的费用、模型可用性、工具接入需要时，可使用现有 runner（执行脚本）。
- 是否需要实施前独立评审，由根规则按风险决定。普通任务不因为选择 Cursor 就增加长方案和多轮共识。
- 模型参数、SDK 版本、启动重试和超时等工具细节统一见 [cursor-local-agent](../../.agents/skills/cursor-local-agent/SKILL.md)，不在多个业务文档中重复维护。

## 2. 两种运行模式

现有脚本要求提示词第一行声明且只声明一种模式：

- `MODE: DESIGN_REVIEW_ONLY`：只评审当前方案，返回 `READY | REVISE | BLOCKED`，列明实际风险、证据和阻塞项。不得写入工作区。
- `MODE: IMPLEMENTATION`：执行当前已授权的任务。提供目标、有效契约、写入范围、非目标、验证和停止条件；若先前做过方案评审，引用已接受版本并另开编码运行。普通任务不要求先取得 Cursor 的 `READY`。

共享契约与范围确定后，执行者可以调整内部实现；新事实影响共享语义、权限、数据处置或任务范围时返回主负责人决策。不得把未决重要问题当作默认答案直接实现。

评审只因重要决策变化才复审相关部分；非阻塞偏好不引发强制往返。同一问题连续两轮无新证据，停止重复评审，补查事实或报告缺少的输入。

## 3. 只读与写入审计

现有 `--allowed-path` 是按运行前后文件变化进行分类的审计清单，不是操作系统沙箱，也不是只读开关。实际权限必须单独核验。

选择 Cursor 做只读评审时，保留现有工具审计要求：

1. 明确禁止创建、修改、删除文件。
2. 检查 `summary.json`、`events.jsonl`、工作区状态及差异。
3. 审计可用且 `runDeltaCount == 0`；即使范围内写入也使只读评审无效。
4. 事件日志完整可解析，相关工具事件未截断，没有写入后恢复等临时修改证据。
5. 运行产物放在 Git 忽略的 `.agents/artifacts/`，不得用该目录存放任务实现。

编码审计按本次运行导致的变化分类，未被本次改动的既有脏文件不算越界。审计失败时保留证据，不自动回滚其他人的工作。上述专属日志和状态不要求其他执行工具照搬。

## 4. 异常与验收

- 失败、取消、超时后先检查已经落地的文件和产物，再决定恢复、接手或重试；不要盲目重放写入任务。
- 选择其他执行方式可在原授权内继续，先确认遗留进程不会继续写入，保留已有有效修改。切换工具不扩大权限或任务范围。
- 执行者提供对应最终代码的验证证据；主负责人检查最终差异、关键断言和集成路径。验证频率按模块规则执行，无需每个角色重复整套检查。
- 页面行为须有受影响路径的浏览器证据；数据库结构、运行时能力需对应层面的验证。未执行的项目如实说明，不把可自动化项直接交给用户。
- 当前方案保持简短、可独立阅读；完整提示词、日志和历史评审留在运行证据中。
