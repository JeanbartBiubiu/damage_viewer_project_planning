# Cursor 可选协作说明

项目通用授权、风险分级、委派和验收以根 `AGENTS.md` 为准。只有用户或当前任务明确选择 Cursor，或需要排查其接线时，本文件和 `cursor-local-agent` 技能才生效；普通任务可由主负责人或其他允许编码的执行代理完成。

## 一、两种模式

runner（执行脚本）要求提示词第一行精确声明一种模式：

- `MODE: DESIGN_REVIEW_ONLY`：只评审当前方案，不创建、修改或删除文件；返回方案版本、结论、有证据的阻塞项和分开的非阻塞建议。
- `MODE: IMPLEMENTATION`：执行当前已授权任务；输入包括目标、有效契约、允许写入范围、非目标、验证和停止条件。普通任务不要求先取得 Cursor 评审结论。

共享契约与范围确定后，执行者可调整内部实现。新事实改变共享语义、权限、数据处置或任务范围时，返回主负责人决定。

## 二、审计边界

`--allowed-path` 是运行前后文件变化的审计清单，不是操作系统沙箱或只读开关。方案评审只有在运行完成、文件和事件审计可用、`runDeltaCount == 0` 且没有任何临时或最终写入证据时才有效。

实现运行只接受本次允许路径内的变化。既有脏改不因未被本次运行触碰而失败；范围外变化或审计不可用时保留证据并按失败处理，不自动回滚其他人的工作。runner 产物放在 Git 忽略的 `.agents/artifacts/`，不作为任务实现文件。

固定模型、SDK、Node、重试、超时、产物字段和当前命令统一见 [cursor-local-agent](../../.agents/skills/cursor-local-agent/SKILL.md) 及 runner 的 `--help`，不在业务文档复制。

## 三、异常与验收

- 失败、取消或超时后先检查事件、最终状态、工作树差异和产物；代码可能已经落地，不盲目重放实现任务。
- 切换执行方式不扩大原授权；先确认没有遗留进程继续写入，再保留或接手有效修改。
- 主负责人复核最终差异，并按模块规则运行对应代码、实库、最终 Wasm 或浏览器验证。Cursor 日志只证明该次工具运行，不替代产品验收。
- 评审只因新事实改变重要决定而复审；同一问题没有新证据时补查事实，不重复文字往返。
- Cursor 不负责跨工作树同步。共享规则在 planning/`master` 提交并推送，其他分支自行获取和合入。
