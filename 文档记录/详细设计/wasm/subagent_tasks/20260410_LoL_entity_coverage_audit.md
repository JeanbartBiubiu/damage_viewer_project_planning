## 审计方法

1. 以现有索引字段为底表：`entryId / sourceCategory / sourceType / ownerId / ownerNameZh / nameZh / primaryGroup / scopeAssessment / mechanismTags / sourceRef`
2. 补充设计覆盖字段：`runtimeLayer / templateOrModel / coverageVerdict / gapOrConversionNote`
3. 若能被现有 4 层模型覆盖，则直接记为 `covered` 或 `partial`
4. 若只能通过转换进入主链路，则记为 `filtered` 或 `needs_conversion`
5. 只有现有模型确实接不住的语义，才进入缺口列表

## 统一判定口径

- `covered`：已有模板和运行时层足够承接
- `partial`：大体可承接，但还缺少固定字段、顺序约定或局部模板细化
- `gap`：当前 4 层模型里没有合适承接点
- `filtered`：明确属于主链路外语义，不进入当前最小实现集

## 收口标准

- 四类实体都完成逐条覆盖映射
- 真正新增的 `gap` 数量收敛到较小规模
- `filtered` 与 `needs_conversion` 的边界稳定
- 不再出现会推翻当前 4 层统一口径的新大类机制
