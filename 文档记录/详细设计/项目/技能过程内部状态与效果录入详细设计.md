## 1. 本次需要确认的决定

1. 技能可以拥有零个或多个“技能过程”。每个过程保存启动方式、一个或多个有序步骤、效果挂接、内部状态操作和可选的普通冷却语义。
2. 角色主动、角色被动、装备主动、装备被动和装备消耗能力继续使用同一技能、过程、内部状态和效果结构，不建立装备能力第二套结构，也不在技能上增加挂载来源字段。
3. 过程启动方式固定为主动、被动和消耗三种。它描述过程如何被使用，不替代现有技能分类；同一技能可以按需要拥有不同启动方式的多个过程。被动过程具体由哪种战斗事件启动留到阶段 7.5；阶段 7.3 只保存其启动方式和启动后的过程骨架。
4. 过程步骤固定为立即、延迟、多段、周期、引导、蓄力、重施和强化下一次普通攻击八种。类型由系统固定，不提供自由新增页面。
5. 一个步骤只描述自身如何产生一次或多次“步骤执行”；过程通过明确的“效果挂接”把阶段 7.2 的效果绑定到过程开始、步骤开始、步骤执行、步骤完成、步骤超时、过程完成或过程失败等固定时点。
6. 资源扣除和失败返还不再建立第二套资源数值。维护者先在阶段 7.2 建立包含资源扣除或资源返还结果的效果，再将该效果挂到过程开始或过程失败等明确时点。
7. 普通技能冷却只保存同一技能的冷却时长公式和冷却开始时点；阶段 7.2 的冷却变化结果仍负责减少、增加或重置某个技能的既有冷却，两者不得混为同一字段。
8. 技能内部状态只属于一个技能，固定支持计数、弹药、模式、准备标记和内部冷却五种。它不是战斗状态，也不是计算时传入参数。
9. 内部状态作用范围只允许技能自身和按当前目标分别保存。按目标范围只开放给计数状态；每目标冷却、来源目标、事件来源目标和跨目标传播仍留到阶段 7.5。
10. 过程通过强类型内部状态操作，在固定过程时点增加、减少、消耗、设置或重置计数与弹药，选择模式，启用、停用或切换准备标记，以及开始或重置内部冷却。
11. 内部状态的初始值、上限、弹药恢复间隔、内部冷却时长，以及过程步骤的延迟、次数、间隔、窗口和普通冷却时长，都引用同一技能的公式；不复制参数值、等级 Map、公式表达式或某次运行值。
12. 效果、内部状态和过程都可以先独立保存。过程只能引用同一技能的公式、效果、内部状态和模式选项；被引用记录删除时返回稳定冲突错误，不级联删除过程。
13. 过程连同完整步骤、效果挂接、内部状态操作和普通冷却一次创建或全量修改；内部状态连同类型明细或模式选项一次创建或全量修改。不提供步骤、挂接、操作或模式选项的独立接口。
14. 本阶段只保存、校验、回读和保护引用，不执行时间线、效果、公式、资源扣除、冷却、充能恢复、内部状态变化或普通攻击强化。

上述决定是阶段 7.3 的完整候选边界。开发执行不得自行增加效果与状态生命周期、条件、外部事件、计算时传入参数供值、暴击、吸血、前序结果、结算、计算预览、发布或 Wasm 字段。

## 2. 范围与非目标

本阶段交付：

1. 单个技能下内部状态的查询、查看、新建、全量修改和删除。
2. 单个技能下过程的查询、查看、新建、全量修改和删除。
3. 八种固定过程步骤及其强类型明细。
4. 过程与阶段 7.2 效果的有序挂接。
5. 五种内部状态、模式选项、弹药恢复和强类型状态操作。
6. 资源扣除、失败返还和普通冷却开始时点的结构化保存。
7. 同技能公式、效果、内部状态和模式选项的真实引用及删除保护。
8. 技能页面内的结构化录入、完整回读、自动检查，以及开发获批后的真实数据库、接口和浏览器验收。

本阶段不包含：

1. 持续属性变化、状态操作和普通护盾的持续时间、层数刷新、逐层到期、周期与提前移除规则。
2. 施放、攻击、命中、造成伤害、受到伤害、状态变化、生命阈值、击杀等外部事件和触发条件。
3. 被控制、死亡、目标不可选取、主动取消等中断来源，以及过程期间移动、攻击或使用其他技能的限制。
4. 技能内部状态、战斗状态、事件值或前序结果向计算时传入参数的供值绑定。
5. 每目标冷却、同一目标免疫窗口、单次过程最大触发次数和循环保护。
6. 暴击、吸血、命中联动、攻击联动、法术护盾阻挡粒度、反伤、斩杀和前序结果联动。
7. 多目标选择、范围形状、传播、弹射、投射物、位移、空间碰撞、召唤物或完整技能集合替换。
8. 角色—技能或装备—技能挂载关系。
9. 公式执行、过程执行、计算预览、发布、计算输入组装或 Wasm。
10. 旧 Ability、Provider、combat-data 过程或内部状态结构的读取、迁移、兼容或双写。

## 3. 数据关系与责任方向

```text
游戏
└─ 技能
   ├─ 技能公式
   ├─ 技能效果
   │  └─ 基础结果
   ├─ 技能内部状态
   │  ├─ 计数 / 弹药 / 准备标记 / 内部冷却明细
   │  └─ 模式选项
   └─ 技能过程
      ├─ 普通冷却 → 同技能公式 + 固定过程时点
      ├─ 有序步骤 → 同技能公式
      ├─ 效果挂接 → 同技能效果 + 固定过程时点
      └─ 内部状态操作 → 同技能内部状态 / 模式选项 / 公式 + 固定过程时点
```

责任方向固定为：

1. 技能拥有过程、内部状态和效果；三者都不保存角色或装备挂载来源。
2. 过程主动引用效果和内部状态；效果和内部状态不反向保存过程键。
3. 过程和内部状态引用技能公式；技能公式不反向引用过程或内部状态。
4. 过程时点只描述过程内部位置，不等于阶段 7.5 的战斗事件。
5. 后续条件和事件只能引用本阶段已保存的过程、步骤、内部状态和效果，不得回头把自由条件文本写入本阶段表。

### 4.3 公共字段

| 字段 | 规则 |
| --- | --- |
| `gameId` / `skillKey` | 只来自路径和响应，请求体不能修改。 |
| `stateKey` | 创建时必填；小写字母开头，只含小写字母、数字和下划线，长度 1～64；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100；同一技能内允许重名。 |
| `stateType` | 必填；只允许第 5 节五种固定值；已有内部状态不可修改种类。 |
| `scope` | 必填；`SKILL` 表示技能自身一份，`TARGET` 表示按当前目标分别保存；已有内部状态不可修改范围。 |
| `description` | 可为 null；空白归一为 null；最长 2000。 |
| `sortOrder` | 必填；不小于 0 的整数。 |
| `detail` | 必填强类型对象，形状由 `stateType` 决定。 |
| `createdAt` / `updatedAt` | 仅响应，由后端维护。 |

列表按 `sortOrder ASC, stateKey ASC` 返回，不分页。内部状态没有单独启停状态；所属技能停用后仍允许维护其内部状态。

## 5. 五种内部状态

### 5.1 计数

`stateType = COUNTER`，`scope` 可以为 `SKILL` 或 `TARGET`：

```json
{
  "initialValueFormulaKey": "zero",
  "maxValueFormulaKey": "max_stacks"
}
```

两个公式都必须属于当前技能。未来执行时下限固定为 0；公式结果应为非负整数。阶段 7.3 不执行公式，因此只校验引用，不静态猜测公式结果。

### 5.2 弹药

`stateType = AMMO`，`scope` 只能为 `SKILL`：

以下仅示意现行请求形状。初始数量、容量和恢复间隔分别核对来源；最大容量不能自动作为初始数量。通用数值规则以[系统精简实施说明：直接数值取值](系统精简实施说明.md#第二单元之一直接数值取值)为准。

```json
{
  "initialValue": { "kind": "PARAMETER", "parameterKey": "initial_ammo" },
  "maxValue": { "kind": "PARAMETER", "parameterKey": "max_ammo" },
  "recoveryIntervalValue": { "kind": "PARAMETER", "parameterKey": "ammo_recovery_ms" },
  "recoveryMode": "ONE_BY_ONE"
}
```

`recoveryMode` 只允许逐个恢复 `ONE_BY_ONE` 或一次全部恢复 `ALL_AT_ONCE`。恢复间隔按毫秒解释。当前只保存方式与数值，尚未定义首次消费何时启用计时、后续消费是否重置已有进度、跨等级或急速变化时的读取与进度规则；条件事件设计也没有增加外部暂停、加速或重置恢复的动作。实际对象依赖这些语义时应继续明确，不能从枚举名称推定恢复时间线已经闭合。

### 5.3 模式

`stateType = MODE`，`scope` 只能为 `SKILL`。`options` 至少两项；每个选项拥有创建后不可修改的 `optionKey`，名称和排序可以编辑，同一模式内标识唯一，并且恰好一项 `initial = true`。

模式只保存简单模式选择，不替换技能集合、不改变角色或装备挂载关系。

### 5.4 准备标记

`stateType = FLAG`，`scope` 只能为 `SKILL`：

```json
{ "initialEnabled": false }
```

它用于“强化下一次攻击已准备”等技能自身布尔状态，不代替可以施加到战斗对象的状态。

### 5.5 内部冷却

`stateType = INTERNAL_COOLDOWN`，`scope` 只能为 `SKILL`：

```json
{ "durationFormulaKey": "internal_cooldown_ms" }
```

时长公式结果按毫秒解释，初始语义固定为可用。每目标冷却不得伪装成 `TARGET + INTERNAL_COOLDOWN`，继续留到阶段 7.5。

### 6.1 摘要

```json
{
  "gameId": "lol",
  "skillKey": "ezreal_q",
  "processKey": "primary_cast",
  "name": "主要施放过程",
  "activationType": "ACTIVE",

  "stepCount": 1,
  "effectBindingCount": 1,
  "stateOperationCount": 0,
  "createdAt": "2026-08-27T00:00:00Z",
  "updatedAt": "2026-08-27T00:00:00Z"
```

### 6.3 过程字段

| 字段 | 规则 |
| --- | --- |
| `processKey` | 创建时必填，格式与 `stateKey` 相同；同一技能内唯一；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100；允许重名。 |
| `activationType` | 必填；主动 `ACTIVE`、被动 `PASSIVE` 或消耗 `CONSUMABLE`。 |
| `description` | 可为 null；空白归一为 null；最长 2000。 |
| `sortOrder` | 必填；不小于 0 的整数。 |
| `cooldown` | 可为 null；非空时必须同时提供同技能公式和合法开始时点。 |
| `steps` | 必填数组，至少一项；同一过程内 `stepKey` 唯一。 |
| `effectBindings` | 必填数组，可以为空；同一过程内 `bindingKey` 唯一。 |
| `stateOperations` | 必填数组，可以为空；同一过程内 `operationKey` 唯一。 |

每个过程至少配置普通冷却、一个效果挂接或一个内部状态操作。普通冷却本身是明确的施法行为；无资源消耗且只在实际命中后结算的技能，可以用仅负责施法步骤与冷却的过程，命中效果由独立命中规则执行。仍禁止只有步骤、没有冷却也没有挂接或状态操作的空过程。列表按 `sortOrder ASC, processKey ASC` 返回；详情内各数组按 `sortOrder ASC, 稳定标识 ASC` 返回。

仅当 `cooldown` 为null且 `effectBindings`、`stateOperations` 同时为空时，Service在写库前返回 `400.VALIDATION_FAILED`，并同时为后两个字段返回原因 `PROCESS_BEHAVIOR_REQUIRED`，说明可通过配置普通冷却、效果挂接或内部状态操作补齐。存在冷却时仍完整验证时长取值、开始时点和引用；无效冷却不能绕过校验。前端采用相同判断，保存和回显仍复用既有过程接口。这一修正来自瑟提及无消耗装备的真实拒绝案例，避免为了过校验新增无来源的零消耗或提前对未命中目标执行效果；不改变命中生产和战斗执行边界。

步骤按 `sortOrder ASC, stepKey ASC` 形成一条线性过程：前一步骤正常完成后进入下一步骤，最后一步骤正常完成后进入过程完成；过程失败后不再继续后续步骤。本阶段不保存分支、回边、任意跳转或关系图。

## 7. 八种过程步骤

步骤公共字段为 `stepKey/name/stepType/description/sortOrder/detail`。已有步骤的 `stepKey` 和 `stepType` 不可修改；需要改变种类时明确删除旧步骤并新增新标识。

### 7.1 立即

`stepType = IMMEDIATE`，`detail = {}`。步骤到达后产生一次步骤执行。

### 7.2 延迟

`stepType = DELAY`：

```json
{ "delayFormulaKey": "impact_delay_ms" }
```

公式结果按毫秒解释；延迟结束后产生一次步骤执行。

### 7.3 多段

`stepType = MULTI_HIT`：

```json
{
  "repeatCountFormulaKey": "hit_count",
  "intervalFormulaKey": null
}
```

次数公式未来按正整数解释。间隔公式可为 null，表示各段属于同一过程时点；非空时按毫秒解释。步骤执行会按段数重复，但命中联动、攻击联动、吸血和暴击次数仍留到阶段 7.6。

### 7.4 周期

`stepType = PERIODIC`：

```json
{
  "repeatCountFormulaKey": "tick_count",
  "intervalFormulaKey": "tick_interval_ms",
  "firstExecution": "AFTER_INTERVAL"
}
```

`firstExecution` 只允许立即执行 `IMMEDIATE` 或等待一个间隔 `AFTER_INTERVAL`。本步骤描述技能过程周期，不代表效果或状态生命周期。

### 7.5 引导

`stepType = CHANNEL`：

```json
{
  "durationFormulaKey": "channel_duration_ms",
  "executionCountFormulaKey": "channel_hit_count",
  "firstExecution": "IMMEDIATE"
}
```

时长按毫秒解释，执行次数未来按正整数解释。中断来源、行动限制和精确时间线执行留到后续阶段。

### 7.6 蓄力

`stepType = CHARGE`：

```json
{
  "minimumChargeFormulaKey": "minimum_charge_ms",
  "maximumChargeFormulaKey": "maximum_charge_ms",
  "releaseAtMaximum": true
}
```

两个时长按毫秒解释。最大时长不得在实际执行时小于最小时长；阶段 7.3 不执行公式，只保存引用。实际蓄力时间向计算时传入参数供值留到阶段 7.5。

### 7.7 重施

`stepType = RECAST`：

```json
{
  "windowFormulaKey": "recast_window_ms",
  "maximumRecastCountFormulaKey": "maximum_recasts"
}
```

窗口按毫秒解释，次数不包含首次启动过程。由什么外部输入触发重施留到阶段 7.5。

### 7.8 强化下一次普通攻击

`stepType = EMPOWERED_BASIC_ATTACK`：

```json
{
  "windowFormulaKey": "empowered_attack_window_ms",
  "consumeMoment": "ATTACK_HIT"
}
```

`consumeMoment` 只允许攻击发起 `ATTACK_START` 或攻击命中 `ATTACK_HIT`。它只决定准备状态或次数何时视为已经消耗，不改变步骤执行语义：该步骤的 `STEP_EXECUTION` 和效果挂接始终在有效普通攻击命中时发生。因此选择 `ATTACK_START` 时，攻击可以在发起时消耗准备状态，而未命中时不执行挂接效果。准备来源、目标切换和普通攻击事件接线留到阶段 7.5。

## 8. 固定过程时点

过程时点统一使用：

```json
{
  "momentType": "STEP_EXECUTION",
  "stepKey": "hit"
}
```

| `momentType` | 中文含义 | `stepKey` |
| --- | --- | --- |
| `PROCESS_START` | 过程开始 | 必须为 null |
| `STEP_START` | 指定步骤开始 | 必填 |
| `STEP_EXECUTION` | 指定步骤每次执行 | 必填 |
| `STEP_COMPLETE` | 指定步骤正常完成 | 必填 |
| `STEP_TIMEOUT` | 指定步骤窗口超时 | 必填，只允许蓄力、重施或强化下一次普通攻击步骤 |
| `PROCESS_COMPLETE` | 过程正常完成 | 必须为 null |
| `PROCESS_FAILURE` | 过程失败 | 必须为 null |

过程失败只保存一个统一出口。失败原因、控制中断、死亡、目标不可选取和主动取消的区分留到阶段 7.5；本阶段不得增加自由事件名称。

## 9. 效果挂接、资源与普通冷却

### 9.1 效果挂接

效果挂接字段为：

```json
{
  "bindingKey": "consume_mana",
  "effectKey": "mana_cost",
  "moment": {
    "momentType": "PROCESS_START",
    "stepKey": null
  },
  "sortOrder": 10
}
```

规则如下：

1. `bindingKey` 在同一过程内唯一，创建后不可修改。
2. `effectKey` 必须引用同一技能的阶段 7.2 效果。
3. 同一效果可以通过不同挂接标识绑定到多个过程时点；一个挂接只执行一个完整效果聚合。
4. 同一时点按 `sortOrder ASC, bindingKey ASC` 排序。
5. 资源扣除使用包含 `RESOURCE_CHANGE + CONSUME` 结果的效果并挂到实际扣除时点；失败返还使用包含 `RESOURCE_CHANGE + REFUND` 结果的效果并挂到 `PROCESS_FAILURE`。
6. 本阶段不自动推断某个效果是不是资源成本，也不复制效果中的属性、公式或数值规则。

### 9.2 普通冷却

```json
{
  "durationFormulaKey": "cooldown_ms",
  "startMoment": {
    "momentType": "PROCESS_START",
    "stepKey": null
  }
}
```

普通冷却只影响当前过程所属技能；时长公式必须属于当前技能并按毫秒解释。`cooldown = null` 表示本过程没有普通冷却语义。减少、增加或重置其他技能冷却仍使用阶段 7.2 的冷却变化结果。

如果开始时点可能在同一过程内发生多次，例如多段、周期、引导或重施步骤的 `STEP_EXECUTION`，普通冷却只在该时点第一次发生时开始，后续同类时点不重复开始或刷新普通冷却。

弹药或充能恢复使用 `AMMO` 内部状态；技能自身被动的独立触发间隔使用 `INTERNAL_COOLDOWN` 内部状态。它们不得混入普通冷却字段。

## 10. 内部状态操作

```json
{
  "operationKey": "consume_focus",
  "name": "消耗专注层数",
  "stateKey": "focus_stacks",
  "operation": "CONSUME",
  "valueFormulaKey": "focus_cost",
  "optionKey": null,
  "moment": {
    "momentType": "PROCESS_START",
    "stepKey": null
  },
  "sortOrder": 10
}
```

公共规则：

1. `operationKey` 在同一过程内唯一，创建后不可修改。
2. `name` 必填，去除首尾空格后长度 1～100。
3. `stateKey` 必须引用同一技能内部状态。
4. `moment` 必须引用当前过程合法时点。
5. 已有操作的 `operation` 不可修改；需要改变语义时删除旧操作并新增新标识。

允许形状：

| 内部状态种类 | 允许操作 | `valueFormulaKey` | `optionKey` |
| --- | --- | --- | --- |
| 计数、弹药 | `INCREASE`、`DECREASE`、`CONSUME`、`SET` | 必填 | 必须为 null |
| 计数、弹药 | `RESET` | 必须为 null | 必须为 null |
| 模式 | `SELECT` | 必须为 null | 必填，引用当前模式选项 |
| 准备标记 | `ENABLE`、`DISABLE`、`TOGGLE` | 必须为 null | 必须为 null |
| 内部冷却 | `START`、`RESET` | 必须为 null | 必须为 null |

数值操作公式必须属于当前技能。`RESET` 恢复内部状态定义中的初始值；内部冷却 `START` 使用内部状态定义中的时长公式。

## 11. 引用、停用与删除规则

1. 父级技能即使已停用，也允许维护自身过程和内部状态。
2. 公式必须存在于同一技能；公式没有启停状态。
3. 效果、内部状态、步骤和模式选项必须存在于同一技能或当前过程，不接受跨技能引用。
4. 被过程步骤、普通冷却、内部状态定义或内部状态操作引用的公式禁止删除，沿用 `409.SKILL_FORMULA_IN_USE`。
5. 被过程效果挂接引用的效果禁止删除，返回 `409.SKILL_EFFECT_IN_USE`。
6. 被过程内部状态操作引用的内部状态禁止删除，返回 `409.SKILL_INTERNAL_STATE_IN_USE`。
7. 被模式选择操作引用的模式选项不能从内部状态全量更新中移除，返回 `409.SKILL_INTERNAL_STATE_OPTION_IN_USE`。
8. 删除过程只删除自身步骤、普通冷却、效果挂接和内部状态操作，不删除效果、公式、内部状态或模式选项。
9. 删除未被引用的内部状态只删除自己的类型明细或模式选项，不删除过程或公式。
10. 删除技能时按“过程 → 效果与结果 → 内部状态 → 公式与节点 → 参数 → 分类关系与技能”的顺序清理自身结构；外部技能的阶段 7.2 冷却变化引用仍按阶段 7.2 规则阻止删除。

## 12. HTTP 契约

所有接口沿用现有 Admin Token、统一成功响应、统一错误外壳和路径编码规则。

### 12.1 内部状态

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/internal-states
GET    /api/admin/games/{gameId}/skills/{skillKey}/internal-states/{stateKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/internal-states
PUT    /api/admin/games/{gameId}/skills/{skillKey}/internal-states/{stateKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/internal-states/{stateKey}
```

1. 列表返回摘要数组，不分页、不接收关键词；空列表返回 `[]`。
2. POST 请求包含公共字段和完整 `detail`；成功返回 201 和完整详情。
3. PUT 不包含 `stateKey`，并全量替换类型明细或模式选项；成功返回 200。
4. 已有内部状态的 `stateType`、`scope` 以及已有模式选项的 `optionKey` 不可修改；模式选项名称、排序和初始项可以全量修改。
5. DELETE 成功返回 204；被过程引用时不删除任何内容。

### 12.2 技能过程

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/processes
GET    /api/admin/games/{gameId}/skills/{skillKey}/processes/{processKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/processes
PUT    /api/admin/games/{gameId}/skills/{skillKey}/processes/{processKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/processes/{processKey}
```

1. 列表返回摘要数组，不分页、不接收关键词；空列表返回 `[]`。
2. POST 在一个事务中写入过程、普通冷却、全部步骤、效果挂接和内部状态操作；成功返回 201 和完整详情。
3. PUT 不包含 `processKey`，请求数组是当前过程完整集合。相同稳定标识更新，新增标识创建，请求中缺少的标识删除。
4. 已有步骤的 `stepType` 和已有内部状态操作的 `operation` 不可修改。
5. PUT 删除仍被本次冷却、效果挂接或状态操作时点引用的步骤时，返回 `400.INVALID_SKILL_PROCESS_REFERENCE`，原因使用 `UNKNOWN_STEP`，字段定位到实际 `moment.stepKey`，并保持旧聚合不变。
6. DELETE 成功返回 204，只删除当前过程内部结构。
7. 所有接口先验证游戏，再验证技能；父级不存在不得用空数组掩盖。

## 13. 稳定错误

沿用现有 `details.fieldIssues`。阶段 7.3 新增或复用：

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | JSON 语法、字段类型、内部状态种类、步骤种类、操作或固定选项无法绑定，或携带不属于当前种类的明细字段。 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、空步骤、空行为、重复稳定标识、不可修改字段、明细形状、时点与步骤组合错误。 |
| 400 | `400.INVALID_SKILL_INTERNAL_STATE_REFERENCE` | 内部状态引用了不存在或跨技能的公式。 |
| 400 | `400.INVALID_SKILL_PROCESS_REFERENCE` | 过程引用了不存在或跨技能的公式、效果、内部状态、步骤或模式选项。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.SKILL_NOT_FOUND` | 父级技能不存在。 |
| 404 | `404.SKILL_INTERNAL_STATE_NOT_FOUND` | 内部状态不存在。 |
| 404 | `404.SKILL_PROCESS_NOT_FOUND` | 技能过程不存在。 |
| 409 | `409.SKILL_INTERNAL_STATE_KEY_EXISTS` | 同一技能内部状态标识重复。 |
| 409 | `409.SKILL_PROCESS_KEY_EXISTS` | 同一技能过程标识重复。 |
| 409 | `409.SKILL_FORMULA_IN_USE` | 删除仍被效果、过程或内部状态引用的公式。 |
| 409 | `409.SKILL_EFFECT_IN_USE` | 删除仍被过程挂接引用的效果。 |
| 409 | `409.SKILL_INTERNAL_STATE_IN_USE` | 删除仍被过程操作引用的内部状态。 |
| 409 | `409.SKILL_INTERNAL_STATE_OPTION_IN_USE` | 全量更新准备移除仍被模式选择操作引用的选项。 |

字段路径使用实际提交数组下标，例如 `steps[1].detail.intervalFormulaKey`、`effectBindings[0].moment.stepKey`、`stateOperations[2].optionKey`、`detail.options[1].initial`。

两类无效引用一次返回全部字段问题。内部状态原因至少区分 `UNKNOWN_FORMULA`；过程原因至少区分 `UNKNOWN_FORMULA`、`UNKNOWN_EFFECT`、`UNKNOWN_INTERNAL_STATE`、`UNKNOWN_STEP` 和 `UNKNOWN_MODE_OPTION`。

## 14. 页面外部行为

1. “技能管理”列表在现有“参数与公式”和阶段 7.2“效果与结果”之外增加“过程与内部状态”操作，不新增主导航或独立路由。
2. 点击后打开“过程与内部状态 - {技能名称}”弹窗，包含“技能过程”和“内部状态”两个页签。
3. 技能过程页签提供列表、新增、查看、编辑和删除；过程编辑器结构化维护基本资料、普通冷却、步骤、效果挂接和内部状态操作。
4. 内部状态页签提供列表、新增、查看、编辑和删除；编辑器按五种固定类型显示对应字段和模式选项。
5. 步骤、效果挂接、内部状态操作和模式选项使用子弹窗或行编辑草稿，不允许直接编辑 JSON、脚本或大块配置文本。
6. 过程步骤按数字排序维护，不建设拖拽关系图。删除草稿中仍被时点引用的步骤时直接阻止并指出引用位置，不静默清空其他配置。
7. 效果选择器读取同一技能阶段 7.2 效果；公式选择器读取同一技能公式；内部状态和模式选项读取当前技能目录，不硬编码业务记录。
8. 查看模式不因目录加载失败而丢失已保存稳定标识；新增和编辑所需目录不完整时只阻止依赖该目录的操作。
9. 保存成功关闭当前编辑弹窗并刷新对应列表；保存失败保留完整聚合草稿和字段错误。
10. 页面不显示阶段说明、未来功能占位、执行预览、计算结果或 Wasm 入口。

## 16. 跨端验收案例

### 16.1 主动立即过程

验收重点：过程不复制伤害结果、公式或冷却变化结果；普通冷却只保存当前技能时长和开始时点。

### 16.2 周期过程

为玛尔扎哈 E 建立周期步骤、执行次数、间隔和伤害效果挂接。

验收重点：可以完整保存周期骨架，但目标死亡传播、其他技能刷新、效果与状态生命周期和事件触发均没有录入字段。

### 16.3 多段与内部计数

为艾希 Q 建立技能自身计数状态、多段步骤和消耗计数操作。

验收重点：多段次数与计数状态分别保存；积累层数的攻击事件、暴击、吸血、命中联动和攻击联动次数没有提前加入。

### 16.4 强化下一次普通攻击

为耀光能力建立准备标记、内部冷却、强化下一次普通攻击步骤、命中效果挂接，以及步骤超时或完成时的准备标记操作。

验收重点：过程骨架可以保存；“施放其他技能后准备”的外部触发仍等待阶段 7.5。

### 16.5 资源扣除与失败返还

### 16.6 删除保护与事务

1. 删除被过程挂接的效果返回 `409.SKILL_EFFECT_IN_USE`。
2. 删除被过程操作引用的内部状态返回 `409.SKILL_INTERNAL_STATE_IN_USE`。
3. 删除被步骤或内部状态引用的公式返回 `409.SKILL_FORMULA_IN_USE`。

## 17. 后续阶段依赖

本阶段只建立后续可引用的稳定骨架，不冻结后续详细设计：

1. 阶段 7.4 为持续属性变化、普通护盾和状态操作补充生命周期关系，不把数值效果或技能内部状态改写成战斗状态。
2. 阶段 7.5 为被动启动、攻击命中、受到伤害、过程失败原因等外部事件建立明确关系，并为计算时传入参数绑定内部状态、战斗状态、事件值或前序结果来源。
3. 阶段 7.5 另行处理每目标冷却、触发次数和循环保护；本阶段的 `TARGET + COUNTER` 只提供按当前目标保存计数的稳定定义。
4. 阶段 7.6 在既有步骤和效果之上补充暴击、吸血、命中联动、攻击联动、法术护盾和前序结果语义。
5. 计算输入和 Wasm 阶段再决定这些结构如何执行，本阶段不预留运行时字段。

## 18. 停止门禁

出现以下任一情况必须停止开发并回到方案评审：

1. 阶段 7.2 最终表、接口或删除语义与本阶段引用前提不一致。
2. 过程必须复制效果结果、公式表达式、参数等级 Map 或资源变化数值才能保存。
3. 内部状态必须改成游戏级变量、战斗状态或自由 JSON 才能表达。
4. 实现需要提前增加外部事件、条件、效果与状态生命周期、动态输入供值、暴击、吸血或前序结果字段。
5. 过程聚合无法在一个事务内维护，必须暴露步骤、挂接或操作的独立半成品接口。
6. 强类型明细和真实外键无法成立，必须退回通用多态关系、数组、JSONB 或自由脚本。
