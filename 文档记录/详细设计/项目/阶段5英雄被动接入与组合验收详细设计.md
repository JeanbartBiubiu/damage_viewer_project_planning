# 阶段5：英雄被动接入与组合验收详细设计

方案版本：第六版5C获批有限范围完成，2026-10-05。5A、5B已分别本地提交，未推送；5C交付真实艾希与烬的条件主体、属性转换、弹药恢复和装备组合。贾克斯整体到期及蔚W伤害后削甲等已确认口径保持；烬采用4发、2500毫秒装填及第四发独立附伤，暴击状态分支后续再补。额外技能强化和阶段6不提前交付。本稿是本阶段增量的唯一详细来源；历史评审和实施证据另记。

本设计承接[六阶段推进方案](./单攻击方计算六阶段推进方案.md)第7节。原生逐刀身份、提交与预算继续以[阶段2设计](./阶段2无装备连续普攻详细设计.md)为准；图表和明细沿[阶段3设计](./阶段3图表字段与交互详细设计.md)；装备、真实接收事件、动态等待和响应消费后回收沿[阶段4设计](./阶段4装备接入与机制验收详细设计.md)。本文只扩充英雄来源及其实际需要的机制，不另建英雄专用计算链。

## 1. 目标、非目标与分步门槛

阶段5默认将角色真实绑定技能、选中装备的绑定技能、已选合法构筑实际授予的技能纳入场景来源；不要求玩家重新逐个添加已经拥有的技能。每项来源技能默认本场景启用，允许额外关闭。来源绑定、本场景开关、已学等级及执行入口是不同层次：默认挂载不意味着主动技能自动施放。A继续自主普攻，B仍无自主攻击和主动施放计划，只执行本场景合法自然组成。被动组成不等于P槽，也不由技能分类或名称单独判断。

| 子阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| 5A 默认挂载、场景开关与常驻 | 双方角色／装备／可选构筑技能默认来源集合、等级供值、按来源禁用、自然入口、完整快照与首刀前初始化。 | 三类来源均默认列入并可独立关闭；至少一项非P槽常驻及一项实际构筑授予进入最终Wasm，主动兄弟入口零次执行。 |
| 5B 开始／命中触发 | 真实开始与命中分离、来源叠层、按来源与对手的计数、期限、内部冷却及装备组合。 | 开始、真实命中、额外联动不混计；首次与到期边界、同刀取值与同次额度、双方归属通过。 |
| 5C 特殊普攻与机制就绪 | 完整特殊主体、离散状态、弹药消费／恢复、唯一下一刀安排。 | 特殊主体不叠加共享伤害；无弹不伪造攻击；装填完成后恢复；英雄与装备同刀组合及同会话压力通过。 |

5A通过后进入5B；5C按“特殊伤害主体→有限弹药／装填闭环”推进，不要求一次交付全部英雄。仅写设计不计英雄录入完成、管理配置完整或运行支持。

本期不含主动技能、需主动开启的攻击强化、普攻重置、真实移动／弹道、动态范围、多目标、召唤物、复活、随机逐次暴击、自动加点或最优施法策略。法力、能量、生命等普通施法费用继续取消；弹药、计数和其他已选机制状态的必要消费并未取消。需要主动施放的分支留阶段6，不用伪造一次施法将其提前激活。

可选构筑接入仅复用现有定义、选择校验和技能授予，不新增符文或海克斯专用体系。额外选择不属于当前角色／装备／构筑授予范围的技能，以及其它额外强化，本期只在布局和职责上保留独立空位；不做选择器、数据录入、接口字段、数据库表、Wasm分支或通用插件机制。

## 3. 场景选择、只读快照与入口范围

### 3.1 默认来源、请求和等级

本阶段将现有快照路径改为 `POST /api/admin/games/{gameId}/simulation-snapshot`，用结构化请求承载选择；仍沿现有管理鉴权，在同一可重复读只读事务内读取，不持久化或执行战斗。替换旧GET调用及文档，不保留兼容入口。后端按实际角色关系、已选装备及合法构筑选择计算默认来源集合，不能把Web是否提交某项技能当成它是否已绑定的依据。

保留双方角色／等级、普攻／等级、双方装备键八个现行字段，增加以下四个必填数组；这替换第一版尚未实施的手动英雄技能选择数组，不提供两套并行契约：

| 字段 | 每项与约束 |
| --- | --- |
| `sourceBuildConfigurations`、`targetBuildConfigurations` | 每项复用[构筑设计](./构筑系统管理与场景装配详细设计.md)第6节的完整配置值：系统、分组角色、位置选择、投入等级及明确预算。空数组只表示该侧未选构筑，不自动选推荐配置。 |
| `sourceSkillSettings`、`targetSkillSettings` | 默认来源上的覆盖设置，每项为 `{ origin, skillKey, enabled, skillLevel? }`。空数组表示未覆盖默认开关，不表示没有绑定技能。 |
| `origin` | 来源身份：角色为 `{ kind: CHARACTER, characterKey }`；装备为 `{ kind: EQUIPMENT, equipmentKey }`；构筑选择实例为 `{ kind: BUILD_OPTION, systemKey, roleKey, groupKey, slotKey, optionKey }`。枚举表示角色、装备、构筑可选项，实际请求使用字符串。 |
| `skillKey`、`enabled` | 稳定技能键和本场布尔开关；只能覆盖该侧默认集合中的真实来源技能。同一完整来源身份＋技能键不重复，不按技能键跨来源统一禁用。 |
| `skillLevel` | 仅角色来源可覆盖已学等级，整数0～真实最高等级；0明确表示未学，来源仍保留、不开执行分支，不改成1。装备沿现行单级定义；构筑等级只由其授予规则产生，不允许覆盖为其它等级。 |

2026-10-04负责人追加页面默认最高等级：读取完整配置后，尚未设置的可编辑角色来源技能按各自真实最高等级预选，并明确写入场景请求后重新读取快照，不只是显示一个未提交的默认值。手动低等级、0未学及清空保留，不因重读恢复最高；全局禁用来源不重开，装备及构筑授予等级不变。所选普攻仍沿 `basicAttackLevel`，不能另行覆盖；后端与引擎不猜未提供等级，也不按角色等级或技能槽位推断。纯主动分支即使有场景等级仍不执行。场景禁用不修改管理中的技能状态、关系或装备／构筑选择。

页面先读取默认来源及完整配置作候选，显示全部本期自然入口和关闭原因，不让用户逐笔选择伤害。自然根由实际配置和场景规则生成，回显 `enabledRuleKeys`供确认与审计，不再作为任意根选择请求。最终事务重新校验关系、构筑选择、来源设置及等级；关系或选择变化不能沿用一个已经不存在的来源覆盖项。

Web保存每份已确认候选的 `baseDigest`，在编译前按技能键与POST返回的完整配置摘要逐项比对；同一规则键下动作或数值变化也必须重新确认。摘要不同或候选缺失时保留草稿、提示刷新，不编译新树；仅收到新的场景摘要不能替代这次确认。沿用已有摘要，不为此新增数据库版本表或候选锁。

例如克格莫Q来源的等级与开关覆盖项为：

```json
{
  "origin": { "kind": "CHARACTER", "characterKey": "champion_kogmaw" },
  "skillKey": "kogmaw_q",
  "enabled": true,
  "skillLevel": 3
}
```

此项不表示只挂载Q或自动施放Q，其它角色绑定仍默认存在；只验证Q的对照场景须显式关闭其它附加来源并记录。等级3只是场景例，不是默认加点。角色关系没有槽位字段，不能用技能键后缀、排序或P分类替代入口判断；本期不新增槽位表或加点合法性系统。

构筑定义、位置规则和完整选择合法性的唯一来源仍为构筑设计，不在本稿复制另一套规则。后端在同一快照事务内读取所选完整定义并校验整套选择；按 `activationRank`（技能激活投入等级）判断实际授予，等级沿 `FIXED`（固定技能等级）或 `SAME_AS_OPTION`（随投入等级）。同一选项在不同合法位置是不同实例，禁用项只停用对应实例授予的技能，不能去掉预算成本、投入或位置数量。无效构筑不能靠关闭技能绕过完整校验。

### 3.2 完整读取与可执行闭包

快照 `selection`回显规范化后的全部选择与覆盖设置；双方 `attachedSkills`继续保存真实关系，并增加默认技能来源清单、所选构筑定义及完整选择。来源清单按实例列出绑定身份、全局状态、本场开关、最终等级或待供值、有效自然根和未执行原因。配置集合按技能键去重读取完整作者树，运行来源不能据此去重；沿用最多32份完整配置边界，超出时明确报告，不静默删来源。

默认清单不等于每条来源立即产生运行状态。只有全局可用、本场开启且等级条件满足的来源，才编译和挂载本期自然组成；未学、关闭或纯主动暂缓的来源保留清单与原因，不初始化状态、不注册监听、不发周期。关闭装备绑定技能不移除该装备固有固定属性，移除装备必须改变选装；关闭构筑技能也不撤销该构筑选择。

每份读取的完整配置保留主体、参数、公式、效果及全部并列结果、过程、内部状态、规则与 `baseDigest`。执行范围从开启来源的全部本期自然根出发，递归追踪其动作、条件、公式、状态、过程时点与生命周期引用，形成必需对象集合；不能因已默认绑定就把整技能主动入口一起运行。

闭包还须反查启用链可能真实产生的过程、结果、内部状态和生命周期事件所匹配的订阅规则，限定本次已选运行来源、拥有方及真实对象归属；再纳入这些规则的完整动作与引用，反复展开直到集合稳定。只沿“规则引用对象”单向收集会漏掉事件尾部，不合格；共用对象用稳定身份去重，条件仍由运行时判断。被读取但未选入的技能不会因此自动获得挂载或事件监听。

独立兄弟入口可标为阶段6主动分支或依赖尚未发生事件；整份来源可以标为本场已关闭或未学。作者内容和排除原因仍可回查。开启来源的任一必要自然结果、条件、数值或引用不支持时整体拒绝，不能自动替用户关掉；用户可明确关闭整个非必需来源做对照，不得将剩余结果称为整英雄／整装备完整。只有参数／公式的待配置自然技能不生成空成功监听。

后端现有“遍历整份配置并要求集合内引用”的检查须拆成完整作者读取与启用闭包检查。被排除主动兄弟或关闭来源的外部引用不强制进入执行集合；开启闭包的定义必须同游戏、真实存在、全局可用并标为只读依赖。读取定义不等于授予运行来源：执行其它拥有方状态或监听时，须有默认集合中实际开启的对应来源和有效等级；所需来源被禁用则报出依赖，不能悄悄重新打开，也不拿同技能另一来源冒充。

技能摘要与场景摘要沿现行口径，场景摘要覆盖默认来源、双方构筑定义／选择、开关、等级、自然根及排除原因、完整作者内容与依赖，排除读取时间。Wasm规则摘要另包含适配版本、明确初值和编译程序；只切换开关也须使旧请求及结果失效。

### 3.3 错误行为

请求字段缺失、未知字段、重复项、非布尔开关或非法整数等返回400；真实来源、构筑合法性、全局启用、等级或必需依赖不符沿 `409.SIMULATION_SNAPSHOT_INVALID`返回具体字段问题。覆盖设置不能授予默认集合之外的技能，额外技能／强化请求本期明确拒绝。后端不猜Wasm运行支持；Web和Wasm继续核对开启闭包，结构错误不伪装为预算停止或部分成功。

### 3.4 5A共享响应及本次准入

双方角色响应保留现有字段，新增 `selectedBuilds`与 `skillSources`：前者每项为 `{ definition, configuration }`，分别是现有完整构筑定义与本次完整选择；后者每项含 `origin`、`skillKey`、`skillName`、`skillStatus`、`enabled`、可空 `skillLevel`、`enabledRuleKeys`及可空 `inactiveReason`。来源身份沿3.1，不另设按英雄编号的规则。

快照编译从完整保留的绑定及作者树中选择有效程序，不能删除原关系模拟关闭。关闭装备技能不删除固定属性；属性派生须根据实际开启的角色、装备和构筑贡献统一组织，不能将额外攻速重复累计。主负责人负责Wasm和Web核心适配，后端与页面执行者按以上字段并行接线，最终统一核对。

## 4. 按技能配置激活的来源与事件组织

开启的角色、装备和构筑授予都编译为明确拥有方的来源挂载；稳定标识、公式命名空间、状态与过程带侧别、完整来源实例和技能身份。双方或不同来源出现同一技能时可共享作者配置，不能合并等级、开关、状态或执行次数；是否叠加、取强或限次沿效果本身配置。构筑不同合法位置不能按选项键合成一个实例。角色／构筑来源不占装备槽，固定属性和技能贡献不得在宿主与Wasm重复加算。

角色所选普攻本身已在默认绑定清单中，只挂载和驱动一次，不能因自动装配再复制主体。用户禁用当前普攻来源时，普攻运行明确拒绝，不忽略开关，也不自动换成共享普攻；B的普攻绑定即使开启仍不增加自主攻击计划。

自然根入口首批允许初始化、真实普攻开始／命中、真实接收／受伤、原生攻击／命中联动。规则仍须表达实际拥有方和合法对手资格；不能仅凭事件类型为A、B一起激活。过程、结果、内部状态和生命周期事件只从已启用链真实产生，不独立伪造为启动输入；其它技能实际使用／命中根入口留阶段6，所选真实普攻自身的命中入口按其完整主体处理。

初始化仍在0毫秒为每个角色发一次自身事件，不按技能数量发多次。先建立双方全部基础属性、来源和显式初态，再完成双方初始化及同步尾部，最后开放首刀。初始机制就绪时首刀可以从0毫秒开始；无弹等机制未就绪时按第6节等待，不伪造0毫秒开始。

每次真实攻击只有一个原使用身份 `useRef`。攻击开始、唯一首次过程、命中事实和同步尾部沿用它；英雄附加开始监听不能再启动一个普通攻击过程。现行接收反应→主体结果→命中监听及同事件条件冻结不改；跨来源保持现有稳定执行次序，来源内部保持作者动作与并列结果顺序。若某机制需要主体伤害前加层，应明确配置到相应开始／接收时点，不因英雄名称调换全局顺序。

额外联动沿原使用身份和真实拥有方，不重新发攻击开始／命中，不凭多一笔伤害推进英雄计数。规则是否响应联动、同次额度共享键及消费范围由配置明确决定；不能拿施放实例标识替代每刀身份，也不能一律让全部英雄附伤跟随鬼索复制。

## 5. 5A／5B常驻、叠层、期限与数值

5A沿初始化结果和普通属性修正执行真实等级参数；所需攻速收益系数等属性继续明确供值。英雄额外攻速即使没有装备，也须进入同一攻速派生；不能因为没有选短剑就漏掉英雄贡献。基础、额外、总攻速和每秒次数仍分开，每方每个派生输出只允许一个定义。

来源叠层与对手标记分别归属实际来源，后者按来源与承受者隔离，不因当前只有一对手就放入全局计数。层数、合格命中数和弹药量必须显式声明为非负整数，初值、上限、写入与消费均检查；现有浮点状态及向上封顶不替代离散校验。达到阈值后各结果及清零／保留顺序沿作者动作，不按伤害记录反算命中次数。

2026-10-05负责人明确蔚W口径：真实普攻命中及鬼索额外命中联动均累计同来源、同目标计数，达到第三次先结算W附加伤害，再削减承受者护甲并应用来源攻速，最后清零计数；第三次主体及W附伤不回溯使用新削甲。W附伤只允许全能吸血，明确禁止生命偷取，不继承普通攻击的吸血覆盖。联动仍不是新的真实攻击开始；阈值、保持期、附伤公式、削甲及攻速数值沿保存参数，顺序沿保存动作，不按英雄编号选分支。实际规则匹配来源拥有方的额外命中事件，不新增仅识别鬼索编号的筛选；本次场景只有已选鬼索产生该事件。

蔚W的原生命公式叶子读取最终生命值，但原生生命最终值会随扣血变化，不能表示最大生命。本轮只将该叶子改为目标当前生命加已损失生命，保留九参数、原公式键和其它伤害系数，不新增属性取值枚举或改变全局最终值含义。全能吸血沿真实游戏规则继承，生命偷取用明确禁止例外；当前游戏只有这两类吸血规则，不凭空补物理／法术吸血目录。

保持、刷新、固定窗口、全部到期和逐层衰减不是同一机制。期限为可表示的正整数毫秒；到期与攻击同刻先按既有精确到期口径处理，旧期限不得清掉刷新实例。负责人在本次实施中明确要求贾克斯按全部层数消失计算：本项目选择攻击开始加层、每次加层刷新2500毫秒保持期，整体到期恢复0层，最高8层；这不是游戏逐层衰减的实装证明。保存为现有 `ALL_AT_ONCE`（整体到期）与 `REFRESH_ALL`（全部刷新）配置，不新增退层字段，也不在运行时按英雄名称选择口径。

5B编译状态显式声明 `valueType:integer`（离散整数），初值与上限必须为非负安全整数；恢复、每次写入及封顶前操作数均复核，不能用封顶隐藏负数或小数。减少与消费允许整数负增量，但不可透支成负值；普通 `number`（数值）声明不借机改义。目标计数复用 `state_scope/provider_target`（来源与对手状态范围）和 `provider.target_state`（当前来源对手状态读取），按实际拥有方、挂载、状态键及真实对手隔离，不新增另一套计数器；本轮不宣称多目标保留。

管理计数明细新增可选 `detail.durationValue`（保持期限取值）；空值或未声明表示不计时，显式0也不计时。正整数毫秒值在合法写入非初值后刷新，到期恢复明确初值；显式写回初值会清除旧计时。Web将其编译为现有状态 `durationMs`（时长）及 `refresh_on_write`（写入刷新）。同目标标记和内部冷却分别采用该保持期与现有固定窗口口径，不混用。保持期限的参数／公式引用仍进入后端校验和引用索引，没有数据库表变更。

目标持续属性沿真实 `SOURCE_TARGET`（来源与承受者）单层实例执行、刷新与到期。新增仅用于 `ATTRIBUTE`（属性）及 `ATTRIBUTE_PERCENT`（属性百分比）的 `RATIO_MULTIPLY`（比例乘算）修正区：增加比例r编译为乘数1+r，减少比例r编译为1-r；乘算位于装备固定加算之后，不修改固有值。旧 `RATIO_ADD`（比例加算）的固有值基数不变，不能将其当作总护甲减少；减少率必须在0至1之间。数据库只扩充乘区的计算方式及合法组合两条检查，不新增表、不删除或改写已有乘区数据。

开始期改变攻速是5B专门门槛：唯一首次过程求得原冷却后，须保存求值当时的属性基线；同刻附加开始结果改变依赖时，按已完成进度为0重映射该等待。禁止重启首次过程、重复消费或重复提交初始冷却，但允许在暂存帧中按新依赖纯求值改期周期；不能把开始前冷却与开始后攻速混配，也不能把有封顶或其它依赖的公式一律比例缩放。统一预检后提交唯一等待；期间的后续变化继续按阶段4同帧提交、唯一节点改期口径执行。

阶段4遗留的非恒定生命周期公式命名风险列为5B公共前置：所有状态强度、期限和嵌套公式引用必须随命名空间一起转换，分别验证可折叠常量与实际属性读取公式。在修复与最终产物复验前，拒绝该类动态期限请求；既有显式常量期限证据仍有效，不称旧风险已经关闭。

## 6. 5C特殊主体、弹药与恢复

### 6.1 主体与属性语义

普攻候选必须来自该角色真实关系、已启用 `basic_attack`分类和完整配置，不再限定 `shared_basic_attack`。仍明确绑定同一真实主体的开始、命中与首次控制能力；主体和被动来源分工清楚，不把特殊伤害作为“共享本体再附加一次”。缺少特殊主体、被动必要分支或机制就绪闭环时明确拒绝，不自动选择共享普攻。

特殊伤害是否允许普通暴击、强制暴击、分项暴击及吸血资格沿已存结果配置处理；期望伤害不自动产生真实暴击事件。需要实际随机暴击去选择不同状态分支而尚无确定口径时，本期拒绝该场景；不以期望伤害比例虚构减速或计数事实。艾希与烬需分别核对主体和被动的真实配置，不读取说明文字执行。

固定攻速、额外攻速转攻击力等必须有可保存的通用作者声明。先核对现有属性修正能否表达；确需扩展现有属性派生时，只开放本批实际需要的攻速／攻击力输出，禁止自身总值回读、循环和多重写入，原普通派生与特殊派生不得同时写同一输出。缺声明或模型不完整时先补这项公共缺口，不能在Web按英雄编号写转换公式。

### 6.2 弹药声明与初态

复用管理 `AMMO`（弹药内部状态）中的 `initialValue`、`maxValue`、`recoveryIntervalValue`、`recoveryMode`和 `recoveryStartCondition`。首批只开放 `ALL_AT_ONCE`（一次恢复全部）＋ `WHEN_EMPTY`（耗尽时开始恢复），承担烬装填闭环；逐个充能和消耗后开始恢复不因管理枚举存在而提前接入。

这五项必须来自完整配置并可按本次等级、明确计算时输入求得；容量为至少1的整数、初值为0～容量的整数，初值0与缺值不同，容量不能代填初始满弹。AMMO不映射为法力属性，也不把装填变成第二只普攻冷却。编译状态使用现行初值／上限字段，并增加弹药恢复描述：状态类型为弹药、恢复间隔、恢复方式、启动条件；已有计数的保持期限不混作恢复间隔。本批内核已实现上述有限消费形态，其它恢复枚举不提前开放。

消费沿现有内部状态动作；首批每次已接受攻击恰有一次可追踪的消费，数量限定为1，指向同一明确弹药状态。编译期从真实开始链定位唯一消费及恢复声明，形成内部机制就绪绑定，不新增按英雄编号选择的计划参数。分支可能不消费、重复消费、变量消费、消费大于1或找不到唯一弹药状态时暂不准入；不把 `WHEN_EMPTY`改成“不足消费时恢复”来掩盖剩余库存停滞。

### 6.3 就绪、消费与唯一下一刀

攻击许可必须在生成真实使用身份和开始事件之前核对。未就绪不扣弹、不发开始／命中、不推进英雄／装备计数，也不计开始次数；只能等待配置中实际存在的恢复时点，不用固定间隔轮询猜测何时可攻击。

已接受攻击在开始链同帧消费，动作失败或预算预检失败时不留下部分消费。第四发等资格使用本次消费前的真实库存或已冻结状态；需要供命中阶段使用的判定沿原使用身份保存，不到命中时重新读取已扣减库存，更不按全场伤害行号判断“第四发”。主体与合法同步尾部仍只执行一次。

耗尽时原生安排唯一恢复事件；恢复完成前不补造攻击。再次可开始时刻取实际普通攻击冷却与机制就绪时刻的共同约束，维护唯一下一刀节点，不把两个等待相加成双重冷却。初态为0且存在合法恢复声明时先安排恢复；不存在可唤醒时点则准入失败，不返回假成功的空战斗。

恢复间隔在真实恢复开始时求一次；同刻队列预检、状态、恢复代号及下一刀安排共同提交，旧恢复事件不能再次补弹。首批不模拟主动提前装填、脱战自动装填、取消装填或普攻重置；作者树存在本次必需而未支持的上述行为时明确报告，不能将恢复方案外推为完整烬被动。

5C的普通攻击周期不能一律套额外攻速比例。实际过程冷却及其属性／状态依赖决定周期；开始期变速和非攻速依赖改期须有独立用例。装填时间只按实际恢复声明变化，不顺手跟着普通攻速光环缩放。观察终点仍为闭区间；目标或来源死亡后不开始下一刀、不续装填，保留当前合法同步尾部与既有完整性口径。

### 6.4 2026-10-05批准的首批范围与实现契约

负责人批准先实现有限范围，之后再补暴击状态分支。烬按固定客户端资料的4发、2500毫秒装填、第四发强制暴击及独立已损生命附伤配置；等级数值按该资料的插值与断点补齐。艾希与烬仍使用期望暴击伤害，不生成随机暴击事件，因此本批不执行暴击触发的强化减速或移速。未进入自然闭包的资料参数继续保留，不把它们称为已运行能力。

艾希主体按目标是否已有本方配置的冰霜状态选择普通伤害或冰霜强化伤害，被动在真实命中后施加普通减速；首刀无冰霜时不提前享受强化。烬普通发和第四发按本次攻击开始库存选择，第四发附伤单独结算且不再次暴击。共享普通攻击不额外挂载。这些选择均来自保存的条件和结果，不按技能键或英雄编号选择算法。

| 明确机制初值 | 页面与冻结档案增加 `mechanicStateInputs`，每项 `{ side, origin, skillKey, stateKey, value }`；只允许实际开启来源的已声明弹药，整数0～容量。未覆盖时使用声明初值，不以容量补满；页面清空视为缺输入，不自动改0或满弹。完整来源身份参与摘要。该数组不增加后端快照请求字段。 |
| 逐刀等待 | 增加可空 `mechanicReadyAtMs`，`finalReadyAtMs` 仍是普通攻击最终冷却时刻；实际下一刀为二者共同约束的较晚时刻。零弹初态首刀允许晚于0，必须由真实恢复记录和就绪事实解释，不能放松其它逐刀时序校验。 |
| 初次机制就绪事实 | 普攻完整汇总增加可空 `initialMechanicReadyAtMs`（初次机制实际就绪时刻）。仅零弹初态的恢复帧成功提交后填写，保存实际已安排时刻；非空弹或恢复未提交为 `null`。此事实不依赖有限机制记录，观察终点早于恢复而没有攻击、关闭或截断记录都不因此伪称结算未完成。 |
| 机制记录 | `mechanicRecords` 每行 `timeMs`、`kind`、`owner`、`providerRef`、`providerDefinitionRef`、`skillKey`、`stateKey`、`beforeValue`、`afterValue`、`operationRef`、可空 `useRef`、可空 `readyAtMs`。种类为 `STATE_CHANGED`、`WAIT_STARTED`、`WAIT_ENDED`，只记录弹药闭环的实际提交，不扩展为所有内部状态事件。 |
| 机制记录说明 | 现有记录说明增加 `mechanicRecordCount`、`returnedMechanicRecords`、`droppedMechanicRecords`、`mechanicRecordsTruncated`；关闭和截断不改变完整结算。 |

属性转换优先复用现行普通属性管道及有限派生，必要依赖必须先完成普通修正，再求转换；不能依赖字典顺序或上一帧值。消费、恢复、使用身份快照和队列在各自实际帧内共同预检、共同提交；独立的后续监听失败不伪称能回滚已经提交的整刀。装填完成同刻先恢复再检查攻击许可，死亡后不再唤醒下一刀。

## 7. 输入冻结、记录与页面

复用现有页面，在攻击方、目标方各自区域展示默认技能来源表，按角色绑定、已选装备、已选构筑分组：来源、技能名、本场开关、最终等级、自然入口、主动暂缓或未支持原因。选入角色／装备或完成构筑选择后自动生成，开关默认开启；关闭行仍留在表中，不做关系删除。全局禁用、未学、场景关闭、暂缓主动和配置缺失分开显示。所选特殊普攻保留独立名称，不能隐藏未支持行为。

构筑配置入口沿已有系统的分组、位置或投入界面；确认整套合法选择后自动列出实际授予，不让玩家重新挑一次授予技能。来源列表之后保留独立的“额外技能与强化”空位并标未接入，不提供可用选择器或请求字段；未来接入也不冒充角色固有绑定或伪造一件装备。本期只保留位置，不开发额外挂载通道。

机制初值只为实际开启且需要的层数／标记／弹药列出，来自明确配置或本次供值，缺值不当0。切换来源开关、等级、角色、装备、构筑、初态或范围均使快照和结果失效；当前仍存在的来源设置沿完整身份保留，来源消失的设置不得套到新来源。保留合法草稿，重新读快照再运行。

冻结档案新增双方默认来源清单、构筑定义／选择、本场开关与最终等级、执行根及排除理由、来源映射和显式机制初值。继续记录摘要、适配版本、请求、产物身份与释放；对照关闭了什么可直接回查。前端不计算叠层、扣弹、恢复或循环单次攻击。

既有完整刀数、双方伤害／生命、来源与类型汇总不改含义。增加有限 `mechanicRecords`（机制变化记录），每行含真实时刻、拥有方、来源定义／实例、技能和状态键、变化前后、操作来源及可空使用身份；恢复／到期不能伪造一个攻击使用身份。类型首批为状态变化、机制等待开始和结束；动作按实际提交记，未提交记录不发布。

记录预算新增 `maxMechanicRecords`，整数0～10000，默认0为关闭；页面显式传2000观察机制，不能依赖隐含预算。保留／丢弃数进入现有记录说明，截断不影响库存、命中、完整伤害汇总或停止原因；这些有限行不宣称全场机制历史完整。机制表与逐刀联动复用既有时间／使用身份，不用图表补造装填区间或到期事件。
