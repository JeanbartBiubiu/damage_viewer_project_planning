## 1. 本次需要确认的决定

1. 效果从属于一个技能。角色主动、角色被动、装备主动、装备被动和装备消耗能力都继续作为技能维护，不为装备效果建立第二套结构。
2. 一个效果保存稳定标识、名称、说明和排序，并至少包含一个结果。效果在阶段 7.2 只是技能下的有序结果组，不挂接施放步骤、触发事件或时间过程。
3. 一个结果保存稳定标识、名称、固定结果种类、作用对象、说明和排序。结果稳定标识在同一效果内唯一，结果种类创建后不可修改。
4. 阶段 7.2 只开放七种基础结果：伤害、直接治疗、普通护盾、属性变化、资源变化、冷却变化和状态操作。结果种类由系统固定，不提供自由新增页面。
5. 斩杀依赖生命阈值或前序生命结果，反伤依赖受击事件和事件来源目标；二者不在阶段 7.2 暴露空壳种类，分别留到阶段 7.5、7.6 结合条件、事件和前序结果完整设计。
6. 伤害、直接治疗、普通护盾、属性变化、资源变化以及非重置类冷却变化都引用同一技能的一个公式。结果不复制公式表达式、等级 Map 或某次运行值。
7. 数值结果可以额外保存固定倍率、固定最小值和固定最大值。它们只修正本结果引用公式的值，不形成第二套等级数值；随技能等级或角色等级变化的修正仍先建立技能参数或公式。
8. 伤害结果引用同一游戏的伤害类型；属性变化和资源变化引用同一游戏的属性；状态操作引用阶段 7.1 的状态；冷却变化显式引用同一游戏的技能。
9. 阶段 7.2 的作用对象只允许“施法者”和“当前目标”。事件来源目标留到阶段 7.5，不提前加入枚举。
10. 状态操作只允许施加和移除，不保存持续时间、层数、刷新、到期、周期、消耗或数值读取时点。状态仍不增加分类字段。
11. 效果连同完整结果数组一次创建或全量修改，后端在一个事务内维护分表记录。数据库不保存结果数组、类型明细 JSONB 或通用多态关联。
12. 本阶段只保存、校验、回读和保护引用，不执行公式、伤害、防御、治疗、护盾、属性、资源、冷却或状态结算。

上述决定是阶段 7.2 的完整边界。开发执行不得自行增加过程、生命周期、条件、事件、暴击、吸血、前序结果、计算预览、发布或 Wasm 字段。

## 2. 范围与非目标

本阶段交付：

1. 单个技能下效果的查询、查看、新建、全量修改和删除。
2. 效果内一个或多个结果的结构化新增、编辑、排序和删除。
3. 七种基础结果的强类型字段、目录引用、停用引用规则和删除保护。
4. 公式引用及固定倍率、固定最小值、固定最大值的保存和完整回读。
5. 独立关系表、真实复合外键、事务写入和编辑日志。
6. 前后端自动检查，以及开发获批后的真实数据库、真实接口和真实浏览器验收。

本阶段不包含：

1. 技能过程、施放步骤、立即、延迟、多段、周期、引导、蓄力、重施、强化下一次攻击或冷却开始时点。
2. 持续属性变化、状态操作和普通护盾的持续时间、层数、刷新、到期、周期、消耗、作用范围或数值读取时点。
3. 条件、事件、触发关系、每目标冷却、技能内部状态或计算时传入参数的实际供值。
4. 暴击资格、暴击系数、生命偷取、全能吸血、命中联动、攻击联动或法术护盾阻挡粒度。
5. 斩杀、反伤、净化、凝滞、复活、生命下限、伤害免疫、治疗降低或伤害修正。
6. 前序结果引用、前序结果执行、结果间依赖、结果复制或循环保护。
7. 公式执行、伤害结算、计算预览、发布、计算输入组装或 Wasm。
8. 角色与技能、装备与技能的挂载关系。
9. 旧 Ability、Provider、combat-data 效果结构的读取、迁移、兼容或双写。

## 3. 数据关系与责任方向

```text
游戏
├─ 伤害类型 ───────────────┐
├─ 属性 ───────────────────┤
├─ 状态 ───────────────────┤
└─ 技能                    │
   ├─ 技能公式 ────────────┤
   └─ 技能效果             │
      └─ 技能效果结果       │
         ├─ 数值规则 ───────┘
         ├─ 伤害明细 → 伤害类型
         ├─ 属性变化明细 → 属性
         ├─ 资源变化明细 → 属性
         ├─ 冷却变化明细 → 技能
         └─ 状态操作明细 → 状态
```

责任方向固定为：

1. 技能拥有技能效果，技能效果拥有结果。
2. 结果主动引用公式、伤害类型、属性、技能或状态；这些被引用记录不反向保存结果键。
3. 技能参数和公式继续独占可配置数值及表达式；结果只保存引用和本结果固定修正。
4. 后续阶段如果需要引用效果或结果，应新增明确关系和真实外键，不在本阶段预留无语义字段。

## 4. 效果公共契约

### 4.1 效果摘要

```json
{
  "gameId": "lol",
  "skillKey": "ezreal_q",
  "effectKey": "on_hit_results",
  "name": "命中结果",
  "description": null,
  "sortOrder": 10,
  "resultCount": 2,
  "createdAt": "2026-08-27T00:00:00Z",
  "updatedAt": "2026-08-27T00:00:00Z"
}
```

### 4.2 效果详情

效果详情在摘要字段之外增加 `results`。结果按 `sortOrder ASC, resultKey ASC` 返回；效果列表按 `sortOrder ASC, effectKey ASC` 返回。排序值允许相同，稳定标识负责确定并列顺序。

```json
{
  "gameId": "lol",
  "skillKey": "ezreal_q",
  "effectKey": "on_hit_results",
  "name": "命中结果",
  "description": null,
  "sortOrder": 10,
  "results": [
    {
      "resultKey": "damage",
      "name": "造成物理伤害",
      "resultType": "DAMAGE",
      "target": "TARGET",
      "description": null,
      "sortOrder": 10,
      "valueRule": {
        "formulaKey": "damage",
        "fixedMultiplier": 1,
        "fixedMinValue": null,
        "fixedMaxValue": null
      },
      "detail": {
        "damageTypeKey": "physical"
      }
    },
    {
      "resultKey": "self_cooldown_reduction",
      "name": "减少自身冷却",
      "resultType": "COOLDOWN_CHANGE",
      "target": "SOURCE",
      "description": null,
      "sortOrder": 20,
      "valueRule": {
        "formulaKey": "cooldown_reduction_ms",
        "fixedMultiplier": 1,
        "fixedMinValue": 0,
        "fixedMaxValue": null
      },
      "detail": {
        "affectedSkillKey": "ezreal_q",
        "operation": "REDUCE"
      }
    }
  ],
  "createdAt": "2026-08-27T00:00:00Z",
  "updatedAt": "2026-08-27T00:00:00Z"
}
```

`resultCount` 只出现在摘要中；详情以 `results.length` 为准。

### 4.3 效果字段规则

| 字段 | 规则 |
| --- | --- |
| `gameId` / `skillKey` | 只来自路径和响应，请求体不能修改。 |
| `effectKey` | 创建时必填并去除首尾空格；小写字母开头，只含小写字母、数字和下划线，长度 1～64；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100；同一技能内允许重名。 |
| `description` | 可为 null；去除首尾空格，空串保存为 null；最长 2000。 |
| `sortOrder` | 必填；不小于 0 的整数。 |
| `results` | 必填数组，至少一项；同一效果内 `resultKey` 不得重复。 |
| `createdAt` / `updatedAt` | 仅响应，由后端维护。 |

## 5. 结果公共契约

### 5.1 公共字段

| 字段 | 规则 |
| --- | --- |
| `resultKey` | 必填；格式与 `effectKey` 相同；同一效果内唯一；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100；允许重名。 |
| `resultType` | 必填；只允许第 6 节七种固定值；已有结果不可修改种类。 |
| `target` | 必填；`SOURCE` 表示施法者，`TARGET` 表示当前目标。 |
| `description` | 可为 null；空白归一为 null；最长 2000。 |
| `sortOrder` | 必填；不小于 0 的整数。 |
| `valueRule` | 数值结果必填；冷却重置必须为 null；状态操作按下方状态种类规则判断。 |
| `detail` | 必填强类型对象，形状由 `resultType` 决定；不接受其他种类字段。 |

效果更新时，已有 `resultKey` 的 `resultType` 必须与原记录一致。删除一个结果后再使用新标识创建其他种类，属于明确的删除和新增，不属于修改稳定身份。

### 5.2 数值规则

```json
{
  "formulaKey": "damage",
  "fixedMultiplier": 1,
  "fixedMinValue": null,
  "fixedMaxValue": null
}
```

规则如下：

1. `formulaKey` 必须引用路径中同一技能的公式。
2. `fixedMultiplier` 必填，必须是大于等于 0 的十进制数；前端默认 1。
3. `fixedMinValue`、`fixedMaxValue` 可为 null；同时存在时最小值不得大于最大值。
4. 未来执行语义固定为“公式结果乘固定倍率，再应用固定最小值和固定最大值”。阶段 7.2 只保存和回读，不求值。
5. 固定最小值和固定最大值是无条件限制；任何依赖目标、状态、事件或前序结果的限制都不在本阶段。
6. 不能用 `valueRule` 保存等级 Map、计算时传入参数实际值或另一个结果的值。

## 6. 七种基础结果

### 6.1 伤害

`resultType = DAMAGE`，必须有数值规则，`detail` 为：

```json
{ "damageTypeKey": "physical" }
```

`damageTypeKey` 必须引用同一游戏的伤害类型。混合伤害拆成多个有序伤害结果，不建立“物理加魔法”等组合类型。

### 6.2 直接治疗

`resultType = DIRECT_HEAL`，必须有数值规则，`detail` 固定为 `{}`。它只表示直接治疗，不表示生命偷取、根据前序伤害治疗或持续治疗。

### 6.3 普通护盾

`resultType = NORMAL_SHIELD`，必须有数值规则，`detail` 固定为 `{}`。它只保存护盾数值；持续、刷新、叠加、衰减、到期和消耗规则留到阶段 7.4。

### 6.4 属性变化

`resultType = ATTRIBUTE_CHANGE`，必须有数值规则，`detail` 为：

```json
{
  "attributeKey": "move_speed",
  "operation": "DECREASE"
}
```

`attributeKey` 引用同一游戏属性。`operation` 只允许：

| 值 | 中文含义 |
| --- | --- |
| `INCREASE` | 增加 |
| `DECREASE` | 减少 |
| `SET` | 覆盖为指定值 |

本结果不保存持续时间或状态关系；需要持续生效时由阶段 7.4 的生命周期关系直接承接，不需要把属性变化伪装成状态。

### 6.5 资源变化

`resultType = RESOURCE_CHANGE`，必须有数值规则，`detail` 为：

```json
{
  "attributeKey": "mana",
  "operation": "RESTORE"
}
```

资源继续引用现有属性，不新建资源目录或资源分类字段。`operation` 只允许：

| 值 | 中文含义 |
| --- | --- |
| `RESTORE` | 恢复资源 |
| `CONSUME` | 扣除资源 |
| `REFUND` | 返还此前扣除的资源 |

三种值即使数值方向可能相同也保留不同业务含义；扣除或返还发生在什么时点留到阶段 7.3。

### 6.6 冷却变化

`resultType = COOLDOWN_CHANGE`，`detail` 为：

```json
{
  "affectedSkillKey": "ezreal_q",
  "operation": "REDUCE"
}
```

`affectedSkillKey` 必须引用同一游戏技能。`operation` 只允许：

| 值 | 中文含义 | 数值规则 |
| --- | --- | --- |
| `REDUCE` | 减少冷却 | 必填，公式结果按毫秒解释。 |
| `INCREASE` | 增加冷却 | 必填，公式结果按毫秒解释。 |
| `RESET` | 重置为可用 | 必须为 null。 |

本阶段只声明一次冷却变化结果，不定义从施放、命中还是效果结束时触发，也不定义“全部基础技能”等集合选择。需要影响多个明确技能时保存多个结果；依赖角色或装备技能集合的选择留到挂载关系完成后另行确认。

### 6.7 状态操作

`resultType = STATUS_OPERATION`。普通移动减速施加的数值、期限和持续行为统一按[系统精简实施说明第四单元](系统精简实施说明.md#第四单元状态身份与普通减速强度)处理；其他状态操作的 `valueRule` 必须为 null。`detail` 为：

```json
{
  "statusKey": "stun",
  "operation": "APPLY"
}
```

`statusKey` 引用同一游戏状态。`operation` 只允许：

| 值 | 中文含义 |
| --- | --- |
| `APPLY` | 施加状态 |
| `REMOVE` | 移除状态 |

本阶段不保存增加层数、减少层数、刷新、覆盖、消耗、持续时间或移除原因。

## 7. 引用与停用规则

1. 创建效果时，伤害类型、属性、受影响技能和状态必须存在于同一游戏且处于启用状态；公式必须存在于同一技能。冷却变化引用当前路径中的父级技能时例外：即使父级技能已停用，也允许显式选择自身，便于维护停用技能的完整资料；其他停用技能仍不可新增引用。
2. 更新效果时，已有结果原样保留的停用伤害类型、属性、受影响技能或状态可以继续保存，也可以被移除；不能新增或改选为停用引用。第 1 项的停用父级自引用例外同样适用于 PUT：只要 `affectedSkillKey` 等于路径 `skillKey`，新增或改选该自引用都允许；其他停用技能仍拒绝。
3. 是否新增引用按结果稳定标识和引用字段比较。只改名称、说明、排序、作用对象或数值规则，不把未改变的目录引用误判为新增。
4. 被任一结果引用的技能公式禁止删除，返回 `409.SKILL_FORMULA_IN_USE`。
5. 被伤害结果引用的伤害类型继续使用 `409.DAMAGE_TYPE_IN_USE`；被状态操作引用的状态继续使用 `409.STATUS_IN_USE`。
6. 属性当前没有删除接口；停用不影响已有结果回读，但不能被新结果选择。
7. 一个技能被其他技能的冷却变化结果引用时禁止删除，返回 `409.SKILL_IN_USE`。删除技能自身时先删除自身效果和结果，再删除公式、参数和技能；自引用冷却结果不会阻止删除自身。`target` 只描述结果作用于施法者还是当前目标，`affectedSkillKey` 只描述被修改的技能记录；二者不证明角色或装备已经拥有该技能。
8. 删除效果只级联删除该效果自己的结果、数值规则和类型明细，不删除任何公式、伤害类型、属性、技能或状态。
9. 删除结果只删除该结果自己的数值规则和类型明细。阶段 7.5、7.6 建立结果间关系后，再为真实外键补充删除保护；本阶段不预留关系字段。

## 8. HTTP 契约

所有接口沿用现有 Admin Token、统一成功响应、统一错误外壳和路径编码规则。

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/effects
PUT    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
```

### 8.1 查询

1. 列表返回效果摘要数组，不分页、不接收关键词；空列表返回 `[]`。
2. 所有接口先验证游戏，再验证技能。游戏或技能不存在时不得用空数组掩盖。
3. 详情返回完整有序结果和类型明细，不返回数据库内部行或空的其他类型明细。

### 8.2 创建

POST 请求包含 `effectKey/name/description/sortOrder/results`。后端在一个事务中写入效果、全部结果、数值规则和类型明细；任一字段或引用失败时不得留下部分记录。成功返回 201 和完整详情。

### 8.3 更新

PUT 请求包含 `name/description/sortOrder/results`，不包含 `effectKey`。请求中的结果数组是效果当前结果全集：

1. 保留相同 `resultKey` 的结果并更新可编辑字段。
2. 新出现的 `resultKey` 作为新增结果。
3. 原来存在但请求中缺少的 `resultKey` 作为删除结果。
4. 已有结果的 `resultType` 不可修改。
5. 效果资料和全部结果必须同一事务成功或回滚。

成功返回 200 和完整详情。不提供单独的结果接口或局部排序接口。

### 8.4 删除

删除成功返回 204。不存在返回 `404.SKILL_EFFECT_NOT_FOUND`。删除只清理该效果内部结构。

## 9. 稳定错误

沿用现有 `details.fieldIssues`。阶段 7.2 新增或复用：

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | JSON 语法、字段类型、结果种类或操作枚举无法绑定，或携带不属于该结果种类的明细字段。 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、空结果数组、重复结果标识、不可修改字段、数值规则形状或范围错误。 |
| 400 | `400.INVALID_SKILL_EFFECT_REFERENCE` | 公式、伤害类型、属性、技能或状态不存在、跨游戏或跨技能。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.SKILL_NOT_FOUND` | 父级技能不存在。 |
| 404 | `404.SKILL_EFFECT_NOT_FOUND` | 效果不存在。 |
| 409 | `409.SKILL_EFFECT_KEY_EXISTS` | 同一技能效果标识重复。 |
| 409 | `409.SKILL_EFFECT_REFERENCE_DISABLED` | 新增了停用伤害类型、属性、技能或状态引用。 |
| 409 | `409.SKILL_FORMULA_IN_USE` | 删除仍被效果结果引用的公式。 |
| 409 | `409.SKILL_IN_USE` | 删除仍被其他技能冷却变化结果引用的技能。 |
| 409 | `409.DAMAGE_TYPE_IN_USE` | 删除仍被伤害结果引用的伤害类型。 |
| 409 | `409.STATUS_IN_USE` | 删除仍被状态操作引用的状态。 |

字段路径使用提交数组下标，例如 `results[1].valueRule.formulaKey`、`results[0].detail.damageTypeKey`。`400.INVALID_SKILL_EFFECT_REFERENCE` 一次返回全部无效引用，字段问题原因至少区分 `UNKNOWN_FORMULA`、`UNKNOWN_DAMAGE_TYPE`、`UNKNOWN_ATTRIBUTE`、`UNKNOWN_SKILL` 和 `UNKNOWN_STATUS`。

已有结果修改 `resultType` 时返回 `400.VALIDATION_FAILED`，定位到对应 `results[index].resultType`；PUT 携带非 null `effectKey` 时同样返回该错误并定位到 `effectKey`。

## 10. 页面外部行为

1. “技能管理”列表增加“效果与结果”操作，不新增主导航或独立页面。
2. 点击后打开“效果与结果 - {技能名称}”弹窗，展示效果名称、稳定标识、结果数量、排序、更新时间和操作。
3. 新建和编辑效果时一次维护效果资料及完整结果列表；效果至少有一个结果才能保存。
4. 结果编辑器先选择中文结果种类，再只显示该种类需要的字段。编辑已有结果时稳定标识和结果种类只读。
5. 公式、伤害类型、属性、受影响技能和状态都使用现有目录选择，不让用户填写大块配置、数据库键拼接或 JSON。
6. 停用引用在已有结果中显示“已停用”并允许原样保留；新建结果不提供停用选项。
7. 数值规则使用“数值公式、固定倍率、固定最小值、固定最大值”四个中文字段。冷却变化明确提示减少或增加量按毫秒解释。
8. 结果列表按排序和稳定标识展示，并提供新增、查看、编辑和删除；结果删除先在本地草稿中生效，保存整个效果后才写后端。
9. 所有弹窗使用现有组件库默认样式，允许点击遮罩或按 Esc 关闭；关闭时直接丢弃未保存的效果草稿。
10. 保存成功关闭当前效果编辑弹窗并刷新效果列表；保存失败保留完整草稿和字段错误。
11. 页面不显示阶段说明、教学段落、后续能力占位或“暂不支持”字段；空列表只显示“暂无效果”。

## 11. 实施顺序

1. Cursor 对本共享契约和两份模块设计完成只读评审，所有问题由驱动模型关闭。
2. 项目负责人审核并确认阶段 7.2 方案；在此之前不得开发。

4. 后端建立效果与结果分表、约束、迁移、接口、引用保护和自动检查。
5. 在项目负责人指定的真实开发数据库执行迁移，重启后端，完成真实接口和重启回读验收。
6. 前端接入冻结接口，完成技能页入口、效果聚合编辑和自动检查。
7. 启动真实前后端，完成跨端浏览器验收并形成独立验收记录。

## 12. 跨端验收案例

以下记录只通过页面手工建立，不写种子：

### 12.1 单次伤害

为伊泽瑞尔 Q 建立效果 `on_hit_results / 命中结果`，其中一个结果：

1. `resultType = DAMAGE`
2. `target = TARGET`
3. 引用物理伤害类型和同技能 `damage` 公式
4. 固定倍率 1，固定最小值和最大值为空

保存、刷新页面和重启后端后，效果、结果、公式键、伤害类型键和顺序保持一致。

### 12.2 多个基础结果

为测试技能建立一个效果，依次保存：

1. 对目标造成魔法伤害。
2. 对施法者直接治疗。
3. 对施法者恢复法力。
4. 减少一个明确技能的冷却。

四个结果分别引用自己的公式，刷新后顺序按 `sortOrder/resultKey` 稳定。页面和接口不声明这些结果在施放、命中还是结束时发生。

### 12.3 普通护盾、属性和状态

1. 普通护盾只保存数值，不出现持续、刷新、衰减或吸收顺序。
2. 属性变化引用移动速度属性并选择“减少”，不保存持续时间。
3. 状态操作引用 `stun` 并选择“施加”，不出现状态分类、层数或生命周期。

### 12.4 更新和删除保护

1. 全量编辑效果时，保留一个结果、增加一个结果、删除一个结果必须同一事务成功。
2. 把已有结果种类从伤害改成治疗必须失败，原结构不变。
3. 删除被结果引用的公式、伤害类型、状态或其他技能必须返回对应 409，结果不受损。
4. 删除效果后只清理其结果和明细，被引用目录记录继续存在。

### 12.5 明确无法配置

以下内容在阶段 7.2 必须没有字段、选项或接口：

1. 斩杀阈值和反伤来源。
2. 条件、事件、触发次数和前序结果。
3. 延迟、多段、周期、引导、蓄力和重施。
4. 持续属性变化、状态操作和普通护盾的生命周期。
5. 暴击、吸血、命中联动和法术护盾阻挡粒度。
6. 公式执行、计算预览、发布或 Wasm。

## 13. 后续阶段依赖标记

## 14. 停止门禁

出现以下任一情况必须停止并回到方案确认：

1. 实施需要恢复旧 Ability、Provider、combat-data 效果结构或双写旧模型。
2. 结果关系必须保存为数组、JSONB、自由脚本、自由结果类型或通用多态关系才能继续。
3. 需要新增过程、效果与状态生命周期、条件、事件、暴击、吸血、前序结果、斩杀或反伤字段。
4. 需要让结果跨技能引用公式、复制公式表达式或保存另一份等级 Map。
5. 需要增加状态分类、资源分类、效果类型管理页或事件类型管理页。
6. 阶段 7.1 尚未验收，或目标数据库缺少已冻结的技能、公式、伤害类型、属性或状态前置结构。
7. 真实数据库结构与确认基线不一致，迁移无法安全停止或回滚。
8. 后端完整测试、前端完整验证或真实跨端验收无法完成，且不能定点确认原因。

触发任一门禁时暂停，不用兼容层、占位字段或扩大阶段范围绕过。
