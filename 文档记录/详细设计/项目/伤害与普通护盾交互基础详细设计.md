## 4. 伤害结果契约

`resultType = DAMAGE` 继续需要原有数值规则，`detail` 精确扩展为：

```json
{
  "damageTypeKey": "physical",
  "deliveryKind": "SKILL",
  "originKind": "DIRECT",
  "critical": {
    "mode": "SOURCE_CRIT_CHANCE",
    "multiplierFormulaKey": null
  },
  "vampRules": [
    {
      "vampType": "LIFE_STEAL",
      "basisOutputKind": "POST_DEFENSE_DAMAGE",
      "efficiencyFormulaKey": "full_efficiency"
    }
  ]
}
```

### 4.1 伤害来源

1. `deliveryKind` 只允许 `SKILL / BASIC_ATTACK`。
2. `originKind` 只允许 `DIRECT / REFLECTED`。
3. 装备主动、被动和消耗能力仍作为技能维护，因此它们产生的技能伤害使用 `SKILL`。
4. `REFLECTED` 只标记反伤结果性质，不自动建立事件、动作目标或保护关系。

### 4.2 暴击策略

| `mode` | `multiplierFormulaKey` |
| --- | --- |
| `DISALLOWED` | 必须为 null。 |
| `SOURCE_CRIT_CHANCE` | 可空；非空时引用当前技能公式。 |
| `FORCED` | 可空；非空时引用当前技能公式。 |

不增加第四种暴击模式、采样次数或等级配置。阶段 7.6.1 只保存并校验，不执行概率或倍率公式。

### 4.3 吸血规则

1. `vampType` 固定为 `LIFE_STEAL / OMNIVAMP / PHYSICAL_VAMP / SPELL_VAMP`。
2. 同一伤害结果中相同 `vampType` 最多一条，数组最多四条；空数组表示没有吸血规则。
3. `basisOutputKind` 只允许 `POST_DEFENSE_DAMAGE / ACTUAL_HP_LOSS`。它们在本阶段只是吸血基准枚举，不表示丰富前序输出已经开放。
4. `efficiencyFormulaKey` 必填并引用当前技能公式。
5. 一次已解析伤害实例对每条规则形成一次未来吸血机会；伤害实例次数继续由阶段 7.3 过程和效果挂接表达，不接受 `vampCount`、等级 Map 或自由说明。

### 4.4 既有数据显式化

阶段 7.6.1 迁移完成后，每个既有伤害结果完整回读为：

1. `deliveryKind = SKILL`。
2. `originKind = DIRECT`。
3. `critical.mode = DISALLOWED` 且倍率公式为 null。
4. `vampRules = []`。

迁移只补结构，不创建业务样本；完成后数据库列不保留静默默认值。新建和更新请求必须提交完整新形状。

## 5. 普通护盾结果契约

`resultType = NORMAL_SHIELD` 继续需要原有数值规则，`detail` 从空对象改为：

```json
{
  "absorbedDamageTypeKey": null,
  "decayMode": "NONE"
}
```

1. `absorbedDamageTypeKey` 可为 null；null 表示全部伤害，非空引用同一游戏伤害类型。
2. `decayMode` 只允许 `NONE / LINEAR_TO_ZERO`。
3. 普通护盾必须属于有生命周期效果，并使用 `PERSISTENT` 结果行为；数值规则表示初始护盾量。`decayMode = NONE` 时继续允许阶段 7.4 已冻结的共享值或每层值语义。
4. `LINEAR_TO_ZERO` 要求生命周期 `durationFormulaKey` 非空、`expiryMode = ALL_AT_ONCE`、结果 `stackValueMode = SHARED`；不得搭配 `PER_STACK`、逐层到期或每层独立到期。
5. 未来护盾耗尽意味着所属生命周期提前结束，但本阶段不扣减护盾、不推进时间，也不产生破裂事件。
6. 既有普通护盾迁移为 `absorbedDamageTypeKey = null / decayMode = NONE`，重复执行不得重复插入。
7. 迁移前若发现既有普通护盾没有生命周期、不是 `PERSISTENT` 或缺少阶段 7.4 要求的值合并字段，必须列出完整结果键并整体停止；迁移不得自动创建生命周期、改结果时点或猜测层数值语义。负责人先通过阶段 7.4 效果接口修正数据并完成回读，再重新执行迁移。

## 6. 既有伤害事件筛选

阶段 7.5 的 `DAMAGE_DEALT / DAMAGE_TAKEN` 身份与目标能力不变，只把 `eventSource.detail` 从空对象扩展为：

```json
{
  "damageTypeKey": null,
  "deliveryKind": "ANY",
  "originKind": "ANY"
}
```

1. `damageTypeKey` 可空；非空引用同一游戏伤害类型。
2. `deliveryKind` 只允许 `ANY / SKILL / BASIC_ATTACK`。
3. `originKind` 只允许 `ANY / DIRECT / REFLECTED`。
4. 已有规则迁移为 null/ANY/ANY 并完整回读，不删除、不复制规则。
5. 其他十五种事件的 detail 和能力不变；`DAMAGE_PENDING` 尚不可选择。
6. 本阶段不增加 `event_value_key`。`DAMAGE_DEALT / DAMAGE_TAKEN` 继续只暴露阶段 7.5 已冻结的值能力，不提前提供伤害结算值。

## 7. 反伤基础保护

阶段 7.6.1 尚无 `DAMAGE_PENDING`，因此执行包含 `originKind = REFLECTED` 伤害结果的效果时：

1. 规则事件必须是 `DAMAGE_TAKEN`。
2. `EXECUTE_EFFECT.targetContext` 必须是 `EVENT_SOURCE`。
3. 规则的 `eventSource.detail.originKind` 必须是 `DIRECT`，或者该规则拥有合法每目标冷却。
4. 从其他事件执行、目标不是事件来源对象，或 `ANY / REFLECTED` 且没有每目标冷却时，返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED`，原因 `REFLECT_LOOP_UNGUARDED`。
5. 把既有效果的伤害改为 `REFLECTED` 时，必须用候选快照重新检查所有引用规则；若产生新的无保护环，效果更新整体失败并保持旧聚合。
6. 阶段 7.6.2 开放 `DAMAGE_PENDING` 后才可把它加入合法反伤来源事件；本阶段不得为未来事件预留隐藏选项。

## 8. 动作可达公式增量

在阶段 7.5 既有封闭收集表上增加：

1. `EXECUTE_EFFECT` 到达伤害结果时，除原数值规则外，还收集非空暴击倍率公式和全部吸血效率公式。
2. `START_PROCESS` 通过阶段 7.3 直接效果挂接到达伤害结果时，按同一规则收集。
3. 创建或更新触发规则时，从上述公式节点读取的 `RUNTIME_INPUT` 参数必须与动作绑定集合完全相等；缺失和多余项继续返回 `400.INVALID_RUNTIME_INPUT_BINDING`，字段定位规则动作或绑定。
4. 暴击和吸血公式不得跨技能；事件筛选本身不引用公式。
5. `PRIOR_ACTION_RESULT.outputKind` 本阶段仍只允许 `CONFIGURED_VALUE`。

效果 PUT 选择、替换或移除暴击/吸血公式时，必须用阶段 7.5 同一个可达参数分析器检查直接执行该效果、或经过程直接挂接到达该效果的既有规则：

1. 如果候选效果使某条既有规则的可达参数集合发生变化，即使新集合只是增加或减少一个参数，效果 PUT 都返回 `409.SKILL_EFFECT_IN_USE`，原因 `TRIGGER_RULE_RUNTIME_INPUT_IN_USE`，不得在效果接口返回指向不存在规则请求数组的 400。
2. 错误字段定位本次效果请求实际改变的 `results[i].detail.critical.multiplierFormulaKey` 或 `results[i].detail.vampRules[j].efficiencyFormulaKey`；详情按 `ruleKey/actionKey/parameterKey` 稳定排序列出受影响规则。
3. 负责人先修改或删除依赖规则，使其不再直接或经过程引用该效果，再更新效果，最后按新可达参数集合恢复规则和绑定。不得允许“预先多绑参数”或新增跨聚合批量接口绕过顺序。
4. 候选效果没有改变受影响规则的可达参数集合时可以继续更新；若另行形成无保护循环，仍优先返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED`。
5. 后端必须复用阶段 7.5 分析器和候选图，不在效果服务复制第二套规则算法。

## 10. 稳定错误

| HTTP | `code` | 本阶段场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | 新枚举无法绑定，或伤害/普通护盾 detail 携带其他种类字段。 |
| 400 | `400.VALIDATION_FAILED` | 暴击、吸血、普通护盾生命周期或衰减组合错误。 |
| 400 | `400.INVALID_SKILL_EFFECT_REFERENCE` | 暴击/吸血公式或伤害类型不存在、跨游戏或跨技能。 |
| 400 | `400.INVALID_SKILL_TRIGGER_RULE_REFERENCE` | 伤害事件筛选引用无效或用在其他事件。 |
| 400 | `400.INVALID_RUNTIME_INPUT_BINDING` | 触发规则 POST/PUT 的可达公式存在缺失、多余或类型不兼容绑定。 |
| 400 | `400.TRIGGER_RULE_CYCLE_UNGUARDED` | 反伤来源、动作目标或保护组合非法，或候选图形成无保护环。 |
| 409 | `409.SKILL_EFFECT_IN_USE` | 效果 PUT 改变暴击/吸血公式后会改变既有规则的可达参数集合；或破坏其他既有规则形状。 |
| 409 | `409.SKILL_FORMULA_IN_USE` | 删除仍被暴击或吸血引用的公式。 |
| 409 | `409.DAMAGE_TYPE_IN_USE` | 删除仍被伤害、普通护盾或伤害事件筛选引用的伤害类型。 |

字段路径使用实际数组下标，例如：

1. `results[0].detail.critical.multiplierFormulaKey`。
2. `results[0].detail.vampRules[1].efficiencyFormulaKey`。
3. `results[1].detail.absorbedDamageTypeKey`。
4. `eventSource.detail.originKind`。

无效原因固定复用或增加 `UNKNOWN_INTERACTION_FORMULA / UNKNOWN_INTERACTION_DAMAGE_TYPE / INVALID_CRITICAL_SHAPE / DUPLICATE_VAMP_TYPE / INVALID_VAMP_BASIS / REFLECT_LOOP_UNGUARDED`。未知数据库约束不得伪装成业务 400。

效果公式变更被既有规则占用时，`409.SKILL_EFFECT_IN_USE` 原因固定为 `TRIGGER_RULE_RUNTIME_INPUT_IN_USE`；详情携带稳定排序的受影响 `ruleKey/actionKey/parameterKey`，前端据此提示先处理依赖规则。

## 15. 停止条件

出现以下任一情况停止并回到方案确认：

1. 阶段 7.5 最终结果、事件、动作、绑定、保护或循环图结构与本设计前提不一致。
2. 实现需要在本阶段增加新结果、新事件、法术护盾范围或丰富前序输出。
3. 实现需要一个覆盖全部阶段 7.6 的总迁移、宽联合或一次性页面改造。
4. 需要 JSONB、数组、自由字符串、通用多态关系或样本专用字段才能保存。
5. 需要执行公式、暴击、吸血、护盾、反伤、事件、结算、预览或 Wasm 才能完成管理功能。
6. 真实数据库、接口、重启回读或浏览器验收不可用且无法定点确认原因。
