## 2. 纯表达式核心与绑定

纯核心落在 `internal/expression`（表达式）。第一阶段的共同校验及生成规范从现有formula包移入该包；生成器更新目标位置，不保留旧入口转发。纯核心只依赖基础库，不导入model、compile、plan、runtime、pipeline或战斗对象。它拥有共同定义校验、有限程序生成、数学原语和数值求值。

`CompileDefinition(definition, allowedBindings)`（编译定义）先执行共同校验，然后将目录输入标识和结果标识转成局部16位索引，生成每个结果一次的有限程序。不把共享结果递归内联；每份定义仍最多64个输入／64个结果／256节点／32层依赖／512预计指令。产物 `Program`（公式程序）使用私有切片，不暴露可写指令、结果表或可变作者树。公开查询返回计数及输入声明的值副本。编译后更改作者树不能改变程序。

程序保留原配置字段定位路径。条件使用只前进的跳转；结果引用按需求值并在本次调用内缓存，未用结果不执行，未选分支不读值。全部结果及分支在编译前已经过结构／引用校验。求值重新建立本次栈和结果缓存，同程序重复运行不复用前次输入或结果；最多32层结果执行，栈及缓存容量有明确上限。

`Evaluate(reader)`（求值）只接收按数值槽编号读取的函数。读取成功值必须有限；缺输入、缺时点、比例除0等由绑定返回明确问题，程序补原表达式位置；原合法0保留。读取每个输入在一次求值内缓存，输入重复引用不会反复观察变化。求值与绑定不写生命、护盾、时钟、冷却或事件。返回数值及本次结果／输入求值次数，便于核对共享结果与读取缓存，不公开可写缓存。

### 2.1 独立输入绑定

绑定落在 `internal/inputbinding`（输入绑定），只依赖纯表达式核心。`Bind(program, catalog)`（建立读值计划）把已校验输入声明精确匹配到可信调用者提供的目录条目；目录使用原属性／技能／参数标识，包含对象、视图及口径授权。重复目录绑定拒绝，未知绑定拒绝，不按名称或前缀猜含义。索引在窄化前检查，目录最多4096项；这是本批绑定目录预算，不承诺读取真实数据库。

建立计划后 `Reader(values)`（本次数值读取）消费按目录条目排列的只读数值视图。属性条目显式提供基础、总值、当前、最大四个带存在标记的数值；参数／上下文提供一个带存在标记的数值。当前帧与事件快照通过独立目录绑定及数值槽区分，不以监听器拥有者替换原事件参与者。

基础、总值、当前、最大直接读取指定字段；加成、已损和两种比例按共同契约计算。需要哪个字段就检查哪个存在性；合法0不回退，缺当前不能从总值补，比例最大值为0失败。未选分支对应的绑定数值不会读取，因此不因无关缺值或除0提前失败。实际战斗状态如何映射成这份只读视图在第三阶段接线，不能把明确构造视图称为已接真实战斗。

绑定计划私有持有输入到目录的索引及口径；不暴露可写切片，编译后修改传入目录不能换绑。每次读取器创建时复制本次显式数值视图，再按需读取，随后修改传入数组也不改变该次视图。

### 2.2 动态错误与数学语义

问题仍使用 `{code,path}`，根为空串，定位规则沿用共同契约。

| 错误码 | 动态含义 |
| --- | --- |
| `FORMULA_MISSING_INPUT` | 选中分支需要的输入值、属性字段或视图缺失。 |
| `FORMULA_NON_FINITE` | 输入、算术中间量或结果非有限。 |
| `FORMULA_DIVISION_BY_ZERO` | 实际执行的除法或比例分母为0。 |
| `FORMULA_INVALID_BOUNDS` | 实际执行的限制运算下界大于上界。 |
| `FORMULA_INVALID_PROGRAM` | 编译后结构不满足已验证的有限栈、编号或跳转约束。 |
| `FORMULA_LIMIT` | 编译累计或执行栈／依赖上限。 |

比较按实际64位浮点值产生0／1，逻辑条件非0为真。四种取整与共同定义一致，中点远离0。舍入放大中间量也检查有限，不能把溢出再除回掩盖。作者显式为有限大数时不承诺任意精度；共同误差界只用于验收比较，不把接近0当成0。

共同数学原语供新程序和现有公式执行器调用。现有表达式解码和战斗取值保持原协议；其原限制运算已有上下界未按顺序校验，本次不借拆分修改该旧语义，新协议在纯程序执行前单独核对下界。这样算术实现只有一个所有者，已保存公式不用改期望值迁就实现。

## 3. 独立执行计划及本次运行所有权

把现有31个 `Compiled*`（编译后结构）及两个无状态方法从compile包移入 `internal/plan`（执行计划）。完整能力引用的解析结构与解析函数同移，编译校验仍属于compile。计划只依赖model、typeset和公式数据，不反向依赖compile、runtime或pipeline。

正式编译器直接生产plan类型；正式执行、过程、门禁和管道直接消费plan类型，不在compile保留别名、转发类型或旧导入外壳。会话接线仍调用 `CompileGeneric`，测试构造工具仍调用真实编译器；这两个入口保留compile依赖。移动保留字段、方法语义、数组顺序、JSON、错误、公开Wasm导出和事件时点，不借拆分改现行伤害结果。

当前驱动条件和重复间隔在运行准入时生成临时公式。为避免向共享计划底层切片写入，运行态持有独立公式表：复制原程序描述列表及索引，复用只读指令；追加程序仅进入该表。所有本次求值和管道读取本次公式表，原计划始终保持原长度、索引和内容。重复运行或失败退出不得把临时程序带入下一次。

## 4. 累计预算及注册入口

现行 `GenericProgramID`（公式程序编号）保持16位表示，可使用0～65535共65536项。所有注册路径统一经过公式表的注册方法，包括命名公式编译／合并、编译上下文、监听修正和运行驱动；先检查总量再生成短编号，不存在旁路cast／append。

冻结默认上限：最多65536程序、每程序最多512指令、累计262144指令、公式表计费内存最多32MiB。计费包含程序／指令结构的目标平台尺寸、程序标识及指令读值字符串的字节数；新纯产物另计全部保留的表达式定位字符串、输入声明／绑定字符串、结果表与读槽内容。重复共用字符串仍保守计入，不宣称它等于实际进程堆。新纯程序会话表使用同一累计预算，读槽累计最多262144、结果累计最多65536；目录及局部索引另按绑定上限检查。

上限是本阶段有限配置，不扩大256MiB宿主内存；测试记录原生尺寸、边界构造及最终Wasm包体／内存。累计检测使用防溢出的剩余额度比较，注册失败不写程序、索引、累计计数或已有编号。相同键若已有同一已编译程序可复用；不能用同名新内容覆盖旧内容。注册返回编号及显式成功状态，全部调用点以成功状态设置存在标记；失败后不得继续索引编号0、折叠、求值或消费。公式注册错误保留原字段路径，现行编译使用原错误容器并使整个编译失败，不返回可运行会话。

现行表达式展开也在有限发射预算内停止，不能先生成指数膨胀的大切片再检查注册数量。新纯程序的共享结果编译一次，不用展开方式生成程序。新表的累计程序／结果／指令／读槽以及32MiB计费预算独立预检，全项通过才提交注册。
