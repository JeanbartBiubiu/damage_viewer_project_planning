## 1. 本次需要确认的决定

1. 生命周期从属于阶段 7.2 的“技能效果”，效果的 `effectKey` 同时是生命周期定义身份。状态目录仍只保存游戏级状态本体，不增加分类、持续时间、层数、公式或技能反向引用。
2. 一个效果可以没有生命周期，也可以恰好拥有一份生命周期。没有生命周期时继续表示一次性结果组；有生命周期时，效果内全部结果必须声明自己位于哪个固定生命周期时点。
3. 生命周期统一承载持续属性变化、普通护盾、周期结果和状态施加。持续数值结果不需要建立伪状态，也不为四类业务另建四套时间结构。
4. 生命周期固定保存持续时间、最大层数、每次施加层数、实例范围、重复施加、到期、周期和数值读取语义；所有可调数值继续引用同一技能公式，不复制等级 Map 或某次运行值。
5. 生命周期结果时点固定为施加时、持续生效、达到满层、每次周期、自然结束和提前移除。它们只组织同一效果内已有结果，不提供自由事件名称，也不建立任意效果之间的触发图。
6. 阶段 7.4 在阶段 7.2 七种结果之外增加第八种固定结果“生命周期操作” `LIFECYCLE_OPERATION`，用于对同一技能下另一个生命周期效果执行增加、减少、覆盖、刷新、消耗或移除。
7. 生命周期始终以 `gameId + skillKey + effectKey` 隔离定义，再按技能自身、来源对象、承受对象或来源与承受对象组合保存未来实例；不同技能、不同效果不会因名称或状态标识相同而自动合并。
8. 重复施加时，层数处理和持续时间处理是两个独立维度；整体到期、逐层到期、每层独立到期和仅显式移除也是明确选项，不使用一个含糊的“刷新方式”字段代替。
9. 生命周期数值结果明确区分“施加时留存数值”和“到固定时点重新读取数值”。阶段 7.4 只保存读取语义，不执行公式，也不向公式提供当前层数、实际周期次数或前序结果。
10. 普通护盾的持续、重复施加和到期属于本阶段；护盾实际吸收伤害、按伤害消耗数值以及护盾破裂后的战斗联动不属于本阶段。
11. 状态施加可以成为持续生效结果，生命周期结束时该次施加自然失效；状态净化、免疫、法术护盾阻止和跨来源状态选择不在本阶段执行。
12. 阶段 7.2 的效果五个接口和全量聚合更新方式保持不变，只扩展效果摘要、效果详情和结果联合类型，不新增生命周期独立管理接口。
13. 阶段 7.3 的过程仍只在固定过程时点挂接完整效果。生命周期不反向引用过程，不修改过程步骤、内部状态或效果挂接契约。
14. 本阶段只保存、校验、回读和保护引用，不执行计时、周期、叠层、状态、属性、护盾、事件、计算预览、发布或 Wasm。

## 2. 范围与非目标

本阶段交付：

1. 效果聚合内可选生命周期的结构化新增、修改、移除和完整回读。
2. 持续时间、最大层数、每次施加层数、实例范围、重复施加和到期规则。
3. 同一生命周期内施加、持续、满层、周期、自然结束和提前移除六个固定结果时点。
4. 持续属性变化、普通护盾、周期结果和状态施加的合法形状。
5. 数值施加时留存或在固定时点重新读取的语义。
6. 生命周期操作结果对同技能另一个生命周期效果的强类型引用和删除保护。
7. 现有效果聚合事务、公式引用、管理日志、前后端自动检查，以及开发获批后的真实数据库、接口和浏览器验收。

本阶段不包含：

1. 生命周期计时、周期执行、属性持续生效、护盾吸收、状态施加或移除的实际运行。
2. 对阶段 7.3 过程步骤、过程时点、冷却、资源扣除、内部状态或效果挂接的修改。
3. 施放、攻击、命中、造成伤害、受到伤害、生命阈值、击杀、离开区域、切换模式等外部事件。
4. 任意效果之间的触发关系、条件树、事件过滤、前序结果供值、每目标冷却、最大触发次数或循环保护。
5. 净化、免疫、法术护盾阻止、控制中断、状态优先级、互斥或覆盖其他来源状态的实际处理。
6. 暴击、吸血、命中联动、攻击联动、反伤、斩杀、伤害修正、护盾结算或特殊阻挡。
7. 当前层数、剩余时间、周期序号、提前移除原因等运行时值向技能公式的实际供值。
8. 计算预览、公式执行、发布、计算输入组装或 Wasm。
9. 状态分类、效果类型管理页、生命周期类型管理页或事件类型管理页。
10. 角色与技能、装备与技能挂载关系。
11. 旧 Ability、Provider、combat-data 生命周期结构的读取、迁移、兼容或双写。

## 3. 数据关系与责任方向

```text
游戏
└─ 技能
   ├─ 技能公式 ───────────────────────────────┐
   ├─ 技能过程 ──效果挂接──────────────────┐  │
   └─ 技能效果                            │  │
      ├─ 可选生命周期                     │  │
      │  ├─ 持续 / 层数 / 范围 / 刷新 / 到期 ┘  │
      │  └─ 周期间隔 ──────────────────────────┘
      └─ 技能效果结果
         ├─ 可选生命周期行为 → 固定生命周期时点
         ├─ 原七种基础结果
         └─ 生命周期操作 → 同技能另一个有生命周期的效果

游戏状态目录 ← 状态施加结果
```

责任方向固定为：

1. 技能拥有效果，效果拥有生命周期和结果；生命周期不成为游戏级目录。
2. 效果生命周期主动引用同一技能公式；公式不反向保存生命周期键。
3. 结果生命周期行为只解释该结果在所属效果生命周期中的位置，不拥有独立身份或独立接口。
4. 生命周期操作结果主动引用同一技能另一个有生命周期的效果；目标效果不反向保存操作结果。
5. 阶段 7.3 过程主动引用效果；效果和生命周期都不反向引用过程。
6. 阶段 7.5 如需把外部事件、条件或另一个效果接到生命周期时点，必须新增明确关系，不得把自由条件文本写入本阶段表。

## 5. 生命周期公共契约

### 5.1 字段

| 字段 | 规则 |
| --- | --- |
| `durationFormulaKey` | 可为 null；非空时引用同一技能公式，未来结果按毫秒解释并应大于 0；null 表示没有自然到期，只能显式移除。 |
| `maxStacksFormulaKey` | 必填；引用同一技能公式；未来结果应为正整数。 |
| `applicationStacksFormulaKey` | 必填；引用同一技能公式；未来结果应为正整数，表示每次施加请求增加或覆盖的层数。 |
| `instanceScope` | 必填；只允许第 5.2 节四种固定值；生命周期存在期间不可修改。 |
| `reapplicationStackMode` | 必填；只允许第 5.3 节三种固定值。 |
| `reapplicationDurationMode` | 有自然到期时必填；没有自然到期时必须为 null。 |
| `expiryMode` | 必填；只允许第 5.5 节四种固定值，并与持续时间及重复施加规则匹配。 |
| `periodicIntervalFormulaKey` | 所属效果存在 `PERIODIC` 结果时必填，否则必须为 null；引用同一技能公式，未来结果按毫秒解释并应大于 0。 |
| `firstPeriodicExecution` | 存在 `PERIODIC` 结果时必填，否则必须为 null；`IMMEDIATE` 表示立即，`AFTER_INTERVAL` 表示等待一个间隔。 |

阶段 7.4 不执行公式，因此后端只验证同技能引用和字段形状，不静态猜测公式最终是不是正整数或正毫秒。公式删除保护必须覆盖上述四个公式引用。

### 5.2 实例范围

| 值 | 中文含义 |
| --- | --- |
| `SKILL` | 当前技能效果只维护一份实例，不按来源对象或承受对象拆分。 |
| `SOURCE` | 按来源对象分别维护实例。 |
| `TARGET` | 按承受对象分别维护实例。 |
| `SOURCE_TARGET` | 按来源对象与承受对象组合分别维护实例。 |

`gameId + skillKey + effectKey` 始终是定义隔离维度，`instanceScope` 只补充未来运行时实例维度。相同 `statusKey`、相同名称或相同公式不会让不同效果自动共享层数和持续时间。

### 5.3 重复施加时的层数处理

| 值 | 中文含义 |
| --- | --- |
| `KEEP` | 保留当前层数，只处理持续时间和持续数值重复施加规则。 |
| `INCREASE` | 当前层数增加本次 `applicationStacksFormulaKey` 的结果，未来执行时不超过最大层数。 |
| `REPLACE` | 当前层数覆盖为本次 `applicationStacksFormulaKey` 的结果，未来执行时不超过最大层数。 |

达到满层事件只在层数从小于最大层数变为等于最大层数时产生一次；已经满层后的重复施加不会重复产生满层事件。

### 5.4 重复施加时的持续时间处理

| 值 | 中文含义 |
| --- | --- |
| `REFRESH_ALL` | 重置整个实例的持续时间；已有层共同使用刷新后的时间。 |
| `KEEP_REMAINING` | 保留当前剩余时间，不因重复施加改变。 |
| `INDEPENDENT` | 每次新增的层按本次施加时刻独立计时。 |

显式 `REFRESH` 生命周期操作会刷新目标实例全部仍有效层的时间，不改变层数；没有自然到期的生命周期不得作为 `REFRESH` 操作的目标。

### 5.5 到期方式

| 值 | 中文含义 |
| --- | --- |
| `ALL_AT_ONCE` | 到期时一次移除全部层。 |
| `ONE_BY_ONE` | 共用计时到点后移除一层；仍有层时重新开始一段完整持续时间。 |
| `INDEPENDENT` | 每层按各自施加时刻独立到期。 |
| `EXPLICIT_ONLY` | 没有自然到期，只能通过生命周期操作或后续外部事件移除。 |

组合约束：

1. `durationFormulaKey = null` 时，`expiryMode` 必须为 `EXPLICIT_ONLY`，`reapplicationDurationMode` 必须为 null，且不得存在 `NATURAL_END` 结果。
2. `durationFormulaKey != null` 时，`expiryMode` 不得为 `EXPLICIT_ONLY`，`reapplicationDurationMode` 必填。
3. `reapplicationDurationMode = INDEPENDENT` 与 `expiryMode = INDEPENDENT` 必须同时出现。
4. `expiryMode = ONE_BY_ONE` 只能搭配 `REFRESH_ALL` 或 `KEEP_REMAINING`。
5. 自然移除最后一层时产生一次自然结束；自然移除部分层而实例仍存在时不产生自然结束。

### 5.6 周期

1. 同一效果内所有 `PERIODIC` 结果共享 `periodicIntervalFormulaKey` 和 `firstPeriodicExecution`；需要不同间隔时拆成不同效果。
2. `firstPeriodicExecution = IMMEDIATE` 表示生命周期实例创建后拥有一个周期时点；`AFTER_INTERVAL` 表示等待一个完整间隔。
3. 提前移除后不再产生尚未发生的周期时点。
4. 周期时点只执行本效果内标记为 `PERIODIC` 的结果，不重新执行整个效果，也不重新施加生命周期。

## 6. 结果生命周期行为

### 6.1 固定时点

| `moment` | 中文含义 |
| --- | --- |
| `APPLICATION` | 每次生命周期施加被接受时处理一次。 |
| `PERSISTENT` | 在生命周期存在期间持续生效。 |
| `FULL_STACKS` | 层数首次从未满变为满层时处理一次。 |
| `PERIODIC` | 每个周期时点处理。 |
| `NATURAL_END` | 最后一层自然到期、实例结束时处理一次。 |
| `EARLY_REMOVE` | 实例在自然到期前因减少、覆盖为零、消耗或移除而结束时处理一次。 |

同一时点内按 `sortOrder ASC, resultKey ASC` 保存确定顺序。跨时点的运行顺序、外部事件接线和前序结果供值继续由后续阶段冻结，本阶段不执行。

### 6.2 数值读取

| `valueReadMode` | 中文含义 |
| --- | --- |
| `APPLICATION_SNAPSHOT` | 每次施加时读取结果数值并留存；后续周期、满层或结束使用已留存值。 |
| `MOMENT_EVALUATION` | 到结果所属固定时点时重新读取结果数值；周期结果每次周期分别读取。 |

规则：

1. 有 `valueRule` 的结果在生命周期效果中必须选择读取方式。
2. 没有 `valueRule` 的结果，包括无强度状态操作和冷却重置，`valueReadMode` 必须为 null。普通减速施加的读取方式以[系统精简实施说明第四单元](系统精简实施说明.md#第四单元状态身份与普通减速强度)为唯一增量定义。
3. `APPLICATION` 和 `PERSISTENT` 数值结果只允许 `APPLICATION_SNAPSHOT`。
4. `FULL_STACKS`、`PERIODIC`、`NATURAL_END`、`EARLY_REMOVE` 数值结果可以选择两种读取方式。
5. 本阶段不保存实际快照值，也不提供当前层数、周期次数、提前移除原因或前序结果供值。

### 6.3 持续数值的层数和值合并

`PERSISTENT` 只允许：

1. `NORMAL_SHIELD`。
2. `ATTRIBUTE_CHANGE`。
3. `STATUS_OPERATION + APPLY`。

持续数值结果，即普通护盾和属性变化，还必须声明：

| 字段 | 值与含义 |
| --- | --- |
| `stackValueMode` | `SHARED` 表示整个生命周期实例共享一个数值；`PER_STACK` 表示公式数值按每个有效层分别贡献。 |
| `reapplicationValueMode` | 仅 `SHARED` 必填；`KEEP` 保留现值，`REPLACE` 使用本次施加值覆盖，`ADD` 把本次施加值加入现值。 |

约束：

1. `PER_STACK` 时 `reapplicationValueMode` 必须为 null；每个新增层按自身施加时刻留存数值。
2. `ATTRIBUTE_CHANGE + SET` 只允许 `SHARED`，并且重复施加值只允许 `KEEP` 或 `REPLACE`。
3. 无强度 `STATUS_OPERATION + APPLY` 的 `stackValueMode` 和 `reapplicationValueMode` 都必须为 null；普通减速施加按第四单元选择共享强度与覆盖。状态层数仍由效果生命周期统一维护。
4. `STATUS_OPERATION + REMOVE`、其他基础结果和 `LIFECYCLE_OPERATION` 不得使用 `PERSISTENT`。
5. 生命周期自然结束或提前移除时，`PERSISTENT` 结果的持续贡献随该实例结束；不需要额外保存一个状态移除或反向属性结果。
6. 普通护盾被伤害消耗数值的实际规则留到阶段 7.6；本阶段只保存重复施加合并和生命周期结束。

### 6.4 周期执行次数

`moment = PERIODIC` 时 `periodicExecutionMode` 必填：

| 值 | 中文含义 |
| --- | --- |
| `ONCE_PER_INSTANCE` | 每个周期时点执行一次，不随当前层数重复。 |
| `ONCE_PER_ACTIVE_STACK` | 每个周期时点按当时有效层数分别执行。 |

其他时点的 `periodicExecutionMode` 必须为 null。实际执行次数、循环上限、暴击次数、吸血次数和命中联动次数不在本阶段执行。

## 7. 生命周期操作结果

### 7.1 结果形状

`resultType = LIFECYCLE_OPERATION`，`detail` 为：

```json
{
  "targetEffectKey": "focus_mark",
  "operation": "CONSUME"
}
```

`targetEffectKey` 必须引用同一技能另一个存在生命周期的效果；不得引用所属效果自身，不得跨技能或跨游戏。

### 7.2 六种操作

| `operation` | 中文含义 | `valueRule` |
| --- | --- | --- |
| `INCREASE` | 增加目标生命周期层数 | 必填，未来结果按非负整数解释 |
| `DECREASE` | 减少目标生命周期层数 | 必填，未来结果按非负整数解释 |
| `SET` | 覆盖目标生命周期层数 | 必填，未来结果按非负整数解释 |
| `REFRESH` | 刷新目标生命周期全部有效层的持续时间 | 必须为 null |
| `CONSUME` | 按业务消耗语义减少目标生命周期层数 | 必填，未来结果按非负整数解释 |
| `REMOVE` | 直接移除目标生命周期整个实例 | 必须为 null |

未来执行语义固定为：

1. 增加和覆盖后的层数不超过目标生命周期最大层数；从未满变为满层时产生满层时点。
2. 减少和消耗后的层数不小于 0；在自然到期前降到 0 时产生提前移除时点。
3. 覆盖为 0 和直接移除都结束整个实例并产生提前移除时点。
4. 刷新不改变层数；目标没有自然到期时，保存操作方效果返回 `400.INVALID_SKILL_EFFECT_REFERENCE`，字段 `results[index].detail.targetEffectKey`、原因 `TARGET_EFFECT_HAS_NO_DURATION`。
5. 操作只改变目标生命周期实例，不从施加时重新执行目标效果，也不创建任意效果触发关系。
6. `target` 继续使用阶段 7.2 的施法者或当前目标；目标生命周期再按自身 `instanceScope` 定位未来实例。
7. `CONSUME` 与 `DECREASE` 在阶段 7.4 的保存形状和层数变化方向相同；“业务消耗”和“普通减层”的运行差异留到后续执行设计，本阶段不自行解释。

阶段 7.4 仍不执行这些操作，只保存和校验结构。

## 8. 聚合、引用与修改规则

1. 效果及其生命周期、结果、结果生命周期行为、数值规则和类型明细仍使用一次 POST 或一次 PUT 作为完整聚合。
2. PUT 中 `lifecycle = null` 表示移除当前效果生命周期；当前效果被其他生命周期操作结果引用时必须失败，不能留下悬空操作。
3. PUT 中有生命周期时，结果数组中的全部结果都必须带完整 `lifecycleBehavior`；缺少一项即整个事务失败。
4. 生命周期存在期间 `instanceScope` 不可修改。PUT 新旧值不同时返回 `400.VALIDATION_FAILED`，字段 `lifecycle.instanceScope`、原因 `IMMUTABLE`。需要改变实例隔离语义时，负责人先提交一次 `lifecycle = null`，再重新建立；若存在外部引用则先处理引用。
5. 结果 `resultType` 继续不可修改；新增 `LIFECYCLE_OPERATION` 不放宽阶段 7.2 规则。
6. 删除被生命周期操作引用的目标效果，或移除其生命周期，返回稳定冲突；所属技能整体删除时由后端按明确顺序先清理生命周期操作引用。
7. 目标生命周期被 `REFRESH` 操作引用时，不得把 `durationFormulaKey` 清空或把到期方式改为 `EXPLICIT_ONLY`。目标 PUT 返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`，字段 `lifecycle.durationFormulaKey`、原因 `REFRESH_OPERATION_IN_USE`；不得静默修改操作方。
8. 删除被生命周期字段引用的公式继续返回 `409.SKILL_FORMULA_IN_USE`。
9. 状态停用后允许旧效果完整回读并可修改非引用字段；新增或改为停用状态引用仍沿用阶段 7.2 冲突语义。
10. 效果详情不得返回数据库内部行、空的其他类型明细或自由扩展字段。

## 9. HTTP 契约

沿用阶段 7.2 的五个接口：

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/effects
PUT    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
```

扩展规则：

1. 列表摘要返回 `lifecycleEnabled`。
2. 详情、创建和更新增加 `lifecycle`；每个结果增加 `lifecycleBehavior`。
3. 结果联合类型增加 `LIFECYCLE_OPERATION`。
4. POST、PUT 任一生命周期字段、公式引用、目标效果引用或组合规则失败时，效果聚合不得部分写入。
5. 不新增生命周期单独 GET、POST、PUT、DELETE 或排序接口。

## 10. 稳定错误

沿用现有 `details.fieldIssues`，新增或扩展：

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | 生命周期枚举、结果种类或联合类型字段无法绑定，或携带不属于当前形状的字段。 |
| 400 | `400.VALIDATION_FAILED` | 生命周期缺字段、组合不合法、结果行为缺失、非法固定时点、值读取或持续值合并形状错误。 |
| 400 | `400.INVALID_SKILL_EFFECT_REFERENCE` | 生命周期公式或目标效果不存在、跨技能、目标没有生命周期、刷新目标没有自然到期或操作引用自身。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.SKILL_NOT_FOUND` | 技能不存在。 |
| 404 | `404.SKILL_EFFECT_NOT_FOUND` | 效果不存在。 |
| 409 | `409.SKILL_EFFECT_LIFECYCLE_IN_USE` | 删除目标效果、移除其生命周期，或把仍被刷新操作引用的目标改为无自然到期。 |
| 409 | `409.SKILL_EFFECT_IN_USE` | 删除仍被阶段 7.3 技能过程挂接引用的效果；同一次删除同时存在两类引用时优先返回本错误。 |
| 409 | `409.SKILL_FORMULA_IN_USE` | 删除仍被生命周期字段或结果数值规则引用的公式。 |

字段路径使用提交数组下标和实际字段，例如：

1. `lifecycle.durationFormulaKey`。
2. `lifecycle.reapplicationDurationMode`。
3. `results[1].lifecycleBehavior.moment`。
4. `results[1].lifecycleBehavior.valueReadMode`。
5. `results[2].detail.targetEffectKey`。
6. `results[2].valueRule.formulaKey`。

`400.INVALID_SKILL_EFFECT_REFERENCE` 的字段问题原因新增 `UNKNOWN_LIFECYCLE_FORMULA`、`UNKNOWN_LIFECYCLE_EFFECT`、`TARGET_EFFECT_HAS_NO_LIFECYCLE`、`TARGET_EFFECT_HAS_NO_DURATION` 和 `SELF_LIFECYCLE_REFERENCE`。同一请求存在多个问题时一次返回全部能确定的问题。

修改已有生命周期的 `instanceScope` 时，`400.VALIDATION_FAILED` 使用原因 `IMMUTABLE`；它与阶段 7.2 已有结果种类不可修改保持同一错误结构。

目标效果因入站刷新操作而不能清空持续时间时，`409.SKILL_EFFECT_LIFECYCLE_IN_USE` 使用字段 `lifecycle.durationFormulaKey`、原因 `REFRESH_OPERATION_IN_USE`；前端不得把它误映射到操作方结果。

## 11. 页面外部行为

1. 继续在技能管理的“效果与结果”弹窗内维护，不新增主导航、独立生命周期页面或自由类型管理页。
2. 效果编辑弹窗增加“生命周期”开关和结构化区域；关闭时隐藏并清空生命周期字段及所有结果行为，存在草稿时必须二次确认。
3. 开启生命周期后，每个结果都显示固定时点；持续数值结果按形状显示层数和值合并字段。
4. 周期结果存在时显示周期间隔、首次周期和每实例或每层执行选择；移除最后一个周期结果时对应字段必须清空。
5. 新增结果种类“生命周期操作”，目标只列出同一技能其他已启用生命周期的效果。目标摘要不包含自然到期明细，因此页面不根据摘要隐藏“刷新”；选择无自然到期目标并提交时由后端返回目标字段错误。
6. 目录加载失败时不能静默当作空目录；保留草稿并允许重试。旧引用不在当前目录时保留只读未知项，提交仍由后端判定。
7. 后端字段错误映射到对应生命周期区或结果子弹窗；无法定位的错误保留通用提示和完整草稿。
8. 页面只展示和编辑配置，不显示倒计时、当前层数、周期动画、计算值、伤害预览或 Wasm 结果。

## 12. 实施顺序

1. 项目负责人确认本共享契约，特别是效果级生命周期、固定时点、第八种结果和删除保护。
2. 阶段 7.3 后端与前端实现完成并进入目标分支；实施前核对实际契约没有偏离已冻结 7.3 设计。
3. 后端先增加关系表、聚合模型、校验、事务和删除保护，并完成自动检查。
4. 后端在开发获批后按受控流程完成真实数据库、真实接口和重启回读验收。
5. 前端基于已验收接口扩展类型、效果表单、结果表单和错误映射，并完成自动检查。
6. 前端在开发获批后完成真实浏览器录入、回读、修改和失败保留验收。
7. 三端验收通过后再更新任务状态；不得以 Cursor `READY` 代替项目负责人开发批准。

## 13. 跨端验收案例

### 13.1 持续属性变化与状态施加

1. 建立有自然持续时间、最大一层、来源与目标组合隔离、重复施加刷新整体的效果。
2. 效果内保存一个 `ATTRIBUTE_CHANGE + DECREASE + PERSISTENT` 结果和一个 `STATUS_OPERATION + APPLY + PERSISTENT` 结果。
3. 创建、查询、修改、重启后回读的生命周期、结果行为和公式引用完全一致。

### 13.2 周期伤害

1. 建立有持续时间、周期间隔、首次等待一个间隔的效果。
2. 周期伤害选择每个实例一次，并选择每次周期重新读取数值。
3. 后端完整回读；页面重新打开时所有选择保持，不执行任何一次伤害或计时。

### 13.3 多层与满层

1. 建立最大层数、每次增加一层、整体刷新、整体到期的效果。
2. 保存持续属性结果和满层伤害结果；满层结果可选择施加快照或满层时重新读取。
3. 再建立一个普通效果，使用生命周期操作增加、消耗或覆盖目标效果层数。
4. 目标效果删除和生命周期移除都因引用返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`。

### 13.4 独立计时

1. 重复持续方式和到期方式同时选择独立。
2. 周期结果选择按有效层分别执行，持续属性选择每层贡献。
3. 任一独立字段缺失或与整体到期混用时，前端先提示，后端仍返回稳定字段错误。

### 13.5 普通护盾

1. 普通护盾作为 `PERSISTENT` 结果保存共享值。
2. 重复施加值分别验证保留、覆盖和相加三种选择可以完整回读。
3. 页面和接口不出现护盾实际吸收、破裂伤害或战斗计算结果。

### 13.6 无自然到期

1. `durationFormulaKey = null`、`expiryMode = EXPLICIT_ONLY`、`reapplicationDurationMode = null` 可以保存。
2. 同时提交自然结束结果必须失败且不产生部分更新。
3. 当前无自然到期效果仍可以保存一个生命周期操作，用于刷新同技能另一个有自然到期的目标效果；只有目标没有自然到期时刷新才返回 `400.INVALID_SKILL_EFFECT_REFERENCE` 和 `TARGET_EFFECT_HAS_NO_DURATION`。
4. 先保存合法刷新操作，再尝试清空目标效果的持续时间；目标 PUT 返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE` 和 `REFRESH_OPERATION_IN_USE`，操作方与目标方回读都保持原值。
5. 生命周期操作移除目标效果的结构可以保存，但不执行移除。

### 13.7 非法组合和事务

1. 无生命周期却带结果行为。
2. 有生命周期但一个结果缺少行为。
3. 状态移除、伤害或生命周期操作被标记为持续生效。
4. 周期结果没有周期间隔，或没有周期结果却保留周期间隔。
5. 生命周期操作跨技能、引用自身或引用无生命周期效果。
6. 任一失败时效果资料、生命周期和全部结果保持更新前状态。

## 14. 后续阶段依赖标记

本节只登记依赖方向，不展开或冻结后续详细设计：

1. 阶段 7.5 可以引用本阶段的效果、结果、固定生命周期时点和生命周期操作，建立外部条件、事件、效果触发关系、计算时传入参数供值、每目标冷却、最大触发次数和循环保护。
2. 外部事件导致的刷新、消耗、移除和提前结束，需要阶段 7.5 把事件接到本阶段已保存的生命周期操作，不回写自由事件字段。
3. 满层伤害或自然结束伤害可以直接放在所属效果的固定时点；满层后移除自身不能通过被禁止的自引用生命周期操作表达，需要阶段 7.5 的明确接线。
4. 阶段 7.6 在前序结果和事件关系明确后，设计护盾实际吸收、暴击、吸血、命中与攻击联动、法术护盾阻挡、反伤、斩杀和特殊结算。
5. Wasm、计算预览、发布和运行时输入组装继续后置，本阶段不建立占位字段。

## 15. 停止门禁

出现以下任一情况必须停止并回到方案确认：

1. 阶段 7.3 实际实现改变阶段 7.2 效果聚合、结果稳定标识或过程效果挂接契约。
2. 实施需要把生命周期字段写入游戏级状态表，增加状态分类，或让持续数值结果伪装成状态。
3. 实施需要把结果、生命周期规则、目标关系或类型明细保存成数组、JSONB、自由脚本或通用多态关系。
4. 实施需要新增生命周期独立接口、独立页面、自由事件类型或效果类型管理页。
5. 实施需要执行计时、周期、属性、状态、护盾、公式、计算预览、发布或 Wasm。
6. 实施需要提前增加阶段 7.5 的外部条件、事件、触发关系、动态输入供值、每目标冷却或循环保护。
7. 实施需要提前增加阶段 7.6 的暴击、吸血、命中联动、法术护盾阻挡、护盾结算、反伤或斩杀。
8. 目标数据库、Backend 或 Web 的阶段 7.2/7.3 实际契约与设计基线不一致，无法用受控破坏式迁移和明确写入范围收敛。
