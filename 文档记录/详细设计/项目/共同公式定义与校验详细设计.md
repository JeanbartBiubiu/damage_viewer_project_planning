# 共同公式定义与校验详细设计

## 1. 本批交付与切换边界

本批落实[概要方案](../../概要设计/项目/通用计算引擎子系统拆分与公式数据驱动重构方案.md)第8节第一阶段：共同定义及三端一致校验。交付唯一结构规范、可重复生成和漂移检查、后端／Web／Go纯校验入口及同源正反样例。本批不切换现行管理保存、快照或正式计算入口，不迁移实库，不构建替换用Wasm。它是新协议实施前的独立交付，不是新旧协议双读兼容层。

三端代码基线与概要一致；本文件补齐新共同协议第一阶段的详细设计，并已据此实现三端校验。第二阶段的程序、输入绑定与只读执行计划，以及第三阶段的保存、索引事务和实际场景请求，在各自实施前进一步冻结并独立评审。本文件独占本批公式结构、局部语义、错误和样例；后续文档引用它，不另造公式树。实际检查及限制见[第一阶段验收记录](../../测试记录/项目/共同公式定义与三端校验第一阶段验收-2026-10-07.md)。

## 2. 唯一规范与消费方式

结构真源为 `contracts/formula/formula.schema.json`，采用JSON Schema（JSON结构约束规范）。其中 `x-limits` 声明整份公式预算，`x-discriminator` 声明节点判别字段，`x-errors` 声明稳定错误码。定义没有伤害类型名称、抗性名称或固定五段。

共同样例真源为 `contracts/formula/cases.json`。每项包含原始定义、由调用者明确授权的绑定目录、预期首个错误码与字段路径；成功的预期为null。生成器按明确目标生成各模块的结构常量、Web类型及测试资源，记录结构和样例的SHA256摘要。它不复制治理规则、技能或任务映射；生成文件不得手改。生成检查重新计算预期内容并比对，不能只相信文件里自报的摘要。

校验器只依赖结构规范与基础JSON／数值库，不依赖数据库、网络、页面、战斗状态、类型服务或旧表达式翻译。三端都暴露“原始定义＋授权绑定目录→首个问题或成功”的纯入口。返回成功仍不足以进入战斗：后续编译器必须从完整选择闭包及当前游戏目录建立授权绑定，不能信任浏览器提交的授权清单。

## 3. 定义结构

顶层只有必填的 `inputs`（输入声明列表）、`stages`（命名结果列表）、`outputStageKey`（输出结果标识）。不接受null、旧字段或额外字段。

| 字段 | 作用与约束 | 期望效果 |
| --- | --- | --- |
| 输入的 `key` | 本公式内唯一标识 | 表达式只读取已声明槽，不解析业务路径。 |
| 输入的 `binding` | 明确对象身份和取值口径 | 由绑定层与真实目录匹配，缺项不补0。 |
| 结果的 `key` | 本公式内唯一标识，区分大小写 | 引用和输出只认标识。 |
| 结果的 `name` | 1～128字符显示名称 | 改中文名称不改运算。 |
| 结果的 `expression` | 共同数值表达式 | 技能金额和防御倍率使用同一树。 |
| `outputStageKey` | 必须指向本公式声明的结果 | 不按数组末项猜输出。 |

标识为1～128字符，以字母、数字或下划线开头，其余允许字母、数字、下划线、点、冒号、斜杠和连字符。不从标识内容推断计算。列表顺序仅用于展示，依赖可以向前或向后引用；更换身份必须明确修改引用。

### 3.1 输入绑定

`binding.kind`（绑定种类）区分三种严格结构，各自禁止其他种类的字段。

| 种类 | 必填内容 | 边界 |
| --- | --- | --- |
| `attribute`（属性） | `object`、`attributeKey`、`valueKind`、`view` | 属性身份保留目录原标识，不拼接 `source.attr.xxx`。 |
| `parameter`（技能参数） | `skillKey`、`parameterKey` | 参数只能来自使用点明确授权的所属技能，不提供参数默认值。 |
| `context`（上下文数值） | `contextKey` | 使用点显式声明的数值槽；不是任意字符串路径或调用。 |

属性对象允许 `source/target/owner/event_source/event_target`，分别表示实际来源、实际目标、供值器拥有者、原事件来源与原事件目标。`view` 只有 `current_frame`（当前帧只读视图）和 `event_snapshot`（已冻结事件视图）。有无事件、参与者映射及可读时点由后续绑定层决定；纯公式不知道战斗对象。调用者授权目录中的绑定必须逐字段精确匹配，不认属性别名、对象替换或隐式时点。

属性口径如下；本批冻结含义，不声称实际绑定已经接通。

| `valueKind` | 取值口径 |
| --- | --- |
| `BASE` | 明确基础值，合法0保留0。 |
| `BONUS` | 总值减基础值。 |
| `TOTAL` | 已完成当前修正与派生的总值。 |
| `CURRENT` | 明确当前值。 |
| `MAX` | 同一属性槽或显式元数据关联的最大值，不按属性名猜另一属性。 |
| `MISSING` | 最大值减当前值，不偷偷夹取。 |
| `CURRENT_RATIO` | 当前值除最大值。 |
| `MISSING_RATIO` | 已损值除最大值。 |

目录存在但本次缺少某口径，在求值时失败；比例的分母为0也失败。授权清单只允许本使用点合法、同游戏、已启用的目录绑定。第一阶段用明确清单验证身份和权限；真实目录查询、快照闭包及状态读取是后续接线范围。

### 3.2 表达式

| `op`（运算种类） | 唯一允许字段 | 数值语义 |
| --- | --- | --- |
| `const` | `op,value` | value为严格十进制字符串。 |
| `read` | `op,inputKey` | 读取已声明输入槽。 |
| `ref` | `op,stageKey` | 读取本公式命名结果，不跨公式。 |
| `add/sub/mul/div/min/max` | `op,args`，恰好两个操作数 | 顺序保留，除0在实际求值时失败。 |
| `eq/ne/lt/lte/gt/gte` | `op,args`，恰好两个操作数 | 比较结果为数值0或1。 |
| `if` | `op,args`，恰好三项 | 条件非0选择第二项，否则第三项；只执行选中分支。 |
| `clamp` | `op,args`，恰好三项 | 数值、下界、上界；下界大于上界时求值失败。 |
| `floor/ceil/trunc` | `op,args`，恰好一项 | 分别向下、向上、向0取整。 |
| `round` | `op,args,decimals`，一项操作数，位数整数0～12 | 在声明小数位舍入，中点远离0；具体有限浮点执行在第二阶段验证。 |

不支持 `expr/min/max/path` 等旧同义字段。未选分支和未用结果仍必须通过全部结构、引用与预算检查；只有动态读值和算术求值是惰性的。

常量格式为 `-?(0或非零开头整数)(可选小数部分)`，不允许指数、前导加号、空格、前导零、非有限文本或JSON数值。最大512字符，原字符串完整保留。解析为64位浮点时非有限或非零下溢到0均拒绝，合法正负0通过。执行继续使用64位浮点，不承诺任意十进制运算无损；第二阶段的数值对照误差为 `max(1e-9, 1e-12 × max(|预期值|, |实际值|))`。整数和结构比对精确。

## 4. 校验顺序、预算与错误

只报告确定性的首个问题，以方便三端逐项对照；未来服务可以按来源包装，不改变内部代码和字段路径。

1. 严格结构与整份节点预算：按声明顺序遍历，未知对象字段按码点顺序先报，再按规范的必填字段顺序检查全部存在性，最后按属性声明顺序递归字段内容。节点判别字段非法直接定位该字段。字符串格式要求完整匹配，不因各语言的正则结尾差异接受末尾换行。表达式遍历根深度为1，进入第33层前停止；第257个节点直接失败，不先递归整个超限树。
2. 结构全部合法后，按结果及表达式声明顺序检查所有常量范围，再依次检查输入重复、结果重复、输出存在性；混合错误也遵守这一顺序。
3. 输入绑定与授权目录精确匹配；所有表达式引用都必须存在。
4. 对所有声明结果按声明顺序检查依赖环，包括未用结果；回边定位原 `stageKey` 字段。
5. 计算包含树和结果引用的最长依赖深度。结果引用节点本身占1层；共享结果只分析一次，不递归内联复制。超限定位该结果的 `expression`。

每份公式最多64个输入、64个结果、256个表达式节点、32层树／依赖深度、512条预计指令。节点对整个公式累计；预计指令为每普通节点1条、每条件节点3条、每个结果保存1条。未使用声明也计预算。短索引和会话累计上限由第二阶段执行计划设计冻结并验证，第一阶段不宣称已修复现行注册器回绕问题。

| 错误码 | 含义 |
| --- | --- |
| `FORMULA_INVALID_STRUCTURE` | 类型、字段、标识、操作数数量、字面格式或结构长度非法。 |
| `FORMULA_INVALID_DECIMAL` | 格式合法但转换为浮点非有限或非零下溢。 |
| `FORMULA_DUPLICATE_KEY` | 输入或结果标识重复。 |
| `FORMULA_UNKNOWN_INPUT` | 表达式输入未声明。 |
| `FORMULA_UNKNOWN_STAGE` | 输出或结果引用不存在。 |
| `FORMULA_UNKNOWN_BINDING` | 声明绑定不在调用者授权目录中。 |
| `FORMULA_CYCLE` | 结果依赖闭环。 |
| `FORMULA_LIMIT` | 整份节点、树／引用深度或预计指令预算超限。 |

问题结构为 `{code,path}`，path采用JSON Pointer（JSON字段定位路径），根为空串，数组项使用数字，字段中的 `~` 和 `/` 分别转义为 `~0` 和 `~1`。字符串长度和未知字段排序采用Unicode码点，三端不使用各语言不同的默认长度或排序。后续编译／运行接线保留原配置路径并附带来源与实际使用身份。动态缺值、除0、运行溢出和非法防御输出在第二阶段冻结；本批没有求值入口，静态通过不能消除动态错误。
