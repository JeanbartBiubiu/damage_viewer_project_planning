# 装备基本管理共享契约

方案版本：`equipment-management-v1`

本文只定义前后端共用的数据、接口、错误和验收口径。模块内部实现分别见：

1. [装备基本管理后端详细设计](../server/game_manage/装备基本管理后端详细设计.md)
2. [装备基本管理前端详细设计](../web/装备基本管理前端详细设计.md)

## 1. 范围

本阶段交付装备基本资料增删改查，以及装备直接数值属性的整块维护。

不包含分类、价格、状态、排序、图片、合成路线、装备技能、属性乘算规则、角色可用关系、发布、计算、Provider、旧数据迁移或兼容双读。

## 2. 装备基本资料

统一响应：

```json
{
  "gameId":"lol",
  "equipmentKey":"long_sword",
  "name":"长剑",
  "description":null,
  "createdAt":"2026-08-23T00:00:00Z",
  "updatedAt":"2026-08-23T00:00:00Z"
}
```

字段规则：

1. `equipmentKey` 创建时去除首尾空格；小写字母开头，只含小写字母、数字和下划线，最长 64；创建后不可修改。
2. `name` 去除首尾空格后长度为 1～100；同一游戏内忽略首尾空格和大小写唯一。
3. `description` 可省略或为 null；空串保存为 null；最长 2000。

接口：

```text
GET    /api/admin/games/{gameId}/equipment?keyword=
GET    /api/admin/games/{gameId}/equipment/{equipmentKey}
POST   /api/admin/games/{gameId}/equipment
PUT    /api/admin/games/{gameId}/equipment/{equipmentKey}
DELETE /api/admin/games/{gameId}/equipment/{equipmentKey}
```

列表返回 `{"items":[],"total":0}`，不分页。关键词按标识和名称模糊查询，空串等同省略，最长 100。POST 请求为 `{equipmentKey,name,description?}`；PUT 请求为 `{name,description?}`。删除返回 204，并级联删除装备属性。

## 3. 装备直接属性

```text
GET /api/admin/games/{gameId}/equipment/{equipmentKey}/attributes
PUT /api/admin/games/{gameId}/equipment/{equipmentKey}/attributes
```

GET 和 PUT 成功响应：

```json
{
  "equipmentKey":"long_sword",
  "attributeValues":{"attack_damage":10}
}
```

PUT 请求为 `{"attributeValues":{...}}`，一次整块替换，最后一次写入生效。

规则：

1. Map 保存装备直接赋予的属性值。`百分比护甲穿透`这类由伤害公式直接读取的独立属性可以配置；`生命值增加 10%`这类对既有属性进行乘算的规则不在本接口表达。
2. 未配置属性不写入 Map；空对象表示没有直接属性。
3. 每个键必须存在于当前属性定义，未知键拒绝。
4. 每个值必须为有限数字；整数属性不得含小数，并满足属性定义的最小值和最大值。
5. 失败时不产生部分写入；错误字段路径为 `/attributeValues/{attributeKey}`。

## 4. 错误

| HTTP | code | 场景 |
|---|---|---|
| 400 | `400.INVALID_BODY` | JSON 无法绑定 |
| 400 | `400.VALIDATION_FAILED` | 基本字段或查询错误 |
| 400 | `400.UNKNOWN_ATTRIBUTE` | 属性键不存在 |
| 400 | `400.ATTRIBUTE_VALUE_INVALID` | 属性值类型或范围错误 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在 |
| 404 | `404.EQUIPMENT_NOT_FOUND` | 装备不存在 |
| 409 | `409.EQUIPMENT_KEY_EXISTS` | 装备标识重复 |
| 409 | `409.EQUIPMENT_NAME_EXISTS` | 装备名称重复 |

## 5. 实施与验收

1. 后端先完成数据库表、接口和真实数据库验证。
2. 前端随后完成列表、资料弹窗、删除确认和装备属性弹窗。
3. 创建、编辑和属性保存后刷新页面能够重新读取。
4. 基本资料编辑不改变属性 Map；属性保存不改变基本资料。
5. 删除装备后，装备和属性均无法读取。
6. 页面只使用“装备”和“装备属性”，不出现技能、乘区或教学说明。
