## 4. 四种持续结果契约

四种结果都必须属于有生命周期效果，并使用 `moment = PERSISTENT`。它们描述未来持续生效的规则，不保存运行实例、当前层数、累计修正值或实际生命值。

### 4.1 伤害修正

`resultType = DAMAGE_MODIFIER` 必须有数值规则；未来数值按比例解释，`detail` 精确为：

```json
{
  "direction": "TAKEN",
  "operation": "DECREASE",
  "damageTypeKey": null,
  "deliveryKind": "ANY",
  "originKind": "ANY",
  "criticalFilter": "CRITICAL_ONLY"
}
```

1. `direction` 只允许 `DEALT / TAKEN`。
2. `operation` 只允许 `INCREASE / DECREASE`。
3. `damageTypeKey` 可空；非空引用同一游戏启用伤害类型。
4. `deliveryKind` 只允许 `ANY / SKILL / BASIC_ATTACK`。
5. `originKind` 只允许 `ANY / DIRECT / REFLECTED`。
6. `criticalFilter` 只允许 `ANY / CRITICAL_ONLY / NON_CRITICAL_ONLY`。

### 4.2 治疗修正

`resultType = HEALING_MODIFIER` 必须有数值规则；未来数值按比例解释，`detail` 精确为：

```json
{
  "direction": "RECEIVED",
  "operation": "DECREASE",
  "healingKind": "ANY"
}
```

1. `direction` 只允许 `DONE / RECEIVED`。
2. `operation` 只允许 `INCREASE / DECREASE`。
3. `healingKind` 只允许 `ANY / DIRECT / VAMP`。

### 4.3 伤害免疫

`resultType = DAMAGE_IMMUNITY` 禁止数值规则，`detail` 精确为：

```json
{
  "damageTypeKey": null,
  "deliveryKind": "ANY",
  "originKind": "ANY"
}
```

过滤值与伤害修正相同。伤害免疫只声明未来阻止匹配伤害，不等于法术护盾，也不自动阻止命中、状态、冷却、资源或其他结果。

### 4.4 生命下限

`resultType = HEALTH_FLOOR` 必须有数值规则，`detail` 精确为：

```json
{ "attributeKey": "hp" }
```

`attributeKey` 必须引用同一游戏启用数值属性。数值规则未来给出绝对生命下限；可以通过公式读取最大生命并换算，但本阶段不按属性标识或中文名猜测生命属性，也不执行公式。

## 5. 生命周期字段矩阵

| 结果 | `valueReadMode` | `stackValueMode` | `reapplicationValueMode` |
| --- | --- | --- | --- |
| `DAMAGE_MODIFIER / HEALING_MODIFIER` | 必须 `APPLICATION_SNAPSHOT` | `SHARED / PER_STACK` | `SHARED` 时必填 `KEEP / REPLACE / ADD`；`PER_STACK` 时必须为 null。 |
| `DAMAGE_IMMUNITY` | 必须为 null | 必须为 null | 必须为 null。 |
| `HEALTH_FLOOR` | 必须 `APPLICATION_SNAPSHOT` | 只允许 `SHARED` | 必填，只允许 `KEEP / REPLACE`。 |

同时遵守：

1. 四种结果均禁止无生命周期或其他离散时点。
2. 生命周期是否有自然持续时间、如何叠层和到期继续由阶段 7.4 字段决定，本阶段不新增持续时间或层数公式。
3. `DAMAGE_MODIFIER / HEALING_MODIFIER / HEALTH_FLOOR` 的数值在施加时留存；`DAMAGE_IMMUNITY` 没有数值合并语义。
4. `PERIODIC` 不是本阶段四种结果的时点，不得用周期结果模拟持续修正。
5. 结果 target 继续使用阶段 7.2 的 `SOURCE / TARGET`；direction 描述相对结果承受对象的造成或受到方向，不能代替 target。

## 6. 即将受到伤害事件

阶段 7.6.2 增加：

```json
{
  "eventType": "DAMAGE_PENDING",
  "detail": {
    "damageTypeKey": null,
    "deliveryKind": "ANY",
    "originKind": "ANY"
  }
}
```

1. 三个筛选字段与阶段 7.6.1 的 `DAMAGE_DEALT / DAMAGE_TAKEN` 完全同形，不建立第二套伤害筛选结构。
2. 当前目标固定为来源对象自身。
3. `EVENT_SOURCE` 可用，表示候选伤害来源对象。
4. 固定观察点只表示防御后候选伤害已经可观察、普通护盾吸收和生命扣除尚未发生；本阶段不冻结修正、暴击、防御或舍入如何得到该候选值。
5. `DAMAGE_PENDING` 可触发显式普通护盾、伤害免疫或生命下限效果；是否影响未来当前伤害由后续运行结算设计负责，本阶段只保存有序动作关系。

## 7. 本阶段事件值

在阶段 7.5 既有固定集合上只追加：

| `eventValueKey` | 值类型 | 允许事件 |
| --- | --- | --- |
| `RAW_DAMAGE` | `DECIMAL` | `DAMAGE_PENDING`。 |
| `POST_DEFENSE_DAMAGE` | `DECIMAL` | `DAMAGE_PENDING`。 |
| `HEALTH_BEFORE` | `DECIMAL` | `DAMAGE_PENDING`。 |
| `PROJECTED_HEALTH_AFTER` | `DECIMAL` | `DAMAGE_PENDING`。 |

规则：

1. 四项同时适用于 `EVENT_VALUE_COMPARE` 条件和 `EVENT_VALUE` 动态输入来源。
2. 事件值仍由事件能力表限制；把四项提交给其他十七种事件必须失败。
3. `PROJECTED_HEALTH_AFTER` 表示普通护盾吸收和实际扣血前的候选生命投影；本阶段只保存值身份，不计算、不钳制也不冻结最终舍入。
4. `DAMAGE_PENDING` 不允许 `SHIELD_ABSORBED / ACTUAL_HP_LOSS / BLOCKED / IMMUNE / KILLED`。
5. 现有事件值身份、值类型和允许事件保持不变，迁移不得用本阶段四项覆盖既有集合。

## 8. 反伤保护与候选规则图

1. 执行含 `originKind = REFLECTED` 伤害结果的效果时，规则事件只允许 `DAMAGE_PENDING / DAMAGE_TAKEN`。
2. 该执行效果动作的目标必须为 `EVENT_SOURCE`。
3. 规则伤害事件的 `originKind` 必须为 `DIRECT`，或者规则拥有合法每目标冷却。
4. 其他事件、其他动作目标或 `ANY / REFLECTED` 且没有每目标冷却的组合继续返回无保护循环错误。
5. 执行 `target = SOURCE` 的伤害在本地候选图中增加 `DAMAGE_PENDING` 和既有 `DAMAGE_TAKEN` 生产边；执行 `target = TARGET` 的伤害对应对方技能规则，挂载未知时不建本地边，也不宣称全局无环。
6. 四种持续结果本身不增加新固定事件生产边；普通护盾耗尽到 `EARLY_REMOVE` 的最终边仍由总契约登记，本阶段不执行护盾。
7. 必须复用阶段 7.5 同一保护边和有向环算法，不建立“伤前规则图”第二套实现。

## 9. 动作可达公式与效果更新

阶段 7.5/7.6.1 的封闭收集表增加：

1. `DAMAGE_MODIFIER / HEALING_MODIFIER / HEALTH_FLOOR` 的 `valueRule.formulaKey`。
2. 直接执行效果和经阶段 7.3 过程挂接到达效果时都按同一规则收集。
3. `DAMAGE_IMMUNITY` 没有数值规则，不产生公式节点。
4. `DAMAGE_PENDING` 筛选不引用公式；阈值继续通过既有 `EVENT_VALUE_COMPARE` 条件的比较公式表达。

触发规则 POST/PUT 的缺失、多余、重复或类型不兼容绑定继续返回 `400.INVALID_RUNTIME_INPUT_BINDING`。效果 PUT 新增、替换或移除三种数值结果公式时：

1. 若候选效果改变直接或过程间接引用规则的可达参数集合，返回 `409.SKILL_EFFECT_IN_USE`，原因 `TRIGGER_RULE_RUNTIME_INPUT_IN_USE`。
2. 字段定位实际改变的 `results[i].valueRule.formulaKey`，详情按 `ruleKey/actionKey/parameterKey` 稳定排序。
3. 处理顺序固定为先修改或删除依赖规则，再更新效果，最后按新集合恢复规则与绑定；不增加跨聚合批量接口或预先多绑参数。
4. 可达集合未变化时允许更新；若候选效果另行形成无保护环，仍返回循环错误并保持原聚合。

## 14. 跨端验收

### 14.1 持续修正

1. 分别保存造成/受到的伤害提高或降低，并组合伤害类型、产生方式、来源性质和暴击过滤。
2. 分别保存造成/受到的直接治疗或吸血提高或降低。
3. 验证共享值、每层值和重复施加值字段严格符合矩阵；关闭、刷新、重启后完整回读。

### 14.2 伤害免疫与生命下限

1. 保存只免疫指定伤害类型和来源的持续结果，确认没有数值规则。
2. 保存引用明确生命属性和下限公式的持续结果，确认只允许共享值和保留/覆盖。
3. 尝试把两者改为离散时点、给免疫增加数值规则或给生命下限按层相加，均失败且原聚合不变。

### 14.3 斯特拉克类伤前保护

1. 新建 `DAMAGE_PENDING`，用 `PROJECTED_HEALTH_AFTER` 与既有阈值公式比较。
2. 有序动作执行阶段 7.6.1 普通护盾效果，并配置合法每目标或技能冷却保护。
3. 页面重开后仍能区分伤害筛选、伤前事件值、护盾动作和冷却；不执行真实伤害或护盾。

### 14.4 迁移与反例

1. 新库和兼容迁移都形成四张新结果表、十二种结果、十八种事件和追加后的事件值检查。
2. 重复执行不重复数据；部分结构、未知前置检查或函数漂移时整体停止。
3. `DAMAGE_PENDING` 读取实际扣血、护盾吸收或击杀结果必须失败。
4. 反伤规则使用其他事件、其他目标或无保护 `ANY / REFLECTED` 时必须失败。
