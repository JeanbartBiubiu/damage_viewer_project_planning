## 3. 展示数据分层、身份与金额

### 3.1 四类数据不能互相替代

| 层次 | 唯一数据源 | 可以证明什么 | 不能据此做什么 |
| --- | --- | --- | --- |
| 冻结输入 | 本次档案中的原快照、显式输入、编译及实际运行请求。 | 谁对谁、等级、配置、运行条件与初始生命。 | 不从当前正在编辑的表单给旧结果补标签或初值。 |
| 完整累计 | `summary`（汇总），其中分类数组为 `summary.damageBreakdown`。 | 本次已提交执行的完整金额、次数、来源分类与击杀事实。 | 计算未完成时不能冒称已完成整段请求。 |
| 有限事实 | `attackRecords`（攻击记录）、`damageRecords`（伤害记录）及 `recording`（记录说明）。 | 已返回每刀和每笔的真实细节。 | 不从有限记录重算全场总额，不补造被丢弃的记录。 |
| 只读采样 | `series`（时间序列）及 `seriesSamplingEvidence`（采样说明）。 | 所返回观察时刻的生命、累计造成伤害和伤害率。 | 不把采样点当成攻击，不能恢复未采样时刻或来源分项曲线。 |

调试证据 `evidence` 用于排查，不作为可靠汇总、逐刀事实或曲线的替代来源。

### 3.2 身份与标签

| 对象 | 关联规则 |
| --- | --- |
| 当前结果 | 视图状态属于当前已完成任务及其冻结档案。沿现有任务标识防迟到覆盖；`runInputHash` 是运行条件摘要，不是全球唯一的运行编号。 |
| A/B与技能 | 使用档案 `snapshot.selection` 的角色／技能稳定标识及等级；名称来自同一 `snapshot`。A/B显示顺序固定，来源拥有者、实际伤害方和受伤方仍分开。 |
| 一刀 | `(planKey, attackIndex, useRef)`，即计划、从1开始的攻击序号、同次使用身份。选中、分页和排序不改变它。 |
| 一笔伤害 | `damageId` 为本次运行内的真实伤害编号；以 `attackIndex + useRef` 关联同刀，计划取本次连续请求。保留 `castInstanceId`（施放实例）及 `operationPath`（实际编译路径）。 |
| 一项分类 | 完整键为 `owner, source, target, abilityRef, operationRef, damageType`，分别为拥有者、伤害方、受伤方、能力、作者结果及伤害类型。名称相同不合并不同身份。 |
| 作者来源 | 使用本次 `operationOrigins`（作者结果与编译来源映射）的能力／结果关联，显示技能、效果、结果及实际编译路径；不另向管理接口读取“最新名称”覆盖旧结果。 |

身份缺失、重复、引用无法核对或金额矛盾时保留问题和原档案，不静默删行或归到“普通攻击”。名称仅作标签；尚无中文名称时显示真实稳定标识，不制造新来源。攻击和伤害保留预算独立：有伤害记录而对应攻击行未保留时，仍显示该笔事实和真实使用身份，并提示“该刀攻击记录未保留”。

### 3.3 金额和缺失语义

“造成伤害”统一指防御后、护盾前的 `postDefenseDamage`；“实际扣血”指引擎已提交的 `actualHpLoss`；“护盾吸收”和“过量伤害”分别取 `shieldAbsorbed`、`overkillDamage`。不能把扣血、造成伤害或初始生命减最终生命混成同一指标。

逐笔 `rawAmount` 是本笔实际防御前输入金额，已经包含当次暴击和出伤修正，不能标成暴击前基础值；若输出了暴击分解，则另显示 `baseRawAmount`（基础金额）、`critAdjustedRawAmount`（出伤修正前的暴击调整合并金额）及相关正常／暴击部分，不重新计算。防御、穿透、修正和暴击详情只展示当前记录实际具备的字段；不适用与必需字段缺失分开，不能将缺失补成0。

时间原值为整数毫秒；图表横轴显示秒，悬停和详情保留整数毫秒。金额与攻速展示最多6位小数，计算、筛选、关联及导出始终使用原精度。真实0正常显示；不存在的时刻明确为 `null` 并显示“未发生／未排定”，不能用真假判断吞掉0毫秒。

## 4. 场景和完整汇总字段

本节路径均相对本次运行档案；`runResult` 是原生运行结果，`assessment` 是前端核对结论，二者不混用。

| 展示项 | 真实来源 | 单位、范围及规则 |
| --- | --- | --- |
| A/B、双方等级、普攻及技能等级 | `snapshot.source/target` 与 `snapshot.selection`。 | 显示冻结选择，不读取新表单。 |
| 初始生命和补充属性 | `initialHealth`、`attributeInputs`，核对 `runRequest.initialSnapshot`。 | 生命值、原属性单位；已录等级值不被输入覆盖。 |
| 选入／排除机制 | 本次编译挂载及原快照中的实际技能关系，沿前置契约核对。 | 本阶段只启用所选完整共享普攻；装备、其他英雄技能、构筑和B挂载均未选入，不能称为当前角色没有这些能力。 |
| 指定观察时长 | `runRequest.stopPolicy.durationMs`，与 `summary.execution.requestedDurationMs`核对。 | 毫秒；是请求终点，不是击杀耗时。 |
| 实际停止时刻 | `runResult.summary.durationMs`，与最终快照时刻核对。 | 本阶段起点0毫秒；击杀或预算停止时可小于指定时长。 |
| 开始／命中／完整完成刀数 | `summary.basicAttack.startedCount/hitCount/completedCount`。 | 完整整数累计；不取表格行数，不把三项统一称为攻击次数。 |
| A/B造成与承受伤害 | `summary.sourceDamageDealt/targetDamageDealt/sourceDamageTaken/targetDamageTaken`。 | 防御后、护盾前；本次全部已提交执行。 |
| A/B累计实际扣血 | `summary.sourceHpLoss/targetHpLoss`。 | 完整已提交生命损失，不用生命差额替代。 |
| 双方最终生命 | `summary.sourceFinalHp/targetFinalHp`，核对最终快照。 | 实际停止时刻的生命；与生命损失分开。 |
| 来源／类型金额与次数 | `summary.damageBreakdown[]`。 | 显示造成伤害、护盾吸收、实际扣血、过量伤害及结算笔数；笔数不是刀数。 |
| 是否击杀及首次击杀时刻 | `summary.execution.targetKilled/targetKilledAtMs`。 | 未击杀为false／null；0毫秒致死有效。不能仅从最终生命或停止原因推断。 |
| 停止、完整性和预算 | `summary.stopReason` 与 `summary.execution.complete/incompleteReason/budgetCause`。 | 枚举含义沿阶段2；真实击杀、未完成尾部和预算原因同时保留。 |
| 来源占比 | 从完整分类金额按所选拥有者、方向、来源／类型合并。 | 默认以同一伤害方向的全部造成伤害为分母；切换金额指标时分子分母一起切换。分母0显示“无贡献比例”，不做0除0。 |
| 汇总可信、任务和清理 | `assessment.issues`、档案 `outcome/cleanup/failurePhase`。 | 事实可核对、请求完成、任务成功、会话正常释放分别显示；释放失败不抹掉真实击杀。 |

顶部完整累计卡片始终属于整次运行，不受时间缩放、来源或明细筛选改变。预算停止时统一改为“截至停止时刻的已提交累计”，保留真实数值但不称“完整请求总额”。

## 5. 曲线字段、采样及伤害率口径

### 5.1 曲线字段

| 曲线 | 采样点真实字段 | 展示规则 |
| --- | --- | --- |
| A/B剩余生命 | `series[].sourceHp/targetHp`。 | 生命值，同一图内两条线；不根据逐笔扣血在前端重建生命。 |
| A/B累计造成伤害 | `series[].sourceDamageDealt/targetDamageDealt`。 | 防御后、护盾前累计，同一图内两条线；不画成累计实际扣血。 |
| 累计平均伤害率 | `series[].sourceCumulativeDps/targetCumulativeDps`。 | DPS即每秒伤害率；直接使用引擎输出，不平均多个采样点的伤害率。 |
| 滚动窗口伤害率 | `series[].sourceWindowDps/targetWindowDps`。 | 窗口取实际请求 `sampling.dpsWindowMs`；与累计平均伤害率单独切换。 |

当前没有“按装备／技能／伤害类型的累计曲线”和“累计实际扣血曲线”。首批不展示这些曲线，不用有限伤害记录反推。来源拆分只用完整分类做条形图和汇总表，伤害类型筛选不改变A/B总量曲线。

### 5.2 时间和伤害率的准确解释

采样在同刻已提交战斗与合法同步尾部之后观察，实际停止时只读取已经提交的部分；预算停止不能补造未执行尾部。0毫秒采样可能已经包含首刀伤害，不等于攻击前初始状态；初始生命单独显示，不插入另一条同刻“初始样本”。保留0和实际结束点，结束点不在等间隔网格时仍有效。

对正时刻t，原生累计平均伤害率分母是从0到t的实际秒数。窗口伤害率采用当前源码的闭区间 `[max(0, t−窗口), t]`，分母为已实际经历的窗口秒数；位于左边界的伤害也计入，因此相邻窗口会共享边界命中，不能解释为互斥时间分段。这是当前实际口径，不在前端偷偷改成左开右闭。

0毫秒没有正的时间分母，原生伤害率字段输出0；图表在该点显示“起点，伤害率不适用”，不把它作为0伤害的证据。原始档案保留引擎0值，伤害率图不连接该点。若实际终止也在0毫秒，只显示单点生命／金额和击杀标记，不生成伪造时长或每秒率。

没有采样时，累计和窗口伤害率显示“未记录时间序列”，不由前端另算一套DPS。完整汇总、来源分类和逐刀／逐笔表仍可用。

### 5.3 曲线请求与粒度

后续图表实现增加“记录时间序列”输入，默认勾选；固定采用请求间隔100毫秒、窗口1000毫秒及最多5000点，首批不增加任意采样参数编辑器。取消勾选时显式 `sampling.disabled=true`，其他请求字段仍保留；勾选时为false。开启曲线不是开启额外战斗，也不是提高攻击密度。

该选项属于运行输入：执行时冻结并进入 `runInputHash`，修改只作用于下一次运行，不能点击开关后给旧结果补出曲线。当前阶段2代码仍关闭采样，本段是待实现规则，不改变其既有验收结论。

实际间隔按原生采样说明读取；原生根据请求观察时长和点数预算选定有效间隔，提前击杀后不由前端重新加密采样。请求点数、返回点数、间隔及降采样以 `seriesSamplingEvidence` 的实际字段展示；候选点数基于实际结束点，不能单凭 `series.length` 推断攻击次数或执行完整性。

### 5.4 进入图表前的校验

在现有连续解释器基础上补充以下检查，不放宽阶段2金额、引用和提交一致性校验：

- 所有点的毫秒时刻是非负安全整数，严格递增且不超过实际停止时刻；各金额、生命和伤害率字段必须明确、有限且非负。
- 开启采样时首点为0，末点为实际停止时刻，返回点数与说明一致且不超过上限；0毫秒结束允许只有一个点。
- 首批累计造成伤害不下降；末点双方生命及累计造成伤害与可靠汇总相符。金额核对沿现有相对容差，不按展示舍入后的文字比较。
- 采样方法、请求／有效间隔、降采样标志与实际请求一致；`summary.seriesDownsampled` 与采样说明一致，终点不被误判为必须等间距。关闭采样则遵守阶段2的空序列说明。
- 可核对的正常首刀、实际击杀时刻和攻击标记用真实记录／击杀字段；不能要求每刀都落在采样点上，也不要求采样数量等于刀数。

发现仅曲线数据非法时停用曲线并列出具体字段问题，已独立通过阶段2核对的可靠汇总和明细可以保留，但整份展示不标“核对通过”；原生预算停止而数据自洽时允许显示截至停止的部分曲线。缺关键汇总或事实身份时不显示可信业务结果，仍允许导出带失败结论的原始档案。

## 6. 页面布局与图表规则

结果区仍位于 `#/simulation/basic-attack`（普攻模拟地址），从上到下为：冻结场景与完整性提示、完整累计卡片、时间图表、来源拆分、攻击／伤害明细及详情、档案导出。编译诊断继续作为诊断区，不混入主业务图表。

| 区域 | 最小规则 |
| --- | --- |
| 结果提示 | 区分完整击杀、完整观察未击杀、预算停止／尾部未完成、数据核对失败和无运行结果；同时展示记录截断、降采样及清理状态。 |
| 时间轴 | 范围为0至实际停止时刻，不延伸到未执行的请求终点；0毫秒结束仅作显示留白，不能增加业务时刻。可缩放和恢复全范围。 |
| 生命／累计伤害图 | 共用横轴，金额和生命分别有纵轴；使用采样阶梯连接，关闭平滑和数值插值。阶梯拐点只表示采样变化，不宣称精确命中位置。 |
| 伤害率图 | 默认累计平均，可切换滚动窗口；横轴与其他时间图联动，明确窗口与0毫秒语义，不与生命共享数值纵轴。 |

| 来源拆分 | 用完整分类按来源或伤害类型合并，显示条形图、金额、占比和结算笔数；四类金额不能堆叠成“总伤害”，以免重复计算。 |
| 无采样／无明细 | 用明确空态替代空白坐标或0值。筛选无记录与原生未返回记录分开说明。 |

## 7. 时间联动、筛选与逐刀详情

### 7.1 悬停和时间区间

时间图共享一个悬停时刻，吸附到最近真实采样点并显示该点准确毫秒，等距时取较早点；不插值出新生命或金额。攻击标记按自身真实时刻悬停，不能被改成最近采样时刻；附近攻击只作定位信息，不说明采样值属于那一刀。

可见时间区间用毫秒保存，规范到0至实际终点，端点包含。缩放同步三个时间图；明细表按该区间筛选攻击的 `startAtMs`、伤害的 `timeMs`。完整累计和来源分类没有按时间区间的完整汇总，保持全场值并标明“整次运行”，不得从采样差额或有限明细计算“区间总伤害”。

### 7.2 来源、类型及排序

来源候选取完整分类及冻结作者映射，保存真实键而不是中文名称。首批提供来源、伤害类型和攻击序号筛选；默认全部来源／类型，不提供当前场景尚不存在的装备筛选项。

来源／类型筛选影响完整分类的筛选小计和伤害表，不改变顶部总量或A/B总量曲线；完整分类小计属于整次运行，伤害表小计明确为“当前已返回记录的小计”。不能用相同“筛选后总伤害”标题掩盖两者的范围差异。

攻击表按时间区间和攻击序号筛选，不由有限伤害表反向判断一刀是否属于某来源；来源／类型筛选作用域在表旁明确提示。来源拆分点击使用同一来源键设置伤害筛选，不建立第二套筛选状态。筛选或排序重置当前页，但不修改原始记录顺序、伤害编号或刀号；导出不是只导当前分页。

### 7.3 选中攻击与结算详情

点击攻击标记或攻击表行，以真实计划、刀号及使用身份选择一刀，并定位到其准确开始／命中时刻。详情显示该刀 `startAtMs, hitAtMs, readyAtMs, nextStartAtMs, attackSpeed, completed`，以及原生逐刀造成伤害、实际扣血和尾部生命。已提交就绪时刻可以晚于实际终点，只在详情显示，不把未来冷却画成已发生攻击；下一刀未排定仍为null。

逐刀金额直接读 `attackRecords`，不能以筛选后的伤害小计覆盖。一刀多笔伤害按 `useRef + attackIndex` 从原返回数组关联，详情不再受来源／时间筛选删减；提示哪些笔被主表筛选隐藏。每笔以 `damageId` 定位，按真实编号显示原提交顺序，可跳转对应作者路径和编译路径，不用数组索引充当身份。

详情分三层：同次身份与时刻；造成伤害／护盾／实际扣血／过量伤害及该笔受伤方生命前后；已输出暴击、防御、穿透和修正字段。金额路径只展示事实与引用关系，不在详情页重新运行公式，不能让“打开详情”改变任何金额。

攻击未完成时保留其已提交事实及未发生的null字段，提示尾部未完成。伤害记录全场被截断时，详情提示“仅展示已返回伤害记录”，不保证该刀的笔数完整；没有返回笔数不能解释为该刀0伤害。有伤害行而攻击行被截断时仍可打开该笔详情，但该刀时刻、攻速和尾部生命显示“未保留”，不得从静态间隔外推。

### 7.4 状态、键盘及重复运行

视图状态仅保存当前档案的时间区间、指标模式、可见曲线、来源／类型／刀号筛选、选中攻击或伤害和分页；不复制一份战斗状态。新运行完成后原子替换结果并重置视图，失败或取消不把旧图表改成新输入的结果。输入已修改但旧结果仍展示时明确标“上一份冻结输入的结果”。连接、游戏变化沿现有保护和迟到隔离规则处理。

选择攻击及打开详情必须有同等表格／按钮入口，不能只能鼠标悬停；键盘可移动、确认选择及关闭详情。图例和状态使用文字，不只靠颜色；窄屏保留卡片和表格，可横向滚动时间图，但不另造一套数据口径。

## 8. 输入、结果和表格导出

### 8.1 完整运行档案

继续使用现有JSON（结构化数据文件）档案，不创建新的发布数据包或后端保存接口。档案覆盖原快照、显式输入、实际编译／运行请求、来源映射、实际输出与预算说明、核对结论及清理结果。原快照和作者配置的字段白名单仍沿前置与阶段2契约；缺省或未产生的结果明确为null，不用0伪装失败。

| 必须保留 | 追溯含义 |
| --- | --- |
| `taskKind, adapterVersion, snapshot, snapshotDigest` | 任务种类、适配版本、冻结配置和摘要。 |
| `attributeInputs, initialHealth, attackSpeedAdmission` | 显式补充、初始生命、攻速上界及其来源。 |
| `compileRequest, runRequest, runInputHash` | 原实际请求和不含会话编号的条件摘要；采样与全部预算保留。 |
| `coverage, operationOrigins` | 作者配置到编译节点的覆盖和来源对应。 |
| `wasm, compileResult, runResult, releaseResult` | 最终产物字节数与摘要、编译／真实运行／释放输出；保留完整累计、有限记录、采样与各类截断说明。 |
| `assessment, outcome, cleanup, failurePhase, error` | 核对、任务、清理和失败边界，不把失败档案描述成成功运行。 |

第三阶段新增的仅是 `displayDefinitionVersion=1`（展示定义版本）和 `view`（当前视图）：可见时间区间、伤害率模式、可见曲线、来源／类型／刀号筛选及选中真实身份。这些是展示信息，不进入战斗条件摘要。完整档案始终导出整份原结果，不能因筛选只保存可见行；导出后改筛选不改原档案。

选入／排除机制说明从本次请求和冻结关系产生，明确本阶段装备、其他英雄技能、B挂载及构筑未选入；不借导出把角色全部关联技能启用。只记录实际采用的结果模型与最终产物，不把静态产物摘要本身作为浏览器已加载对应字节的证据。

### 8.2 当前表格导出

新增“导出当前表格CSV”，CSV即逗号分隔表格文件。分别用于来源分类、攻击、伤害及时间序列表；导出当前表全部筛选结果，不只导当前页，也不重建被截断的数据。按钮明确标“整次运行分类”“已返回攻击／伤害记录”或“原生采样点”，空筛选结果时禁用当前表导出并说明原因，完整档案仍可下载。

每行附带运行条件摘要、表格种类、导出范围、可见时间区间、来源／类型／刀号筛选、计算完整性、攻击／伤害记录截断和序列降采样标志；这些列的具体中文标题在实现中与页面使用同一标签。分类表不套用时间区间，序列表不套用来源／类型筛选；导出范围必须说明哪些筛选对当前表实际生效。

时间用原整数毫秒，数值用原精度，缺失时刻输出空单元格；文本正确转义逗号、引号和换行，使用带字节序标记的UTF-8（通用文本编码）文件。对名称和作者文本中以 `= + - @` 等开头、可能被表格软件当成公式的内容作文本转义；原数值列不改变数值，JSON档案保留原业务文本。表格文件只用于查看，不承诺重新执行；完整档案是追溯入口。

### 8.3 密钥排除

导出字段按业务白名单构造，不展开连接配置、请求头、本地存储、工作线程消息或整个客户端对象。禁止出现鉴权令牌、Cookie、密码、API密钥或带密钥的请求地址。错误字段只记录已脱敏的阶段、码、业务路径和信息，不复制未经处理的请求／响应对象。文件名由任务种类、业务标识与安全时间构造，不包含连接或鉴权信息。
