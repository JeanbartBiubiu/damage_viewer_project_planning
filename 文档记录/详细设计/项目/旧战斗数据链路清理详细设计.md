## 1. 本次需要确认的决定

1. 旧 Provider、Ability、Effect Sequence、Effect Step、旧类型目录、旧实体、旧版本发布和旧 `/combat-data` 链路整体删除，不迁移数据、不保留兼容接口、不做双写。
2. 当前阶段 0～7.4 已完成的游戏、属性、等级配置、角色、装备、技能分类、技能、技能参数、技能公式、伤害类型、状态、技能效果、技能过程、内部状态和生命周期管理全部保留。
3. `images` 表、按游戏建立图片分区的数据库能力、图片管理接口、图片管理页面和浏览器图片缓存保留；分区函数收敛为只处理 `images`，只删除图片能力对旧实体和旧战斗数据页面的引用。
4. 旧版本发布能力本次一并删除。新的发布能力以后基于当前业务表重新设计，不复用旧 `game_versions`、`game_data_state` 或旧发布服务。
5. 前端旧页面、旧导航、旧路由、旧数据装配和依赖旧数据的 Wasm 验证入口一并删除。底层 Wasm 文件、桥接代码和工作线程保持冻结，不在本次改造。
6. `GET /api/games` 收敛为当前页面实际需要的游戏标识、游戏名称和可选游戏图片地址，不再返回旧阶段配置；等级范围继续由游戏等级配置接口管理。
7. 旧接口删除后直接按不存在处理并返回普通 404；旧前端地址不做跳转兼容，统一落到当前第一个管理页“属性管理”。
8. 数据库采用明确列出对象的破坏式迁移，不使用 `CASCADE`。发现清单外依赖、目标数据库不明确、当前业务表缺失或图片分区能力无法保留时立即停止。
9. 本次清理完成并通过真实数据库、接口和浏览器验收后，阶段 7.5 必须按清理后的实际代码重新核对依赖，再单独获得开发批准。

## 2. 目标与非目标

本次交付：

1. 清除数据库中已经被阶段 0～7.4 取代的旧表、旧触发器、旧函数、旧迁移和旧种子数据。
2. 清除后端旧战斗数据、旧版本发布对应的控制器、服务、数据访问层、映射文件和测试。
3. 清除前端旧管理页面、入口、路由、服务、类型、数据装配、缓存和旧验证测试。
4. 保持当前阶段 0～7.4 管理接口、页面和数据不变，并保留图片管理能力。
5. 用静态检查、自动测试、真实数据库迁移、接口冒烟和桌面浏览器验收证明旧链路已经完整消失。
6. 更新仍被视为当前说明的后端和前端文档，避免继续引导使用已删除入口。

本次不包含：

1. 阶段 7.5 条件、事件和动态输入供值功能的开发。
2. 对旧数据的转换、导入、导出、归档、兼容读取或临时回退接口。
3. 新发布模型、发布页面或新计算数据组装的设计和开发。
4. 新图片字段、角色或装备图片关联、技能图标关联。
5. Wasm 计算契约、运行时、二进制、桥接接口或计算逻辑改造。
6. 移动端页面适配或移动端测试。
7. 与旧链路无关的目录整理、命名调整或顺手重构。

## 3. 清理后的系统边界

```text
游戏
├─ 等级配置
├─ 属性
├─ 角色 ──角色等级属性
├─ 装备 ──装备属性
├─ 技能分类
├─ 伤害类型
├─ 状态
└─ 技能
   ├─ 分类关联
   ├─ 参数与公式
   ├─ 效果与结果
   ├─ 过程与内部状态
   └─ 效果生命周期

图片管理（独立保留）

旧实体 / Provider / Ability / Effect Sequence / Effect Step / 旧发布链路
└─ 全部删除
```

清理完成后的责任方向固定为：

1. 当前管理页面只访问当前业务接口；不得再通过旧 `/combat-data` 接口间接维护任何当前对象。
2. 当前业务表直接表达对象和关系；不得为旧结构保留旁路表、宽 JSON 或兼容映射。
3. 游戏等级范围只由 `game_level_configs` 及其当前接口负责；不得从旧游戏阶段配置读取。
4. 图片仍是独立资源；本次不因为删除旧引用而删除图片本体。
5. 发布与 Wasm 都是后续独立阶段；本次只删除依赖旧数据结构的上层入口，不设计替代实现。

## 5. 对外行为

### 5.1 保留接口

1. 当前阶段 0～7.4 已有接口的路径、请求、响应、错误含义和权限不因本次清理发生业务变化。
2. `GET /api/games` 只返回：

```json
{
  "gameId": "lol",
  "gameName": "英雄联盟",
  "gameImgUrl": null
}
```

3. `gameImgUrl` 允许为空。旧 `progressionSchema` 字段删除，前后端同步收敛。
4. 游戏等级配置继续使用现有管理接口，不并入游戏摘要。

### 5.2 删除接口

1. `/api/admin/games/{gameId}/combat-data/**`
2. `/api/games/{gameId}/combat-data/**`
3. `GET /api/games/{gameId}/versions/current`
4. 旧发布接口的三个既有别名：`versions:publish`、`versions/:publish`、`versions/publish`

删除后的行为固定为普通 404，不返回 410，不增加兼容控制器、重定向或提示接口。

### 5.3 前端地址

1. 导航中只显示保留的当前管理页面。
2. 默认地址和不能识别的旧地址落到 `#/attributes`。
3. 不为任何旧地址保留隐藏菜单、兼容组件或旧数据请求。
4. 页面只面向桌面端，按现有桌面布局验收，不新增移动端断点和触控测试。

## 6. 数据处理原则

1. 74 张旧表及其数据直接删除，不搬入当前表。
2. 45 张保留父表在迁移前后都必须存在；迁移不得修改这些表的字段、约束或业务数据。`images_<gameId>` 子分区按当前游戏集合保留，不计入父表数量。
3. 迁移脚本必须在一个事务中执行，逐项写明删除对象，使用反向依赖顺序，不使用 `CASCADE`。
4. 迁移脚本可重复执行；第二次执行不得报错，也不得影响保留表。
5. 真实数据库执行前必须确认数据库实例、数据库名和游戏数据分区范围，并完成备份；如果明确是可丢弃的本地数据库，可由项目负责人明确免除备份。
6. 执行前记录 45 张保留父表的存在性、现有 `images` 子分区和关键业务表行数；执行后再次核对。任何非预期差异都视为失败。
7. 依赖预检允许的删除闭包只包含：74 张明确旧父表、通过 PostgreSQL 分区目录关系得到的这些父表全部子分区、旧效果步骤的十一项触发器和两个函数、旧数据状态函数，以及这些对象自身拥有的索引、约束等内部对象。任何闭包外的表、视图、物化视图、触发器或函数依赖旧表时停止，不得临时加 `CASCADE` 绕过。

## 7. 实施顺序

开发获得批准后按以下顺序执行：

1. 冻结本方案版本，重新核对 Backend、Web 分支和阶段 7.4 实际实现，确认没有新增旧链路引用。
2. 后端先完成新鲜建库脚本、破坏式迁移、旧实现删除和保留接口调整；前端可基于已冻结接口契约并行删除旧页面和调用。
3. 两端分别完成静态检查、单元测试和构建，不执行真实删表。
4. 对目标数据库做只读预检，确认目标、保留表、旧表、依赖和行数，并完成备份或取得可丢弃数据库确认。
5. 停止旧后端进程，执行破坏式迁移；重复执行迁移一次，再应用当前触发器脚本。
6. 启动后端，验证保留接口成功、旧接口 404、当前管理接口读写正常。
7. 启动前端，使用桌面浏览器验证所有保留页面，确认旧菜单和旧入口消失，旧地址落到属性管理。
8. 对照阶段 7.5 三份方案重新核对表名、服务边界、接口和页面入口，形成复核清单；如需修正阶段 7.5 文档，由阶段 7.5 的独立文档任务处理，本次实现不写入那三份文档，也不顺带开发阶段 7.5。

数据库清理不能早于后端静态验证，也不能在后端仍运行旧代码时执行。前端不能在后端保留接口契约尚未确定时自行猜测响应。

## 8. 停止条件与恢复方式

出现以下任一情况立即停止：

1. 目标数据库无法唯一确认。
2. 45 张保留父表中有表缺失，或迁移前关键数据行数无法建立基线。
3. 旧表被清单外对象引用，必须依赖 `CASCADE` 才能继续。
4. 当前阶段 0～7.4 的服务仍直接读取任何待删除表。
5. 后端或前端存在未识别的同路径并行改动，无法确认归属。
6. 迁移后保留表结构或数据发生非预期变化。
7. 当前管理接口或页面回归失败，且无法在本任务允许范围内定位修复。
8. `images` 仍为分区表，但迁移或新鲜建库脚本无法为已有和新增游戏建立对应图片分区。

代码恢复使用正常 Git 回退或修复提交；不得重置用户工作区。数据库恢复使用执行前备份重新建立本地数据库。因为本方案明确不保留旧兼容结构，所以不设计在线双轨回退。

## 9. 跨端验收

### 9.1 静态验收

1. 新鲜数据库脚本只包含 45 张保留父表及按游戏建立的 `images` 子分区能力；旧 74 张父表、旧数据状态函数和旧效果步骤触发器均不存在。
2. 后端源码、映射和测试中不再存在旧战斗数据控制器、服务和数据访问层。
3. 前端源码和测试中不再存在旧页面、旧路由、旧客户端、旧数据装配器和旧发布入口。
4. 不存在为了兼容旧地址、旧响应或旧表新增的别名、适配层或双写。
5. 底层 Wasm 文件和接口没有发生本次运行造成的改动。

### 9.2 自动检查

1. 后端完整测试通过，并完成打包验证。
2. 前端代码检查、类型检查、单元测试、构建和非 Wasm 桌面端到端测试通过。
3. 数据库清理契约测试证明删除清单和保留清单精确匹配，迁移脚本不含 `CASCADE`。

### 9.3 真实运行验收

1. 数据库中恰好保留本方案列出的 45 张当前父表，以及与 `games` 当前记录对应的 `images` 子分区；如果环境存在明确批准的基础设施表，必须单独列出，不得混入业务父表计数。
2. 迁移前后的当前业务数据行数一致。
3. `GET /api/games`、图片接口和阶段 0～7.4 当前管理接口返回成功。
4. 所有删除接口返回普通 404。
5. 浏览器导航只包含当前管理功能；旧页面不可达，未知地址落到属性管理。
6. 属性、角色、装备、技能分类、伤害类型、技能、状态、游戏配置和图片管理至少各完成一次列表加载；选择一个低风险对象完成新增、查看、修改、删除闭环。
