## 1. 本次需要确认的决定

1. 阶段 7.6 不建立独立的自由“特殊机制”目录，也不引入脚本、标签或通用多态关系。数据继续从属于现有技能效果结果和技能触发规则。
2. 阶段 7.2～7.4 的效果五个接口继续作为效果聚合唯一写入口；阶段 7.6 扩展结果联合类型、伤害明细、普通护盾明细和结果级法术护盾阻挡范围，不新增结果子接口。
3. 阶段 7.5 的触发规则五个接口继续作为事件与前序结果关系唯一写入口；阶段 7.6 只增加四种固定事件、三类伤害事件明细和丰富前序结果来源，不新增事件或绑定子接口。
4. 伤害结果必须明确伤害来源方式 `SKILL / BASIC_ATTACK` 和来源性质 `DIRECT / REFLECTED`。反伤仍是一条正常伤害结果，但必须标记为 `REFLECTED`，不能用负伤害或伤害修正伪装。
5. 每个伤害结果独立保存暴击策略：不允许暴击、按来源对象暴击率判定或强制暴击；可选引用一个同技能公式覆盖本结果暴击倍率。
6. 暴击率转普通伤害等不发生暴击的机制继续由普通公式读取属性表达，不为它增加第四种暴击模式。
7. 吸血规则从属于伤害结果，按生命偷取、全能吸血、物理吸血和法术吸血分别保存。同一伤害结果同一种吸血方式最多一条规则。
8. 每条吸血规则明确读取防御处理后伤害或实际扣血，并引用同技能公式作为适用效率。一次已解析的伤害实例对每条规则产生一次吸血机会；伤害实例次数继续由阶段 7.3 过程步骤和效果挂接表达，不复制次数公式。
9. 命中联动与攻击联动不作为伤害结果的布尔开关，分别增加固定结果 `HIT_LINK_APPLICATION` 和 `ATTACK_LINK_APPLICATION`。它们的数值规则表示本次应用次数，因此可以与伤害实例和吸血次数独立排序、延迟和重复。
10. 鬼索延迟再次应用命中联动使用阶段 7.3 延迟过程步骤挂接 `HIT_LINK_APPLICATION` 结果表达，不新增“鬼索专用”字段。
11. 普通护盾继续使用 `NORMAL_SHIELD`，但明细增加可空伤害类型限制和衰减方式。护盾只吸收匹配伤害，数值耗尽视为生命周期提前结束；线性衰减使用所属生命周期持续时间，不复制第二个持续时间字段。
12. 法术护盾增加固定结果 `SPELL_SHIELD`，与普通数值护盾完全分离。它必须是生命周期持续生效结果，不拥有数值规则。
13. 允许参与法术护盾阻挡的离散目标结果使用可空 `spellShieldBlockScope`，固定区分整个技能、所属效果、当前伤害实例和当前结果。null 表示该结果不参与法术护盾阻挡，且不会被同技能或同效果中其他结果的 `SKILL / EFFECT` 范围连带阻挡；直接治疗和普通护盾固定为 null。
14. 法术护盾成功阻挡后产生固定事件 `SPELL_SHIELD_BLOCKED`。护盾消耗和后续治疗、增益仍通过阶段 7.5 有序动作及阶段 7.4 生命周期操作显式接线，不隐藏在护盾结果中。
15. 阶段 7.6 增加六种固定特殊结果：伤害修正、治疗修正、伤害免疫、生命下限、法术护盾和斩杀。连同两种联动结果，本阶段共增加八种结果，不提供自由结果类型。
16. 伤害修正、治疗修正及符合条件的持续属性修正必须按[乘区管理与修正结果补充共享契约](./乘区管理与修正结果补充详细设计.md)引用独立乘区；同区加算、跨区相乘、适用阶段和动态读取由该补充契约唯一拥有。本总契约不重复定义乘区字段，也不提前执行乘区聚合或舍入。
17. 伤害免疫只阻止匹配伤害，不等同法术护盾，也不自动阻止命中、状态或其他结果；生命下限允许伤害成立但把生命保持在公式给出的下限之上。
18. 斩杀读取目标当前生命属性和阈值公式，语义固定为当前值小于等于阈值时标记击杀结果；它不是一条超大真实伤害。
19. 阶段 7.5 的 `PRIOR_ACTION_RESULT + CONFIGURED_VALUE` 保持不变；阶段 7.6 在同一来源联合类型上增加原始伤害、防御后伤害、护盾吸收、实际扣血、实际治疗、阻挡、免疫、状态施加和击杀结果。
20. 丰富前序结果仍只能引用同一规则内排序更早的执行效果动作及其明确结果，不允许同效果内隐式依赖、后向引用、跨规则引用或跨技能公式引用。
21. 布尔结果统一以整数 0/1 提供给 `RUNTIME_INPUT` 参数；数值结果按小数来源处理。阶段 7.6 不保存某次实际值。
22. 阶段 7.6 增加 `DAMAGE_PENDING`、`HIT_LINK_APPLIED`、`ATTACK_LINK_APPLIED` 和 `SPELL_SHIELD_BLOCKED` 四种固定事件，并扩展 `DAMAGE_DEALT / DAMAGE_TAKEN` 的固定筛选和值能力。
23. `DAMAGE_PENDING` 只表示“防御后候选伤害已知、护盾吸收和生命扣除尚未发生”的固定观察点，用于斯特拉克类伤前护盾；本文不进一步冻结全部结算步骤的全局顺序。
24. 本阶段只保存、校验、回读和保护引用，不执行随机暴击、吸血、伤害修正、护盾吸收、法术护盾、命中联动、攻击联动、斩杀、公式、事件、计时、最终结算、计算预览或 Wasm。
25. `COOLDOWN_CHANGE.detail.affectedSkillKeys` 已是非空技能标识列表，但一个多目标冷却变化仍只有一个 `resultKey`、按操作共享的零或一套数值规则和一组结果级属性。`REDUCE / INCREASE` 共享一套数值规则，`RESET` 没有数值规则。阶段 7.6 的阻挡范围、修正和前序结果身份都作用于整个结果；不同技能需要不同数值、时点或阻挡行为时拆成不同结果。

## 2. 范围与非目标

本阶段交付：

2. 普通护盾的伤害类型限制与线性衰减语义。
3. 结果级法术护盾阻挡范围和法术护盾持续结果。
4. 伤害修正、治疗修正、伤害免疫、生命下限、斩杀、命中联动和攻击联动固定结果。

7. 新公式、伤害类型、属性、效果和结果引用的真实外键及删除保护。
8. 扩展后的无保护循环生产表、反伤闭环限制和稳定错误。

5. 自由事件、自由结果、自由修正器、脚本、字符串表达式、JSONB、数组外键或通用“对象种类 + 对象键”关系。
6. 角色技能和装备技能挂载、发布、计算预览、公式执行、实际事件分发或 Wasm。
7. 修改状态基本资料或增加状态分类。
8. 旧 Ability、Provider、combat-data 或旧 DPS 结构的迁移、兼容读取或双写。

## 3. 数据关系与责任方向

```text
游戏
└─ 技能
   ├─ 技能公式 / 属性 / 伤害类型
   ├─ 技能过程 ──步骤重复与时点
   ├─ 技能效果
   │  ├─ 可选生命周期
   │  └─ 技能效果结果
   │     ├─ 原八种结果
   │     ├─ 八种阶段 7.6 结果
   │     ├─ 可选法术护盾阻挡范围
   │     ├─ 伤害 → 暴击策略 / 吸血规则 / 伤害来源
   │     └─ 普通护盾 → 吸收类型 / 衰减方式
   └─ 技能触发规则
      ├─ 21 种固定事件
      ├─ 有序动作
      └─ 动态输入绑定
         └─ 更早动作结果 → 固定输出种类
```

责任方向固定为：

1. 特殊交互主动扩展结果；结果不反向修改公式、属性、伤害类型、过程或状态目录。
2. 暴击和吸血只属于伤害结果；其他结果不复制这些字段。
3. 法术护盾阻挡范围属于可能被阻挡的结果；`SPELL_SHIELD` 结果只表示阻挡能力存在，两者不是同一个字段。
4. 触发规则主动引用效果、结果和公式；效果不反向保存规则键。
5. 前序结果绑定只记录来源身份和值种类，不保存运行值或结果缓存。
6. 阶段 7.3 过程仍决定效果在哪个时点执行；阶段 7.6 的联动结果不反向引用过程步骤。

## 4. 扩展后的结果公共字段

每个结果在阶段 7.4 字段基础上增加：

```json
{
  "spellShieldBlockScope": null
}
```

`spellShieldBlockScope` 可为 null，非空只允许：

| 值 | 中文含义 |
| --- | --- |
| `SKILL` | 成功阻挡当前结果时，声明本次技能使用整体属于阻挡单元。 |
| `EFFECT` | 成功阻挡当前结果时，声明所属效果整体属于阻挡单元。 |
| `DAMAGE_INSTANCE` | 只阻挡当前这一伤害实例；仅 `DAMAGE` 可选。 |
| `RESULT` | 只阻挡当前结果。 |

规则：

1. `target = SOURCE` 时必须为 null；施加给来源对象的结果不能被当前目标的法术护盾阻挡。
2. `DIRECT_HEAL` 与 `NORMAL_SHIELD` 无论 `target` 和生命周期时点为何都必须为 null；直接治疗和普通护盾不是法术护盾的阻挡单元。
3. `DAMAGE_INSTANCE` 只允许伤害结果。
4. 生命周期持续生效结果必须为 null；阻挡判断只属于离散结果。
5. `SPELL_SHIELD`、伤害免疫、生命下限、伤害修正和治疗修正必须为 null。
6. 其他结果只有在 `target = TARGET`、生命周期时点不是持续生效且未被上述固定规则禁止时才允许非空；否则必须为 null。
7. null 不表示“无敌”或“免疫”，只表示法术护盾不处理该结果。
8. `SKILL / EFFECT` 的阻挡单元只包含相应技能使用或效果内 `spellShieldBlockScope` 非空且资格合法的离散结果；不得把 null 结果纳入阻挡单元。

## 5. 伤害结果扩展

`resultType = DAMAGE` 的 `detail` 扩展为：

```json
{
  "damageTypeKey": "physical",
  "deliveryKind": "SKILL",
  "originKind": "DIRECT",
  "critical": {
    "mode": "SOURCE_CRIT_CHANCE",
    "multiplierFormulaKey": null
  },
  "vampRules": [
    {
      "vampType": "LIFE_STEAL",
      "basisOutputKind": "POST_DEFENSE_DAMAGE",
      "efficiencyFormulaKey": "full_efficiency"
    }
  ]
}
```

### 5.1 伤害来源

`deliveryKind`：

| 值 | 中文含义 |
| --- | --- |
| `SKILL` | 技能过程或技能效果产生的伤害。装备能力同样作为技能维护，因此仍使用本值。 |
| `BASIC_ATTACK` | 普通攻击或明确修改普通攻击的伤害实例。 |

`originKind`：

| 值 | 中文含义 |
| --- | --- |
| `DIRECT` | 普通直接伤害。 |
| `REFLECTED` | 因受到攻击或伤害而新建、指向事件来源对象的反伤。 |

反伤仍必须由阶段 7.5 `DAMAGE_TAKEN` 等固定事件、`EVENT_SOURCE` 动作目标和明确伤害结果共同表达。只把 `originKind` 改为 `REFLECTED` 不会自动创建反伤关系。

### 5.2 暴击策略

| `mode` | 中文含义 | `multiplierFormulaKey` |
| --- | --- | --- |
| `DISALLOWED` | 本伤害不发生暴击。 | 必须为 null。 |
| `SOURCE_CRIT_CHANCE` | 未来按来源对象暴击率判定。 | 可空；非空时覆盖本结果暴击倍率。 |
| `FORCED` | 本伤害强制按暴击处理。 | 可空；非空时覆盖本结果暴击倍率。 |

倍率公式必须属于当前技能。阶段 7.6 只验证引用和字段形状，不执行公式、不静态判断结果是否大于 0。多段过程中每个伤害结果实例独立拥有本策略；共享还是独立采样由后续运行设计决定，本阶段不增加采样次数字段。

### 5.3 吸血规则

`vampType` 固定为：

1. `LIFE_STEAL`：生命偷取。
2. `OMNIVAMP`：全能吸血。
3. `PHYSICAL_VAMP`：物理吸血。
4. `SPELL_VAMP`：法术吸血。

`basisOutputKind` 只允许：

1. `POST_DEFENSE_DAMAGE`：防御处理后的伤害。
2. `ACTUAL_HP_LOSS`：实际扣除生命值。

`efficiencyFormulaKey` 必填并引用同技能公式。相同 `vampType` 不得重复；空数组表示该伤害不适用任何吸血。一次已解析伤害实例对每条规则产生一次吸血机会；多段伤害次数来自阶段 7.3，不能再提交 `vampCount`、等级 Map 或自由说明代替结构。

## 6. 普通护盾扩展

`resultType = NORMAL_SHIELD` 继续需要数值规则，`detail` 从空对象扩展为：

```json
{
  "absorbedDamageTypeKey": null,
  "decayMode": "NONE"
}
```

1. `absorbedDamageTypeKey` 可为 null；null 表示吸收所有伤害类型，非空时引用同一游戏启用伤害类型。
2. `decayMode` 只允许 `NONE / LINEAR_TO_ZERO`。
3. 普通护盾仍必须按阶段 7.4 作为生命周期持续生效结果；数值规则给出初始护盾量。
4. `LINEAR_TO_ZERO` 要求所属生命周期 `durationFormulaKey` 非空、`expiryMode = ALL_AT_ONCE`，且该护盾结果的 `stackValueMode = SHARED`；表示一个共享护盾量沿当前实例持续时间线性衰减至 0，不增加第二个衰减时长公式。`PER_STACK`、逐层到期和每层独立到期均禁止搭配线性衰减。
5. 匹配伤害消耗护盾至 0 时，未来语义为所属生命周期提前结束；自然到期仍使用阶段 7.4 自然结束。
6. 本阶段只保存语义，不实际扣减、衰减或产生护盾破裂事件。

## 7. 八种新增固定结果

### 7.1 伤害修正 `DAMAGE_MODIFIER`

需要数值规则，未来数值按比例解释；`detail`：

```json
{
  "direction": "TAKEN",
  "operation": "DECREASE",
  "damageTypeKey": null,
  "deliveryKind": "ANY",
  "originKind": "ANY",
  "criticalFilter": "CRITICAL_ONLY"
}
```

1. `direction = DEALT / TAKEN`。
2. `operation = INCREASE / DECREASE`。
3. `damageTypeKey` 可空；非空引用同游戏伤害类型。
4. `deliveryKind = ANY / SKILL / BASIC_ATTACK`。
5. `originKind = ANY / DIRECT / REFLECTED`。
6. `criticalFilter = ANY / CRITICAL_ONLY / NON_CRITICAL_ONLY`。
7. 只能是生命周期 `PERSISTENT` 结果，数值按施加时留存。

### 7.2 治疗修正 `HEALING_MODIFIER`

需要数值规则，未来数值按比例解释；`detail`：

```json
{
  "direction": "RECEIVED",
  "operation": "DECREASE",
  "healingKind": "ANY"
}
```

1. `direction = DONE / RECEIVED`。
2. `operation = INCREASE / DECREASE`。
3. `healingKind = ANY / DIRECT / VAMP`。
4. 只能是生命周期 `PERSISTENT` 结果，数值按施加时留存。

### 7.3 伤害免疫 `DAMAGE_IMMUNITY`

没有数值规则；`detail`：

```json
{
  "damageTypeKey": null,
  "deliveryKind": "ANY",
  "originKind": "ANY"
}
```

过滤值与伤害修正相同。它只能是生命周期 `PERSISTENT` 结果；不会自动阻止命中联动、攻击联动、状态或非伤害结果。

### 7.4 生命下限 `HEALTH_FLOOR`

需要数值规则；`detail`：

```json
{ "attributeKey": "hp" }
```

属性必须是同游戏启用数值属性。数值规则未来给出绝对下限，可以通过公式读取目标最大生命并乘比例。它只能是生命周期 `PERSISTENT` 结果。

### 7.5 法术护盾 `SPELL_SHIELD`

没有数值规则，`detail = {}`。它只能是生命周期 `PERSISTENT` 结果。成功阻挡由第 9 节固定事件表达，持续时间和移除继续使用阶段 7.4 生命周期。

### 7.6 斩杀 `EXECUTE`

需要数值规则；`detail`：

```json
{ "attributeKey": "hp" }
```

数值规则未来给出绝对斩杀阈值。它是离散结果，不允许 `PERSISTENT`；是否满足阈值和是否击杀只形成结果输出，本阶段不执行。

### 7.7 命中联动应用 `HIT_LINK_APPLICATION`

需要数值规则，未来结果按非负整数解释；`detail = {}`。数值表示本次应用命中联动的次数。它是离散结果，不允许 `PERSISTENT`。

### 7.8 攻击联动应用 `ATTACK_LINK_APPLICATION`

需要数值规则，未来结果按非负整数解释；`detail = {}`。数值表示本次触发攻击联动的次数。它是离散结果，不允许 `PERSISTENT`。

### 7.9 与阶段 7.4 生命周期字段组合

本节扩展阶段 7.4 的持续结果白名单，不替换原有普通护盾、属性变化和状态施加规则：

| 结果 | `moment` | `valueReadMode` | `stackValueMode` | `reapplicationValueMode` |
| --- | --- | --- | --- | --- |
| `DAMAGE_MODIFIER`、`HEALING_MODIFIER` | 必须 `PERSISTENT` | 必须 `APPLICATION_SNAPSHOT` | `SHARED / PER_STACK` | `SHARED` 时必填 `KEEP / REPLACE / ADD`；`PER_STACK` 时必须 null。 |
| `HEALTH_FLOOR` | 必须 `PERSISTENT` | 必须 `APPLICATION_SNAPSHOT` | 只允许 `SHARED` | 必填，只允许 `KEEP / REPLACE`；生命下限不按层相加。 |
| `DAMAGE_IMMUNITY`、`SPELL_SHIELD` | 必须 `PERSISTENT` | 必须 null | 必须 null | 必须 null。 |
| `EXECUTE`、`HIT_LINK_APPLICATION`、`ATTACK_LINK_APPLICATION` | 禁止 `PERSISTENT`；可使用所属生命周期允许的离散时点 | 按阶段 7.4 对该离散时点的数值读取规则 | 必须 null | 必须 null。 |

五种持续特殊结果是伤害修正、治疗修正、伤害免疫、生命下限和法术护盾。斩杀、命中联动和攻击联动是三种离散结果。`PERIODIC` 时仍按阶段 7.4 填写 `periodicExecutionMode`，其他时点必须为 null。

## 8. 次数边界

1. 伤害次数：仍由阶段 7.3 `MULTI_HIT / PERIODIC / CHANNEL` 等步骤的执行次数及效果挂接时点形成，每次执行一个伤害结果即形成一个伤害实例。
2. 吸血次数：每个已解析伤害实例对它拥有的每条吸血规则提供一次机会；没有吸血规则即为零次。
3. 命中联动次数：由 `HIT_LINK_APPLICATION.valueRule` 独立给出。
4. 攻击联动次数：由 `ATTACK_LINK_APPLICATION.valueRule` 独立给出。
5. 需要“伤害五次、生命偷取五次、命中联动一次”时，使用五次伤害实例和一次命中联动结果，不得把伤害乘五后再使用布尔开关。
6. 需要延迟再次应用命中联动时，把命中联动结果挂到延迟步骤时点，不在结果中保存延迟毫秒。

## 9. 固定事件扩展

阶段 7.5 的 17 种事件保持身份不变，阶段 7.6 增加四种，总数变为 21 种：

| `eventType` | 中文含义 | 必填明细 |
| --- | --- | --- |
| `DAMAGE_PENDING` | 来源对象即将承受一次防御后候选伤害 | `damageTypeKey` 可空、`deliveryKind`、`originKind`。 |
| `HIT_LINK_APPLIED` | 来源对象应用一次命中联动 | 可空 `sourceSkillKey`；空表示任意技能产生。 |
| `ATTACK_LINK_APPLIED` | 来源对象触发一次攻击联动 | 可空 `sourceSkillKey`；空表示任意技能产生。 |
| `SPELL_SHIELD_BLOCKED` | 当前技能的法术护盾成功阻挡敌对结果 | `shieldEffectKey`，必须引用当前技能中含 `SPELL_SHIELD + PERSISTENT` 的生命周期效果。 |

同时把原本明细为 `{}` 的 `DAMAGE_DEALT / DAMAGE_TAKEN` 扩展为与 `DAMAGE_PENDING` 相同的筛选对象：

```json
{
  "damageTypeKey": null,
  "deliveryKind": "ANY",
  "originKind": "ANY"
}
```

`damageTypeKey` 可空，非空引用同游戏伤害类型；`deliveryKind = ANY / SKILL / BASIC_ATTACK`；`originKind = ANY / DIRECT / REFLECTED`。已有空明细在阶段 7.6 迁移时明确转为三个 ANY/null 字段，响应不再返回空对象。

### 9.1 事件上下文能力

| `eventType` | 当前目标 | `EVENT_SOURCE` | 允许事件值 |
| --- | --- | --- | --- |
| `DAMAGE_PENDING` | 来源对象自身 | 有，为候选伤害来源对象 | `RAW_DAMAGE`、`POST_DEFENSE_DAMAGE`、`HEALTH_BEFORE`、`PROJECTED_HEALTH_AFTER`。 |
| `DAMAGE_DEALT` | 本次伤害承受对象 | 无 | `RAW_DAMAGE`、`POST_DEFENSE_DAMAGE`、`SHIELD_ABSORBED`、`ACTUAL_HP_LOSS`、`BLOCKED`、`IMMUNE`、`KILLED`。 |
| `DAMAGE_TAKEN` | 来源对象自身 | 有，为本次伤害来源对象 | 与 `DAMAGE_DEALT` 相同。 |
| `HIT_LINK_APPLIED` | 本次联动目标 | 无 | `LINK_INDEX`、`LINK_COUNT`。 |
| `ATTACK_LINK_APPLIED` | 本次联动目标 | 无 | `LINK_INDEX`、`LINK_COUNT`。 |
| `SPELL_SHIELD_BLOCKED` | 法术护盾承受对象，即来源对象自身 | 有，为被阻挡结果的来源对象 | 无。 |

数值类型：伤害、护盾、生命值为 `DECIMAL`；`LINK_INDEX / LINK_COUNT` 为从 1 开始的 `INTEGER`；`BLOCKED / IMMUNE / KILLED` 为提供 0/1 的 `INTEGER`。事件只保存固定身份和值能力，不实际生成值。

固定观察点只冻结到以下程度：`DAMAGE_PENDING` 在候选防御后伤害可用、护盾吸收和生命扣除尚未发生时匹配；`DAMAGE_DEALT / DAMAGE_TAKEN` 在阻挡、免疫、护盾吸收、实际扣血和击杀结果已经可观察后匹配；`KILL / ENTITY_DIED` 仍使用阶段 7.5 的独立事件身份。多个修正、暴击、防御、护盾和舍入如何得到这些观察值，继续留给后续结算设计。

### 9.2 反伤与伤前规则保护

1. 任一规则的 `EXECUTE_EFFECT` 动作目标效果含 `originKind = REFLECTED` 的伤害结果时，该规则事件只能是 `DAMAGE_PENDING / DAMAGE_TAKEN`，动作目标必须是 `EVENT_SOURCE`，并且规则自己的 `eventSource.detail.originKind` 必须为 `DIRECT`，或者规则配置合法每目标冷却。不能从其他事件创建反伤，也不能用 `ANY / REFLECTED` 创建无保护反馈。
2. `DAMAGE_PENDING` 规则可以先执行普通护盾、伤害免疫或生命下限效果；它不能引用本次尚未产生的 `SHIELD_ABSORBED / ACTUAL_HP_LOSS / KILLED`。
3. `SPELL_SHIELD_BLOCKED` 规则执行移除护盾、治疗或启动延迟过程时，继续纳入阶段 7.5 规则图；不得在护盾结果中隐藏动作。

## 10. 丰富前序结果来源

`PRIOR_ACTION_RESULT.detail` 形状不变：

```json
{
  "sourceActionKey": "primary_damage",
  "sourceResultKey": "damage",
  "outputKind": "ACTUAL_HP_LOSS"
}
```

`outputKind` 固定表：

| `outputKind` | 值类型 | 合法来源结果 |
| --- | --- | --- |
| `CONFIGURED_VALUE` | `DECIMAL` | 阶段 7.5 既有规则：任意具有 `valueRule` 的即时结果。 |
| `RAW_DAMAGE` | `DECIMAL` | `DAMAGE`。 |
| `POST_DEFENSE_DAMAGE` | `DECIMAL` | `DAMAGE`。 |
| `SHIELD_ABSORBED` | `DECIMAL` | `DAMAGE`。 |
| `ACTUAL_HP_LOSS` | `DECIMAL` | `DAMAGE`。 |
| `ACTUAL_HEALING` | `DECIMAL` | `DIRECT_HEAL`；或至少拥有一条吸血规则的 `DAMAGE`。 |
| `BLOCKED` | `INTEGER 0/1` | `spellShieldBlockScope` 非空的离散结果。 |
| `IMMUNE` | `INTEGER 0/1` | `DAMAGE`。 |
| `STATUS_APPLIED` | `INTEGER 0/1` | `STATUS_OPERATION + APPLY`。 |
| `KILLED` | `INTEGER 0/1` | `DAMAGE / EXECUTE`。 |

多目标冷却变化结果只按 `sourceResultKey` 产生一个前序结果候选。仅当结果具有 `valueRule` 时，才由共享数值规则形成一个 `CONFIGURED_VALUE`，且不按 `affectedSkillKeys` 展开；`RESET` 没有该输出。

`CONFIGURED_VALUE` 始终表示来源结果自身保存的数值规则，不表示同乘区加算值、乘区因子或最终修正值。使用 `MOMENT_EVALUATION` 的持续修正仍属于持续生效结果，不因此获得同轮前序结果输出。

规则：

1. 来源动作仍必须是同一规则中排序更早的 `EXECUTE_EFFECT`。
2. 来源结果必须属于来源动作目标效果；无生命周期或 `APPLICATION` 结果才允许作为同一轮动作序列来源。
3. 来源类型必须与目标 `RUNTIME_INPUT` 参数兼容；整数可以绑定整数或小数，其他来源只能绑定小数。
4. 不允许同动作、后向、跨规则、跨技能、持续、满层、周期、自然结束或提前移除结果。
5. 数值结果未实际产生时未来固定提供 0；布尔结果固定提供 0/1。阶段 7.6 不保存这些值。
6. 需要根据丰富结果决定是否执行另一组动作时，使用本阶段固定事件建立另一条规则，不在阶段 7.5 条件组中增加“执行到一半再判断”的动作内条件。
7. `DAMAGE + ACTUAL_HEALING` 表示该伤害结果全部适用吸血规则最终形成的实际治疗合计，不表示某一种吸血规则的单独值；需要区分来源时拆分伤害结果，不增加自由吸血键引用。

## 11. 可达公式扩展

阶段 7.5 的动作可达公式封闭表增加：

1. `DAMAGE`：暴击倍率公式和全部吸血效率公式。
2. `NORMAL_SHIELD`：仍只收集结果数值规则；衰减不新增公式。
3. `DAMAGE_MODIFIER / HEALING_MODIFIER / HEALTH_FLOOR / EXECUTE / HIT_LINK_APPLICATION / ATTACK_LINK_APPLICATION`：结果数值规则。
4. 新伤害事件筛选不引用公式；`DAMAGE_PENDING` 阈值继续由既有 `EVENT_VALUE_COMPARE` 条件公式表达。

执行效果或启动过程动作到达上述公式时，公式使用的 `RUNTIME_INPUT` 参数仍必须恰好拥有一个绑定。事件筛选和保护公式仍不得引用 `RUNTIME_INPUT`。

## 12. 聚合、引用与修改规则

1. 效果 POST/PUT 一次维护效果、生命周期、全部结果、特殊明细、暴击、吸血和法术护盾阻挡范围；任一失败全部回滚。
2. 触发规则 POST/PUT 一次维护事件、条件、动作、绑定和保护；新事件明细与丰富输出种类不提供独立接口。
3. 已有结果的 `resultType` 继续不可修改；伤害 `deliveryKind / originKind`、暴击模式、吸血规则、普通护盾明细和 `spellShieldBlockScope` 可全量修改，但必须通过引用和形状校验。
4. 删除或改种类被前序结果绑定引用的结果，继续返回 `409.SKILL_EFFECT_IN_USE`；改变伤害吸血规则使 `ACTUAL_HEALING` 不再可用同样视为破坏引用。
5. 删除被暴击、吸血、特殊结果或伤害事件引用的公式、伤害类型、属性、效果和结果必须返回现有稳定冲突，不依赖外键异常转 500。
6. 删除技能时先删除自身触发规则，再删除过程、效果特殊子表和结果，最后清理内部状态、公式、参数和技能；其他技能的 `sourceSkillKey` 仍阻止删除。
7. 修改效果、结果、生命周期或规则后，按第 13 节封闭生产表对当前技能规则图重新检查。
8. 停用目录允许旧引用原样回读；新增或改选停用目录继续返回引用停用错误。
9. 阶段 7.6 compatibility migration 必须把每个既有 `DAMAGE` 的 `deliveryKind/originKind` 回填为 `SKILL/DIRECT`，补一条 `DISALLOWED + null multiplier` 暴击策略，并为每个既有 `NORMAL_SHIELD` 补一条“全部伤害 + `NONE` 衰减”交互；这些只把此前没有的能力显式化，不是业务样本或运行兼容层。

## 18. 跨端验收案例

本节描述阶段 7.6 全部完成后的综合目标，不要求阶段 7.6.1 一次通过全部案例。分段归属固定为：7.6.1 验证伊泽瑞尔 Q 的伤害/暴击/吸血部分、荆棘之甲和普通护盾基础；7.6.2 验证斯特拉克与持续修正；7.6.3 验证希维尔 E 及结果阻挡范围；7.6.4 验证艾希 Q、鬼索和收集者的结果/事件骨架；7.6.5 再验证所有丰富前序输出和七个案例的完整组合。

### 18.1 艾希 Q

1. 多段过程形成五次伤害实例。
2. 伤害标记为 `BASIC_ATTACK + DIRECT`，配置生命偷取规则。
3. 单独保存一次 `HIT_LINK_APPLICATION` 和一次 `ATTACK_LINK_APPLICATION`。
4. 保存、关闭、刷新和后端重启后仍能区分五次伤害/吸血与一次联动。

### 18.2 伊泽瑞尔 Q

1. 伤害为物理、`SKILL + DIRECT`，不允许或按配置允许暴击。
2. 分别配置生命偷取、全能吸血、物理吸血，不配置法术吸血。
3. 伤害结果使用 `spellShieldBlockScope = RESULT`；冷却减少结果为 null。
4. 另存一次命中联动和一次攻击联动；完整回读后仍显示“伤害可被阻挡，冷却减少不被阻挡”。

### 18.3 希维尔 E

1. 生命周期效果含 `SPELL_SHIELD + PERSISTENT`。
2. `SPELL_SHIELD_BLOCKED` 规则引用该效果，先移除护盾，再启动 0.25 秒延迟过程并执行治疗和增益效果。
3. 页面能完整回读护盾、事件、动作顺序和延迟过程，不显示实际阻挡或治疗值。

### 18.4 荆棘之甲

1. `DAMAGE_TAKEN` 过滤 `deliveryKind = BASIC_ATTACK`、`originKind = DIRECT`。
2. 规则动作目标为 `EVENT_SOURCE`，执行 `originKind = REFLECTED` 的魔法伤害和重伤状态效果。
3. 把事件过滤改为 `ANY` 且移除每目标冷却时，后端拒绝为 `REFLECT_LOOP_UNGUARDED`。

### 18.5 鬼索的狂暴之刃

1. 既有内部状态保存幻影层数。
2. 满层触发规则启动含 0.15 秒延迟步骤的过程。
3. 延迟步骤执行一次 `HIT_LINK_APPLICATION`，不是把当前伤害简单乘二。

### 18.6 斯特拉克的挑战护手

1. `DAMAGE_PENDING` 提供 `PROJECTED_HEALTH_AFTER`。
2. 条件把该值与目标最大生命 30% 公式比较，满足时先执行普通护盾效果。
3. 护盾 `decayMode = LINEAR_TO_ZERO`，生命周期持续 4.5 秒并配置每目标或技能冷却保护。
4. 页面重开后能区分伤前触发、护盾数值、线性衰减和冷却，不执行结算。

### 18.7 收集者

1. `DAMAGE_DEALT` 过滤非反伤来源，条件读取目标当前生命并与 5% 最大生命公式比较。
2. 有序动作执行 `EXECUTE`，阈值公式完整回读。
3. 后续动作可把 `KILLED` 作为 0/1 前序结果供值；本阶段不发金币或执行死亡奖励。

### 18.8 反例

以下请求必须失败且原聚合保持不变：

1. 非伤害结果携带暴击或吸血字段。
2. 同一伤害重复 `LIFE_STEAL`。
3. `DISALLOWED` 暴击仍提交倍率公式。
4. `DAMAGE_INSTANCE` 用在非伤害结果。
5. 线性衰减普通护盾没有自然持续时间。
6. `SPELL_SHIELD` 不在 `PERSISTENT`。
7. `ACTUAL_HEALING` 引用没有吸血规则的伤害结果。
8. `DAMAGE_PENDING` 读取 `ACTUAL_HP_LOSS`。
9. 反伤规则接受 `REFLECTED` 且无任何保护。
10. 伤害结果提交自由 `vampCount`，试图绕过过程次数和吸血规则。
11. 前序结果引用 `PERSISTENT`、同动作、后续动作或跨技能动作结果。
12. `DAMAGE_PENDING` 读取 `SHIELD_ABSORBED` 或 `KILLED`。
13. 暴击、吸血或特殊结果公式引用另一技能公式。
14. 规则从伤害事件之外执行反伤效果，或反伤动作目标不是事件来源对象。
15. 线性衰减护盾使用 `PER_STACK`、逐层到期或每层独立到期。
16. 直接治疗或普通护盾提交非空 `spellShieldBlockScope`。

## 19. 后续依赖标记

本节只登记方向，不展开后续详细设计：

1. 未来计算输入组装需要把本阶段结构映射为执行上下文和结果输出，但不得反向改变本阶段稳定标识。
2. 未来结算设计需要确定已冻结乘区聚合进入暴击、防御、护盾、生命扣除、吸血和死亡链路的精确顺序与舍入。
3. Wasm 需要另行形成共享 ABI 和执行方案；本阶段不预留 Wasm 字段。

## 20. 停止门禁

出现以下任一情况必须停止并回到方案确认：

1. 阶段 7.6.2 及乘区补充的最终接口、表、事件能力、动作顺序、动态输入绑定、乘区约束或循环图与本方案前提不一致。
2. 实现需要修改 7.1 状态分类边界，或把特殊交互保存为状态分类、自由标签、JSONB、数组或通用多态关系。
3. 实现需要新增效果结果子接口、事件子接口或独立半成品页面才能保存。
4. 实现需要执行公式、随机数、伤害、护盾、吸血、事件、结算、预览、发布或 Wasm 才能完成管理功能。
5. 实现需要提前冻结完整结算顺序、跨技能挂载或运行时对象模型。
6. 代表案例无法用固定结果、固定事件、过程、生命周期和有序动作表达，必须引入样本专用字段。
7. 完整后端测试、前端验证、真实迁移、真实接口或真实浏览器验收不可用，且无法定点确认原因。
8. 实现方试图用一个迁移、一个编码运行或一次综合验收直接完成全部阶段 7.6。

在主会话内部闭环评审关闭问题且项目负责人明确确认当前子阶段前，只允许修改阶段 7.6 总设计、7.6.3～7.6.5 增量设计和既有任务映射，不得进入代码、数据库或服务操作。
