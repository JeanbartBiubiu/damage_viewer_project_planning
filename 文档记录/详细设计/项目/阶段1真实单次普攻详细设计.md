六阶段顺序、共享数据读取和属性责任、机制取舍继续由总方案第1、3、4.1、4.2节定义；本文件是阶段1单次请求约定、展示字段和任务行为的详细来源。既有引擎请求与结果以[通用类型](../../../web/src/types/genericEngine.ts)及对应Wasm模型为准，不新增另一套运行协议，不重做前置数据适配。

## 1. 目标、范围与非目标

用户在现有普攻页面选择A/B及等级、完整共享普攻及等级，读取场景并明确补充必要输入，点击“执行一次普攻”。同一个真实浏览器工作线程依次完成编译、一次运行和释放。结果区直接说明本次伤害与B生命变化，用户不需要通过编译统计判断有没有扣血。

首批真实样本复用亚托克斯／阿狸，双方等级1、`shared_basic_attack`（共享普通攻击）等级1。样本选择不是页面默认值；读取最新真实配置并保存快照后，以该快照作为本次输入。A只有所选共享普攻，B不自主攻击，装备、构筑和其他英雄技能均不选入。原共享普攻全部开始、命中、伤害与联动结果及实际依赖必须保留。

本阶段不开发连续攻击、统一攻击时钟、图表、装备、英雄被动或主动技能；不新增场景保存接口，不写业务数据。控制行动限制、特殊普攻和未接入作者结构继续沿总方案明确拒绝，不能过滤原配置后假称支持。

阶段1只对正常存活双方进行主运行验收。初始当前生命0仍是合法的死亡状态，可保留输入并用于现有编译检查；单次运行入口增加本阶段专属的正生命前置校验，分别提示“攻击方初始已死亡”或“目标初始已死亡”，不开始运行任务，不自动改满血，也不制造本次击杀。这不改变通用装配器允许0的契约；原生死亡边界另做构造检查，不能据其返回的停止原因宣称已完成本次攻击。

## 3. 输入与单次请求约定

### 3.1 输入冻结及失效

执行使用当前已读完整快照及本次显式补充属性、双方初始当前生命。点击执行后立即占用任务引用，再冻结输入副本；准备、编译和运行期间不能修改输入。运行不暗中重新读取服务器或拼接另一份配置；需要最新数据时由用户重新读取场景，得到新的完整快照后再执行。

固有等级属性不能被补充输入覆盖，附加属性、类型、范围与正攻速校验沿总方案和现有装配器；本阶段不增加默认零值。初始生命未填与明确0使用不同提示，正常单次运行要求双方当前生命大于0且不超过真实上限。

三个等级采用下拉选择且不默认选值。A/B共用当前游戏等级配置的最小／最大等级；普攻使用所选技能的1至最高等级。范围未返回或读取失败时禁用对应控件，失败提供重试，不猜1～18或默认1级；切换普攻清空旧技能等级，全部合法等级明确选择后才允许读取场景。沿现有等级配置与技能详情接口读取，不新增后端契约。

改变A/B、等级或普攻选择使场景快照及派生产物失效；改变补充属性或初始生命只使准备请求、编译结果、单次结果及档案失效。连接、游戏或令牌改变清空整个旧场景并终止任务。重新读取开始只清除派生产物；成功读取并检查新快照后重置补充值及初始生命，失败或取消保留旧快照、当前选择和已填输入。运行失败或同一环境下取消也保留输入，不保存管理数据。

### 3.2 复用的请求模板

以本次新编译得到的会话生成现有单次模板，不用编译档案中已经释放的会话。下列约定来自[场景装配器](../../../web/src/engine/simulationAdapter.ts)，只用于当前瞬时单次普攻：

| 项目 | 固定约定及含义 |
| --- | --- |
| 角色键 | 运行时角色键为 `source/target`（攻击方／目标），与原英雄稳定标识分开；数据归属按请求角色键匹配。 |
| 初始快照 | 时间0，属性及资源从本次编译输入复制；A保留真实所选挂载，B无挂载；使用账本、过程实例、护盾和状态为空，不沿用前次结果。 |
| 驱动 | 两条单次条目：`first_attack_start`（发起）、`first_attack_hit`（命中）；均为0毫秒，优先级0、1，无重复或就绪循环。 |
| 使用身份 | 同一 `first_attack_use`（本次使用）连接开始、命中及过程；命中序号1，保留明确历史事实。此固定键只在当前独立运行内使用，不复用前次会话或账本。 |
| 停止策略 | `durationMs=1`（1毫秒观察上限），目标死亡及无事件时停止；它不是攻击耗时、普攻间隔或击杀时间模型。 |
| 采样 | 间隔100毫秒、窗口100毫秒、最多10点；阶段1不新增关闭采样字段，不用非正间隔冒充关闭。采样关闭及预算隔离属于阶段2。 |
| 安全预算 | 复用当前编译设置：事件10000、每事件命令256、队列10000、链深32。不开放预算编辑控件，也不临时调大预算来通过失败场景。 |

开始和命中虽然同刻，仍需沿稳定顺序执行；即时作者步骤不替代实际命中。当前同步伤害、联动及吸血在该调用中完成，不等待下一次普攻冷却。后续若选入延时结果或复杂过程，本阶段按原范围拒绝，不扩大观察窗把它们偷偷纳入。

正常单次运行可能在0毫秒以 `no_events`（没有后续事件）结束；致死时也可能为0毫秒且没有采样点。不能要求结果时长等于1毫秒，不能要求非空时间序列，也不计算以0毫秒为分母的伤害率。

## 4. 任务流程与会话清理

### 4.1 单次任务顺序

1. 校验场景已读取、必需输入已填及阶段1正生命条件。未通过时定位字段，不建立工作线程。
2. 以同步任务引用阻止重复点击，冻结快照与输入，清除旧派生结果，保留输入草稿；开始准备请求。
3. 建立本任务独占的通用客户端，编译后核对 `ok/sessionId/schemaHash/rulesHash`（通过标记／会话／结构摘要／规则摘要）。缺会话或摘要不符不进入运行。
4. 从本次编译请求及会话生成单次请求，调用现有 `run`，仅执行一次，不自动重试。
5. 核对有效返回、最终快照摘要、角色键、必需数值及第5节单次完整性；保存实际结果，不由前端求伤害公式。
6. 在线程仍存活且持有本任务会话时正常释放，核对释放结果的会话与通过标记；无论释放成功与否，最后终止线程。
7. 只有当前任务身份仍有效时发布结果、错误和档案并解除忙碌；旧任务的结果及最终清理不能覆盖新任务。

运行结果没有独立的会话或运行编号字段；任务身份依现有客户端消息匹配、任务引用和拥有的会话保持，不虚构返回字段。摘要校验读取 `finalSnapshot.schemaHash/rulesHash`（最终快照摘要）并与本次请求比较。

### 4.2 销毁后的旧会话不可释放

当前客户端会在运行超时或线程崩溃后销毁线程，下一次发送会重新建立空线程。因此不能在这些错误后无条件调用释放，否则会向新线程提交旧会话。

阶段1为[通用客户端](../../../web/src/engine/genericEngineClient.ts)增加只读查询 `hasLiveWorker`（是否仍持有存活工作线程）；它反映现有创建、销毁和终止路径，不建立第二份会话注册表，不改变Wasm协议。客户端每个任务独占且只按编译、运行、清理顺序调用，线程销毁后不主动重建，因此此查询足以控制本任务收尾。若线程已经销毁，跳过旧会话释放并记录清理方式为“销毁线程”，不能通过错误消息文字猜测，也不能自动重新编译和重跑。

普通运行错误而线程仍存活时继续尝试正常释放。没有生成会话时只终止已建立线程，不生成假释放结果。取消及确认离开立即终止任务线程，不排队等待同步计算中的释放调用；它们不是成功运行或正常释放。

现有30秒超时只覆盖已经发送的运行请求，不覆盖初始化、编译或释放。阶段1保留该边界及明确取消入口，不把它描述成整项任务30秒超时，不另造重试或全局超时系统。

## 5. 真实结果解释与通过判据

### 5.1 最小展示字段

| 展示内容 | 实际来源与口径 |
| --- | --- |
| 本次A/B、等级、普攻 | 冻结的业务快照和选择，不用返回中的 `source/target` 冒充英雄稳定标识。 |
| 本次造成伤害 | `summary.sourceDamageDealt`：A造成的防御后、护盾前伤害，不是B实际扣血，也不是编译统计。 |
| B运行前／后生命 | 前值取本次运行请求中的B当前生命；后值取 `summary.targetFinalHp`，并与最终快照B的 `attributes.hp.current` 一致性核对。 |
| B实际生命损失 | 前值减后值，仅解释返回的生命变化；完整证据下与本次B伤害行的 `actualHpLoss` 之和核对。首批无护盾、回复或其他目标来源，不能把造成伤害直接当此值。 |
| A最终生命 | `summary.sourceFinalHp`，与最终快照A当前生命核对；保留可能来自已读吸血规则的变化，不假定一定等于初值。 |
| 执行结论 | 单次业务完成、未完整验证、运行失败或取消，结合下节证据判断，不仅依据 `DoneResult.ok`。 |
| 清理结论 | 正常释放并终止线程、线程已销毁、释放失败或尚未清理；与伤害结果分开。 |
| 停止原因与警告 | 原 `summary.stopReason` 及 `warnings` 转为中文说明，原码和路径保留在调试详情。 |

本阶段不展示从能力尝试或施放计数换算的攻击次数，不展示伤害率或连续击杀耗时。派生字段只解释、求和及核对已输出事实，不重新计算暴击、抗性或伤害公式。

### 5.2 伤害与身份的证据边界

伤害证据 `kind=damage`（伤害）实际含 `source/target/damageType/rawAmount/mitigatedAmount`（双方／类型／防御前后金额），正常结算另含 `damageId/postDefenseDamage/shieldAbsorbed/actualHpLoss/overkillDamage`（伤害标识／防御后金额／护盾吸收／实际扣血／过量伤害）及五阶段、暴击信息。`rawAmount` 已经过暴击与造成伤害修正；暴击前金额读取 `baseRawAmount`。只读取实际有限数值，缺字段不能补0或接受数字字符串。

不存在 `resolvedAmount/hpLoss/targetHpAfter`（假定的结算额／扣血／逐笔剩余生命）字段；伤害行也没有直接输出 `providerRef/useRef/skillKey`（挂载／使用身份／技能标识）。其归属依 `abilityRef/operationRef/castInstanceId`（能力／操作／施放实例）及本次编译定义核对，从能力标识解析实际来源挂载，不能把不存在的挂载字段设为必填。阶段1只有一个所选来源和一次使用，可结合命中、联动证据说明关联，但必须标明是当前单次场景的关联，不能伪装成通用逐击事实输出。最终剩余生命读取汇总及最终快照，不根据伤害行制造逐笔生命时间线。

### 5.3 业务完成与清理成功分开

单次业务完成须同时满足：

- 编译通过、会话及摘要有效，实际运行返回有效 `DoneResult`，最终角色与摘要匹配；B没有自主驱动或造成伤害。
- `emitted_event`（已发事件）证据中，本次来源的原生普攻开始和命中各一次；不能使用能力施放总数替代。命中、过程和联动的使用身份与单次请求一致。
- 最终过程实例成功完成；全部所选作者结果及联动应用可由覆盖清单和完整证据核对。联动次数按原固定值或原公式，不一律假定为1；0次仍需应用证据但不要求发联动事件。
- 伤害汇总、实际扣血和最终生命有限且一致；正常0伤害允许完成命中和联动，不能按“伤害为0”判定未执行。
- 没有过程拒绝、预算停止、运行错误或证据截断。原警告完整显示；未知或影响正确性的警告不允许通过，不能统一隐藏或忽略。

`no_events`、`duration_reached`（观察上限）或 `target_dead`（目标死亡）只有在上述完整证据同时成立时才可标单次完成；正常单次并不要求停止码固定为某一个。`budget_exceeded`（预算耗尽）即使伴随 `ok=true` 或B生命已为0，也不能标完整验收通过；已返回的生命归零事实保留，不抹去或伪造成本阶段已验证的完整击杀。来源死亡、双方死亡、未知停止码及缺失必要证据均报告未完整验证或失败。

只有单次业务完成、正常释放响应有效且线程最终终止，才显示“单次普攻运行通过”。运行已完成但释放失败时仍可显示真实伤害和生命，另标“运行已返回，清理失败”，不出现整体通过提示。证据截断时可显示有效汇总及“明细不完整”，不能据截断前的几条记录通过完整性核对。

命令、链深或公式错误可能只有错误帧而没有可用的部分运行结果；此时显示错误及路径，主结果标“尚无有效运行结果”，不得把初始生命或0伤害填成运行结果。

## 6. 页面交互与失效保护

复用 `#/simulation/basic-attack`（普攻模拟）和已有场景输入，新增主操作“执行一次普攻”。原“编译验证”继续是独立诊断入口，执行一次不要求用户先点它。读取、补零和明确满生命工具保留；运行结果放在主要结果区，编译统计、请求与引用覆盖放在调试详情或下载区。

| 情况 | 页面行为 |
| --- | --- |
| 缺场景或必要输入 | 禁用执行入口或定位具体输入错误；未填生命与明确0分别解释。 |
| 准备、编译、运行、释放中 | 显示对应中文状态；冻结输入与其他任务入口，保留取消按钮。新增 `running`（运行中）阶段，任务引用同步互斥，不能仅依赖按钮禁用。 |
| 同一环境下失败或取消 | 保留当前快照、选择与输入；显示失败阶段、原对象／字段路径，不显示旧成功结果。 |
| 修改选择或显式输入 | 按第3.1节清除失效结果；重新运行用新任务和新会话，不复用旧线程状态。 |
| 切模式、改连接、游戏或令牌 | 沿现有壳层确认和清理；拒绝离开保留地址、模式及当前任务，确认后终止线程并丢弃迟到回复。 |
| 重复点击、旧请求迟到 | 同一时刻只接受一个任务；结果与收尾均核对当前任务引用，旧错误不能清除新任务忙碌或覆盖新结果。 |

结果标题与提示须区分“仅编译验证通过”“单次普攻运行通过”“连续攻击尚未接入”。新增运行后同步修改当前页面顶部说明，不宣称连续攻击或图表已完成。

## 7. 单次档案

沿当前编译档案方式，新增独立的单次运行档案。字段白名单如下；不导出整项UI任务或客户端对象。

| 字段组 | 内容 |
| --- | --- |
| 类型与结论 | `taskKind=single_attack`（单次攻击任务）、整体结论、业务执行与清理结论、失败阶段及错误。它是业务档案标识，不是新Wasm协议。 |
| 数据与输入 | 原完整快照及摘要、对象选择与等级、显式属性补充值及初始生命、适配器版本、实际Wasm字节数与摘要。 |
| 请求与映射 | 实际编译请求、覆盖清单、实际提交的单次 `runRequest`（运行请求），保留初始快照、驱动、使用身份、停止策略、采样和预算。 |
| 原始结果 | 编译结果、实际 `runResult`（运行结果）、原始警告与证据、释放结果及清理方式；尚未执行的步骤用空值，不生成假结果。 |
| 展示解释 | 本次结果区采用的业务解释及完整性检查结论，原始结果仍保留供复核。 |

档案只在已准备真实请求后提供；准备失败继续定位输入，不为其制造编译或运行请求。编译失败的档案可保留真实编译错误，运行请求和结果为空。输入变化使旧档案入口失效。

禁止记录API基址、令牌、鉴权头、Cookie、请求选项、浏览器存储、控制器或工作线程对象；也不把这些值混入规则摘要。界面现有连接设置不因此改变。致死时空时间序列原样保存，不用补采样点制造数据。

## 9. 验收矩阵

人工数值只属于独立构造配置，不是正式英雄属性。用当前独立作者用例与对应机制测试组织场景，不修改或复制 `generic_p0_basic_damage.json`（通用基准样例）来迁就实现。人工配置也经过实际适配与最终Wasm路径；不通过覆盖真实角色固有属性或写数据库制造测试输入。

| 用例 | 核对内容 |
| --- | --- |
| 基础单击 | 独立配置：攻击力100、护甲100、暴击0、穿透0、无盾，B初始生命300；原公式给出防御后伤害50、实际扣血50、B最终250，开始和命中各一次。 |
| 期望暴击 | 同上，暴击率0.25、原倍率2；暴击后防御前125、防御后62.5，B最终237.5；不得改成禁暴击或额外随机掷骰。 |
| 穿透与前序阶段 | 独立配置明确实际五阶段表达式，护甲100、比例穿透0.2、固定穿透20时有效抗性60；核对每阶段及结果，不只看总伤害。 |
| 过量与致死尾处理 | 伤害50、B初始生命20；造成伤害50、实际扣血20、过量30、最终生命0；同步命中及联动完整，空时间序列及0毫秒停止合法。 |
| 零伤害 | 独立配置伤害0；仍存在本次命中、合法结算与联动，实际扣血0、B生命不变，不以正伤害作为唯一成功判据。 |
| 联动与过程 | 核对原配置全部结果、同次使用及成功过程；正次数、0次数分别核对应用与已发事件，运行后冷却可追溯，不要求下一刀或计时推进。 |
| 输入拒绝 | 必需值未填、非有限、越界、覆盖固有属性及非法攻速定位正确。明确生命0不被当成未填、不改满血；单次入口拒绝初始死亡，不产生本次运行或击杀档案。 |
| 错误与不完整 | 编译拒绝、摘要不符、运行错误、预算停止、证据截断及必要字段缺失不显示完整通过；有实际返回事实时保留，有错误而无结果时不补0。 |
| 清理与迟到 | 正常释放、释放失败、取消、确认／拒绝离开、环境改变、运行30秒超时及崩溃分别核对；线程已销毁时不新建线程释放旧会话，不自动重试，旧回复不回流。 |
| 重复与身份 | 同一显式输入完成两次新的编译／运行／释放，比较数值及关键事实，允许会话标识不同；同步重复点击只产生一项任务。 |
| 真实首批场景 | 只读取得亚托克斯／阿狸及完整共享普攻，用明确补充值与初始生命运行；按本次原公式独立核对金额、暴击、防御、联动、最终生命及释放，不能借人工配置替代。 |

数值核对使用浮点容差，建议 `1e-9 × max(1, |预期值|)`，不以展示小数位四舍五入后的文本代替原数值。期望值在验收侧独立按原配置算例核对，不把第二份伤害公式放入生产页面。

如果真实角色固有数值不适合制造某个边界，用独立构造配置验证该机制；真实样本仍单独运行。非零暴击等真实场景补充值须在档案中明确标注来源为场景输入，不称作正式英雄基础值。
