## 2. 目标、范围与分步门槛

A仍是唯一自主行动方，B不新增主动施放或攻击计划。技能默认绑定和本场开启只表示来源存在，只有明确列入指令的主动使用才会发生；构筑与装备被动沿真实初始化、使用、命中、受击或联动事件执行。不按英雄编号选择技能算法，不另建主动技能伤害引擎。

| 子阶段 | 交付 | 退出门槛 |
| --- | --- | --- |
| 6A 指定时刻单次施放 | 关闭背景普攻，只给一条首次施放指令；保留默认自然来源与明确开关，执行成功门禁、原过程、冷却、命中或自身治疗。 | 三个首批有限组成进入真实工作线程；普通拒绝有记录且不产生成功使用、治疗或伤害；费用取消不改变必要机制消费。 |
| 6B 有限技能列表与背景普攻 | 同一A的按时尝试列表，可选择开启持续普攻；共用原生时钟、行动占用、冷却和唯一下一刀。 | 冷却前／边界／之后、同刻竞争、占用释放与死亡通过；至少一件真实施法激活装备被动与后续普攻完整联调。 |
| 6C 选定复杂过程 | 选少量有限多段／引导和简化蓄力／重施组成，支持关联原使用的明确释放或取消。 | 次数、间隔、窗口、消费、过早／过晚命令、取消与死亡按保存配置执行，不把多段压为同刻或恢复旧结束事件。 |

保持普通施法费用取消。法力、能量及作为施法成本声明的生命费用不成为门槛、不扣除、不返还；弹药、层数、计数和必要充能消费不因这一政策取消。普攻冷却不受技能急速影响，主动技能冷却只沿明确配置求得，不能在宿主重复折扣。

本阶段不含最优连招、自动补放、失败重试、普攻重置、真实移动／弹道／碰撞、完整控制链、复活、多目标、召唤物或外来技能／海克斯选择。已有独立机制检查不等于该阶段全部开放；必需结果属于未支持范围时，整份选定组成拒绝，不能静默裁剪后标成功。

## 4. 场景选择、指令与快照

### 4.1 只读选择增量

继续使用现行 `POST /api/admin/games/{gameId}/simulation-snapshot`（只读场景聚合接口），不新增场景持久化表。6A已实现以下首次选择字段；6B／6C相关阶段仍按后续门槛开放：

| 字段 | 作用与约束 |
| --- | --- |
| `basicAttackSkillKey`、`basicAttackLevel` | 改为配对可空。两项为空表示本场不驱动普攻；两项均提供时沿真实A绑定和等级校验。不能只提供一项，不能自动换共享普攻。UI关闭背景普攻可保留本地选择草稿，但请求明确为空。 |
| `plannedSkills` | 主动入口选择数组，最多16份不同来源；不放指令时刻或重复施放次数。每项包含 `origin`（现有完整角色来源身份）、`skillKey`、`skillLevel`、`phaseKinds`（本次使用的阶段集合）。同来源去重，同技能不能同时绑定两个等级。 |
| `phaseKinds` | 6A／6B仅 `INITIAL`（首次使用）；6C按已支持的 `RECAST`（重施）、`CHARGE_RELEASE`（蓄力释放）、`CANCEL`（主动取消）补根。取消按实际过程取消入口解释，不伪装成使用事件。未知阶段、重复值和缺根拒绝。 |
| 既有来源设置 | 仍负责本场开关与等级；计划不能授予技能、重新启用全局停用对象或忽略0未学。计划等级与该侧最终来源等级不一致时报错，不自动覆盖。 |

首版计划只允许A真实角色绑定的已启用、已学技能。读取外部引用定义不等于授予来源；B只有已有合法自然入口。装备或构筑主动使用与外来技能选择不因新增计划提前开放。

后端在同一只读事务中聚合当前角色、装备、构筑、默认自然根及本次计划根，按真实引用补齐完整作者数据。动作或必要结果不支持时不是后端帮用户关闭来源的理由；没有主动根也不能将参数／公式对象返回为“空程序成功”。完整作者内容、根及排除理由分别保存。

自然根按本场实际驱动可达事件播种：不驱动普攻时，不独立开启普攻开始／命中／接收根；双方初始化保留，计划的成功使用、过程时点、合法技能命中及其实际伤害／接收尾部进入闭包。显式动作产生的攻击／命中联动仍按声明追踪，不能因关闭背景普攻一并删除，也不能把技能伤害自动改成普攻事件。资料不足不能伪称不可达，必要自然来源仍按阶段5完整准入或明确关闭。

计划闭包除了首次阶段和过程，还必须纳入该来源合法 `SKILL_HIT`（技能命中）根、结果、公式及目录；当前样本的命中结果不由过程订阅自动追踪。不能用“本次选择未命中”裁掉完整可能命中的作者分支。其它未计划的主动入口保留原因但不自动施放。

所选主动与默认自然来源按完整身份只挂载一次，不能复制常驻、被动或同次额度。`sourceSkillSettings`不塞入时刻或多条相同来源来模拟连招。三类默认来源和额外强化空位保持阶段5规则。

### 4.2 运行指令增量

UI维护显式 `skillActions`（技能行动指令）列表，编译时绑定到同一份场景内的实际能力。后端选择只声明本次需要的技能／阶段；实际时刻属于运行输入：

| 字段 | 作用与约束 |
| --- | --- |
| `instructionKey` | 本次稳定且唯一的指令标识，编辑时不以当前行号替代；用于失败、使用身份和明细关联。 |
| `atMs`、`sortOrder` | 请求尝试时刻及同刻顺序，非负整数，时刻不超过观察终点；时刻相同按顺序再按稳定标识决定，不依赖浏览器数组偶然顺序。 |
| `origin`、`skillKey`、`skillLevel` | 必须准确对应当前快照内的计划来源和最终等级，不能引用关闭、未学或未纳入快照的来源。 |
| `phaseKind` | 6A仅一条 `INITIAL`；6B为1～64条首次尝试，不隐式重复；6C才开放其它已支持阶段。该阶段还必须属于对应快照 `plannedSkills.phaseKinds`；不允许临时执行未进入快照闭包的重施／释放／取消。 |
| `parentInstructionKey` | 首次为空；重施／释放／取消必须引用本次同来源的首次指令，且不得前向或成环。引用的是原使用，不生成一次新施法。首次被拒或尚未形成有效过程时，控制指令记失败。 |
| `targetSide` | 仅允许A自身或唯一B。来源与效果的作用对象依完整配置解释，不因为选择自身就将原目标伤害改为治疗。首批不提供第三对象、任意坐标或队友列表。 |
| `hitPreset` | 有目标命中入口时必须明确选择“施放完成后对唯一目标命中”或“本次未命中”的有界预设；不是游戏弹道结论。自身治疗不为生成明细伪造命中。 |
| 明确运行输入 | 只列本次必要且已声明的输入；6A首批三项没有未绑定计算时参数。6C释放时刻／必要强度不能缺值或默认满蓄力。 |

6A不含背景普攻，6B由用户显式启用。编译保存来源、阶段能力和合法释放绑定，Web再将用户时刻与顺序组装到运行请求的同一 `driverPlan`（原生驱动计划）内：可空 `basicAttack`与 `skillActions`。`firstAtMs`、同刻顺序及本次命中／未命中预设属于Run输入，不进入编译声明；当前普通 `entries`及输入 `skillUses`、`skillHitFacts`、`attackStartFacts`、`processCommandFacts`均为空，不与自动计划混传。既有独立通用机制工具的输入事实路径不用于本次自动计划，也不为此增加旧设计兼容层。

原生每条 `skillActions` 绑定字段确定为：`instructionKey`、`firstAtMs`（由UI的尝试时刻转换）、`sortOrder`、固定 `source: source`、`target`、`skillKey`、`bindingKey`（本次编译的来源绑定标识）、`action`（过程控制阶段）、`abilityRef`（该实际控制能力）、可空 `parentInstructionKey`及 `hitBindings`（实际释放／命中绑定数组）。所有引用来自本次编译，不由用户填任意能力名；原生再次核对拥有方、来源、技能、阶段和过程，首次与后续控制不能混用。

合法绑定在 `rules.skillActionBindings`（编译期技能行动绑定）声明：每项含唯一 `bindingKey`、固定源侧、实际 `providerRef`／`providerDefinitionRef`、`skillKey`、`controls`（阶段控制数组，每项 `action`、`processKey`、`abilityRef`）及合法 `hitBindings`。阶段不得重复。每个编译命中绑定含唯一 `hitBindingKey`、`processKey`、原有完整 `moment`和同来源 `hitAbilityRef`，只由完整作者结构及已核定释放点产生；运行时不能改过程或把完成时点偷换成开始时点。

Run每个 `hitBindings`项只含已编译的 `hitBindingKey`及明确 `preset`：`TARGET_HIT`（释放后对所选唯一目标尝试命中）或 `MISS`（本次明确未命中）。原生核对键与所选来源／阶段，时点及能力唯一取自编译声明，预设不跳过目标资格或法术护盾。6A伤害技能只绑定该唯一过程的成功完成时点、一次主目标命中；自身治疗数组为空。6C才增加有界步骤执行与多段绑定。完成失败、错过程、旧步骤版本或关联使用不成功时不派生命中，不能在开始时预先造一条独立成功命中事实。

修改技能、来源、等级、阶段集合或作者摘要须重新读取并确认快照；只修改时刻或同刻顺序时，不必重新读相同定义，但旧运行结果立即过期。`snapshotDigest`（场景摘要）覆盖选择和完整作者内容，编译规则摘要覆盖实际程序与编译输入，运行输入摘要覆盖完整指令、时刻、初态、假设和预算，不能以一个摘要替代另外两个。

## 5. 首次成功、过程与命中

### 5.1 时刻表示尝试，不是预约成功

在指令时刻先核对A存活、真实来源和目标、过程／行动条件、普通冷却及必要机制状态。冷却未好、行动忙或本次条件不符时记录一次拒绝，不消费、不治疗、不造成功使用／命中；不延至就绪时刻，不重试，也不替换其它技能。非法引用或不支持的作者组成在运行前拒绝，不伪装成正常战斗跳过。

保留现有同挂载活动过程拒绝再次 `INITIAL` 的约束；这与行动占用独立。`occupiesAction: false`只表示不锁整个A，不代表已支持同技能在途重入。要重施或释放须使用其原过程控制阶段，不用第二次首次冒充；未知或未支持的并行同技能实例不在6B开放。

门禁通过后，原生沿真实首次控制链创建唯一使用身份、启动原过程及原冷却，再发布成功首次使用和合法同步尾部。开始事件补齐实际 `useRef`、拥有方、技能、使用阶段、指令与来源引用，不能仅有技能分类而没有本次身份。纯技能运行同样具有完整开始事件目录，不把普通技能标为普攻或挂一份假普攻来触发它。拒绝使用不能触发“施放后”装备。必要队列、消费、冷却、过程及使用事实在各自帧内共同预检、共同提交；已提交的后续监听失败仍按既有部分结果与预算口径返回，不宣称整次施法可全部回滚。

初次资格与治疗分支读取实际该次开始事件的冻结条件集合，沿已有 `listener.condition`（监听条件）先匹配全部、再执行的链路；不能译成逐操作重新求值的 `operation.condition`（操作条件）后声称冻结。不执行一支后重新挑选另一支。开始事件发生在实际 `PROCESS_START` 操作及其同步尾部之后，并不等于无条件的“准入前属性”；索拉卡两项治疗留在该事件监听链，不能先放进过程开始操作再由开始监听治疗一次。数值公式的当前时点／施加快照仍沿各自声明，不全局冻结所有伤害取值。基本攻击开始、技能成功使用、命中、联动和伤害记录分别计数，不能拿金额或伤害行数代替使用次数。

### 5.2 释放和命中必须有明确来源

## 8. 完整结果、有限记录与页面

保留完整伤害分类、逐笔结算、只读采样和冻结档案，新增事实需与预算独立：

| 输出 | 本阶段增量 |
| --- | --- |
| `summary.skillActions` | 整份指令计划的总数、已到达、接受、普通拒绝、接受前执行中止及未到达累计；总数＝已到达＋未到达，已到达＝接受＋普通拒绝＋接受前中止。已知拒绝不等于运行异常，死亡或观察终点未到达不伪造成尝试。 |
| `summary.skillUses` | 实际成功使用、释放、真实命中实例、完成、失败及观察终点仍在途的累计；重施不当作新首次使用，自身治疗不伪造命中。 |
| `skillActionRecords` | 有限指令事实：标识、请求／实际时刻、阶段、源／目标、技能来源、接受／拒绝及原因、可空真实使用身份。未接受不补造身份。 |
| 使用和过程明细 | 沿真实身份关联开始、释放、步骤、命中、失败、完成及普通／行动就绪；有限截断不能改变上述完整累计。 |
| 伤害记录 | 主动伤害归原技能及原使用，不伪造普攻刀号；非普攻 `attackIndex`（刀号）为空，可按指令／使用／命中关联。反伤与装备仍保留真实拥有者、方向和结果来源。 |
| 直接治疗 | 新增按侧直接治疗完整累计及必要来源分类／有限记录，区分原始、修正、有效治疗与溢出；不混成吸血。生命账为初态减实际扣血加有效吸血加有效直接治疗，沿真实上限核对。 |
| 记录预算 | 为新增有限行动／使用／治疗记录单独说明总数、保留、丢弃和截断；0或截断不改变结算，UI显式给预算。不能用调试证据补造被截断明细。 |

观察终点早于释放时可以“完整完成本次观察、技能仍在途”；不能将其当作完整施法完成，也不能为凑完成数提前命中。预算不足保持已提交部分、明确不完整原因和实际停止时刻，不能把尚未到达指令改为成功。

“接受”以成功开始帧提交为界：已到达但开始提交前预算失败记接受前中止，无使用身份／消费／过程／冷却；提交后尾部失败保留接受与使用事实、已提交生命账，不将其改成未接受。纯技能也必须输出公共执行完整性、预算原因与已提交结果，不能只复用当前依赖普攻对象的部分结果分支。已知预算停止返回一致的部分结算；其它执行异常不得包装为完整成功或静默补齐记录。

在现有 `#/simulation/basic-attack`（当前计算页）扩充指定技能计划区和背景普攻开关，不另建独立连招工作台。入口文案可调整为单攻击方模拟；A/B仍按两栏配置。来源技能等级默认最高须先读真实上限并显式提交，低等级、0未学、关闭与清空草稿保留。没有输入就不运行，不自动补零、满血或最佳施放。

计划表先支持技能、阶段、时刻、目标和同刻顺序；6C再开放关联首次指令、释放／取消输入。展示普通拒绝与主动过程明细靠近计划表，时间轴加入实际施放／命中／失败标记；缩放筛选不改变顶部完整累计。冻结档案保存原选择、完整指令、摘要、初态、输入、命中预设、费用取消及排除项、产物身份和清理结果；CSV只导出实际返回事实，不还原截断记录。

### 8.1 6A落地字段与独立预算

完整指令累计字段为 `plannedCount`（计划总数）、`reachedCount`（已到达）、`acceptedCount`（接受）、`rejectedCount`（普通拒绝）、`abortedBeforeAcceptCount`（接受前执行中止）及 `unreachedCount`（未到达）。实际使用累计字段为 `startedCount`（成功开始）、`releasedCount`（成功释放）、`hitCount`（真实命中实例）、`completedCount`（过程完成）、`failedCount`（过程失败）及 `inFlightCount`（仍在途）。

运行结果新增 `skillActionRecords`（有限指令事实）、`skillUseRecords`（有限使用／过程事实）及 `healingRecords`（有限直接治疗事实）。预算分别为 `maxSkillActionRecords`，范围0～4096，以及 `maxSkillUseRecords`、`maxHealingRecords`，范围0～10000；省略时分别保留1000、2000、2000项。各类总数、返回数、丢弃数和截断标志独立保存于原 `recording`（记录摘要），不能从已返回行数推导完整累计。

指令事实明确接受、普通拒绝或接受前中止，未接受的使用引用为空；实际使用事实按开始、释放、命中、完成、失败关联原指令与使用。主动命中伤害同时保存真实 `hitRef`（命中引用），与使用事实的命中引用一致，不靠金额猜身份。双方直接治疗完整累计为 `sourceDirectHealing`、`targetDirectHealing`，吸血继续独立；治疗明细保留真实作者操作引用，无自定义引用时取实际编译路径，不把空字符串当有效来源。

纯技能监听及门禁均严格读取必要数值；条件为假是普通拒绝，求值异常或缺值是明确执行错误，不包装为“未命中”或补零。开始帧致死后不再发布后续成功使用治疗监听；已提交的接受、使用与失败事实仍保留。以上为当前6A实现，不自动开放混合或复杂控制。

## 10. 验收、开放问题与结论

6A至少覆盖：正常首次、时刻未到、源死亡、错误目标／归属、延时结束前后、明确未命中／阻挡、伤害或治疗来源和吸血资格、直接治疗阈值及上限、费用取消但必要消费保留、重复会话无残留。单条新场次的冷却未好门禁先由独立原生构造证明，真实重复尝试／冷却边界留到6B，不为6A额外开放任意状态恢复或预排第二条施法。399／400只作为生命上限1000的独立构造算例；真实对象按其已录实际生命上限验证40%以下／等值／以上，不覆盖固有上限来凑算例。未发生真实使用／命中时不能出现对应结果。

6B至少覆盖：同技能冷却前1毫秒／就绪／后1毫秒、同刻指令稳定顺序、施放占用与唯一下一刀、属性或冷却变化改期、取消／释放唤醒、同刻死亡、真实施法激活装备与后续普攻一次消费、直接治疗与吸血完整生命账。0及截断记录、关闭采样不改变完整结算。

6C至少覆盖：各段独立时刻和命中、有限次数、一次首次与冷却、原使用关联、过早／过晚释放和重施、窗口到期、最大释放声明、主动取消、源死亡、旧步骤事件守卫和预算原子性。每类实际核定后才开放，不因管理枚举存在提前成功。

实施收尾沿模块规则运行受影响检查、全量Go／原生基准、最终Wasm与宿主编译／运行／释放、Web静态／类型／单测／构建及真实浏览器。每个真实组合至少同工作线程100次、同Node会话200次比较完整结果、恢复初态、错误摘要后的恢复与会话释放，并记录最后产物与请求。只做方案时不重复已有效的5C测试，也不将阶段6测试写成已通过。

首批进入6A不需要负责人先补新资料。通用释放／命中绑定和门禁发布次序已按独立方案复核进入实施，最终结果以6A验收记录为准；6B需核定所选对象的步骤占用、唯一等待及非零急速冷却表达；6C需实际选择复杂对象。明确信息由开发侧独立完成，只有缺核心事实才集中提问。6B和6C的拟议能力不得因6A接口和新字段存在就提前宣称已支持。
