# 伤害类型结算公式管理共享方案

方案版本：`damage-type-formula-management-v1-frozen`

方案状态：项目负责人已确认，后端、实库迁移和前端管理闭环已于 2026-09-27 完成。本轮未修改 Wasm，未接入计算宿主，不能以保存成功宣称伤害已经按公式结算。

本文是伤害类型结算公式的数据、接口、校验、页面行为、实施顺序和跨端验收的唯一来源。关联的现行契约：

1. [技能分类与伤害类型管理共享契约](./技能分类与伤害类型管理详细设计.md)
2. [技能参数与公式管理共享契约](./技能参数与公式管理详细设计.md)
3. [乘区管理与修正结果共享契约](./乘区管理与修正结果补充详细设计.md)

## 1. 目标与成功标准

本次在现有“伤害类型管理”中增加结算公式配置，使每个伤害类型可以保存一份独立、结构化、可完整回读的防御结算定义。

固定责任边界如下：

```text
技能伤害公式
  └─ 定义本笔原始伤害

伤害类型结算公式
  └─ 定义防御计算使用的基础抗性、穿透、有效抗性和最终倍率
```

成功必须同时满足：

1. 一种伤害类型至多拥有一份结算公式，不建立脱离伤害类型的全局公式目录。
2. 结算公式包含五个固定阶段：基础抗性、百分比穿透、固定穿透、有效抗性、抗性倍率。
3. 后端可以保存、读取、替换和移除完整公式，并校验结构、阶段依赖和属性引用。
4. 前端可以在伤害类型管理页查看配置状态并完成结构化编辑，不要求用户手写 JSON。
5. 保存失败、目录加载失败或回读失败时保留当前草稿，不把失败显示成未配置或保存成功。
6. 公式配置与伤害类型基础资料互不误覆盖；修改名称、说明、状态或排序不得清空公式。

本次成功只证明管理配置、真实数据库、HTTP 接口和浏览器编辑闭环，不证明公式可执行，不证明伤害、防御、穿透、护盾或生命值结算已经接入。

## 2. 范围与非目标

### 2.1 本次交付

1. 伤害类型结算公式的数据库字段和迁移。
2. 一组按伤害类型寻址的公式读取、保存和移除接口。
3. 公式树结构、阶段依赖、属性引用、停用属性及字段路径校验。
4. 伤害类型列表中的配置状态，以及同页面内的公式查看和编辑入口。
5. 后端自动检查、真实数据库与接口回读、前端自动检查和真实浏览器验收。

### 2.2 明确不包含

1. Wasm、浏览器计算宿主、编译请求、运行会话或伤害结算执行。
2. 把现有物理、魔法、真实伤害规则自动写入数据库，或按伤害类型名称猜测公式。
3. 预置伤害类型、默认公式、默认抗性属性或默认穿透属性。
4. 修改技能参数和技能公式的数据契约、页面或引用关系。
5. 新建“全局公式管理”“伤害规则中心”或“伤害类型参数管理”页面。
6. 计算预览、示例数值试算、舍入、数值精度或运行时错误语义。
7. 修改现有伤害类型稳定标识，或为旧设计增加双写、双读和兼容字段。
8. 发布、版本快照、战斗数据组装或公式执行证据。

## 3. 关系与固定结算位置

现有乘区契约已经固定未来顺序：技能或普通攻击先形成原始伤害，防御前伤害乘区随后生效，再执行伤害类型的防御计算，最后进入防御后伤害乘区。

本方案只保存其中“伤害类型的防御计算”所需配置，不改变前后两个乘区，也不把乘区规则复制进伤害类型公式。

```text
原始伤害
  → 防御前伤害乘区
  → 伤害类型结算公式（本次仅配置）
  → 防御后伤害乘区
  → 后续护盾与生命值结算
```

伤害结果继续使用自己的数值规则生成原始伤害，并通过 `damageTypeKey` 选择伤害类型。伤害类型公式不引用技能参数，也不保存某个技能、装备、角色或符文的反向关系。

## 4. 公共数据契约

### 4.1 一类一份完整公式

伤害类型公式详情使用以下形状：

```json
{
  "gameId": "lol",
  "damageTypeKey": "physical",
  "formula": {
    "resistanceBeforePenetration": {
      "nodeType": "ATTRIBUTE",
      "attributeOwner": "TARGET",
      "attributeKey": "armor",
      "attributeValueKind": "TOTAL"
    },
    "penetrationPercent": {
      "nodeType": "ATTRIBUTE",
      "attributeOwner": "SOURCE",
      "attributeKey": "armor_pen_percent",
      "attributeValueKind": "TOTAL"
    },
    "penetrationFlat": {
      "nodeType": "ATTRIBUTE",
      "attributeOwner": "SOURCE",
      "attributeKey": "armor_pen_flat",
      "attributeValueKind": "TOTAL"
    },
    "effectiveResistance": {
      "nodeType": "STAGE_RESULT",
      "stageKey": "RESISTANCE_BEFORE_PENETRATION"
    },
    "resistanceFactor": {
      "nodeType": "FIXED",
      "value": 1
    }
  },
  "updatedAt": "2026-09-27T00:00:00Z"
}
```

上述只是数据形状示例，不是物理伤害的完整公式，也不得作为系统预置数据。

一种伤害类型只有这一份公式，因此不增加公式标识、公式名称、说明、排序或公式列表。伤害类型的名称和稳定标识就是该公式的业务身份。

### 4.2 五个固定阶段

| 字段 | 中文含义 | 可引用的前序阶段 |
| --- | --- | --- |
| `resistanceBeforePenetration` | 基础抗性 | 无 |
| `penetrationPercent` | 百分比穿透 | 基础抗性 |
| `penetrationFlat` | 固定穿透 | 基础抗性、百分比穿透 |
| `effectiveResistance` | 有效抗性 | 基础抗性、百分比穿透、固定穿透 |
| `resistanceFactor` | 抗性倍率 | 前四个阶段 |

阶段顺序固定，不允许作者新增阶段、改名、重排或建立回指。固定顺序既防止循环引用，也让页面和后端能够准确定位错误。

五个阶段统一使用十进制数值。百分比穿透和抗性倍率使用小数口径，例如 15% 保存为 `0.15`；固定穿透和基础/有效抗性使用对应属性的数值口径。零是明确值，不表示缺失。

本次只保存各阶段的结构，不执行数值计算。文案可以说明预期口径，但不能把未运行的范围、非负、有限值或最终伤害结果描述为已验证。

### 4.3 公式节点

伤害类型公式只允许四种节点：

| `nodeType` | 必填字段 | 含义 |
| --- | --- | --- |
| `OPERATION` | `operation`、`operands` | 对两个有顺序的子节点执行运算。 |
| `FIXED` | `value` | 明确的有限固定数值。 |
| `ATTRIBUTE` | `attributeOwner`、`attributeKey`、`attributeValueKind` | 读取来源对象或目标对象的属性。 |
| `STAGE_RESULT` | `stageKey` | 读取当前阶段之前已经定义的阶段结果。 |

不允许 `PARAMETER` 节点。伤害类型没有所属技能，不能借用任一技能的固定、等级或计算时传入参数。

### 4.4 运算与属性取值

运算沿用技能公式已经使用的六种类型：

| `operation` | 含义 |
| --- | --- |
| `ADD` | 相加 |
| `SUBTRACT` | 左值减右值 |
| `MULTIPLY` | 相乘 |
| `DIVIDE` | 左值除以右值 |
| `MIN` | 取较小值 |
| `MAX` | 取较大值 |

每个运算节点必须且只能有两个子节点。属性对象沿用 `SOURCE / TARGET`，属性取值沿用技能公式已经定义的 `BASE / BONUS / TOTAL / CURRENT / MISSING / CURRENT_RATIO / MISSING_RATIO`。本次不新建另一套属性目录或取值枚举。

每个阶段表达式的最大深度为 32，节点总数最多为 256。根节点计入深度和节点数。未知字段、多余字段、空节点、非法枚举或非有限固定值均拒绝整次保存。

### 4.5 代表性表达方式

物理或魔法伤害可以把实际抗性属性、穿透属性和常数按项目资料录入。例如正负抗性分段可以使用 `MIN` 和 `MAX` 组合表达，不要求增加条件节点。

绕过抗性的伤害类型仍保存完整五阶段：前四项使用明确的 `0`，抗性倍率使用明确的 `1`。这只是录入方式，不是系统按名称自动补值。

## 5. HTTP 接口

伤害类型基础资料接口保持不变。列表、详情、创建响应和基础资料更新响应共用的伤害类型对象增加只读布尔字段：

```json
{
  "damageTypeKey": "physical",
  "name": "物理伤害",
  "formulaConfigured": true
}
```

`formulaConfigured` 只表示数据库中存在完整公式对象，不表示公式正确执行或已经通过运行验证。创建和基础资料更新请求都不接收该字段。

公式使用独立子资源：

| 方法 | 路径 | 用途 | 成功状态 |
| --- | --- | --- | ---: |
| `GET` | `/api/admin/games/{gameId}/damage-types/{damageTypeKey}/formula` | 读取完整公式 | 200 |
| `PUT` | `/api/admin/games/{gameId}/damage-types/{damageTypeKey}/formula` | 新建或完整替换公式 | 200 |
| `DELETE` | `/api/admin/games/{gameId}/damage-types/{damageTypeKey}/formula` | 移除公式，保留伤害类型 | 204 |

规则：

1. `PUT` 请求体只提交 `formula`，不重复提交游戏、伤害类型标识、名称、状态或排序。
2. `PUT` 始终完整替换五个阶段，不提供单节点或单阶段局部修改。
3. 基础资料 `PUT /damage-types/{damageTypeKey}` 不接收、不返回请求公式字段，也不得清空已有公式。
4. 列表不返回完整公式树；查看或编辑时再读取子资源。
5. `DELETE` 只把该类型恢复为“未配置”，不删除伤害类型及其既有引用。
6. 公式保存或移除后更新伤害类型的 `updatedAt`，列表刷新后同步显示配置状态。

## 6. 校验、引用与错误

### 6.1 保存校验

后端在一个事务内完成：

1. 锁定当前游戏和伤害类型。
2. 校验五个阶段齐全且没有额外字段。
3. 校验每棵表达式的节点形状、字段互斥、深度和节点数。
4. 校验 `STAGE_RESULT` 只引用当前阶段之前的固定阶段。
5. 收集全部属性引用并核对它们属于当前游戏。
6. 新建公式只能引用启用属性；修改时既有停用属性引用可以原样保留，但不能新增停用属性引用。是否属于既有引用按“属性对象、属性标识、属性取值方式”三元组比较更新前后的引用集合；改变其中任一项都视为新引用。
7. 一次返回全部可定位字段问题；任一问题存在时不写入部分阶段。

当前管理服务不执行公式，因此不在后端伪造除零、正负范围或最终倍率验证。固定值只校验为有限数；真正的数值执行与运行错误不属于本次范围。

### 6.2 引用与状态

1. 伤害类型停用不删除公式，重新启用后原公式仍在。
2. 公式引用的属性后来停用时，已有引用继续可见并可原样保存；前端标明“已停用”，新建和改选不能选择它。
3. 属性当前没有删除接口，本次不新增属性删除行为。
4. 删除伤害类型仍沿用已有占用保护；删除成功时同一行中的公式一并删除，不建立孤儿公式。
5. 移除公式不修改任何技能效果中的 `damageTypeKey` 引用。

### 6.3 稳定错误

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | 请求 JSON、字段类型或枚举无法绑定。 |
| 400 | `400.VALIDATION_FAILED` | 阶段缺失、多余字段、节点结构、深度、节点数或固定值不合法。 |
| 400 | `400.INVALID_DAMAGE_TYPE_FORMULA_REFERENCE` | 属性不存在、跨游戏或前序阶段引用不合法。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.DAMAGE_TYPE_NOT_FOUND` | 伤害类型不存在。 |
| 404 | `404.DAMAGE_TYPE_FORMULA_NOT_FOUND` | 读取或移除尚未配置的公式。 |
| 409 | `409.FORMULA_ATTRIBUTE_DISABLED` | 新增了停用属性引用。 |

字段问题使用完整路径，例如：

```text
formula.effectiveResistance.operands[1].stageKey
formula.resistanceFactor.operands[0].attributeKey
```

前端只根据统一错误外壳和字段路径定位，不解析数据库原文或错误消息猜测类型。

## 7. 后端责任与存储

### 7.1 数据库

在 `damage_types` 增加一个可空的 JSONB（数据库结构化对象）字段，例如 `calculation_formula`：

1. `NULL` 明确表示未配置。
2. 非空时数据库只做根对象形状检查；完整节点、枚举和引用校验由服务层负责。
3. 不建立独立公式表、公式标识、公式名称或表达式索引。
4. 不为 JSONB 建立通用搜索索引；公式只按伤害类型主键读取。
5. 现有行迁移后保持 `NULL`，不按名称或稳定标识自动生成公式。

### 7.2 服务与事务

后端负责：

1. 新增公式请求、响应和表达式节点模型。
2. 在伤害类型列表、详情、创建和基础资料更新响应中返回 `formulaConfigured`。
3. 增加公式子资源控制器、映射和事务服务。
4. 复用当前游戏写入锁和伤害类型行锁，写入后按主键完整回读。
5. 审计日志记录公式新建、替换和移除，不记录凭据或数据库连接信息。

后端不负责：

1. 计算五个阶段的实际数值。
2. 把公式转换为 Wasm 或浏览器运行输入。
3. 根据 `physical / magic / true` 等名称生成规则。
4. 为缺失属性或缺失阶段补 `0` 或 `1`。

## 8. 前端页面行为

### 8.1 列表入口

“伤害类型管理”保持现有路由和导航，在列表增加：

1. “结算公式”列，显示“已配置”或“未配置”。
2. “配置公式”操作；查看模式可显示“查看公式”。
3. 基础资料编辑、启停和删除继续使用现有入口，不把完整公式塞入基础资料弹窗。

### 8.2 公式编辑器

公式弹窗标题为“结算公式 - {伤害类型名称}”，固定显示五个阶段。每个阶段使用结构化节点编辑器：

1. 运算节点显示运算和左右子节点。
2. 固定值节点提供有限数值输入。
3. 属性节点依次选择来源/目标、属性和属性取值方式。
4. 前序结果节点只列出当前阶段之前允许引用的阶段。
5. 页面生成中文结构预览，但不执行公式或显示计算结果。

技能公式现有编辑器的递归节点卡片、错误定位、属性目录和中文预览交互可以复用；伤害类型公式必须使用独立数据类型和校验入口，不能让技能公式意外接受固定值或前序结果节点。

### 8.3 加载、草稿与失败

1. 打开编辑器以公式详情请求为准；详情返回前只显示加载状态。列表中的 `formulaConfigured` 只用于展示，不能代替详情读取。
2. 只有详情请求精确返回 `404.DAMAGE_TYPE_FORMULA_NOT_FOUND` 时才建立空白五阶段草稿；游戏不存在、伤害类型不存在、未授权、网络失败或其他错误都保持错误状态，不能显示为未配置。
3. 属性目录失败时保留公式草稿，阻止保存并提供重试。
4. 关闭存在修改的公式草稿前确认是否放弃；取消关闭后保留全部输入。
5. 保存失败保留完整草稿、节点错误和滚动位置。`PUT` 成功后先保留弹窗和草稿，再独立读取公式；只有回读结构与本次提交一致时才关闭弹窗、刷新列表并显示成功。
6. 回读失败、超时或结构不一致时显示“保存结果待确认”，保留草稿并提供重新读取入口；在已落地状态未确认前不得盲目重发 `PUT`。
7. 移除公式需要确认；失败时保留弹窗和现有公式。
8. 切换游戏、接口地址或令牌后清除旧详情和迟到响应，不能把上一游戏公式带入当前草稿。

## 9. 数据迁移与破坏式更新边界

1. 数据库迁移只增加可空公式字段和必要形状约束，不删除或改写现有伤害类型及引用。
2. 现有伤害类型迁移后统一显示“未配置”；不建立运行时回退公式。
3. 代表性物理、魔法、绕过抗性公式必须在页面能力完成后由维护者明确录入，不写入迁移脚本或后端默认值。
4. 本次不修改伤害类型稳定标识，不处理现有 `physics / physical`、`real / true` 等历史命名差异。
5. 本次不建设旧接口兼容层。前后端在同一功能批次切换到带 `formulaConfigured` 的当前响应。

## 10. 实施顺序与写入责任

### 10.1 后端先行

后端负责数据库迁移、公式模型、接口、校验、事务和测试。实施顺序：

1. 增加数据库字段与迁移合同检查。
2. 增加表达式模型和纯结构校验。
3. 增加属性引用与停用引用校验。
4. 增加公式读取、保存、移除接口和列表配置状态。
5. 完成后端自动检查及确认数据库上的迁移、写入、回读和回滚验证。

### 10.2 前端随后接入

前端在接口冻结后负责类型、客户端、列表状态、公式弹窗、草稿保护和测试。不得修改后端、Wasm 或技能公式业务契约。

前后端共用字段、错误和阶段顺序以本文为准；内部类名、组件拆分和函数组织由各模块按现有模式决定，不在本文逐函数冻结。

## 11. 验证与验收

### 11.1 后端自动检查

至少覆盖：

1. 五阶段公式保存、详情读取、完整替换和移除。
2. 列表 `formulaConfigured` 在保存和移除后正确变化。
3. 基础资料更新和启停不清空公式。
4. 缺阶段、多阶段、非法节点字段、超深、超节点数和非有限固定值。
5. 合法前序引用，以及同阶段、后序和未知阶段引用拒绝。
6. 未知、跨游戏、停用属性引用规则。
7. 事务失败不留下部分公式，写入锁和审计记录正确。
8. 现有伤害类型和技能公式检查保持通过。

### 11.2 前端自动检查

至少覆盖：

1. 公式详情响应严格校验和请求路径编码。
2. 四种节点的切换、递归编辑、预览和字段错误映射。
3. 五阶段前序结果选项不产生循环。
4. 已停用旧属性保留、新停用属性不可选。
5. 加载失败、保存失败、移除失败和迟到响应不丢草稿。
6. 基础资料操作不会携带或清空公式。
7. 现有伤害类型管理和技能公式编辑行为保持不变。

### 11.3 真实接口与浏览器验收

验收至少完成：

1. 选择一个已有伤害类型，通过真实页面录入含属性、固定值、运算和前序结果的五阶段公式。
2. 保存后关闭、刷新、重开，五阶段结构与中文预览完整一致。
3. 修改伤害类型名称、说明、状态和排序后，公式仍完整保留。
4. 公式替换后旧节点不残留；移除后类型保留且列表变为“未配置”。
5. 模拟未知属性、停用属性和非法前序引用，页面定位到具体节点并保留草稿。
6. 浏览器请求只使用伤害类型及公式子资源，不调用 Wasm，不发起计算请求。

证据必须分开报告：静态检查、后端单测、真实数据库、HTTP、前端单测、构建和浏览器操作各自只证明对应层面。不得把配置保存和页面重开描述为运行时伤害验证。

## 12. 停止条件

出现以下任一情况，停止实现并返回项目负责人确认：

1. 真实业务资料无法用五个固定阶段表达，必须增加可重排阶段、循环引用、条件系统或任意脚本。
2. 实现必须修改技能公式节点语义，导致既有技能公式请求或回读形状变化。
3. 后端必须执行公式才能完成保存校验。
4. 前端必须调用 Wasm、计算宿主或战斗接口才能完成编辑与回读。
5. 目标数据库已存在同名但结构不同的公式字段或未识别的正式公式数据。
6. 需要自动按伤害类型名称、属性名称或旧运行时规则生成业务公式。
