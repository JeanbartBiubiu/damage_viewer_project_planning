# 角色基本管理共享契约

方案版本：`character-management-v4`

本文是角色基本管理的唯一共享契约。字段、HTTP、错误语义、实施顺序和跨端验收只在本文定义；后端与前端详细设计不得复制或重定义。

关联文档：

1. [角色基本管理后端详细设计](../server/game_manage/角色基本管理后端详细设计.md)
2. [角色基本管理前端详细设计](../web/角色基本管理前端详细设计.md)

## 1. 范围

本阶段交付游戏等级配置、角色基本资料增删改查，以及按游戏等级配置维护角色已配置属性的 1～N 级数值。

角色使用独立数据和接口，用户页面只使用“角色”。新链路不得读取、写入、迁移或双写旧实体、Provider、战斗数据修订、发布和 Wasm 数据。

非目标：角色状态、排序、图片、装备、技能、Provider、发布、计算、旧数据迁移和兼容双读。

## 2. 等级配置

管理接口：

```text
GET /api/admin/games/{gameId}/level-config
PUT /api/admin/games/{gameId}/level-config
```

成功响应：

```json
{"gameId":"lol","minLevel":1,"maxLevel":18}
```

PUT 请求体为 `{"minLevel":1,"maxLevel":18}`，范围必须在 1～100 且最大等级不小于最小等级。保存后，已有角色 Map 在同一事务中按新范围整理：保留范围内已有值、新等级补 0、移除范围外等级。游戏不存在返回 `404.GAME_NOT_FOUND`；GET 配置不存在返回 `409.LEVEL_CONFIG_REQUIRED`。

前端使用独立“游戏配置”页面维护等级范围，不放入角色管理页面。

## 3. 角色基本资料

统一响应对象：

```json
{
  "gameId":"lol",
  "characterKey":"malzahar",
  "name":"玛尔扎哈",
  "description":null,
  "createdAt":"2026-08-23T00:00:00Z",
  "updatedAt":"2026-08-23T00:00:00Z"
}
```

字段规则：

1. `characterKey`：创建时 trim；小写字母开头，只含小写字母、数字、下划线，最长 64；创建后不可修改。
2. `name`：trim 后 1～100；同一游戏忽略首尾空格和大小写唯一。
3. `description`：可省略或 null；trim 后空串保存为 null；最长 2000。
4. `createdAt`、`updatedAt`：ISO 时间。

接口：

```text
GET    /api/admin/games/{gameId}/characters?keyword=
GET    /api/admin/games/{gameId}/characters/{characterKey}
POST   /api/admin/games/{gameId}/characters
PUT    /api/admin/games/{gameId}/characters/{characterKey}
DELETE /api/admin/games/{gameId}/characters/{characterKey}
```

列表响应为 `{"items":[],"total":0}`，不分页。`keyword` 按标识和名称模糊查询；trim 空串等同省略，最长 100。

POST 请求为 `{characterKey,name,description?}`，成功返回 201 和角色对象，并在同一事务建立外层等级完整、内层为空的默认角色属性 Map。PUT 请求为 `{name,description?}`，成功返回 200 和角色对象；它只全量修改基本资料，不读写属性 Map。DELETE 返回 204，硬删除角色和其属性 Map。

## 4. 等级属性大 Map

读取与整块保存：

```text
GET /api/admin/games/{gameId}/characters/{characterKey}/attributes
PUT /api/admin/games/{gameId}/characters/{characterKey}/attributes
```

GET 与 PUT 成功响应：

```json
{
  "characterKey":"malzahar",
  "minLevel":1,
  "maxLevel":18,
  "levelValues":{
    "1":{"hp":580,"armor":18},
    "2":{"hp":610,"armor":20}
  }
}
```

PUT 请求为 `{"levelValues":{...}}`，一次整块替换，使用最后一次写入生效，不增加版本号。

归一化规则：

1. 外层等级必须恰好覆盖 `minLevel..maxLevel`；只接受无前导零的十进制字符串。
2. 内层键必须存在于当前属性定义；未知键拒绝。
3. 同一属性要么在全部等级中都有数值，要么在全部等级中都不出现；前者为已配置，后者为未配置，部分等级缺失拒绝。
4. 新增属性定义后，旧角色仍保持未配置，不自动补 0。
5. PUT 只校验已配置属性：必须为有限数字，整数属性不得含小数，并满足属性最小值和最大值。失败不产生部分写入。
6. 存储层保留未配置状态；未来计算读取未配置属性时再按 0 处理，不反向污染管理数据。
7. 格点错误路径固定为 `/levelValues/{level}/{attributeKey}`。

## 5. 稳定错误

| HTTP | code | 场景 |
|---|---|---|
| 400 | `400.INVALID_BODY` | JSON 无法绑定 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、查询或 Map 顶层字段错误 |
| 400 | `400.UNKNOWN_ATTRIBUTE` | 未知属性键 |
| 400 | `400.LEVEL_VALUES_INVALID` | 等级集合、等级键或内层结构错误 |
| 400 | `400.ATTRIBUTE_VALUE_INVALID` | 非数字、整数小数或范围错误 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在 |
| 404 | `404.CHARACTER_NOT_FOUND` | 角色不存在 |
| 409 | `409.CHARACTER_KEY_EXISTS` | 角色标识重复 |
| 409 | `409.CHARACTER_NAME_EXISTS` | 角色名称重复 |
| 409 | `409.LEVEL_CONFIG_REQUIRED` | 等级配置缺失 |

可定位错误统一使用 `details.fieldIssues`。基本字段名不加斜杠；等级属性只使用上述格点路径。

## 6. 实施顺序与验收

1. 后端先完成等级配置、角色存储、接口和真实数据库执行。
2. 前端在冻结接口上完成角色列表、基本资料弹窗、删除确认和等级属性编辑。
3. 自动化通过后启动前后端，以真实数据库完成浏览器验收。

跨端必须证明：

1. 导航只有“角色管理”，不再显示“实体创建”和“实体 Provider 挂载”。
2. 创建后刷新能回读；基本资料编辑不改变 Map；Map 整块保存后刷新一致。
3. 未知属性、属性范围、缺等级配置分别返回冻结错误且不部分写入。
4. 删除后角色读取为 404，属性 Map 同时消失。
5. 新角色链路不依赖旧实体、Provider、战斗数据、发布或 Wasm。
6. 等级属性弹窗按“行=属性、列=等级”展示，禁止再使用“等级展开后录入属性列表”。
7. 单属性设置按固定值或 `当前等级值 = 起始值 + (当前等级 - 最小等级) × 每级增量` 生成整行，保存时提交外层等级完整、内层属性稀疏的 Map。
