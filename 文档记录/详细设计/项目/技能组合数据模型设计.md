# 技能组合数据模型设计

版本：第一版。基线：1bc6a8551及本次已确认的业务范围。本稿只设计数据库中的定义数据：表、字段、枚举、归属、引用、约束和旧数据调整。Wasm调度、执行算法、运行协议和前端页面布局均不在本稿范围；没有修改建表脚本或真实数据库。

业务范围以[技能六模块能力组合表](/C:/project/damage_viewer_project_planning/文档记录/概要设计/项目/技能六模块能力组合表.md)为准：现行49名代表，婕拉整名排除、妮蔻仅1V1；装备和符文沿原清单。进度仍由[阶段进度](/C:/project/damage_viewer_project_planning/数据参考/全量录入-2026-09/阶段进度.json)维护。

## 1. 本版结论

1. 保留现有九张技能核心表、三张挂载表和引用索引。技能子对象继续以game_id、skill_key及自身键定位，不取消与技能的绑定。
2. 组合关系继续写在过程、效果和触发规则对应的结构化字段中；它们各自拥有明确语义。引用索引由这些真实字段生成，不能代替作者配置。
3. 本版不新增物理表，不删除已有物理列。变化集中在现有JSONB字段内部的引用归属、事件筛选、结束关联及必要输入描述。JSONB是数据库用于保存结构化对象的列类型。
4. 同技能对象可以直接组合；跨技能只开放本稿列明的状态引用和持续状态读取。效果执行、过程调用、参数和公式引用保持当前边界，不笼统开放任意跨技能调用。
5. 新增字段和约束均标为“拟新增／拟调整”，不是现有系统已支持的声明。移除施法费用和简化操作窗口，是本期组合内容的取舍，不意味着可以删除承载其他机制的通用表或整列。

**2026-09-26旧数据处理口径：按MVP直接调整本批对象。** 本次只整理现行49名英雄范围内、实际受模型调整影响的技能数据；范围外先保持原样，不要求全游戏补齐，不引入新旧双写或长期兼容层。新增必填校验也以本次变更对象为边界，不能让未改动的范围外旧数据阻断这批修改。具体见第6、9章。

当前建表脚本共28张逻辑表、219个物理列；本版保持该物理结构数量。完整旧字段解释见[字段字典](/C:/project/damage_viewer_project_planning/数据参考/技能字段字典-2026-09-25/技能配置数据库字段字典.md)，本稿只补设计决策与变化，避免重抄所有字段。

## 2. 数据归属与表关系

### 2.1 六模块对应哪些表

| 配置模块 | 根表／关系表 | 记录什么 |
| --- | --- | --- |
| 主体与分类 | skills、skill_categories、skill_category_relations | 技能身份、等级、启停、分类及分类关联 |
| 参数与公式 | skill_parameters、skill_formulas | 固定／等级／输入参数及公式定义 |
| 效果与生命周期 | skill_effects | 一个效果的结果清单、生命周期及结果间关联 |
| 施放过程 | skill_processes | 步骤、普通冷却、时点效果挂接和状态操作 |
| 内部状态 | skill_internal_states | 计数、弹药、模式、标记、内部冷却的定义 |
| 条件与触发 | skill_trigger_rules | 事件来源、条件组、动作、输入供值及触发限制 |

六模块是职责划分，不是一模块一张表。角色、装备、符文仍通过三张关系表挂载技能。

~~~mermaid
flowchart LR
  C[角色／装备／符文] --> R[三类技能挂载表]
  R --> S[skills 技能]
  S --> P[skill_parameters 参数]
  S --> F[skill_formulas 公式]
  S --> E[skill_effects 效果]
  S --> T[skill_processes 过程]
  S --> I[skill_internal_states 内部状态]
  S --> G[skill_trigger_rules 规则]
  K[skill_categories 分类] --> KR[skill_category_relations 分类关系]
  KR --> S
  T -. 效果挂接 .-> E
  T -. 状态引用 .-> I
  G -. 条件／动作／供值引用 .-> E
  G -. 启动／推进／失败引用 .-> T
  G -. 状态读取 .-> I
  F -. 参数引用 .-> P
~~~

实线表示主体归属或关系表关联；虚线表示JSON内部的业务引用。虚线不等于数据库已经建立了对应的物理外键。

### 2.2 根表主键、字段与外键

下表的“子对象公共列”指game_id、skill_key、该对象键、name、description、sort_order、created_at、updated_at。普通对象键最长64字符，格式沿现有小写字母开头的稳定键规则。name通常最长100字符，description通常最长2000字符；规则说明最长1000字符。现有status列只在已有该列的表中保留，不统一给所有子表补一个启停列。

| 表 | 主键 | 主要字段（除主键及公共元数据） | 物理外键／唯一性 |
| --- | --- | --- | --- |
| skills | game_id＋skill_key | name、description、max_level、status、sort_order及时间戳 | game_id→games；技能名称目前不是唯一键 |
| skill_categories | game_id＋skill_category_key | name、description、status、sort_order及时间戳 | game_id→games；同游戏名称去空白后忽略大小写唯一 |
| skill_category_relations | game_id＋skill_key＋skill_category_key | 无其他业务字段 | 分别引用同游戏技能、分类；复合主键去重 |
| skill_parameters | game_id＋skill_key＋parameter_key | 公共列；value_type、value_mode、fixed_value、level_values | 所属技能复合外键 |
| skill_formulas | game_id＋skill_key＋formula_key | 公共列；expression | 所属技能复合外键 |
| skill_effects | game_id＋skill_key＋effect_key | 公共列；results、lifecycle | 所属技能复合外键 |
| skill_internal_states | game_id＋skill_key＋state_key | 公共列；state_type、scope、detail | 所属技能复合外键 |
| skill_processes | game_id＋skill_key＋process_key | 公共列；activation_type、steps、cooldown、effect_bindings、state_operations | 所属技能复合外键 |
| skill_trigger_rules | game_id＋skill_key＋rule_key | 公共列；event_type、event_source、condition_groups、actions、limits | 所属技能复合外键 |
| skill_object_references | 现有九列共同组成主键 | 来源类型、来源字段路径、目标类型、目标技能／对象／子项键 | 来源技能有物理外键；多态目标由业务校验保护 |
| character_skill_relations | game_id＋character_key＋skill_key | sort_order及现有元数据 | 同游戏角色与技能外键 |
| equipment_skill_relations | game_id＋equipment_key＋skill_key | sort_order及现有元数据 | 同游戏装备与技能外键 |
| rune_skill_relations | game_id＋rune_key＋skill_key | sort_order及现有元数据 | 同游戏符文与技能外键 |

现有删除策略按原建表脚本保留；不因补跨技能引用扩大级联删除。技能组成或子项被引用时，删除与改种类仍须检查依赖。

### 2.3 定义数据与本次计算数据分开

| 内容 | 是否进入上述管理表 | 例子 |
| --- | --- | --- |
| 稳定配置 | 是 | 伤害公式、最大弹药、恢复时间、历史窗口长度 |
| 引用关系 | 是 | Q读取P的计数；过程结束时引用本技能效果 |
| 来源说明与模拟约定 | 沿现有说明字段及统一文档 | 满蓄力、合并二次释放、本期不计算施法费用 |
| 某次场景的输入 | 不写入这些定义表 | 双方当前生命、起始层数、当前弹药、战前受伤记录 |
| 某次计算的变化记录 | 不写入这些定义表 | 本次扣血、护盾剩余、当前冷却结束时刻、累计受伤事件 |

因此，保留历史累计能力不要求先给管理库增加一张“每次战斗日志表”。本稿只定义历史读取的配置含义；其记录和计算方式属于后续运行设计。

## 3. 现有结构如何承载组合

### 3.1 参数与公式

| 字段 | 类型／枚举 | 数据约束与作用 |
| --- | --- | --- |
| value_type | INTEGER整数／DECIMAL十进制 | 限定参数值域，不代表单位 |
| value_mode | FIXED、SKILL_LEVEL、CHARACTER_LEVEL、RUNTIME_INPUT | 分别为固定、技能等级、角色等级和计算时输入 |
| fixed_value | numeric，可空 | 仅固定模式有值 |
| level_values | 等级键到数值的JSON对象，可空 | 仅等级模式有值，按对应等级范围完整保存 |
| expression | JSON对象 | OPERATION运算、PARAMETER参数、ATTRIBUTE属性三类节点；沿现有六种运算及双方属性取值 |
| 统一数值取值 | FIXED＋value，或PARAMETER＋parameterKey，或FORMULA＋formulaKey | 三种形状互斥；参数／公式仍属于引用方当前技能 |

RUNTIME_INPUT只声明所需数值，不保存某次输入值。供值关系由规则动作中的runtimeInputBindings定义。公式参数引用不因状态跨技能而一并放开；例如Q读取W层数，是将该层数提供给Q自己的输入参数，而非直接借用W的全部公式环境。

### 3.2 效果

| 字段／子项 | 现有形状 | 组合含义 |
| --- | --- | --- |
| results | 结果数组 | 每项含resultKey、resultType、target、valueRule、detail、lifecycleBehavior等 |
| resultKey | 同父效果内唯一稳定键 | 其他配置引用结果时必须同时知道所属技能、效果与结果 |
| resultType | 沿现有19种结果类型 | 伤害、治疗、盾、属性／资源／冷却变化、状态、修正等，不按英雄另造类型 |
| lifecycle | 对象或空 | 整个效果的实例范围、期限、层数、重施及周期定义 |
| lifecycleBehavior | 结果上的对象或空 | 描述结果在父效果中的应用时点、数值读取与层数组合方式 |
| results为空数组 | 仅在存在合法lifecycle时可用 | 纯资格标记，无须伪造一个伤害结果 |

普通护盾、法术护盾、伤害免疫、生命下限和处决仍为不同结果形状。取消施法费用不删除RESOURCE_CHANGE，因为怒气等保留机制仍可能使用通用资源变化。ATTACK_TIMER_RESET在本期组合中暂缓，不据此删除承载其他结果的results列。

### 3.3 过程与内部状态

| 位置 | 现有结构 | 数据职责 |
| --- | --- | --- |
| processes.steps | 有序步骤数组，stepKey同过程内唯一 | 保留IMMEDIATE、DELAY、MULTI_HIT、PERIODIC、CHANNEL、CHARGE、RECAST、EMPOWERED_BASIC_ATTACK八类现有定义 |
| processes.cooldown | durationValue＋startMoment或空 | 普通技能冷却长度及其开始时点 |
| processes.effect_bindings | bindingKey、effectKey、moment等 | 将过程时点关联到本技能效果 |
| processes.state_operations | operationKey、stateKey、operation、value、optionKey、moment等 | 指定状态操作与时点；本稿拟补状态所属技能 |
| states.state_type | COUNTER、AMMO、MODE、FLAG、INTERNAL_COOLDOWN | 计数、弹药、模式、标记、内部冷却 |
| states.scope | SKILL、TARGET | 只有COUNTER允许按目标；其他种类只允许技能范围 |
| states.detail | 按state_type分派的对象 | 初值、上限、恢复方式、模式选项或时长等 |

单一施放延迟用既有DELAY的delayValue。普通攻击间隔可由本技能公式表达1÷攻速秒，毫秒口径用1000÷攻速；这里确定数值来源和归属，不定义攻击排期算法。公式中的常量仍使用本技能参数，属性节点读取来源对象攻速。

最大层数、最大弹药等定义值与某次当前值分开。拟补的数据约束：可静态确定时初始计数／弹药不得超过对应上限；状态类型、范围和模式选项的现有限制继续成立。

### 3.4 规则

| 位置 | 现有形状 | 组合含义 |
| --- | --- | --- |
| event_source | eventType＋detail | 监听哪类事件，按何种来源筛选；event_type检索列保持一致 |
| condition_groups | 组数组，组内有条件数组 | 组间任一满足，组内全部满足；空组列表表示无附加条件 |
| actions | 动作数组 | 当前四类：执行效果、启动过程、推进过程、令过程失败 |
| runtimeInputBindings | 动作内的供值数组 | 把事件、状态或前序结果等数值绑定到被调用方参数 |
| resultModifiers | 动作内结果修正 | 按明确结果键指定现有允许的修正 |
| limits | 三项规则限制组成的对象 | 每目标冷却、每过程次数、同次使用限制；接口现有平铺方式不在此变更 |

规则没有直接写内部状态的第五种动作；状态写入通过过程state_operations表达。组、条件、动作、绑定等稳定键保持各自唯一范围；修改排序不改变身份，不能把数组位置当引用键。

## 4. 组合关系与引用范围

| 来源 | 目标 | 设计范围 | 归属如何记录 |
| --- | --- | --- | --- |
| 公式、数值取值 | 参数／公式 | 当前技能 | 沿现有parameterKey／formulaKey及当前skill_key |
| 过程效果挂接、规则执行效果 | 效果 | 当前技能 | 沿现有effectKey |
| 规则启动／推进／令过程失败 | 过程 | 当前技能 | 沿现有processKey |
| 状态操作、状态条件、状态事件、状态供值 | 内部状态 | 同游戏，可明确指向另一技能 | 拟新增stateSkillKey＋既有stateKey |
| 持续状态层数／剩余时间读取 | 来源效果和结果 | 同游戏，可明确读取另一技能的来源 | 拟新增effectSkillKey＋既有sourceEffectKey／sourceResultKey |
| 生命周期条件读取 | 效果生命周期 | 同游戏，可明确读取另一技能 | 拟新增effectSkillKey＋既有effectKey |
| 技能使用／命中等来源筛选 | 技能 | 同游戏 | 沿既有sourceSkillKey |
| 伤害事件来源筛选 | 技能 | 同游戏 | 在伤害事件detail拟新增sourceSkillKey |
| 生命周期盾结束依赖 | 普通护盾结果 | 只限同一父效果 | 拟新增endWhenShieldEndsResultKey |
| 冷却变化／技能急速范围 | 技能或分类 | 沿现有全技能、技能列表、分类三种方式 | 复用affectedSkillScope，不重复设计 |
| 属性、伤害类型、乘区、战斗状态身份 | 游戏目录 | 同游戏 | 沿相应目录键，不写死为英雄名称 |

跨技能引用仍引用一份有明确归属的数据。状态本身不移到全局变量表，不为Q、W等各复制同一个共享计数。引用中不加入某次战斗的对象编号、实际拥有者编号或瞬时剩余值。

### 4.1 内部状态引用：拟新增stateSkillKey

| 字段 | 类型／空值 | 约束 |
| --- | --- | --- |
| stateSkillKey | 稳定键字符串，目标结构必填 | 同game_id的技能；明确状态定义的归属 |
| stateKey | 稳定键字符串，必填 | 与game_id、stateSkillKey一起定位唯一内部状态 |
| optionKey | 现有可空稳定键 | 仅模式相关条件／操作使用，必须属于上述状态 |
| scope | 从目标状态定义读取，不在引用处重复存 | 不能通过引用绕过TARGET仅限计数的限制 |

涉及四处：processes.state_operations[]；规则INTERNAL_STATE_CHANGED事件明细；INTERNAL_STATE_CHECK条件明细；INTERNAL_STATE输入绑定明细。同技能引用也显式填写当前技能键。旧引用缺所属技能时，已知含义就是其原根对象的skill_key，可一次性补齐；不长期维护两种引用协议。

内部状态变化事件本稿仅扩展定义引用的形状，不定义新事件枚举或派发算法。引用存在性、种类、范围、模式选项及原有循环约束必须一起校验。

开发核对补充：规则动作的计算时输入绑定仍只指向规则本技能参数。跨技能状态操作若需要重新求取另一技能状态定义中的RUNTIME_INPUT，当前结构无法绑定该外部参数，应明确拒绝该组合；不能拿本技能同名参数冒充它，也不静默填零。固定值、等级参数及属性公式保持各自原定义技能的归属。本版不因此扩展跨技能参数绑定协议。

### 4.2 持续状态与生命周期读取：拟新增effectSkillKey

| 使用位置 | 所需字段 | 组合约束 |
| --- | --- | --- |
| STATUS_CHECK的层数／剩余时间比较 | effectSkillKey、sourceEffectKey、sourceResultKey及既有statusKey等 | 三键指向同游戏对应来源效果中的持续状态结果，且状态身份一致 |
| COMBAT_STATUS输入的层数／剩余时间 | 同上 | 同一明确来源，不能把同名状态的其他来源混在一起 |
| LIFECYCLE_CHECK条件 | effectSkillKey、effectKey及既有检查方式／对象 | 目标效果确实有生命周期；对象要求继续由该生命周期实例范围决定 |

状态仅检查存在／不存在时，沿现有状态身份与对象规则，不要求假造来源结果；禁止填入只属于层数读取的来源字段。以上只扩展读取，本版不开放跨技能执行任意效果或跨技能生命周期改写。

这一补充避免“为了跨技能读层数，把原持续效果层数再复制一份COUNTER”的重复数据。已有内部计数与持续效果层数各自保持唯一来源。

### 4.3 伤害事件筛选：拟新增sourceSkillKey

| 字段 | 类型／空值 | 约束与含义 |
| --- | --- | --- |
| sourceSkillKey | 稳定键字符串或null | 同游戏技能；null表示不按来源技能筛选 |
| damageTypeKey | 沿现有可空目录键 | 伤害类型筛选 |
| deliveryKind | ANY／SKILL／BASIC_ATTACK | 任意、技能、普攻产生方式 |
| originKind | ANY／DIRECT／REFLECTED | 任意、直接、反弹来源性质 |

仅补DAMAGE_PENDING、DAMAGE_DEALT、DAMAGE_TAKEN三类现有伤害事件的detail，不改变event_type列枚举。来源技能筛选描述“这笔伤害来自哪个技能”；结果所属技能、事件监听规则所属技能及触发它的其他技能不能因名字相近混为同一键。具体伤害归属仍需来源资料核定。

### 4.4 同父盾结束依赖：拟新增endWhenShieldEndsResultKey

字段位于skill_effects.lifecycle内部，类型为可空稳定键。null表示无此关联；非空只引用本效果results中的一项，不增加跨效果或跨技能的级联链。

数据约束如下，既有盾值、吸收类型、衰减、时长和属性增益公式保持其原定义：

- 引用必须唯一指向同父NORMAL_SHIELD结果，且其生命周期行为为PERSISTENT、stackValueMode为SHARED。
- maxStacksValue与applicationStacksValue在全部有效等级组合中必须静态恒为1；可用固定值、可确定的参数或公式。拒绝运行输入、属性读取等动态依赖、除零与任一等级非1，不能只检查当前选定等级。
- reapplicationStackMode必须为KEEP；expiryMode只允许ALL_AT_ONCE或EXPLICIT_ONLY，禁止ONE_BY_ONE与INDEPENDENT。期限有无及重施期限方式继续遵守原互斥约束，禁止独立重施计时。
- instanceScope为SOURCE时盾target必须为SOURCE；为TARGET或SOURCE_TARGET时必须为TARGET；SKILL范围禁止设置本关联。
- 同父所有持续结果的target必须与被引用盾一致，结果引用不得跨父效果或跨技能。

该字段表达父效果与指定盾结果的结束依赖，仅定义关联含义，不在本稿设计结束事件的执行方式。之前保留分支中的草稿不等于该字段已在活动代码实现。

## 5. 必要配置的最小补充

下列内容同样只定义配置字段；与前述三类引用补充一起作为第一版模型提案，均未实施。

### 5.1 弹药恢复与装填的启动条件

AMMO.detail现有initialValue、maxValue、recoveryIntervalValue、recoveryMode继续保留。recoveryMode已有ONE_BY_ONE逐个恢复、ALL_AT_ONCE整组恢复，但仅凭它不能完整说明何时开始恢复。

| 拟新增字段 | 类型／枚举 | 含义 |
| --- | --- | --- |
| recoveryStartCondition | 必填枚举 | AFTER_CONSUME：消耗后满足缺额即进入恢复；WHEN_EMPTY：弹药为空后进入恢复／装填 |

recoveryIntervalValue的含义随恢复方式明确：逐个恢复使用一发的恢复间隔，整组恢复使用整组装填时长。最大弹药为正整数，初值为非负整数且不超过上限，时间为正数。与既有模式组合时按真实装备／技能资料确认，不从名字“充能”自动判定。

旧数据不能只依据recoveryMode机械补启动条件。本批涉及的AMMO对象按来源直接整理，修改后满足新必填约束；本批之外的AMMO保持原样，不检查其是否补上本次新增字段。范围内确实缺少关键依据的对象单列，其他对象继续处理，不猜值或填零。本版不增加装填日志表或当前发次列；当前发次是某次场景状态，弹匣容量及装填规则才是管理定义。

### 5.2 战斗时长与近期受伤的供值定义

继续使用本技能RUNTIME_INPUT参数声明被公式读取的数值，在规则动作runtimeInputBindings中拟扩展两种sourceType。没有必要新增游戏全局变量目录或把历史记录塞入skill_parameters。

| 拟新增sourceType | 中文含义 | detail字段 | 数据约束 |
| --- | --- | --- | --- |
| COMBAT_ELAPSED_TIME | 所选对象本次入战后时长 | subject | subject沿现有SOURCE／CURRENT_TARGET／EVENT_SOURCE资格；结果单位为毫秒，不默认满层 |
| RECENT_DAMAGE_SUM | 最近时间窗的受伤累计 | subject、windowValue、outputKind、可空sourceSkillKey、可空damageTypeKey、deliveryKind、originKind | 窗口为正时长且不依赖计算时输入；筛选沿既有目录和三种伤害来源条件 |

RECENT_DAMAGE_SUM.outputKind首版限定POST_DEFENSE_DAMAGE（防御后伤害）或ACTUAL_HP_LOSS（实际扣血）；具体对象用哪一种须由来源核定，不把两种量互换。引用的窗口参数／公式仍属于规则所在技能；sourceSkillKey为同游戏筛选；subject中的事件来源对象仍须由原事件实际提供。

COMBAT_ELAPSED_TIME明确采用**按对象分别起算**的数据含义，不是全场统一经过时间。subject选择哪个对象，就读取该对象满足本次入战资格之后的时长；起点之前已入战的状态由场景提供，规则创建时间或技能拥有者不能替代另一个对象的起点。缺少必要入战事实时是缺输入，不能默认满层。面具持有者使用SOURCE；只有原事件提供独立来源对象时才能选EVENT_SOURCE。

该来源供给时长，面具每秒增伤的公式／等级表和上限属于对应技能定义，不存一个无依据的“最大倍率”。RECENT_DAMAGE_SUM供给的是明确定义的伤害量，不能代替为当前缺失生命。这里固定输入数据的归属和含义，不设计入战事件如何检测。

上述新增来源解决“配置应写什么”，不定义如何记录历史、如何维护战斗开始时点或如何调度读取。能力存在、数据可保存和运行可用仍是不同状态。

## 6. 数据约束由哪一层保证

| 约束 | 数据库直接保证 | 管理保存校验／完整引用检查 |
| --- | --- | --- |
| 根对象身份、技能归属 | 主键、复合外键 | 保留现有不可改键规则 |
| 数组或对象的顶层形状 | 现有JSONB检查约束 | 本次变更对象按新定义检查明细形状、必填和未知字段；未调整旧对象不强制补新增字段 |
| 嵌套子项身份 | 不为每项建立物理行 | 检查键唯一、父对象正确及排序字段合法 |
| 新的跨技能状态／效果读取 | 引用索引已有目标技能键，但不是目标物理外键 | 检查同游戏目标三键、类型、范围、状态身份和允许方向 |
| 盾结果依赖 | 无新增物理外键 | 检查同父、普通盾类型、持续行为、单层及目标一致 |
| 参数／公式依赖 | 根表外键不覆盖树内每个键 | 完整取值图、依赖、类型与可静态检查的边界 |
| 原对象被删、改种类或移除子项 | 沿现有物理删除约束 | 最终聚合引用检查；失败不保存半份对象 |
| 伤害来源与历史读取筛选 | 保留原事件种类列 | 检查新增明细字段及来源资格、窗口、数值口径 |

引用索引继续使用game_id、source_skill_key、source_type、source_key、field_path、target_type、target_skill_key、target_key、target_sub_key九列。状态引用写目标状态所属技能；结果读取还写父效果与结果子键。按本次受影响的来源对象重新提取并替换其索引，未调整对象的索引保留，不让作者单独维护第二份关系。

当前代码会在同游戏提交时校验全部聚合并整体替换引用索引；**这处现有行为需随本版调整**：保留写事务及引用存在性、删除保护，但新增字段的完整形状校验限定在本次变更对象及其实际受影响的本批组合，不扫描范围外旧对象的新字段完整性。必要的外部依赖可以只读核对，不借此扩大写入范围；若删除会破坏未改动对象的既有引用，保留相应对象／关系，不顺手清理外部数据。

49名名单用于确定本批整理清单，不写进通用表约束或按英雄名分支。后续其他对象进入实际编辑时直接按新模型整理；本次不为尚未处理的数据开发新旧双协议读写或自动后台迁移。实际实例拥有者、某次挂载是否具备所引用技能等也不是静态数据库外键能证明的内容。

## 8. 用代表配置检验表能否表达

以下键名仅为设计示例，不是要求新增业务对象，不代表对象当前已经保存为该形状。

### 8.1 普通伤害与冷却

库奇Q类配置：技能主体关联等级参数；公式引用本技能参数和来源属性；伤害效果保存DAMAGE结果；过程保存一个总施放延迟与普通冷却；规则关联使用、过程和伤害所需入口。过程时点、规则及效果中的键能唯一定位相应对象，不把同一条伤害复制到两个位置作为同一次执行的替代。

普通普攻的间隔公式可写成“毫秒常量参数1000 ÷ 来源对象攻速”，供普通攻击相关冷却定义引用。本稿只核对公式和引用可存，不证明现有管理入口已经支持全部攻击组合。

### 8.2 跨技能共享一份计数

假设计数定义属于annie_p，键为pyromania。annie_q的过程状态操作引用：

~~~json
{
  "stateSkillKey": "annie_p",
  "stateKey": "pyromania"
}
~~~

上面只是状态引用片段，完整状态操作仍须具备既有operationKey、operation、moment等字段。另一技能的条件或输入绑定引用同样两键即可指向同一份定义；不会另建一份Q专用的同名计数。归属表行仍为(game_id, annie_p, pyromania)。

韦鲁斯W若采用TARGET范围计数，仍只有W拥有的定义，Q的引用明确指向W；如果实际配置采用持续状态结果层数，则使用effectSkillKey＋来源效果＋来源结果读取，不能为了共享再复制第二份计数。

### 8.3 按伤害来源技能关联持续效果

### 8.5 弹药与装填

逐发恢复示例：recoveryMode为ONE_BY_ONE，recoveryStartCondition为AFTER_CONSUME，recoveryIntervalValue定义一发恢复间隔。整匣装填示例：ALL_AT_ONCE＋WHEN_EMPTY，时长定义整匣装填等待。烬等特殊普攻的实际容量、节拍和资格按原资料核对；两种示例只说明字段的组合含义。

面具对应技能可以声明一个战斗时长输入参数，来源选择COMBAT_ELAPSED_TIME；受苦增伤公式与灼烧结果分开保存。雷恩加尔W类技能声明一个近期受伤量参数，来源选择RECENT_DAMAGE_SUM，明确窗口和累计数值口径；窗口定义是配置，窗口内每次伤害记录不是管理表行。

7. 不开发新旧双写、通用版本兼容层或全库自动迁移。范围外以后确实要用时再按新模型直接整理，不提前覆盖。

## 10. 数据模型验收清单

| 检查 | 应得到的结果 |
| --- | --- |
| 本技能组合 | 过程、效果、状态、规则均可唯一定位，不需要重复保存同一份定义 |
| 跨技能计数 | 引用另一技能计数成功；错误游戏、错误状态键或模式选项被拒绝 |
| 持续状态读取 | 效果、结果、状态身份不一致被拒绝；存在性检查不要求无意义来源 |
| 删除保护 | 被引用根对象或嵌套子项删除被拒绝，提示准确的来源字段 |
| 类型与范围 | 非COUNTER不能伪装TARGET状态；操作／读取类型与被引用状态匹配 |
| 伤害事件筛选 | sourceSkillKey合法或null；其他事件不因此接受任意额外字段 |
| 盾关联 | 跨父、跨技能、非普通盾、多层或对象不一致被拒绝 |
| 弹药定义 | 本批变更对象的容量、初值、恢复时长与启动条件齐全；范围外旧AMMO缺新增字段不阻断本批 |
| 两种新增供值 | 单位、窗口、对象资格与筛选明确；历史量不与当前缺血量混用 |
| 旧数据范围 | 新字段只整理本批对象；范围外定义和索引保持，不能因全游戏校验要求扩大迁移 |
