## 1. 本次需要确认的决定

1. 状态是游戏下可被多个技能引用、存在本身需要被规则识别的独立记录，使用独立 `statuses` 表、独立接口和独立“状态管理”页面；它不是所有持续数值效果的通用容器。
2. 状态维护稳定标识、行为种类、名称、说明、启停状态和排序；数值、期限和重施行为仍由效果管理。
3. 行为种类及普通减速的当前共享定义统一见[系统精简实施说明第四单元](系统精简实施说明.md#第四单元状态身份与普通减速强度)，它不是自由分类，不建设分类页面。攻速增加、护甲降低等持续属性变化和普通护盾仍属于技能效果，不在状态管理中建立对应数值记录。
4. 状态名称在同一游戏内忽略大小写和首尾空格唯一，避免技能效果选择时出现无法区分的同名记录。
5. 状态创建后稳定标识不可修改；停用不删除记录，也不释放标识和名称。
6. 后续新增状态引用时只能选择启用记录；已经存在的引用允许继续读取停用记录。具体引用关系在阶段 7.2 建设。
7. 状态被后续效果引用时禁止删除并返回稳定冲突错误；本阶段先冻结错误和删除语义，不提前创建效果表。
8. 不预置眩晕、沉默等默认记录，验收数据只通过页面手工建立。
9. 本阶段不复用旧战斗数据状态结构，不迁移旧状态数据，也不接入发布、计算或 Wasm。

上述决定不授权增加自由分类、生命周期字段、旧数据兼容或运行时状态实例。2026-09-19 的状态种类增量按第四单元实施，原阶段 7.1 验收记录保留历史含义。

## 2. 范围

本阶段交付：

1. 状态的新建、查询、查看、编辑、启用、停用和删除。

6. 旧 `status_definitions`、旧 combat-data 状态表或旧 Provider/Ability 结构的读取、迁移、兼容和双写。

## 3. 公共数据契约

状态完整响应：

```json
{
  "gameId": "lol",
  "statusKey": "stun",
  "statusKind": "STUN",
  "name": "眩晕",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10,
  "createdAt": "2026-08-27T00:00:00Z",
  "updatedAt": "2026-08-27T00:00:00Z"
}
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `gameId` | 所属游戏，只从路径和响应提供，不允许请求体修改。 |
| `statusKey` | 创建时必填并去除首尾空格；小写字母开头，只含小写字母、数字和下划线，长度 1～64；创建后不可修改。 |
| `statusKind` | 状态行为身份；取值、必填和不可变规则统一见第四单元。 |
| `name` | 必填；去除首尾空格后长度 1～100；同一游戏内忽略大小写和首尾空格唯一。 |
| `description` | 可省略或为 null；去除首尾空格，空串保存为 null；最长 2000。 |
| `status` | 必填；只允许 `ENABLED` 或 `DISABLED`。 |
| `sortOrder` | 必填；必须是大于等于 0 的整数。 |
| `createdAt` / `updatedAt` | 仅响应，由后端维护。 |

`0` 是合法排序值。状态停用后仍参与稳定标识和名称唯一校验。

## 4. HTTP 契约

```text
GET    /api/admin/games/{gameId}/statuses?keyword=&status=
GET    /api/admin/games/{gameId}/statuses/{statusKey}
POST   /api/admin/games/{gameId}/statuses
PUT    /api/admin/games/{gameId}/statuses/{statusKey}
DELETE /api/admin/games/{gameId}/statuses/{statusKey}
```

### 4.1 查询

1. `keyword` 可选，按状态标识和名称不区分大小写包含查询；去除首尾空格后空串等同省略，最长 100。
2. `status` 可选，只允许 `ENABLED` 或 `DISABLED`；空串等同省略。
3. 返回顺序固定为 `sortOrder ASC, name ASC, statusKey ASC`。
4. 当前不分页，统一返回 `{"items":[],"total":0}`。
5. 所有接口先验证游戏存在；不存在返回 `404.GAME_NOT_FOUND`，列表不得用空数组掩盖游戏不存在。

### 4.2 创建

```json
{
  "statusKey": "stun",
  "statusKind": "STUN",
  "name": "眩晕",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10
}
```

创建成功返回 201 和完整状态响应。

### 4.3 更新

```json
{
  "statusKind": "STUN",
  "name": "眩晕",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10
}
```

PUT 为全量修改。稳定标识只来自路径；请求体中的 `statusKey` 只允许省略或为 null，非 null 时返回 `400.VALIDATION_FAILED` 并定位到 `statusKey`。成功返回 200 和完整响应。

更新请求必须携带当前 `statusKind`，不能通过更新改变状态行为身份。

### 4.4 启用与停用

启用和停用复用 PUT。前端携带当前种类、名称、说明、排序和目标启停状态全量提交。页面必须直接提供“启用”或“停用”，不能要求进入编辑弹窗修改状态。

### 4.5 删除

1. 删除成功返回 204。
2. 记录不存在返回 `404.STATUS_NOT_FOUND`。
3. 未被引用的启用或停用记录都可以删除。
4. 状态被后续效果引用时返回 `409.STATUS_IN_USE`，不得级联删除效果或其他引用方。

## 5. 稳定错误

沿用现有统一错误外壳和 `details.fieldIssues`：

| HTTP | code | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | JSON 语法、字段类型或状态枚举无法绑定。 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、查询参数或格式错误。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.STATUS_NOT_FOUND` | 状态不存在。 |
| 409 | `409.STATUS_KEY_EXISTS` | 同一游戏状态标识重复。 |
| 409 | `409.STATUS_NAME_EXISTS` | 同一游戏状态名称重复。 |
| 409 | `409.STATUS_IN_USE` | 状态已被引用，不能删除。 |

查询参数中的非法 `status` 返回 `400.VALIDATION_FAILED` 并定位到 `status`；JSON 请求体中的未知状态值按无法绑定处理，返回 `400.INVALID_BODY`。前端不得解析数据库原文判断错误类型。

## 6. 页面外部行为

1. 主导航新增“状态管理”，路由为 `#/statuses`，放在“技能管理”之后、“游戏配置”之前。
2. 页面提供关键词、状态筛选、查询、重置、刷新、新增、查看、编辑、启用/停用和删除。
3. 列表显示状态名称、状态标识、说明、启停状态、排序、更新时间和操作；对应列标题固定为“启停状态”。
4. 状态筛选使用可见的“全部 / 启用 / 停用”单选按钮，查询前后选中值保持稳定。
5. 新增、查看、编辑、状态确认和删除确认全部使用现有组件库默认弹窗，不覆盖边框、阴影、定位或宽度样式。
6. 新增默认启用、排序默认 0；编辑时状态标识只读，启停只从列表直接操作。
7. 点击遮罩或按 Esc 可以关闭资料弹窗，直接丢弃未保存内容；不在弹窗内增加二次确认。
8. 保存成功自动关闭资料弹窗并刷新当前查询；保存失败保留弹窗、输入和字段错误。
9. 启停或删除成功关闭确认弹窗并刷新；失败时保留确认弹窗和错误信息。
10. 页面不展示用途说明、学习提示或引导段落；空列表只显示“暂无状态”。

## 8. 跨端验收

以下记录只作为手工验收样例，不写入种子：

1. `stun / 眩晕`
2. `silence / 沉默`

必须同时满足：

1. 空表打开显示“暂无状态”，不自动创建默认记录。
2. 状态可以创建、刷新回读、查看、编辑名称/说明/排序、停用、启用和删除。
3. 重复标识、重复名称、非法标识、空名称、超长说明、负排序和非法状态均返回稳定错误。
4. 状态筛选连续切换、查询和重置后，页面选中值与实际请求一致。
5. 点击遮罩或按 Esc 可以关闭资料弹窗；保存成功必定自动关闭，保存失败保留草稿。
6. 页面和接口不出现状态分类、持续时间、层数、刷新、到期、周期、技能、公式、效果、图片、发布或 Wasm 字段。
7. 数据库只保存基础字段，不出现状态配置大块内容、旧状态表兼容读取或默认数据。
8. 后续用测试外键模拟引用时，删除映射为 `409.STATUS_IN_USE`，不删除引用方。
9. 真实接口除主链外至少抽查一条字段错误返回 400，以及一条重复标识或重复名称返回 409；其余错误由自动测试完整覆盖。

## 9. 停止门禁

出现以下任一情况必须停止并回到方案确认：

1. 实施必须复用或恢复旧 `status_definitions`、旧 combat-data 状态表、Provider 或 Ability 结构。
2. 目标数据库已经存在结构不一致的 `public.statuses`。
3. 状态基本资料无法通过独立表和真实游戏外键表达。
4. 实施需要提前增加分类、生命周期、效果、计算、发布或 Wasm 字段。
5. 实现必须新增通用字典框架、通用状态类型页面或自定义弹窗样式。
6. 后端完整测试、前端完整验证或真实数据库迁移不可用，且无法定点确认原因。

触发任一门禁时暂停，不自行增加兼容层或扩大阶段范围。
