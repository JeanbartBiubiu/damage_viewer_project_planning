## 2. 目标与成功标准

目标：

1. 结果可以按全部技能、明确技能或技能分类选择作用范围。
2. 相同范围结构可以被两个已确认结果复用，不复制不同字段和关系表。
3. 分类范围保存分类引用，不在保存时展开成技能快照。
4. 现有冷却变化数据可以无损迁移到新范围结构。
5. 能保存“位移类技能增加 180 技能急速”的配置。

成功标准：

1. 三种范围均能创建、修改、回读和删除。
2. 冷却变化与技能急速结果都使用相同的接口范围对象。
3. 迁移后既有伊泽瑞尔 Q 多技能冷却变化仍是一个结果，目标集合不丢失。
4. 未知、停用、重复或形状冲突的范围被稳定拒绝。
5. 页面不需要用户离开结果弹窗才能新增技能分类。
6. 验收只证明配置闭环，不宣称技能急速或冷却已经执行。

## 3. 范围与非目标

本补项包含：

1. 一个公共技能作用范围对象。
2. 冷却变化结果切换到公共技能范围。
3. 一种固定技能急速修正结果。
4. 技能和技能分类引用、启停规则和删除保护。
5. 既有效果聚合接口和结果弹窗的增量。
6. 阶段 7.6.5 公式可达性、结果引用和事件图累计回归。

本补项不包含：

1. 角色与技能、装备与技能的挂载关系。
2. 角色技能、装备技能来源筛选或自动排除字段。
3. 海克斯、天赋或符文管理页面。
4. 技能急速换算、当前冷却执行、时间线、Wasm 或计算输入。
5. 任意结果都能挂技能范围的开放结构。
6. 技能交集、排除集合、分类条件表达式或自由脚本。
7. 为技能急速建立乘区。
8. 兼容旧的扁平 `affectedSkillKeys` 接口字段。

## 4. 公共技能作用范围

### 4.1 接口形状

公共对象固定为：

```json
{
  "mode": "CATEGORIES",
  "skillKeys": [],
  "skillCategoryKeys": ["displacement"]
}
```

字段：

| 字段 | 规则 |
| --- | --- |
| `mode` | 必填，只允许 `ALL / SKILLS / CATEGORIES`。 |
| `skillKeys` | 必填数组，仅 `SKILLS` 时允许非空。 |
| `skillCategoryKeys` | 必填数组，仅 `CATEGORIES` 时允许非空。 |

固定形状：

| `mode` | `skillKeys` | `skillCategoryKeys` |
| --- | --- | --- |
| `ALL` | 必须为空 | 必须为空 |
| `SKILLS` | 至少一项 | 必须为空 |
| `CATEGORIES` | 必须为空 | 至少一项 |

两个数组均禁止 null、空字符串和重复项。响应按目录稳定顺序返回，不保留点击顺序。

### 4.2 匹配语义

1. `ALL` 表示作用对象实际拥有的完整技能集合。
2. `SKILLS` 表示该集合中标识命中的技能。
3. `CATEGORIES` 表示该集合中属于任一已选分类的技能。
4. 多个分类按并集匹配；同一技能命中多个分类时，同一结果只处理一次。
5. 范围不区分技能由角色还是装备提供，二者遵守同一规则。
6. 当前配置阶段只保存范围；“实际拥有的技能集合”由阶段 9 挂载关系和阶段 11 计算输入共同提供。
7. 分类关系改变后，范围继续引用分类本身，不保留旧的展开结果。

### 4.3 当前允许使用范围的结果

| 结果 | 是否必填 | 含义 |
| --- | --- | --- |
| `COOLDOWN_CHANGE` | 必填 | 对匹配技能的当前冷却执行既有减少、增加或重置。 |
| `SKILL_HASTE_MODIFIER` | 必填 | 对匹配技能持续增加或减少技能急速点数。 |

其他结果不得提交技能作用范围。范围结构不是自由扩展点；新增第三个使用方必须更新固定联合、数据库形状和页面矩阵。

## 5. 两种结果契约

### 5.1 冷却变化

既有 `COOLDOWN_CHANGE.detail` 调整为：

```json
{
  "operation": "REDUCE",
  "affectedSkillScope": {
    "mode": "SKILLS",
    "skillKeys": ["ez_q", "ez_w", "ez_e", "ez_r"],
    "skillCategoryKeys": []
  }
}
```

规则：

1. `operation` 仍只允许 `REDUCE / INCREASE / RESET`。
2. `REDUCE / INCREASE` 必须有数值规则，单位仍为毫秒。
3. `RESET` 不得有数值规则。
4. 旧 `detail.affectedSkillKeys` 不再接受、返回或双写。
5. 一个结果无论匹配多少技能，仍只有一个结果身份、一个操作和一套数值规则。
6. `ALL` 是冷却变化的合法范围；后端和前端均不得继续要求至少一个明确技能。

### 5.2 技能急速修正

新增固定结果 `SKILL_HASTE_MODIFIER`，中文名称为“技能急速修正”。`detail` 固定为：

```json
{
  "operation": "INCREASE",
  "affectedSkillScope": {
    "mode": "CATEGORIES",
    "skillKeys": [],
    "skillCategoryKeys": ["displacement"]
  }
}
```

规则：

1. `operation` 只允许 `INCREASE / DECREASE`。
2. `valueRule` 必填，公式结果按非负技能急速点数解释，不是秒数或百分比。
3. `target` 继续使用结果公共字段 `SOURCE / TARGET`，表示修改哪一方拥有的技能集合。
4. 必须属于有生命周期效果，且 `lifecycleBehavior.moment = PERSISTENT`。
5. 本版只允许 `valueReadMode = APPLICATION_SNAPSHOT`；层值和重复施加值沿用现有持续数值快照规则。
6. `spellShieldBlockScope` 和 `modifierZoneKey` 均不得提交。

固定增加 180 时公式返回 180，不能录成 `1.8` 或 `180%`。

## 6. 属性、技能急速与乘区边界

| 业务含义 | 维护位置 |
| --- | --- |
| 角色或装备提供、对全部技能生效的普通技能急速 | 角色或装备属性 |
| 只对特定技能集合生效的技能急速 | `SKILL_HASTE_MODIFIER` + 公共技能作用范围 |
| 一次性减少、增加或重置已经产生的当前冷却 | `COOLDOWN_CHANGE` + 公共技能作用范围 |

技能急速修正不使用乘区：

1. 技能急速点数是未来冷却公式的加算输入，不是伤害、治疗或属性比例乘区。
2. 多个生效结果命中同一技能时，未来按结果分别产生有符号点数后汇总。
3. 全局技能急速属性与范围修正如何合并并换算冷却留到阶段 11，本轮只保留可区分的数据来源。

## 7. 接口与聚合边界

继续使用既有效果聚合接口：

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/effects
PUT    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
```

1. POST/PUT 一次提交完整效果、生命周期和结果数组。
2. 不增加范围、技能目标、分类目标或技能急速明细的子接口。
3. 后端完整响应必须包含规范化后的 `affectedSkillScope`。
4. `resultCount` 仍按结果数量统计，不按范围关系或未来匹配数量展开。

## 8. 引用、启停和删除

1. `SKILLS` 的每个技能必须属于同一游戏。
2. `CATEGORIES` 的每个技能分类必须属于同一游戏。
3. 新建或改变范围时只允许启用的技能和分类。
4. 已有停用引用可以原样保留；新增、替换或重新选中停用引用必须失败。
5. 明确技能被其他技能的冷却变化或技能急速结果引用时，删除返回既有技能占用错误。
6. 技能分类被任一范围引用时，删除返回既有技能分类占用错误。
7. 删除结果或效果只清理自身范围和明细，不删除目录对象。
8. 删除结果所属技能时，自身效果先清理；自身明确引用不阻止删除，外部引用仍阻止。

## 9. 破坏式替换与数据迁移

当前为 MVP，不保留旧接口兼容：

1. 既有冷却变化的明确技能关系迁入公共范围，模式固定为 `SKILLS`。
2. 迁移逐结果核对目标数，复制成功且数量一致后才能移除旧关系结构。
3. 不新增旧字段读取、双写、兼容响应或前端回退。
4. 已发布版本和 Wasm 输入不在本轮迁移范围。
5. 新库直接使用公共范围最终结构。

迁移失败必须整体回滚，不能留下同一结果同时使用新旧两种范围的状态。

## 10. 稳定错误

不新增顶层错误码：

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.VALIDATION_FAILED` | 范围形状、结果组合、重复项、多余旧字段或生命周期不合法。 |
| 400 | `400.INVALID_SKILL_EFFECT_REFERENCE` | 公式、技能或技能分类不存在或跨游戏。 |
| 409 | `409.SKILL_EFFECT_REFERENCE_DISABLED` | 新增、替换或重新选择停用技能或技能分类；PUT 原样保留已有停用引用除外。 |
| 409 | `409.SKILL_EFFECT_IN_USE` | 修改结果破坏既有触发规则引用或公式参数绑定。 |
| 409 | `409.SKILL_FORMULA_IN_USE` | 删除仍被技能急速结果引用的公式。 |
| 409 | `409.SKILL_IN_USE` | 删除仍被公共范围明确引用的技能。 |
| 409 | `409.SKILL_CATEGORY_IN_USE` | 删除仍被公共范围引用的技能分类。 |

字段问题使用实际路径：

```text
results[0].detail.affectedSkillScope.mode
results[0].detail.affectedSkillScope.skillKeys[1]
results[0].detail.affectedSkillScope.skillCategoryKeys[0]
results[0].lifecycleBehavior.moment
```

## 11. 页面外部行为

1. 继续在“技能管理 → 效果与结果 → 新增/编辑结果”中配置，不新增导航或独立页面。

4. 范围为指定技能时显示技能多选框。
5. 范围为指定技能分类时显示分类多选框，并提供“新增技能分类”。
6. 新增分类成功后刷新目录并自动选中；失败保留父结果和分类草稿。
7. 切换范围立即清空隐藏集合。
8. 查看和摘要显示中文名称；未知或停用旧引用不能静默丢失。

10. 弹窗沿用组件库默认样式和当前 2K 桌面宽度，不做移动端适配。

## 12. 与阶段 7.6.5 的关系

1. 冷却变化的结果身份、操作和值规则不因范围重构而改变。
2. 技能急速结果的数值公式进入既有执行效果和过程挂接的可达公式收集。
3. 技能急速结果只能持续生效，因此不提供立即可用的前序结果输出。
4. 技能范围本身不产生事件；技能急速结果也不产生伤害、治疗、状态、击杀或联动事件边。
5. 阶段 7.6.5 的十种前序输出、二十一种事件和二十三种事件值保持不变。
6. 效果修改和结果删除继续经过现有入站引用保护。

## 14. 跨端验收

### 14.1 既有冷却变化迁移

1. 迁移前准备一个含 Q/W/E/R 四个明确目标的冷却变化结果。
2. 迁移后结果返回 `mode = SKILLS`，四个技能标识完整，旧字段不再返回。
3. 数据库只有一条公共范围和四条明确技能关系，没有旧目标关系。
4. 保存、刷新、后端重启和再次回读均保持一致。

### 14.2 三种范围

1. 两种结果均可保存 `ALL`，两个目标数组为空。
2. 两种结果均可保存多个明确技能，响应稳定排序。
3. 两种结果均可保存多个分类，数据库不展开技能。
4. 三种模式来回切换后只保留当前模式关系。
5. 多分类使用并集语义；配置层不计算实际匹配结果。

### 14.3 位移技能急速案例

准备启用的“位移”分类和返回 180 的公式，创建永久生效效果：

```json
{
  "resultType": "SKILL_HASTE_MODIFIER",
  "target": "SOURCE",
  "valueRule": {
    "formulaKey": "skill_haste_180",
    "fixedMultiplier": 1,
    "fixedMinValue": null,
    "fixedMaxValue": null
  },
  "detail": {
    "operation": "INCREASE",
    "affectedSkillScope": {
      "mode": "CATEGORIES",
      "skillKeys": [],
      "skillCategoryKeys": ["displacement"]
    }
  },
  "spellShieldBlockScope": null,
  "lifecycleBehavior": {
    "moment": "PERSISTENT",
    "valueReadMode": "APPLICATION_SNAPSHOT",
    "stackValueMode": "SHARED",
    "reapplicationValueMode": "KEEP",
    "periodicExecutionMode": null
  }
}
```

验收只证明结构保存与回读，不宣称位移技能已经获得 180 技能急速。

### 14.4 拒绝与保护

1. 空的 `SKILLS`、空的 `CATEGORIES`、重复项和同时提交两类目标均返回 400。
2. 冷却变化提交旧 `affectedSkillKeys` 返回 400，不静默转换。
3. 未知或跨游戏技能/分类返回 400；新增、替换或重新选择停用技能/分类返回既有 409；事务均无半成品。
4. 技能急速结果缺少生命周期、非持续时点、非快照读取、携带乘区或法术护盾范围均返回 400。
5. 被引用技能和分类删除分别返回既有 409，占用解除后可删除。
6. 删除效果只清理范围和结果明细，不删除目录对象。
7. 阶段 7.6.5 十种输出、二十一种事件及相关回归保持通过。

## 15. 重点评审问题

1. 公共范围表以效果结果为唯一父级，并由固定结果白名单约束，是否足以避免通用多态关系。
2. 既有冷却目标迁移到 `SKILLS` 后立即删除旧结构，是否覆盖全部回滚和计数校验。
3. 技能急速结果只开放施加时快照，是否与现有生命周期检查兼容且没有遗漏封闭分支。
4. 阶段 7.6.5 的输出、事件、公式可达性和结果删除保护是否有遗漏影响面。

## 16. 停止条件

出现以下任一情况停止并回到方案：

1. 阶段 7.6.5 实际结果联合、数据库结构或触发规则保护与本文前提不一致。
2. 公共范围无法通过真实外键和固定结果白名单约束，必须退化为自由多态关系。
3. 冷却变化旧目标无法在单事务内无损迁移并核对数量。
4. 配置保存必须依赖阶段 9 挂载或阶段 11 计算才能完成。
5. 实现需要 JSONB、数组外键、自由条件表达式或来源筛选字段。
6. 自动检查、真实数据库、真实接口或桌面页面验收不可用且无法定点确认原因。
