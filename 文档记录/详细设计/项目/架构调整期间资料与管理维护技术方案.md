# 架构调整期间资料与管理维护技术方案

## 1. 目标与范围

在 Wasm 架构讨论期间，把可以独立验收的资料准备、数据健康检查和管理体验修复做实。本轮基线为 `8bbafdf11`，从最新主干创建短期分支和临时工作树。逐对象进度继续以 `数据参考/全量录入-2026-09/阶段进度.json` 为唯一来源；本方案归属现有任务 `planning-full-data-entry`，不为内部步骤新增任务。

交付四项：可复现的离线资料队列和首批来源卡、只读配置引用审计、管理页加载及通用错误提示修复、后台图片目录轻量化。资料整理先覆盖现有重点范围；首批人工核对阿卡丽被动、Q、E、R。资料完整、管理配置保存、正式运行证明分别记录。

本轮实现与本地验收已完成，证据及发现的现有资料问题见[验收记录](../../测试记录/项目/资料准备与管理维护验收-2026-10-28.md)。本方案保持当前行为定义，验证数字与历史评审只在验收记录维护。

本轮不修改 Wasm、共享技能模型、战斗机制、全局游戏规则或已有正式证明身份；不写业务库，不执行迁移或索引修复，不自动把来源卡变成可运行配置，不部署、合并或推送。来源快照不联网覆盖，确有新资料需求时另行记录页面与版本。

## 2. 当前事实与资料边界

当前台账的重点范围由 `heroes.priorityScope.batches[].heroes.sourceChampionId` 决定，为41名英雄、205个技能槽；明确排除25个，有效分母180。历史文档里的50名、49名和全库865个槽不用于本轮分母。工具每次从输入重新统计，不把这些数字写死。

本地全英雄 Wiki 入口为 `数据参考/lol-wiki-champions-full/README.md`。页面目录、原文和依赖分别位于 `champions/`、`raw/`、`dependencies/`；来源版本、页面修订和原文摘要共同构成证据。旧资料分类器的单目标伤害范围不作为当前机制资格判定。

现有正式证明中存在英雄整体记录，而台账按技能槽记录。两者状态不一致只列为“口径待复核”；不能据此宣布台账错误或把该英雄全部技能改成完成。运行证明中的排除项和管理配置的完整性需要分别核对。

## 3. 离线资料与进度对账

### 3.1 输入与输出

入口为 `tools/data-readiness/cli.mjs`，使用 Node.js 内置库，支持 `--repo-root`、`--output`、`--check`，可显式指定正式证明清单。输入只读。默认生成目录位于被忽略的 `output/maintenance-20261028/`；通过人工核对的有界来源卡位于 `数据参考/全量录入-2026-09/资料准备-2026-10-28/`。

输出包括重点范围队列、来源卡、台账与证明对账、中文摘要。排序、字段和摘要稳定；相同输入重复运行应产生相同结果。检查模式校验输入和既有产物，不改输入、台账或来源文件；拒绝把输出目录指向输入资料或仓库源码。

### 3.2 来源卡约束

每张卡至少包含技能标识、英雄、槽位、台账结论、来源 URL、页面修订号及时间、原文相对路径、字节数和 SHA-256 摘要、相关原文及待核事项。逐一校验被引用文件的真实字节及摘要；路径越界、缺页、修订不一致、损坏文件必须明确失败。

等级数值、公式、触发条件和持续时间保留原文。不能把正则抽出的数字直接认定为等级曲线，不能把空值补零，也不因资料齐备自动标记可录入或可运行。首批来源卡只回答“依据在哪里、还需要核对什么”，后续录入仍走现行保护保存与独立回读流程。

### 3.3 对账约束

报告重点范围内各结论计数和排除后的分母；正式证明只按真实标识关联，并保留证明状态、身份与范围。英雄整体通过与单技能暂缓并存时输出待复核提示，不能展开为每个槽位都通过。缺少正式证明不推断机制不支持。工具不修改 `阶段进度.json`。

## 4. 后端只读引用审计

新增管理读取能力，对指定游戏的当前配置重新提取引用，与保存的 `skill_object_references` 对比。复用现有 `SkillObjectReferences` 的提取与目标检查语义，不再实现第二套引用识别器，也不调用写入护栏的事务入口。

同一次只读、可重复读事务读取源聚合、目标目录和现存索引，保证对比来自一致视图。引用身份包含游戏、来源技能/类型/对象/字段路径，以及目标类型/技能/对象/子对象；不能只比较目标键。报告缺少的索引、多余的索引、目标不存在和无法提取的源对象，保留可定位的稳定键和字段路径。

审计输出包含读取数量、问题总数、展示数量和完整性；展示问题必须有上限。达到读取规模限制、源对象无法解析或检查未完成时，明确标记未完成，不能返回“健康”。接口只表示引用一致性，不表示所有业务语义、数值或运行时可用。读取错误沿现有错误模型返回，鉴权及游戏隔离保持现行规则。

管理路由为 `GET /api/admin/games/{gameId}/configuration-reference-audit`，沿现有管理鉴权；不存在游戏返回现行游戏不存在错误。响应的 `gameId` 表示范围，`complete` 表示是否完成审计，`healthy` 仅在完整且零问题时为真；`observedIssueCount` 是已确定问题数，完整时 `totalIssueCount` 为精确总数，不完整时为 `null`。`returnedIssueCount` 和 `truncated` 表示展示数量与是否省略问题；仅展示截断不会使审计变成未完成。`counts` 的 `sourceCount`、`existingReferenceCount`、`catalogTargetCount`、`extractedReferenceCount` 分别记录源、现存引用、目录目标和提取引用数量；未完成的提取数量为 `null`。

`issues` 最多200项，按问题类别及完整来源/目标身份稳定排序；每项包含 `code`、中文 `message` 和上述定位字段。类别为 `INDEX_MISSING`（缺少索引）、`INDEX_EXTRA`（多余索引）、`TARGET_MISSING`（目标不存在）、`SOURCE_JSON_INVALID`（源对象无法提取）、`AUDIT_LIMIT_EXCEEDED`（超出审计预算）。不返回源 JSON 或完整数据库异常。

读取预算为5000个源、50000条现存引用、20000个目录目标、50000条唯一提取引用，源 JSON 与引用路径合计32MiB且单源不超过2MiB。在数据库内先统计行数与字节，再读取正文；恰好等于上限仍允许完整审计，超过上限或读取保险证明遗漏则报告未完成。源、目录、索引投影直接在包内复用写入护栏已有的只读 SQL 常量；不修改写入护栏，不额外暴露其内部快照。目标校验按目标所属上下文分组，避免每条引用扫描完整游戏配置。

逐源提取失败时，不能把该源已有索引判为多余；其它引用指向其无法确认的子目标时，也不能伪造“目标不存在”。可以确定的其它问题继续报告，同时 `complete=false`。审计不更新任何配置或索引，不增加自动修复入口、不获取游戏写锁。真实库验证只运行只读查询与读取接口。

## 5. 管理页加载与错误提示

角色和装备列表的请求进行中，如果游戏或管理令牌变为空，立即清空列表及错误并结束加载。保留请求序号隔离，旧请求晚返回时不得回填列表，也不得影响新请求的加载状态。恢复有效上下文后可重新查询。

浏览器测试使用固定响应与可控延迟复现同一页面实例的上下文变化；正常应用壳层切页另做冒烟，二者证据分别记录，不把页面重建误认为并发隔离已获验证。

前端未知错误、网络失败和后端通用格式错误改为准确中文。保留服务端明确业务信息、状态码、错误码、字段问题和定位信息；没有异常自动重试写请求。后端通用字段校验不再一律称为“属性信息不合法”。

## 6. 图片目录轻量化

当前图片管理页从浏览器本地缓存读取，翻页不调用后台图片列表；公共全量/增量同步负责下载内容。这一现状决定本轮不重做图片页、不增加逐行详情请求。

后台 `GET /api/admin/games/{gameId}/images` 改为独立的目录条目响应，保留 `gameId`、`imageKey`、`name`、`description`、`mimeType`、`byteSize`、`width`、`height`、`enabled`、`createdAt`、`updatedAt`，完全移除 `imageBase64` 字段。SQL 列表查询也不读取该内容列，不能仅在序列化时隐藏。筛选、排序及总数语义不变，不增加新的分页协议。

详情、创建及更新响应继续返回完整图片；公共同步仍按启用状态返回图片内容或停用标记。现有缓存同步、预览、编辑和代表图关系行为继续生效，不保留旧目录兼容响应。接口文档和后端 README 同步更新。

验收分别测目录与同对象详情的真实响应字节，检查目录无内容字段；公共同步和图片详情做读取回归。只报告后台目录的载荷变化，不宣称当前缓存页面获得网络加速。

## 7. 实施责任与顺序

主负责人维护共享方案、任务映射、集成及最终验证。资料工具和管理页小修复可独立实施；后端引用审计与图片响应先经过独立方案核对，再由后端执行者实现。执行者只改各自明确拥有的文件，不覆盖其他执行者修改。

先完成范围及基线核对，再并行实现资料工具与管理页小修复；冻结后端接口并实施；最后集成检查、只读数据库和真实 HTTP 验证、浏览器冒烟及独立最终复核。重要语义变化返回主负责人集中决策，常规实现自主继续。
