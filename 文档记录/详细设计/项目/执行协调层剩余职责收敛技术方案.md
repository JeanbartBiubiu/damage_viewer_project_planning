# 执行协调层剩余职责收敛技术方案

本方案承接“评估 execution 目录的功能拆分”会话对第二轮遗留项的核查。建议继续使用现有包：将残留准入判定交给准入包，将效果变更预演交给生命周期包，将纯报告转换交给报告包，并删除三个无调用函数。根层继续拥有真实帧、读取时点、跨功能顺序、预算汇总及统一提交，不以清空根目录或减少到某个文件数为目标。

本文是**待确认的实施方案**，没有开始修改运行代码。当前已实现的所有权和执行语义仍以[功能执行与组合设计](执行协调层功能执行与组合重构技术方案.md)为准；本文只定义这次剩余工作的范围、交接和验收。任务沿用 `planning-engine-subsystem-refactor`，不因方案成文改变其状态。

## 1. 依据与问题边界

## 2. 准入判定归入现有准入包

### 2.1 监听操作准入

将 `validateEquipmentHitListener` 的操作遍历及允许／拒绝规则整体交给准入包，继续复用已有的头部、回复、动态效果和冷却缩减检查。不能只抽出每个判断函数、仍让根层维护整套允许操作分支。

根层只在原准入位置准备以下有限事实，调用结束后不得保留借用：

| 输入 | 归属及约束 |
| --- | --- |
| 已编译监听、操作、定义和公式表 | 复用现有 `admission.Input`（准入输入）及只读编译类型；原会话、规则和错误身份随输入传递 |
| 实际选中来源的绑定 | 从真实行动对象提取已有 `CompiledSkillActionBinding`（编译后技能行动绑定）；保留当前选择顺序，不以全部编译能力代替实际计划 |
| 真实普攻来源及命中能力 | 在原位置从选中普攻或运行请求取得；未选择与选择了不匹配普攻分别表达 |
| 监听所属挂载对应的状态字段定义 | 根层按原挂载解析字段来源，仅传只读编译字段，不传效果状态写入口 |

目标标记、弹药减时、目标状态续时、普攻冷却缩减、总冷却返还、实例续时、同类连接递归拒绝和动态效果闭包仍按现有分支顺序判断。原静态金额核对不改成运行金额缓存；有效0、缺失字段和未计划来源继续分别处理。

根层的 `isOwnedProviderDurationListener`（所属实例续时监听判断）、`targetMarkListenerOwned`（目标标记监听归属判断）及这条链专用的计划绑定遍历一并下移。`actionflow.OwnedTotalCooldownRefund`（总冷却返还准入）当前只有这一条准入链的生产调用，随其迁入准入包并删除旧能力声明；实际冷却返还执行仍留在行动执行包。确有其他消费者的计划查询保留原所属入口，不为本轮复制一份运行状态。

准入包不得导入行动、效果、监听执行包或调度器。取数适配不传“已允许该操作”一类替代完整规则的布尔清单，也不接收根执行器或任意查询回调；只传上述可核对的事实。现有单实现纯函数不另建服务对象或能力接口。

### 2.2 目标标记初始准入

根层在原 `initTargetMarkSources` 调用点，按编译操作顺序准备本项所需事实：运行开始时刻、实际计划绑定、实际普攻命中绑定、拥有者存在性、指定目标状态的值及期限，以及已有角色资源视图。初始状态袋的“不存在”和“存在且为0”保留，不能通过惰性到期、默认填充或当前目标重映射改变原输入。

准入包负责核对：零时刻新场景、真实计划父来源、实际选中的普攻或首次技能入口、拥有者存在、不能恢复外部活动标记，以及回复资源的当前值和正容量是否合法。根层随后才沿原初始化流程继续，不在准入包安装状态、生成使用身份或排队。

两条准入链都返回现有 `*model.EngineError`（引擎错误）或空错误。错误码、消息、路径、引用、会话身份及首个失败项保持不变。根层提取事实不能提前求值或先检查后续项目而覆盖原首错；无须改变原读取含义的字段直接按值或只读引用交接。

## 3. 生命周期包拥有完整的效果预演

将 `preflightProviderMutation` 的规则，以及同一角色内按序预演多项变更的循环，移入现有生命周期执行对象。根层对每个有变更的角色调用一次预演，只取得新增排程数或原错误，不取得可发布的新状态。

建议的有限交接如下，具体内部命名由实现者决定：

| 交接 | 内容 |
| --- | --- |
| 根层输入 | 该角色原位置选定的基础实例列表、现有 `lifecycle.Mutation`（同帧效果变更）列表、当前绝对时刻、运行终点、是否存在普攻，以及当前暂存双方是否存活 |
| 生命周期包借用 | 既有编译定义、定义查找、周期能力与首拍间隔计算、原错误身份；不新增执行器总入口 |
| 生命周期包内部 | 仅复制有变更角色的实例列表，按原序推进小范围预演；复用、过期、刷新、移除及首拍数量均在这里决定 |
| 返回根层 | 新增事件数量和原引擎错误；预演列表不发布、不保留到下次提交，也不注册实例身份或计时载荷 |
| 根层后续 | 与状态到期、锚定周期、护盾、弹药、行动等待、冷却唤醒和过程计时数量汇总，在原位置检查唯一队列容量，再沿原提交顺序发布 |

预演必须保留以下边界：

- 已有动态投影时仍使用原基础实例列表，不把已经投影的最终列表再次施加一遍。根层保留“不混合不支持的非纯生命周期变更”的全帧检查。
- 同来源及目标复用、移除过期旧实例、永久生命上限实例禁止在战斗中改变、关联盾不能独立刷新，以及严格移除和外来归属错误保持原样。
- 替换、延长、叠层及最低余时的分支顺序、期限是否真正增加、精确到期和额外排程数保持原样。同一帧后续变更读取前一项的预演结果。
- 普通周期、锚定周期、普攻场景的首拍边界和双方存活条件保持原样。预演不重新求作者金额，不推进时钟，不实际入队。
- 队列容量不足仍在本帧发布前失败；此前已提交帧不回滚。后续实际发布或同步尾部失败仍保留原有部分成功事实。

不为预演复制整场快照、事件堆、历史或过程表，也不复用会分配真实身份、安装效果或触发监听的应用入口。它与实际应用共享已有只读查找和周期计算；其余整理以行为等价及正式Wasm成本为依据，不借机统一全部生命周期算法。

## 4. 报告包拥有纯转换，根层保留取事实的时点

| 当前函数或代码段 | 建议落点 | 根层继续负责 |
| --- | --- | --- |
| `genericExecuteEvidenceItem`（斩杀证据转换） | 报告包纯函数，输入现有 `contract.ExecuteFact`（斩杀事实）及明确时刻 | 判断何时暂存或记录证据 |
| `genericDamageEvidenceItem`、`writeCritEvidenceFields`（伤害与暴击证据转换） | 报告包纯函数，复用现有伤害及暴击事实 | 完成伤害事实、身份与数值归属后，在原位置调用 |
| 根层 `attachCastProvenance`（施放来源字段转换） | 报告包的字段转换辅助函数，统一本轮根调用方 | 真实施放编号和来源的分配及传入；数值操作包自己的同名局部实现不扩大迁移 |
| `damageSnapshotEvidenceData`（已冻结伤害快照到报告字段的转换） | 报告包纯函数，只读既有伤害快照 | 事件创建、冻结及派发时点 |
| `recordCommittedDamage` 中的详细记录字段组装 | 报告包接收已提交伤害事实和有限的明细归属值，生成记录 | 行动伤害观察、死亡登记、可靠累计、保留额度判断，以及真实使用、命中、指令和普攻索引的原时点读取 |
| `buildDamageInstanceSnapshot`（供事件公式读取的伤害快照构造） | 本轮保留根层 | 该值在 `events.go` 和 `operations.go` 进入后续公式读取，是执行事实，不按报告开关省略 |

明细归属值用具体小值结构表达已有的使用、命中、指令、普攻索引及存在性，不传完整 `Frame`（真实帧）、`Engine`（单场执行器）、行动对象或活动状态视图。普攻及强化对使用归属的覆盖仍按原位置决定。字段缺失、显式空值、有效0、数值类型、列表顺序和引用优先级均逐项保持；本轮不整理外部报告格式。

`damageSnapshotEvidenceData` 的现有参数类型是 `formula.EventDamageSnapshot`（公式使用的只读伤害快照）。建议明确新增**仅 `report → formula`** 这一条包依赖以复用该类型；报告不调用公式求值或绑定运行上下文。不复制快照字段另造共享协议，不传完整事件快照，也不为隐藏依赖增加类型别名。包边界检查同时维持报告不得导入执行包、行动、效果和调度器的规则，独立评审需核对这一条新增依赖的实际用途。

简要模式继续只记证据种类及计数，不构造证据字段映射。伤害明细仍在 `RecordCommittedDamage`（已提交伤害累计）返回可保留后才生成字段；普通证据则保留现有详细模式的构造、暂存及最终限额记账次序，不能把两条路径改成同一个提前过滤入口。可靠累计不受截断影响；未提交帧不能提前写入报告。嵌套映射和切片沿用既有冻结与输出所有权约定，不因迁移增加逐笔全面深复制，也不能让报告保留之后还会改写的活动引用。

本轮不整体迁移 `buildDoneResult`、`buildFinalSnapshot`、`executionSummary`（最终结果、快照和执行完整性汇集）。它们仍需要跨行动、效果、报告和循环读取事实，部分读取还会结算到期或刷新贡献。只迁移本节已定位的纯转换，避免让报告包取得战斗控制权。

## 6. 允许修改范围与实施顺序

| 写入范围 | 限定用途 |

| `wasm/tinygo_engine_v2/tests/runtime/`、`scripts/check-package-boundaries.mjs` 及其测试 | 公开组合回归、精确依赖边和禁止反向控制的检查 |

实施顺序为：

1. 确认本稿及独立评审结论；记录实际起点、已有脏改、最终基线Wasm及冻结输入。先验证受影响基线，既有失败与本轮失败分开记录。
2. 删除三个无调用函数并完成编译检查，形成容易核对的清理差异。
3. 迁移纯报告转换，锁定字段、简要模式及保留额度边界；再迁移两条准入链，锁定首错、身份和实际选中来源。
4. 最后迁移效果预演，将状态及队列边界与简单代码移动分别审阅；根层只保留跨角色汇总和真实发布。
5. 更新能力目录、依赖检查和阅读入口，完成正式产物及机制回归，由未参与实现的代理独立复核最终关键差异。

第3步的报告转换与准入规则可在边界明确后并行只读调查；并行实现须给每个执行者互不重叠的文件，根层共享文件统一由集成人负责。预演依赖稳定的基线与根提交结构，按上述顺序集成，不要求为了并行另造接口。
