## 1. 目标与成功标准

本设计只交付一条可独立使用的属性作者配置链：

1. 数据库存在唯一、清晰的属性定义表。
2. 后端提供属性列表、详情、新建、修改和停用接口。
3. 前端提供独立属性管理页面，支持手动保存、错误定位和刷新后重新打开。
4. 删除旧战斗资源模型，生命值、法力值、能量只作为普通属性定义。
5. 旧属性/资源通用逐表页面退出作者配置主入口，消除双作者入口。
6. 从空的作者配置属性表开始，维护者可以仅通过网页完成代表性属性录入。

成功只表示属性作者配置能够保存和回读，不表示角色属性值、装备加成、能力参数、发布版本或计算输入已经完成。

## 2. 范围与非目标

### 2.1 本轮交付边界

1. 后端删除旧战斗资源模型（无替代表），并新增作者配置属性存储与管理接口。
2. 前端新增独立属性管理页，主导航使用「属性管理」；旧 `combat-data` 通用工作台与实体成长页退出产品主导航和 App 渲染。
3. 共享契约保持本路径，供既有链接继续有效。

模块文件清单、写入允许范围、DDL/DROP、事务实现与验证命令见对应子文档。

### 2.2 非目标

1. 不设计角色属性值、等级成长值、装备属性加成或能力属性加成。
2. 不设计能力局部参数、能力消耗和当前生命/法力等场景状态。
3. 不设计发布版本、发布快照或计算输入。
4. 不为旧属性/资源接口建设双读、双写、回退或迁移。
5. 不修改现有计算读取、装配和运行代码。
6. 不执行真实数据库 DDL、清库、迁移、seed、发布或 Git 集成。
7. 不删除与旧战斗资源模型无关的战斗数据表、种子和历史测试证据。
8. 不引入 Wasm、计算、发布或 Git 作为本任务工作产物。
9. 契约中不存在 `displayUnit` / `display_unit`：schema、API 与前端类型/表单/表格均不得出现该字段。

## 3. 属性归属规则

只有同时满足以下条件的数据，才能进入属性定义：

1. 是当前游戏中可独立命名和录入的面板量或独立公式量。
2. 可以被多个角色、装备或能力关系引用。
3. 不依赖某个具体来源才能解释含义。
4. 不是战斗中的当前状态、目标上下文或能力局部常量。

归属示例：

| 当前数据 | 新归属 |
| --- | --- |
| `move_speed` 移动速度 | 保留一个属性定义 |
| `ms_f` 固定移动速度 | 不建立属性定义；后续作为来源对移动速度的固定增加 |
| `ms_pct` 百分比移动速度 | 不建立属性定义；后续作为来源对移动速度的百分比增加 |
| 固定护甲穿透、百分比护甲穿透 | 保留两个属性定义；二者是独立业务量 |
| `tick_damage` 玛尔扎哈 E 每跳基础伤害 | 后续归能力局部参数 |
| `hp`、`mana`、`energy` | 保留为属性定义，不建立平行资源定义 |
| `champion_level` | 归成长阶段，不是属性定义 |
| `attack_speed_growth` | 归角色属性成长关系，不是独立属性定义 |
| `bonus_armor`、`target_bonus_health` | 归派生或上下文数据，当前阶段不录入 |

属性管理页面不通过名称关键词猜测归属。上述边界由产品规则、后端请求合同和后续关系表方向共同保证；本阶段不建立能力或装备关系表来提前承接数据。

## 4. 旧战斗资源模型

旧战斗资源模型直接删除、不建立替代表；新接口不得回退读取旧资源表。精确表名与 DROP 顺序只写在后端详细设计中。

与资源无关的旧战斗数据保持不变。不从现有 `public.attribute_definitions` 或旧 seed 自动迁移属性定义，也不建立旧表到新表的同步、回退读取或适配器。

## 5. HTTP 契约

基础路径：

```text
/api/admin/games/{gameId}/attributes
```

| 方法 | 路径 | 用途 | 成功状态 |
| --- | --- | --- | --- |
| GET | `/attributes?keyword=&status=` | 查询全量属性 | 200 |
| GET | `/attributes/{attributeKey}` | 查看单条属性 | 200 |
| POST | `/attributes` | 新建属性 | 201 |
| PUT | `/attributes/{attributeKey}` | 修改属性 | 200 |

本阶段不提供 DELETE。停用通过 PUT 修改 `status` 完成。

### 5.1 查询与列表

1. `keyword` 可选，按 `attribute_key` 和 `name` 不区分大小写包含查询。
2. `status` 可选，只允许 `ENABLED`、`DISABLED`。
3. `?keyword=`、`?status=` 的空串标准化为 null，等同于省略，不报枚举错误。
4. 返回顺序固定为 `sort_order ASC, name ASC, attribute_key ASC`。
5. 当前不分页，返回全部匹配记录。
6. 列表查询的 `status` 先按字符串接收，再由本资源校验器映射，避免非法值落入旧的 `400.INVALID_BODY`。
7. 列表、详情、创建和修改都必须先验证游戏存在；不存在统一返回 `404.GAME_NOT_FOUND`，不得用空列表或属性不存在掩盖非法游戏。

### 5.2 字段语义

响应与写入共用下列字段。schema、API 与前端均不得出现 `displayUnit` / `display_unit`。

| 字段 | 规则 |
| --- | --- |
| `attributeKey` | 游戏内稳定标识；创建后不可修改。创建时必填，长度 1–64，匹配 `^[a-z][a-z0-9_]{0,63}$`。 |
| `name` | 必填；trim 后长度 1–100；同一游戏内忽略大小写和首尾空格后唯一。 |
| `valueType` | 必填；只允许 `DECIMAL`、`INTEGER`。开关、枚举和文本不作为面板属性。 |
| `minValue`、`maxValue` | 可选；后续数值录入使用的合法范围。跨字段 `minValue <= maxValue` 失败时定位到 `maxValue`。 |
| `description` | 可选；trim 后空串转 null；长度不超过 2000。 |
| `status` | 必填；只允许 `ENABLED`、`DISABLED`。只表示可用/停用；当前阶段不提供硬删除。停用记录继续占用稳定标识和规范化名称，不允许复用。 |
| `sortOrder` | 必填；必须大于等于 0。 |
| `keyword`（仅查询） | 可选；trim 后长度不超过 100；超长时定位到 `keyword`。 |
| `createdAt`、`updatedAt` | 仅响应；由存储层维护。 |

明确不进入本契约的旧语义：`default_value`、`value_kind`、`rate_target_attr_key`、图片引用、发布 revision 与 `_log`。

### 5.3 创建

创建请求：

```json
{
  "attributeKey": "move_speed",
  "name": "移动速度",
  "valueType": "DECIMAL",
  "minValue": 0,
  "maxValue": null,
  "description": "角色面板移动速度",
  "status": "ENABLED",
  "sortOrder": 100
}
```

### 5.4 全量 PUT

路径中的 `attributeKey` 是唯一更新目标。请求体若出现非 null `attributeKey`，返回 `400.VALIDATION_FAILED` 并定位到 `attributeKey`，不得静默忽略或覆盖路径值。请求体 `attributeKey` 只允许省略或 JSON null。

`name`、`valueType`、`status`、`sortOrder` 必须出现且非 null。`minValue`、`maxValue`、`description` 省略或传 JSON null 均表示写入数据库 NULL，不表示保留旧值。

更新请求示例：

```json
{
  "name": "移动速度",
  "valueType": "DECIMAL",
  "minValue": 0,
  "maxValue": null,
  "description": "角色面板移动速度",
  "status": "ENABLED",
  "sortOrder": 100
}
```

## 6. 稳定错误

沿用现有统一外壳：

```json
{
  "error": {
    "code": "400.VALIDATION_FAILED",
    "message": "属性信息不合法",
    "details": {
      "fieldIssues": [
        {
          "field": "maxValue",
          "code": "RANGE_INVALID",
          "message": "最大值不能小于最小值"
        }
      ]
    }
  }
}
```

稳定错误：

| HTTP | code | 场景 |
| ---: | --- | --- |
| 400 | `400.VALIDATION_FAILED` | 字段、格式、范围错误 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在 |
| 404 | `404.ATTRIBUTE_NOT_FOUND` | 属性不存在 |
| 409 | `409.ATTRIBUTE_KEY_EXISTS` | 稳定标识重复 |
| 409 | `409.ATTRIBUTE_NAME_EXISTS` | 名称重复 |

非法查询参数也必须返回 `400.VALIDATION_FAILED` 与字段定位，不得落入现有 `400.INVALID_BODY`。

`401.UNAUTHORIZED`、`403.FORBIDDEN` 沿用现有 Admin 过滤器合同，不为本资源重复定义。前端只依赖稳定错误结构，不解析数据库错误文本。

模块测试可以断言上述字段与错误码，但不得另写一套字段或错误含义。

## 7. 实施顺序

三个实施单元按顺序执行，不得并行修改本共享契约。后端响应和错误合同冻结后，前端再接入。

1. 在 `C:\project\damage_backend_dev` 删除旧战斗资源模型及其后端入口（无替换、无双读）。
2. 在同一后端 worktree 交付作者配置属性存储与 `/api/admin/games/{gameId}/attributes`。
3. 在 `C:\project\damage_web_dev` 交付独立属性管理页，并让旧 `combat-data` / 实体成长退出产品入口；旧 registry 与旧客户端保持冻结。

## 8. 跨端验收

服务启动或页面可打开不能替代保存与回读。真实库删除旧表、写入作者配置 DDL 和真实页面验收，必须先由项目负责人单独确认准确的数据库主机、数据库名、待删表数据量和备份方式；细则见后端详细设计。

代表性录入：

1. `move_speed / 移动速度`
2. `armor_pen_flat / 固定护甲穿透`
3. `armor_pen_percent / 百分比护甲穿透`
4. `hp / 生命值`

跨端必须同时成立：

1. 从空属性表打开页面，确认空状态。
2. 旧资源模型已经删除（无替代表、新接口不回读旧表）。
3. 新建上述四条属性并逐条保存；刷新后字段完整回读。
4. 修改名称、范围、状态和排序，保存并再次回读。
5. 重复 key、重复名称、非法范围和非法 key 返回共享稳定错误，前端能按 `fieldIssues` 定位。
6. 主导航没有旧 `combat-data` 分组和实体成长入口；`#/combat-data/**`、`#/admin/**`、`#/entity-growth` 保留原 hash，内容按现有未知路由回到总览；不新增未找到页面，也不重定向到 `#/attributes`。
7. 没有 `ms_f`、`ms_pct` 和 `tick_damage` 预置数据。
8. 请求、响应、表格和表单均不包含 `displayUnit` / `display_unit`。
9. 新属性页面只调用 `/api/admin/games/{gameId}/attributes`，不回退旧属性/资源接口。

## 9. 停止门禁

出现以下任一情况必须停止，不得自行扩大范围：

1. `public.games` 不能作为稳定游戏根，且需要重做游戏管理。
2. 新属性接口必须修改现有计算读取、装配或运行代码才能工作。
3. 必须保留旧属性/资源双读或迁移才能通过当前验收。
4. 清理资源引用必须修改 Wasm、计算代码或非资源业务语义。
5. 已确认目标库的任一待删表存在数据，但尚未明确允许丢弃或完成备份。
6. 实施需要删除未提交工作或与资源无关的历史测试证据。
7. 后端/前端完整验证暴露与本设计无关的既有失败，且无法定点隔离。
8. Cursor 写入审计不可用、越界写入，或方案评审出现任何文件改动。

方案冻结不等于授权执行真实数据库重置或发布。
