## 4. 法术护盾结果

`resultType = SPELL_SHIELD` 的精确形状为：

```json
{
  "resultType": "SPELL_SHIELD",
  "valueRule": null,
  "spellShieldBlockScope": null,
  "detail": {},
  "lifecycleBehavior": {
    "moment": "PERSISTENT",
    "valueReadMode": null,
    "stackValueMode": null,
    "reapplicationValueMode": null
  }
}
```

规则：

1. 所属效果必须有生命周期，结果时点必须为 `PERSISTENT`。
2. 禁止数值规则，detail 固定为空对象。
3. `valueReadMode / stackValueMode / reapplicationValueMode` 必须为 null。
4. 法术护盾结果自身的 `spellShieldBlockScope` 必须为 null。
5. 持续时间、重复施加层数、到期和移除继续由阶段 7.4 生命周期管理；本阶段不增加“可阻挡次数”或“自动消耗”字段。
6. 成功阻挡后的移除必须通过触发规则执行明确生命周期操作，不能隐藏在本结果中。
7. `SPELL_SHIELD` 不引用乘区，detail 仍为空；新增该结果不得改变其他修正结果已经保存的 `modifierZoneKey` 或动态读取方式。

## 5. 结果级阻挡范围

阶段 7.6.3 起，每个结果公共形状显式增加：

```json
{ "spellShieldBlockScope": null }
```

非空只允许：

| 值 | 中文含义 |
| --- | --- |
| `SKILL` | 当前结果成功被阻挡时，以本次技能使用整体作为阻挡单元。 |
| `EFFECT` | 以当前结果所属效果整体作为阻挡单元。 |
| `DAMAGE_INSTANCE` | 只阻挡当前伤害实例。 |
| `RESULT` | 只阻挡当前结果。 |

资格矩阵：

| 结果/组合 | 允许范围 |
| --- | --- |
| `DAMAGE`，且 `target = TARGET`、时点不是 `PERSISTENT` | `SKILL / EFFECT / DAMAGE_INSTANCE / RESULT`。 |
| `ATTRIBUTE_CHANGE / RESOURCE_CHANGE / COOLDOWN_CHANGE / STATUS_OPERATION / LIFECYCLE_OPERATION`，且 `target = TARGET`、时点不是 `PERSISTENT` | `SKILL / EFFECT / RESULT`。 |
| `STATUS_OPERATION + APPLY`，且 `target = TARGET`、时点为 `PERSISTENT` | 只允许 `RESULT` 或 null；状态施加结果参与阻挡，已施加的状态随父生命周期结束。 |
| `DIRECT_HEAL / NORMAL_SHIELD` | 必须为 null；无论 target 和生命周期时点如何都不允许阻挡。 |
| `DAMAGE_MODIFIER / HEALING_MODIFIER / DAMAGE_IMMUNITY / HEALTH_FLOOR / SPELL_SHIELD` | 必须为 null。 |
| 任意 `target = SOURCE`，或上述状态施加以外的 `moment = PERSISTENT` | 必须为 null。 |

一个 `COOLDOWN_CHANGE` 即使关联多个 `affectedSkillKeys`，也只有一个结果级 `spellShieldBlockScope`。该范围对整个结果及全部受影响技能共同生效；需要不同阻挡行为时必须拆成不同结果。

补充规则：

1. `DAMAGE_INSTANCE` 只允许 `DAMAGE`。
2. null 只表示法术护盾不处理该结果，不表示免疫、无敌或运行时一定生效。
3. null 结果不会被同技能或同效果中其他结果的 `SKILL / EFFECT` 范围连带阻挡；这两种阻挡单元只包含相应范围内 `spellShieldBlockScope` 非空且资格合法的离散结果。
4. 创建和更新请求必须显式提交该字段，响应必须始终返回 null 或合法值；前后端不依赖缺失字段补默认。
5. 本阶段的十三种结果之外没有隐藏的可阻挡类型。

持续状态的窄例外用于维迦 E 一类录入：只在一次 `APPLY` 结果产生时判断法术护盾，成功施加后的持续期间不重复判断。该次施加被阻挡时不创建或刷新该次状态实例；重复施加仍使用父生命周期的层数、续期和实例范围，结果自身的 `stackValueMode`、`reapplicationValueMode` 保持 null。这里只定义录入契约，后端保存和回读不证明战斗运行已经执行这些行为。

## 6. 法术护盾成功阻挡事件

事件形状固定为：

```json
{
  "eventType": "SPELL_SHIELD_BLOCKED",
  "detail": {
    "shieldEffectKey": "spell_shield"
  }
}
```

`shieldEffectKey` 必须引用当前技能中同时满足以下条件的效果：

1. 效果存在生命周期。
2. 效果至少包含一个 `SPELL_SHIELD` 结果。
3. 该结果满足本阶段 `PERSISTENT` 完整形状。

事件能力：

1. 当前目标固定为法术护盾承受对象，即来源对象自身。
2. `EVENT_SOURCE` 可用，表示被阻挡结果的来源对象。
3. 事件没有事件值；条件和动态输入不得选择任何 `eventValueKey`。
4. `shieldEffectKey` 只识别护盾能力所属效果，不保存被阻挡结果、攻击者技能、实际范围或运行值。

## 7. 显式后续动作

1. 法术护盾成功阻挡后，需要消耗护盾时，规则动作必须执行一个明确的生命周期操作结果以移除或调整目标护盾效果。
2. 需要治疗、属性增益或状态时，继续按阶段 7.5 有序执行对应效果。
3. 需要延迟 0.25 秒等行为时，启动阶段 7.3 已有延迟过程；不得把延迟毫秒保存到护盾结果或事件明细。
4. 动作顺序由现有 `sortOrder/actionKey` 表达；本阶段不增加“阻挡后自动执行”字段或事件专用动作。
5. `SPELL_SHIELD_BLOCKED` 规则继续参与每目标冷却、单过程限制和候选循环检查。

## 8. 候选规则图

1. 任何允许阻挡且 `spellShieldBlockScope` 非空的离散结果，未来可能产生目标法术护盾技能的 `SPELL_SHIELD_BLOCKED`。
2. 当前技能内存在明确的法术护盾效果和对应规则时建立本地候选边；跨技能挂载或跨对象能力归属未知时不建本地边，也不宣称全局无环。
3. `SPELL_SHIELD_BLOCKED` 的有序动作继续按阶段 7.5 既有生产表产生相应事件；移除保护边后检查残余有向环。
4. 新增或修改阻挡范围、法术护盾结果、事件引用或动作时，都必须使用同一候选快照重新检查当前技能规则图。
5. 本阶段不建立独立“护盾循环检查器”，也不执行真实阻挡来推导边。

## 9. 修改与引用保护

1. 删除整个 `shieldEffectKey` 目标效果继续返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_EFFECT_IN_USE`。
2. 从被引用效果移除最后一个合格法术护盾结果、移除生命周期或把结果改成非法形状，返回 `409.SKILL_EFFECT_IN_USE / TRIGGER_RULE_SHAPE_IN_USE`，定位本次实际变化字段并列出受影响规则。
3. 只要效果仍至少有一个合格法术护盾结果，增删其他不相关结果不应误报该事件引用冲突。
4. 增加或扩大结果阻挡范围形成无保护循环时返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED`，效果事务不落地。
5. 规则创建/更新引用一个当前不合格的效果返回 `400.INVALID_SKILL_TRIGGER_RULE_REFERENCE`，原因 `SHIELD_EFFECT_NOT_ELIGIBLE`。
6. `spellShieldBlockScope` 本阶段尚未被丰富前序结果绑定引用；对应 `BLOCKED` 输出依赖只在阶段 7.6.5 建立。

## 10. HTTP 与聚合边界

1. 效果五个接口把结果联合扩展到十三种，并在每个结果上读写 `spellShieldBlockScope`；一次 POST/PUT 维护完整效果、生命周期、结果、阻挡策略和法术护盾结果。
2. 触发规则五个接口把事件联合扩展到十九种；一次 POST/PUT 维护事件、条件、动作、绑定和保护。
3. 不增加法术护盾、阻挡范围、阻挡事件或消耗子接口。
4. 已有结果类型继续不可原地修改；新建法术护盾使用新结果标识。
5. 效果列表与规则列表响应保持现状，不增加法术护盾标记、阻挡摘要或护盾效果名称；现有效果编辑弹窗的结果表可从完整效果详情显示最小阻挡摘要。

## 11. 稳定错误

| HTTP | `code` | 本阶段场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | 法术护盾结果、阻挡范围或事件联合无法绑定，或携带其他种类字段。 |
| 400 | `400.VALIDATION_FAILED` | 法术护盾生命周期、数值规则或阻挡范围资格组合错误。 |
| 400 | `400.INVALID_SKILL_TRIGGER_RULE_REFERENCE` | `shieldEffectKey` 不存在、跨技能或不满足法术护盾资格。 |
| 400 | `400.TRIGGER_RULE_CYCLE_UNGUARDED` | 新阻挡生产边形成无保护环。 |
| 409 | `409.SKILL_EFFECT_IN_USE` | 删除或修改仍被阻挡事件引用的效果、生命周期或最后一个合格法术护盾结果。 |

字段路径使用实际下标，例如 `results[0].spellShieldBlockScope`、`results[1].lifecycleBehavior.moment` 和 `eventSource.detail.shieldEffectKey`。

无效原因固定复用或增加 `INVALID_SPELL_SHIELD_SCOPE / SPECIAL_RESULT_REQUIRES_PERSISTENT / SHIELD_EFFECT_NOT_ELIGIBLE`。未知数据库约束不得伪装为业务 400。

## 12. 页面外部行为

1. 结果种类增加中文“法术护盾”，只显示生命周期相关字段，不显示固定说明或数值规则。
2. 合格离散目标结果显示“法术护盾阻挡范围”中文下拉；不合格组合直接隐藏该字段并提交 null。
3. 直接治疗和普通护盾不得出现阻挡范围字段或不可阻挡说明。
4. 条件与触发事件增加中文“法术护盾成功阻挡”，护盾效果使用当前技能合格效果目录选择。
5. 该事件不显示事件值；动态输入前序结果也不显示“已阻挡”。
6. 保存失败保留完整草稿并定位字段；资格目录加载失败不得退化为自由填写效果标识。

### 14.2 结果阻挡范围

2. 属性、资源、冷却、状态和生命周期操作结果只允许技能、效果或当前结果。
3. target 改为来源对象时范围必须清空。时点改为持续生效时，只有目标状态 `APPLY` 的 `RESULT` 可以保留；其他范围清空，未清空请求后端拒绝且原聚合不变。
4. 一个同时选择 Q、W、E、R 的冷却变化结果只保存一个阻挡范围；页面、接口和回读都不得按四个目标拆成四条策略或四个结果。
5. 维迦 E 状态施加保存、关闭、重开后仍为 `TARGET + APPLY + PERSISTENT + RESULT`，状态期限由父生命周期管理。改为 `REMOVE` 时提示清除阻挡粒度；不新增状态名删除规则代替来源实例结束。

### 14.3 固定禁止组合

1. 直接治疗和普通护盾无论 target 和时点如何都只能提交 null。
2. 四种阶段 7.6.2 持续结果和法术护盾自身只能提交 null。
3. 非伤害结果提交 `DAMAGE_INSTANCE` 必须失败。
4. 持续状态 `APPLY` 提交 `SKILL / EFFECT / DAMAGE_INSTANCE` 必须失败；持续 `REMOVE`、其他持续结果和来源对象均不因本次窄例外获得非空粒度资格。

### 14.4 引用、迁移与循环

1. 删除或破坏被规则引用的法术护盾效果返回稳定 409；仍有另一合格护盾结果时不误报。
2. 扩大阻挡范围形成无保护环时返回循环错误并回滚。
3. 新库和兼容迁移形成两张本阶段表、十三种结果和十九种事件；重复执行安全，部分结构整体停止。
4. 迁移前后 `modifier_zones`、三类修正结果的乘区引用、结构兼容检查和 `MOMENT_EVALUATION` 矩阵保持不变；父表总数精确为 83。

## 16. 停止条件

出现以下任一情况停止并回到方案确认：

1. 阶段 7.6.2 最终结果、生命周期、事件能力或规则图与本文前提不一致。
2. 法术护盾闭环必须隐藏执行护盾消耗、治疗、增益或延迟才能保存。
3. 需要提前开放斩杀、联动、丰富输出或真实阻挡运行时。
4. 需要自由阻挡类型、JSONB、数组、脚本或通用多态关系。
5. 直接治疗或普通护盾无法在前后端和数据库统一保持不可阻挡。
6. 真实数据库、接口、重启回读或浏览器验收不可用且无法定点确认原因。
