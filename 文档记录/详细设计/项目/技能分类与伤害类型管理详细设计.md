## 1. 本次需要确认的决定

1. 技能分类使用一张扁平表，不建立“技能分类分组”。终极技能、普通技能、被动技能、主动技能、普通攻击、控制技能、单体技能、持续伤害技能和范围技能都可以直接作为技能分类记录。
2. 后续技能管理通过关联表让一个技能多选多个技能分类；本阶段不设置组内互斥、必选、数量限制或其他选择规则。
3. 伤害类型是伤害结算使用的伤害通道，物理伤害、魔法伤害和真实伤害属于伤害类型；持续伤害、暴击伤害、范围和单体不属于伤害类型。
4. 后续由每条具体伤害效果选择伤害类型，而不是在技能上保存一个唯一伤害类型。一个技能可有多条伤害效果，也可因此包含多种伤害类型。
5. 技能分类和伤害类型是两个独立对象，使用两张表、两组接口和两个页面；不建设通用类型表或通用类型页面。
6. 两个页面分别使用“技能分类管理”和“伤害类型管理”，不增加“基础配置”“规则中心”等新的产品名称。
7. 两类数据都支持新建、查询、查看、编辑、启用、停用和删除。已被后续数据引用时禁止删除，返回明确冲突错误。
8. 本阶段不预置任何记录；验收数据只通过页面手工创建，不成为系统固定名单。
9. 伤害类型当前只保存稳定标识、名称、说明、状态和排序，不增加护甲、魔抗、颜色、图标、计算公式或暴击字段。

上述决定是本次开发的冻结输入，实施不得自行增加分类分组或扩大到技能、公式、效果和 Wasm。

## 2. 范围

本阶段交付：

1. 技能分类完整增删改查和状态切换。
2. 伤害类型完整增删改查和状态切换。
3. 前端独立页面、后端独立接口和数据库独立存储。
4. 查询、字段校验、重复校验、引用保护、编辑日志和真实数据库/浏览器验收。

本阶段不包含：

1. 技能基本资料、技能等级、技能参数、消耗或冷却。
2. 技能与技能分类的实际关联、技能页面中的分类多选。
3. 公式、伤害效果、治疗、护盾、状态、触发条件或时间过程。
4. 伤害效果与伤害类型的实际关联，以及伤害类型与抗性属性、减伤公式或最终结算顺序的映射。
5. 暴击率、暴击伤害、是否可暴击或实际暴击判定。
6. 图片、发布版本、计算输入、Wasm、默认种子或旧数据迁移。
7. 旧 `types`、`type_relations`、`reserved_type` 和现有战斗数据接口的改造、删除或兼容读取。

## 3. 共同字段

### 3.1 技能分类

```json
{
  "gameId": "lol",
  "skillCategoryKey": "active",
  "name": "主动技能",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10,
  "createdAt": "2026-08-23T00:00:00Z",
  "updatedAt": "2026-08-23T00:00:00Z"
}
```

### 3.2 伤害类型

```json
{
  "gameId": "lol",
  "damageTypeKey": "physical",
  "name": "物理伤害",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10,
  "createdAt": "2026-08-23T00:00:00Z",
  "updatedAt": "2026-08-23T00:00:00Z"
}
```

### 3.3 对象边界

1. 技能分类没有分组字段，也不承载互斥、必选或计算规则。排序只决定管理页面和后续多选列表的展示顺序。
2. 技能分类可以自由组合。一个技能同时选择“主动技能”“控制技能”和“范围技能”是合法情况。
3. “持续伤害技能”只表达技能内容特征；实际按时间多次结算仍由后续伤害效果和时间过程表达。
4. 伤害类型只回答“一次伤害按哪种伤害通道结算”，不表达触发方式、作用范围、持续方式或是否暴击。

### 3.4 字段规则

| 字段 | 规则 |
| --- | --- |
| `skillCategoryKey` / `damageTypeKey` | 创建时必填并去除首尾空格；小写字母开头，只含小写字母、数字和下划线，最长 64；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100；在各自对象内按同一游戏、忽略大小写和首尾空格唯一。 |
| `description` | 可省略或为 null；空串保存为 null；最长 2000。 |
| `status` | 必填；只允许 `ENABLED`、`DISABLED`。停用记录继续占用稳定标识和名称。 |
| `sortOrder` | 必填；整数且大于等于 0。 |
| `createdAt`、`updatedAt` | 仅响应，由后端维护。 |

技能分类和伤害类型分别校验唯一性；两类对象之间允许出现相同名称或相同稳定标识。

## 4. HTTP 契约

### 4.1 技能分类

```text
GET    /api/admin/games/{gameId}/skill-categories?keyword=&status=
GET    /api/admin/games/{gameId}/skill-categories/{skillCategoryKey}
POST   /api/admin/games/{gameId}/skill-categories
PUT    /api/admin/games/{gameId}/skill-categories/{skillCategoryKey}
DELETE /api/admin/games/{gameId}/skill-categories/{skillCategoryKey}
```

### 4.2 伤害类型

```text
GET    /api/admin/games/{gameId}/damage-types?keyword=&status=
GET    /api/admin/games/{gameId}/damage-types/{damageTypeKey}
POST   /api/admin/games/{gameId}/damage-types
PUT    /api/admin/games/{gameId}/damage-types/{damageTypeKey}
DELETE /api/admin/games/{gameId}/damage-types/{damageTypeKey}
```

### 4.3 查询

1. `keyword` 可选，按稳定标识和名称不区分大小写包含查询；去除首尾空格后空串等同省略，最长 100。
2. `status` 可选，只允许 `ENABLED`、`DISABLED`；空串等同省略。
3. 返回顺序固定为 `sortOrder ASC, name ASC, stableKey ASC`。
4. 当前不分页，统一返回 `{"items":[],"total":0}`。
5. 所有接口先验证游戏存在；不存在统一返回 `404.GAME_NOT_FOUND`，列表不得用空数组掩盖游戏不存在。

### 4.4 创建与更新

技能分类创建请求：

```json
{
  "skillCategoryKey": "active",
  "name": "主动技能",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10
}
```

伤害类型创建请求：

```json
{
  "damageTypeKey": "physical",
  "name": "物理伤害",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 10
}
```

PUT 为全量修改，可编辑字段为 `name`、`description`、`status`、`sortOrder`。稳定标识只来自路径；请求体中的 `skillCategoryKey` / `damageTypeKey` 只允许省略或为 null，非 null 时返回 `400.VALIDATION_FAILED` 并定位到该字段。创建成功返回 201；更新成功返回 200。

### 4.5 启用与停用

启用和停用复用 PUT，由前端携带当前名称、说明、排序及目标状态整条提交。页面不得要求用户进入编辑弹窗才能恢复启用。

### 4.6 删除

1. 删除成功返回 204。
2. 删除不存在记录返回对应 404。
3. 当前未被引用的启用或停用记录均可删除。
4. 后续技能或效果表建立真实外键后，被引用记录删除必须返回对应 `409.*_IN_USE`，不得级联删除引用方。

## 5. 稳定错误

沿用现有统一错误外壳与 `details.fieldIssues`。本阶段新增：

| HTTP | code | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | JSON 语法、字段类型或状态枚举无法绑定 |
| 400 | `400.VALIDATION_FAILED` | 字段、查询参数或格式错误 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在 |
| 404 | `404.SKILL_CATEGORY_NOT_FOUND` | 技能分类不存在 |
| 404 | `404.DAMAGE_TYPE_NOT_FOUND` | 伤害类型不存在 |
| 409 | `409.SKILL_CATEGORY_KEY_EXISTS` | 技能分类稳定标识重复 |
| 409 | `409.SKILL_CATEGORY_NAME_EXISTS` | 技能分类名称重复 |
| 409 | `409.SKILL_CATEGORY_IN_USE` | 技能分类已被引用，不能删除 |
| 409 | `409.DAMAGE_TYPE_KEY_EXISTS` | 伤害类型稳定标识重复 |
| 409 | `409.DAMAGE_TYPE_NAME_EXISTS` | 伤害类型名称重复 |
| 409 | `409.DAMAGE_TYPE_IN_USE` | 伤害类型已被引用，不能删除 |

查询参数中的非法 `status` 返回 `400.VALIDATION_FAILED` 并定位到 `status`；JSON 请求体中的未知状态值按无法绑定处理，返回 `400.INVALID_BODY`。`401.UNAUTHORIZED` 和 `403.FORBIDDEN` 沿用现有全局合同。前端不得解析数据库原文判断错误类型。

## 6. 页面外部行为

1. 主导航新增“技能分类管理”和“伤害类型管理”两个入口，不增加通用分类入口或合并页。
2. 两个页面都提供关键词、状态筛选、查询、重置、刷新、新增、查看、编辑、启用/停用和删除。
3. 状态筛选使用可见的“全部 / 启用 / 停用”单选按钮，查询前后选中值保持稳定。
4. 新建、查看、编辑、状态确认和删除确认均使用组件库默认弹窗，不覆盖弹窗边框、阴影、定位或宽度样式。
5. 点击遮罩或按 Esc 可以关闭资料弹窗；关闭时直接丢弃未保存内容，不再增加弹窗内二次确认。
6. 保存成功自动关闭弹窗并刷新列表；保存失败保留弹窗和输入内容。
7. 启用、停用和删除成功后自动关闭确认弹窗并刷新列表；失败时弹窗保留并显示错误。
8. 页面不展示用途说明、学习提示或引导段落；空列表只显示“暂无技能分类”或“暂无伤害类型”。

## 7. 实施顺序

1. 后端先建立两张独立表、迁移、两组管理接口和测试。
2. 在已确认的开发数据库执行迁移并完成真实接口增删改查验证。
3. 前端再接入两组已冻结接口，完成两个页面及自动检查。
4. 最后启动真实前后端，逐页完成浏览器验收。

任一步都不执行发布或 Wasm 验证。

## 8. 跨端验收

以下记录仅作为手工验收样例，不预置到数据库：

1. 技能分类：`active / 主动技能`、`control / 控制技能`、`area / 范围技能`、`damage_over_time / 持续伤害技能`。
2. 伤害类型：`physical / 物理伤害`、`magic / 魔法伤害`、`true / 真实伤害`。

必须同时满足：

1. 两个页面从空表打开时分别显示正确空状态。
2. 两类记录均可创建、刷新回读、查看、编辑名称/说明/排序、停用、启用和删除。
3. 状态筛选连续切换、查询和重置后，选中状态与实际请求一致。
4. 重复稳定标识、重复名称、非法标识、空名称、负排序和非法状态均返回稳定错误，页面定位或展示清楚。
5. 点击遮罩或按 Esc 可以关闭资料弹窗；保存成功必定自动关闭。
6. 两个页面只调用各自新接口，不调用旧通用类型或战斗数据接口。
7. 数据库中两类数据分别存储；技能分类保持单层结构，不存在分类分组、大 Map、多态关联或两类对象共用一张表。
8. 技能分类验收可录入“持续伤害技能”；方案、页面文案和验收数据不把“持续伤害”“暴击伤害”“范围”或“单体”定义成伤害类型。伤害类型仍是可配置数据，不在前后端硬编码名称白名单。
9. 页面和接口均不出现护甲、魔抗、公式、暴击配置、图片、发布、Provider 或 Wasm 字段。

## 9. 停止门禁

出现以下任一情况必须停止并回到方案确认：

1. 实施必须复用或修改旧 `types`、`type_relations`、`reserved_type` 或现有战斗数据接口。
2. 两类对象无法使用独立表和真实游戏外键表达。
3. 页面必须新增通用类型框架、通用字典页面或自定义弹窗样式才能完成。
4. 实施需要提前创建技能、公式、效果、发布或计算结构。
5. 目标数据库已存在同名但结构不一致的表。
6. 开发阶段的后端完整测试或前端完整验证不可用，且无法定点确认原因。
7. 实施必须增加技能分类分组、组内选择规则或在技能表上保存唯一伤害类型。

实施过程中若触发任一停止门禁，必须暂停开发并重新确认方案。
