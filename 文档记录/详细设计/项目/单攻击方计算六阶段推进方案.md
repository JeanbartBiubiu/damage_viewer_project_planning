# 单攻击方计算六阶段推进方案

方案版本：第一版补充，2026-10-01；两项前置工作已实施验收，六阶段仍按本文后续推进。

本稿承接负责人提出的六阶段顺序及评审，作为现行管理数据接入 Wasm（浏览器内运行的计算引擎）的方案入口。负责人已授权并行实施两项前置工作；当前已完成双模式工作台及首批完整普攻的数据接入、最终浏览器编译与释放。阶段1～6的真实业务运行仍未验收，未写入或迁移业务数据。

前置工作、阶段顺序、跨端责任与运行口径由本文统一定义。管理数据字段继续以对应共享契约为准，已有通用机制继续以源码和已验收契约为准。旧[验证里程碑V2](../../概要设计/验证里程碑V2.md)与[单攻击方DPS旧计划](../最小验证/V2-单攻击方DPS协议与开发计划.md)保留历史依据，其旧发布链、旧单攻入口和批次顺序不作为本轮实施要求。

## 1. 目标与已确认边界

先完成六阶段之外的两项前置工作：工作台提供“数据管理／计算模拟”总切换，现行管理数据完成到Wasm可接受请求的装配与适配。随后让一组真实 A/B 和“普通攻击·共享”完成单次攻击，再由Wasm持续产生普攻，将B攻击到生命值为零。前两阶段通过实际计算结果验收；图表字段与交互从第三阶段展开。

“单攻击方”表示只有 A 拥有自主攻击驱动；第六阶段可再为 A 加入指定施法计划。B 在第四阶段以后可以具有已选定的常驻效果、装备光环及受击反应。B 的反伤可以伤害 A，因此后续运行保留双方死亡和来源死亡的结束原因。

本期继续采用[技能六模块能力组合表](../../概要设计/项目/技能六模块能力组合表.md)已经确认的计算取舍：取消法力、能量、生命等施法费用及费用不足拒绝；保留机制资源的必要消费、技能冷却、正常攻速节拍、弹药恢复、装填、基本到期与刷新；普攻重置暂缓；所选蓄力取核定上限，二次释放按已确认的直接释放口径；位移和弹道直接到达目标，保留必要距离事实。

控制状态的行动限制暂缓。首批场景明确排除会使 A 眩晕、致盲、缴械、停攻或无法合法命中的控制型反应；攻速减益仍属于需要接入的属性变化。符文及其他构筑授予暂不选入这六阶段的代表场景，后续沿通用挂载机制单列接入，不能自动启用角色已有的全部挂载。

完成标准按“本阶段选定机制与代表配置完整通过”判断，不以全英雄、全装备、全技能一次全部支持为目标。

## 3. 前置工作与六阶段总览

两项前置工作独立于六阶段，不增加第7、8阶段，也不再与阶段1重复安排同一份格式适配。双模式壳层可与数据适配并行准备；数据前置验收必须先于阶段1单次计算，之后才进入连续普攻及图表。

### 3.1 前置一：双模式工作台

在现有应用外壳放置始终可见的“数据管理／计算模拟”总切换，共用游戏与连接设置，按当前路由决定模式。数据管理模式只显示现有各类增删改查入口；计算模拟模式隐藏全部管理菜单，只显示已经接入的模拟页面入口。切换改变导航与主内容，不改变API权限，也不要求复制一套应用外壳。

| 项目 | 首版规则 |
| --- | --- |
| 页面与模式 | 由同一导航定义维护完整路径、所属模式及页面。不能沿当前“仅取地址中#后路径的首段”逻辑解析多段模拟路径，也不单独持久化一个可能与地址冲突的模式值。 |
| 默认与直达 | 根地址及未知地址继续进入现有属性管理页；明确的管理地址进入管理模式，明确的模拟地址进入计算模式。首个模拟落点建议为 `#/simulation/basic-attack`（普攻模拟）。刷新、前进后退和复制地址均保持页面、菜单及总切换一致。 |
| 首批模拟页面 | 前置阶段先有有效的普攻模拟页面外壳与“计算尚未接入”说明；阶段1、2逐步接入无图表输入、运行与结果。未来实际交付另一类模拟页面时再增加入口，不为六阶段各建一张空页面。 |
| 未保存草稿 | 切模式和直接改地址都复用现有离开保护；拒绝离开时路由、模式、菜单和草稿均保持，确认放弃后才完成切换。模式切换不自行保存管理数据。 |
| 会话与迟到响应 | 模拟任务持有独占的通用引擎客户端与工作线程，不借默认单例管理任务会话。正常完成或空闲时离开后释放会话；编译或运行请求未完成时离开须确认并终止该任务的工作线程，清除待处理请求、使旧会话失效，丢弃迟到结果，不排队等待同步计算中的释放指令。连接、游戏或令牌改变时同样使旧场景和会话失效。 |
| 加载与权限 | 管理模式不因新增总切换就加载Wasm；沿客户端现有按需建立工作线程的模式。计算模式可以只读当前数据，但不直接新增、修改或删除管理配置；管理接口原有鉴权保持，隐藏菜单不作为权限保护。 |

壳层验收覆盖两模式菜单互斥、直达与默认地址、刷新及历史导航、草稿取消与确认。会话释放、编译或运行中离开和连接变更的真实计算验证随前置数据任务及阶段1、2补齐；前置壳层通过不计为Wasm运行或图表完成。

### 3.2 前置二：现行数据到Wasm请求的接入

先按六阶段会用到的各类数据清点当前字段和语义：角色等级属性、挂载与技能等级、参数公式、效果结果、过程与内部状态、条件触发、分类、乘区、伤害结算与吸血。逐项记录作者字段、目标请求位置、单位、身份、求值时刻、缺失含义，以及“直接可用／适配器转换／需要通用模型或编译增量／本阶段排除”。不能只对字段改名而忽略语义不同。

数据链路固定为：后端所选场景只读快照，经Web场景装配与现有适配器转换，形成Wasm编译请求；编译成功后，再由宿主提供会话标识、初始快照及明确运行条件。Wasm不直接读取管理接口，不要求后端表结构与运行时结构完全相同。

| 数据层 | 内容与边界 |
| --- | --- |
| 后端场景快照 | 保存本次A/B及所选原配置、完整依赖、稳定标识和一致性摘要；读取规则唯一见第4.1节。 |
| `CompileRequest`（编译请求） | 用 `typeCatalog/combatants/sharedProviders/rules/formulas/settings`（分类、角色、共享供值器、规则、公式、设置）表达可执行定义，复用现有通用机制；等级与属性责任唯一见第4.2节。 |
| `RunRequest`（运行请求） | 保存会话及摘要、明确初始快照、驱动、结束策略、采样与预算；前置准备单次请求结构与身份绑定，阶段1才实际执行单次使用事实，阶段2才引入内核连续驱动，不能先在Web排出整场攻击。 |
| `DoneResult`（运行结果） | 沿用现有结果模型；阶段2所需新增事实和完整性语义见第5.3节，展示字段留到阶段3，不在前置工作另造结果协议。 |

本前置任务完成各类数据的结构差异清点，并实际适配首批A/B、共享普攻及必需依赖；完整执行入口、暴击、联动、五阶段公式等声明不得删减。必要通用请求模型和编译层增量也在本任务交付，Web类型、工作线程与最终Wasm同步核对。第4.3节统一列出差异：其中格式表达、绑定与编译属于前置，执行正确性属于阶段1，不再重复开发。

对首批所选入口建立逐引用覆盖清单：作者过程、规则、效果的每个并列结果、暴击字段及五阶段引用分别对应到实际编译节点，保留来源标识与字段路径。当前编译器并不执行原始 `rules.triggerRules`（原始触发规则）字段，必须转换成实际被消费的监听、能力与操作；把原配置塞进未消费字段或仅凭编译元数据数量不能证明接入完整。单次运行请求也需检查快照、挂载、驱动与使用身份的结构及引用关系，不能只调整编译请求而漏掉运行请求；其实际行为仍在阶段1验证。

不要求在前置任务中实现第四至第六阶段的全部行为。后续选入装备或技能时，沿本次确定的数据边界完成其实际转换及必要机制增量；尚未接入的入口明确拒绝并定位，不用“编译可接受”冒充“全部机制可运行”。项目允许破坏式更新，缺口直接修当前契约，不增加旧发布数据、旧字段别名或双格式兼容路线。

当前首批字段对齐与边界如下。数据差异清点覆盖后续类别，但仅实际接入本次完整共享普攻，表中未接入项不能被当作已支持：

| 作者数据 | 当前请求表达与边界 |
| --- | --- |
| 角色等级表及基础属性 | 按明确等级形成双方属性槽；基础值、上限与当前值分开。附加属性仅接受显式场景补充值，初始当前生命通过 `initialHealth`（双方初始生命）明确提供。 |
| 挂载、技能及分类 | A只启用所选普攻，B不启用自主驱动；真实所选技能分类完整进入能力类型，其他挂载只保留来源信息，不自动启用。 |
| 参数、公式及数值规则 | 固定值、明确等级参数、属性和运算转换为通用表达式；来源字段到实际编译节点逐项留档。 |
| 暴击、伤害和联动结果 | 每笔伤害成对声明 `critChance/critMultiplier`（概率／倍率）；使用实际 `critical_strike_chance` 属性及该结果原倍率公式。攻击／命中联动分别编成独立应用操作，次数必须为非负整数，不再次产生原生普攻事件。 |
| 攻击过程与普通冷却 | 原生开始监听调用显式 `useRefFromEvent`（复用原生使用身份）的首次过程控制；即时发起记录不冒充命中。原冷却公式只外包四舍五入和最低1毫秒的单位规则，不改作者表达式。 |
| 条件触发 | 原始开始规则转换为来源拥有者监听，命中规则完整转换为命中候选；其他条件或入口目前明确拒绝，不塞入未消费的原始触发字段。 |
| 伤害类型五阶段及游戏吸血 | `damageTypeFormulas`（伤害结算公式集合）保留实际五阶段，前序读值限定于已完成阶段，替代同类型固定抗性而不是二次结算；吸血规则及分类沿已有通用机制接入。 |
| 装备、构筑、内部状态与复杂过程 | 明确留在后续阶段。首批快照仅返回选定根对象及依赖；首批装配拒绝未支持结果、内部状态及非即时攻击记录过程，不过滤后宣称成功。 |

编译版本沿当前引擎的 `generic-p0`，结构摘要使用本次接入定义，规则摘要包含快照、适配器版本、完整请求与显式初值。单次运行模板同时保留真实挂载和统一使用身份；它仍需在阶段1经过实际运行验证。

### 3.4 六阶段总览

| 阶段 | 交付与子阶段 | 通过门槛 |
| --- | --- | --- |
| 1. 真实配置与单次普攻贯通 | 消费前置任务的场景与编译请求，验收一次攻击开始、命中、全部联动及数值结算。 | 在前置编译验收基础上，真实配置通过最终Wasm与浏览器工作线程完成单次运行及释放；输入、转换和结果可回查。 |

## 4. 数据接入契约与阶段1单次闭环

第4.1、4.2节是前置数据任务的唯一接入定义；第4.3节共用缺口清单，按第3.2节区分前置编译与阶段1执行责任；第4.4节只定义单次运行验收。已在前置任务完成的读取与翻译不在阶段1重新实现。

### 4.1 所选对象的一致性快照

后端新增有界的场景只读聚合入口，沿当前鉴权，在同一可重复读事务内读取本次 A/B、角色等级属性、挂载和所选技能，并按真实引用补齐参数、公式、效果、过程、内部状态、规则、分类、伤害结算公式、乘区和游戏吸血规则。首批只选择实际挂载 `shared_basic_attack` 的普通角色，A/B等级明确，B无攻击计划，装备、英雄被动、主动技能和构筑选择均为空。

请求描述场景选择；响应保留作者原配置、稳定标识与引用关系。只读取所选根对象及所需依赖，不冻结整个游戏，不持久化本次计算。单技能的 `baseDigest`（配置摘要）不能替代整个场景的一致性；快照摘要须由这次事务内返回内容统一生成，读回时间只作追溯。

已选技能原配置完整读取，场景记录启用的执行入口和排除的独立入口。例如第五阶段可以启用Q中的独立被动入口并明确排除其主动施放。沿启用入口补齐完整规则、过程、效果及并列结果；某个必需结果或依赖尚不支持时，报出技能、对象和字段路径，不能过滤该结果后把剩余伤害标为成功。缺依赖、停用引用、缺伤害公式与缺数值分别报告；失败不拼出部分成功快照。

### 4.3 必须补齐的适配与内核缺口

1. 完整读取 `shared_basic_attack`，将攻击力、间隔、暴击倍率及所有引用编译；开始和命中沿实际规则顺序执行。
2. 将原生普攻开始、作者攻击过程开始和实际命中接到同一使用身份。现有过程开始只产生普通技能开始通知，不能据此认定原生普攻已贯通；作者“记录攻击发起”的步骤也不是实际命中。阶段1明确一次开始与命中事实的输入及消费，阶段2再由内核逐刀生成，不能伪造命中或改写作者步骤绕过衔接。
3. `SOURCE_CRIT_CHANCE`（来源暴击率）明确映射为首版确定性的期望伤害；倍率使用原结果的配置公式。现有读取全局暴击倍率的路径不足时，补最小通用倍率声明；不能把某个结果的专用倍率写成全局属性覆盖其他伤害。禁止只因首例暴击率为零，就把作者模式改成禁止暴击。
4. `ATTACK_LINK_APPLICATION/HIT_LINK_APPLICATION`（攻击/命中联动应用）必须有完整次数和身份语义。原生攻击事件与联动应用分别处理，防止联动又重新产生同一原生事件而递归；空监听集合可以没有附伤，但联动本身仍要执行和可核对。
5. 读取本次伤害类型的五阶段公式，将固定值、属性、运算和前序阶段结果编译到既有防御结算位置；五阶段按固定顺序运行，倍率仅应用一次。不能只接受同名类型，或把实际公式与原生固定抗性处理连续执行两次。
6. 依据实际引用映射 `attack_damage`、暴击属性以及 `magic_resistance` 等当前管理标识；不得用旧 `crit_damage/magic_resist` 名称推断作者数据。公式缺值、除零或非有限结果返回具体路径。
7. 攻击过程的冷却公式同时是攻击间隔来源。阶段1核对其公式和起算时刻，阶段2由统一攻击时钟消费其定义，避免普通过程冷却与新增重复调度分别再等待一次；普攻间隔不受技能急速修改。

第5项只开放当前四类公式节点和五阶段结构，并复用通用表达式编译及数值管道。若需要扩张作者语言，回到伤害类型共享契约核定；缺公式不能回退为隐式默认规则。

沿用前置任务交付的场景快照读取契约、所选数据装配器与编译请求，补齐单次运行必要通用增量、模拟壳层内的无图表验证入口及运行档案。验收一组真实接口配置完整走 `engine_compile/engine_run/engine_release_session`（编译/运行/释放）；真实角色属性、共享普攻和结算公式直接进入最终产物。此阶段才以真实结算证明前置声明能够执行。

## 5. 阶段2：无装备连续普攻与可靠结果

### 5.1 连续攻击与攻击时钟

宿主只声明“A持续对B使用已选普攻”，Wasm在执行时逐刀生成独立攻击身份，沿同一身份关联开始、命中、本体伤害和联动。下一刀产生新身份；不让Web按起始攻速预排整场，也不解除单次事实限制后重复使用旧身份。

首版基线在0毫秒发起首刀，命中延迟明确为0；仍区分开始时间、命中时间和下一次开始时间。开始、命中与其合法联动按稳定顺序完成。攻击间隔读取已选过程的公式，以有限正值四舍五入到整数毫秒、最低1毫秒；攻速非正、缺失及非法结果明确失败。

本稿建议：在本刀命中及联动完成后读取最新有效攻速，求下一次间隔；下一次开始时刻取“本刀开始时刻加间隔”与“本刀结算完成时刻”的较大值。超过间隔后才完成命中时不得排到过去，也不再额外等待一轮过程冷却。共享过程的 `PROCESS_START`（过程开始）提供起算基准，间隔和就绪由一个攻击时钟统一管理。阶段2攻速静态；进入第4C动态攻速前，在本文补齐等待期间改速、到期同刻及旧事件失效的规则。普攻重置仍暂缓，不能顺带启用。

攻速上限来源由选定游戏规则或明确场景模型提供，实施任务核定取值和封顶顺序；本稿不继承旧DPS的3.0常量。第2阶段首批样本选择远离上限的普通共享普攻，特殊固定节拍、弹匣和额外攻击在第5阶段按独立机制验收。

### 5.2 运行与结束规则

同时提供固定时长观察和目标死亡停止，两者均有明确最长时长及事件预算。固定时长首版沿当前运行循环计入结束时刻本身的事件；本刻仍合法的效果及派生动作沿稳定调度处理，不启动超过观察上限的事件。死亡、错误和预算限制仍可提前停止，不能承诺预算耗尽后继续执行无界派生链。

死亡时的合法尾处理限定为本刀已进入的伤害管道、生命裁剪、允许的击杀吸血、按机制允许的同步联动及死亡通知；不强行推进未来延时效果，不再启动死亡后的独立普攻或施法。不能在B生命归零的瞬间从伤害函数提前返回；尾处理同样受防循环与事件预算约束，未完成时明确报告。后续有反伤时验收 `source_dead/both_dead`（来源/双方死亡）等既有结束原因。

已发生击杀、调度结束原因和结算是否完整分别记录。预算恰在致死单元完成时耗尽，仍保留已经提交的击杀事实和时刻；预算在致死前耗尽则不得标为击杀。没有事件、预算上限或公式失败不能直接等同于击杀成功，也不能据预算原因抹去实际死亡。重复运行从显式起始快照初始化，前一次使用账本、状态、计时和会话不得串入下一次。

无图表验证提供明确的关闭采样选项，不能把未填或非正采样间隔当作关闭；当前实现会回退到100毫秒采样。采样只观察，不消耗战斗事件预算，输出点另有预算；更改采样频率或关闭采样不改变攻击、伤害、生命与击杀时刻。

### 5.3 增强现有运行结果

沿用 `DoneResult.summary/finalSnapshot/series/warnings/evidence`（汇总/最终快照/时间序列/警告/证据），只补本期必要的稳定事实与完整性说明。以下定义事实语义；具体字段及预算在阶段2A协议评审时落实到当前模型和Web类型，不建立并行结果协议。

| 事实 | 必须表达 |
| --- | --- |
| 攻击事实 | 攻击身份与序号、真实来源和目标、所属普攻、开始/命中时间、有效攻速、下一开始时间或不再安排的原因。 |
| 伤害结算事实 | 伤害身份及所属使用/攻击、拥有者与真实伤害双方、技能/效果/结果标识、修正前后金额、五阶段防御值、护盾吸收、实际扣血、过量伤害及剩余生命。 |
| 分类汇总 | 从完整执行过程独立累计攻击次数、造成伤害与实际生命损失，并按来源及伤害类型拆分；不受明细输出预算影响。 |
| 运行元数据 | 指定观察时长与实际停止时刻、已发生击杀及其时刻、结束原因、结算完整性、模型约定、摘要、警告、事实条数与输出完整性。 |

一刀可以关联多笔伤害，反伤也是独立伤害；伤害条数不能作为攻击次数。阶段2增强现有汇总，独立维护完整来源与类型计数，不能假设当前双方总量和技能汇总已经足够。可靠事实输出有明确预算与截断标记；表格被截断时仍显示完整执行的汇总及“明细不完整”，不得从前1000条调试证据重算整场总量或来源拆分。若执行本身未完成，汇总明确只覆盖已执行部分，不能标为完整场景结果。

现有造成伤害按防御后、护盾前累计，生命裁剪不反向修改它。图表分别展示造成伤害和实际生命损失。固定窗平均伤害率按指定时长计算，击杀时长使用实际死亡时刻；实际停止时长不得冒充用户指定观察时长。零时刻击杀的除时长指标显示无定义，避免除零。

期望暴击逐刀扣血得到的是“期望单击模型下的击杀时刻”，不是随机战斗击杀时间的数学期望。需要真实暴击事件才能触发的被动，在该模型下明确不支持，不能制造一次暴击或小数次触发。

| 6A 指定时刻单次施放 | 指令表示“此时尝试”。冷却、目标或机制条件不符时记录失败/跳过；不自行延期或换技能。继续取消施法费用，不重新以法力/能量不足设门槛。 |
| 6B 指定技能序列 | 操作顺序由场景明确提供，验收与普攻的时间竞争、必要施法延迟、等待和恢复、冷却改变及触发。普攻重置不在本期自然启用。 |
| 6C 选定复杂过程 | 按即时/延时、多段/引导及简化后的蓄力/重施各选代表；保留本期明确中断、死亡终结和基本到期。核定有限段数不意味着把全部伤害挤在同一时刻。 |

需要主动技能才能触发的装备被动，例如依赖实际施放的待击效果，安排到第6阶段组合验收。前置尚未到达的对象记录为待接入，不能假定自然触发。暂缓的控制、复活、完整移动、多对象和自动策略不以加入某件装备或英雄为由扩大本期范围。
