## 1. 前端方案

### 1.1 交付目标与范围

用户从“计算模拟”菜单进入新的“混合战斗分析”页面，完成场景和自动技能配置后，能看到双方生命、累计造成伤害和每秒伤害率，查看技能、普攻、伤害及直接治疗的已返回事实，并从一次真实使用定位对应记录和冻结的作者来源。缩放、选择和筛选只影响展示，不执行战斗公式，不改变调度或重新计算结果。

| 实施前源码事实 | 本轮处理 |
| --- | --- |
| `AutomaticSkillResult.tsx`已有完整累计、逐规则统计、资格账本、自动事实时间轴、明细表和冻结档案下载，尚未展示采样曲线。 | 在新页面复用并扩充该结果区，保留现有核对、等待和清理提示。 |
| `automaticSkillRequest.ts`已经传入采样设置；`automaticSkillResult.ts`已经调用`inspectContinuousAttackSeries`核对采样。 | 直接消费已核对数据，采样参数和数值口径保持。 |
| `ContinuousAttackCharts.tsx`已有生命、累计伤害、累计／窗口伤害率曲线及同步缩放。 | 提取本轮确实共用的采样展示，复用图表初始化、尺寸变化和卸载释放。 |
| `ContinuousAttackResult.tsx`及其评估器依赖普攻汇总，伤害选择也依赖刀号。 | 自动模式保留独立结果核对；共享展示不要求普攻存在，纯主动的普攻记录自然为空。 |
| 当前自动技能浏览器专项主要通过独立构造直接运行真实工作线程。 | 增加实际操作自动配置和结果界面的专项，再补真实服务的代表场景。 |

本轮新增前端页面和路由，后端接口、数据库字段及运行协议保持。自动模式的复杂过程范围保持；最优连招搜索、跨次结果比较、档案导入和实时逐事件播放另行安排。单次1毫秒专项保持暂停，双属性网格另行实施。

### 1.2 独立页面、导航与任务归属

| 页面 | 路由与菜单 | 功能归属 |
| --- | --- | --- |
| 现有普攻模拟 | `#/simulation/basic-attack`，“计算模拟／普攻模拟” | 保留单次／连续普攻、固定时刻技能计划、现有结果与编译诊断。自动循环入口改为前往新页面的导航入口。 |
| 新增混合战斗分析 | `#/simulation/combat-analysis`，“计算模拟／混合战斗分析” | 独立选择双方、等级、装备／构筑、技能来源和初始输入，配置自动技能优先级、关联冷却与一次资格，切换背景普攻，执行及查看本轮完整分析。 |

新页面承担自动循环的唯一配置与分析入口；原页的自动编辑和执行控件迁到新页。保留已有自动调度能力，不同时维护两套自动表单、执行流程或结果面板。新页是可直接打开并独立完成计算的页面，不依赖原页先生成一份结果。分析页支持纯主动，标题不表示强制开启背景普攻。

导航继续由`src/config/navigation.ts`统一声明，在现有计算模拟分组增加第二个条目，`src/App.tsx`接入新页面；管理／计算模式切换仍由路由决定。原默认计算落点保持普攻模拟；新路径直达、刷新、前进后退、侧栏选中和移动端菜单均能正确识别。两个模拟页面复用同一连接与游戏设置。

页面壳为`CombatAnalysisPage.tsx`。首版将原`BasicAttackCompilePanel.tsx`移为`SimulationScenarioPanel.tsx`，集中维护实际共用的场景输入、配置确认和计算任务管理；两个页面分别以固定的普攻／自动模式使用它，复用`AutomaticSkillPlan.tsx`、请求装配、现有引擎客户端与结果核对。页面各自持有草稿、任务及冻结结果；不复制整份大组件，不新增第二套Wasm加载器，也不以把原普攻页整页嵌入新页代替独立交互。新页背景普攻默认开启，用户可明确关闭。

新页按“双方角色与等级、装备及角色技能、准备计算、确认必要输入、开始计算”组织，独立使用`CombatScenarioSetup.tsx`布局。桌面双方并排，窄屏完整分组上下排列。角色确定后按真实绑定直接列出技能，常规操作仅为启用与等级；不提供二次普攻选择或主动技能添加。主动身份由完整作者配置的本技能首次主动使用入口识别，被动保留自然来源，不能把所有非普攻都当作主动。唯一普攻自动带入，缺失或多份绑定时提示修正，并允许关闭普通攻击继续纯主动，不猜选第一份。

角色技能仅在该行设置一次启用和等级；首次使用真实最高等级，0、关闭、清空及较低等级各自保留。关闭主动只从本次执行集合排除，不删除该技能的优先级与连招草稿；仍启用的技能引用关闭项时提示修正，不能静默删除关系。换角色清理原角色连招，连接与角色的迟到读取不覆盖当前列表。结构提示只辅助解释，执行准入仍由真实场景装配及引擎负责。

构筑与装备／构筑技能放在各侧折叠区，角色来源不重复列出。施放优先级、目标、命中方式、关联冷却、前置资格和自动记录选项进入“高级施放设置”，无需展开即可完成普通场景。未启用任何主动但保留普攻时沿现有连续普攻路径执行，并隐藏不适用的自动记录选项。配置版本、场景明细及编译诊断折叠；必要补充值与生命仍需明确提供，不因简化布局隐式补零、夹取生命或放宽未支持机制。

切页时沿用现有计算中离开确认：拒绝离开则路径、菜单、表单与任务保持；确认离开则取消读取、终止当前页计算、释放本页客户端持有的资源，并隔离迟到响应。页面卸载后旧会话和结果不得成为新页结果；新页直达或刷新从自身初态开始。本轮不新增跨页草稿持久化或自动传递运行快照。运行空闲时的离开策略沿用现有模拟页，表单变化仍按第1.5节使当前结果过期。

### 1.3 页面与曲线

自动模式结果区依次展示：冻结场景与状态提示、全场累计、曲线、完整来源／类型拆分、规则与资格账本、事实时间轴、明细及选中项详情、冻结档案下载。全场累计与资格账本始终属于整次运行；记录截断、执行未完成、输入已变化及会话清理状态分别保留。

曲线采用现有三个面板：双方剩余生命、双方累计造成伤害、双方每秒伤害率。伤害率可切换累计平均与既有窗口值，图例可控制显示，三个面板与事实时间轴共用一个毫秒区间。悬停只定位实际返回的采样点，提示真实采样时刻；技能与普攻标记使用原始事实时刻，不吸附到采样网格。

完整来源／类型拆分直接消费`summary.damageBreakdown`，复用既有分类表和贡献展示。实际拥有者、伤害方向、能力及操作身份共同区分来源，名称仅作标签；造成伤害、护盾吸收、实际扣血及过量伤害分别选看，不相加为总额。金额占比沿阶段3的同方向全场分母，零分母显示无贡献比例。

复用现有“记录时间序列”开关及100毫秒、1000毫秒窗口、最多5000点的请求设置，保留引擎返回的有效间隔、降采样及终点说明。关闭采样时显示“未记录时间序列”，明细和完整累计仍按原范围可用。汇总输出与采样是独立选项：汇总模式仍可展示明确请求且核对通过的曲线，事实明细区标记“未请求”，不解释为没有发生战斗。

事实或协议核对失败时沿用现有自动结果的阻断规则，保留诊断和安全下载入口，不为接图而放宽断言。执行预算导致的合法部分结果，明确显示截至实际停止点的已提交累计及曲线。零毫秒结束只展示真实返回的点；起点伤害率显示“不适用”，不制造行动前采样。

### 1.4 时间、选择与来源联动

身份及字段的权威含义见第2.2节。前端仅从冻结请求、输出和作者映射建立只读关联，索引随新档案一次建立，视图变化不复制一套战斗状态。

| 操作 | 展示行为 |
| --- | --- |
| 选择一次自动技能开始／完成事实 | 以非空使用身份定位同次使用上下文中已返回的伤害、直接治疗、过程事实及冻结来源；同一使用的开始和完成定位同一个详情。 |
| 选择一刀背景普攻 | 保留计划标识、刀号和使用身份的组合，定位该次普攻及其已返回结算。 |
| 选择一笔伤害 | 以伤害编号定位原记录，显示其使用身份、命中身份、实际来源、伤害类型、金额分解和作者路径；没有普攻刀号的主动伤害同样可选。 |
| 选择资格授予或消费 | 展示记录明确携带的双方规则及相关使用，保留消费者与授予者的区别，不把两次使用合并成一次。 |
| 选择等待变化、普通拒绝或开始前中止 | 展示原始原因和下一检查说明；没有使用身份时不生成一次施法，也不显示伪造的零伤害详情。 |
| 选择直接治疗 | 展示冻结原记录及其可核对的使用关联。治疗没有独立编号，原数组位置只作本档案内的展示行键。 |

时间轴分别显示技能事实、背景普攻及结算标记。同毫秒事实保留各自类别内的原始顺序；自动记录序号不充当所有事件的全局顺序。图表点击和表格／键盘选择使用同一选择状态，图形交互有可聚焦的表格等价入口。

展示“同次使用上下文的已返回结算”，不把有限记录之和标成该技能的完整伤害。装备、被动及周期效果保留各自真实作者来源；仅凭时间靠近、规则优先级、技能名称或资格关系，不推断额外因果链。没有可证明使用关联的结算继续独立列出。

时间区间筛选作用于各类事实的实际发生时刻，普攻表按开始时刻；来源和伤害类型筛选作用于伤害明细及已有完整分类。全场累计、规则次数、资格和双方总量曲线不随筛选改变。完整分类小计属于整次运行，明细小计明确为“当前已返回记录的小计”。本轮不生成按技能／装备的分项时间曲线，也不计算区间完整伤害。

选中项详情从原始返回数组取数，不受主表筛选删减；被筛掉的相关记录可标示为“主表已隐藏”。某类记录截断或未请求时，提示该类详情不完整；记录缺失不解释为零次、零伤害或没有治疗。作者来源沿本次冻结的`operationOrigins`核对，无法唯一核对时展示问题及原路径，不回读最新管理数据补标签。

### 1.5 视图状态与冻结档案

视图只保存时间区间、伤害率模式、可见曲线、来源／类型和金额展示设置、选中的使用、伤害编号、自动记录序号或治疗原数组位置，以及必要分页。自动技能选择使用真实使用身份，普攻选择继续保留计划／刀号／使用身份组合；治疗行的位置键只在当前冻结数组内有效。

新运行成功完成时原子替换档案并重置视图。失败或取消按现有任务状态处理；仍展示旧结果时保留旧冻结输入及过期提示。规则顺序、关联关系、背景普攻、采样、目标或模式变化继续使结果过期；新视图不增加快照重读或管理请求。连接与游戏变化、离开和取消继续沿用当前隔离规则。

扩充`buildAutomaticSkillArchive`的当前视图白名单，自动档案展示版本升为2；导出完整冻结请求和原结果，不能因筛选只保存可见记录。数据继续经过既有连接及凭据过滤。该版本只描述前端展示，不改变Wasm协议；本轮保留JSON下载，不增加CSV或导入兼容层。

| 档案下载 | 原始输入输出及新的视图一致，连接和凭据不进入档案。 |
| 普攻、固定时刻混合计划回归 | 被共用组件影响的既有图表、选择、导出及清理仍通过。 |

先运行受影响的导航、任务管理、自动结果、采样、展示和档案单测，再按`web/AGENTS.md`完成`npm run lint`、`npm run typecheck`、`npm run test`、`npm run build`及新旧模拟页面的真实浏览器路径。因涉及公共路由，功能收尾还须执行`npm run test:e2e:non-wasm`，覆盖既有管理页离开保护和模式切换。当前自动专项命令为`node node_modules/@playwright/test/cli.js test --config tests/fixtures/simulationAutomaticSkills.config.ts --reporter=line`；新增页面专项须明确纳入该配置，不能只增加一个不会被运行的文件。

独立构造的正式工作线程测试继续保留；新页面专项必须从`#/simulation/combat-analysis`通过实际控件选择双方和技能、调整顺序与关联、执行、选择详情、修改输入及下载，不以页面内直接调用工作线程代替界面验收。另用实际后端只读快照和新页面完成安妮Q/W代表场景，先开启背景普攻，再关闭复验；实际数值、显式补充和禁用来源由当次冻结配置确定，不复制历史28325毫秒等结果当作当前预期。真实服务未运行或用例跳过时，该层验收保持未完成。

本轮只读消费现有业务配置。发现缺数据或未支持的英雄分支时保留具体对象与字段问题，不为了页面通过而删配置、补零或改作者公式。验收记录分别列出静态、单测、独立构造浏览器、真实HTTP／页面、实际Wasm身份和独立评审；阶段3旧范围尚缺的独立评审，按现行组件及其原范围收尾，不仅凭新增自动页面通过就关闭。

## 2. Wasm方案

### 2.1 本轮责任与生产改动

源码核对表明，现有正式输出已经能承载本轮曲线和有限事实联动。默认实施范围为**生产Go代码零改动、公开协议零新增、正式产物继续复用**；本章交付现有输出契约、关联限制及对应验证。必要时只补尚未被覆盖的契约测试，不为展示新增日志、全局序号或因果追踪系统。

Wasm继续负责真实战斗事实、稳定累计、只读采样和已有身份，前端按这些事实展示。本轮不改伤害、治疗、冷却、资格、快照、过期、错误、预算及执行顺序；保留256MiB和出口清理后的GC，不重启性能实验，也不扩展多段、蓄力、重施或引导的自动释放策略。

### 2.2 现有输出与关联契约

以下表格集中定义本轮消费哪些事实，前端不得另造一套对应规则；数值与调度原语义继续以上文链接的既有契约为准。

| 输出 | 现有身份或字段 | 可以证明的关系与限制 |
| --- | --- | --- |
| `summary`与`automaticSkillSummary` | 双方完整累计、停止与完整性；逐规则次数、等待和完整资格账本。 | 对应本次实际提交的全场事实，不由有限记录反算。资格最后使用身份用于最后一份状态，不还原已截断历史。 |
| `series`与`seriesSamplingEvidence` | 真实`timeMs`、双方生命、累计造成伤害、累计／窗口伤害率；请求／有效间隔、点数、降采样及方法。 | 双方总量采样，不是按技能或来源拆分的曲线；`outputMode=summary`不会隐含关闭采样。 |
| `automaticSkillRecords` | 本类`sequence`序号、规则键、`useRef`（实际使用身份）、`relatedRuleKey`与`relatedUseRef`（相关使用身份）。 | 非空使用身份连接真实使用上下文；资格消费中的相关身份指向授予者。序号仅表示自动事实内部顺序，不是全局事件序号；等待和开始前拒绝可无使用身份。历史等待记录只含首个相关规则，完整相关等待集合仅见最终规则等待状态，不能还原每时刻全部关联冷却。 |
| `attackRecords` | `planKey`、`attackIndex`、`useRef`及真实开始／命中／冷却时刻。 | 普攻选择保留三者组合；不以刀号关联没有刀号的主动伤害。 |
| `damageRecords` | `damageId`、可为null的`attackIndex`、字符串`useRef`、按原协议可缺省或为null的`instructionKey`／`hitRef`，以及真实拥有者、伤害双方、能力、操作与编译路径。 | 伤害编号定位本次原记录；已存在的使用与命中身份支持精确关联。`instructionKey`用于核对原生计划归属，不假定其等于自动规则键。`useRef`为空串表示未提供使用关联，仅保留独立结算，不合成身份。 |
| `healingRecords` | `timeMs`、双方、能力／操作及可空的使用和指令身份；没有独立治疗编号。 | 只按现有非空使用身份建立可核对关联；冻结原数组位置只能作展示键，不能作为跨表业务身份。此数组是直接治疗，不代表全部吸血。 |
| `finalSnapshot`中的过程事实 | 实际过程使用身份、提供者及技能归属。 | 核对记录对应的真实过程；原记录未保留时不能据此重建逐笔伤害、历史命中或资格事件。 |

自动模式按当前协议不输出手动固定计划的`skillActionRecords`和`skillUseRecords`。它们缺失不等于自动结果损坏；本轮依赖的是自动记录、通用结算及最终过程事实。

### 2.3 必须保持的语义

**采样。** 开启采样时保留起点及实际停止点，零毫秒结束可只有一个点。零时刻采样可能已经包含同刻提交的伤害，不能等同于行动前生命。造成伤害和伤害率使用既有抗性后、护盾吸收前的口径，包含被盾吸收及过量部分，与实际扣血分别展示。窗口端点、分母及累计值均直接沿现有引擎输出消费，前端不重新推导；自动模式继续按现行准入从0毫秒初态运行，本轮不扩大为非零快照恢复。采样不维持战斗事件、不消耗战斗事件预算，不改变执行与停止事实。

**记录与完整性。** 汇总模式、未请求记录和预算截断各自保持原统计。先按输出模式判断是否请求明细，再按`automaticSkillRecording`与通用`recording`的原字段说明预算保留范围；自动记录有单独的省略计数，不能把它套成通用记录的同形字段。零记录预算不改变调度、全场金额、规则累计或资格。有限记录只证明返回的事实，不能补造缺失记录。执行未完成、目标已经死亡以及输出记录不完整是不同维度。

**使用与来源。** 同一使用上下文中的结算仍保留各自真实拥有者、来源和操作。使用身份不是承诺“这个技能造成了全部后续周期／被动伤害”；没有显式身份的周期或触发结算不按时间、资格链或父子名称强行归属。可空身份继续为空，不为了联动新增伪身份。

**顺序与确定性。** 只保留现有各类记录的顺序与编号，不新增跨类排序事实。前端缩放、筛选和选中项不进入运行请求，不改变公式、事件数量、快照、共同冷却或一次资格。相同冻结编译／运行请求在同一正式产物下，新增展示前后原始输出应逐字节一致。

### 2.4 Wasm验证与采用边界

| 验证组 | 本轮必须覆盖 |

默认不改Go生产代码时，复用当前正式产物，在模块目录运行`node scripts/smoke-node.mjs --wasm dist/tinygo_engine_v2.wasm`与`node scripts/automatic-skills-smoke-node.mjs dist/tinygo_engine_v2.wasm`及受影响的真实浏览器专项，记录实际产物路径、字节数和SHA256。自动技能Node脚本当前默认指向旧专项目录，因此必须显式传入正式dist路径。不为本轮展示重建一套诊断构建，也不重复进行耗时、分配及一万次性能压力专项。

若实现中发现既有输出与本章事实不符，先给出最小可复现请求、原始输出、字段路径及受影响场景，返回主负责人修订方案。涉及新增公开字段、改身份或预算语义时，先独立评审，不作为前端接线的附带修复。确需修改Go逻辑后，按模块规则运行受影响测试、`go test -count=1 ./...`、`go run ./cmd/bench`；影响正式字节时用`build-wasm.ps1`构建，再执行两项Node验证并同步Web、身份文件及生产包，核对实际浏览器字节。新增每事件查找、缓存或分配时才附正式Wasm剖析／分配对照，本轮不预设此类改动。
