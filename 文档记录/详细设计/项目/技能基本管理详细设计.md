## 1. 本次需要确认的决定

1. 技能使用独立的 `skills` 表，不复用旧 `abilities`、Provider、旧技能表或现有战斗数据结构。
2. 技能和技能分类使用专用的 `skill_category_relations` 关联表。数据库不使用整数数组、字符串数组、JSONB 或通用类型关联表保存分类关系。
3. 前后端请求和响应使用 `skillCategoryKeys: string[]`，由后端在事务内转换为关联表记录。
4. 一个技能可以选择零个或多个技能分类。空数组表示暂未分类；不设置分类分组、互斥、必选或数量上限。
5. 技能等级统一从 1 开始，只保存 `maxLevel`。因此技能的等级范围固定为 `1..maxLevel`，不再保存始终为 1 的最小等级。
6. 同一游戏内技能标识唯一；技能名称允许重复，后续角色或装备归属关系不能依赖名称定位技能。
7. 伤害类型不保存在技能上。后续由具体伤害效果选择伤害类型。
8. 技能可以独立保存，不在本阶段建立角色—技能、装备—技能或其他归属关系。
9. 本阶段不预置技能记录，不兼容旧结构，不接入发布和 Wasm。

上述决定已经冻结。编码执行不得自行改成数组字段、通用类型关系或旧能力模型。

## 2. 范围

本阶段交付：

1. 技能基本资料的新建、查询、查看、编辑、启用、停用和删除。
2. 技能与技能分类的多选关系维护。
3. 独立数据库表、独立后端接口和独立“技能管理”页面。
4. 字段校验、分类引用校验、事务写入、编辑日志、自动检查和真实数据库/浏览器验收。

本阶段不包含：

1. 技能参数、各等级数值、消耗、冷却和施法时间。
2. 公式、伤害效果、治疗、护盾、属性修改、状态、触发条件和时间过程。
3. 技能与伤害类型的直接关系。
4. 角色或装备归属、图片、发布、计算输入和 Wasm。
5. 旧 `abilities`、Provider、`types`、`type_relations` 或现有战斗数据接口的改造、迁移、兼容读取和双写。

## 3. 数据与关系

### 3.1 技能

```json
{
  "gameId": "lol",
  "skillKey": "ezreal_q",
  "name": "秘术射击",
  "description": null,
  "maxLevel": 5,
  "status": "ENABLED",
  "sortOrder": 10,
  "skillCategoryKeys": ["active", "single_target"],
  "createdAt": "2026-08-26T00:00:00Z",
  "updatedAt": "2026-08-26T00:00:00Z"
}
```

### 3.2 数据库表

`skills` 保存技能基本资料：

| 列 | 规则 |
| --- | --- |
| `game_id` | 所属游戏，和 `skill_key` 组成主键并外键引用游戏。 |
| `skill_key` | 稳定标识，创建后不可修改。 |
| `name` | 展示名称；同一游戏内允许重复。 |
| `description` | 可空说明。 |
| `max_level` | 正整数，表示可配置等级为 1 到该值。 |
| `status` | `ENABLED` 或 `DISABLED`。 |
| `sort_order` | 非负整数。 |
| `created_at` / `updated_at` | 后端维护。 |

`skill_category_relations` 只保存三个键：

| 列 | 规则 |
| --- | --- |
| `game_id` | 参与两个复合外键，禁止跨游戏关联。 |
| `skill_key` | 外键引用同游戏技能；删除技能时级联删除关系。 |
| `skill_category_key` | 外键引用同游戏技能分类；分类被引用时禁止删除。 |

三列共同组成主键。另建以分类为前导列的索引，供技能分类删除保护和后续反向查询使用。关联表不保存顺序、状态、名称或大 Map；展示顺序始终读取技能分类自身的排序。

### 3.3 为什么不用 PostgreSQL 数组

接口中的数组只是一次提交多个分类键的表达方式，数据库仍按一行一个关系保存。这样可以直接保证同游戏外键、重复关系唯一、分类删除保护和按分类查询；不需要在数组元素上另写无法复用的完整性检查。

## 4. 字段规则

| 字段 | 规则 |
| --- | --- |
| `skillKey` | 创建时必填并去除首尾空格；小写字母开头，只含小写字母、数字和下划线，最长 64；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100；允许与其他技能同名。 |
| `description` | 可省略或为 null；空串保存为 null；最长 2000。 |
| `maxLevel` | 必填；必须是大于等于 1 的整数。 |
| `status` | 必填；只允许 `ENABLED`、`DISABLED`。 |
| `sortOrder` | 必填；必须是大于等于 0 的整数。 |
| `skillCategoryKeys` | 必填数组，可以为空；每项必须符合技能分类标识格式；不允许 null、空串和重复项。 |
| `createdAt` / `updatedAt` | 仅响应，由后端维护。 |

列表顺序固定为 `sortOrder ASC, name ASC, skillKey ASC`。响应中的 `skillCategoryKeys` 按技能分类的 `sortOrder ASC, name ASC, skillCategoryKey ASC` 返回，不保留请求数组顺序。

## 5. 技能分类引用规则

1. 新建技能时，请求中的每个分类都必须存在于同一游戏且处于启用状态。
2. 编辑技能时，已有关系指向的停用分类可以原样保留，也可以移除；不能新增一个已经停用的分类。
3. 技能分类停用不改变技能状态，也不自动删除已有关系。
4. 页面不再把停用分类提供为可新增选项，但必须显示技能已经关联的停用分类，并标记“已停用”。
5. 技能分类被任一技能引用时，删除分类继续返回现有 `409.SKILL_CATEGORY_IN_USE`。
6. 技能删除时只级联删除自身的分类关系，不删除技能分类。
7. 技能启用、停用或只编辑基本资料时，必须完整保留未被用户移除的分类关系。

## 6. HTTP 契约

```text
GET    /api/admin/games/{gameId}/skills?keyword=&status=
GET    /api/admin/games/{gameId}/skills/{skillKey}
POST   /api/admin/games/{gameId}/skills
PUT    /api/admin/games/{gameId}/skills/{skillKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}
```

### 6.1 查询

1. `keyword` 可选，按技能标识和名称不区分大小写包含查询；去除首尾空格后空串等同省略，最长 100。
2. `status` 可选，只允许 `ENABLED`、`DISABLED`；空串等同省略。
3. 当前不分页，统一返回 `{"items":[],"total":0}`。
4. 所有接口先验证游戏存在；不存在返回 `404.GAME_NOT_FOUND`，列表不得用空数组掩盖游戏不存在。

### 6.2 创建

```json
{
  "skillKey": "ezreal_q",
  "name": "秘术射击",
  "description": null,
  "maxLevel": 5,
  "status": "ENABLED",
  "sortOrder": 10,
  "skillCategoryKeys": ["active", "single_target"]
}
```

创建基本资料和全部分类关系必须在同一事务完成；任一字段或分类失败时不得留下技能或部分关系。成功返回 201 和完整技能响应。

### 6.3 更新

```json
{
  "name": "秘术射击",
  "description": null,
  "maxLevel": 5,
  "status": "ENABLED",
  "sortOrder": 10,
  "skillCategoryKeys": ["active", "single_target"]
}
```

PUT 为全量修改，`skillCategoryKeys` 整块替换。稳定标识只来自路径；请求体中的 `skillKey` 只允许省略或为 null，非 null 时返回 `400.VALIDATION_FAILED` 并定位到该字段。基本资料更新和关系替换在同一事务完成，成功返回 200 和完整技能响应。

### 6.4 启用与停用

启用和停用复用 PUT，由前端携带当前基本资料、完整分类键和目标状态提交。列表直接提供“启用”或“停用”操作，不要求进入编辑弹窗修改状态。

### 6.5 删除

删除成功返回 204；记录不存在返回 `404.SKILL_NOT_FOUND`。删除事务同时清除该技能的分类关系。

## 7. 稳定错误

沿用现有统一错误外壳与 `details.fieldIssues`。本阶段新增或复用：

| HTTP | code | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | JSON 语法、字段类型或状态枚举无法绑定。 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、查询参数、分类数组格式或重复分类错误。 |
| 400 | `400.UNKNOWN_SKILL_CATEGORY` | 请求包含同游戏不存在的技能分类。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.SKILL_NOT_FOUND` | 技能不存在。 |
| 409 | `409.SKILL_KEY_EXISTS` | 技能稳定标识重复。 |
| 409 | `409.SKILL_CATEGORY_DISABLED` | 尝试为技能新增停用分类。 |
| 409 | `409.SKILL_CATEGORY_IN_USE` | 删除仍被技能引用的技能分类；沿用阶段 4 错误。 |

分类数组问题定位到 `/skillCategoryKeys/{index}`；无法关联到单一项的重复问题定位到 `skillCategoryKeys`。前端不得解析数据库原文判断错误类型。

## 8. 页面外部行为

1. 主导航新增“技能管理”，路由为 `#/skills`；不恢复旧“能力配置”或旧技能页面。
2. 页面提供关键词、状态筛选、查询、重置、刷新、新增、查看、编辑、启用/停用和删除。
3. 列表显示技能名称、稳定标识、最高等级、分类、状态、排序、更新时间和操作；分类显示名称标签，停用分类使用“已停用”标记。
4. 新建和编辑弹窗提供稳定标识、名称、最高等级、技能分类多选、说明、状态和排序。创建时状态默认启用、最高等级默认 1、排序默认 0。
5. 状态筛选使用可见的“全部 / 启用 / 停用”单选按钮，查询前后选中值保持稳定。
6. 资料、状态和删除确认都使用组件库默认弹窗，不添加自定义弹窗边框、阴影、定位或宽度样式。
7. 点击遮罩或按 Esc 可以关闭资料弹窗；关闭时直接丢弃未保存内容。保存成功自动关闭并刷新，保存失败保留弹窗和输入内容。
8. 页面不展示用途说明、学习提示或引导段落；空列表只显示“暂无技能”。
9. 技能分类列表加载失败时，技能列表仍可查看并用分类键兜底显示，但新增和编辑暂不可用，避免误覆盖分类关系；刷新成功后恢复。

## 10. 跨端验收

以下仅作为手工验收样例，不写入种子：

1. 技能：`ezreal_q / 秘术射击 / maxLevel=5`。
2. 分类：选择已存在的“主动技能”和“单体技能”；若实际库没有这些分类，先通过技能分类页面创建。

必须同时满足：

1. 空表打开显示“暂无技能”，不创建默认记录。
2. 技能可创建、刷新回读、查看、编辑名称/说明/最高等级/分类/排序、停用、启用和删除。
3. 空分类数组可以保存；多个启用分类可以保存且刷新后保持。
4. 重复分类、未知分类和新选停用分类返回稳定错误，且基本资料和关系均不产生部分写入。
5. 已有关联分类停用后，技能仍可读取、切换状态和编辑基本资料；保留或移除该分类均可保存，但不能把其他停用分类新增到技能。
6. 技能分类被技能引用时不能删除；删除技能后分类可以正常删除。
7. 状态筛选连续切换、查询和重置后，页面选中状态与实际请求一致。
8. 点击遮罩或按 Esc 可以关闭资料弹窗；保存成功必定自动关闭。
9. 数据库中基本资料和分类关系分别存储；关联列不是数组、JSONB 或通用类型关系。
10. 页面和接口不出现伤害类型、参数、公式、效果、角色归属、装备归属、图片、发布、Provider 或 Wasm 字段。

## 11. 停止门禁

出现以下任一情况必须停止并回到方案确认：

1. 实施必须复用或修改旧 `abilities`、Provider、`types`、`type_relations` 或现有战斗数据接口。
2. 分类多选无法通过专用关联表和同游戏复合外键表达。
3. 实施需要把分类键改存为数据库数组、JSONB 或技能表单一分类列。
4. 实施需要提前建立技能参数、公式、效果、归属、发布或计算结构。
5. 目标数据库已存在同名但结构不一致的 `skills` 或 `skill_category_relations`。
6. 后端完整测试、前端完整验证或真实数据库迁移不可用，且无法定点确认原因。

触发任一门禁时暂停开发，不自行扩大或改写方案。
