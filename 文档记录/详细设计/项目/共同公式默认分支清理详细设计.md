# 共同公式默认分支清理详细设计

## 2. 准入和错误

需要公式的集合仅为实际编入计划的所有damage（伤害）操作原键，不要求整个目录中未使用类型都配公式。能力、供值器周期、规则、监听、过程及命中候选沿统一操作编译检查，不从类型名称或金额判断是否豁免。未配置类型可以留管理草稿，不能进入本次计划；零金额同样需要明确公式，明确常量0与1均合法。

类型不在damage目录仍返回 `unknown_type_key`（未知类型键）；已知类型缺少成功注册公式返回 `missing_damage_type_formula`（缺少伤害类型作者公式），阶段为compile，路径为原操作的damageType，引用为原键。结构／绑定／预算错误保持共同校验定位，不把损坏定义当成默认倍率。

伤害数值结算入口在零金额、非有限及其它金额短路前先确认该原键对应成功注册计划，并核对绑定存在、程序索引合法及共同程序种类。缺项／不可用计划返回 `runtime_invariant_failed`（运行计划约束失败），带实际操作定位，不索引默认程序0、不补倍率、不提交本帧部分写入。绕过伤害专用结算进入通用命令入口的damage也返回该错误。普通伤害与复制伤害均调用同一共同程序，复制继续使用完整冻结的双方属性视图，不只覆盖armor／magic_resist等固定名字。

## 3. 删除范围

原生删除 `isKnownDamageSettlementType`、`MitigateRawDamage`及带来源版本、原生抗性与穿透／别名数学、仅支持这些行为的damage命令路由及可替换全局伤害解析器。通用命令路由继续支持治疗、护盾与斩杀；`ApplyMitigatedDamage`（按已结算金额扣盾和生命）保持为唯一对应落点。用途包装、属性求值与其它已确认机制继续使用当前内部表达式，不因本批清理删除通用操作语言。

伤害证据保留原金额、共同倍率、普通／暴击防御后两部分、乘区、护盾及生命字段。删除 `resistanceBeforePenetration/penetrationPercent/penetrationFlat/effectiveResistance`（穿透前抗性、百分比穿透、固定穿透、有效抗性）及其计划／事件投影；它们已不代表任意共同定义，不重新解释为作者阶段。Web类型与连续详情同步删除这四项，倍率显示改称防御倍率，作者具名结果仍保留原名。

Web删除只做原键返回的旧 `damageTypeAdapter`（类型适配器）入口，三个调用直接消费真实原键并保留空值检查；连续详情类型名称按原键匹配目录，移除旧damage/前缀拼接。不得在TypeScript、Java或测试加载器重建默认类型翻译。正式快照已经要求完整作者定义，不改变后端读写契约、鉴权或目录权限。

## 4. 基准与测试迁移

原 `internal/testkit/fixtures/generic_p0_basic_damage.json` 字节保持不变，不读取并复制来补新字段，不在Go／Node加载器偷偷注入公式。旧产物保留900证据；第四阶段最终产物对这个原输入应明确拒绝缺公式，作为破坏式准入的专门测试，不删除原测试来冒充回归成功。两工作树已有LF／CRLF检出差异分别保留原字节，同一Git对象和在内存核对的LF摘要证明内容一致，不为了统一摘要改写原文件。

另建从零构造的显式作者基准：一份已声明供值器和单次能力，明确100原金额、常量1防御、目标1000生命，单次结果900；身份可沿稳定测试引用以减少无关变动，但不得复制旧JSON。Go与Node当前冒烟／基准显式选择该新输入，通用加载器保持纯读取。旧协议验证使用原基线档案，当前协议验证使用新明示输入，名称和报告区分。

其他机制的测试源输入显式声明该场景所需的共同类型公式，包括无防御、正负抗性、穿透和复制冻结；公式是该测试的作者数据，不按类型字符串自动选择或扫描补默认值。现有机制断言保留金额、盾、生命、时点、费用、事件、冻结和原范围，除新协议准入／删除的旧证据字段及下述已确认的时序差异外，不通过删测试或改原数值期望消除失败。必要测试构造可复用明确传入原键与完整共同定义的工具，不能提供自动默认类型目录。

苍穹（6699）同帧把来源穿透从10更新为22时，旧默认分支读取本帧暂存值22，得到391.18864577173275；已验收共同公式读取伤害帧入口视图10，得到366.4819944598338。用户于本阶段明确选择保持帧入口视图。该案例按入口10独立计算新期望，同时保留状态变化10→22、事件时点以及旧值22的对照计算；这是已授权的行为差异，不调整共同公式视图或操作顺序来复刻旧默认分支，也不宣称该案例数值完全不变。

Web直接读取旧canonical（原固定样例）的成功案例改为上述独立输入，并单列旧输入拒绝。手工工作线程请求在作者构造处明确提供所有实际伤害的共同公式；初始金额0、额外能力、监听、复制也覆盖。旧第三A／B冒烟内嵌旧基准段改成明确的协议拒绝及新基准900，其余已有共同公式断言保持。

伤害来源结构清单允许既有作者 `damageTypeFormulas`（类型公式目录）字段通过，只遍历真正操作容器，不把公式当成伤害操作、不新增默认定义或第二个求值器。旧手工作者样例按第三B真实技能归属、完整目录和正式工作线程预检补齐；已有过程超时失败与浮点严格门槛由当前原生契约核对，不放宽生产行为。真实作者组成升级后，旧有界入口必须明确拒绝超范围完整配置，并以现行真实入口验证，不能裁掉新组成后宣称原配置成功。
