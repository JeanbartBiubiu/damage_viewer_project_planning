## 1. 本次需要确认的决定

1. 本阶段只管理技能参数和技能公式，两者都从属于一个技能。
2. 技能参数支持固定值、按技能等级、按角色等级和计算时传入四种取值方式。
3. 两种等级参数保存完整等级 Map。前端可以固定填充或等差递增，提交前必须展开为完整 Map。
4. 计算时传入参数只声明稳定标识、名称和整数/小数类型，`fixedValue` 与 `levelValues` 都为空；当前层数、实际蓄力时间和命中次数使用这种方式。
5. 不建立 `calculation_variables` 表、接口、页面或公式节点。不同技能的层数、标记和蓄力状态不能共享同一个游戏级全局定义。
6. 目标已损失生命值等内容不是独立变量。公式直接读取目标生命值属性的“已损失值”；同理可以读取属性的基础值、加成值、最终值、当前值和相应比例。
7. 公式只能引用同一技能的参数和同一游戏的属性；属性引用必须指定施法者/目标以及取值方式。
8. 公式支持加、减、乘、除、取较小值和取较大值。上限用取较小值表达，下限用取较大值表达。
9. 公式不支持条件、分支、幂运算、非线性衰减、公式互相引用或数值字面量。可调整数字必须先建成技能参数。
10. 条件、条件倍率、条件上限和条件下限留给后续技能效果；效果中的固定倍率、固定上限和固定下限可以直接填写。
11. 后续效果中随技能等级或角色等级变化的数值必须引用本阶段的参数或公式，不再保存等级 Map。
12. 计算时传入参数的实际值由阶段 7 的效果或后续计算过程提供，本阶段不设计具体供值绑定，也不保存实际值。
13. 不新增显示单位字段。百分比系数统一以小数保存，例如 `15%` 保存为 `0.15`。
14. 本阶段不预置业务数据，不兼容旧公式结构，不复用旧 `provider_formulas`，不接入发布和 Wasm。

这些决定通过 Review 后冻结。开发执行体不得自行恢复游戏级计算变量、增加公式条件、字面量节点、公式互相引用、通用关系表或效果字段。

## 2. 范围

本阶段交付：

1. 单个技能下参数的新增、查询、查看、编辑和删除。
2. 单个技能下公式的新增、查询、查看、编辑和删除。
3. 四种参数取值方式的录入、校验和完整回读。
4. 属性七种取值方式的公式引用、保存和完整回读。
5. 公式结构编辑、引用校验和参数删除保护。
6. 技能最大等级变更与按技能等级参数的联动调整。
7. 游戏等级范围变更与按角色等级参数的联动调整。
8. 前后端自动检查、真实数据库接口验收和真实浏览器验收。

本阶段不包含：

1. 游戏级计算变量定义和管理页面。
2. 计算时传入参数的实际值、默认值、来源绑定或运行历史。
3. 技能效果、条件、触发、目标选择、时间过程、伤害类型选择和效果执行顺序。
4. 本阶段不要求全量录入冷却、消耗和施法时间，但这些可调数值仍通过通用技能参数表达；消耗对象、扣除时机、冷却开始方式和 `cast time = none` 等非数值语义不在本阶段。
5. 角色—技能、装备—技能、图片、发布和版本管理。
6. 公式求值、计算输入组装、运行时属性值构建和 Wasm。
7. 全量录入 Wiki 中的所有参数；验收只录入代表性案例。
8. 旧能力模型、旧通用类型关系、旧公式表和现有战斗数据接口的迁移、兼容读取或双写。

## 3. 数据关系与责任方向

```text
游戏
├─ 属性定义
└─ 技能
   ├─ 技能参数
   │  ├─ 固定值
   │  ├─ 按技能等级
   │  ├─ 按角色等级
   │  └─ 计算时传入
   └─ 技能公式
      └─ 公式表达式
         ├─ 引用同一技能的参数
         └─ 引用同一游戏的属性 + 施法者/目标 + 属性取值方式

后续技能效果
├─ 引用一个技能公式
└─ 为公式使用的计算时传入参数提供本次实际值
```

技能参数和属性不反向保存公式键。后续效果引用公式，并按需要为计算时传入参数供值；本阶段不建立效果表、效果接口和供值关系。

角色等级和技能等级只用于选择对应等级参数值，不作为普通公式输入再次定义。

## 4. 公共数据契约

### 4.1 技能参数

固定参数：

```json
{
  "gameId": "lol",
  "skillKey": "ezreal_q",
  "parameterKey": "total_ad_ratio",
  "name": "总攻击力系数",
  "valueType": "DECIMAL",
  "valueMode": "FIXED",
  "fixedValue": 1.3,
  "levelValues": null,
  "description": null,
  "sortOrder": 20,
  "createdAt": "2026-08-26T00:00:00Z",
  "updatedAt": "2026-08-26T00:00:00Z"
}
```

按技能等级取值的参数：

```json
{
  "gameId": "lol",
  "skillKey": "ezreal_q",
  "parameterKey": "base_damage",
  "name": "基础伤害",
  "valueType": "DECIMAL",
  "valueMode": "SKILL_LEVEL",
  "fixedValue": null,
  "levelValues": {
    "1": 20,
    "2": 45,
    "3": 70,
    "4": 95,
    "5": 120
  },
  "description": null,
  "sortOrder": 10,
  "createdAt": "2026-08-26T00:00:00Z",
  "updatedAt": "2026-08-26T00:00:00Z"
}
```

计算时传入参数：

```json
{
  "gameId": "lol",
  "skillKey": "twitch_e",
  "parameterKey": "current_stacks",
  "name": "当前层数",
  "valueType": "INTEGER",
  "valueMode": "RUNTIME_INPUT",
  "fixedValue": null,
  "levelValues": null,
  "description": null,
  "sortOrder": 30,
  "createdAt": "2026-08-26T00:00:00Z",
  "updatedAt": "2026-08-26T00:00:00Z"
}
```

按角色等级取值时，`valueMode` 为 `CHARACTER_LEVEL`，`levelValues` 必须完整覆盖游戏等级配置的 `minLevel..maxLevel`。

参数规则：

1. `parameterKey` 在同一技能内唯一，创建后不可修改。
2. `valueType` 只允许 `INTEGER` 或 `DECIMAL`。
3. `valueMode` 只允许 `FIXED`、`SKILL_LEVEL`、`CHARACTER_LEVEL` 或 `RUNTIME_INPUT`。
4. `FIXED` 必须有 `fixedValue`，`levelValues` 必须为 `null`。
5. 两种等级模式必须有 `levelValues`，`fixedValue` 必须为 `null`。
6. `RUNTIME_INPUT` 的 `fixedValue` 和 `levelValues` 都必须为 `null`。
7. 等级 Map 的键必须是十进制等级字符串，不能缺级、越界或包含额外键。
8. 配置值允许为负数、零或小数；`INTEGER` 参数的所有已保存配置值必须是整数。
9. 模式和值类型允许编辑，但更新请求必须同时提交符合新模式、新类型的完整值；后端不猜测转换方式。
10. 删除仍被公式引用的参数必须失败。

### 4.4 公共字段规则

技能参数和技能公式共同遵守：

1. `parameterKey`、`formulaKey` 必须以小写字母开头，只能包含小写字母、数字和下划线，长度为 1～64；创建后不可修改。
2. `name` 去除首尾空白后长度为 1～100。
3. `description` 可为 `null`；纯空白归一化为 `null`；非空时最长 2000 个字符。
4. `sortOrder` 必填，且必须为不小于 0 的整数。
5. 时间字段由后端维护，创建和更新请求都不能提交。
6. 名称允许重复，稳定引用和删除保护只认稳定标识。

## 5. 属性取值方式

### 5.1 对象范围

`attributeOwner` 只允许：

1. `SOURCE`：施法者。
2. `TARGET`：目标。

### 5.2 取值类型

`attributeValueKind` 只允许：

| 值 | 中文含义 | 语义 |
| --- | --- | --- |
| `BASE` | 基础值 | 选定角色等级下，装备和后续效果加成前的属性值。 |
| `BONUS` | 加成值 | 最终值与基础值的差额。 |
| `TOTAL` | 最终值 | 已合并当前配置加成的最终属性；生命值、法力值和能量场景中同时作为最大值。 |
| `CURRENT` | 当前值 | 本次计算中的当前属性值；没有单独提供当前值时等于最终值。 |
| `MISSING` | 已损失值 | `max(TOTAL - CURRENT, 0)`。 |
| `CURRENT_RATIO` | 当前值比例 | `TOTAL = 0` 时为 `0`，否则为 `CURRENT / TOTAL`。 |
| `MISSING_RATIO` | 已损失比例 | `TOTAL = 0` 时为 `0`，否则为 `MISSING / TOTAL`。 |

所有属性都使用同一组取值类型，不在属性定义中新增“是否支持当前值”等字段。阶段 6 只保存取值选择，不构建或执行这些值；后续计算输入必须遵守这里的语义。

比例结果使用 `0..1` 小数语义。后续计算输入若提供小于 0 或大于最终值的当前值，如何拒绝由计算输入阶段确认，不在本阶段静默改写配置。

## 6. 公式表达式规则

### 6.1 节点类型

| `nodeType` | 必填字段 | 含义 |
| --- | --- | --- |
| `OPERATION` | `operation`、`operands` | 对两个子节点执行运算。 |
| `PARAMETER` | `parameterKey` | 读取同一技能的参数，包括计算时传入参数。 |
| `ATTRIBUTE` | `attributeOwner`、`attributeKey`、`attributeValueKind` | 读取施法者或目标属性的指定值。 |

### 6.2 运算

| `operation` | 子节点数 | 含义 |
| --- | ---: | --- |
| `ADD` | 2 | 相加。 |
| `SUBTRACT` | 2 | 左值减右值。 |
| `MULTIPLY` | 2 | 相乘。 |
| `DIVIDE` | 2 | 左值除以右值。 |
| `MIN` | 2 | 取较小值，可表达结果上限。 |
| `MAX` | 2 | 取较大值，可表达结果下限。 |

每个运算节点必须且只能有两个有顺序的子节点。需要三个以上操作数时通过嵌套表达；减法和除法严格按左右顺序执行。

### 6.3 结构限制

1. 表达式必须有且只有一个根节点。
2. 根节点可以是引用节点，也可以是运算节点。
3. 根节点深度记为 1，每个子节点深度等于父节点深度加 1，任意节点深度不得超过 32；节点总数最多为 256，根节点计入总数。
4. 引用节点不能携带 `operation` 或 `operands`；运算节点不能携带任何引用键。
5. 不提供数值字面量节点。公式内出现的可调整数字都先建成技能参数。
6. 不提供公式引用节点，避免公式之间形成隐式依赖或循环。
7. 不提供游戏级变量节点；非属性动态值通过本技能的 `RUNTIME_INPUT` 参数引用。
8. 创建和更新时校验整棵表达式；任一节点无效则整次写入失败。
9. 本阶段只验证和保存公式，不执行公式。运行时除零、数值溢出和计算精度留到计算阶段统一确定。

## 7. 等级范围联动

### 7.1 技能最大等级变化

更新技能 `maxLevel` 时，后端在同一事务中调整该技能所有 `SKILL_LEVEL` 参数：

1. 原范围和新范围重叠的等级保留原值。
2. 新增等级补 `0`。
3. 超出新范围的等级删除。
4. 调整后的每个 Map 必须精确覆盖 `1..maxLevel`。
5. 技能基本资料更新或任一参数调整失败时全部回滚。
6. `FIXED`、`CHARACTER_LEVEL` 和 `RUNTIME_INPUT` 参数不受影响。

降低最大等级会永久删除超出范围的参数值，前端必须在提交技能修改前明确提示影响范围；升高最大等级不额外确认，但成功后提示新增等级已补零。

### 7.2 游戏等级范围变化

更新游戏等级配置时，后端在现有角色属性调整事务中同时调整所有 `CHARACTER_LEVEL` 参数：

1. 重叠等级保留原值。
2. 新增等级补 `0`。
3. 超出新范围的等级删除。
4. 角色属性、角色等级参数和等级配置必须同时成功或同时回滚。
5. `FIXED`、`SKILL_LEVEL` 和 `RUNTIME_INPUT` 参数不受影响。

按角色等级参数的创建和更新要求游戏已经存在等级配置；没有配置时返回现有 `409.LEVEL_CONFIG_REQUIRED`。

## 8. 引用与删除规则

1. 公式只能引用路径中当前技能的参数，不能跨技能引用。
2. 公式只能引用当前游戏的属性，不能跨游戏引用。
3. 创建公式时只能选择启用属性。
4. 更新公式时，已经引用的停用属性可以原样保留；不能新增停用属性引用。是否为新增按 `(attributeOwner, attributeKey, attributeValueKind)` 比较更新前后的引用集合。
5. 参数被公式引用时返回冲突，不删除参数、不改公式。
6. 删除公式时删除其完整表达式。
7. 删除技能时按照“公式表达式 → 公式 → 参数 → 技能”的顺序清理。
8. 更新参数数值、模式或类型不会自动改写引用它的公式；公式只保存参数键。
9. 把普通参数改为 `RUNTIME_INPUT` 或反向修改不会改变公式结构，但更新后必须满足新模式的值形状。

## 9. HTTP 契约

所有接口沿用现有管理接口的 Admin Token、统一成功响应和统一错误外壳。路径中的每个片段都必须编码。

### 9.1 技能参数

| 方法 | 路径 | 成功 |
| --- | --- | --- |
| GET | `/api/admin/games/{gameId}/skills/{skillKey}/parameters` | 200，返回按 `sortOrder/name/parameterKey` 排序的完整列表。 |
| GET | `/api/admin/games/{gameId}/skills/{skillKey}/parameters/{parameterKey}` | 200，返回详情。 |
| POST | `/api/admin/games/{gameId}/skills/{skillKey}/parameters` | 201，返回创建后的详情。 |
| PUT | `/api/admin/games/{gameId}/skills/{skillKey}/parameters/{parameterKey}` | 200，全量修改后返回详情。 |
| DELETE | `/api/admin/games/{gameId}/skills/{skillKey}/parameters/{parameterKey}` | 204。 |

POST 请求包含 `parameterKey/name/valueType/valueMode/fixedValue/levelValues/description/sortOrder`。PUT 不包含 `parameterKey`，其余字段全量提交。

### 9.2 技能公式

| 方法 | 路径 | 成功 |
| --- | --- | --- |
| GET | `/api/admin/games/{gameId}/skills/{skillKey}/formulas` | 200，返回按 `sortOrder/name/formulaKey` 排序的公式摘要列表。 |
| GET | `/api/admin/games/{gameId}/skills/{skillKey}/formulas/{formulaKey}` | 200，返回含表达式的详情。 |
| POST | `/api/admin/games/{gameId}/skills/{skillKey}/formulas` | 201，返回创建后的详情。 |
| PUT | `/api/admin/games/{gameId}/skills/{skillKey}/formulas/{formulaKey}` | 200，全量替换资料和表达式后返回详情。 |
| DELETE | `/api/admin/games/{gameId}/skills/{skillKey}/formulas/{formulaKey}` | 204。 |

POST 请求包含 `formulaKey/name/description/sortOrder/expression`。PUT 不包含 `formulaKey`，其余字段全量提交。公式更新不提供局部节点修改接口。

### 9.3 路径与父级检查

1. 所有接口先验证游戏存在；不存在返回 `404.GAME_NOT_FOUND`，列表不得用空数组掩盖。
2. 再验证技能存在；不存在返回 `404.SKILL_NOT_FOUND`。
3. 详情、更新和删除必须按完整父级路径查找，不能只凭子键跨游戏或跨技能命中。

## 10. 稳定错误

沿用现有 `details.fieldIssues`。本阶段新增或复用：

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | JSON 语法、字段类型或枚举无法绑定。 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、参数值形状、完整等级 Map 或表达式结构错误。 |
| 400 | `400.INVALID_FORMULA_REFERENCE` | 公式包含不存在、跨游戏或跨技能的参数/属性；字段问题给出具体节点路径和原因。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.SKILL_NOT_FOUND` | 技能不存在。 |
| 404 | `404.SKILL_PARAMETER_NOT_FOUND` | 技能参数不存在。 |
| 404 | `404.SKILL_FORMULA_NOT_FOUND` | 技能公式不存在。 |
| 409 | `409.LEVEL_CONFIG_REQUIRED` | 创建或更新按角色等级参数时游戏没有等级配置。 |
| 409 | `409.SKILL_PARAMETER_KEY_EXISTS` | 同一技能参数键重复。 |
| 409 | `409.SKILL_FORMULA_KEY_EXISTS` | 同一技能公式键重复。 |
| 409 | `409.FORMULA_ATTRIBUTE_DISABLED` | 新增了停用属性引用。 |
| 409 | `409.SKILL_PARAMETER_IN_USE` | 删除仍被公式引用的技能参数。 |

`400.VALIDATION_FAILED` 的字段问题至少区分：取值方式和值字段不匹配、缺少等级、额外等级、等级键格式错误、整数参数收到小数、属性取值方式缺失、运算子节点数错误、节点字段互斥错误、深度超限和节点数超限。

`400.INVALID_FORMULA_REFERENCE` 一次返回全部无效引用；字段路径形如 `expression.operands[1].attributeKey`，字段问题原因使用 `UNKNOWN_SKILL_PARAMETER` 或 `UNKNOWN_ATTRIBUTE`。

## 11. 页面外部行为

1. “技能管理”列表增加“参数与公式”操作，打开当前技能的管理弹窗。
2. 弹窗标题为“参数与公式 - {技能名称}”，包含“技能参数”和“技能公式”两个页签。
3. 技能参数按固定值、技能等级、角色等级和计算时传入分组展示。
4. 等级参数保持“行 = 参数，列 = 等级”；新增和编辑可选择固定填充、等差递增或逐级手填。
5. 计算时传入参数不显示数值输入，只维护名称、标识、整数/小数类型、说明和排序。
6. 公式使用结构化编辑器选择运算、技能参数或“施法者/目标 → 属性 → 属性取值方式”，不让用户手写 JSON 或表达式字符串。
7. 公式列表只显示公式名称、稳定标识、排序和更新时间；查看或编辑时再读取完整公式详情并显示结构化中文预览。
8. “游戏配置”页面不增加计算变量区块，只保留角色等级参数随游戏等级范围调整的确认文案。
9. 所有弹窗使用现有组件库默认样式，允许点击遮罩或按 Esc 关闭；保存成功后当前编辑弹窗自动关闭并刷新对应列表。
10. 页面不显示“这里维护什么、不维护什么”等学习说明，不新增全局弹窗样式或页面教学文案。
11. 参数和公式没有启用/停用状态，页面不出现状态筛选或启停操作。

## 12. 实施顺序

1. 项目负责人确认本共享契约和两份模块设计。
2. 后端加入新表、迁移、模型、接口、引用校验和等级联动，并完成自动检查。
3. 在真实 PostgreSQL 执行迁移，重启后端，完成真实接口和重启回读验收。
4. 前端按冻结接口加入客户端、参数/公式弹窗、四种参数录入和属性取值选择，并完成自动检查。
5. 启动前后端，在真实浏览器完成跨端验收。
6. 形成验收记录后才把三个实现任务标为完成。

后端先冻结并验证接口，前端随后对接；开发期间不并行修改未冻结的请求结构。

## 13. 跨端验收案例

### 13.1 技能等级参数和基础公式

为伊泽瑞尔 Q 建立：

1. `base_damage`：按技能等级取值，完整覆盖 Lv1..Lv5。
2. `total_ad_ratio`：固定值 `1.3`。
3. `damage`：`base_damage + 施法者.攻击力.最终值 × total_ad_ratio`。

保存、刷新页面和重启后端后，参数 Map、公式结构和中文预览必须一致。

### 13.2 目标已损失生命值

为测试技能建立固定参数 `missing_health_ratio = 0.15` 和公式：

```text
目标.生命值.已损失值 × missing_health_ratio
```

验收重点：不存在 `target_missing_health` 参数或游戏级变量；公式属性节点完整保存 `TARGET + hp + MISSING`。

### 13.3 当前层数

为图奇 E 建立：

1. `base_damage`：等级参数。
2. `damage_per_stack`：等级参数。
3. `current_stacks`：`INTEGER + RUNTIME_INPUT`，不保存固定值或等级 Map。
4. 公式：`base_damage + current_stacks × damage_per_stack`。

本阶段只验证参数定义和公式引用可以保存、回读；不输入实际层数、不执行公式。

### 13.4 上限

建立固定参数 `damage_cap`，使用 `MIN(原结果, damage_cap)` 保存无条件上限。公式中不能出现条件节点。

### 13.5 等级联动

1. 技能最大等级从 5 改为 6：技能等级参数 Lv1..Lv5 保留，Lv6 自动为 0；计算时传入参数不变化。
2. 再从 6 改为 4：Lv5..Lv6 删除，前端先提示并由用户确认。
3. 游戏等级范围扩大和缩小时，角色属性与全部角色等级参数按同一规则一起调整；计算时传入参数不变化。

### 13.6 删除保护与事务

1. 删除被公式引用的参数返回 `409.SKILL_PARAMETER_IN_USE`，公式不受损。
2. 公式更新包含一个无效参数或属性引用时，公式资料和全部节点保持更新前状态。
3. 删除技能后，该技能的参数、公式和表达式全部清除。

### 13.7 明确拒绝的表达

以下内容在本阶段必须无法配置：

1. 游戏级计算变量或公式变量节点。
2. 把目标已损失生命值复制成技能参数。
3. “目标生命值低于 30% 时乘 2”。
4. 德莱文 R 命中单位后的非线性衰减。
5. 幂运算或一个公式引用另一个公式。
6. 在效果或公式中重新保存一份等级 Map。
7. 为计算时传入参数保存某次实际层数、时间或次数。

## 14. 停止门禁

出现以下任一情况必须停止开发并回到方案 Review：

1. 需要恢复游戏级计算变量表或增加另一套动态输入目录。
2. 属性七种取值方式无法表达已确认的生命值、基础/加成攻击力等代表性公式。
3. 需要新增条件、分支、幂运算、非线性衰减或公式执行语义。
4. 发现后续效果无法为本技能的计算时传入参数供值，必须改变阶段 6 公共字段。
5. 需要让公式跨技能、跨游戏或引用另一个公式。
6. 需要在参数之外新增第二份等级数值来源。
7. 需要接入 Wasm、发布链、旧公式结构或旧能力模型。
8. 真实数据库结构与已确认基线不符，迁移无法安全停止或回滚。

在项目负责人明确确认本方案、Cursor 只读评审返回 READY 且所有评审项关闭之前，不得进入代码、SQL、数据库或页面开发。
