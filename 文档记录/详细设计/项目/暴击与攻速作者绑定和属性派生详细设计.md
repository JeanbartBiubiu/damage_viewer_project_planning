# 暴击与攻速作者绑定和属性派生详细设计

本批承接[剩余固定规则检查](../../测试记录/项目/通用引擎剩余固定规则检查-2026-10-10.md)第2.4—2.6节。负责人已选择“先去除固定属性和派生公式”，保留确定性的普通／自然／强制暴击分支结算，不开放随机暴击或任意战斗流程编排。

开始时四工作树干净：原生a5bd76b56、Web e6275c08d、后端8767d0d6d、规划f36d20bb3。现行共同公式、防御入口视图、复制冻结、事件及动作时钟保持。

## 1. 游戏计算配置

现行属性、等级与技能表没有游戏级用途绑定和派生定义。新增一张按game_id（游戏标识）唯一的game_calculation_rules（游戏计算配置）表，保存完整配置JSONB（数据库结构化值）及更新时间；不借用等级或吸血表，不伪造技能来源。

管理GET／PUT入口为 `/api/admin/games/{gameId}/calculation-rules`。响应为 `{gameId, baseDigest, configuration}`；不存在配置时configuration为null，摘要仍由该空状态计算。PUT请求为 `{baseDigest, configuration}`，只接受非空完整候选，按游戏锁、读取版本比较、候选校验、同事务写入与回读处理。摘要不符返回409及当前摘要，错误保留页面草稿；成功再独立GET核对。未保存配置不补旧键或默认公式。

| 配置字段 | 含义与约束 |
| --- | --- |
| criticalChanceAttributeKey | 可空暴击概率属性标识。SOURCE_CRIT_CHANCE（按来源概率暴击）读取该属性最终值；实际使用时必须配置。FORCED（必定暴击）明确概率1，不依赖此绑定。 |
| criticalMultiplierMin | 可空的暴击倍率下限；非空须为有限非负数，0与null不同。null表示不设下限，倍率仍须有限且非负。原游戏要保持至少1必须显式填1。 |
| attackSpeedAttributeKey | 可空的连续攻击速度属性标识；使用连续普攻时必须配置。读取实际属性最终值，仍按消费者检查正数及本次明确上界。 |
| attributeDerivations | 完整派生规则数组，最多4项；无规则使用空数组，不根据键名补规则。 |

每项派生包含 `ruleKey`（稳定规则标识）、`attributeKey`（输出属性）、`valuePolicy`（明确执行位置）、`activationAttributeKeys`（激活属性集合）和完整共同 `formula`（公式）。标识遵守当前属性／子项格式，不重复规则或输出。输出须为当前游戏启用的非生命属性；激活集合非空、去重，来自当前启用属性。

现行核心生命属性仅hp，其max是生命槽字段，不把其他属性名猜成生命。输出类型由属性目录提供；两种数值类型都可使用，INTEGER（整数）派生最终结果必须为安全整数。目录类型变更重新复核最终配置及实际数值，不一概禁止所有有引用的类型变化。

激活集合也排除hp；本批只开放真实直接属性和已支持属性变化结果的普通属性激活，不增加伤害、治疗或生命成本驱动的生命状态派生。配置阶段明确拒绝这种激活声明，不能接受后在运行场景中默默不激活。

激活集合按本场真实开启来源是否可能改变其中任一属性决定。装备直接属性、可达自身／对手属性结果按实际投送方向收集；不按加成攻速键判断，不把普通读取误当属性变化。关闭或不可达来源不激活。规则一旦编入计划，在后续真实属性变化时按现有派生和等待机制重求，不在宿主另建时钟。

来源明确声明同一输出的永久派生时，该拥有方的来源规则替代游戏规则；两个来源竞争同一输出仍拒绝。这是现行专属固定输出覆盖游戏派生的通用化，依据真实输出身份，不识别英雄或属性名称。游戏规则只补没有来源输出的槽。

来源派生沿角色／构筑已验收的完整永久形状开放；装备仍沿本来支持的永久修正，未支持的装备SET（属性覆盖）或动态转换整体拒绝，不因去固定键额外开放新结果形状。只有实际编出的来源输出才能覆盖游戏规则。

共同公式只授权该派生拥有者的本帧普通属性BASE／BONUS／TOTAL（基础／加成／最终值），不允许技能参数、事件、成本或充能输入。共同内部引用及环由原规范检查。同批派生输出只能读冻结BASE；不开放派生之间的总值链，保存与实际编译均拒绝自身／其他输出的BONUS／TOTAL读取。普通修正与派生的完整全图排序不纳入本批。

用途绑定、输出、激活集合和所有声明输入必须属于当前游戏且启用。未知字段、重复、非法策略或共同公式问题返回400.VALIDATION_FAILED（配置校验失败），保留准确字段路径与共同错误码。属性停用、删除或类型变更通过既有游戏写入守卫复核最终配置；采用独立游戏配置复核，不扩大技能引用索引的来源归属。

## 2. 一致快照与宿主装配

快照catalogs.calculationRules（计算配置目录）运输完整上述响应，进入snapshotDigest（快照摘要）。目录收集用途绑定、输出、激活集合及所有共同声明输入，再核对真实属性目录。缺失、停用、损坏配置按现行场景错误定位，不补旧概率键、攻速键、收益系数或公式。

源数值缺失仍要求明确输入。属性合法0按作者数学参与计算，不再因名字为收益系数被宿主或原生提前拒绝；实际除0、非有限值或指定攻速非正仍失败。关闭场景规则不删除配置或伪造固有值。

Web依据配置生成显式概率读取、倍率下限和连续攻击速度绑定。装备只贡献真实直接属性；通用来源报告实际可能改变的属性，不保留derivationSides／fixedAttackSpeedSides（原攻速专用侧标记）。激活游戏派生采用完整共同公式，不在TypeScript（前端实现语言）复制计算式或解释共同算术。覆盖清单定位实际游戏配置、来源输出与编译节点。

现有SOURCE_CRIT_CHANCE和FORCED的倍率必须在实际装配时明确声明；管理未完成草稿仍可为空，但运行不得使用默认倍率。纯主动当前暴击准入不扩大。

## 3. 通用具名公式的归属

NamedFormula（具名公式）新增必填scope（归属）：skill（技能）或game（游戏）。技能归属保留必填真实skillKey和私有参数目录；游戏归属不允许skillKey，parameters明确为空数组，只授权普通属性输入。旧缺scope输入明确拒绝，全部正式作者构造和调用者同步更新，不在加载器注入字段。

游戏程序的完整作者定义由原生同一纯公式编译器和预算管理消费。公式引用身份包含游戏规则、拥有方与使用位置；技能级身份不改写。预检及最终编译均核对原生核定值。游戏派生的source对象指该派生拥有者，目标方挂载时不会误读攻击方；技能派生保持原真实技能归属，内部既有source／target读取保持战斗双方语义。

## 4. 原生派生与连续时钟

沿既有combatantKey／attributeKey／value／skillKey结构，valuePolicy必填set或multiply（修正前替换或修正后乘算），新增必填valueType（输出目录数值类型）为DECIMAL（小数）或INTEGER；移除空值策略与两属性白名单。最多4份实际编入计划的派生、每拥有方输出唯一、真实槽和完整依赖检查保持。生命槽继续由生命管道处理。

| 策略 | 执行语义 |
| --- | --- |
| set | 公式结果作为该输出的修正前基准，再运行原属性修正管道一次；不重复装备修正。 |
| multiply | 在普通属性修正完成的总值上乘有限非负因子；不再次运行同一修正。 |

普通派生结果要求有限并满足明确输出类型，允许目录语义中的0或负值；乘算因子非负，乘后结果有限。INTEGER最终结果还检查无小数且在安全整数范围，不静默取整。删除按attack_speed_ratio（原收益系数键）扫描全部依赖并检查正数的分支，求值仍严格读取实际惰性分支。未执行分支不因该特定键预先失败。

连续入口接受任何已声明非生命输出，不再限计划攻速和攻击力。提交预检对实际AttackSpeedAttributeKey（本计划消费的速度属性）执行正数／上界检查，首次等待尚未建立时也必须检查。非法初始化、求值溢出和队列预算失败不提交本帧属性、过程或时钟。

计划主动技能沿既有单过程、控制和命中绑定准入过程时点或即时ATTRIBUTE_CHANGE（属性变化）结果：只接受明确加算、已声明非hp槽和source／self／target（本次来源／自身／实际目标）选择。目标按真实行动指令解析，不能固定解释为对手；不扩大监听器或普攻直接修改集合。新基础值在裁剪及赋值前要求有限，保留已有已提交过程与费用，只回滚当前失败帧。动态结果核对沿本次实际驱动、命中预设、可达操作及拥有方查找速度依赖，不因未安排或未命中的能力放宽静态核对。

周期属性修正沿当前完整来源／持续周期、拥有方和加算形状，只将固定加成攻速目标解除为实际已声明非生命自身属性。依赖、改期、保持进度和唯一下一刀仍由原生现有逻辑处理。前端可靠结果判断使用真实绑定及依赖，不按属性名正则判断动态攻速。

## 5. 暴击输入与下限

所有critEligible（允许暴击）的伤害必须显式成对声明critChance／critMultiplier（概率／倍率表达式）。删除缺声明时读取crit_chance／crit_damage（旧属性别名）的路径；非暴击伤害不要求它们。缺声明在编译期报missing_required_field（缺少必要字段）；损坏运行计划返回runtime_invariant_failed（运行约束失败），不消费默认程序。

操作可显式声明critMultiplierMin（倍率下限）；只允许在可暴击伤害上使用，有限且非负，缺声明表示无下限。来源配置的criticalMultiplierMin映射到该字段。保留原先下限应用位置：倍率输入及自然／强制分支修正后各按明确下限处理，再检查有限非负。没有字段时不偷偷补1。

概率夹取0至1、普通权重1−q、自然权重min(p,q)、强制权重max(0,q−p)及三分支结算继续作为现行确定性模式。修正顺序、防御一次、受到暴击过滤、吸血及复制冻结保持，不把此次移除绑定写成所有暴击数学都可任意编排。

倍率有限不意味着合成金额有限。普通部分、暴击部分及合计金额在冻结、复制、证据及帧提交前要求有限非负；组合溢出返回明确运行约束错误，不让非有限值进入输出序列化。同一会话后续合法请求必须可以恢复。

## 6. 实施责任与验收

主负责人拥有本共享设计、原生协议／编译／运行／作者构造及最终产物集成。后端执行代理仅写后端工作树的模型、校验、事务、快照、SQL和对应测试／说明；Web执行代理仅写前端类型、客户端、游戏配置面板、装配与相关测试／说明。并行文件不重叠，保护其他人的改动。实库与正式浏览器作者操作由主负责人统一处理。

先独立复核本方案，再分端实施。新增表迁移只创建所需表，不删真实数据；执行前核对实际目标库、表与约束。现行lol（当前游戏）配置明确录入已有概率／攻速身份、倍率下限1与原攻速派生数学及激活属性，作为实际作者配置保存，不成为程序默认或业务种子。先冻结现状和候选，沿正式管理页保护保存，独立读回，再验证实际快照、最终Wasm及工作线程。

验收至少包含：

1. 暴击概率、攻击速度和加成／系数全部重命名仍得相同结果；删除旧别名，显式0概率、数据下限0／1／其他值均按声明运行。
2. 改变完整游戏派生公式无需改源码；游戏作用目标隔离、来源覆盖、关闭来源、缺配置、停用依赖和摘要变化有证据。
3. 任意非生命输出、0与负属性、惰性未执行分支；实际缺值／除0／溢出、同批输出回读、输出重复及容量失败均明确拒绝。
4. 重命名速度下的动态等待保持进度和唯一节点；首次初始化非法速度及预算失败的属性／时钟不提交。
5. 原暴击分支、修正、防御、幻影复制、烬／艾希及装备动态攻速数学保留独立原断言；不降低重复次数或裁剪作者组成放行。
6. 分端必要全量检查、最终Wasm构建／摘要／标准往返／基准／会话重复、真实服务与实际页面保存及运行分层留证。
