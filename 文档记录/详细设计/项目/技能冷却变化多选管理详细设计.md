# 技能冷却变化多选管理共享契约

方案版本：阶段 7.5 验收补项第 1 版。

方案状态：已完成开发、迁移和验收。

关联文档：

1. [后端详细设计](../server/game_manage/技能冷却变化多选管理后端详细设计.md)
2. [前端详细设计](../web/技能冷却变化多选管理前端详细设计.md)
3. [技能效果结构与基础结果管理共享契约](./技能效果结构与基础结果管理详细设计.md)
4. [条件事件与动态输入供值管理共享契约](./条件事件与动态输入供值管理详细设计.md)

## 1. 目标场景

本补项解决以下配置：

1. 伊泽瑞尔 Q 命中后执行一个冷却变化效果。
2. 同一个效果结果同时减少伊泽瑞尔 Q、W、E、R 的剩余冷却 1500 毫秒。
3. 装备主动技能和装备被动技能不在选择列表结果中，因此不受影响。
4. 效果仍是一个结果，不为四个技能复制四个结果标识、名称、公式、操作和排序。

本补项来源于阶段 7.5 真实页面验收，但修改对象是阶段 7.2 已落地的冷却变化结果契约。实施顺序固定在阶段 7.6.1 之前。

## 2. 已确认决定

1. “受影响技能”从单选改为显式多选。
2. 一个 `COOLDOWN_CHANGE` 结果拥有一个稳定结果标识、一个作用对象、一个操作和一套数值规则，同时关联一个或多个明确技能。
3. 多个受影响技能属于同一个结果的目标集合，不增加效果摘要中的结果数量。
4. 前端不得把一次多选静默拆成多个结果；后端和数据库必须直接保存一个结果到多项技能的关系。
5. 接口可以使用技能标识列表，数据库必须使用真实关系表和外键，不使用 PostgreSQL 数组、JSONB 或逗号拼接文本。
6. `REDUCE`、`INCREASE`、`RESET` 及数值规则语义保持不变：减少和增加按毫秒解释，重置不得携带数值规则。
7. `target` 仍只表示对施法者或当前目标执行冷却变化；受影响技能列表只表示需要修改哪些技能的冷却。
8. 本补项不推断角色或装备归属，也不自动展开“角色全部技能”。录入者通过显式勾选 Q、W、E、R 排除装备技能。
9. 角色和装备技能挂载完成后，可以另行增加自动按归属选择的能力；不得为该未来能力预留空字段。
10. 阶段 7.5 的事件、条件、动作和结果引用不变。执行效果动作仍引用一个效果，前序结果仍引用一个结果稳定标识。
11. 同一结果的所有受影响技能共享作用对象、操作、数值规则、生命周期行为和后续结果级属性。若不同技能需要不同数值、操作、时点或阻挡行为，必须建立不同结果。

## 3. 契约替换范围

本文件只替换[技能效果结构与基础结果管理共享契约](./技能效果结构与基础结果管理详细设计.md)中与单个受影响技能有关的约束：

1. 详情示例中的 `affectedSkillKey`。
2. 第 6.6 节“冷却变化”的明细结构和“多技能保存多个结果”决定。
3. 第 7 节受影响技能的停用引用、更新比较和删除保护。
4. 第 9 节与受影响技能字段路径有关的错误。
5. 第 10、12 节冷却结果的页面和验收行为。

原契约的效果聚合、结果稳定标识、结果种类不可修改、作用对象、数值规则、生命周期、接口路径和其他七类结果规则继续有效。

## 4. 数据关系与责任方向

```text
技能效果
└─ 冷却变化结果
   ├─ 冷却变化明细：操作
   ├─ 数值规则：减少或增加时必填
   └─ 受影响技能关系
      ├─ 技能 Q
      ├─ 技能 W
      ├─ 技能 E
      └─ 技能 R
```

责任方向固定为：

1. 冷却变化结果拥有操作和受影响技能集合。
2. 受影响技能记录不反向保存效果或结果标识。
3. 每个受影响技能都必须是同一游戏中真实存在的技能。
4. 受影响技能之间没有执行顺序；接口回读按技能目录的 `sortOrder`、`skillKey` 稳定排序。
5. 将来计算输入如何展开多个技能不属于本阶段；配置层只保证集合可保存、可校验、可回读和可保护引用。

## 5. HTTP 契约

接口路径、方法、成功状态码和效果聚合写入方式保持不变：

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects
GET    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/effects
PUT    /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/effects/{effectKey}
```

冷却变化结果的 `detail` 改为：

```json
{
  "affectedSkillKeys": [
    "ezreal_q",
    "ezreal_w",
    "ezreal_e",
    "ezreal_r"
  ],
  "operation": "REDUCE"
}
```

字段规则：

1. `affectedSkillKeys` 必须是非空字符串列表。
2. 每项先按现有稳定标识规则规范化，再检查空值、格式和重复。
3. 同一技能标识在一个结果内只能出现一次。
4. 请求顺序不具有业务语义；响应按技能目录顺序稳定返回。
5. 旧字段 `affectedSkillKey` 不再接受，也不双写；提交旧字段返回 `400.INVALID_BODY`。
6. 减少和增加必须携带原有 `valueRule`；重置时 `valueRule` 必须为 null。
7. 创建和全量更新仍一次提交完整效果及结果数组，没有独立的受影响技能写接口。

## 6. 校验与错误

| 场景 | HTTP 与错误码 | 字段路径 |
| --- | --- | --- |
| `affectedSkillKeys` 不是列表、列表项不是字符串，或提交旧 `affectedSkillKey` | `400.INVALID_BODY` | `results[i].detail.affectedSkillKeys`、具体列表项或旧字段 |
| 列表为空 | `400.VALIDATION_FAILED`，原因 `AFFECTED_SKILL_REQUIRED` | `results[i].detail.affectedSkillKeys` |
| 规范化后出现重复技能 | `400.VALIDATION_FAILED`，原因 `DUPLICATE_AFFECTED_SKILL` | 重复项 `results[i].detail.affectedSkillKeys[j]` |
| 技能不存在或不属于同一游戏 | `400.INVALID_SKILL_EFFECT_REFERENCE`，原因 `UNKNOWN_SKILL` | 对应列表项 |
| 新增了停用技能引用 | `409.SKILL_EFFECT_REFERENCE_DISABLED`，原因 `SKILL_DISABLED` | 对应列表项 |
| 删除仍被其他技能冷却结果引用的技能 | `409.SKILL_IN_USE` | 技能删除请求 |

停用规则沿用现有语义并扩展到集合：

1. 新建结果只能选择启用技能。
2. 当前路径父级技能即使已停用，仍允许把自身加入列表。
3. 编辑已有结果时，原结果中已有的停用技能可以原样保留或移除。
4. 对同一结果新增停用技能仍被拒绝；是否新增按结果稳定标识和旧、新目标集合的差集判断。
5. 目录中已不存在的目标技能必须显示稳定标识并阻止保存，不能静默丢弃。

## 7. 全量更新和结果身份

1. `resultKey` 和 `resultType` 的不可修改规则保持不变。
2. 编辑冷却结果允许增加、移除或重新选择受影响技能。
3. 目标集合变化不创建新结果，不改变结果排序、名称、生命周期行为或前序结果引用。
4. 后端在同一效果 PUT 事务中写入最终目标集合；任一技能引用、数值规则或结构校验失败时，效果、结果和目标集合全部回滚。
5. 一个结果关联四个技能时，`resultCount` 仍只计为一个结果。
6. 阶段 7.4 生命周期行为、阶段 7.5 动作与前序结果，以及阶段 7.6 未来增加的结果级阻挡或修正都作用于整个结果，不按目标技能拆分。

## 8. 页面外部行为

1. “受影响技能”使用现有组件库默认多选下拉框，支持搜索和清空，不增加自定义样式。
2. 新建结果只提供启用技能和当前父级技能例外。
3. 编辑结果时，所有已选技能以标签显示；已有停用项标记“已停用”并可移除。
4. 未选择任何技能时不能保存，并在多选字段下显示错误。
5. 保存成功后关闭结果编辑弹窗；重新打开时完整回显所有受影响技能。
6. 结果列表和查看弹窗显示已选技能名称；数量较多时使用组件库默认折叠能力，不针对移动端设计。
7. 页面不增加“角色全部技能”“排除装备技能”等尚无挂载关系支撑的选项，也不显示阶段说明或教学文案。

## 9. 数据迁移原则

1. 已有每条冷却变化结果的单个 `affectedSkillKey` 必须迁移为只含该技能的一项集合，不能丢数据。
2. 新库结构直接使用一对多关系；已有库通过独立兼容迁移完成结构转换。
3. 迁移必须单事务执行，可重复检查完整新结构；旧结构、完整新结构和部分迁移结构必须明确区分。
4. 部分结构、约束漂移或回填数量不一致时主动停止，不使用静默默认值。
5. 不保留旧字段、不双写、不兼容旧请求；当前 MVP 允许破坏式契约更新。

## 10. 范围与非目标

本补项包含：

1. 冷却变化结果的多技能显式选择、保存、回读和全量更新。
2. 真实关系表、外键、停用规则和技能删除保护。
3. 后端强类型请求、响应、聚合服务和数据库迁移。
4. 前端多选、草稿转换、错误定位和桌面浏览器验收。
5. 伊泽瑞尔 Q 选择 Q、W、E、R 的代表案例。

本补项不包含：

1. 角色技能或装备技能挂载关系。
2. 自动选择角色全部技能、自动排除装备技能或根据装备变化动态展开集合。
3. 冷却计时、技能是否当前可用、技能是否实际拥有、公式执行或结果结算。
4. 发布、计算输入、Wasm、旧 Ability、Provider 或旧 combat-data。
5. 修改阶段 7.6 的伤害、护盾、斩杀、联动或前序结果范围。
6. 为同一结果中的不同技能配置不同数值、操作、生命周期或阻挡方式。

## 11. 实施顺序与门禁

1. 项目负责人审核本共享契约和两份模块详细设计；未确认前不得开发。
2. 后端先完成数据库结构、兼容迁移、强类型接口、事务和删除保护。
3. 在负责人指定的真实开发数据库备份后执行迁移，验证旧单目标数据无损回填。
4. 重启后端并完成真实 POST、GET、PUT、DELETE 冲突和重启回读验收。
5. 前端再切换到多选契约，完成表单、客户端、单元测试和桌面端浏览器验收。
6. 本补项前后端、真实数据库和真实页面全部验收通过后，才能开始阶段 7.6.1 开发。

## 12. 跨端验收

代表案例固定为：

1. 先建立伊泽瑞尔 Q、W、E、R 和一个装备技能，以及固定 1500 毫秒公式。
2. 在 Q 的效果中新增一个冷却变化结果，作用对象为施法者，操作为减少，选择 Q、W、E、R。
3. 保存后数据库存在一条冷却变化明细和四条受影响技能关系，不存在装备技能关系。
4. GET 详情返回一个结果和四个 `affectedSkillKeys`；页面重开完整回显四项。
5. 编辑为只选择 W、E、R 后保存，Q 关系被删除，其他三项保留。
6. 添加重复技能时前端先阻止；绕过前端提交时后端返回稳定字段错误，数据库无部分写入。
7. 新增停用外部技能被拒绝；原有停用目标可以保留或移除。
8. 删除被其他技能结果引用的 W 时返回 `409.SKILL_IN_USE`；先从目标集合移除后可删除。
9. 阶段 7.5 的 Q 命中规则仍只执行一个效果，不因四个目标变成四个动作或四个结果。
10. 验收只证明配置管理闭环，不声明真实冷却已经执行。

## 13. 停止条件

出现以下任一情况必须停止并回到方案确认：

1. 实现需要把技能列表保存为数组列、JSONB、文本拼接或前端隐藏拆分结果。
2. 实现需要提前建立角色/装备挂载或运行时技能归属模型。
3. 现有阶段 7.5 结果引用要求一个目标技能拥有独立结果身份，导致一个多目标结果语义不成立。
4. 兼容迁移不能无损回填现有单目标记录。
5. 后端最终接口、前端类型和数据库关系对“一个结果对应多个技能”的理解不一致。
6. 真实数据库、接口或浏览器验收不可用且无法定点确认原因。
