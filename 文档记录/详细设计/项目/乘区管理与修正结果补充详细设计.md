## 1. 目标与成功标准

本补充阶段必须完成：

1. 增加游戏级独立乘区定义及其增删改查页面。
2. 乘区不从属于技能、角色、装备、海克斯或天赋，也不保存这些来源的反向列表。
3. 具体引用落在技能效果的修正结果上，而不是技能主记录上；一个技能可以通过多个结果进入不同乘区。
4. 持续属性增加/减少、伤害修正和治疗修正必须引用兼容乘区。
5. 同一乘区内的有效修正先做带符号加算；比例乘区形成 `1 + 加算结果`，不同乘区的比例因子再相乘。
6. 允许伤害、治疗和持续属性修正选择施加时快照或每次对应数值结算时重新读取公式。
7. 前端在修正结果编辑器中可以选择已有乘区，也可以明确打开“新增乘区”弹窗；新增成功后回到原草稿并自动选中。

成功只表示定义、引用、校验、保存和完整回读已经闭环，不表示公式已经执行，也不表示属性、伤害或治疗已经按乘区结算。

## 2. 关系与责任边界

固定关系如下：

```text
游戏
├─ 属性定义
├─ 乘区定义
└─ 技能
   └─ 效果
      └─ 结果
         ├─ 持续属性增加/减少 ──→ 属性定义 + 乘区定义
         ├─ 伤害修正 ──────────→ 乘区定义
         └─ 治疗修正 ──────────→ 乘区定义
```

规则：

1. 技能、装备技能、海克斯技能和天赋技能只要产生修正结果，都通过结果引用同一游戏的乘区；乘区不区分来源种类。
2. 角色或装备后续如何挂载技能不属于乘区定义，不在乘区表增加角色、装备或来源类型字段。
3. 属性定义仍只表示基础面板量或独立公式量。固定移动速度和百分比移动速度不因乘区出现而重新建立属性定义；它们是对移动速度属性的不同修正。
4. 百分比护甲穿透仍是伤害公式需要的独立属性，不等于“生命值提高 10%”一类乘区修正。
5. 乘区只决定修正值如何分组和解释，不拥有触发条件、持续时间、层数、公式表达式、伤害类型、技能/普攻过滤或暴击过滤。
6. 条件继续由现有效果、触发规则和公式表达；乘区不建立第二套条件系统。

## 3. 乘区定义

### 3.1 公共字段

乘区请求和响应使用以下字段：

```json
{
  "modifierZoneKey": "damage_outgoing_general",
  "name": "通用伤害提高",
  "domain": "DAMAGE",
  "calculationMode": "RATIO_ADD",
  "applicationStage": "DAMAGE_PRE_DEFENSE",
  "description": null,
  "status": "ENABLED",
  "sortOrder": 100
}
```

| 字段 | 规则 |
| --- | --- |
| `modifierZoneKey` | 游戏内稳定标识，创建后不可修改；长度 1～64，匹配现有稳定标识规则。 |
| `name` | 必填；同一游戏内忽略大小写与首尾空格后唯一。 |
| `domain` | `ATTRIBUTE / DAMAGE / HEALING`。 |
| `calculationMode` | `FLAT_ADD / RATIO_ADD`。 |
| `applicationStage` | 固定结算阶段，必须与作用范围和计算方式匹配。 |
| `description` | 可空，长度不超过 2000。 |
| `status` | `ENABLED / DISABLED`。停用后不允许新增或改选引用，已有引用可原样保留。 |
| `sortOrder` | 只负责管理页面排序，不承担结算优先级。 |

响应另有 `gameId / createdAt / updatedAt`。

### 3.2 固定组合

第一版只允许以下组合：

| `domain` | `calculationMode` | `applicationStage` | 用途 |
| --- | --- | --- | --- |
| `ATTRIBUTE` | `FLAT_ADD` | `ATTRIBUTE_FLAT` | 大力 `+20` 攻击力等固定属性修正。 |
| `ATTRIBUTE` | `RATIO_ADD` | `ATTRIBUTE_PERCENT` | 歌利亚巨人 `+15%` 攻击力或法强等比例属性修正。 |
| `DAMAGE` | `RATIO_ADD` | `DAMAGE_PRE_DEFENSE` | 砍倒、回归基本功、巨人杀手等防御计算前伤害比例修正。 |
| `DAMAGE` | `RATIO_ADD` | `DAMAGE_POST_DEFENSE` | 明确要求在防御计算后生效的最终伤害比例修正。 |
| `HEALING` | `RATIO_ADD` | `HEALING_RESULT` | 造成或受到的直接治疗、吸血比例修正。 |

本轮不增加伤害固定增减、治疗固定增减、取最大值、覆盖最终值、乘区自定义脚本、可编辑聚合方式或可编辑舍入方式。出现真实样例后单独确认，不提前为旧方案全部能力建字段。

### 3.3 乘区不绑定具体属性

属性乘区不保存 `attributeKey`。具体属性仍由属性变化结果选择，未来聚合键包含“作用对象 + 属性 + 乘区”。因此同一个比例属性乘区可以用于攻击力或法强，但不同属性的修正不会互相加算。

这样可以保持两层责任：

1. 乘区定义“固定加算还是比例加算”。
2. 结果定义“修正哪个属性以及修正多少”。

适应之力最终落到攻击力还是法强不由乘区判断；本补充阶段要求录入时选择实际被修正属性。若后续需要根据角色构筑自动选择攻击力或法强，应建立独立的适应之力解析需求，不能在乘区名称或技能来源中猜测。

## 4. 固定聚合语义

### 4.1 候选值

每个正在生效并且过滤条件匹配的修正结果产生一个候选值：

1. 数值规则先得到非负修正量。
2. `INCREASE` 转为正值，`DECREASE` 转为负值。
3. `FLAT_ADD` 的单位是属性绝对值。
4. `RATIO_ADD` 的单位是小数比例，例如 15% 保存和解释为 `0.15`。
5. `valueRule.fixedMultiplier` 只修正该结果自己的公式值，不创建乘区，也不改变跨来源聚合关系。

本阶段只保存公式引用和固定修正，不执行公式，因此“公式结果非负”是未来执行契约，不能通过后端静态求值伪造校验。

### 4.2 同一乘区加算

同一乘区内所有有效候选先求和：

```text
zoneValue = Σ signedCandidateValue
```

结果来自哪个技能、装备技能、海克斯或天赋不影响加算。是否属于同一乘区只看同一游戏下相同的 `modifierZoneKey`，同时仍需满足当前作用对象、属性和过滤上下文一致。

### 4.3 不同乘区相乘

比例乘区先形成各自因子：

```text
zoneFactor = 1 + zoneValue
```

同一结算阶段的不同比例乘区再相乘：

```text
stageFactor = Π zoneFactor
```

示例：

1. 两个技能都选择同一伤害乘区，分别提高 10% 和 20%，得到 `1 + 0.10 + 0.20 = 1.30`。
2. 两个技能选择不同伤害乘区，分别提高 10% 和 20%，得到 `1.10 × 1.20 = 1.32`。
3. 同一固定属性乘区的 `+20` 与 `+10` 攻击力得到 `+30`；固定属性修正不与比例乘区直接相乘，而是先加入属性，再应用比例属性乘区。

### 4.4 固定阶段顺序

未来计算顺序固定为：

1. 角色等级属性与装备直接属性形成基础属性。
2. `ATTRIBUTE_FLAT` 的乘区结果加入对应属性。
3. `ATTRIBUTE_PERCENT` 的不同乘区因子相乘并应用到属性。
4. 技能或普通攻击公式形成原始伤害。
5. `DAMAGE_PRE_DEFENSE` 乘区生效。
6. 执行伤害类型对应的防御计算。
7. `DAMAGE_POST_DEFENSE` 乘区生效。
8. 治疗结果形成后应用 `HEALING_RESULT` 乘区。

本阶段不执行上述顺序。未来计算不得在每个乘区后单独舍入；同一阶段全部乘区完成后再按后续结算方案统一处理，因此页面排序不影响数值。

## 5. 修正结果契约

### 5.1 持续属性增加或减少

既有 `ATTRIBUTE_CHANGE` 不新增结果种类，按以下规则补充：

1. 没有生命周期的离散属性变化保持原语义，不引用乘区。
2. `operation = SET` 不引用乘区，继续表示明确覆盖值。
3. `moment = PERSISTENT` 且 `operation = INCREASE / DECREASE` 时，`detail.modifierZoneKey` 必填。
4. 该乘区必须属于 `ATTRIBUTE`；结果自己的 `attributeKey` 继续指定被修正属性。
5. `ATTRIBUTE_FLAT` 下公式值按绝对属性值解释；`ATTRIBUTE_PERCENT` 下按小数比例解释。

示例：

```json
{
  "attributeKey": "attack_damage",
  "operation": "INCREASE",
  "modifierZoneKey": "attribute_flat_general"
}
```

### 5.2 伤害修正

`DAMAGE_MODIFIER.detail` 在现有字段上增加必填 `modifierZoneKey`：

```json
{
  "direction": "DEALT",
  "operation": "INCREASE",
  "modifierZoneKey": "damage_outgoing_general",
  "damageTypeKey": null,
  "deliveryKind": "SKILL",
  "originKind": "ANY",
  "criticalFilter": "ANY"
}
```

乘区必须属于 `DAMAGE + RATIO_ADD`。`direction`、伤害类型、技能/普通攻击、直接/反伤和暴击字段继续只负责候选是否适用，不负责乘区归组。

回归基本功使用 `deliveryKind = SKILL` 排除普通攻击；巨人杀手和砍倒的比例由公式读取来源/目标属性计算，不建立专用乘区字段。

### 5.3 治疗修正

`HEALING_MODIFIER.detail` 在现有字段上增加必填 `modifierZoneKey`：

```json
{
  "direction": "DONE",
  "operation": "INCREASE",
  "modifierZoneKey": "healing_done_general",
  "healingKind": "ANY"
}
```

乘区必须属于 `HEALING + RATIO_ADD`。造成/受到与直接治疗/吸血仍只负责匹配候选。

### 5.4 不使用乘区的结果

伤害、直接治疗、普通护盾、资源变化、冷却变化、状态操作、生命周期操作、伤害免疫和生命下限不得提交 `modifierZoneKey`。伤害结果自己的伤害公式系数也不等于乘区。

已有结果的 `resultType` 仍不可原地修改。修改乘区只改变现有修正结果的引用，不改变结果身份。

## 6. 生命周期与动态读取

当前 `valueReadMode` 两个值继续复用，不增加第三个枚举：

| 值 | 修正结果中的含义 |
| --- | --- |
| `APPLICATION_SNAPSHOT` | 每层或共享值在施加时读取并保留。 |
| `MOMENT_EVALUATION` | 每次对应属性、伤害或治疗数值进入该乘区时重新读取公式。 |

补充矩阵：

| 结果 | 读取方式 | 层值 | 重复施加值 |
| --- | --- | --- | --- |
| 持续属性增加/减少、伤害修正、治疗修正 | `APPLICATION_SNAPSHOT` | `SHARED / PER_STACK` | 沿用现有快照规则。 |
| 持续属性增加/减少、伤害修正、治疗修正 | `MOMENT_EVALUATION` | `SHARED / PER_STACK` | 必须为 null；共享值每个生命周期实例贡献一次，每层值由每个有效层分别贡献。 |
| 属性覆盖、生命下限 | 继续只允许 `APPLICATION_SNAPSHOT + SHARED` | 不变 | 不变。 |
| 伤害免疫 | null | null | null。 |

`MOMENT_EVALUATION + SHARED` 每次结算只计算一个当前值，不随层数重复；`MOMENT_EVALUATION + PER_STACK` 由每个有效层分别贡献。两者都不保存历史公式结果，也不复用 `KEEP / REPLACE / ADD`，避免把动态值和历史快照混在一起。

巨人杀手、砍倒等依赖当前来源或目标属性的公式必须使用 `MOMENT_EVALUATION`。固定的歌利亚巨人或大力属性修正可以使用 `APPLICATION_SNAPSHOT`。

动态读取公式只能使用固定值、技能等级值、角色等级值和来源/目标属性节点；本阶段禁止引用 `RUNTIME_INPUT` 参数，因为触发动作只在效果施加时绑定一次运行输入，无法为后续每次属性、伤害或治疗结算持续供值。需要事件值参与的修正必须先使用施加快照，或在后续运行契约中单独设计持续绑定，不能静默复用过期事件值。

本节只冻结未来读取身份，不实现运行实例、属性解析、伤害结算或治疗结算。

## 7. 乘区管理接口

基础路径：

```text
/api/admin/games/{gameId}/modifier-zones
```

| 方法 | 路径 | 用途 | 成功状态 |
| --- | --- | --- | ---: |
| GET | `/modifier-zones?keyword=&domain=&status=` | 查询乘区 | 200 |
| GET | `/modifier-zones/{modifierZoneKey}` | 查询详情 | 200 |
| POST | `/modifier-zones` | 新建 | 201 |
| PUT | `/modifier-zones/{modifierZoneKey}` | 全量修改 | 200 |
| DELETE | `/modifier-zones/{modifierZoneKey}` | 删除未引用乘区 | 204 |

规则：

1. 列表顺序固定为 `sortOrder ASC, name ASC, modifierZoneKey ASC`，不分页。
2. `modifierZoneKey` 创建后不可修改。
3. 未被引用时可以修改作用范围、计算方式和结算阶段；已被引用时三者不可修改，只能修改名称、说明、状态和排序。
4. 停用允许保留既有引用，但不能建立新的引用或把其他结果改选到该乘区。
5. 被任一结果引用时 DELETE 返回占用错误，不级联删除结果。

## 8. 稳定错误

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.VALIDATION_FAILED` | 乘区字段、固定组合或修正结果乘区字段缺失/多余。 |
| 400 | `400.INVALID_SKILL_EFFECT_REFERENCE` | 乘区不存在、停用、跨游戏、作用范围不匹配或计算方式不匹配。 |
| 404 | `404.MODIFIER_ZONE_NOT_FOUND` | 乘区详情、修改或删除目标不存在。 |
| 409 | `409.MODIFIER_ZONE_KEY_EXISTS` | 同一游戏稳定标识重复。 |
| 409 | `409.MODIFIER_ZONE_NAME_EXISTS` | 同一游戏规范化名称重复。 |
| 409 | `409.MODIFIER_ZONE_IN_USE` | 删除乘区，或修改已引用乘区的作用范围、计算方式、结算阶段。 |

效果字段问题定位到 `results[i].detail.modifierZoneKey`；乘区自身字段定位到 `domain / calculationMode / applicationStage`。未知数据库约束不得伪装为业务错误。

## 9. 页面外部行为

1. 主导航在“伤害类型管理”和“技能管理”之间增加“乘区管理”，路由为 `#/modifier-zones`。
2. 页面提供关键词、作用范围、状态筛选，以及查看、新建、编辑、启停和删除。
3. 页面不显示阶段说明、教学文案、旧乘区结构、Provider、Wasm 或计算预览。
4. 弹窗使用组件库默认样式，允许点击遮罩或按 Esc 关闭，不增加自定义边框或移动端适配。
5. 属性变化、伤害修正、治疗修正结果按自身类型只显示兼容乘区。
6. 乘区选择器旁提供“新增乘区”；必须由用户明确点击，不能把输入文本自动创建为乘区。
7. 从结果弹窗新建乘区时预设并锁定兼容作用范围；保存成功关闭乘区弹窗、刷新目录并自动选中，原效果草稿不得丢失或自动保存。
8. 停用或未知旧引用显示状态并允许原样保留；新增和改选不显示停用项。

## 10. 数据与迁移原则

1. 当前代码和数据库不再拥有旧 `coefficient_buckets`；不得恢复旧表、旧 JSON 配置或旧 API。
2. 新库直接建立关系表和三处明确外键。
3. 已有库使用独立迁移补表、列、外键、索引和延迟检查。
4. 不建立系统默认乘区，不按方向、名称、伤害类型或公式自动猜测乘区。
5. 如果已有持续属性增加/减少、伤害修正或治疗修正记录无法直接补齐必填乘区，迁移必须在修改结构前报告数量并停止；由项目负责人决定删除测试数据或提供明确映射。
6. 不为旧数据建立兼容乘区、双读、双写或回退字段。

## 11. 实施顺序

1. 项目负责人审核本候选方案并关闭固定/比例属性、动态读取和页面入口问题。
2. 按当前代码和真实数据库复核已有三类修正记录数量及阶段 7.6.2 实际结构。
3. 后端先交付乘区表、接口、三处结果引用、生命周期矩阵和兼容迁移。
4. 执行真实数据库迁移、接口增删改查、引用保护、重启回读和事务回滚验收。
5. 前端再交付独立页面、导航、结果选择器和弹窗内新增入口。
6. 执行桌面浏览器保存、关闭、刷新、重开、失败保留和内联新增验收。
7. 本补充阶段通过后，重新核对阶段 7.6.3～7.6.5 的前置表数、结果形状函数和设计状态，再决定是否开发 7.6.3。

## 12. 跨端验收

### 12.1 乘区定义

1. 新建固定属性、比例属性、防御前伤害、防御后伤害和治疗五类代表乘区。
2. 刷新、关闭页面和后端重启后字段完整回读。
3. 修改已引用乘区的作用范围、计算方式或阶段返回 409；修改名称、说明、状态和排序成功。
4. 删除被引用乘区返回 409；删除未引用乘区成功。

### 12.2 属性修正

1. 大力使用 `ATTRIBUTE + FLAT_ADD` 乘区和攻击力属性，公式值为 20。
2. 歌利亚巨人使用 `ATTRIBUTE + RATIO_ADD` 乘区，公式值为 0.15，并明确选择攻击力或法强属性。
3. 同一乘区可被多个技能结果引用；不同属性仍分别回读，不发生跨属性关系合并。
4. 持续增加/减少缺乘区、引用伤害乘区或属性覆盖携带乘区均失败。

### 12.3 伤害与治疗修正

1. 回归基本功选择伤害乘区并固定 `SKILL`，普通攻击过滤仍不可选中该候选。
2. 巨人杀手公式读取目标额外生命值并选择 `MOMENT_EVALUATION`，关闭和重开后保留。
3. 两个结果选择同一乘区与选择两个不同乘区都能无损保存，页面摘要清楚显示乘区名称。
4. 治疗修正只能选择治疗乘区，伤害修正不能选择属性或治疗乘区。
5. 动态读取公式引用运行输入参数时保存失败；改为只读取来源/目标属性后可以保存。

### 12.4 内联新增与失败保留

1. 在结果弹窗中打开新增乘区，保存后自动选中且效果其他字段不变。
2. 新增乘区失败时保留乘区草稿和父效果草稿。
3. 关闭新增乘区弹窗只丢弃乘区草稿，不关闭父结果或父效果弹窗。

### 12.5 反例

1. 系统不得自动创建“通用乘区”或把所有提高伤害结果归到同一区。
2. `direction`、伤害类型、技能/普攻、暴击和治疗类型不得被当作隐式乘区。
3. 页面、接口和数据库不得出现旧 `bucketConfig`、自由 JSON、来源类型数组或技能反向列表。
4. 本阶段验收不得以 Wasm 计算结果代替真实数据库、接口和浏览器回读。

## 13. 非目标与停止条件

本轮不包含：

1. 实际属性、伤害、治疗、护盾、防御、舍入或同帧结算。
2. Wasm、计算输入组装、发布、计算预览或乘区证据输出。
3. 海克斯、天赋、装备与技能的挂载页面或来源分类表。
4. 适应之力自动选择攻击力/法强。
5. 固定伤害减免、固定治疗增减、取最大值、覆盖最终值或自定义聚合方式。

出现以下任一情况停止开发并回到方案确认：

1. 真实数据库存在无法无损归属乘区的已有修正结果。
2. 当前公式不能读取巨人杀手所需的来源/目标属性，必须增加新的公式语言或条件系统。
3. 需要执行 Wasm 或提前实现 7.6.3～7.6.5 才能完成保存与回读。
4. 需要 JSONB、数组外键、自由字符串关系、默认隐式乘区或来源特例。
5. 固定属性和比例属性不能通过明确阶段保持稳定顺序。
