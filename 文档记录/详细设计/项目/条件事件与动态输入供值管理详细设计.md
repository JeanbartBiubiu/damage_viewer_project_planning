## 1. 本次需要确认的决定

1. 阶段 7.5 新增从属于单个技能的“技能触发规则”聚合。规则负责把一个固定事件来源、可选条件组和一组有序动作连接起来，不把条件或事件字段塞回阶段 7.2 效果、阶段 7.3 过程或阶段 7.4 生命周期表。
2. 事件种类是系统固定联合类型，不建立事件类型表、自由新增页面、脚本或自定义事件名称。事件明细只引用已经存在的技能、过程、步骤、效果、结果、生命周期时点、状态、属性和内部状态稳定标识。
3. 条件使用两层固定结构：条件组之间为“或”，同一组内条件为“且”。不建立任意嵌套条件树；没有条件组表示无条件触发。
4. 一个规则至少包含一个动作。动作按 `sortOrder ASC, actionKey ASC` 顺序确定先后，固定支持执行效果、启动过程和令过程失败三种，不提供自由动作类型。
5. 阶段 7.3 的过程效果挂接仍表示“固定过程时点无条件执行完整效果”，不迁移到触发规则。需要外部事件、条件或动态输入时才建立触发规则。
6. 执行效果和启动过程动作可以为同一技能的 `RUNTIME_INPUT` 参数提供本次来源绑定；公式定义、参数定义和某次实际值仍不保存在规则中。
7. 动态输入来源固定为技能内部状态、战斗状态、当前事件值和同一规则中更早动作的基础结果值。属性值继续由公式属性节点直接读取，不重复建立属性供值绑定。
8. 前序结果在本阶段只开放“基础结果值” `CONFIGURED_VALUE`：即结果公式应用阶段 7.2 固定倍率、固定最小值和固定最大值后的数值，尚未经过防御、护盾、实际扣血、暴击、吸血、阻挡或免疫。丰富结果来源留到阶段 7.6。
9. 前序结果只能引用同一规则内更早的“执行效果”动作、该动作目标效果中的一个数值结果，并且该结果必须在效果执行当下可用。生命周期的持续生效、满层、周期、自然结束和提前移除结果不能作为同一轮动作序列的前序值。
10. 执行效果动作可以对目标效果中的数值结果增加一次固定倍率、固定最小值和固定最大值修正。随等级或运行状态变化的修正必须继续通过技能参数、公式和动态输入表达。
11. 每目标冷却和单次过程最大触发次数是规则级可选保护。两者都引用同一技能公式，只保存结构和引用，不求值、不计时、不计数。
12. 循环检查以规则为节点，按封闭生产表展开现有过程效果挂接和生命周期操作可能形成的规则依赖。保护在目标规则动作前生效；移除所有进入受保护规则的边后，剩余图不得存在有向环。
13. 规则动作的目标对象固定为“当前目标”或“事件来源对象”。无论选择哪一种，阶段 7.2 结果中的 `SOURCE` 始终表示技能拥有者，`TARGET` 表示该动作选定的目标对象；本阶段不修改 `SkillEffectTarget`。
14. 过程失败原因固定为受到控制、来源死亡、目标不可选取、主动取消和事件终止。失败动作必须是规则最后一个动作，避免失败后是否继续执行后续动作产生歧义。
15. 生命周期时点事件只允许施加、达到满层、每次周期、自然结束和提前移除；`PERSISTENT` 是持续存在语义，不是一次离散事件。
16. 事件筛选、条件右值、每目标冷却和单次过程最大触发次数直接引用的公式不得包含 `RUNTIME_INPUT` 参数；这些公式没有动作上下文。动态输入绑定只服务于执行效果或启动过程动作的可达公式。
17. 阶段 7.5 只保存、校验、回读和保护引用，不执行事件分发、条件判断、动作、公式、供值、计时、触发次数、循环、伤害、状态或过程。

## 3. 数据关系与责任方向

```text
游戏
├─ 状态 / 属性 / 技能目录
└─ 技能
   ├─ 技能参数与公式
   ├─ 技能内部状态
   ├─ 技能过程 ──步骤 / 固定过程时点 / 无条件效果挂接
   ├─ 技能效果 ──结果 / 可选生命周期 / 固定生命周期时点
   └─ 技能触发规则
      ├─ 一个固定事件来源
      ├─ 零到多个条件组
      │  └─ 一到多个固定条件
      ├─ 一到多个有序动作
      │  ├─ 执行同技能效果
      │  │  ├─ 动态输入来源绑定
      │  │  └─ 固定结果修正
      │  ├─ 启动同技能过程
      │  │  └─ 动态输入来源绑定
      │  └─ 令同技能过程失败
      ├─ 可选每目标冷却
      └─ 可选单次过程最大触发次数
```

责任方向：

1. 触发规则主动引用已有对象；被引用对象不反向保存规则标识。
2. 事件来源只描述“何时尝试匹配规则”，条件只描述“是否允许”，动作只描述“匹配后按什么顺序关联已有过程或效果”。
3. 动态输入绑定只为动作可达公式中的 `RUNTIME_INPUT` 参数声明来源，不修改参数和公式定义。
4. 固定结果修正从属于某个执行效果动作，不修改被引用效果的基础结果。
5. 规则属于一个技能。除 `SKILL_USED` 和 `SKILL_HIT` 可以筛选同一游戏其他技能外，过程、效果、结果、生命周期、内部状态、公式、参数和模式选项引用都必须属于当前技能。

### 4.3 基本字段

| 字段 | 规则 |
| --- | --- |
| `ruleKey` | 创建时必填；格式与 `effectKey` 相同；同一技能内唯一；创建后不可修改。 |
| `name` | 必填；去除首尾空格后长度 1～100。 |
| `description` | 可为 null；非空时去除首尾空格后长度不超过 1000。 |
| `sortOrder` | 必填；0～999999。 |
| `eventSource` | 必填；必须符合固定事件联合类型。 |
| `conditionGroups` | 必填数组；可以为空；组标识不得重复。 |
| `actions` | 必填数组；至少一项；动作标识不得重复。 |
| `perTargetCooldown` | 可为 null；非空时符合第 10 节。 |
| `maxTriggersPerProcess` | 可为 null；非空时符合第 10 节。 |

PUT 不提交 `ruleKey`。已有 `groupKey`、`conditionKey`、`actionKey` 和 `bindingKey` 的种类不可原地修改；需要改变种类时明确删除旧标识并用新标识新增。

## 5. 固定事件来源

### 5.1 固定种类

| `eventType` | 中文含义 | 必填明细 |
| --- | --- | --- |
| `SKILL_USED` | 技能被主动或消耗使用 | 可空 `sourceSkillKey`；`useKind = ACTIVE / CONSUMABLE / ANY`。空技能表示来源对象使用任意技能。 |
| `BASIC_ATTACK_START` | 普通攻击发起 | 无。 |
| `BASIC_ATTACK_HIT` | 普通攻击命中 | 无。 |
| `SKILL_HIT` | 技能命中 | 可空 `sourceSkillKey`；空表示来源对象任意技能命中。 |
| `PROCESS_MOMENT` | 当前技能过程到达固定时点 | `processKey` 和阶段 7.3 `moment`。 |
| `RESULT_AVAILABLE` | 当前技能某个无生命周期基础结果到达可用时点 | `effectKey`、`resultKey`。 |
| `LIFECYCLE_MOMENT` | 当前技能生命周期到达离散时点 | `effectKey`；`moment = APPLICATION / FULL_STACKS / PERIODIC / NATURAL_END / EARLY_REMOVE`。 |
| `DAMAGE_DEALT` | 来源对象造成伤害 | 无；本阶段不携带伤害结算值。 |
| `DAMAGE_TAKEN` | 来源对象受到伤害 | 无；事件来源对象表示伤害来源。 |
| `STATUS_CHANGED` | 指定对象的战斗状态施加或移除 | `subject = SOURCE / CURRENT_TARGET`、`statusKey`、`change = APPLY / REMOVE`。 |
| `HEALTH_THRESHOLD_CROSSED` | 指定对象生命属性越过阈值 | `subject`、`attributeKey`、`thresholdFormulaKey`、`direction = UPWARD / DOWNWARD`。 |
| `INTERNAL_STATE_CHANGED` | 当前技能内部状态发生固定变化 | `stateKey`；`changeKind = VALUE_CHANGED / OPTION_SELECTED / FLAG_CHANGED / COOLDOWN_READY`。 |
| `CONTROL_RECEIVED` | 来源对象受到控制 | 无；事件来源对象表示控制来源。 |
| `ENTITY_DIED` | 指定对象死亡 | `subject = SOURCE / CURRENT_TARGET`。 |
| `ENTITY_UNTARGETABLE` | 指定对象变为不可选取 | `subject = SOURCE / CURRENT_TARGET`。 |
| `KILL` | 来源对象完成击杀 | 无；当前目标表示被击杀对象。 |
| `PROCESS_CANCEL_REQUESTED` | 指定过程收到主动取消请求 | `processKey`。 |

规则：

1. `sourceSkillKey` 非空时必须引用同一游戏已存在技能；允许引用当前技能自身。
2. `detail` 始终是对象；表中“无”的事件提交 `{}`，不得提交 null 或其他事件字段。`PROCESS_MOMENT` 的公共形状固定为 `{ "processKey": "...", "moment": { "momentType": "...", "stepKey": null } }`，完整复用阶段 7.3 嵌套时点；数据库可以拆列但响应必须还原该形状。
3. `PROCESS_MOMENT`、`PROCESS_CANCEL_REQUESTED`、`RESULT_AVAILABLE`、`LIFECYCLE_MOMENT` 和 `INTERNAL_STATE_CHANGED` 只能引用当前技能对象。
4. `PROCESS_MOMENT` 复用阶段 7.3 固定过程时点及步骤约束，不建立第二套过程时点。
5. `RESULT_AVAILABLE` 的目标效果必须没有生命周期。效果一旦拥有生命周期，其全部结果都只通过所属 `LIFECYCLE_MOMENT` 表达事件身份，避免 `APPLICATION` 同时出现结果事件和生命周期事件两种身份；同一规则动作内读取 `APPLICATION` 结果值仍按第 8.5 节处理。
6. `LIFECYCLE_MOMENT` 目标效果必须存在生命周期。`APPLICATION`、`FULL_STACKS` 和 `EARLY_REMOVE` 不要求效果内已有同名时点结果；`PERIODIC` 要求已配置周期间隔；`NATURAL_END` 要求存在自然持续时间且到期方式不是仅显式移除；`PERSISTENT` 永远不允许作为事件。
7. `HEALTH_THRESHOLD_CROSSED` 的 `attributeKey` 必须引用当前游戏启用的数值属性，阈值公式必须属于当前技能且不得引用 `RUNTIME_INPUT` 参数。现有属性没有“生命值分类”字段，因此 Backend 不按属性名称猜测，页面由数据维护者明确选择代表生命值的属性。

### 5.2 事件上下文能力

“来源对象”固定表示运行时拥有当前技能的对象。每种事件必须按下表确定“当前目标”；表中回退到来源对象后，当前目标始终存在。“事件来源对象”只表示造成受到伤害、控制或状态变化的另一对象，只有表中标记“有”的事件可以在条件、动作或每目标冷却中选择 `EVENT_SOURCE`。

| `eventType` | 当前目标固定绑定 | `EVENT_SOURCE` | 允许的事件值 |
| --- | --- | --- | --- |
| `SKILL_USED` | 该次技能使用的显式目标；没有时为来源对象。 | 无 | 无。 |
| `BASIC_ATTACK_START` | 本次普通攻击目标。 | 无 | 无。 |
| `BASIC_ATTACK_HIT` | 本次普通攻击命中的对象。 | 无 | `HIT_INDEX`。 |
| `SKILL_HIT` | 本次技能命中的对象。 | 无 | `HIT_INDEX`。 |
| `PROCESS_MOMENT` | 目标过程实例的目标；没有时为来源对象。 | 无 | `STEP_EXECUTION_INDEX` 只在 `STEP_EXECUTION`；`CHARGE_DURATION_MS` 只在蓄力步骤的 `STEP_EXECUTION / STEP_COMPLETE / STEP_TIMEOUT`；`RECAST_COUNT` 只在重施步骤的 `STEP_EXECUTION / STEP_COMPLETE / STEP_TIMEOUT`。 |
| `RESULT_AVAILABLE` | 目标效果执行上下文的目标；没有时为来源对象。 | 无 | 无。 |
| `LIFECYCLE_MOMENT` | 目标生命周期实例的承受对象。 | 无 | `LIFECYCLE_STACKS`、`REMAINING_MS`；`PERIOD_INDEX` 只在 `PERIODIC`。 |
| `DAMAGE_DEALT` | 本次伤害承受对象。 | 无 | 无。 |
| `DAMAGE_TAKEN` | 来源对象自身。 | 有，为本次伤害来源。 | 无。 |
| `STATUS_CHANGED` | `subject` 指定的状态变化对象。 | 有，为本次状态施加或移除来源。 | 无。 |
| `HEALTH_THRESHOLD_CROSSED` | `subject` 指定的生命属性变化对象。 | 无 | `ATTRIBUTE_BEFORE`、`ATTRIBUTE_AFTER`、`THRESHOLD_VALUE`。 |
| `INTERNAL_STATE_CHANGED` | `TARGET` 范围状态的实例目标；技能范围状态为来源对象。 | 无 | `STATE_BEFORE`、`STATE_AFTER` 只在 `VALUE_CHANGED`。 |
| `CONTROL_RECEIVED` | 来源对象自身。 | 有，为本次控制来源。 | 无。 |
| `ENTITY_DIED` | `subject` 指定的死亡对象。 | 无 | 无。 |
| `ENTITY_UNTARGETABLE` | `subject` 指定的不可选取对象。 | 无 | 无。 |
| `KILL` | 本次被击杀对象。 | 无 | 无。 |
| `PROCESS_CANCEL_REQUESTED` | 目标过程实例的目标；没有时为来源对象。 | 无 | 无。 |

固定顺序约定：生命周期时点先形成 `LIFECYCLE_MOMENT`，再按阶段 7.4 `sortOrder/resultKey` 处理该时点结果；无生命周期效果按同一结果顺序形成 `RESULT_AVAILABLE`。本阶段只冻结事件身份和顺序，不执行它们。

### 5.3 固定事件值

固定事件值只允许以下标识，并由第 5.2 节事件能力表限制：

| `eventValueKey` | 中文含义 | 来源值类型 | 允许事件 |
| --- | --- | --- | --- |
| `STEP_EXECUTION_INDEX` | 当前步骤第几次执行 | `INTEGER` | `PROCESS_MOMENT` 的 `STEP_EXECUTION`。 |
| `CHARGE_DURATION_MS` | 实际蓄力毫秒数 | `DECIMAL` | 蓄力步骤的 `PROCESS_MOMENT`。 |
| `RECAST_COUNT` | 当前过程已重施次数 | `INTEGER` | 重施步骤的 `PROCESS_MOMENT`。 |
| `HIT_INDEX` | 当前命中序号 | `INTEGER` | `BASIC_ATTACK_HIT`、`SKILL_HIT`。 |
| `LIFECYCLE_STACKS` | 当前生命周期层数 | `INTEGER` | `LIFECYCLE_MOMENT`。 |
| `PERIOD_INDEX` | 当前周期序号 | `INTEGER` | `LIFECYCLE_MOMENT + PERIODIC`。 |
| `REMAINING_MS` | 当前生命周期剩余毫秒数 | `DECIMAL` | `LIFECYCLE_MOMENT`。 |
| `STATE_BEFORE`、`STATE_AFTER` | 数值内部状态变化前后值 | `INTEGER` | `INTERNAL_STATE_CHANGED`。 |
| `ATTRIBUTE_BEFORE`、`ATTRIBUTE_AFTER` | 生命属性越阈值前后值 | `DECIMAL` | `HEALTH_THRESHOLD_CROSSED`。 |
| `THRESHOLD_VALUE` | 本次阈值公式值 | `DECIMAL` | `HEALTH_THRESHOLD_CROSSED`。 |

白名单由本共享契约独占，前后端代码各自实现同一固定表，不建立游戏级事件值目录。阶段 7.6 的原始伤害、防御后伤害、护盾吸收、实际扣血、实际治疗、阻挡、免疫和击杀结果不得混入本表。

序号和值约定：`STEP_EXECUTION_INDEX`、`HIT_INDEX`、`PERIOD_INDEX` 从 1 开始；单次步骤或不属于步骤序列的单次命中固定为 1；命中由阶段 7.3 重复步骤产生时，`HIT_INDEX` 等于该步骤本次 `STEP_EXECUTION_INDEX`。`RECAST_COUNT` 不含首次启动，第一次重施为 1。毫秒值非负，层数和内部状态值按阶段 7.3/7.4 定义钳制后的值提供。本阶段仍不实际生成这些值。

`INTERNAL_STATE_CHANGED` 的变化语义固定为：

1. `VALUE_CHANGED` 只允许计数或弹药，表示一次已接受操作令数值前后不同；达到最大值仍只产生这一个变化事件，若需判断满值，使用 `INTERNAL_STATE_CHECK + VALUE + EQ` 比较该状态的 `maxValueFormulaKey`。
2. `OPTION_SELECTED` 只允许模式，表示选中项发生变化；具体选项由内部状态条件过滤。
3. `FLAG_CHANGED` 只允许准备标记，表示布尔值发生变化；新值由内部状态条件过滤。
4. `COOLDOWN_READY` 只允许内部冷却，表示从不可用变为可用。
5. 不提供与 `VALUE_CHANGED` 重叠的 `VALUE_REACHED` 事件，也不在事件明细复制第二个阈值公式。

## 6. 条件组与固定条件

### 6.1 组合规则

公共形状为：

```json
{
  "groupKey": "target_is_low_health",
  "name": "目标低生命值",
  "sortOrder": 10,
  "conditions": [
    {
      "conditionKey": "health_below_threshold",
      "conditionType": "ATTRIBUTE_COMPARE",
      "sortOrder": 10,
      "detail": {
        "subject": "CURRENT_TARGET",
        "attributeKey": "hp",
        "attributeValueKind": "CURRENT_RATIO",
        "comparator": "LTE",
        "comparisonFormulaKey": "low_health_ratio"
      }
    }
  ]
}
```

1. `conditionGroups = []` 表示无条件匹配。
2. 每个组至少一个条件；组之间为“或”，组内条件为“且”。
3. 多个条件组同时满足时，规则仍只触发一次并只执行一遍动作。
4. `groupKey` 和 `conditionKey` 格式与 `ruleKey` 相同，分别在规则和条件组内唯一，创建后不可修改；组名必填且遵守规则名称长度，条件不另存名称。
5. 条件组和条件分别按 `sortOrder/key` 回读。
6. 不支持组内再嵌套组，也不通过 JSON 保存自由条件树。

### 6.2 属性比较 `ATTRIBUTE_COMPARE`

字段为 `subject`、`attributeKey`、`attributeValueKind`、`comparator`、`comparisonFormulaKey`。

1. `subject` 允许 `SOURCE`、`CURRENT_TARGET`、`EVENT_SOURCE`；事件不提供事件来源对象时不得选择后者。
2. 属性必须属于当前游戏；新增引用时必须启用。
3. 属性取值方式沿用阶段 6 已冻结的七种方式。
4. 比较公式必须属于当前技能且不得引用 `RUNTIME_INPUT` 参数。

### 6.3 战斗状态检查 `STATUS_CHECK`

固定检查方式：

| `checkKind` | 其他字段 |
| --- | --- |
| `PRESENT`、`ABSENT` | `subject`、`statusKey`；来源效果和比较字段必须为 null。 |
| `STACKS_COMPARE` | 额外必填 `sourceEffectKey/sourceResultKey/comparator/comparisonFormulaKey`。 |
| `REMAINING_MS_COMPARE` | 额外必填 `sourceEffectKey/sourceResultKey/comparator/comparisonFormulaKey`。 |

`sourceEffectKey/sourceResultKey` 必须指向当前技能具有生命周期的效果，以及其中 `PERSISTENT + STATUS_OPERATION + APPLY` 且引用相同 `statusKey` 的结果。这样层数和剩余时间只读取明确生命周期实例，不把同名状态的多个来源隐式合并。比较公式必须属于当前技能且不得引用 `RUNTIME_INPUT` 参数。

### 6.4 技能内部状态检查 `INTERNAL_STATE_CHECK`

固定取值方式：

| `valueKind` | 合法对象与比较字段 |
| --- | --- |
| `VALUE` | 计数或弹药；必填 `comparator/comparisonFormulaKey`。 |
| `OPTION_SELECTED` | 模式；必填 `optionKey`，比较字段为空。 |
| `ENABLED` | 准备标记；必填 `expectedBoolean`，比较字段为空。 |
| `REMAINING_MS` | 内部冷却；必填 `comparator/comparisonFormulaKey`。 |

内部状态和模式选项必须属于当前技能。状态种类必须与取值方式匹配；比较公式不得引用 `RUNTIME_INPUT` 参数。

### 6.5 事件值比较 `EVENT_VALUE_COMPARE`

字段为 `eventValueKey`、`comparator`、`comparisonFormulaKey`。事件值必须出现在第 5.2～5.3 节当前事件类型白名单中，公式必须属于当前技能且不得引用 `RUNTIME_INPUT` 参数。

### 6.6 比较符

比较符固定为 `LT / LTE / EQ / NE / GTE / GT`。所有比较右值通过同技能公式提供；不在条件中复制固定值或等级 Map。

## 7. 有序动作

### 7.1 公共字段与顺序

每个动作包含 `actionKey/name/actionType/sortOrder/targetContext/detail/runtimeInputBindings/resultModifiers`。

1. `actionKey` 格式与 `ruleKey` 相同，在规则内唯一，创建后不可修改。
2. `EXECUTE_EFFECT` 和 `START_PROCESS` 的 `targetContext` 固定为 `CURRENT_TARGET` 或 `EVENT_SOURCE`；事件不提供事件来源对象时不得选择后者。`FAIL_PROCESS` 的 `targetContext` 必须为 null，因为它结束来源对象当前技能下的指定过程，不重新选择一个动作目标。
3. 动作按 `sortOrder ASC, actionKey ASC` 串行确定先后；排序允许相同，但稳定标识决定并列顺序。
4. 同一规则内只能有一个 `FAIL_PROCESS`，并且必须排在最后。

### 7.2 执行效果 `EXECUTE_EFFECT`

`detail.effectKey` 必须引用当前技能效果。动作可以保存动态输入绑定和固定结果修正。

未来执行上下文中，效果结果的 `SOURCE` 仍是技能拥有者；`TARGET` 是 `targetContext` 选定的对象。阶段 7.2 的目标枚举不增加“事件来源对象”。

### 7.3 启动过程 `START_PROCESS`

`detail.processKey` 必须引用当前技能过程。主动、被动和消耗过程都通过明确事件规则启动，不从过程名称或技能分类推断。动作可以保存动态输入绑定，但不能保存结果修正。

### 7.4 令过程失败 `FAIL_PROCESS`

明细包含 `processKey` 和固定 `failureReason`：

| `failureReason` | 中文含义 |
| --- | --- |
| `CONTROLLED` | 受到控制。 |
| `SOURCE_DIED` | 来源对象死亡。 |
| `TARGET_UNTARGETABLE` | 当前目标不可选取。 |
| `ACTIVE_CANCELLED` | 主动取消。 |
| `EVENT_ABORTED` | 当前事件终止。 |

失败动作不允许目标对象、动态输入绑定或结果修正。失败后仍由阶段 7.3 `PROCESS_FAILURE` 固定时点承接既有无条件失败效果挂接。

## 8. 动态输入来源绑定

### 8.1 公共规则

每个绑定包含 `bindingKey/parameterKey/sourceType/detail`：

```json
{
  "bindingKey": "damage_from_first_action",
  "parameterKey": "previous_damage",
  "sourceType": "PRIOR_ACTION_RESULT",
  "detail": {
    "sourceActionKey": "deal_first_damage",
    "sourceResultKey": "damage",
    "outputKind": "CONFIGURED_VALUE"
  }
}
```

1. `bindingKey` 在动作内唯一，创建后不可修改。
2. `parameterKey` 必须是当前技能 `RUNTIME_INPUT` 参数；同一动作内一个参数只能有一个绑定。
3. `EXECUTE_EFFECT` 和 `START_PROCESS` 的可达公式只按下方封闭收集表确定，不由实现按字段名称猜测或递归到未直接执行的其他规则。
4. 每个可达公式引用的 `RUNTIME_INPUT` 参数必须恰好有一个绑定；不允许绑定未被可达公式引用的参数。
5. 整数来源可以绑定 `INTEGER` 或 `DECIMAL` 参数；小数来源只能绑定 `DECIMAL` 参数。布尔来源固定以整数 `0/1` 提供，可以绑定两种参数。`PRIOR_ACTION_RESULT + CONFIGURED_VALUE` 在本阶段统一按小数来源处理，不根据公式节点猜测整数结果。
6. 执行效果动作建立的绑定随该次效果上下文保留，供其生命周期后续固定时点使用；本阶段只保存来源定义，不保存实际快照。

可达公式键的封闭收集表为：

| 动作 | 收集范围 |
| --- | --- |
| `EXECUTE_EFFECT` | 目标效果全部结果的 `valueRule.formulaKey`，以及生命周期的持续时间、最大层数、每次施加层数和周期间隔四个公式键。生命周期操作没有独立明细公式，需要数值时仍包含在结果 `valueRule` 中。 |
| `START_PROCESS` | 目标过程普通冷却、全部步骤明细和内部状态操作直接引用的公式；`RESET`、内部冷却 `START/RESET` 等操作实际读取的内部状态定义公式；阶段 7.3 直接效果挂接目标按上一行递归收集。只由后续触发规则执行、不是过程直接挂接的效果不纳入。 |

公式不能引用另一个公式，因此收集到公式键后只需读取其参数节点，不继续展开公式图。

### 8.2 技能内部状态 `INTERNAL_STATE`

明细使用第 6.4 节相同的 `stateKey/valueKind` 形状。`VALUE`、`OPTION_SELECTED` 和 `ENABLED` 是整数来源，其中后两者提供 `0/1`；`REMAINING_MS` 是小数来源。`OPTION_SELECTED` 还必须提供 `optionKey`。

### 8.3 战斗状态 `COMBAT_STATUS`

固定取值为 `PRESENT / STACKS / REMAINING_MS`：

1. `PRESENT` 只需 `subject/statusKey`，是提供 `0/1` 的整数来源。
2. `STACKS` 是整数来源，`REMAINING_MS` 是小数来源；两者必须再提供第 6.3 节相同的 `sourceEffectKey/sourceResultKey`，读取明确生命周期实例。

### 8.4 当前事件值 `EVENT_VALUE`

明细只包含 `eventValueKey`，必须属于当前规则事件白名单，并与目标参数类型兼容。

### 8.5 更早动作的基础结果值 `PRIOR_ACTION_RESULT`

明细包含 `sourceActionKey/sourceResultKey/outputKind`，本阶段 `outputKind` 只允许 `CONFIGURED_VALUE`。

1. 来源动作必须是同一规则中排序更早的 `EXECUTE_EFFECT`。
2. 来源结果必须属于来源动作目标效果，具有 `valueRule`，并且没有生命周期或位于 `APPLICATION`。
3. 来源结果的值类型必须与目标参数兼容。
4. 不允许引用同一动作、后续动作、持续生效、满层、周期、自然结束或提前移除结果。
5. 需要在同一效果内部使用前序结果时，MVP 阶段应拆成两个效果和两个有序动作，不增加效果内隐式依赖。

## 9. 固定结果修正

固定结果修正只从属于 `EXECUTE_EFFECT`，每项包含：

```json
{
  "resultKey": "damage",
  "fixedMultiplier": 1.5,
  "fixedMinValue": null,
  "fixedMaxValue": 500
}
```

规则：

1. `resultKey` 必须属于动作目标效果且结果具有 `valueRule`；同一动作内不得重复。
2. 三个修正字段至少一个非 null；倍率必须大于等于 0；最小值和最大值同时存在时最小值不得大于最大值。
3. 未来顺序固定为：阶段 7.2 基础公式与基础固定修正 → 本动作固定倍率 → 本动作固定最小值 → 本动作固定最大值。
4. 不保存修正公式或等级 Map。需要动态修正时，使用参数、公式和第 8 节来源绑定。
5. 条件控制整个动作，不单独控制某一个结果修正。需要“满足条件时修改、否则保持原值”时建立互斥规则，不在修正中增加条件字段。

## 10. 触发保护与循环检查

### 10.1 每目标冷却

```json
{
  "durationFormulaKey": "per_target_cooldown_ms",
  "targetContext": "CURRENT_TARGET"
}
```

公式必须属于当前技能、不得引用 `RUNTIME_INPUT` 参数，未来按正毫秒解释。`targetContext` 使用第 7.1 节相同语义；事件不提供事件来源对象时不能选择 `EVENT_SOURCE`。

### 10.2 单次过程最大触发次数

```json
{
  "processKey": "focus_attack",
  "limitFormulaKey": "one_trigger"
}
```

过程和公式必须属于当前技能，公式不得引用 `RUNTIME_INPUT` 参数，未来公式结果按正整数解释。该保护只允许用于 `PROCESS_MOMENT` 规则，并且 `processKey` 必须等于事件来源过程；它在条件和动作之前限制该规则在这一次明确过程实例中的匹配次数。其他事件没有必然过程上下文，不能用一个无关过程键伪装循环保护。本阶段不建立运行实例或计数记录。

### 10.3 无保护循环拒绝

循环图的节点固定为当前技能的 `RULE:{ruleKey}`。若规则 A 的任一动作按下表可能产生规则 B 的事件来源，则增加一条 `A -> B` 边，并记录 `sourceRuleKey/actionKey/producedEvent/targetRuleKey`：

| 动作 | 封闭的可能事件生产规则 |
| --- | --- |
| `EXECUTE_EFFECT` | 无生命周期效果的每个结果产生精确 `RESULT_AVAILABLE(effectKey,resultKey)`；有生命周期效果产生 `LIFECYCLE_MOMENT(effectKey,APPLICATION)`，可能施加至满层时同时可能产生 `FULL_STACKS`，有周期时可能产生 `PERIODIC`，有自然到期时可能产生 `NATURAL_END`。 |
| `EXECUTE_EFFECT` 的伤害结果 | `target=TARGET` 可能产生 `DAMAGE_DEALT`、`HEALTH_THRESHOLD_CROSSED(CURRENT_TARGET,DOWNWARD)`、`KILL`、`ENTITY_DIED(CURRENT_TARGET)`；`target=SOURCE` 可能产生 `DAMAGE_TAKEN`、`HEALTH_THRESHOLD_CROSSED(SOURCE,DOWNWARD)`、`ENTITY_DIED(SOURCE)`。 |
| `EXECUTE_EFFECT` 的直接治疗或属性变化结果 | 直接治疗按结果目标可能产生相同 subject 的 `HEALTH_THRESHOLD_CROSSED(...,UPWARD)`；属性变化只在 `attributeKey` 与阈值事件相同且 subject 与结果目标一致时匹配，`INCREASE` 只向上、`DECREASE` 只向下、`SET` 两个方向都可能。普通护盾、资源和冷却变化不产生生命阈值事件。 |
| `EXECUTE_EFFECT` 的状态操作或持续状态结果 | 按相同 `statusKey` 和 `APPLY/REMOVE` 产生 `STATUS_CHANGED`；持续状态自然或提前结束还可能产生对应 `REMOVE`。 |
| `EXECUTE_EFFECT` 的生命周期操作结果 | `INCREASE/SET` 可能令目标效果产生 `FULL_STACKS`；`DECREASE/SET/CONSUME/REMOVE` 可能令目标效果产生 `EARLY_REMOVE`；`REFRESH` 不产生生命周期时点。 |
| `START_PROCESS` | 产生目标过程全部合法 `PROCESS_MOMENT`；阶段 7.3 直接效果挂接按上面的执行效果行递归展开；数值、模式和准备标记操作分别可能产生 `VALUE_CHANGED/OPTION_SELECTED/FLAG_CHANGED`。内部冷却 `RESET` 在原先不可用时可能产生 `COOLDOWN_READY`，`START` 只进入冷却，绝不产生就绪事件。自然计时到期不由本阶段三种动作直接生产，因此不建立规则入边。 |
| `FAIL_PROCESS` | 只产生目标过程的 `PROCESS_MOMENT + PROCESS_FAILURE`。 |

匹配规则固定为：精确过程、结果、生命周期和内部状态事件必须键一致；状态事件还必须 `statusKey/change` 一致；生命阈值必须 subject、direction 一致，属性变化还必须属性键一致，伤害和直接治疗因现有数据没有生命值属性分类而只忽略属性键；`ENTITY_DIED` 必须 subject 一致；其余宽事件按同一 `eventType` 匹配。`SKILL_USED`、普通攻击、`SKILL_HIT`、`CONTROL_RECEIVED`、`ENTITY_UNTARGETABLE` 和 `PROCESS_CANCEL_REQUESTED` 不由本阶段三种动作生产，不建立入边。

保护和拒绝规则：

1. 每目标冷却或合法的单次过程最大触发次数都在目标规则 B 的条件与动作之前限制整条规则，因此所有进入 B 的边是有保护边。
2. 临时移除全部进入有保护规则的边，对剩余规则图执行有向环检查；存在自环或多规则环时返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED`。
3. 错误详情返回一条确定循环路径中的 `ruleKey/actionKey/producedEvent`，相同图按 `ruleKey/actionKey/eventType` 排序，保证测试结果稳定。
4. 创建、更新或删除规则，以及修改被规则引用的效果、结果、生命周期、过程、步骤或内部状态形状时，都用候选快照重新检查整张当前技能规则图。
5. 每目标冷却只证明相同动作目标上的即时反馈受到正毫秒窗口限制；本阶段没有多目标传播。单次过程保护只证明明确过程实例内次数有限。图检查不证明跨时间业务一定终止，也不执行事件。

## 11. 聚合、引用与修改规则

1. POST 和 PUT 在一个事务中维护规则、事件明细、条件组、条件、动作、绑定、结果修正和两类保护；任一失败时不得留下部分记录。
2. PUT 中的子项数组是当前规则全集。保留相同稳定标识的子项，新增新标识，删除请求中缺少的旧标识。
3. 删除或重排动作后，所有前序结果绑定仍必须指向更早动作；否则整次 PUT 失败并保持旧聚合。
4. 删除规则直接引用的效果，删除它被引用的结果，移除它被引用的生命周期，或修改被引用结果/生命周期时点使规则失效，都返回 `409.SKILL_EFFECT_IN_USE`；被引用的过程或步骤返回 `409.SKILL_PROCESS_IN_USE`；内部状态和模式选项沿用阶段 7.3 冲突错误。
5. 被事件、条件或绑定引用的状态返回 `409.STATUS_IN_USE`；被规则引用的公式返回 `409.SKILL_FORMULA_IN_USE`；被绑定的参数返回 `409.SKILL_PARAMETER_IN_USE`。
6. 阶段 7.4 生命周期操作单独引用目标效果时仍返回 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`。同一次效果修改同时受到阶段 7.3 过程挂接或阶段 7.5 触发规则引用时，优先返回 `409.SKILL_EFFECT_IN_USE`；只有不存在这两类引用时才返回生命周期专属错误。不得依赖数据库外键异常转成 500。
7. 效果、过程或内部状态形状更新虽然没有删除稳定标识，但若候选形状会新建无保护规则环，仍返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED`；引用仍存在但形状被破坏才使用 409，不把循环错误改成冲突错误。
8. 删除当前技能时先删除自身触发规则，再按“过程 → 效果与结果 → 内部状态 → 公式 → 参数 → 技能”清理。其他技能的 `sourceSkillKey` 引用仍使用 `409.SKILL_IN_USE` 阻止删除。
9. 删除规则只删除自己的聚合，不删除任何被引用对象。
10. 停用状态、属性或其他技能不破坏已有回读；新增或修改为新的停用引用时返回对应引用停用错误。

## 12. HTTP 契约

所有接口沿用现有 Admin Token、统一成功响应、统一错误外壳和路径编码规则：

```text
GET    /api/admin/games/{gameId}/skills/{skillKey}/trigger-rules
GET    /api/admin/games/{gameId}/skills/{skillKey}/trigger-rules/{ruleKey}
POST   /api/admin/games/{gameId}/skills/{skillKey}/trigger-rules
PUT    /api/admin/games/{gameId}/skills/{skillKey}/trigger-rules/{ruleKey}
DELETE /api/admin/games/{gameId}/skills/{skillKey}/trigger-rules/{ruleKey}
```

1. 所有接口先验证游戏，再验证技能；父级不存在不得以空列表掩盖。
2. POST 提交 `ruleKey/name/description/sortOrder/eventSource/conditionGroups/actions/perTargetCooldown/maxTriggersPerProcess`，成功返回 201 和完整详情。
3. PUT 不提交 `ruleKey`，其余字段全量提交，成功返回 200 和完整详情。
4. DELETE 成功返回 204；不存在返回稳定 404。
5. 不提供事件、条件、动作、绑定、修正、排序或保护的独立子资源接口。

## 13. 稳定错误

沿用 `details.fieldIssues`，新增或复用：

| HTTP | `code` | 场景 |
| ---: | --- | --- |
| 400 | `400.INVALID_BODY` | 固定联合类型或枚举无法绑定，或携带不属于当前种类的字段。 |
| 400 | `400.VALIDATION_FAILED` | 基本字段、空动作、空条件组、重复标识、不可修改种类、动作顺序或修正范围错误。 |
| 400 | `400.INVALID_SKILL_TRIGGER_RULE_REFERENCE` | 规则引用不存在、跨游戏、跨技能、类型不匹配或当前事件不提供的对象和值。 |
| 400 | `400.INVALID_RUNTIME_INPUT_BINDING` | 参数不是计算时传入、缺少或多余绑定、来源不可用、值类型不兼容，或前序动作顺序不合法。 |
| 400 | `400.TRIGGER_RULE_CYCLE_UNGUARDED` | 当前技能规则图存在不经过任何保护边的有向环。 |
| 404 | `404.GAME_NOT_FOUND` | 游戏不存在。 |
| 404 | `404.SKILL_NOT_FOUND` | 父级技能不存在。 |
| 404 | `404.SKILL_TRIGGER_RULE_NOT_FOUND` | 触发规则不存在。 |
| 409 | `409.SKILL_TRIGGER_RULE_KEY_EXISTS` | 同一技能规则标识重复。 |
| 409 | `409.SKILL_EFFECT_IN_USE` | 删除或破坏仍被规则引用的效果或结果。 |
| 409 | `409.SKILL_EFFECT_LIFECYCLE_IN_USE` | 没有过程挂接和触发规则冲突，但阶段 7.4 生命周期操作仍阻止删除效果或移除/改变目标生命周期。 |
| 409 | `409.SKILL_PROCESS_IN_USE` | 删除或破坏仍被规则引用的过程或步骤。 |
| 409 | `409.SKILL_INTERNAL_STATE_IN_USE` | 删除仍被规则引用的内部状态。 |
| 409 | `409.SKILL_INTERNAL_STATE_OPTION_IN_USE` | 移除仍被规则引用的模式选项。 |
| 409 | `409.SKILL_FORMULA_IN_USE` | 删除仍被规则引用的公式。 |
| 409 | `409.SKILL_PARAMETER_IN_USE` | 删除仍被来源绑定引用的参数。 |
| 409 | `409.STATUS_IN_USE` | 删除仍被规则引用的状态。 |
| 409 | `409.SKILL_IN_USE` | 删除仍被其他技能事件筛选引用的技能。 |

字段路径必须使用实际提交下标，例如 `eventSource.detail.effectKey`、`conditionGroups[0].conditions[1].detail.statusKey`、`actions[1].runtimeInputBindings[0].detail.sourceActionKey`、`actions[0].resultModifiers[0].resultKey`。

无效引用原因至少区分：`UNKNOWN_SKILL`、`UNKNOWN_PROCESS`、`UNKNOWN_STEP`、`UNKNOWN_EFFECT`、`UNKNOWN_RESULT`、`UNKNOWN_LIFECYCLE`、`UNKNOWN_STATUS`、`UNKNOWN_ATTRIBUTE`、`UNKNOWN_INTERNAL_STATE`、`UNKNOWN_MODE_OPTION`、`UNKNOWN_FORMULA`、`UNKNOWN_PARAMETER`、`EVENT_VALUE_NOT_AVAILABLE`、`EVENT_SOURCE_NOT_AVAILABLE`、`RESULT_NOT_IMMEDIATELY_AVAILABLE` 和 `REFERENCE_TYPE_MISMATCH`。

效果聚合因触发规则引用而发生 409 时，字段和原因固定为：

1. 删除整个效果：字段 `effectKey`，原因 `TRIGGER_RULE_EFFECT_IN_USE`。
2. 从 PUT 结果全集移除被引用结果：字段 `results`，原因 `TRIGGER_RULE_RESULT_IN_USE`，拒绝值携带被移除的 `resultKey`；不能使用请求中并不存在的数组下标。
3. 把被引用生命周期改为 null：字段 `lifecycle`，原因 `TRIGGER_RULE_LIFECYCLE_IN_USE`。
4. 改变被引用结果时点或生命周期形状：定位实际字段，如 `results[i].lifecycleBehavior.moment` 或 `lifecycle.periodicIntervalFormulaKey`，原因 `TRIGGER_RULE_SHAPE_IN_USE`。

若同一次请求同时存在多种引用冲突，优先级固定为：阶段 7.3 过程挂接或阶段 7.5 触发规则的 `409.SKILL_EFFECT_IN_USE` → 阶段 7.4 生命周期操作的 `409.SKILL_EFFECT_LIFECYCLE_IN_USE`。同一错误码内按字段路径排序返回全部可确定问题。

## 14. 页面外部行为

1. “技能管理”列表在现有操作中增加“条件与触发”，打开当前技能的触发规则管理弹窗，不新增主导航或独立路由。
2. 规则编辑按“基本信息 → 事件来源 → 条件组 → 有序动作 → 触发保护”从上到下维护。
3. 事件、条件、动作和来源根据固定种类显示中文字段；用户不填写 JSON、复合键或自由表达式。
4. 条件组明确显示“组之间满足任一组，组内必须全部满足”。
5. 动作列表显示确定顺序，前序结果选择器只展示更早执行效果动作中可用的数值结果。
6. 参数选择器只展示当前动作可达公式实际使用的 `RUNTIME_INPUT` 参数，并显示缺少、重复或多余绑定。
7. 页面可以用中文摘要展示引用关系，但不提供运行、计算预览、事件模拟、循环演示或图形化流程编辑。

## 16. 跨端验收案例

### 16.1 满层引爆并移除标记

1. `LIFECYCLE_MOMENT + focus_mark + FULL_STACKS`。
2. 第一动作执行引爆伤害效果。
3. 第二动作执行包含 `LIFECYCLE_OPERATION + REMOVE` 的独立移除效果。
4. 该动作链只会令标记产生提前移除，不会再次产生满层事件，因此封闭规则图本身无环，不要求虚构过程次数保护。

保存、修改和重启回读后，时点、动作顺序、效果引用和保护完整一致；标记效果没有自引用生命周期操作。

### 16.2 低生命值触发护盾

1. `HEALTH_THRESHOLD_CROSSED + SOURCE + hp + DOWNWARD`。
2. 阈值引用同技能公式。
3. 可选属性条件进一步限定生命比例。
4. 执行护盾效果并配置每目标冷却。

页面不执行生命值判断或护盾计算。

### 16.3 命中后追加结果

1. `SKILL_HIT` 筛选当前技能。
2. 可选检查目标存在指定标记。
3. 按顺序执行伤害效果和状态操作效果。

关系可以完整保存，阶段 7.3 原有过程效果挂接不被改写。

### 16.4 前序基础结果驱动后续公式

1. 第一动作执行具有即时数值结果的效果。
2. 第二动作执行另一个效果。
3. 第二动作把自身某个 `RUNTIME_INPUT` 参数绑定到第一动作结果的 `CONFIGURED_VALUE`。

把来源动作移到第二动作之后、改为周期结果或删除来源结果时，整次更新失败且旧规则保持不变。

### 16.5 强化下一次普通攻击

1. `BASIC_ATTACK_HIT` 作为事件。
2. 条件检查当前技能准备标记已启用。
3. 第一动作执行强化效果，第二动作启动或衔接消费该准备标记的过程。
4. 动态输入可绑定命中序号或内部计数。

页面不执行攻击、命中、状态消费或伤害。

### 16.6 过程失败原因

分别建立受到控制、来源死亡、目标不可选取和主动取消事件规则，最后一个动作令同一过程以对应固定原因失败。保存后失败动作必须保持最后，阶段 7.3 `PROCESS_FAILURE` 挂接保持不变。

### 16.7 无保护循环

1. 规则 A 的结果事件执行效果 B。
2. 规则 B 的结果事件执行效果 A。
3. 两条规则都没有每目标冷却或单次过程最大触发次数。

第二条关系保存返回 `400.TRIGGER_RULE_CYCLE_UNGUARDED`。为任一参与规则增加每目标冷却后可以保存；结果事件不是 `PROCESS_MOMENT`，不能用无关过程次数伪装保护。系统仍不执行循环。

### 16.8 内部冷却就绪后启动过程

1. 事件为指定内部冷却的 `INTERNAL_STATE_CHANGED + COOLDOWN_READY`。
2. 动作为启动一个过程，该过程内部对同一内部冷却执行 `START`。
3. `START` 只令状态进入不可用，不生产新的就绪事件。

封闭规则图没有自环，不要求增加每目标冷却。若过程改为对仍未就绪的内部冷却执行 `RESET`，才按可能产生就绪事件参与循环检查。

3. 实施需要把条件、事件、动作、绑定或关系保存成 JSONB、数组、自由脚本或通用多态关联。
4. 实施需要建立事件类型、条件类型、动作类型或游戏级计算变量管理页。
5. 实施需要执行事件、条件、动作、公式、计时、触发次数、过程、生命周期、状态、伤害、预览、发布或 Wasm。

8. 目标数据库、Backend 或 Web 的阶段 7.2～7.4 实际契约与本方案基线不一致，无法用受控破坏式迁移和明确写入范围收敛。
