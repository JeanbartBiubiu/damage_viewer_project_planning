# 执行协调层职责边界与验收约束

准入、命中、监听和运行求值已经从执行根包抽出。本文保留拆包后需要共同维护的所有权、依赖、读值时点和验收约束；完整方法、实现步骤与测试入口从[执行功能说明](../../../wasm/tinygo_engine_v2/internal/runtime/execution/README.md)和具体类型的能力声明进入。已落实的施工清单由源码、测试及Git历史承接。

本次验证结果见[拆包验收](../../测试记录/项目/执行协调层拆包验收-2026-11-01.md)。整体职责以[子系统现状](../../概要设计/项目/Wasm子系统职责与协作现状及调整方向.md)为准；[接口草案](../../概要设计/项目/Wasm子系统接口设计草案.md)中的有限排程与调度决策仍是独立待讨论内容。

## 职责和状态所有权

下表源码路径相对 `wasm/tinygo_engine_v2/`。

| 所有者 | 负责的内容 | 交接边界 |
| --- | --- | --- |
| 根 `internal/runtime/execution/` | 运行装配、实际身份、读取准备、操作执行、事件次序、帧暂存和统一提交 | 为子包准备明确输入，组合判断和计算结果 |
| `execution/admission/` | 初始选择、来源结构、周期与目标范围、初始化及动态恢复等准入校验 | 无长期运行账，不安装效果或计算后续事件的固定金额 |
| `execution/hit/` | 命中索引、接触历史、同刻分组、命中序号与技能范围判盾账 | 返回命中判断和独立范围值，不执行候选或移除护盾 |
| `execution/listener/` | 动态监听列表、类型及拥有者匹配、施放节流 | 提供选择依据，实际条件冻结、资格复查和执行由父层组合 |
| `execution/evaluation/` | 属性派生、依赖探测、单场缓存与作者防御求值 | 接收选定时点的只读输入，返回数值、条件或新属性表 |
| `runtime/action/` | 实际使用身份、过程、占用、冷却、弹药和等待 | 使用身份、只读视图及所属变更对象 |
| `runtime/effect/` | 效果、状态、护盾、修正及其恢复和快照转换 | 只读视图、所属变更对象或独立快照 |
| `runtime/report/` | 可靠累计、有界记录和已有快照的结果投影 | 消费已提交事实，不决定事件或记录的发生时点 |
| `internal/scheduler/` | 唯一时钟、队列、事件计数与停止账 | 根入口创建同一循环，执行层借用；功能包只取得明确模拟时点 |

四个执行子包彼此不导入，也不导入父执行包、根运行包或调度器。角色、行动、效果、报告和数值管道不反向取得这些执行子包的能力。运行求值可以使用效果只读解析器与数值管道，准入可以使用已有公式和数值校验。

依赖检查按具体包路径声明，不允许以整个执行目录的通配白名单替代。父层不把完整 `Engine`（单场执行器）、`Frame`（暂存及提交单元）或拥有全部能力的大接口传入子包。主要对象继续使用具体类型；纯输入、结果和函数不建立空服务接口。

每场运行新建命中账、监听账和属性缓存。实际使用身份继续由行动包持有，命中历史不携带弹药或开始状态捕获对象。技能范围判盾只保留范围及盾身份，避免复制整个执行冻结上下文。

## 共同额度、命中和监听顺序

同次使用额度只由父层 `use_trigger.go` 持有，命中规则组和普通监听共享一套预留、提交和失败释放。施放节流、同次使用额度与伤害修正消费分别保持原有含义。

父层保留真实命中的执行顺序：普攻受击通知、原序命中候选或规则组、事件当前属性和资源刷新、普通监听、法盾阻挡监听、强化尾部。命中包与监听包通过明确事实交接，不互相触发执行。

规则组继续共用一帧和一份额度预留；每个候选开始前清空它可读的操作输出，逐候选生成原伤害事实。命中序号和合格接触仍在原尝试时点记录，不统一改为帧成功后登记。

监听派发先冻结动态列表，再在任何监听操作前按原序冻结条件；执行每一项前仍复核实际挂载及匹配资格。动态卸载不会改写本次已冻结的列表，但已失效的来源不能继续执行。节流及额度只在原成功边界记账。

## 准入、读取与缓存

准入同时保留原始初始快照和物化后的实际数值视图，原始作者选择与生命上限分别核对。初始化和当前生命同步保持原顺序，不以提前同步掩盖半血或最大生命错误。

动态治疗等准入只核对当前拥有者的合法输入，实际事件仍重新求金额。准入结果不携带可跨事件复用的初始金额；检查和错误保留原有短路顺序、字段路径、能力及会话身份。

| 读取用途 | 保留的时点 |
| --- | --- |
| 普通金额与操作条件 | 当前帧暂存投影 |
| 作者防御公式 | 当前伤害帧的入口视图 |
| 复制伤害防御 | 原伤害保留的冻结防御双方 |
| 事件入口 | 产生事件的原帧入口，而非监听子帧入口 |
| 事件属性和资源 | 事件冻结值，仅在现有指定位置刷新 |
| 过程开始与实际成本 | 已获准的真实过程事实及其可读时点 |

父层先完成动态效果同步、惰性到期和视图准备，再调用运行求值。读取准备不是纯查询，不能为了抽函数而删除或提前。

属性缓存继续核对实际拥有者、双方方向、严格读取、字段存在性、修正挂载及供值状态。整轮跳过只在已有可证明的正向双方路径同时核对输入与输出后使用；原两遍重算仍由父层决定。活视图只在约定的同步调用内借用，历史事实独立冻结，写句柄不跨发布使用。

## 帧提交和输出

根执行层按现有位置处理动态效果投影、护盾生命周期准备、预检、所属状态发布、生命周期操作、过程与强化事实、死亡冻结、队列发布、帧事实及后续死亡处理。局部发布后失败保留真实已发生事实，不引入全链回滚。

时钟、同刻选择、处理后立即状态核对、停止优先级、旧事件失效和各类预算沿既有循环。明细关闭或截断不改变命中、额度、可靠累计或最终状态。

效果恢复与导出保留嵌套状态的独立所有权、缺失与有效0、空护盾形态以及状态贡献顺序。报告只接收已拥有的快照及明确时点，记录何时发生仍由父层决定。

## 验证约束

命令与工具链唯一入口见[引擎说明](../../../wasm/tinygo_engine_v2/README.md)、[固定机制说明](../../../web/tests/mechanisms/README.md)和[开发与独立评审流程](../../项目说明/开发与独立评审流程说明.md)。

- 算法和私有状态测试随所有者迁移；跨所有者组合通过模块 `tests/runtime/` 的真实根入口验证，不公开可写测试钩子或复制循环。
- 包依赖检查同时覆盖合法方向和父子反向、四包互相控制、状态子系统反向取得执行能力的失败例。能力声明与公开方法、中文说明和类型排列同步。
- 运行重构收尾完成全量Go、原生基准、正式Wasm构建及编译／运行／释放冒烟；固定机制经生产适配和真实分发产物验证。代表浏览器流程覆盖连续普攻、有限过程及混合自动连招。
- 结构移动先比较语法树，再比较拆分前后的完整实际结果；数值、逐笔顺序、来源、停止原因及末态共同核对，不能只比较总伤害。
- 新增逐事件查找、缓存或分配必须有正式Wasm剖析或真实分配证据。诊断产物分别对应基线与候选实际源码，只允许诊断插桩差异，并在相同冻结输入、模式和采样下与各自正式产物逐字节比较结果。
- 性能使用至少三轮交替运行，每轮预热10次、采集200次。每场景以各轮往返耗时中位数的中位数比较，退化超过5%须补查并复测，持续超限不合入；往返包含运输和出口清理，不能声明纯引擎收益。新增逐事件分配或属性页复制须消除或由主负责人依据测量重新决策。

公开编译／运行／释放协议、准入范围、数值和错误、付款与预算、身份及同刻顺序保持。发现必须改变这些语义时，先与结构重构分开，由主负责人重新收敛范围。更具体的函数组织和施工细节以源码、测试与Git历史为准。
