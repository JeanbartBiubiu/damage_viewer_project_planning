# WASM 伤害模拟引擎概要设计（数据流转）

## 1. 目标与边界

### 1.1 目标
- 设计一条可复用的数据流，使同一套前端与 WASM 能适配多款“角色-技能-装备”游戏。
- WASM 保持固定输入/输出协议，业务场景（斩杀线、最大伤害、装备对比）由前端编排。
- 保障可复现：同一 `gameId + versionId + dataHash + input + seed` 输出一致。

### 1.2 非目标
- 不做实时战斗引擎（不做帧同步、渲染驱动、输入响应系统）。
- 不在首期实现技能偷取/附身、多单位召唤、超复杂多形态武器系统。

## 2. 角色与职责

- 后端（`game_manage`）：
  - 提供版本、全量数据包、字典和缓存协商（`ETag/If-None-Match`）。
  - 维护数据语义正确性，不参与模拟过程。
- 前端（编排层）：
  - 拉取并缓存数据包，组装固定 `EngineBundleV1` 与 `EngineRunInput`。
  - 根据场景策略多次调用 `run`，消费 `tick/done/error`。
- WASM 引擎（执行层）：
  - 接收固定协议，执行事件推进与伤害结算。
  - 输出采样点与结果摘要，不理解“业务场景名”。

## 3. 核心数据对象（单向流）

1. 后端标准包：`GameDataBundleV1`
2. 前端组装包：`EngineBundleV1`
3. 单次运行输入：`EngineRunInput`
4. 单次运行输出：`EngineTickMessage[] + EngineDoneMessage`

约束：
- 后端数据是事实来源，WASM 不直接请求后端。
- 前端可做轻量裁剪，但不得破坏 `mechanicsConfig` 语义。
- `hpAttrKey`、`ownerType`、属性 key 全部数据驱动，不硬编码游戏常量。

## 4. 端到端主流程（Control Plane + Compute Plane）

### 4.1 Control Plane（版本与初始化）
1. 前端调用 `GET /api/games/{gameId}/versions/current`，拿到 `versionId/dataHash`。
2. 前端调用 `GET /api/games/{gameId}/versions/{versionId}/bundle`（带 `If-None-Match`）。
3. 命中 `304` 则复用本地缓存，未命中则刷新缓存。
4. 前端把 `GameDataBundleV1` 组装成 `EngineBundleV1`，发送 `init` 给 worker/WASM。
5. 收到 `ready` 后进入可运行状态。

### 4.2 Compute Plane（单次模拟）
1. 前端生成 `runId` 与 `EngineRunInput`，发送 `run`。
2. WASM 推进事件队列并按采样节奏回传 `tick`。
3. 达到停止条件（`enemyDead/selfDead/maxSeconds/cancelled/error`）回传 `done`。
4. 前端将 `samples/result` 入视图层（图表、对比卡片、导出）。

## 5. 场景编排模式（前端策略层）

### 5.1 斩杀线（二分）
- 固定角色、装备、`seed`、`maxSeconds`。
- 仅调整 `overrides.enemy.baseStats[hpAttrKey]`。
- 以 `stopReason == enemyDead` 作为二分判定条件。

### 5.2 最大伤害值（枚举/搜索）
- 固定其余条件，枚举 `itemIds` 或参数组合。
- 每个组合触发一次 `run`，比较 `cumulativeDamageToEnemy` 或 `timeToKillEnemyMs`。

### 5.3 装备/属性敏感性对比
- 只变更 `addItemIds/removeItemIds` 或 `baseStats` 某一维度。
- 其余输入保持一致，确保结果可解释。

## 6. 运行状态机（前端视角）

`UNINITIALIZED -> INITIALIZING -> READY -> RUNNING -> DONE`

补充状态：
- `RUNNING -> CANCELLING -> DONE(cancelled)`
- 任意状态可进入 `ERROR`（需可恢复到 `READY` 或重新 `INIT`）

## 7. 一致性与可追溯

### 7.1 一致性键
- 推荐记录 `SimKey = gameId/versionId/dataHash/runId/seed`。
- 所有图表与结果缓存必须绑定 `dataHash`，避免版本串数据。

### 7.2 可复现
- 随机模式必须固定 `seed`。
- 前端对同一输入重复运行，结果应与基线一致（容许浮点误差阈值）。

## 8. 错误与降级策略

- `INVALID_INPUT`：前端输入校验失败，阻止运行并提示可修复字段。
- `SEMANTIC_ERROR`：数据包语义问题（引用缺失、表达式非法），标记版本不可用。
- `RUNTIME_ERROR`：执行时异常，保留上下文并允许用户重试或降级到简化模式。

## 9. 观测与运维最小集

- 关键日志字段：`gameId/versionId/dataHash/runId/seed/stopReason/durationMs`。
- 指标建议：
  - 初始化耗时（bundle parse/init）
  - 单次 run 耗时
  - tick 数量与平均间隔
  - 错误率（按错误码分类）

## 10. 首版落地切片（概要）

1. 打通 Control Plane：版本检查、bundle 缓存、`init/ready`。
2. 打通 Compute Plane：`run/tick/done/cancel`。
3. 实现两类场景编排：斩杀线（二分）+ 最大伤害（枚举）。
4. 建立最小回归：固定 `bundle + input + seed` 的结果快照对比。
