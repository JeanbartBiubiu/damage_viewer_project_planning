# 执行协调约束

继承上层运行规则。根包拥有运行装配、原时点读取准备、预算身份、跨功能固定次序、真实帧及统一提交。功能算法和私有局部状态按本目录 README 进入六个执行所有者及三个支撑包，不能把业务留在根层适配方法中。

- `Engine` 与根 `Frame` 的字段保持私有；功能局部帧、候选、监听、续接和额度记录也由各自所有者私有持有。角色数值、行动、效果、报告状态继续使用所属包的真实状态与变更对象。
- 只借用根入口提供的同一个 `scheduler.Loop`，不再创建时钟、事件堆或独立停止账。
- 统一提交保留现有预检、发布、生命周期、唤醒、事实与报告顺序；不要把旧有部分成功边界改成整体回滚。
- 过程与效果只读查询使用视图，暂存写入使用所属包的变更对象，不为跨包调用恢复可写集合。
- `actionflow`、`lifecycle`、`operation`、`hit`、`listener`、`continuation` 六个执行所有者不互相导入，也不导入父包、根运行包或调度器。`operation/lifecycle` 可使用 `evaluation`，`hit/listener/continuation` 可借用 `usage`；其余合法依赖由边界脚本逐项维护。
- 根层每场组合唯一 `usage.Ledger`，额度算法与记录归 `usage`。命中规则组与监听传递真实预留凭据，保留原提交和失败释放位置，不建立第二份账。
- 同帧专用操作只在当前真实帧借用所属变更对象，不创建子帧、提交或立即派发。`resolve_skill_hit` 只准备事实；跨命中、普通监听、阻挡监听与强化的顺序只有根层一份。
- 同步子能力执行使用消费方声明的有限阶段能力。返回后按原规则复查真实资格；每次调用使用独立恢复凭据，不保存单个“当前帧”，不新增逐事件适配对象、闭包或大快照。
- 通用事件快照只带有限身份、数值和命中事实；完整候选计划及强化等待上下文归 `hit`，不能塞进共同契约或复制续接快照。
- 单测与实现同包；`wiring_test.go` 只为私有不变量测试组合真实入口。系统组合回归通过 `tests/runtime/` 的根会话执行。

修改执行路径按模块规则运行全量 Go、原生基准、正式 Wasm 及生产适配机制回归。
