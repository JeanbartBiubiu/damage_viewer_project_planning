# 执行协调与功能入口

本目录组合一次运行，使用根入口创建的唯一循环。六个执行所有者负责实际业务流程及私有局部事实，三个支撑包分别负责准入、运行求值和共同额度。根层准备原时点读值、组合有限同步阶段并保留真实帧的预检与发布边界。

| 要修改的功能 | 入口 | 负责的边界 |
| --- | --- | --- |
| 运行前的来源、初始快照和机制准入 | `admission/` | 完整来源/初始化监听、装备生命及目标标记初态判定，借用实际选中来源和原始初态，不执行战斗 |
| 普攻、技能行动、过程与共同等待 | `actionflow/` | 实际接纳、普通费用/冷却、完整过程阶段、占用、弹药及恢复资格，使用真实行动状态 |
| 效果应用、状态期限、护盾与周期 | `lifecycle/` | 完整实例应用/复用/刷新/移除、到期、关联盾及续时、所属批次发布与预检；预演不发布 |
| 数值操作及作者事件 | `operation/` | 完整数值重算、缓存使用、初始数值阶段及规则修正；执行条件与伤害／治疗／吸血／资源／斩杀，持有逐伤及输出事实 |
| 命中事实、候选、主体替换与强化 | `hit/` | 完整尝试、首接触/历史及规则组接纳，执行阻挡、候选与强化，私有持有命中上下文和局部强化暂存 |
| 动态监听与完整派发 | `listener/` | 冻结列表及条件、逐项复查活资格、执行遍历、成功节流和实际额度处理 |
| 复制与续接 | `continuation/` | 完整复制事实准入/冻结/预算，私有持有收集、重复请求、延迟载荷和同步因果，执行稳定排序与复制遍历 |
| 属性派生、缓存和作者防御求值 | `evaluation/` | 准备完成的视图到计算结果，不发布状态 |
| 同次使用额度 | `usage/` | 唯一 `Ledger` 拥有身份校验、真实预留凭据、提交及失败释放 |
| 运行装配与跨功能提交 | 根目录22个组合文件 | 原时点读取、预算身份、有限同步交接、真实帧预检与统一发布 |

根目录按以下22个组合文件阅读。表中“接线”不接收所属功能的完整业务流程或第二份局部状态。

监听操作及目标标记初态规则已归准入包，效果变更预演归生命周期包，斩杀、伤害、暴击及冻结事件字段的纯转换归相邻 `report/`（报告包）。根层保留事实读取、归属覆盖、可靠累计及记录额度的原时点，不向报告传递真实帧或活动行动视图。

| 功能 | 文件入口 |
| --- | --- |
| 单场装配、循环和初始化 | `engine.go`、`initialization.go` |
| 根帧及原时点读值准备 | `frame.go`、`reads.go` |
| 同帧数值与专用操作交接 | `operations.go` |
| 统一预检、发布及跨功能事件顺序 | `commit.go`、`publish.go`、`events.go` |
| 技能行动、过程与普攻接线 | `actions.go`、`processes.go`、`passive_processes.go`、`attacks.go` |
| 效果、状态与计时接线 | `effects.go`、`effect_state.go`、`effect_timing.go` |
| 命中、强化与监听接线 | `hit.go`、`empowered.go`、`listeners.go` |
| 复制续接与唯一共同额度接线 | `continuation.go`、`usage.go`、`cumulative_refund.go` |
| 可靠累计、记录和最终结果汇集 | `reporting.go` |

角色数值、行动和效果的私有状态继续由相邻的 `actor/`、`action/`、`effect/` 持有，恢复及快照转换也由效果包负责。报告包消费已提交事实和已拥有的快照，数值管道只计算，不决定事件顺序。

行动已封装过程初始化、完整时点、重施两帧与蓄力释放规则；根桥接不解释步骤进入、终结或最大重施次数。普通施放、周期和非分阶段锚定帧共用行动的费用/冷却政策，各自原帧、统计与尾部保持。行动结果来自本次真实帧的发布回执，错误可与已接纳事实并存；监听消费该结果，按原入口优先级准备、按原错误和成功边界派发。详细职责及失败语义见[行动与过程](../../../../../文档记录/概要设计/项目/Wasm子系统控制反转规划.md#d-action)。

效果已封装过期复用、刷新与移除政策、关联盾操作、到期资格及所属批次发布/预检。根只交出真实效果状态头、原上下文及有限同步工作，保留全部拥有者先发布、原数值/行动/监听交接和统一提交。新建与刷新各自的排程先后、普通与关联盾清扫、延后错误及已发布前缀均沿原规则；逐盾期限由效果在预检与发布两个时点分别核对。边界见[效果生命周期](../../../../../文档记录/概要设计/项目/Wasm子系统控制反转规划.md#d-effect)。

数值完整过程位于`operation/attributes.go`，规则修正落点位于`operation/rule_modifiers.go`。根在原时点交付所属变更及效果读准备，缓存仍是同一单场evaluation状态。两遍、效果变化单遍、全局依赖补算与初始三阶段分别保持；live写回重新读取真实角色，只替换数值。actor.Stage/Publish继续由统一提交按原跨所属顺序调用，完整职责不要求合并状态对象。

命中尝试和规则组接纳由hit完整消费，组不再伪装成监听取得额度。listener拥有负载、入口/实际引用及额度身份；continuation拥有资格、懒消费集合、冻结和追加后容量核验；lifecycle拥有冻结盾到严格移除命令的校验。根保留真实帧、原成功凭据提交及同步尾部，已提交事实不因后续失败回滚。旧预留包装及仅供根测试使用的叶入口已移除。

初始化的完整来源与监听准入位于admission/initial_sources.go，固定装备生命检查也归准入。根按原顺序调用，提供有限匹配、引用规范化、实际挂载和选中来源，准入只使用基础类型集合而不导入执行兄弟包。报告CompleteSampling一次交出序列和完整采样说明，根保留观察前效果准备、终结事实及最终DTO汇合。

六个执行所有者不互相导入，也不导入执行根包、根运行包或调度器。`operation/lifecycle` 可以使用 `evaluation`，`hit/listener/continuation` 可以借用根层组合的同一 `usage.Ledger`。其余合法依赖以包边界脚本为准，不建立通用执行器入口。

根层传递明确值、所属变更对象和有限同步能力，不传完整 `Engine` 或根 `Frame`。功能执行保留原帧及错误边界；同帧专用操作不自行创建子帧、提交或立即派发。独立子能力由根层在原位置创建真实帧并完整处理同步尾部，返回后由所属执行重新核对活资格。嵌套绑定分别持有恢复凭据，不用单个“当前帧”。

每场共同额度只有一份，额度算法及记录归 `usage`；命中规则与监听共享真实预留凭据。使用身份归 `action`，命中历史归 `hit`，发动前状态及弹药捕获归行动执行，复制收集和同步因果归 `continuation`，不能互相复制成第二份事实。

当前暂存、帧入口、事件入口和事件冻结值各有读取时点，复制伤害另用原冻结防御双方视图。共同事件只携带有限身份、数值和命中事实，完整计划、候选及强化等待上下文由 `hit.Context` 私有持有。

根层保留普攻受击通知→命中候选或规则组→事件当前属性和资源刷新→普通监听→法盾阻挡监听→强化尾部的固定次序。`resolve_skill_hit` 在原帧只准备事实。监听执行先冻结列表及全部条件，再逐项复查真实挂载；节流与额度仍在原成功边界记录。提交失败保留原有已发布事实，不隐含整条派生链回滚。

实现与私有不变量测试同包；跨所有者的组合回归位于模块 `tests/runtime/`。持续约束及分配、宿主成本的验证要求见[功能执行与组合设计](../../../../../文档记录/详细设计/项目/执行协调层功能执行与组合重构技术方案.md)，构建、正式产物核对和验证命令见[引擎说明](../../../README.md)。
