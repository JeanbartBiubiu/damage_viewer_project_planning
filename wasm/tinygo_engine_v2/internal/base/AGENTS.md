# 基础层协作规则

本文件适用于 `internal/base/**`。本目录只归集稳定基础能力，各叶目录保持独立 Go 包；本层不放 Go 实现，不新增模块。

## 写入边界

1. 普通英雄、技能、装备、监听器、过程或展示迭代默认不修改基础层。先在外层完成业务组合、输入绑定和状态管理，不加入对象专用分支或战斗执行状态。
2. 变更例外限于可复现的基础能力缺陷、明确要求的基础契约或数学原语变更，以及已有授权覆盖的基础性能优化。说明基础问题、外层组合为何不足、受影响契约及验证结果；保持行为的路径迁移单独标明。
3. 已确认的属性分页测量与必要优化仍在授权范围内，按实际复制页数和正式 Wasm 同口径对照决定，当前基线为每页8项；不因文档清理或目录变化再次请求相同授权。
4. 基础算法变化与业务功能变化分开差异及验收。不改旧固定期望来迁就新业务，不削弱快照、缺值或预算断言。
5. 共享模型相关结构、公式契约和生成器变化同样触发受影响基础测试，不能只按本目录是否改动决定验证范围。

## 依赖与验证

包能力、项目内依赖白名单及命令见同目录 [README.md](README.md)。禁止反向依赖运行时、编译器、执行计划、数值管道或战斗公式；`model` 仅作为既有协议数据依赖例外，不在其中加入反向业务依赖。

纯表达式的生成物由仓库公式生成器维护，不手改、不恢复旧目标或转发包。包依赖脚本检查生产代码实际导入；基础包测试独立验证行为，二者都不能代替正式 Wasm 或浏览器证据。
