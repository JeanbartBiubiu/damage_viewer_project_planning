# 后续双属性网格优化事项

2026-10-15收尾更新：单次纯计算1毫秒专项暂停，转回功能开发。性能工作等双属性网格功能时重启，目标为**1万个真实不同点在30秒内完成**；优先只返回击杀时长的结果、批量协议、计划与运行内存复用，以及减少每个点各做一次整堆回收。当前256MiB、出口回收、公开协议及业务语义保持，以下历史证据保留。

后续需求：两个属性各100个值，共100×100个不同点，在30秒内得到每点的击杀时长。单点详情另外计算，保留完整具体记录。1万个点是数量上限，单点战斗长度与持续效果密度还要单独界定。

待实施方向：

1. 编译时明确声明两个可变属性输入，批量复用同一编译计划；每点使用独立初始运行状态，保留未声明字段、装备挂载、资源及生命校验。
2. 增加时长专用结果，仅返回时长、击杀、停止和完成状态；跳过展示数据构造，同时完整执行战斗事实、执行预算与首次提交死亡时间捕获。
3. 使用有界线程池及分块传输，提供进度与取消，核对并发带来的内存容量和稳定性。
4. 先验收真实1万个变化点与较重场景，再按热点决定后续优化。可先显示稀疏预览并补算；击杀时长存在阈值跳变，插值不作为精确结果。

已有证据：本机14核、约32GiB内存，12线程同输入重复1万次计算28.194秒，线程池生命周期29.027秒，含新浏览器生命周期29.978秒。各线程只编译一次，错误和结果差异为0。但不同输入只有一个；正式快照校验拒绝实际属性变化，不能视为真实网格验收通过。8／12线程分别需要2／3GiB固定Wasm线性内存容量。

降低主动回收频率的独立实验，在连续混合详细输出时发生内存不足，未合入；不据此改变正式回收策略。
