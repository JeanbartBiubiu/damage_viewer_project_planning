# Web AGENTS.md

## 范围与入口

本文件适用于 `web/**`。先读同目录 `README.md`，再读目标路径更近的 `AGENTS.md`；技术入口、环境变量和命令以 README 与 `package.json` 为准，不在本文件重复。

默认只写 `web/**` 及本任务明确包含的前端文档或工具。`server/**`、`db/**`、`wasm/**` 和接口定义默认只读；跨模块契约变化返回主负责人统一处理。

## 当前边界

- 当前产品面是属性、角色、装备、构筑系统、技能分类、伤害类型、技能、状态、修正区域、图片和游戏配置管理页；导航真源为 `src/config/navigation.ts`，路由壳层为 `src/App.tsx`。
- API 基址统一经 `src/services/apiClient.ts` 解析，默认同源，开发代理见 README。账号使用浏览器安全凭据（Cookie），正式会话与受限流程分别校验防跨站请求伪造值（CSRF）；不在浏览器本地存储密码、绑定二维码、恢复码或凭据。
- 当前页面只使用现行业务与图片接口。已删除的 `/combat-data/**`、`versions/current`、旧发布、旧实体、Provider、Ability、Effect Sequence 和 Effect Step 页面不恢复兼容。
- Wasm 宿主使用 TinyGo V2 的 `engine_compile`、`engine_run`、`engine_release_session`。只改宿主桥接时不在前端隐式改变 ABI。

## 编码约束

- 业务输入、草稿和接口结果使用明确类型；外部未知值先以 `unknown` 接收并校验。不要用 `any`、强制断言或补空值掩盖缺失字段与契约错误。
- 展示组件负责呈现和交互，业务规则、请求适配及计算映射沿现有模块拥有；同一派生值从已有状态计算，避免再存一份并依赖副作用同步。
- 订阅、计时器和异步请求明确创建与清理边界；页面切换、输入变化或请求先后颠倒时，取消旧请求或核对身份，避免过期结果覆盖当前草稿。预期请求失败按现有错误模型处理，保留应保留的用户输入。
- 计算输入保留来源身份以及缺失与有效0的区别。前端不得补造默认数值、从截断明细反算可靠总额，或在展示层复制引擎的结算规则。

## 单元测试与组合验证

- 逻辑、服务与适配器单测使用 Vitest（前端单元测试框架）。新增文件遵循 `vitest.config.ts` 的发现规则，当前为 `src/**/*.test.ts`；脚本检查沿用 `package.json` 中的 Node 测试入口，不能假定任意测试后缀都会执行。
- 纯逻辑直接给输入并断言结果；客户端测试用受控请求替身核对路径、载荷、凭据、错误和取消信号。用例结束后恢复全局对象、模块状态、计时器和替身，异步断言必须等待完成。
- 组件交互、真实路由、浏览器存储及页面切换使用 Playwright（浏览器测试工具）验证；接口拦截用例只证明页面接线，真实服务验证另行取证。测试命令及既有配置查 README。
- 引擎适配回归使用 `tests/mechanisms/`，写法和数值期望以该目录 README 为准；普通服务单测不替代真实Wasm的编译、运行和释放。共用测试原则见[开发流程](../文档记录/项目说明/开发与独立评审流程说明.md)。
