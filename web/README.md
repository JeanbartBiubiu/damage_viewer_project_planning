# Damage Viewer Web

`web/` 是 Damage Viewer 的前端工作台。它提供“数据管理／计算模拟”两种模式，负责管理页面、图片缓存，以及 TinyGo V2 Wasm 的场景装配、编译验证、单次与连续普攻及只读图表。

它在整条链路里的位置是：

1. 读取后端游戏列表和当前管理接口。
2. 提供属性、角色、装备、构筑系统、技能分类、伤害类型、技能、状态、游戏配置和图片管理页。
3. 在浏览器侧处理上传图片，并缓存、同步公开图片资源。

## 技能共同公式接入

技能公式的 expression（表达式）只保存完整共同定义。管理页复用共同编辑核心，支持所属技能参数与来源／目标当前帧的启用属性输入、全部共同运算、自由具名结果及最终输出，十进制字符串和展示顺序保持原样。统一保存按最终候选参数集合校验，同次新增参数可直接引用；未使用输入仍参与授权和删除保护。独立公式写入后再读取同对象核对，响应不明或读回失败保留冻结草稿，只提供重新读取确认。

宿主深复制共同定义和每份程序的私有参数目录，只选择固定值或明确技能／角色等级的原目录值；计算时输入不补零。参数绑定保持作者技能身份，实际蓄力与已提交成本只在已有允许动作供值。外部程序身份按使用位置与等级隔离，内部输入键、结果键与引用保持原文，供值器和能力填写真实技能归属。

需要静态数字的准入先沿同一个 GenericEngineClient（通用引擎客户端）做完整程序编译及会话释放，取得原生 approvedStaticValues（静态核定数值目录），页面显示预检次数。缓存范围包含完整快照、作者定义、私有参数目录与等级；相关数据变化重新预检。Web不解释共同算术，原恒1、范围、初值上限、主体互斥及过程事实检查消费原生数值。最终场景编译再次逐条核对实际程序身份与核定值，缺值或变化拒绝运行；单技能静态状态字段保留外部公式引用，由原生独立检查依赖与原范围。聚合多个技能的装备状态及静态永久转换使用同身份原生核定的字面数值，完整作者程序仍进入最终编译并核对。运行档案记录预检次数和最终编译结果。属性依赖的永久转换携带真实技能归属，原生以派生拥有方作为共同输入来源、另一侧作为目标读取；作者绑定不改写。内部已有属性读取仍保留原战斗双方语义。

## 游戏计算配置与通用属性派生

游戏配置页新增“游戏计算规则”，沿 `/api/admin/games/{gameId}/calculation-rules` 读取完整版本摘要和配置，以原摘要保存候选，再独立读取确认。暴击概率属性、倍率下限和连续攻击速度属性均由作者明确选择；0下限与空下限不同，未配置不补旧属性标识。配置草稿纳入原页面离开保护，失败保留，响应或读回未确认时冻结草稿供重新读取确认。派生规则使用既有共同公式编辑器，只授权拥有方本帧普通属性的基础、加成及最终值。

装备只贡献真实直接属性；角色、构筑和装备可达结果报告实际投送方向可能改变的属性。游戏派生按明确激活集合编入，真实支持并编出的来源输出替代同侧游戏输出，竞争输出拒绝。完整共同定义以 `scope:game`（游戏归属）程序进入同一原生编译，不由宿主生成旧攻速数学。技能程序明确 `scope:skill`（技能归属）及真实技能和私有参数目录；缺少归属的旧输入拒绝。

每个实际输出都携带真实目录类型与明确策略：修正前替换或修正后乘算。非生命输出可任意命名；整数输出不得静默取整，派生之间不得读取非基础值。属性合法0按作者公式参与计算，实际缺值、除0、溢出及计划速度非法仍拒绝；连续等待继续由原生改变并保持唯一下一刀。可靠结果依据真实绑定和程序依赖判断动态变化。

有限主动计划允许已编入过程时点或即时属性改变命中候选对明确非生命普通属性执行平加，按来源、自身或本次目标的真实槽投送。原单过程、绑定、费用、行动占用和时钟核对保持；不增加生命属性改变、乘区或新执行形状，运行基础值溢出在夹取前拒绝。

## 双模式与普攻模拟入口

常驻总切换在两种模式间导航，菜单只显示当前模式入口。模式由完整地址路径决定，不单独保存一份模式状态；根地址及未知地址仍进入 `#/attributes`，模拟入口为 `#/simulation/basic-attack`。管理直达地址自动进入管理模式，刷新与前进后退保持一致。管理草稿取消离开不会破坏历史目标；连接、游戏与令牌仍由两模式共用。

普攻模拟已接入“执行一次普攻”和“执行连续普攻”，展示造成伤害、实际扣血、双方运行前后生命、停止原因和清理状态；连续结果在同页提供图表与明细联动。明确选择A/B及等级、所选共享普攻及等级后，通过快照接口一次读取完整作者配置；未录的必要属性必须显式补充，不能覆盖角色固有等级值。双方初始当前生命也需明确输入，0与未填分开；“双方以满生命开始”只在用户点击后读取真实上限。0仍可用于编译检查，实际运行入口要求双方当前生命大于0。

场景选择按攻击方、目标方两栏组织：攻击方栏包含角色、等级、普攻技能与等级、装备，目标方栏包含角色、等级和装备；窄屏按完整分组上下排列，不交错双方字段。攻击方、目标及普攻使用可搜索下拉框，支持名称与稳定标识搜索，候选和选中项展示头像或技能图标。角色列表两边共用；普攻仅列出攻击方已挂载且启用的普攻分类技能，切换攻击方会清空普攻选择及等级。图片仅在可见时读取代表图片关联，优先复用本地缓存，缺图时读取单张图片，不自动拉取全量图片；无头像时显示占位。切换游戏、连接或令牌会取消旧目录与图片读取。

三个等级使用下拉框：攻击方与目标共用当前游戏 `level-config`（等级配置）的最小／最大等级，普攻使用所选技能的1至最高等级。等级不默认选择，切换普攻清空旧技能等级。范围未返回或读取失败时禁用选择，失败提供重试；没有全部合法等级时不能读取场景，不用固定1～18或默认1级替代未读取的配置。

`src/engine/simulationAdapter.ts`将作者原配置转换为当前通用编译请求，并给出原字段到实际编译节点的覆盖清单；等级、公式、暴击、独立联动、过程开始和共同防御定义全部保留。单次任务独占真实工作线程，依次编译、运行、释放并终止；超时或崩溃已经销毁线程时，通过 `hasLiveWorker`（线程存活查询）跳过旧会话释放，不新建空线程或自动重跑。取消或确认离开终止线程，迟到响应不覆盖新场景；重新读取失败或取消保留原快照与输入。换装清除失效快照，保留当前生命与补充值草稿；重新读取不自动满血或夹取，输入越界明确提示，旧结果保留并标记过期。
