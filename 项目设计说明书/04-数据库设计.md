## 一、功能说明

1. **多游戏存储**：`game_id` LIST 分区。
2. **revision 模型**：最新主表 + `change_revision`；publish 增量拷贝 `change_revision ∈ (previousPublishedRevision, publishRevision]` 的行到对应 `*_log`，并在版本上冻结 `publishRevision`。
3. **combat-data**：实体、属性/资源、Provider、能力、效果步骤及 detail 表。
4. **审计**：`"user"` schema（`edit_log` 等）。

取向：手写 DDL，无 Flyway；新库跑 `schema.sql` → `triggers.sql` → `seeds/reserved_types_seed.sql`。

---

## 二、核心模型

### 2.1 `game_data_state` + `change_revision`

| 概念 | 说明 |
|------|------|
| `game_data_state` | 每游戏一行；`current_revision` / `published_revision`；Admin PUT 与 publish 锁本行串行化 |
| 最新主表 | 每业务键一行；行上 `change_revision` 记录最近写入点 |
| 发布 | 新建/更新 `game_versions`，冻结 `publishRevision`；增量拷贝 `change_revision ∈ (previousPublishedRevision, publishRevision]` 的行到对应 `*_log`（PK 含 `version_id`） |
| 读模型 | Public 读**最新主表**（及 state）；历史分析可用 `_log` |

### 2.2 多游戏 LIST 分区

- 业务表 `PARTITION BY LIST (game_id)`；子表 `{parent}_{game_id}`。
- `ensure_game_partitions(game_id)` 父表清单以 `db/game_manage/triggers.sql` 为准（例：`game_entities`、`ability_definitions`、`effect_steps` 及其 `_log`，以及 `attribute_definitions` / `types` / `type_relations` / `images` 等）。
- 非分区：`games`、`game_versions`、`game_data_state`、`game_progression_schema`、`reserved_type*` 等。

### 2.3 已移除的旧模型（勿当作现行）

全量 Bundle / Wasm Catalog 快照表、独立 hero/item/skill 资源表、owner-categories、以及 `type_relations.deleted` tombstone **不是**当前 schema/mapper 路径。旧库切换见下方兼容迁移。

## 三、表族概览（public）

### 3.1 元数据

- `games`、`game_data_state`、`game_versions`（含 `change_revision`）
- `game_progression_schema` + `_log`
- `images`（分区；不纳入 combat revision）

### 3.2 类型与属性基线

- `attribute_definitions` + `_log`
- `types` / `type_relations` + `_log`（硬主键；无 `deleted` 列）
- `reserved_type` / `reserved_type_relation`

### 3.3 Generic combat-data（§9 in schema.sql）

主表 + 对应 `_log`，包括但不限于：

| 域 | 代表表 |
|----|--------|
| 实体 | `game_entities`、`entity_attribute_*`、`entity_resource_*`、`entity_provider_mounts` |
| 资源定义 | `resource_definitions` |
| Provider | `provider_definitions`、`provider_formulas`、`provider_lifecycles`、`provider_modifiers`、`provider_listeners`、`provider_state_fields`、`provider_tick_sequences`、`listener_match_types` |
| 能力 | `ability_definitions`、`ability_parameters`、`ability_state_fields`、`ability_phases`、`ability_costs`、`ability_cooldowns` |
| 效果 | `effect_sequences`、`effect_steps`、相位/监听挂接表、各类 `*_effect_details` |

可执行 DDL 与 COMMENT 见 `schema.sql`；分区父表见 `triggers.sql`。

## 五、与 Wasm / Web 的契约位置

```
最新主表 (+ change_revision)
  → Public combat-data API
  → Web combatDataLoader / assembler → CompileRequest
  → engine_compile / engine_run / engine_release_session
```

发布不产生引擎 Bundle JSON；引擎输入由前端从最新 combat-data 装配。
