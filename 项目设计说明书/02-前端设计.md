## 一、功能说明：前端要做什么

前端是 **React + Arco 的「Web 控制台」**，承担三类功能：

1. **机制数据管理后台**：英雄/技能/装备/属性/类型/状态/公式/乘区桶等的管理（查询卡片 + 表格 + 弹窗编辑）。注意是**列表读取 + 全量 PUT upsert/replace**，**除类型关系的 tombstone 软删（按目标 replace 实现）外，无独立 DELETE 端点**。
2. **版本发布与缓存编排**：发布版本、回读 `current/bundle` 校验、图片与 Bundle 的 IndexedDB 本地缓存。
3. **把存储配置编译为引擎配置并跑计算**：通过适配层把发布 Bundle + 用户选择编译成引擎输入，调 TinyGo V2 引擎做 M1/M2/M3/M4 字段验证与 DPS 计算，配 ECharts 与证据展示。

> 它**不是**面向最终玩家的展示站，也**不是**完整「场景模拟」产品——后者仍在规划（[§十](#十规划路线roadmap)）。

## 三、架构与目录

```
壳层      App.tsx（导航 + 全局会话[selectedGameId/adminToken/apiBaseUrl] + 页面 switch + bundleRefreshSeed）
配置层    config/navigation.ts（路由 ID/分组/接口说明）、config/reservedTypes.ts
契约层    types/api.ts（全部 API 契约类型）
服务层    services/*（apiClient / bundleSnapshot / bundleCache / imageCache / resourceImage / typeCatalog）
引擎桥    engine/*（tinygoV2Bridge / tinygoV2BundleAdapter / tinygoV2DpsAdapter + wasm 产物）
组件层    components/*（DataTable/Panel/... + hero-editor/skill-editor/item-editor/formula-editor）
页面层    pages/*（Overview/VersionPublish/Images/WasmValidation*）+ pages/admin/resources/{resource}/
```

**全局壳层 `App.tsx`**：Hash 路由 `#/{routeId}`（`#/versions`、`#/version-publish` → `workspace`；`#/admin/{seg}` 仅映射 4 个 builtin 资源）；`localStorage` 存 `damage-viewer.web.api-base-url` / `.admin-token`；发布成功后 `bundleRefreshSeed++` 驱动 Wasm 验证页重载 bundle。

## 四、资源页通用机制（开发资源页照此套用）

### 4.1 `useCrudResourcePage`（`admin/resources/shared/useCrudResourcePage.ts`）

```ts
useCrudResourcePage<TRecord, TSearch, TForm>({
  apiBaseUrl, selectedGameId, adminToken,
  createSearchData, createFormData,
  listRecords, saveRecord, filterRecords, toFormData,
  getSuccessMessage?, afterSaveRecord?,
})
```

| 阶段 | 行为 |
|------|------|
| 列表 | `selectedGameId && adminToken` 时 `listRecords`；`refreshSeed` 触发重载 |
| 搜索 | 编辑 `searchData` → `handleSearch` 应用 → `filterRecords(records, applied)`（前端过滤，全量不分页） |
| 弹窗 | `openCreate/View/EditModal`；`modalMode: create/view/edit` |
| 保存 | `submitModal` → `saveRecord`（PUT 整条覆盖）→ `afterSaveRecord?` → 成功提示 → 关弹窗 → `refreshSeed++` |
| 失败 | `Message.error(getErrorMessage(error))` |

### 4.2 资源页切片结构（`admin/resources/{resource}/`）

| 文件 | 职责 |
|------|------|
| `index.tsx` | 组装：定义 `listRecords/saveRecord/filterRecords/toFormData` 并挂 hook |
| `constants.ts` / `types.ts` | 默认值工厂 / `XxxRecord`/`FormData`/`SearchData` |
| `search.tsx` / `table.tsx` / `columns.tsx` / `modal.tsx` | 查询表单 / 工具栏+表格 / 列定义 / 弹窗表单（view 只读） |
| `shared/json.ts`、`shared/typeRelations.ts`、`shared/useTypeCatalog.ts`、`shared/useResourceImageCache.ts` | JSON 解析 / 类型挂载 payload / 类型目录索引 / 图片缓存读取 |

> 保存模式：整条 PUT；`KNOWN_*_FIELDS` + `extraFieldsText` 保留未知顶层字段（skills、formula-profiles 等），避免丢字段。`status-management` 不走此 hook，自管状态机。
>
> **关于"删除"**：全站**无独立 DELETE HTTP 端点**。唯一的"删除"语义在**类型关系**：通过 `PUT /type-relations/{targetCategory}/{targetId}`（按目标全量替换）提交一个不含某条关系的集合即可移除它；底层 `type_relations.deleted` 是软删 tombstone（[DB §3.4](./04-数据库设计.md#34-类型网络)）。其它资源无法删除，只能 PUT 覆盖。

## 五、页面功能规格（已落地）

### 5.1 系统总览 `OverviewPage`（`#/overview`）

- **功能**：展示游戏列表、当前版本、owner-categories、公开 API 说明；选游戏；刷新快照。
- **API**：`listGames`（壳层）、`getCurrentVersion`、`getOwnerCategories`（`allSettled` 合并部分失败）。
- **缓存**：无。

### 5.2 版本发布 `VersionPublishPage`（`#/workspace`）

- **功能**：发布快照 + 回读 current/bundle 校验。**需 Admin Token**。
- **发布流程**（`usePublishFlow.handlePublishVersion`）：
  1. 校验 `versionCode` 非空、`selectedGameId` + token。
  2. 并行 `getItems` + `getSkills` → `buildPublishedContractDiagnostics(items, skills)`。
  3. 若存在 `severity==='error'` 的诊断 → **阻止发布**。
  4. `publishVersion({ versionCode, releaseDate? })`。
  5. `loadPublishedBundleSnapshot` 回读 current + bundle。
  6. 成功 → `onDataPublished()` 通知壳层刷新。
- **缓存**：发布后 bundle 写入 `bundleCache`。

### 5.3 图片缓存页 `ImagesPage`（`#/images`）

- **功能**：IndexedDB 图片缓存查看/同步/清理（**不需 Token**）。
- **全量同步**：`getImages(gameId)` → `upsertRemoteImages`。
- **增量同步**：`updatedAfter = 本地最新 update_time` → `getImages(gameId, updatedAfter)`。
- **自动 priming**：每 game 首次进入且缓存为空 → 静默全量一次。
- **清理**：`clearGameImageCache(gameId)`（按 `{gameId}_` 前缀）。同一时间仅一个 `syncAction`。

### 5.4 Wasm 验证 / DPS 页

| 路由 | 页面 | 功能 |
|------|------|------|
| `#/wasm-validation` | `WasmValidationPage` | M1 Actor 初始属性快照对照 |
| `#/wasm-validation-m2` | `WasmValidationM2Page` | M2 Action 面板初始快照 |
| `#/wasm-validation-m3` | `WasmValidationM3Page` | M3 单技能 1v 假人 + M4 机制证据 |
| `#/wasm-validation-m4-closure` | `WasmValidationM4ClosurePage` | M4 闭环 preset |
| `#/wasm-validation-v2-dps` | `WasmValidationV2DpsPage` | 单英雄站桩 DPS + ECharts |
| `#/wasm-validation-v2-dps-multi-hero` | 同文件 | 多英雄同装备 DPS 对比 |
| `#/wasm-validation-v2-dps-stacking-passive` | 同文件 | Batch H 叠层被动验证 |

进入条件：`selectedGameId` + `loadPublishedBundleSnapshot`（受 `externalRefreshSeed` 驱动）。V2 DPS 运行时序见 [§七](#七wasm-调用与适配层)。

## 六、关键编辑器（机制录入）

### 6.1 技能机制编辑（`components/skill-editor` + SkillsModal）

- `mechanicsConfig` 默认 `{ version:1, stacks:[], triggers:[] }`。
- `SkillMechanicsConfigEditor` 结构化编辑 `version/stacks/triggers`，并通过 `onDpsPassiveEffectsChange` 写回 `dpsPassiveEffects[]`：支持模板创建（`dpsPassiveTemplates`）、按 `attacker`/`target` 分组、`summarizeDpsPassiveEffects` 摘要。
- `validateDpsPassiveEffects`：`version=1`、`triggers` 为数组；`dpsPassiveEffects[]` 逐项校验 `passiveId/ownerRole/trigger/operations`（kind 白名单含 `damage/add_stack/execute_threshold` 等）；有 error 则禁止保存。**目标契约**的 `trigger.event` 应与引擎全集一致（含 `on_crit`，见 [适配层规范 §8.1](./08-适配层编译规范.md#81-触发模型统一说明消除歧义)）；当前前端白名单仍缺 `on_crit`，这是待修实现差异。
- 保存 payload = 已知字段 + `extraFieldsText`（保留未知顶层字段）。

这些字段最终被引擎当配置解释执行，语义见 [Wasm §5.4](./05-Wasm计算引擎设计.md#54-operation-语义机制-配置的操作)。

### 6.2 装备编辑（`item-editor`）

- `skillRefs`：`SkillRefSelector` 多选已有 skill；`validateItemSkillRefs` 校验 owner 匹配/被动形态。**空数组 = 不接被动**（不自动挂全部 skill）。
- `ItemDpsPassiveSkillCreator`：用模板（`attacker_on_hit_damage`/`attacker_execute_threshold`/`attacker_crit_context_modifier`/`bucket_damage_modifier` 等）`putSkill` 创建 item-owned skill → 追加到 `skillRefs` 草稿（不自动 `putItem`，需点 Save）。
- `recipeIds`：`ItemRecipeSelector` 多选合成组件；`statModifiers`：`BaseStatsEditor` + 属性目录。

### 6.3 状态管理 Tab（`status-management`）

单页 5 个 Tab（`StatusResourceId`），各对应一类资源 + 各自 PUT：`statusDefinitions`/`controlStateProfiles`/`statusModifierGroups`/`statusAttributeModifiers`/`statusPeriodicHpEffects`。顶部「状态上下文」按 `statusId` 聚焦；统一 `StatusResourceModal`（`extend` 为 JSON 文本）；周期效果按 `effectKind=damage|heal`、`canCrit` 分支校验；无删除；保存后 `refreshSeed++` 全量重拉。

## 七、Wasm 调用与适配层

### 7.1 桥接 `tinygoV2Bridge.ts` 调用时序

```
TinyGoV2Bridge.create({ wasmUrl }) → 校验导出函数
invoke(fn, kind, payload):
  JSON.stringify → encodeFrame(MAGIC=0x32475644, schemaVersion=1, kind, payload)
  → alloc → 写 memory → engine_*(ptr,len) → dealloc
  → engine_outbox_ptr/len → decodeFrames → engine_outbox_clear
  → code!==0 → TinyGoV2InvocationError
```

- `init(bundle)` kind=1；`beginRun(input)` kind=2；`step(maxEvents)` 读 outbox 返回 frames；M1/M2 用 `snapshotInitial`/`snapshotActionsInitial`。
- `decodeFramePayload<T>(frame)` → `JSON.parse`。

### 7.2 适配层（存储配置 → 引擎配置）

> 完整的编译规则（selection schema、属性快照合成、动作/公式编译、被动展开、operation 完整契约）见 [08-适配层编译规范](./08-适配层编译规范.md)。本节只给概览。

| 文件 | 职责 |
|------|------|
| `tinygoV2BundleAdapter.ts` | 把 `GameDataBundle` + 选择编译为 `EngineBundleV2` + run 输入；`compileTinyGoV2ValidationInput`（M1–M4）、`compileDpsAttackerBundle`、公式/状态 registry 编译 |
| `tinygoV2DpsAdapter.ts` | `prepareV2DpsInput(bundle, selection, versionCode, wasmSha256, skillRefOptions)` → `{ engineBundle, runInput, preflightBlockedReasons }`；Preflight 检查 |

**V2 DPS 运行时序**（`WasmValidationV2DpsPage`）：

```
1. prepareV2DpsInput(...)  → engineBundle + runInput + preflightBlockedReasons
2. preflightBlockedReasons.length>0 → 不调引擎，展示 blocked 原因
3. create → init(engineBundle) → beginRun(runInput)   # 无 mode 参数；DPS 由 runInput JSON 形态识别（含 curves+simulationRules 且无 self/enemy）
4. 从 outbox 找 DONE(13) 帧; 无则 error  （DPS 在 beginRun 内完成，不调 step）
5. 解析 done payload → ECharts 曲线 + effectBreakdown 证据面板
```

**Preflight 检查项**：目标须含 `target_dummy` 类型；目标装备被动 ownerRole 匹配；equipment skillRef 解析无 error；攻击方须有 `action/basic_attack` 模板；`dpsPassiveEffects` 形态正确。触发事件白名单按目标契约应放行 `on_crit`，当前缺口同 §6.1。

引擎侧契约见 [Wasm §5.1](./05-Wasm计算引擎设计.md#51-输入输出契约顶层)。

## 八、API 客户端与契约（`services/apiClient.ts` + `types/api.ts`）

### 8.1 基址 / 鉴权 / 错误

```ts
resolveApiBaseUrl(explicit?) // explicit || VITE_API_BASE_URL || 'http://localhost:8080'，去尾斜杠
class ApiRequestError extends Error { status: number; code?: string; details?: Record<string, unknown> }
getErrorMessage(error: unknown): string
// fetch + Accept: application/json；有 body 时 Content-Type；token → Authorization: Bearer
// 成功返回 ApiResult<T> = { data, status, etag }
```

前端**不处理 CORS**：开发期 `localhost:5173` 直连 `localhost:8080`，跨域由后端 `WebCorsConfig` 放行。

### 8.2 导出函数（节选，均 `Promise<ApiResult<T>>`）

| `getHeroes`/`putHero`、`getSkills`/`putSkill`、`getItems`/`putItem` | `(..., token[, id, body])` |

### 8.3 `types/api.ts` 关键类型

`GameSummary`、`CurrentVersion`、`ImageAsset`、`OwnerCategory`；Admin 实体 `Hero/Skill/Item/AttributeDefinition/TypeDefinition/TypeRelation/SkillMount/FormulaProfile/FormulaBinding/CoefficientBucket/StatusActionControlRule` + 状态五件套；`VersionPublishPayload/Response`、`BundleMeta`、`GameDataBundle`；`*Response` 包装 `{ gameId, <array> }`。

## 九、本地缓存 schema

| 缓存 | 文件 | DB / store | 主键 | 存储形态 | 读写时机 |
|------|------|-----------|------|---------|---------|
| 图片 | `imageCache.ts` | `image_db` v1 / `images`（keyPath `uri`） | `{gameId}_{uri}` | `{uri, create_time, update_time, image(base64)}` | ImagesPage 同步 / `useResourceImageCache` 读 / 上传后 `upsertImageAsset` |

> 索引：图片 `create_time`/`update_time`；Bundle `versionCode`/`cachedAt`。升级策略：`onupgradeneeded` 删除并重建 store。缓存阶段 2（自动静默同步、LRU 跨 game 缓存管理、Quota 兜底）已设计待实现，详见 `图片资源IndexDB缓存方案.md` §11；Blob 化与后端删除接口明确推迟。
