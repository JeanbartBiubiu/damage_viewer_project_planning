## 示例：为两个实体挂上 Provider / 能力并在通用验证页跑通

目标：在游戏 `lol` 下准备 source/target 两个 `game_entities`，挂载 Provider 与能力，发布后在 `#/wasm-validation-generic` 完成 compile / run / release。

### 步骤 1 · 录入（Web Admin）

1. 打开 `#/combat-data/entities`，PUT 两个实体（identity 字段锁定后不可改）。
2. 按需在 `#/combat-data/providers`、`abilities`、`effect-steps` 等分表写入定义；effect-step **恰好一个** detail。
3. 用 `#/combat-data/entity-provider-mounts`（或 registry 中对应资源）把 Provider 挂到实体。

Admin PUT 经 `combatDataClient` → `PUT /api/admin/games/{gameId}/combat-data/**`；后端递增 `change_revision`。

### 步骤 2 · 存储（后端 + DB）

- 写入对应最新主表（如 `game_entities`、`provider_definitions`、`ability_definitions`、`effect_steps` + detail）。
- `game_data_state.current_revision` 递增；行上 `change_revision` 更新。
- 可选写 `"user".edit_log`。

### 步骤 3 · 发布

`POST /api/admin/games/lol/versions:publish` `{ "versionCode": "…" }`：

- 冻结 `publishRevision` 到 `game_versions`；
- 增量拷贝 `change_revision ∈ (previousPublishedRevision, publishRevision]` 的行进各 `*_log`；
- **不**生成 Bundle/Catalog。

前端 `#/workspace` 回读 current 与 combat-data state。

### 步骤 4 · 读取 + 装配

`WasmValidationGenericPage`：

1. `loadCombatDataGraphRevisionSafe` 拉齐 graph（可走 IndexedDB）。
2. 选择 source/target entity。
3. `combatDataAssembler` 产出 `CompileRequest`（及运行输入）。

规则见 [08](./08-适配层编译规范.md)。

### 步骤 5 · 计算（Wasm）

```
engine_compile(CompileRequest) → session
engine_run(...) → 结果帧 / 时间线
engine_release_session(...)
```

经由 `genericEngineClient` + `tinygoV2Bridge`（generic profile）。

### 步骤 6 · 验证

在 `#/wasm-validation-generic` 确认页面标题「通用引擎验证」、游戏上下文与 combat-data revision 可见；有实体时可完成装配与运行。发布门禁可用 `npm run smoke:wasm-generic`（需真实 `E2E_*`）。

### 数据流回顾

```
Admin PUT combat-data/**          → 最新主表 + change_revision
  → versions:publish              → 冻结 publishRevision；增量拷贝变更行到 *_log
  → GET combat-data/**            → combatDataLoader
  → assemble CompileRequest       → engine_compile / run / release
```

## 扩展心法

| 想加什么 | 优先落点 | 何时改引擎 |
|----------|----------|------------|
| 新实体/数值/挂载 | combat-data 表 + Admin 页 | 从不 |
| 新效果步骤类型（已有 detail 族） | effect-steps + detail PUT | 从不 |
| 装配规则变更 | `combatDataAssembler` | 契约变更时同步 Wasm |
| **全新引擎语义** | — | 扩 TinyGo 模型 + ABI 契约后再改装配 |

判断准则：目标语义能否用现有 Provider/能力/效果步骤表达。能 → 纯数据；不能 → 先扩引擎，再回到配置。
