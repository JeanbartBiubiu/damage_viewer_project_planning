## 一、功能说明：后端要做什么

后端是一个 **单体 Spring Boot 服务 `data_manage`**，定位：「PostgreSQL 多游戏分区数据工作台 + 版本化 Bundle 发布服务」。要做的事：

1. **公共只读 API**：给玩家端提供游戏列表、当前版本、发布 Bundle、图片、归属字典（无需鉴权，可缓存）。
2. **Admin 管理 API**：给编辑者提供机制数据列表查询、GET 单条（部分资源）、PUT 全量覆盖写与发布操作（需 JWT + `canEdit`），无独立 DELETE。
3. **语义校验**：写入与发布时校验阶段范围、引用存在性、机制结构。
4. **版本发布**：把编辑态冻结为全量 `bundle_json` 快照，推进版本区间。
5. **编辑审计**：写操作记 `edit_log`。

**明确不做**：伤害/DPS 计算（在 [Wasm 引擎](./05-Wasm计算引擎设计.md)）；用户登录/注册（外部系统签发 JWT）。

## 四、对外接口契约

### 4.1 全局约定

- **成功**：`2xx` 直接返回 JSON 对象/数组，**无 wrapper**。
- **失败**：统一结构

```json
{ "error": { "code": "422.SEMANTIC_ERROR", "message": "...", "details": { "path": "...", "reason": "..." } } }
```

- **错误码**：

| code | HTTP | 场景 |
|------|------|------|
| `400.INVALID_BODY` | 400 | JSON/参数/结构/阶段范围非法 |
| `401.UNAUTHORIZED` | 401 | 无 Bearer / JWT 无效过期 |
| `403.FORBIDDEN` | 403 | `canEdit=false` |
| `404.NOT_FOUND` | 404 | game/资源/快照/路由不存在 |
| `409.CONFLICT` | 409 | 版本号重复等 |
| `422.SEMANTIC_ERROR` | 422 | 引用不存在、发布语义校验失败 |
| `500.INTERNAL_ERROR` | 500 | 未捕获异常 |

- **鉴权**：Public `/api/games/**`（非 admin）无需 JWT；Admin `/api/admin/**` 需 `Authorization: Bearer <jwt>`，ES256，claims 必含 `email`/`canEdit`/`paid`/`exp`，`canEdit=false`→403；本地 `app.auth.jwt.disabled=true` 跳过。
- **禁止版本字段**：upsert 请求体递归出现 `startVersionId/endVersionId/versionId/versionCode/isCurrent/dataHash`（及 snake_case）→ `400`。
- **ETag/304**：仅 `GET /api/games` 与 `GET .../owner-categories` 计算 ETag 支持 `If-None-Match`→304；`current`/`bundle`/`images` 无 ETag。
- **edit_log**：Admin 写成功后写 `{method,path,responseCode,requestBody?}`；fail-open（写日志失败不阻断业务）；顺带清理 7 天前记录。

### 4.2 Public 接口（无 JWT）

```http
GET /api/games                         # [{gameId,gameName,gameImgUrl,progressionSchema}]; 支持 304
GET /api/games/{gameId}/versions/current  # {gameId,versionCode,releaseDate?,publishedAt?,updatedAt}; 无→404
GET /api/games/{gameId}/versions/{versionCode}/bundle  # 全量 bundle_json(见 §5.1); 无快照→404
GET /api/games/{gameId}/images?updatedAfter=<ISO>      # {gameId,images:[{uri,imageBase64,updatedAt}]}
GET /api/games/{gameId}/owner-categories               # {gameId,ownerCategories:[...]}; 支持 304
```

`GET /api/games` 响应示例：

```json
[{
  "gameId": "lol", "gameName": "英雄联盟", "gameImgUrl": "https://.../lol.png",
  "progressionSchema": { "progressionKind": "LEVEL", "stageMin": 1, "stageMax": 18, "stageLabel": "Lv", "requireAllStages": true }
}]
```

> 无 `game_progression_schema` 记录时 `progressionSchema` 用默认值（LEVEL,1–18,Lv,requireAllStages=true）。

### 4.4 代表性请求/响应 JSON（可拷贝）

**英雄 PUT `/heroes/{heroId}`**：

```json
// 请求
{ "name": "Ahri", "title": "九尾妖狐", "avatarUrl": "https://...",
  "baseStats": { "hp": 500, "atk": 55 }, "statsByLevel": { "hp": [500, 520, 540] } }
// 响应：同结构 + "heroId"
// 列表 GET：{ "gameId": "lol", "heroes": [ { "heroId": "...", "name": "...", "baseStats": {} } ] }
```

**技能 PUT `/skills/{skillId}`**（机制配置随技能存储）：

```json
{
  "ownerType": "hero", "ownerId": "hero_ahri", "skillKey": "Q", "name": "...",
  "resourceCosts": {}, "cooldowns": {}, "params": {}, "timingProfile": {},
  "mechanicsConfig": {
    "version": 1, "triggers": [],
    "dpsPassiveEffects": [
      { "passiveId": "p1", "ownerRole": "attacker",
        "trigger": { "event": "on_basic_attack_hit" }, "internalCooldownMs": 0,
        "operations": [ { "kind": "damage", "targetRole": "target", "damageType": "physical", "amount": 15 } ] }
    ]
  }
}
```

> `ownerType/ownerId` 允许同时为 null（共享/模板技能）——实现比文档宽松。

**装备 PUT `/items/{itemId}`**：

```json
{ "name": "...", "goldCost": 300, "iconUrl": "...",
  "statModifiers": [ { "attrKey": "move_speed", "value": 25 } ],
  "skillRefs": ["skill_passive_x"], "recipeIds": ["item_1001"] }
```

> **`statModifiers` 的存储映射**（API 数组 ↔ DB 行表）：请求体里的内联数组 `statModifiers[]` 在 `PostgresWriteStore` 内被拆成 `public.item_stat_modifiers` 的多行（每个 `attrKey` 一行 `value`），不是存进 `items` 表的 JSON 列。`GET 列表` 与 `buildBundle` 反向把这些行聚合回 `statModifiers` 数组。写入时该 item 的旧行按全量覆盖处理。`items` 表本身**无** `stat_modifiers` 列（见 [DB §3.5](./04-数据库设计.md#35-归属英雄技能装备)）。

**属性定义 PUT `/attribute-definitions/{attrKey}`**：

```json
{ "sortOrder": 10, "attrName": "Attack Damage", "attrType": "number",
  "defaultValue": 0, "valueKind": "scalar", "minValue": 0, "maxValue": 9999 }
// valueKind=rate 时须带 rateTargetAttrKey
```

**类型关系按目标全量替换 PUT `/type-relations/{targetCategory}/{targetId}`**：

```json
// 请求
{ "relations": [ { "typeId": 1001 }, { "typeId": 1002, "extend": { "source": "admin_ui" } } ] }
// 响应
{ "gameId": "lol", "targetCategory": "character", "targetId": "hero_ahri",
  "typeRelations": [ { "typeId": 1001, "targetCategory": "character", "targetId": "hero_ahri" } ] }
```

**周期 HP 效果 PUT**（含暴击字段）：

```json
{ "effectKind": "damage", "tickFormulaId": "formula_dot_tick", "damageType": "magic",
  "canCrit": true, "critChanceSource": "attacker_crit_chance", "critMultiplier": 2.0, "perStack": false }
```

**乘区桶 PUT `/coefficient-buckets/{bucketKey}`**：

```json
{ "resolutionDomain": "attribute", "stageKey": "attribute/final_multiplier",
  "targetAttrKey": "ability_power", "aggregationMode": "multiply", "bucketConfig": { "valueUnit": "factor" } }
```

**发布 POST `/versions:publish`**：

```json
// 请求
{ "versionCode": "14.1", "releaseDate": "2026-02-08" }
// 响应
{ "gameId": "lol", "versionCode": "14.1", "releaseDate": "2026-02-08", "publishedAt": "...", "updatedAt": "..." }
```

**图片 PUT `/images/{uri}`**：请求 `{ "imageBase64": "data:image/png;base64,..." }` → 响应 `{ "uri", "imageBase64", "updatedAt" }`。

## 五、关键子系统详细设计

### 5.1 读写主链路（service/）

```
GameDataService（业务聚合）
 ├── PostgresReadStore   读：组装资源 / buildBundle()
 ├── PostgresWriteStore  写：校验 + upsert + publishVersion()
 ├── PostgresJsonSupport  JSON ↔ 列 稳定序列化
 └── DefaultBasicAttackProvisioner  发布前补齐 LoL 默认普攻技能/公式/挂载
```

`buildBundle()` 顶层结构见 [数据库 §5.2](./04-数据库设计.md#52-发布-bundle-顶层结构buildbundle-实际输出)。

### 5.2 版本与发布算法

写入（upsert）：首次写入时 `resolveVersionIdForWrite()` 取/建 `__workspace__` 版本；主表 `ON CONFLICT` upsert，`start=end=workspaceVersionId`，每个业务 ID 仅 1 行。

发布 `PostgresWriteStore.publishVersion(gameId, {versionCode, releaseDate})`：

```
1. 拒绝 versionCode = '__workspace__'; 版本号重复 → 409.CONFLICT
2. 新建 game_versions 行 → versionId
3. changedAfter = 上一版 published_at (首版=EPOCH)
4. 各表 listChangedSince(gameId, changedAfter)  // updated_at > changedAfter
5. buildBundle() 全量组装 → validateBundleForPublish()(语义校验, 见 §6)
6. 对每条变更行:
     主表 updateVersionRange: SET start=end=versionId        // 发布点区间 [v,v]
     _log 表 upsert*Log: 写 (entity_keys..., start_version_id=versionId) 字段快照
   未变更行: 不动 (保留旧区间)
7. 写 published_bundle_snapshots.bundle_json
8. clearCurrentVersion + markVersionCurrent(versionId)
9. 失效 currentVersion / bundle 读缓存
```

### 5.3 鉴权（support/auth/）

`AdminAuthFilter` 仅拦截 `/api/admin/**`：校验 ES256 JWT → 读 `email/canEdit/paid` 入 `AuthContext`；`canEdit=false`→403。本地默认禁用。

### 5.4 缓存（config/CacheConfig + Redis）

缓存名 `games/currentVersion/bundle/images/ownerCategories`。**普通写**只失效 `games/images/ownerCategories`；**发布**才清空 `currentVersion/bundle`（只有发布改变只读快照）。

### 5.5 关键配置

| 配置 | 行为 |
|------|------|
| CORS（`WebCorsConfig`） | 仅 `/api/**`；`allowedOrigins=*`；暴露 `ETag`；无 credentials |
| 序列化（`JacksonConfig`） | 对象/Map 键**字母序**排序（稳定 JSON，利于 diff/缓存命中） |
| 启动探测 | `app.startup.fail-fast`（默认 false） |
| 多环境 | 仅 `application.yml`；IT 用 `application-it.yml` |

环境变量（`SPRING_DATASOURCE_*`、`IT_DB_*`、`APP_AUTH_JWT_DISABLED` 等）见 `server/data_manage/README.md`。

## 六、校验规则

写入失败返回 `400`，发布全量校验失败返回 `422`。

- **阶段 / statsByLevel**（依赖 `game_progression_schema`）：`statsByLevel` 两种结构——`attrKey→number[]`（长度 = `stageMax-stageMin+1`）或 `stageKey(整数字符串)→{attrKey:number}`（stage∈[min,max]）；`requireAllStages=true` 时每 stage 必须存在且 attrKey 集合一致。
- **引用存在性**（`validateBundleForPublish`）：`items.statModifiers[].attrKey`→属性；`items.skillRefs/recipeIds`→skill/item；`skills.ownerType` 已登记且 `ownerId` 存在；`typeRelations`、`formulaBindings`、`skillMounts`、状态资源各引用链；`coefficientBuckets` attribute 域 `targetAttrKey` 必填存在；`status_action_control_rules` 的 typeId 链。
- **mechanicsConfig / dpsPassiveEffects**：`version=1`；`triggers` 为数组；`dpsPassiveEffects[]` 每项 `ownerRole∈{attacker,target}`、`internalCooldownMs` 非负、`operations[].targetRole∈{attacker,target}`。其中 `trigger.event` 的**目标契约 = 引擎全集（含 `on_crit`）**。当前后端发布校验白名单为 `{on_basic_attack_hit, on_spell_hit, on_hit, on_damage_dealt, on_damage_taken, dot_tick}`，**暂缺 `on_crit`，属待修实现差异——应放行 `on_crit` 以对齐引擎**（引擎运行时已支持）。完整触发模型与全集见 [适配层规范 §8.1](./08-适配层编译规范.md#81-触发模型统一说明消除歧义)。

> `triggers[]` 与 `dpsPassiveEffects[]` 的分工：`triggers[]` 服务 1v1 事件引擎路径（编译为 `EngineBundleV2` 的 action effects / 1v1 触发器）；`dpsPassiveEffects[]` 服务单攻击方 DPS 路径。纯 DPS 录入时 `triggers` 通常为 `[]`。
- **属性边界**：`valueKind=rate` 须带存在的 `rateTargetAttrKey`；`min/max/default` 边界校验。
- **图片**：`imageBase64` 须为 `data:image/...;base64,...`。
