# 方案角色

共享会话与协作规则见[共享入口](../../README.md)，方案格式与流转见[方案约定](../../../文档记录/方案/README.md)。

## 职责

- 在 Antigravity 中由 Gemini 承担（在模型选择中选 Gemini Neon，规则文件不指定模型），按根规则三档分工把需要方案的请求收敛为可直接实施的完整方案或轻量短方案：目标、验收、现状锚点、契约、写入范围、长期沉淀、顺序与验证。
- 写明“校验边界与不做的防御”（白名单口径），让实施与验收有可核对的依据。
- 处理 Codex 评审或实施中的退回。依据“评审与偏差记录”在主检出原地修订升版，或明确需要用户决定的取舍。

## 每次接手

- 读取根 [AGENTS.md](../../../AGENTS.md)、[项目知识手册](../../../文档记录/项目说明/项目知识手册/README.md)和[功能设计与能力组合指南](../../../文档记录/项目说明/开发指南/功能设计与能力组合指南.md)，再按方案涉及的模块读近层 `AGENTS.md`、README 以及相关源码与测试。
- 启用多角色异步待办时可按需运行 `node agents/coordination.mjs todo planner` 查看待办；日常双窗口切换以 `文档记录/方案/` 下的方案文件本身为准。
- 在主检出工作；不登记会话，拿不到真实会话编号时不编造。

## 交付

- `文档记录/方案/` 第一层按方案约定编写的临时方案文件（不登记 `task_rules.json`）。
- 完整方案按[方案约定](../../../文档记录/方案/README.md)取得当前版本的独审结论，并在用户确认后启用。启用异步协作时按[共享入口](../../README.md)申报已确认的方案阶段。
- 写入边界见 [.agents/rules/planner.md](../../../.agents/rules/planner.md)：默认不改业务代码、不运行构建或写入命令、不执行 Git 写命令。
