# 数据库 AGENTS.md

## 范围与入口

本文件适用于 `db/**`。先读同目录 [README.md](README.md)、[数据库设计与验证指南](../文档记录/项目说明/开发指南/数据库设计与验证指南.md)及目标目录已有说明，再核对受影响的建表脚本、迁移和真实消费代码。后端查询与事务同时遵循 `server/data_manage/AGENTS.md` 及目标路径近层规则。

默认只修改本任务明确包含的数据库脚本和说明。文件修改授权不自动包含执行SQL、变更实库、删除数据或调整数据库角色权限；这些操作按已有任务授权与根规则执行，不重复请求已经取得的授权。需要访问实库时使用 `backend-db-access`；纯静态审查不读取连接凭据。

## 持续边界

- 建表脚本定义当前目标结构，迁移只描述特定已有结构的变更；不批跑迁移目录，不用 `IF NOT EXISTS` 代替结构核对，不改写已执行迁移来假定旧库已更新。
- 新表、字段、约束和查询先明确业务事实、完整身份、类型与空值含义，再选择约束、索引及写入边界。MVP不预建旧设计兼容层或无当前用途的表与索引。
- 静态SQL、模拟单测、应用启动与实库状态分别判断；未连接或未执行时，不声称结构已生效、并发已安全或数据已迁移。
- `db/task_doc_governance/` 的任务规则与派生SQLite遵循根规则及 `task-doc-governance`，不手改派生索引，不将业务数据库设计流程套成治理重建要求。

## 最低检查

| 改动或交付 | 最低证据 |
| --- | --- |
| 说明、路径和引用 | 核对实际目标、当前定义及差异；不触发业务全量测试 |
| 新增或调整表、字段、约束、触发器 | 静态核对身份、空值、类型、依赖、删除行为及消费代码；按交付目标补受影响测试与实库证据 |
| 查询、索引或写入条件 | 核对实际谓词、排序、参数与结果列、影响行数及并发不变量；性能结论须有同口径实库测量 |
| 编写迁移 | 写清目标、源结构前置、执行次序、事务归属、数据处置及独立回读方法；不得把未执行脚本报告为迁移完成 |
| 实库结构或迁移完成 | 在已授权目标核对实际结构、约束和索引，另行读回数据；受影响的拒绝、回滚、并发和接口行为按任务验收 |

真实数据删除、权限变化或破坏性迁移按根规则做方案和独立评审；具体运行及回读方法见对应模块说明，不另设通用审批。
