# 账号数据库

新账号使用 `auth` 命名空间的七张表。完整字段及流程契约见[账号方案](../../文档记录/详细设计/项目/账号注册登录与权限接入技术方案.md)，运行入口见[后端说明](../../server/data_manage/README.md)。

- 全新账号存储执行 `schema.sql`：安装并核对 `public.pgcrypto`，创建七张账号表及使用账号编号、用户名快照的编辑日志表。不再创建旧邮箱身份表，不需要数据库定时任务扩展。
- 已有旧 `"user".edit_log` 执行 `migrations/20261104_account_identity.sql`：前提是尚无 `auth` 模式、旧编辑日志包含 `id/email/edit_body/create_time`，在同一事务创建七表并把 `email` 改为可空的 `legacy_email`，新增账号编号及用户名快照。原记录、编号、正文与时间原样保留。
- 旧 `"user".email` 和访问统计不参与新认证，也不会由迁移自动转换、清空或删除。脚本不支持重复执行，不把结构不匹配解释为空库；操作前核对实库、备份及本次迁移范围。

成本 12 的数据库密码版本使用历史迁移 `migrations/20261105_postgres_password_material.sql`：同一事务安装／核对 `public.pgcrypto` 的密码、盐和随机字节函数，检查当时的 `$2a$12$` 完整编码；存在 Argon2 等旧编码时停止，不转换或删除账号。该脚本与 `20261104` 均已用于对应版本，不改写或重放。

当前新生成密码改为成本 10，已有合法成本 12 继续按自身编码验证；两者均由同一 `pgcrypto` 算法处理，不自动重哈希或改账号数据。密码直接调用及限流联合预占沿用现有表结构，本轮无需新迁移。已含成本 10 账号的数据库不能重跑上述只接受成本 12 的历史检查。Argon2 等不支持编码仍不能无明文转换，须独立决定数据处置。

部署还须按实际应用角色和目标数据库配置两项参数日志为零，关闭数据库审计的参数记录，使用扩展查询协议和受控加密连接；命令与连接要求见[后端说明](../../server/data_manage/README.md)。应用自身不修改角色、参数日志或全局权限。仅安装扩展不代表这些运行条件已经满足。

账号、安全事件和编辑日志的保留策略不同：未开通账号超过七天可清理，从属凭证／流程／会话级联删除；安全事件与历史编辑身份仍保留，外键置空。定时清理由应用执行，静态 SQL 不代表实库已经迁移或清理。
