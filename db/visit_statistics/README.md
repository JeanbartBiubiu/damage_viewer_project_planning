# 访问统计

沿用旧前端的上报时机：每次整页加载记一次页面访问量（PV），刷新增加，站内页面切换不增加。独立访客数（UV）按北京时间当天的匿名浏览器编号去重；登录、退出和切换账号不更换编号。清除浏览器存储或换浏览器会被视为新访客。

## 接口与权限

| 接口 | 请求与响应 | 权限 |
| --- | --- | --- |
| `POST /api/visits` | JSON 正文 `{visitorId: "标准 UUID"}`；成功返回 204 | 匿名；沿用允许来源、JSON 类型及 `X-Damage-Client: web` 检查，不读取会话 |
| `GET /api/admin/visits/last30days` | 直接返回 `{date: "YYYY-MM-DD", pv: 数值, uv: 数值}[]` | 正式会话及编辑资格 |

查询固定返回含今天的近 30 个自然日，日期升序，无访问的日期补零。每天的 UV 单独去重，不能相加作为 30 天独立访客数。响应禁止缓存，错误沿用现有 `error.code/message/details` 结构。

浏览器将随机 UUID 保存于 `localStorage`；存储不可用时仅在当前页面保留。上报不携带会话凭据、不等待登录恢复；失败静默结束，不重试、不阻塞业务。顶栏“访问统计”仅向有编辑资格的账号显示，弹窗展示今日数字与每日列表；退出后清除弹窗数据。

## 存储与安装

在目标数据库执行本目录 `schema.sql`，新增 `analytics.daily_visits` 一张表。主键为日期与访客编号，单条数据库语句原子增加 PV；每日 UV 是当天记录行数。仅保留匿名编号和访问次数，不记录账号、地址或页面内容，不依赖 Redis 或定时汇总。

已有库先核对目标和是否存在 `analytics`，再执行脚本；应用不会自动建表。旧项目的访问统计不迁移、不删除。该脚本只用于首次安装，不作为现有结构升级器。

## 验证入口

后端 `VisitStatisticsServiceTest`、`VisitControllerTest` 验证日期边界、补零、输入和权限；真实数据库验证须覆盖相同访客重复／并发上报、不同访客及独立读回。前端统计客户端测试及浏览器用例验证刷新计次、切页不计次、失败静默、编辑权限与退出后的数据清除。模块收尾检查见各自 README。

## 本地性能抽样（2026-11-05）

本机 Java 服务连接隔离 PostgreSQL：8 个并发请求上报 800 次，耗时 1.756 秒，约每秒 456 次，中位耗时 15.40 毫秒，95% 请求在 28.67 毫秒内完成；同日总计 PV 803、UV 18，独立数据库回读一致，没有并发丢计数。

近 30 天共 30,018 条每日访客记录，连续查询 30 次，中位耗时 27.81 毫秒，95% 请求在 43.82 毫秒内完成；另有两条窗口外记录，均未计入。该短时抽样用于判断本期是否需要额外组件，不代表生产容量上限。原始脱敏结果保存在被忽略的 `output/pvuv/`。
